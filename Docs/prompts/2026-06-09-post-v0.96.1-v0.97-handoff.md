## v0.97.0 candidate menu (parked from v0.96.0 + v0.96.1)

Same menu from my last opinionated read, updated with v0.96.1 close + the heartbeat-already-shipped fact.

### Highest leverage, smallest scope (one-cycle PATCH territory)

**A. Per-skill SemVer + versioning CI** (~6-8 stages)
Each blueprint + mechanism gets its own SemVer; CI fails on pin mismatch (currently `check-version-sync.js` only gates workshop_version + package.json). Catches the kind of drift where the cowork blueprint version diverges from contract_version (landmine #20).

**B. v0.95.1 migrator (carry-forward)** (~10-12 stages)
Cycle plan + design already committed since v0.95.1. Execution-ready. Adds a `sauce migrate` command surface that handles frontmatter schema migrations (e.g. for users on pre-v0.30 daily note shapes). Useful for distribution but not load-bearing yet.

### Highest leverage, medium scope (one-cycle MINOR territory)

**C. Memory salience + decay + supersession** (~12-16 stages)
Mem0/Zep/Graphiti/Letta-style. Carry-forwards in memory.md get a salience score from Rail L's tick signal; older bullets decay; resolved items naturally fall away from the carry-forward list. Composes beautifully with Rail L. The "Was today useful?" tick on (say) the Calendar callout becomes evidence that the synthesis bullet "9am standup matters" should stay salient.

**D. Per-item L2R + Thompson sampling** (~16-20 stages)
The "real" learning. Each surfaced item carries a feature vector (already in sidecars from v0.96.0 Rail W); ranker learns at item granularity instead of kind. Per-user weight vector replaces per-kind weight. Adds Thompson sampling exploration discipline (so the system doesn't collapse into filter bubble).
**Wait before doing this** — you need a few weeks of Rail L per-kind data first to see if per-kind granularity is even insufficient. If kind-level learning produces visible noise reduction over 2-3 weeks, this can wait longer.

### Heaviest, biggest scope

**E. W2 — full structured-output API rewrite for compose-body** (~16-20 stages)
The report's "real" version of the writer. Compose-body becomes ONE Anthropic API call with `tool_choice: StructuredOutput` against a JSON schema; Node helper converts JSON → markdown deterministically. Removes the last prose-trust layer (the LLM emitting markdown the writer parses). Needs `ANTHROPIC_API_KEY` in cron env. Doubles per-fire token cost.

### My honest opinionated read (one user's vote)

**Top of the v0.97.0 menu:** **C (memory salience)** + **A (per-skill SemVer)** bundled as one MINOR cycle.

Reasoning:
- Memory salience is the natural next composer with Rail L. Tick signal feeds salience scoring. After 1-2 weeks of Rail L data, salience has meaningful evidence to operate on. Ship it BEFORE per-item L2R because salience operates on memory.md (low blast radius) while per-item L2R touches plan-dispatch ordering (high blast radius).
- Per-skill SemVer is small, addresses a real silent-drift risk (landmine #20 is one example), and unblocks a cleaner "blueprint X bumped 0.34.1 → 0.34.2 with these changes" review experience.

**Bottom of the v0.97.0 menu (defer):** **D + E**. D needs Rail L lived data first. E is a heavy refactor that should wait until v0.96.0 sidecar corpus has 30+ days of production data to validate the schema against.

## What to do if reports come back with surprises

| Surprise | Likely root cause | First-look |
|---|---|---|
| No sidecar files written | Rail W writer rejecting schema | Read recent atomic-note + check for `failed:contract-violation:sidecar-schema` Notice |
| Rating callout missing | `engagement.learning_enabled: false` set explicitly OR compose-body skipped emission | Check engagement record + compose-body call site |
| Rating callout shows kinds you didn't surface | Bug in `surfaced_kinds_for_rating` derivation in orchestrator | Check orchestrator Step 14f compose-body call |
| Heartbeat callout fires erroneously | freshness window too tight OR sidecar walk missed files | Check `cadence-freshness-windows.json` + walkCadenceSidecars's file globbing |
| Detection callout fires for known MCPs | `pending_confirmations` not empty when it should be | Check kind-classifier-cache.json — known MCPs should be cached |
| learned_weights frontmatter never lands | learn-from-checks skipped OR write failed | Check synthesize-day post-step Notice output |
