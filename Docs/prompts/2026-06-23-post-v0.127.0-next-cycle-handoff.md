## Carry-forwards (from v0.127.0 design § "Out of scope")

The universal task contract is in place; the following consumer surfaces are now mechanically trivial follow-ups but were deliberately out of v0.127.0 scope to constrain blast radius.

1. **Click-to-edit on aggregator widget rows** — `ToDoDailyProjectGroups` + `ToDoDailyUnassignedMeetings` currently open the source file on row click. Editing-in-place there requires multi-file writes that complicate the cycle without changing the user's daily journal flow. Worth slotting once the v0.127.0 single-file edit path has soaked.
2. **Project To-Do click-to-edit** — drop `TodayCaptureEditableList` into `Project To-Do.md` with `sectionAnchor: 'ownedTasks'`. The widget is already `findTaskLines`-anchored; only the section anchor changes. Trivial follow-up; ship as v0.127.1 PATCH or fold into the next MINOR.
3. **Recurring registry edit** — recurring tasks have their own modal tab; the `editExisting` mode currently routes only to the one-shot path. Extending edit to the recurring tab would let users edit a recurring-task definition (rule + title + project) via the same modal.
4. **Move-task-across-files via the edit modal** — destination select is currently disabled in edit mode. Future cycle if requested; requires a delete-from-source + write-to-destination pair on `replaceTaskAt`.
5. **`applyArgsScrubBackfill` over `pantry/` workshop content** — intentionally not scrubbed in v0.127.0; pantry is git-managed (landmine #18). If a future cycle needs the pantry mirror to reflect post-heal templates, design an explicit backfill helper.
