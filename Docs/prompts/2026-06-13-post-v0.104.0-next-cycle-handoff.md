**ONE new helper, two integration points, pure additive.** **DocSearch** — CustomJS class. `render(dv, opts)` builds the filter UI strip (text input + dynamic top-8 tag chips + scoped-Obsidian-search button + status pill) + returns the initial `filterContext` `{text, tags, hasActiveFilter}`. Static `DocSearch.matches(page, ctx)` is the pure predicate consumed by `ProjectDocsIndex` + `SectionHub` at query time — AND-logic across text substring (`file.name` + `tags` + first 200 chars of `file.content`) + every selected tag chip. `_countTags(pages)` scans scope for chip pool (excludes `doc-note` tag itself; top-8 cap via `.slice(0, 8)`). Scoped-search button invokes Obsidian's `global-search:open` command pre-filled with `path:"<scopePath>"` — the escape hatch for full-body fuzzy search. **`ProjectDocsIndex`** (extended) mounts `DocSearch.render` at `recursive: true` cross-section scope above the section card row; the `allDocs` query gates on `DocSearch.matches` so dashboard doc-count chip + per-section meta counts both reflect the live filter. **`SectionHub`** (extended) mounts `DocSearch.render` at depth-appropriate scope (depth 1 `recursive: true` so the count covers sub-section docs; depth 2 `recursive: false` leaf); docs query + depth-1 sub-section card meta count gate on `DocSearch.matches`. `onChange` triggers full re-render via `dv.container.empty() + this.render(dv)` with `_currentCtx` carry-over so the active filter survives keystrokes.

**Pure additive — no migration required.** No schema changes, no frontmatter rewrites, no installer step, no contract bump. The cleanest cycle close in the recent arc.
