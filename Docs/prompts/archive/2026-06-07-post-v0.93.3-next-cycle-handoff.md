## CRITICAL — v0.93.3 contract redefinition

The original v0.93.3 design assumed `applyExternalPlugins` installs plugins from `external_plugins[]`. **It doesn't.** Per `platform/install.js:2693`: *"the installer cannot install Obsidian community plugins itself, so this is a detection-and-surface-up helper, not a remediation step."* Plugin install lives only in `platform/bootstrap.js`'s `phaseFetchPlugins` (the network-gateway), invoked on fresh-vault bootstrap.

Consequence:
- **Fresh bootstrap consumers** (`sauce bootstrap`) → new-tab-default-page + smart-connections auto-installed via phaseFetchPlugins reading every subscribed mechanism's `external_plugins[]`.
- **Existing consumer vaults** (`sauce update --bump-pins` after `brew upgrade sauce`) → both plugins NOT auto-installed. User sees two warning Notices and must manually install both via Settings → Community plugins. After the manual install, the next `sauce update` will run `applyCommunityPluginData` to scaffold new-tab-default-page's `data.json`.

Closing the existing-consumer gap is **the recommended v0.94.0 candidate** (below).
