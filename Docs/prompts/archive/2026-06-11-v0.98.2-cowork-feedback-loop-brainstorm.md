## The brainstorm task

Design v0.98.2 — the cowork feedback-loop closure cycle. The cycle must:

1. **Honor the vision.** Close the loop my vision describes: user ticks items + sets knobs + types prose → another job ingests the signal → relevant files get updated → all scheduled jobs adjust the next day. v0.98.1 built the capture surface; v0.98.2 builds the ingest + apply mechanism.
2. **Extend the workshop coherently.** New helpers, sub-skills, or schemas v0.98.2 introduces should fit the architectural posture already established (deterministic helpers carry structural shape; OI prose carries voice; orchestrators are thin coordinators; structural rules WIN over voice on conflict).
3. **Serve both vaults' long-term continuity.** Whatever v0.98.2 writes to consumer vaults should serve both Headspace and Accuris as they exist today, AND any future engagements either vault adds. The design must NOT bake assumptions specific to one vault's configuration into the platform code (vision § 5 generalizability dimension — "the same skill code serves any user with any setup with any needs"). At the same time, the design must NOT require either vault to re-bootstrap to a new structure just to benefit from v0.98.2 — long-term cohesion matters more than uniformity.
4. **Compose with v0.98.1's capture surface, not duplicate it.** v0.98.1 ships: stable item-IDs (`^item-<kind>-<7hex>` block-IDs on surfaced items in EOD compose-body output); per-item LIKE ticks; per-kind 3-position frequency knob (less/same/more); tagged fenced free-text block (` ```feedback…``` `); v=1 sentinel; sidecar observability field. v0.98.2 reads these.
5. **Respect the 4 user-content preservation safeguards** v0.98.1 installed (pre-deploy snapshot recipe, post-install diff verification, automated forbidden-paths CI guard at `scripts/check-files-forbidden-paths.js`, .bak tripwire). v0.98.2's design must NOT introduce any new `files[]` entry with a dest path under `context/<engagement-id>/`, `memory/`, `daily/`, `weekly/`, `monthly/`, `snapshots/`, or `summaries/` (Safeguard 3 will fail CI).
6. **Address the per-item DOWNVOTE question explicitly.** v0.98.1 deferred it as a v0.98.1.x candidate / v0.98.2 brainstorm seed. v0.98.2 brainstorm must land on a real decision — either ship the parallel "what I didn't like" row alongside the LIKE ticks, OR explicitly decide that downvote signal flows through the free-text + LLM ingest and document why.
