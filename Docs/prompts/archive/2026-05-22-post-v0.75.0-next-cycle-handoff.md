## Conventions reminder

- **Direct-push to `main`.** No feature branches unless a cycle has parallel streams that warrant them. Single linear history.
- **One commit per stage.** Follow-up commits allowed for catches within the same stage (e.g., S1 + S1 follow-up). Never squash post-hoc.
- **No Claude sign-off in commit messages.** Conventional-commits format: `type(scope): subject`. No `Co-Authored-By` lines unless the user explicitly requests it.
- **No `--no-verify`.** Hooks always run. If a hook fails, fix the underlying issue.
- **No `git add -A`.** Stage files explicitly by path.
- **Workshop self-install gates the release.** If `node platform/test/run-install.js .` fails, do NOT push to consumers.
- **`sauce update --bump-pins`** is the new consumer deploy step replacing the manual 4-vault pin-bump ritual (as of v0.75.0 / Workstream D). Workshop dogfood stays on `node platform/test/run-install.js .` until the self-vault detection patch ships.
- **JSON not YAML** for all platform metadata.
- **Template variables for paths** — never hardcoded.
- **No `file.mtime` reads** in any new code (landmine #23).
- **`customJS.X` is a singleton instance**, never a class constructor.
- **`cd` into consumer vaults** before `sauce update` — cwd determines the vault context.
