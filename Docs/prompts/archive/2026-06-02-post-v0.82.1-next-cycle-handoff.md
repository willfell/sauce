## Open carry-forwards from v0.82.1 (newly surfaced)

### FLN-v821-1 — V0750-VERSION exact-version assertions

`run-cowork-smoke.js` carries a `V0750-VERSION` exact-version pin asserting `cowork === X.Y.Z`. When cowork bumped at S8.1, this pin broke and required a manual edit. Structurally different from the floor-pin problem FLN-v81-1 solved: `versionAtLeast()` handles `>=` checks; `=== "x.y.z"` exact pins are not covered.

**Candidate fix:** extend `semver-helper.js` with `versionEquals(version, expected)` and refactor exact-pin sites to call it. Or audit each site and migrate to floor checks where semantically appropriate. ~2 stages.

### FLN-v821-2 — installItem version-skip + new in-loop mechanism interaction

When new logic is introduced INSIDE the per-item install loop (e.g., `resetSourceContributions`), the version-skip guard at `install.js:223` silently bypasses it unless the blueprint's version bumps. Discovered at S8: the production dogfood install short-circuited cowork's loop body entirely because cowork's version was unchanged. Required a co-occurring PATCH bump (S8.1) to validate end-to-end.

**Candidate fix:** plan-template addition mandating a co-occurring blueprint PATCH bump for any cycle touching `installItem`-internal logic. Or add a `--force-reinstall` mode flag to bypass the version-skip guard for a single dogfood run. Landmine #23 candidate.

### FLN-v821-3 — S0 verification pattern for cleanup FLNs

The v0.82.1 S0.3 divergent-bodies check caught a design-assumption error (two scope shapes, not one) before committing a buggy dedup key. The pattern deserves codification: any cleanup-style FLN touching an accumulator on real-world files should always enumerate all value shapes before writing any code.

**Candidate fix:** add a "S0 data-shape verification" protocol to the cleanup-cycle plan template or to `Docs/agent-guides/build-test-verify.md`. Doc-only; ~0 stages.
