## Carry-forwards explicitly out of scope this cycle

From v0.127.0 design § "Out of scope" — pre-staged for whichever cycle picks them up next:

1. **Click-to-edit on aggregator widget rows** — `ToDoDailyProjectGroups` + `ToDoDailyUnassignedMeetings` currently render rows as click-through-to-source-file. Extending them with a pencil-edit affordance requires multi-file writes (the edit needs to know which source file the row originated from + resolve `lineIdx` against that file's current content). Not blocking the v0.127.0 surface; deferred.

2. **Project To-Do click-to-edit** — `TodayCaptureEditableList` is already type-dispatched in shape; reusing it on Project To-Do notes with `sectionAnchor: 'ownedTasks'` gives `<Project> To-Do.md` the same edit UX with ~30 LOC of wiring. Trivial follow-up.

3. **Recurring registry edit** — recurring tasks live in `Recurring Tasks.md` with their own grammar (`every Wednesday`, etc.). The current `editExisting` mode in `ToDoCreateTask.open` forces `mode: 'one-shot'`. Extending the modal's recurring tab to accept an `editExistingRecurring: { filePath, lineIdx, parsed }` option would close this.

4. **Move-task-across-files via edit modal** — destination select is disabled in edit mode. Enabling it would require a `moveTask(oldFilePath, oldLineIdx, newFilePath, newPayload)` method on `TaskInteractions` that handles the read-delete-from-source + read-append-to-destination as a single atomic operation. Worthwhile but non-trivial.

5. **`applyArgsScrubBackfill` over `pantry/` workshop content** — intentionally not scrubbed in v0.127.0; `pantry/` is git-managed (landmine #18) and any heal-written change there gets clobbered on next `sauce update`. Deferred indefinitely unless a workflow change makes the workshop git-state non-canonical.

6. **`sauce update --bump-pins` does NOT auto-subscribe to NEW mechanisms.** v0.127.0 deploy required a manual add of `task-interactions` to each vault's `ranch/platform-subscription.json` because `--bump-pins` only advances EXISTING pins. Carry-forward: extend `--bump-pins` (or `sauce wizard`) to detect that a blueprint's `depends_on` references a mechanism not in the consumer's subscription and offer to auto-add it. Low priority; the manual step is a one-line edit, but it's a footgun for first-time cycle deploys.
