## Recommended next cycle: v0.94.0 — `applyExternalPluginInstall`

**Closes the v0.93.3 existing-consumer install gap.** v0.93.3 added new-tab-default-page + smart-connections to mechanism `external_plugins[]` but the install pass can only WARN about missing plugins; it can't INSTALL them. The bootstrap pass CAN install them but only runs on fresh-vault first-install. v0.94.0 adds a new helper `applyExternalPluginInstall` that runs per-item in the install loop, fetches missing plugins (mirroring bootstrap's `phaseFetchPlugins`), and appends to `.obsidian/community-plugins.json`.

After v0.94.0 ships:
- `sauce update --bump-pins` auto-installs v0.93.3's two declared plugins on existing consumers.
- The v0.93.3 "manual Settings → Browse → Install" workflow becomes a one-time historical artifact.
- Future cycles can confidently use `external_plugins[]` as a declarative install primitive.

**Workshop versioning**: probably `0.93.3 → 0.94.0` MINOR (new install behavior). No mechanism bumps required (platform-side helper).

**Alternatives if user redirects**: v0.94.1 (Echoes-warning reword), v0.94.2 (platform de-personalization), v0.95.0 (connector/knob ergonomics — the BIG one), v0.95.1 (vault-config schema migration), v0.96.0+ (cross-machine wrapper alignment). All originally catalogued in the prior state doc; resequenced in the post-v0.93.3 state doc § 4.
