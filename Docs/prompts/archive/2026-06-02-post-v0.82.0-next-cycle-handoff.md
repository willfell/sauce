## Open carry-forwards from v0.82.0 (newly surfaced)

### FLN-v82-1 (HIGH PRIORITY) — engagement-type accessibility

Engagement-type JSON manifests (`platform/blueprints/cowork/engagement-types/*.json`) are declared in cowork's `engagement_types[]` but NOT in `files[]` — they never materialize to consumer vaults. The midday-tripwire orchestrator's SKILL.md says "Load engagement-type manifest" but there's no canonical path for the agent to read it from on the consumer side. Default-to-`[]` → silent exit.

**Three candidate designs** (described in v0.82.0 result doc §"WS-C investigation finding" and exit handoff §"FLN-v82-1"):

**(a) Materialize JSONs into consumer vaults (RECOMMENDED).** Add engagement-types/*.json to cowork's `files[]` so they land at e.g. `spice/cowork/context/engagement-types/*.json`. Update midday-tripwire/SKILL.md (and any other orchestrator that consumes the manifest) to reference the materialized path. Pure additive; visible install surface change. Likely 5-7 stages: failing test → manifest entries → orchestrator path edits → version bump → cycle-close.

**(b) Embed `tripwire_aspects` + other runtime fields per-engagement in vault-config.md.** `cowork:bootstrap-vault` seeds defaults from manifest at bootstrap time. Cleanest user-facing model; requires bootstrap-vault skill edits + vault-config schema bump. Larger scope (~10 stages).

**(c) Hardcode aspect mappings per engagement type into the orchestrator SKILL.md.** Least elegant; minimal scope (~3 stages). Tightly couples orchestrator to engagement-type catalog.

**Recommendation: option (a)** — pure additive, doesn't touch user content, mirrors how mcp-skill-map.json was handled (materialized to `spice/cowork/context/mcp-skill-map.json`). Will fix the accuris midday-tripwire silent no-op once vault re-runs install.

### FLN-v82-2 — ranch/rules/cowork.json dedup

Install appends rather than dedupes `rule_fragments`. Every dogfood run adds ~15 path_glob fragments (each fragment ~40 lines). HEAD-of-v0.82.0 has 14 duplicate copies per path_glob; file is ~7900 lines. Pre-existing bug since at least v0.78.0 (every cycle's S9 commits the same ~+630-line delta). Doesn't break preflight (semantic dedup likely happens at rule-evaluation time) but file size keeps growing.

**Fix candidate:** add unique-key dedup at install-time. Probably in the rules-merge layer in `platform/install.js` (or wherever `applyRuleFragment` lives). One-time cleanup commit to truncate the existing duplicates. Low risk; high cleanup value. ~3-4 stages.

### FLN-v82-3 — parseYamlIsh hyphen-key support

Pre-existing limitation in `platform/blueprints/cowork/helpers/context-builder-dry-run.js` line 35: flat-key regex `^([a-z_]+):` silently drops keys with hyphens. Custom kinds with hyphens (e.g., `lharries-whatsapp`, `sharepoint-online`) can't appear in `user-preferences.md` today.

**Fix candidate:** widen the regex to `^([a-z_][a-z0-9_-]*):`. One-line code change + tests. ~2 stages.
