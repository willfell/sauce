### FLN-v83-2 — `sauce update --bump-pins` doesn't reliably bump blueprint pins

Reproduced post-v0.83.0 deploy on accuris (other machine): `sauce update --bump-pins` bumped the workshop pin (0.81.1 → 0.83.0) but the cowork blueprint subscription pin stayed at 0.21.1 (workshop catalogue had moved to 0.22.0). The install loop correctly refused to process cowork: `[Notice] platformInstall: skipping cowork — subscription pins cowork@0.21.1 but workshop has 0.22.0`. Workaround: manually edit `ranch/platform-subscription.json` to set cowork = 0.22.0, then re-run `sauce update` (no `--bump-pins` needed). Inconsistent across machines — on the WORKSHOP-MACHINE accuris-sauce, `--bump-pins` DID bump the subscription pin to 0.22.0 (but installed.json still records 0.21.1, suggesting a separate install-loop completion gap).

**Candidate fix:** audit `platform/cli/cmd-update.js` `--bump-pins` flag handling. The flag likely walks workshop catalogue + writes pin updates, but blueprint pin updates may be missed when the consumer's prior pin is N-2 or N-3 behind (skip-major case) or when the JSON serializer drops nested mutations. Repro: take a vault at workshop 0.81.x + cowork 0.21.1 (multi-cycle-behind), run `sauce update --bump-pins`, observe subscription pin staying at 0.21.1. ~2-3 stages including the cross-machine repro fixture. PATCH posture.
