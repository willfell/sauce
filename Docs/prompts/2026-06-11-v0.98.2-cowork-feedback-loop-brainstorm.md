## Three structural gaps the v0.98.2 brainstorm MUST acknowledge

These were surfaced by the post-v0.98.1 audit. They contradict things `Docs/cowork-ecosystem.md` describes as load-bearing. v0.98.2 needs to either fix them, work around them, or formally retire the concepts that depend on them:

### Gap 1 — No `personality.md` files anywhere

`Docs/cowork-ecosystem.md` documents `spice/cowork/context/<engagement>/personality.md` as a per-engagement voice file. **It does not exist on disk for any engagement on either vault.** Personality content currently lives inline inside `brand-voice.md` + `working-style.md` + the `user-preferences.personality.notes` block.

v0.98.2 implication: when the reconciler proposes voice/personality changes (per the user's vision: "another job took what i liked, what i didn't like, my feedback, then updated the relevant files"), where do they get written? Options:
- Append to existing `brand-voice.md` (gentlest — already there)
- Append to `user-preferences.personality.notes` (config-side)
- Create new `personality.md` (introduces a new authoritative-voice file — schema change)
- Use a new dedicated `spice/cowork/memory/<engagement>/voice-deltas.md` proposed-changes file (most conservative)

### Gap 2 — No `microscopes/` directories anywhere

`Docs/cowork-ecosystem.md` describes per-kind microscopes at `spice/cowork/context/<engagement>/microscopes/<kind>.md` owning the per-kind output-shape contract. **They don't exist on disk for any engagement on either vault.** Either microscopes are inline in `user-preferences.md` / OI prose / engagement context files, or the per-kind output-shape contract isn't actually being enforced from a per-engagement file (which would be a generalizability gap — every engagement renders the same per-kind shape).

v0.98.2 implication: when the reconciler proposes per-kind output-shape changes ("surface fewer Diana emails", "show ADO stories with story-id-first formatting"), where do they get written? If microscopes don't exist, v0.98.2 might need to materialize them. Or alternatively, the per-kind contract lives in `user-preferences.md` and microscopes are a fiction that should be retired.

Investigation step v0.98.2 brainstorm should do FIRST: grep the actual orchestrator-instructions + sub-skills to see where per-kind output shape is ACTUALLY enforced today (`grep -rn "microscope" platform/blueprints/cowork/content/data/ platform/blueprints/cowork/skills/`). Ground truth before designing.

### Gap 3 — No `learned_weights.json` files for any engagement on either vault

`Docs/cowork-ecosystem.md` describes `spice/cowork/memory/<engagement>/learned_weights.json` as the durable per-engagement weight state — the file the reconciler reads + writes, the file that tomorrow's brief consults for kind ordering. **It does not exist on disk for any engagement on either vault.** Only the skeleton template is present at `spice/cowork/context/engagement-shared-templates/learned_weights-skeleton.json`.

**This is the biggest finding.** The feedback loop the user is asking to enhance **may not actually be running yet**. Either:
1. The reconciler has never fired on either vault
2. The reconciler is firing but writing somewhere other than the documented path
3. The reconciler is configured to fire but failing silently
4. The reconciler isn't actually wired into the cron schedule for these vaults

v0.98.2 implication: before designing "another job that takes feedback and updates files," verify the existing job (`cowork:learn-from-checks`) is actually running. If it isn't, v0.98.2 may need to FIRST wire up the reconciler properly before adding the v0.98.2 ingest sub-skill on top. The brainstorm should explicitly confirm this state before designing.

Investigation step v0.98.2 brainstorm should do EARLY: check the active cron schedule (`/cowork sync-scheduled-jobs` to inspect, OR examine `spice/cowork/scheduled-jobs.md` if present on the consumer vault); examine `spice/cowork/context/reconciler-log.md` in each vault to see if the reconciler has ever fired; check whether the consumer vault has run `sauce update --bump-pins` recently to pick up the v0.96.0+ reconciler.
