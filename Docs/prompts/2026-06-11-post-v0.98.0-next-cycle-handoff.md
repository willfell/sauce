## Open questions for v0.98.1 brainstorm (resolve at cycle open)

Per v0.98.0 design § Forward arc:

1. **Frequency knob granularity** — 3-way (`less / same / more`) or 5-way (`much-less / less / same / more / much-more`)?
   - 3-way is simpler to grade in the briefs and to ingest in v0.98.2 (single signed signal per kind). 5-way gives finer-grain signal but requires the user to make more nuanced judgments per cadence.
   - Lean: 3-way to start; 5-way is an additive v0.98.2.x candidate IF the 3-way signal proves too coarse.

2. **Rail L on non-EOD cadences** — yes/no, and if yes, what shape?
   - Today's Rail L (`[!todo]+ Was today useful?`) fires only at EOD. v0.98.1 expansion could keep that posture OR add a one-tap "this brief was useful: [ ] yes [ ] no" on every cadence.
   - Lean: keep Rail L EOD-primary; add a lightweight one-tap on MB / midday for the cadences with the highest brief-write velocity; do NOT add to weekly/monthly (low-volume, already reflective).

3. **Free-text encoded as a fenced code block** (recommended; parse target = content between triple-backticks after the sentinel) — confirm.
   - Fenced code block is the simplest parse target (greedy regex against the sentinel + the next triple-backtick block). Alternative would be raw blockquote prose under a sub-section, but parsing prose is fragile.
   - Lean: confirm fenced code block; sentinel = `<!-- cowork:feedback-capture v=1 -->` HTML comment at top of Rail L.

### v0.98.1 questionnaire expansion + free-text capture (NEXT)

Per v0.98.0 design § Forward arc:

- **Stable item-IDs.** Compose-body emits each surfaced person-block / PR-row / ADO-story-row with a trailing `^item-<stable-key>` block-ID. Key = `hash(kind + identifier)` — day-stable so longitudinal signal accrues. Block-IDs render invisibly in reading mode.
- **New Rail L shape.** Per-item ticks (one checkbox per surfaced item, wikilink to the block-ID) + per-kind frequency knobs (`less / same / more` checkboxes) + free-text fenced code block + sentinel HTML comment.
- **Sentinel for v0.98.2 parse.** HTML comment `<!-- cowork:feedback-capture v=1 -->` at top of the Rail L callout. v0.98.2 reconciler greps for the sentinel + parses the markdown structure beneath it.
- **Surfaces hit (sketch).** compose-body output contract gains item-ID emit rules; NEW helper `composeFeedbackCapture(plan, surfaced_items)` builds the Rail L sub-callouts; 5 cadences' Rail L body updates (eod-review primary; the other 4 cadences' Rail L stays kind-level OR gains a one-tap "this brief was useful: [ ] yes [ ] no" per Q2 above).
- **`learned_weights` schema stays at version 2** for v0.98.1 (capture only — no writes yet). v0.98.2 bumps to 3.

### v0.98.2 reconciler free-text + per-item-tick ingest (queued)

- **Trigger.** Reconciler fires on existing cadence (daily during warmup, weekly post-warmup). Reads the last N days of EOD reviews + any cadence brief carrying a `<!-- cowork:feedback-capture v=1 -->` sentinel.
- **Parse structured signal (deterministic).** Per-item ticks → looked up against the item-ID hash registry → rolled up per-kind, per-person, per-channel weight nudges. Frequency knobs → direct weight delta.
- **Parse free-text (LLM pass).** NEW sub-skill `cowork:ingest-feedback` runs an LLM pass (Sonnet 4.6 — cost-fast, open question) with a structured-output prompt: "Read this user's feedback prose. Extract structured intents: (a) per-person/channel/topic uprank/downrank, (b) voice corrections, (c) coverage gaps, (d) other. Return as deltas with proposed write-targets."
- **Apply with audit trail.** Deltas logged to `spice/cowork/memory/<engagement>/feedback-deltas.md`. Numeric updates: applied directly. Microscope `what_matters` strings: append-only. Personality/voice changes: PROPOSED only — surface in next-day morning brief as a callout. Coverage gaps: written to `spice/cowork/memory/<engagement>/coverage-queue.md`.
- **Sizing.** MINOR; needs full brainstorm + design phase.

## 7-day quality observability window (post-v0.98.0 deploy)

Per v0.98.0 result doc § Post-deploy operational sequence:

- **Synopsis word count distribution.** Target: 50-60 words; hard cap 80. Grade overshoots as v0.98.0.x PATCH candidate. Real-world LLM behavior under the new contract is the open question.
- **First-sentence concrete-token presence.** PR#, person + decision, inbound + ask. The HC-V0980-SYNOPSIS-A5 assert pins this at the helper-fixture layer; live briefs need eyeball grading.
- **Cross-kind connective tissue.** When the day has cross-kind dependencies (e.g., "Zhenzhen's PR #353 → blocking content-registry-prod → which gates today's 10am with Stefan"), does the synopsis thread them as connective tissue or enumerate per-kind?
- **Empty-day fallback prose quality.** On a genuinely quiet day (no actionable items, no inbox debt, no blocking calendar conflicts), does the synopsis say "Quiet day —" plainly or pad?
- **Per-kind callout default-collapsed semantics.** Verify across all 5 cadences (visual check in Obsidian — every `[!<type>]-` callout renders collapsed by default; click expands).

If any regression, file v0.98.0.x PATCH candidate. Structural regressions (lead callout missing / closing callout re-emerges / per-kind callouts back to `+`) are caught by HC-V0980-* + the 9 compose-body golden fixtures and should never escape preflight. Prose-quality regressions (synopsis lecture-mode instead of prediction-mode) require live grading.
