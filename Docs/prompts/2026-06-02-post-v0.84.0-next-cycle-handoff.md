## Open carry-forwards from v0.84.0 (newly surfaced)

### FLN-v84-1 — Tier 2 (weekly synthesis) + Tier 3 (monthly synthesis)

v0.84.0 shipped Tier 0 + Tier 1. The cowork memory architecture has 4 tiers; Tier 2 + Tier 3 are specified in the v0.84.0 design doc but deferred. Tier 2: a `cowork:synthesize-week` orchestrator reads the past 7 daily summary callouts and produces a weekly roll-up note at `spice/cowork/memory/<engagement_id>/YYYY-Www.md`. Tier 3: a `cowork:synthesize-month` orchestrator reads weekly summaries for the month and produces a monthly roll-up.

**Candidate:** v0.85.0 MINOR. Could bundle with FLN-v84-2 (other-orchestrator wire-throughs) in a single v0.85.0 MINOR if the scope stays manageable (~4-6 stages for Tier 2 alone; Tier 3 adds ~2 stages).

### FLN-v84-2 — wire-through to midday-tripwire / eod-review / weekly-review / monthly-review

`cowork:morning-briefing`'s step 3a wire-through shipped in v0.84.0. The four remaining atomic-note orchestrators (`midday-tripwire`, `eod-review`, `weekly-review`, `monthly-review`) could each read recent memory via a parallel pre-flight step. Each needs its own pre-flight step + body composition update (same pattern as morning-briefing step 3a; copy-and-adapt). Null-data gating applies here too.

**Candidate:** v0.85.0 MINOR. Could bundle with FLN-v84-1. Risk: if bundled, the stage count grows to ~8-10 — may be worth splitting into separate MINOR cycles (v0.85.0 Tier 2/3; v0.86.0 other-orchestrator wire-throughs).

### FLN-v84-3 — memory retention / compression policy

Memory files accumulate indefinitely. At 1-2 ticks/day × ~50 lines/tick, a year-long active engagement accumulates ~73k lines across 365 daily files. A rolling summarization (e.g., compress ticks older than 30 days into their daily summary only; compress daily summaries older than 90 days into their weekly summary only) or date-based archival policy will eventually be needed.

**Candidate:** design-only cycle first; no harness changes until compression logic is scoped. Long-term.

### FLN-v84-4 — Smart Connections semantic retrieval over memory notes

`spice/cowork/memory/**` is a natural corpus for semantic similarity queries. A future cycle could wire `sc-bridge` (or equivalent) to surface relevant past context beyond the most-recent-file read (e.g., "what was happening 3 weeks ago on this engagement when the project was in planning?"). Aligns with the Smart Connections candidate noted in project machine memory.

**Candidate:** long-term; depends on sc-bridge stability + user adoption of the memory layer.
