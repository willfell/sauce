# Cowork orchestrator — reconcile-cowork

## Substitution tokens

**Static (substituted at sync time):**
- `{{$engagement_id}}`, `{{$engagement_label}}`, `{{$timezone}}`
- `{{$workshop_version}}`, `{{$cowork_version}}`, `{{$contract_version}}`
- `{{$cadence}}` — fixed to `reconcile-cowork`

**Fire-time (literal in wrapper; LLM resolves at fire time via PRELUDE):**
- `{{$today_date}}`, `{{$today_weekday}}`, `{{$today_dirpath}}`
- `{{$yesterday_date}}` — yesterday's YYYY-MM-DD ISO in {{$timezone}}
- `{{$yesterday_dirpath}}` — yesterday's `<YYYY>/<MM-Month>/<YYYY-MM-DD>`

## Steps

### Step 0 — Pre-flight

1. Confirm `mcp__<obsidian>__obsidian_get_file_contents` is connected.
2. Read `spice/cowork/context/vault-config.md` frontmatter. Locate engagement record matching `id: "{{$engagement_id}}"`. Capture engagement.
3. Resolve `today_date`, `today_weekday`, `today_dirpath` from current date in `{{$timezone}}`. ALSO resolve `yesterday_date` (today - 1 day) and `yesterday_dirpath` for the scan target.

### Step 1 — List yesterday's atomic notes

4. Invoke `mcp__<obsidian>__obsidian_list_files_in_dir` on `spice/cowork/daily/{{$yesterday_dirpath}}/`. Capture list of `.md` files + `.cowork.json` files.

   If the directory doesn't exist (no atomic notes fired yesterday): SKIP to Step 8 (heartbeat check); reconciler-log will note "no notes scanned".

### Step 2 — Backfill missing sidecars

5. For each `.md` file in yesterday's directory:
   a. Check if companion `.cowork.json` exists at the same dirpath.
   b. If MISSING: read the `.md` content via `obsidian_get_file_contents`. Parse the frontmatter (look for `type:` and `engagement_id:`). If `engagement_id != "{{$engagement_id}}"`, skip this file (not our engagement's note).
   c. Extract `surfaced_kinds[]` by scanning the body for `> [!example]+` and `> [!warning]+` callout headers. Apply heuristic kind-inference:
      - title contains "Calendar" → kind: `calendar`
      - title contains "Email" / "Gmail" / "Inbox" → `email`
      - title contains "Chat" / "Teams" / "Slack" → `chat`
      - title contains "Message" → `messages`
      - title contains "Finance" / "Debt" / "Scoreboard" → `finance`
      - title contains "Project" / "Kanban" → `projects`
      - title contains "Thread" → `threads`
      - title contains "GitHub" / "Pull Request" → `github`
      - title contains "ADO" / "Work Item" → `ado`
   d. Compose sidecar JSON (per the canonical schema from `{{shared.sidecar_schema_template}}`):
      - `generated_by: "<orig generator> (reconciler-backfill@0.97.1)"` (use the .md's `generator` frontmatter as orig; fallback `"cowork:unknown@?"`)
      - `generated_at`: file mtime if available; else now
      - `cadence`: from `CADENCE_BY_TYPE` mapping
      - `frontmatter`: mirror of the .md frontmatter
      - `surfaced_kinds`: as computed
      - `surfaced_items: []` (items unrecoverable from prose without LLM running gather)
      - `render_aspects_applied: []`
      - `memory_used: { yesterday_present: false, drift_warning_present: false, echoes_count: 0 }`
      - `plan_dispatch: { mode: "reconciler-backfill", kinds_dispatched: <count>, warnings_emitted: 0 }`
   e. Write the sidecar via `obsidian_put_content` to the corresponding `.cowork.json` path.

### Step 3 — Parse rating callouts

6. For each `.md` file in yesterday's directory belonging to `{{$engagement_id}}`:
   a. Read content (or reuse from Step 5 if already loaded).
   b. Find the rating callout sentinel: `<!-- cowork:rating-block schema=1.0.0 cadence=<X> day=<Y> -->`
   c. If sentinel present, scan upward from the sentinel for `> - [x] Kind` and `> - [ ] Kind` lines. Build observations: `{ kind: <lowercase>, ticked: <bool> }` per line.

7. Aggregate observations across all of yesterday's notes per kind. Compute `tick_count` and `skip_count` per kind.

### Step 4 — Update learned_weights

8. Read `spice/cowork/context/user-preferences.md` frontmatter via Obsidian MCP. Parse `learned_weights:` block (may be absent → initialize skeleton; may be legacy single-engagement shape → migrate to nested per v0.96.1).
9. Locate `learned_weights.engagements["{{$engagement_id}}"]`. If absent, create skeleton:
   ```yaml
   per_kind: {}
   totals:
     notes_scanned: 0
     notes_with_any_tick: 0
     warmup_until: "{{$yesterday_date}} + 7 days, ISO"
     upgrade_notice_emitted: false
     scanned_days: []
   ```
10. Apply update formula per kind that surfaced an observation:
    ```
    w_old = current weight (default 1.00)
    w_raw = w_old * 0.98 + 0.15 * (tick_count - 0.5 * skip_count) / (tick_count + skip_count + 5)
    w_new = clamp(w_raw, 0.10, 3.00)
    round w_new to 3 decimal places (banker's rounding for half-to-even)
    ```
    Update `per_kind[<kind>]`:
    ```
    weight: w_new
    ticks: prev.ticks + tick_count
    skips: prev.skips + skip_count
    warmup: prev.warmup
    last_updated: "{{$yesterday_date}}"
    ```
11. Evaluate warmup graduation: for each kind, if `days_since_first >= 7` AND `ticks + skips >= 7`, set `warmup: false`.
12. Update totals:
    - `notes_scanned += <yesterday's note count>`
    - `notes_with_any_tick += <count of notes with at least 1 [x]>`
    - `scanned_days.push("{{$yesterday_date}}")` (dedup-aware)

### Step 5 — Write .bak + updated user-preferences.md

13. Read current user-preferences.md content. Write it verbatim to `spice/cowork/context/user-preferences.md.bak` via `obsidian_put_content`. (Backup before rewrite.)
14. Compose new frontmatter — replace ONLY the `learned_weights:` block, preserve all other top-level keys (`priorities`, `personality`, `mcps`, etc.). Use this serialization for `learned_weights:`:
    ```yaml
    learned_weights:
      schema_version: "1.1.0"
      engagements:
        <engagement_id>:
          per_kind:
            <kind>: { weight: <num>, ticks: <int>, skips: <int>, warmup: <bool>, last_updated: "<YYYY-MM-DD>" }
            ...
          totals:
            notes_scanned: <int>
            notes_with_any_tick: <int>
            warmup_until: "<ISO>"
            upgrade_notice_emitted: <bool>
            scanned_days: [<list>]
        <other_engagement_id (if multi-engagement vault)>:
          ... preserve other engagements' blocks exactly ...
    ```
15. Write the updated user-preferences.md via `obsidian_put_content`.

### Step 6 — Heartbeat check (walk 30-day sidecar window)

16. Build expected_cadences[] from `engagement.cadences`:
    - if `morning` → `morning-briefing`
    - if `midday` → `midday-tripwire`
    - if `eod` → `eod-review`
    - if `weekly` → `weekly-review`
    - if `monthly` → `monthly-review`
    - if `lens_shift` → `lens_shift`

17. For each day in the last 30 days:
    a. Compute dirpath: `spice/cowork/daily/<YYYY>/<MM-Month>/<YYYY-MM-DD>/`
    b. Invoke `obsidian_list_files_in_dir` on that dirpath (if exists).
    c. For each `.cowork.json` file, read via `obsidian_get_file_contents`. Parse JSON. Extract `frontmatter.type` + `generated_at`.
    d. Map frontmatter.type to cadence per `CADENCE_BY_TYPE` (cowork-morning-briefing → morning-briefing; cowork-morning-briefing-cold → lens_shift; etc.).
    e. If `engagement_id` matches and cadence is in expected_cadences, track `last_fire_at[<cadence>] = max(prior, generated_at)`.

18. Evaluate freshness per cadence:
    - Windows: morning-briefing/midday-tripwire/eod-review/capture-tick = 36h; weekly-review/synthesize-week/lens_shift = 192h; monthly-review = 840h.
    - missed = [cadence for cadence in expected_cadences where last_fire_at[cadence] is absent OR `(now - last_fire_at[cadence]) > window_hours`]

### Step 7 — Emit heartbeat warning callout (if any missed)

19. If `missed.length > 0`:
    a. Read today's `spice/cowork/memory/{{$engagement_id}}/{{$today_dirpath}}/memory.md` via `obsidian_get_file_contents`. (If absent, skip this step — synthesize-day creates memory.md; reconciler doesn't.)
    b. Compose callout body:
       ```markdown
       > [!warning]+ Cron heartbeat anomaly — {{$today_date}}
       > <intro per first_fire flag>
       > - **<cadence>**: <last fired XXX OR never fired> (expected: within <window_hours> hours)
       > - ...
       >
       > Investigate the scheduled-job configuration in claude.ai's Cowork UI, or run `/cowork sync-scheduled-jobs <engagement_id>` to refresh the paste-blocks. Confirm the job's task ID exists + is enabled.
       ```
       If `first_fire == true` (no sidecars found ANYWHERE in the 30-day window), use intro: `> No v0.96.0+ sidecars found yet — this may be the first post-upgrade fire. Revisit tomorrow to confirm.`
       Else: `> Some scheduled cadences haven't fired within their expected windows:`
    c. Locate existing `> [!warning]+ Cron heartbeat anomaly` callout in memory.md (regex). If present, REPLACE it. Else, append after the synthesis section (before `## Ticks` if present, else at end).
    d. Write updated memory.md via `obsidian_put_content`.

### Step 8 — Append reconciler-log entry

20. Read `spice/cowork/context/reconciler-log.md` via Obsidian MCP (may not exist; treat as empty).
21. Compose new entry:
    ```markdown
    ## {{$today_date}} 03:00 MT (run-id: rl-{{$today_ymd_compact}}-0300)
    **Engagement processed:** {{$engagement_id}}
    **Yesterday processed:** {{$yesterday_date}}

    **Sidecar status:**
    - <N> atomic notes scanned
    - <M> sidecars backfilled
    - <K> sidecars validated GREEN

    **Rating callouts:**
    - <N> notes had rating-block sentinel; <M> notes missing sentinel
    - Aggregated observations: <kind1>: <t> ticks / <s> skips; ...

    **learned_weights update:**
    - <kind1>: <before> → <after>
    - ... per kind delta if non-trivial
    - <K> kinds graduated out of warmup

    **check-heartbeat:**
    - <GREEN | N missed cadences>
    ```
22. Prepend new entry to existing log content. Split content on `^## ` headers; cap to last 30 entries (prepend mine, slice to 30).
23. Compose full file with frontmatter `---\ntype: cowork-reconciler-log\n---\n\n# Reconciler log\n\n` + entries joined.
24. Write via `obsidian_put_content`.

### Step 9 — Done notice

25. Emit Obsidian Notice: `cowork:reconcile-cowork complete -- {{$engagement_label}} {{$today_date}} | <N> sidecars backfilled | <K> learned_weights deltas | <heartbeat verdict>`.

## Idempotency

Re-runs the same day are safe:
- Sidecar backfill: idempotent (only creates `.cowork.json` if absent)
- learned_weights update: applies update formula to fresh weight; same observations would compound on re-fire — skip if today's date is already in `scanned_days[]`.
- check-heartbeat: idempotent — regex-replaces prior callout in memory.md
- reconciler-log: idempotent — checks if today's run_id already in log, skips append if so

## Failure modes

- Yesterday's daily dir doesn't exist (no notes fired) → SKIP Steps 2-5 entirely; still run heartbeat (Steps 6-7) which is the whole point on a "nothing fired" day.
- user-preferences.md unreadable → abort with `failed:contract-violation:prefs-unreadable`. Heartbeat + reconciler-log still attempted.
- memory.md absent → heartbeat warning is not written (no memory file to attach to). Surface in reconciler-log instead.
- Sidecar walk hits a corrupt JSON file → skip + log warning; don't abort.

## Performance

~50-160 MCP calls per fire per engagement. Bounded by 30-day sidecar walk size. Acceptable for nightly automation.
