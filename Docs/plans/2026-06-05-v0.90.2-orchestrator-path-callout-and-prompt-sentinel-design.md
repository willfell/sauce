## 0. Why this cycle

Two live-runtime failures observed this morning on the v0.90.1 deploy:

1. **Output-path failure (accuris, willfell laptop machine):** scheduled morning briefing on accuris wrote the atomic note to `spice/daily/2026/06-June/Friday-2026-06-05.md` (the daily-blueprint path) instead of `spice/cowork/daily/2026/06-June/2026-06-05/morning-briefing.md` (the cowork atomic-note path). The LLM read the consumer vault's CLAUDE.md row `| Daily | spice/daily | /daily |` and conflated the daily-blueprint path with the cowork atomic-note path. The orchestrator's frontmatter description, intro paragraph, and Step 16 sub-skill invocation all name the correct path explicitly — but the LLM didn't process those: it short-circuited after composing the body, wrote to its guessed path, and never invoked `cowork:write-run-note-morning-briefing`. The LLM's own self-diagnosis admitted: *"the orchestrator I read didn't invoke any write sub-skill - it just described the content to compose"* — false; the SKILL.md has the invocation at Step 16 — meaning the LLM didn't read that far.

2. **Empty-prompt-body false-positive (accuris, this machine):** scheduled morning briefing on accuris wrote a stub note because the LLM treated the v0.4.0 installer-default user-prompt body (a single instructional blockquote *"Vault-editable prompt for cowork:morning-briefing. Edit the body to customize..."*) as "non-empty content" and short-circuited to Step 10's empty-prompt stub branch WITHOUT trying the engagement-template fallback. Headspace's user-prompt has identical content but headspace's LLM session that morning fell through correctly. This is LLM-behavior variance on an ambiguous prompt body. FLN-v90-2 was queued at v0.90.0 close; v0.90.2 closes it.

Both failures share a root cause: **LLM attention truncates before reaching key SKILL.md steps OR mis-interprets ambiguous content**. The fix is structural — make the critical path / write-sub-skill / empty-prompt instructions impossible to miss even if the LLM only reads the top of the SKILL.md.

## 1. Fix A — CRITICAL output-path callout at TOP of 5 orchestrator SKILL.md files

Insert `[!warning]+ CRITICAL: output path (v0.90.2)` callout block at the TOP of each of:
- `morning-briefing/SKILL.md`
- `midday-tripwire/SKILL.md`
- `eod-review/SKILL.md`
- `weekly-review/SKILL.md`
- `monthly-review/SKILL.md`

Position: immediately after the `---` closing the YAML frontmatter, BEFORE the `# cowork:<orchestrator>` H1 heading. First text the LLM reads after parsing frontmatter.

Callout shape (parametrized per orchestrator — substitute `<orchestrator>` and `<write-sub-skill>`):

```markdown
> [!warning]+ CRITICAL: output path (v0.90.2)
> This orchestrator writes ONE atomic note to:
>
> `spice/cowork/daily/<YYYY>/<MM-Month>/<YYYY-MM-DD>/<orchestrator>.md`
>
> DO NOT write to `spice/daily/<YYYY>/<MM-Month>/<weekday>-<YYYY-MM-DD>.md` — that's the daily-note blueprint (a separate surface for hand-edited daily notes), NOT this orchestrator's output. The consumer vault's CLAUDE.md may list `spice/daily/` under the "Daily" topic in its resolver table; THAT IS NOT WHERE COWORK ATOMIC NOTES GO. The cowork atomic-note path is fundamentally different from the daily-blueprint path.
>
> The write happens via sub-skill `cowork:<write-sub-skill>` (READ its SKILL.md before invoking). NEVER write the atomic note directly via the `Write` tool, the `Edit` tool, or `mcp__obsidian__obsidian_put_content` from this orchestrator body — ALWAYS delegate to the write sub-skill which enforces the path + frontmatter + structural-marker contracts.
```

Substitution per file:

## 5. Risks

1. **Fix A is prose-only and depends on LLM attention.** A callout block at the top of a 300-line file should be unmissable, but LLMs can still skip prominent content. Mitigation: callout uses `[!warning]+` (the most attention-grabbing Obsidian callout type) + the title says "CRITICAL" + the body explicitly cites the failure mode + names the trap (CLAUDE.md `spice/daily/` row). If LLMs continue mis-writing, escalate to a non-prose fix (e.g., a write-guard in the write-run-note sub-skill that aborts if invoked from outside the orchestrator's expected call path).

2. **Fix B's sentinel pattern is fragile to v0.4.0 default-text drift.** If a future version of the installer changes the default blockquote text, the sentinel detection breaks. Mitigation: the sentinel detection is ONE branch in a fallback chain; if pattern doesn't match, Step 10 proceeds with the existing logic. No regression. Plus B.2/B.3 makes future fresh installs avoid the sentinel entirely.

3. **`materialize_once: true` change is asymmetric.** Existing vaults' prompt files stay as they are; only fresh installs get the truly-empty prompts. Existing accuris/headspace need either (a) manual user customization (we did this for accuris earlier today) OR (b) rely on B.1 runtime sentinel detection. Both are addressed.
