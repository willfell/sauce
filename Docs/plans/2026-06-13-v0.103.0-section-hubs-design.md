# v0.103.0 — section hubs (hierarchical navigation tree)

## TL;DR

v0.102.0's single-page Confluence-style Docs Hub renders ALL sections as buckets on one note. User observation post-dogfood: "I can't tell what's in which section." Reframe: each section becomes a first-class entity with its own hub note. `Docs.md` becomes a sections INDEX (lists sections, doesn't list docs). Each section folder contains a `<Section Name>.md` hub note that lists THIS section's docs + sub-sections + has its own + New Doc / + New Sub-Section buttons. File system mirrors the hierarchy, capped at 2 nesting levels (project → section → sub-section → docs). Templates ensure breadcrumb navigation on every node.

## Decisions (locked at brainstorm, 2026-06-13)

| Question | Decision |
| --- | --- |
| Nesting depth | 2-level cap: project → section (depth 1) → sub-section (depth 2) → docs. After depth 2, only docs can be added. |
| Docs.md landing content | Section cards + quick `+ New Doc` shortcut (prompts for section + title) + dashboard widgets (open meetings, kanban summary, status). NO recent-docs panel. |
| Section Hub anatomy | Minimal — breadcrumb header + `+ New Doc` (presetPrompts: this section) + `+ New Sub-Section` (only depth 1) + sub-section cards (depth 1) + doc cards. |
| Migration of existing v0.102.0 vaults | Auto-create section hubs for every existing section folder + heal Docs.md to new sections-index template + migrate frontmatter from string to wikilink form. Idempotent. |
| Section identity | Wikilink everywhere — doc-note `section: "[[Knowledge]]"`, project `sections: ["[[Knowledge]]", ...]`. Migration rewrites the v0.102.0 string form. |
| Breadcrumb | New `Breadcrumb` CustomJS helper rendered at top of every node (project, docs index, section hub, sub-section hub, doc-note). Clickable wikilinks. |
| Section Hub template | ONE shared template (`Template, Section Hub.md`) — depth-awareness lives in the `SectionHub` helper (`if depth === 2, suppress + New Sub-Section + sub-sections list`). |
| Default-section guarantee | Every project always has `Knowledge` + `Notes` section hubs after migration, even if currently empty. |
| Dashboard widgets scope | Stub for v0.103.0: doc count chip + open meetings chip + project status chip. Real expansion deferred to v0.103.x patches. |
| Doc-note breadcrumb injection | Migration injects a dataviewjs Breadcrumb block at the TOP of every existing doc-note body (above the doc's actual content). Marker-region pattern so re-running install is idempotent. |
| Out-of-scope (deferred) | v0.102.1 in-page filter (search), arbitrary-depth nesting, drag-to-move UI, section-renaming UI, section deletion UI, dashboard expansion, lint helper for folder/frontmatter drift. |

## Section 1 — Concept overview

Three note types form a hierarchical navigation tree. File system mirrors hierarchy. 2-level cap.

```
spice/projects/<slug>/
├── <Project Name>.md                   (project hub)
└── docs/
    ├── Docs.md                          (type: docs-hub — SECTIONS INDEX)
    ├── <section-slug>/                  (section folder)
    │   ├── <Section Name>.md            (type: section-hub, depth: 1)
    │   ├── <doc>.md                     (lives directly in section)
    │   ├── <sub-section-slug>/          (sub-section folder, depth 2 max)
    │   │   ├── <Sub-Section Name>.md    (type: section-hub, depth: 2)
    │   │   └── <doc>.md                 (lives in sub-section)
    │   └── ...
    └── ...
```

**Three note kinds:**
- `type: docs-hub` (REPURPOSED) — project docs landing; renders the sections INDEX, not a doc list.
- `type: section-hub` (NEW) — lives at `docs/<slug>/<Section Name>.md`; renders sub-sections + docs + create buttons.
- `type: doc-note` (UNCHANGED structurally) — gains breadcrumb header + `sub_section` frontmatter field.

## Section 2 — Schema

**Project frontmatter** — one field migrated:
```yaml
# Was (v0.102.0):  sections: [Knowledge, Notes, Plans]
# Now (v0.103.0):
sections:
  - "[[Knowledge]]"
  - "[[Notes]]"
  - "[[Plans]]"
```

**Section Hub** (NEW frontmatter):
```yaml
type: section-hub
project: "[[<Project Name>]]"
project_slug: <slug>
section: "<Display Name>"           # e.g. "Knowledge"
section_slug: <slug>                # e.g. "knowledge"
parent_section: ""                  # empty for depth 1; wikilink for depth 2
depth: 1                            # 1 or 2
created_at: "..."
tags: [section-hub]
```

**Doc-note** — one field added, one migrated:
```yaml
type: doc-note
project: "[[<Project>]]"
project_slug: <slug>
section: "[[<Section>]]"            # was string; now wikilink (migrated)
sub_section: "[[<Sub-Section>]]"    # NEW; empty when doc lives directly in section
created_at: "..."
tags: [doc-note]
```

**Identity rule:** folder slug + display name + hub note filename + frontmatter all stay in lockstep. Migration repairs drift; render-time helper flags mismatches.

**Validator rule_fragments updated:**
- New `section-hub` rule_fragment at `spice/projects/*/docs/**/*.md` with `type === "section-hub"` requiring `project`, `project_slug`, `section`, `section_slug`, `parent_section`, `depth`.
- `doc-note` rule_fragment: `section` field now required to be a wikilink string (string-with-`[[...]]`).
- `docs-hub` rule_fragment unchanged (just lists sections now, not docs).

## Section 3 — Templates + CustomJS helpers

**Templates** (`platform/blueprints/project/templates/`):

1. **`Template, Docs Hub.md`** — REWRITTEN. Renders:
   - `Breadcrumb` block (Project / Docs)
   - `ProjectNavButtons` row
   - Quick `+ New Doc` shortcut (modal prompts for section + title)
   - `+ New Section` button (presetPrompts.parent_section = "")
   - `ProjectDocsIndex` view — section cards
   - Dashboard widget row (3 chips: doc count, open meetings, project status)

2. **`Template, Section Hub.md`** — NEW. Same template used for both depth 1 and depth 2; helper depth-aware. Renders:
   - `Breadcrumb` block (Project / Docs / Section [/ Sub-section])
   - `ProjectNavButtons` (with context-aware additions: Project, Sibling Sections, [Sub-section hubs only] Section)
   - `+ New Doc` button (presetPrompts.section = this section)
   - `+ New Sub-Section` button (only when depth === 1; presetPrompts.parent_section = this section)
   - `SectionHub` view — sub-section cards (depth 1 only) + doc cards (filtered to this section)

3. **`Template, Doc Note.md`** — extended with a `Breadcrumb` block at the top (above existing body). Migration injects this for existing docs.

**Helpers** (`platform/blueprints/project/helpers/`):

- **`ProjectDocsIndex`** (NEW) — replaces `ProjectDocsSections` on Docs Hub. Reads project's `sections[]` frontmatter, renders section cards with doc-count meta. Reads dashboard data (meeting count via cross-blueprint query, kanban count via local query). Emits the quick `+ New Doc` shortcut + the `+ New Section` button.
- **`SectionHub`** (NEW) — renders any section-hub note. Reads its own frontmatter (`depth`, `section_slug`); queries sub-sections (depth 1 only) and docs (this section). Emits + New Doc + + New Sub-Section (when depth=1).
- **`Breadcrumb`** (NEW, small helper, ~50 LOC) — reads current note's frontmatter, walks parent chain, emits clickable trail.
- **`ProjectDocsSections`** (v0.102.0) — KEPT but @deprecated since 1.17.0. Allows rollback path. Removed in v0.104.0.
- **`ProjectDocsCards`** (pre-v0.102.0) — already deprecated; REMOVED in v1.17.0.

## Section 5 — Migration: `applyProjectSectionsHubMigration`

New installer step. Wired in `platform/install.js` between `applyProjectSectionsMigration` (v0.102.0) and `applyExternalPluginInstall`. Idempotent. Per-project failure-loud.

Per-project walk:
1. **Skip if already migrated.** Idempotency guard: check if `docs/Docs.md` body contains `customJS.ProjectDocsIndex.render` (the v1.17.0 sentinel). If yes, skip.
2. **Heal Docs.md.** Read the current body; replace any `ProjectDocsCards` / `ProjectDocsSections` invocation + standalone `entity-create:doc-note` block with the canonical `ProjectDocsIndex` block. Frontmatter gains nothing — the body change is the sentinel.
3. **Migrate project's `sections[]`.** Read project note. If `sections:` contains string entries, rewrite to wikilink form.
4. **Materialize Section Hubs.** For each `docs/<slug>/` subfolder (excluding `Docs.md`), if no `<Titlecase Slug>.md` file exists, create one with the canonical Section Hub frontmatter (depth: 1). Use the titlecase-from-slug helper.
5. **Recurse one level.** For each section folder, walk subfolders one level deep. Each sub-folder containing ≥1 doc-note gets a Sub-Section Hub (depth: 2, parent_section wikilinked).
6. **Migrate doc-note frontmatter.** For each doc-note: rewrite `section: "Knowledge"` → `section: "[[Knowledge]]"`. If doc lives in a sub-section folder, write `sub_section: "[[<Sub-Section>]]"`. Inject `<!-- breadcrumb-v1.17.0 -->` marker + dataviewjs Breadcrumb block ABOVE existing body (only if marker not already present).
7. **Default-section guarantee.** If a project lacks `docs/knowledge/` or `docs/notes/` folders, create them empty + materialize their Section Hubs.
8. **Final summary event.** `migrated N project(s); skipped M; W warning(s)`.

**For NEW projects** via entity-create: the project's `extra_files[]` materialization includes Knowledge.md + Notes.md hubs out of the box (added to project entity-create entry).

## Section 6 — Navigation

**Breadcrumb on every node.** Rendered at the top of project hub, Docs.md, Section Hub, Sub-Section Hub, doc-note. Clickable wikilinks; current note renders without link.

**Implementation:** new `Breadcrumb` CustomJS helper. Reads current note's frontmatter (`type`, `project`, `section`, `sub_section`); emits the appropriate trail. ~50 LOC.

**ProjectNavButtons extended** with new contexts:
- `context: "section-hub"` (depth 1) → renders Project | Docs | Sibling Sections nav buttons.
- `context: "section-hub-depth2"` (depth 2) → renders Project | Docs | Section | Siblings nav buttons.
- `context: "docs-hub"` already exists; no change.
- `context: "doc-note"` already exists; no change.

**Detection:** `ProjectNavButtons` inspects `dv.current().type` and `dv.current().depth` to pick the right branch.

## Section 9 — Risks + mitigations

| Risk | Mitigation |
| --- | --- |
| Migration is destructive (moves 30 doc bodies via prepending breadcrumb block). | Per-doc try/catch; failed-doc list logged. Idempotency marker `<!-- breadcrumb-v1.17.0 -->`. |
| Existing user-typed frontmatter conflicts with migrated wikilink form (e.g. user wrote `section: "Knowledge"` differently). | Migration logs every rewrite as an `info` event. User can hand-fix post-install. |
| Breadcrumb helper produces wrong trail when frontmatter drifts from folder. | Folder-derived backstop: if frontmatter chain doesn't resolve, fall back to folder-walk. |
| Sub-section hub at depth 2 attempts to spawn its own sub-section (should be blocked). | SectionHub helper depth-conditioned: suppresses + New Sub-Section button when depth === 2. |
| Section Hub note filename drifts from section_slug folder name (user renames folder). | Render-time mismatch warning chip on the Section Hub. Lint helper deferred (out of scope). |
| 30 doc bodies modified in accuris — if migration partial-fails, vault state is mixed. | Per-doc atomic write (write-then-no-rollback); log every change. Reversible via git on the consumer vault. |
| `applyProjectSectionsMigration` (v0.102.0) and `applyProjectSectionsHubMigration` (v0.103.0) both touch project structure. Order matters. | New step runs AFTER v0.102.0 step in install.js dispatch sequence. v0.102.0 step is idempotent so re-running is safe. |
