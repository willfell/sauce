# Engine reintegration — design (pointer)

**Cycle:** 2026-09-22 · **Version:** workshop 0.291.1 → 0.292.0 (predicted) · **Session:** `sauce-plugin-mktng-refactor`

The design for this cycle lives at [`engine-reintegration.md`](engine-reintegration.md): the archaeology of the loop-based execution (`/sauce-pipeline` → `/sauce-autoloop` → coordinator → `plugins/loop` → wac.plugins → `plugins/mayo`), the inventory of loop machinery still in the repo with a live / dead / half-migrated verdict for each path, the finding that no node-based engine ever existed as code (only as design notes in the `sauce-ai-loop-system` and `meta-board-loop-system-rnd` vault projects), the engine contract (graph note, node types, edge semantics, ledger, projection, scheduling, isolation), the integration (runtime at `platform/engine/`, thin always-on `engine` mechanism, `sauce run` and `/sauce`, mayo as a consumer, deletions), the MVP versus follow-up split, and the breaking changes.

The Director's Phase 2 reply of 2026-09-22 amended it: build fresh from § 4 (D0); runtime at `platform/engine/` plus the thin mechanism (D1); the installer auto-subscribes `engine` and, formally, `platform-claude` (D2); the ledger is one append-only file per run in the vault with no shared index (D3); `mayo:run --engine` is opt-in until one live epic completes through the graph and its ledger is diffed against a coordinator run (D4); sweep clean worktrees only and delete only merged branches (D5); untrack and ignore `.local/` (D6); apply the GitHub description from the session and list the topics (D7); ship `platform/engine/sauce-engine.plist.sample` before deleting the old sample; README and launch post describe what shipped, not the roadmap; `Docs/engine.md` carries a real ledger excerpt.

The non-negotiable from that reply, "the current coordinator flow must be expressible as a shipped graph with no loss of behavior", is what `platform/engine/graphs/delivery-slice.md` and `platform/test/run-engine-delivery-graph.js` exist to prove.
