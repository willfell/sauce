## 3. Debt widgets (6 new)

All widgets follow the established finance-helper conventions verified in S0:

- Class lives at `platform/blueprints/finance/helpers/<kebab-case>.js`.
- Single async `render(dv[, opts])` exported method.
- Unique CSS root class (e.g. `dbt-sum-root`) for embed-dedup via `dv.container.closest(".markdown-embed")` + previous-instance removal.
- Hardcoded color palette: `#16a34a` green, `#b45309` amber, `#dc2626` red (matches BudgetSummary CF-3 polish).
- Atomic mutations via `customJS.FinanceFrontmatter.update(file, mutator)` (matches BudgetDefaultsEditor pattern).

### 3.1 `DebtsHubSummary`

Page-level helper on `Debts.md`. Three-band rollup:

- **Band 1** — Totals: total debt across all entities · total monthly interest cost (Σ balance × apr/100/12) · total planned monthly attack (Σ planned_monthly_payment) · projected zero-debt date (max payoff per debt).
- **Band 2** — Per-kind progress strip: credit cards $X across N · student loans $Y across M (only shows kinds with entries).
- **Band 3** — Per-debt pill-cards sorted by balance DESC. Each card: name · balance · APR badge · paydown progress chip (CC only: `1 - balance/credit_limit`).

CSS root: `dhs-root`. Marker constant (for header-comment): `dhs-v0.6.0`.

### 3.2 `DebtSummary`

Per-debt entity helper. Three-band rollup:

- **Band 1** — Numbers: Current balance / APR / monthly interest / planned monthly attack / projected payoff date. "Edit balance" pill (opens DebtConfigEditor modal).
- **Band 2** — Sparkline of `balance_history[]` (SVG inline). Delta-from-prior-snapshot pill (green if down, red if up). If `balance_history.length < 2`, render placeholder text "No history yet — edit balance to start tracking".
- **Band 3** — (CC only) Paydown progress bar: `1 - balance/credit_limit` as percent + utilization chip.

Math:
- `monthly_interest = current_balance * apr / 100 / 12`
- `projected_payoff_months = Math.ceil(current_balance / (planned_monthly_payment - monthly_interest))` — flag `Infinity` if denominator ≤ 0 (display "Increase planned monthly attack" with red chip).
- `projected_payoff_date = today + projected_payoff_months months` (calendar-day, ISO).

CSS root: `dbt-sum-root`. Marker: `<!-- debt-summary-v0.6.0 -->` (used by installer migration for idempotency).

### 3.3 `DebtsCards`

Mirror of `BudgetsCards` / `PaychecksCards`. Renders a grid of `Debt-*.md` notes as mini-cards on the Debts.md hub. Sort: balance DESC. Card content: name · balance · APR badge · paydown chip. Click → navigate to the debt entity note.

CSS root: `dbt-cards-root`. Lives at `platform/blueprints/finance/helpers/debts-cards.js`.

### 3.4 `DebtDefaultsEditor`

Flat list editor on `Debt Defaults.md`. Mirrors `PaycheckDefaultsEditor` pattern (single table; click-row-to-edit modal; per-row × delete). Columns: Kind · Name · Balance · APR · Min · Planned · URL · Opened.

Modal field set (per row):
- `kind`: dropdown (credit-card | student-loan | other)
- `name`: text
- `current_balance`: number
- `credit_limit`: number (shown only when kind=credit-card)
- `apr`: number
- `min_payment`: number
- `planned_monthly_payment`: number
- `url`: text
- `opened_date`: date

`+ Add Debt` button defaults `kind: credit-card`. Required-field validation: kind + name + current_balance + apr.

CSS root: `dde-root`. Lives at `platform/blueprints/finance/helpers/debt-defaults-editor.js`.

### 3.5 `DebtConfigEditor`

Per-debt edit modal triggered from `DebtSummary`'s "Edit balance" pill. Same field set as defaults modal (minus opened_date — that doesn't change post-creation).

**Auto-snapshot on save:** If `current_balance` value changes between modal open and save, prepend `{date: today_YYYY-MM-DD, balance: <previous_current_balance>, source: manual}` to `balance_history[]` before writing the new `current_balance` and bumping `last_updated`. Sort descending by date (most recent first).

CSS root: `dce-root` (modal — only rendered while open; no embed-dedup needed). Lives at `platform/blueprints/finance/helpers/debt-config-editor.js`.

### 3.6 `FinanceNavRow`

Single context-aware nav-row class. Replaces `BudgetNavButtons`, `PaycheckNavButtons`, `InvoiceNavButtons` (the three deleted in Section 7).

**Render signature:** `async render(dv)`. No `opts` — context is detected from `dv.current()`.

**Detection table:**

| Detect | Mode | Buttons rendered |
|---|---|---|
| `file.path == 'spice/finance/Finance.md'` | `hub-finance` | Budgets · Paychecks · Invoices · Debts |
| `file.path == 'spice/finance/budgets/Budgets.md'` | `hub-budgets` | Finance · Paychecks · Invoices · Debts · + New Budget · ⚙ Defaults |
| `file.path == 'spice/finance/paychecks/Paychecks.md'` | `hub-paychecks` | Finance · Budgets · Invoices · Debts · + New Paycheck · ⚙ Defaults |
| `file.path == 'spice/finance/invoices/Invoices.md'` | `hub-invoices` | Finance · Budgets · Paychecks · Debts · + New Invoice |
| `file.path == 'spice/finance/debts/Debts.md'` | `hub-debts` | Finance · Budgets · Paychecks · Invoices · + New Debt · ⚙ Defaults |
| `page.type == 'budget'` | `entity-budget` | Finance · Budgets · ← prev · next → (siblings by month) |
| `page.type == 'paycheck'` | `entity-paycheck` | Finance · Paychecks · ← prev · next → (siblings by pay_period_start) |
| `page.type == 'invoice'` | `entity-invoice` | Finance · Invoices · Time Log · Board |

**Note on hub modes:** The HubActions composition (cross-hub nav + entity-create + defaults) is already delegated via `FinanceHubActions.render(dv, {...})`. `FinanceNavRow` in hub modes is a thin wrapper that just calls `FinanceHubActions.render(dv, derivedOpts)`. This avoids duplication. The detection logic + `derivedOpts` resolution lives in `FinanceNavRow`.

**Entity-mode rendering:** Inline flex row identical visual treatment to current `BudgetNavButtons`/`PaycheckNavButtons` (uppercase section label · accent-button row · hover state · top hairline divider). One CSS root: `fnr-root` (with attr `data-mode="<mode>"` for inspection).

**Sibling lookup** (for `entity-budget`/`entity-paycheck`/`entity-debt`): glob the sibling folder, sort by the relevant sort key, find current file's index, render prev/next links.

Lives at `platform/blueprints/finance/helpers/finance-nav-row.js`.

## 4. Paycheck ↔ debt glue

### 4.1 Schema extension on `expenses[*]`

```yaml
expenses:
  - { item: Rent, amount: 1100, category: Rent }                                          # unchanged
  - { item: Apple Card payment, amount: 800, category: Debt, debt: "[[Debt-Apple-Card]]" }  # NEW debt: field
```

Two new optional fields:
- `debt`: wikilink string (e.g., `"[[Debt-Apple-Card]]"`). When present + resolvable, the expense is treated as a debt-payment expense.
- `url`: text (already exists on Paycheck Defaults rows; semantics unchanged — see §4.3 for migration).

### 4.2 Scaffold-time resolution (entity-create flow)

`entity-create@0.7.0` `seed_from_defaults` already copies defaults' `expenses[]` into the new Paycheck. **No mechanism changes needed.** Resolution happens during the deep-copy step:

- For each copied expense item where `defaults_item.debt` is set:
  - Resolve the wikilink → `Debt-*.md` file path.
  - Read the debt entity's frontmatter.
  - Override `amount = debt.planned_monthly_payment` (debt entity is canonical for planned attack).
  - Override `url = debt.url` (debt entity is canonical for issuer URL).
- If debt link unresolvable (entity doesn't exist yet), fall back to defaults' stored `amount` (keeps idempotency safe during install ordering).

**Implementation site:** The `seed_from_defaults` resolver lives in the entity-create mechanism. To keep this v0.108.0 cycle clean — and to ensure `+ New Paycheck` at runtime (not just install time) gets the live debt-entity values — entity-create bumps **0.7.0 → 0.7.1 PATCH**: additive, opt-in `seed_from_defaults.resolve_wikilinks: boolean` field. When `true`, the resolver walks copied items, looks for `debt:` (or any) wikilinks pointing into the vault, resolves + reads target frontmatter, and applies a per-link field-merge map (`{from_key: to_key}`) onto the copied item.

Finance's paycheck `new_entity_button` declares:

```json
"seed_from_defaults": {
  "source_path": "spice/finance/Paycheck Defaults.md",
  "source_array": "expenses",
  "per_item_set": { "paid": false },
  "resolve_wikilinks": {
    "field": "debt",
    "merge": { "planned_monthly_payment": "amount", "url": "url" }
  }
}
```

Zero existing-behavior change for other consumers (Budget defaults, future blueprints). PATCH (not MINOR) because the field is fully optional + back-compat.

### 4.3 `PaycheckExpensesEditor` extension

When rendering a row where `expense.debt` is set:
- Render a small colored chip after the Category cell: `Apple Card · 12% paid` (text = debt name + paydown percent if cc-kind).
- Chip background color = paydown progress band (red < 33%, amber 33-66%, green > 66%).
- Click on chip → navigate to the debt entity note.

Modal edit form: when row has `debt:`, lock the `amount` and `url` cells (read-only, show "from debt entity" note). User edits debt-side via DebtConfigEditor.

### 4.4 `applyFinancePaycheckDefaultsDebtLinking` migration

Append-only frontmatter migration on `spice/finance/Paycheck Defaults.md`:

1. Read `Paycheck Defaults.md`'s `expenses[]`.
2. For each expense row whose `item:` value matches a known CC payment pattern (regex matches "Apple Card", "Cap1 Platinum", "Discover", "FNBO", "Scheels" — list from CF-3 dataset):
   - Look up the corresponding `Debt-*.md` entity in `spice/finance/debts/` by name match (case-insensitive, ignore "payment" suffix).
   - If found: set `debt: "[[Debt-<name>]]"` on the defaults row.
   - Strip the inline `url:` field from the defaults row (debt entity is canonical now).
3. Mark migration idempotent via `__debt_links_migrated: v0.108.0` top-level frontmatter key on Paycheck Defaults. Subsequent install runs short-circuit.
4. Pre-write `.sauce-backup/<timestamp>/spice/finance/Paycheck Defaults.md` snapshot.

Same regex-YAML-mutation posture as `_backfillBudgetGroupsFromText` (per S0 verification — append-only frontmatter mutation, no `processFrontMatter`).

5. Mark migration via top-level `__group_seed_migrated: v0.108.0` for idempotency.

History: per-file groups_seeded count, categories_reassigned count, untouched files.
