The user mental model post-v0.79.0: "you set up the kind (`/cowork preferences`), then you deepen it (`/cowork microscope <kind>`) — and the briefings get better as you iterate." The capture loop is "where all value is with sauce, cowork, and the user experience" (user's words from the design). v0.79.0 is the shippable slice; everything below is the sequenced follow-on.

## Carry-forward queue (design §11 + cycle-specific FLNs)

These are NOT regressions — they are deliberate sequencing decisions or follow-on capabilities discovered during the cycle. Pick any of these as v0.80.x candidates.

### From design §11 (microscope vertical-slice extensions)

1. **`contacts-map.md` sibling-file convention** — format + gather-consumption for user-supplied number→name (and other identity) maps in `per-mcp/<kind>/`. The `classifyGap` `user-supplied` branch already references this; the next cycle defines the file format + the gather-side read+merge step.
2. **WhatsApp MCP-swap follow-through** — once a user adopts `lharries/whatsapp-mcp` (whatsmeow-backed local SQLite bridge), capture a deep WhatsApp microscope (message-level: `list_chats` / `get_message_context` / `search`). v0.79.0's `edit-microscope` surfaces the MCP-ceiling gap live but does no work for the swap itself.
3. **`samples/` sibling dir** — cached example outputs per kind (`per-mcp/<kind>/samples/<timestamp>.md`) so `edit-microscope` can show "last time it looked like this" when deepening. Useful when the user re-runs the capture loop weeks later.
4. **Per-kind microscope versioning / changelog** — track how a contract deepened across iterations. The S11 helper's "deepen pass" appends rather than replaces, but there is no version stamping or diff view yet.
5. **Hard-rule post-processor** — a mechanical emoji-strip / word-budget pass for when the prompt-level `hard_rules` prove insufficient in practice. v0.79.0 is prompt-level only; HC-V0790-D1 guards the composed-body contract but agent compliance is best-effort.
6. **Expanded known-kinds catalog** — promote frequent custom kinds (drive: Google Drive / Dropbox / S3; code-platform: GitHub / GitLab; project-tracker: Linear / Jira / ADO; monitoring: NewRelic / Datadog / PagerDuty) into the canonical catalog with hand-curated question sets. Microscope makes custom kinds first-class enough that this is no longer urgent, but the question-set polish is worth it for the long tail.
7. **Cross-vault `inherits_from`** for microscope contracts — share deep contracts across a user's vaults (queued alongside the cross-vault preferences inheritance already in the In-flight queue). Resolution-order spec + cycle-detection guard required.
8. **Canonical-gather microscope parity (hybrid)** — currently a microscope forces served-by routing (covers all kinds uniformly). If a user wants a canonical skill's polished tables PLUS a microscope, design a hybrid path. Deferred until user-requested.

### Cycle-specific FLNs surfaced during v0.79.0 execution

(Open any note with the four callout types, e.g. a recent cowork briefing or a fresh scratch with `> [!info]`, `> [!warning]`, `> [!tip]`, `> [!example]` blocks.)
10. **FLN-v79-2: install.js has no CLI handler.** Every workshop dogfood document + the plan's stage instructions say `node platform/install.js --vault . --auto-approve`, but install.js exports `async function(tp)` for Templater and silently ignores `--vault` / `--auto-approve` when invoked from a shell — the script imports and exits. The correct CLI invocation is `node platform/test/run-install.js . --auto-approve`. Either (a) add CLI arg parsing + auto-dispatch to install.js (so the docs become accurate), or (b) sweep the docs (CLAUDE.md, build-test-verify.md, plan templates, agent guides) to use the harness wrapper invocation. Option (a) is preferable; mid-cycle stage instructions should be a single-tool path.
11. **FLN-v79-3: B3/D1 fixture 80-char floor edge.** The plan's `agent_markdown` for these HC cases was 78 chars — under `gather-from-served-by-helper.js`'s `md.length < 80` floor. Defer-or-fold: either (a) document the floor explicitly in the plan template's HC-case skeleton (so future cycles avoid the trap), or (b) lower the floor (it's a heuristic guard against accidentally-empty agent outputs, not a contract — 80 may be too aggressive).

13. **FLN-v79-5: CS-MIG-1 hardcoded counts.** Adding any cowork skill bumps both `expected 36` (skill entries) AND `expected 45` (total contributions) in `platform/test/run-claude-surface.js` CS-MIG-1. ## Lateral context the next chat will want

- **The "where all value is" thesis.** The capture loop (v0.79.0's `cowork:edit-microscope`) is the load-bearing UX. Everything else (canonical gathers / served-by gathers / voice contract) is plumbing that lets the loop's output drive the briefings. Whoever owns the next cycle should iterate on the capture loop's UX (the "one question at a time" + "consent-gated live sample" steps) more than on plumbing.
- **The emoji thesis.** The reason `hard_rules` had to reach the gather dispatch (not just the voice contract) is that on headspace's 2026-05-29 morning-briefing, the dominant emoji-leak source was section-title glyphs (💬/💰/📅/📧) and table glyphs (🔒/✅/🚨/💵) — both authored by gather sub-skills, which the voice contract is explicitly walled off from per v0.78.0's `[!example]+`-callouts-are-shaped contract. Don't undo this wall — it's right. Instead, the hard-rules path reaches the gather *separately*. Future post-processor (carry-forward §5) could be a belt-and-suspenders layer on top.
- **The microscope-routing trade-off.** When a microscope exists for a canonical kind (e.g., `calendar`), v0.79.0 routes that kind through `gather-from-served-by` instead of the canonical `gather-calendar` skill. The microscope body IS the deep contract; the kind's prior `notes` carry as `baseline_notes`. This means the user gives up the canonical skill's polished, vendor-specific tables in exchange for a deep custom contract. Most users will be happy with this trade; users who want both can request the hybrid (carry-forward §8).
