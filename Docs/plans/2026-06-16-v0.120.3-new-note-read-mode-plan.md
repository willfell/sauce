# New-Note Read-Mode Implementation Plan (v0.120.3)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every newly-created note opens in read/preview mode — never edit-mode with the title selected (the journal-from-nav repro). Achieved with a single shared, race-guarded helper invoked at every create-and-open dispatch site.

**Architecture:** A new tiny `open-helpers` mechanism exposes `customJS.OpenHelpers.forceActiveLeafPreview()`. It is a **post-open chokepoint** (decision: brainstorming 2026-06-16): after a note is created+opened, it defers one macrotask (so plugin/Templater opens finish claiming the leaf), then flips the active leaf to `mode: 'preview'`. It no-ops on non-markdown leaves (kanban boards take over the leaf with a custom view type — see the documented blank-pane race in `ranch/scripts/project/project-nav-buttons.js`) and never throws. Definite create paths call it unconditionally; the arbitrary `invoke_command` path calls it only when the nav entry opts in via `read_mode_after: true` (so a non-note command never yanks the user's active editing leaf).

**Tech Stack:** Plain Node CustomJS classes; headless DOM/Obsidian stubs in `platform/test/`. Runtime view-mode behavior cannot be exercised headlessly (no Dataview/Obsidian process) — the helper's *logic* is unit-tested with stubs; the real flip is verified in the manual dogfood step.

**Ships as:** v0.120.3 PATCH (bug fix), the second standalone slice of the note-chrome arc (design: `Docs/plans/2026-06-16-v0.121.0-note-chrome-standard-design.md`).

```js
    _state: viewState,
    getViewState() { return this._state; },
    setViewState(s) { this._applied = s; },
  };

// OH1 — markdown leaf in source mode → flipped to preview

  const app = { workspace: { activeLeaf: leaf } };
  new (loadClass(app))().forceActiveLeafPreview();
```

```js
// open-helpers.js — shared post-open view-mode helper (sauce v0.120.3).
//
// Single API: customJS.OpenHelpers.forceActiveLeafPreview()
// Call it immediately AFTER a create-and-open dispatch. It defers one macrotask
// (so a plugin/Templater-driven open finishes claiming the leaf), then flips the
// active markdown leaf to reading (preview) mode. No-ops on non-markdown leaves
// (a kanban board takes over its leaf with a custom view type — forcing preview
// there blanked panes; see project-nav-buttons.js race note) and never throws.
class OpenHelpers {
  forceActiveLeafPreview() {
    setTimeout(() => {
      try {
        const leaf = app.workspace.activeLeaf;
        if (!leaf || typeof leaf.getViewState !== "function") return;
        const state = leaf.getViewState();
        if (!state || state.type !== "markdown") return;
        if (state.state && state.state.mode === "preview") return;
        leaf.setViewState({ ...state, state: { ...(state.state || {}), mode: "preview" } });
      } catch (_e) { /* convenience hook — never throw */ }
    }, 0);
  }
}
```
