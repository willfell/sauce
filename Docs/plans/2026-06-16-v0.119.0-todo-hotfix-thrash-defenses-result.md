## Pre-existing data-loss bug discovered during deploy verification

**Bug:** The to-do blueprint manifest (since v0.116.0) declares `{{module_directory}}/Recurring Tasks.md` (the user-facing recurring task registry) as a `files[]` entry WITHOUT `materialize_once: true`. The installer therefore overwrites the user's accumulated recurring tasks with the empty template whenever the upstream template SHA changes (cosmetic updates, SectionLabel migrations, etc.). User content is backed up to `Recurring Tasks.md.bak` but never restored.

**Live impact this deploy:** v0.119.0's template diff `601dc124..54a80a4d` triggered the overwrite:
- accuris-sauce lost two recurring tasks (`test recurring task`, `Monitor this Dashboard [New Relic Link](...)`)
- headspace-sauce lost one recurring task (`yup`)
- ero-sauce was unaffected (no accumulated recurring tasks)

**Restoration (completed):** Restored from `.bak` files on accuris + headspace immediately post-deploy. Verified contents are intact.

**Root cause:** Pre-existing manifest gap; not introduced by v0.119.0. The registry was first declared in v0.116.0 manifest commit `4365d8ca` without `materialize_once`. Every cycle that touches the template (v0.5.0 SectionLabel, v0.5.1/.2/.3 cosmetic, v0.7.0 this cycle) silently wipes accumulated user content.

**Recommended follow-up:** ship v0.119.1 PATCH adding `materialize_once: true` to the `{{module_directory}}/Recurring Tasks.md` files[] entry. Also queue a `cowork:doctor`-style scan to detect this anti-pattern across other blueprints (e.g., any other files[] entry whose dest is in `{{module_directory}}/` and which represents user-mutable state).

## Lessons captured

(Captured during execution; the plan's task structure surfaced several decision points that
warrant codification.)

1. **Plan's `formatSentinel` emit had a whitespace bug.** Phase 1 implementer found that the
   plan's literal in Task 1.1 Step 2 produced an empty-set comment with a stray space
   (`<!-- recurring-materialized-2026-06-16:  -->`) because the template string interpolated an
   empty join result after the space-after-colon. The HC-V0119-SENT-C assertion expected
   `<!-- recurring-materialized-2026-06-16: -->` (single space). Fixed inline during Phase 1 by
   conditionally emitting the trailing space only when the set was non-empty. Lesson: when an
   emit template has a separator between fixed-text and variable-text, the variable-text empty
   case needs explicit handling — don't rely on `Array.join(',')` to do the right thing for
   `Set.size === 0`.

2. **Plan-code shipped a self-test breakage twice (Phase 3 + Phase 4).** Both `run-customjs-contract.js`
   and `scripts/lint-display-markers.js` had `SKIP_PATTERNS` that unconditionally excluded their
   own fixture directories — which broke the `--self-test` mode that NEEDS to scan those fixtures.
   The fix in both cases was the same shape: plumb `skipPatterns` (or `skip` opt) through `walkDir()`
   / `scan()` so `--self-test` can override with an empty array. Lesson: when a scanner has BOTH a
   live mode and a self-test mode, the skip-rules need to be parameterized from day one — not bolted
   on after the self-test mysteriously finds zero violations.

3. **Plan Task 1.7 only bumped the blueprint manifest; needed top-level platform/manifest.json bump too.**
   The to-do manifest version bumped 0.6.1 → 0.7.0 in `platform/blueprints/to-do/manifest.json` cleanly
   per Task 1.7, but `platform/manifest.json`'s `blueprints[].to-do.version` pin ALSO needed to bump in
   lockstep — caught at Phase 5 Stage 2c dogfood (installer skipped to-do with version mismatch).
   Fix-up commit (`097e934`) landed in Phase 5. Lesson: workshop manifest catalogue + per-blueprint
   manifests must move in lockstep at the SAME plan task — bumping one without the other is the
   v0.102.0-codified landmine #24 firing again.

4. **Workshop_version sequencing belongs at Phase 7 (cycle close), not Phase 5.** Phase 5 plan
   originally instructed bumping `workshop_version` in `ranch/platform-subscription.json` to 0.119.0
   during Stage 2c dogfood — but that immediately broke `check-version-sync.js` (the three-way
   parity gate at HC-V0890-VERSION-C) because `package.json` + `platform/manifest.json` were still
   at 0.118.1. Phase 5 reverted the workshop_version bump (kept the to-do@0.7.0 blueprint entry)
   and deferred the three-way lockstep to Phase 7. Lesson: any preflight gate that enforces N-way
   parity across files dictates that all N files must move in the SAME atomic commit — the
   workshop_version triplet (package.json + platform/manifest.json + ranch/platform-subscription.json)
   belongs at the FIRST commit of cycle-close, not earlier.

5. **Anchor lint baseline of 59 grandfathered warnings is mostly markdown EMITTERS, not parsers.**
   The lint heuristic in `scripts/lint-display-markers.js` flags any regex anchored on `^## ` or
   string-prefix check on `'## '` — but in practice, most matches in `platform/` are emitters
   (writers of `## Heading` markdown), not parsers keying on display markers. The heuristic is
   over-broad, but the baseline grandfathers them; new code is what matters. Lesson: lint heuristics
   that catch a target pattern WITH FALSE POSITIVES can still ship safely if (a) the baseline
   grandfathers existing matches and (b) the opt-out marker is clearly documented. Future cycles
   that refactor parsers to stable anchors will shrink the baseline organically.

6. **The 6 placeholder smoke checklists are scaffolds — fill in as future cycles touch each blueprint.**
   Per the plan's intent and the README in `Docs/agent-guides/smoke-checklists/`. The load-bearing
   one (`to-do.md`) carries bug-(b) + bug-(c) verification items concretely; the placeholders
   (`daily.md`, `meetings.md`, `scratch.md`, `people.md`, `project.md`, `cowork.md`) deliberately
   stub `(TODO: list <blueprint>'s template files; verify each renders cleanly)` and similar so
   blueprint owners pick them up as they next touch each surface. This keeps the directory live
   without inflating cycle scope. Lesson captured: scaffolds with explicit "TODO" stubs are honest
   placeholders; pretending to fill them in this cycle would have been performance.

## Late-cycle additions (2026-06-16 17:13 UTC)

The user reported a live bug on the accuris vault while v0.119.0 was awaiting PR open: clicking
**+ New Project** creates the project file (`spice/projects/dev-enablement/Dev-Enablement.md`) but
the hub note crashes with `TypeError: Cannot read properties of undefined (reading 'file')` at
`ProjectNavButtons.render:349` and `ProjectWorkstreamManager.render:13`. This was bundled into
v0.119.0 (instead of carrying forward to a v0.119.1 PATCH) per user request: "let's ensure a fix
is incorporated for this alongside everything that you've added in there." Two fixes landed:

7. **Project render-guards (5 helpers).** After `EntityCreate.create → openFile`, Dataview hasn't
   indexed the new file yet, so `dv.current()` returns undefined on the first render tick. Five
   project helpers were unguarded: `ProjectNavButtons`, `ProjectWorkstreamManager`,
   `ProjectWorkstreams`, `ProjectNotesCards`, `ProjectReferencedByCards`. (`ProjectStatusWidget`
   already had the guard.) Each gained the `if (!current || !current.file) return;` early-return
   pattern at the top of `render()` — same pattern used by the to-do helpers + project-status-widget.
   Project blueprint bumped 1.22.1 → 1.22.2 PATCH. Lockstep updates: `platform/manifest.json`,
   `ranch/platform-subscription.json`, `platform/test/seed-vault/ranch/platform-subscription.json`.
   NEW `platform/test/run-project-render-guards.js` harness: 5 widgets × 4 dv-stub variants
   (undefined / null / file-less / no-current-method) = 20 PROJGUARD asserts. Wired into preflight.

8. **C1 XSS fix (final-code-review finding).** The cycle's final code-reviewer agent surfaced a
   leading-whitespace bypass in `_isSafeUrl` (both to-do widgets that gained `_isSafeUrl` in
   Phase 2). Browsers strip leading whitespace from `href` attrs before resolution, so
   ` javascript:alert(1)` executes as `javascript:` — but the scheme regex `^[a-z][a-z0-9+.-]*:`
   is anchored at character 0 and doesn't match leading whitespace, falling through the "relative
   URL — allow" path. Fix: `String(url).trim()` BEFORE scheme detection in both
   `ToDoDailyUnassignedMeetings._isSafeUrl` and `ToDoDailyProjectGroups._isSafeUrl`. Added TDM-7
   (regression for `ToDoDailyUnassignedMeetings`) and TDM-8 (same shape for `ToDoDailyProjectGroups`).
   Assertions cover three whitespace variants (` javascript:`, `\tjavascript:`, uppercase) +
   the render-path test (malicious link emits as escaped text, not anchor).

These two additions extend v0.119.0's THREE-bug claim (was two — sentinel + markdown render — now
three with project render-guard; plus security fix). The cycle still ships as v0.119.0 MINOR;
no version reshuffle.
