# v0.113.0 plan — schema registry + linter

Six stages. Per-stage commits.

## S1. Inventory + seed `platform/schemas-index.json`

**Deliverable:** NEW `platform/schemas-index.json` per design §1.

**Approach:**
1. Walk the 8 schema surfaces from the brief.
2. For each surface, decide the right granularity (one entry per cadence sidecar; one entry per blueprint's rule_fragments[]; one entry per data file; etc.).
3. Author ≥ 15 entries (target 20-25).
4. For sidecar entries, extract `accepted_versions` from each JSON Schema's `schema_version.enum`.

**Acceptance:**
- File exists.
- `schema_version === 1`.
- `schemas[]` length ≥ 15.
- `node -e "JSON.parse(require('fs').readFileSync('platform/schemas-index.json'))"` succeeds.
- Every entry has at minimum `id`, `kind`, `owner`, `source`.
- Manual spot check: pick 3 entries at random, open `source` files, confirm they exist + match the entry's description.

**Commit:** `feat(schemas): v0.113.0 S1 — seed platform/schemas-index.json with N entries`

## S2. `scripts/lint-schemas.js`

**Deliverable:** NEW `scripts/lint-schemas.js` per design §2.

**Acceptance:**
- `node scripts/lint-schemas.js` exits 0 against the seeded index from S1.
- `node scripts/lint-schemas.js --list` prints one line per schema (`<id> · <kind> · ...`).
- `node scripts/lint-schemas.js --json` outputs parseable JSON.
- Injecting a synthetic bad-source entry into a copy of the index makes lint exit 1.
- Deleting a required key from a copy → exits 1.
- Adding a duplicate `id` to a copy → exits 1.

**Commit:** `feat(tooling): v0.113.0 S2 — scripts/lint-schemas.js validates registry`
