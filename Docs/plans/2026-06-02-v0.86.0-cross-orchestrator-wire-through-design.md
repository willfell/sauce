## 1. Scope

### 1.1 §1 midday-tripwire wire-through

**Surface.** `platform/blueprints/cowork/skills/orchestrators/midday-tripwire/SKILL.md`.

**Memory consumption:** `cowork:read-memory { engagement_id, tier: "tick", window: "today", limit_ticks: 4 }`. Captures recent 4 hours of tick activity (the period since morning-briefing fired).

**Body injection:** `[!example]+ Earlier today` callout after the synopsis, listing tick HH:MM lines (oldest-first per v0.85.0 composeMemoryCallouts convention).

**New helper:** `composeMidamMemoryCallout(outputToday) -> string`. Pure function. Returns empty string when outputToday is null OR has zero ticks.

### 1.2 §2 eod-review wire-through

**Surface.** `platform/blueprints/cowork/skills/orchestrators/eod-review/SKILL.md`.

**Memory consumption:** `cowork:read-memory { engagement_id, tier: "tick", window: "today", limit_ticks: 16 }` (full day's ticks). Also `cowork:read-memory { engagement_id, tier: "day", window: "today" }` to surface today's daily synthesis IF synthesize-day fired earlier in the EOD chain.

**Body injection:** `[!example]+ Today's tick log` callout after the synopsis showing today's ticks; if `day_synthesis` is present + synthesized, ALSO inject `[!info]+ Today's pattern` callout with the synthesis paragraph.

**New helper:** `composeEodMemoryCallout(outputTicks, outputDay) -> { tickLogCalloutMd, dayPatternCalloutMd }`. Mirrors composeMemoryCallouts's dual-output shape.

### 1.3 §3 weekly-review wire-through

**Surface.** `platform/blueprints/cowork/skills/orchestrators/weekly-review/SKILL.md`.

**Memory consumption:** `cowork:read-memory { engagement_id, tier: "week", window: "this-week" }`. Returns this week's Tier 2 synthesis if synthesize-week has fired (otherwise null-data).

**Body injection:** `[!info]+ This week so far` callout after the synopsis with weekly_pattern body + ≤5 carry-forward bullets.

**New helper:** `composeWeeklyMemoryCallout(outputWeek) -> string`. Returns empty string when week_synthesis is null.

### 1.4 §4 monthly-review wire-through

**Surface.** `platform/blueprints/cowork/skills/orchestrators/monthly-review/SKILL.md`.

**Memory consumption:** `cowork:read-memory { engagement_id, tier: "week", window: { start: <month-start-iso>, end: <today-iso> } }` (this month so far; multiple week syntheses).

**Body injection:** `[!info]+ This month's pattern` callout aggregating up to 4 weekly syntheses. List each week's pattern summary as a bullet.

**New helper:** `composeMonthlyMemoryCallout(outputMonth) -> string`. Aggregates multiple week_synthesis records; returns empty string when there are zero synthesized weeks.

### 1.5 Out of scope (deferred)

- Tier 3 (`cowork:synthesize-month`) — deferred per sequencing decision. Monthly-review just aggregates weekly syntheses inline.
- Compose helper consolidation — 4 per-orchestrator helpers chosen over single switch-based composer (each orchestrator's callout context differs enough to justify separation; consolidation if/when patterns prove uniform).
- Engagement-types schema bump — no new cadences; existing morning/midday/eod/weekly/monthly stay unchanged.
- Semantic retrieval — v0.87.0's territory.

## 6. Risks + mitigations

### 6.1 Helper count growing (4 NEW per cycle)

v0.85.0 shipped `composeMemoryCallouts`; v0.86.0 ships 4 more. If v0.87.0+ ships another N, the helpers/ dir grows to 10+.

**Mitigation:** consolidation is deferred. When a consolidation refactor lands (v0.90.0?), the shared shape will be obvious from accumulated empirical patterns.

### 6.2 Friday's monthly-review (last-day-of-month overlap) edge case

When the last day of the month is a Friday, both weekly-review (14:30) AND monthly-review (04:00 next-month-day-1) fire. The week-review reads this-week's syntheses; monthly-review reads this-month's. Friday's data is captured cleanly in both (synthesize-day at 17:20 fires before monthly).

**Mitigation:** monthly-review's wire-through uses explicit `{ start: <month-start>, end: <month-end> }` window, NOT "this-month" relative tag. This ensures month boundaries are correct.

### 6.3 Cowork MINOR bump triggers re-materialization across 4 SKILL.md surfaces

The cowork 0.24.1 → 0.25.0 bump fires the install loop. All 4 modified orchestrator SKILL.md dests get re-materialized into `.claude/skills/cowork/<name>/SKILL.md`.

**Mitigation:** intentional. Materialization happens via the `materializeClaudeSurface` global step (per landmine #16 v0.80.0+ observation) regardless of per-item version short-circuit. No special handling needed.
