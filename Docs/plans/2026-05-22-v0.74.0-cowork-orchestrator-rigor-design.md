# v0.74.0 — Cowork Orchestrator Rigor (design)

**Cycle:** workshop v0.74.0
**Date:** 2026-05-22
**Theme:** v0.71.0 shipped a presentation contract but under-enforced it; three real bug families surfaced post-deploy. This cycle hardens enforcement (body-shape self-check + title/summary required), broadens the midday-tripwire model beyond finance-only (`tripwire_aspects[]`), migrates the cowork write path off the Obsidian REST API to filesystem-first I/O (the API outage on 2026-05-22 was the trigger), and turns `cowork:onboard-scheduled-jobs` into the single conversational entry-point post-`brew upgrade sauce`.
**Scope:** `cowork` 0.12.0 → **0.13.0**; engagement-types 0.1.0 → **0.2.0** (additive `tripwire_aspects[]`). **No mechanism bumps** — activity-feed, daily, validator stay put.

## Problem

Three bug families surfaced after the v0.71.0 cowork-presentation-polish cycle shipped:

### Bug family A: midday-tripwire gate scoped too narrowly
`platform/blueprints/cowork/skills/orchestrators/midday-tripwire/SKILL.md` step 2 gates on `render_aspects.finance_block != "include"` and silently early-exits otherwise. Personal engagements pass; w2-fte and consulting get a no-op. But the v0.71.0 body-shape examples for `write-run-note-midday-tripwire` include calendar-drift and project-approval-queue tripwires — completely non-finance — which are unreachable under the current gate. Confirmed broken on accuris (w2-fte) at the 12:30 Mon-Fri scheduled job.

### Bug family B: write-run-note body-shape contract isn't enforced
v0.71.0 S5 shipped a uniform `## Body shape` section in all 6 `write-run-note-<orch>` SKILL.md files. The contract is guidance text, not enforcement. The 2026-05-22 accuris recovery run after an Obsidian REST API outage IGNORED ALL OF IT — no `SpaceNavButtons` block, no `> [!info]-` admonitions, no per-section tables, no `> [!warning]` admonitions (uses inline italic `*(could not fetch...)*` instead), no `> [!tip]` close, no `summary:` frontmatter, no `title:` frontmatter. Output captured at `/Users/willfellhoelter/notes/sauce/accuris-sauce/spice/cowork/daily/2026/05-May/2026-05-22/morning-briefing.md`. Compounding factor: the accuris prompt file at `spice/cowork/prompts/morning-briefing.md` is still the cowork@0.4.0 empty stub from 2026-05-13 — `cowork:onboard-scheduled-jobs` Option-(a) ("use the platform-shipped default for engagement-type") never actually overwrote it. The orchestrator then ran against the empty prompt + advisory body-shape contract and freelanced plain markdown.

### Bug family C: missing `title:` + `summary:` frontmatter
The v0.71.0 rule_fragments declared `summary: { required: true }` but nothing fails at write time when the orchestrator skips emitting it — the validator only runs via `/audit`, not in the orchestrator's write path. There is no `title:` field at all. The daily-note Activity panel card surfaces the literal filename ("morning-briefing") instead of a friendly title; the card subtitle reads body substrings instead of a curated TL;DR.

### Cross-cutting issue: write path depends on a flaky transport
Today's failure was triggered by an Obsidian Local REST API outage. The orchestrators use `mcp__obsidian__create_note` / `obsidian_put_content` for all atomic-note writes. Because cowork jobs execute in the vault root (the bash sandbox lines up with the vault boundary), filesystem I/O is the simpler + more resilient path: no TLS, no auth, no plugin dependency, works even when Obsidian is closed.

## Solution overview

Three loosely-coupled workstreams in one cycle:

### Workstream A — body-shape enforcement (Bugs B + C)
- Workshop ships the skeleton in 6 `write-run-note-<orch>/SKILL.md` bodies; Claude adapts content within it. Skeleton = 5 structural markers (SpaceNavButtons block + `> [!info]-` synopsis + ≥1 `> [!example]+` section + `> [!warning]` for skipped gathers + `> [!tip]` close) + 2 frontmatter fields (`summary:`, `title:`).
- Each `write-run-note-*` skill grows 3 new sections (`## Title composition`, `## Adaptive body skeleton`, `## Pre-write self-check`).
- `title: { required: true, type: "string" }` added to all 6 atomic-note `rule_fragments` (parity with `summary:` from v0.71.0).
- 5 cadence orchestrators handle the new `failed:contract-violation:<field>` status (emit Notice; skip state-update steps; do not mark complete).
- Bulletproof orchestrator step 14 (empty-prompt → literal stub goes INSIDE the info admonition; 5 markers still emitted; no freelancing).

### Workstream B — tripwire-aspects model (Bug A)
- Each engagement-type JSON grows `tripwire_aspects: string[]`:
  - personal: `["cc_drift"]`
  - w2-fte: `["calendar_drift", "queue_growth"]`
  - consulting: `["cc_drift", "calendar_drift", "queue_growth"]`
- Widen `supported_cadences` to include `"midday"` for w2-fte and consulting.
- `midday-tripwire` orchestrator preflight gate: `len(engagement.tripwire_aspects) == 0` → exit silently. Else proceed; gather + decide branches per-aspect.
- Severity scheme flattens to `"warn" | "alert"` (replaces finance-only `"yellow" | "red"`). Per-aspect mapping: cc_drift retains today's yellow→warn / red→alert; calendar_drift sets alert on ≥1 hour drift in next 4h; queue_growth sets alert on ≥10 new items since yesterday EOD, warn on 3-9. (Heuristic starting numbers; tunable in future cycles.)
- `severity` rule_fragment pattern broadens from `^(yellow|red)$` to `^(warn|alert)$`.
- Two existing gather skills grow a `## Modes` section: `gather-calendar` adds `drift-check` mode; `gather-projects` adds `tripwire-delta` mode.

### Workstream C — filesystem-first writes + single-command onboarding (Bug A's REST outage + Bug B's silent copy-failure)
- New `cowork:check-vault-routing` mode `{ required: ["filesystem"] }` — verifies cwd resolves to a writable vault root (presence of `spice/cowork/context/vault-config.md` is the sentinel). Existing `{ required: ["obsidian"] }` mode stays for skills that need REST/MCP.
- 6 `write-run-note-*` skills migrate the write step from `mcp__obsidian__create_note` / `obsidian_put_content` to the native `Write` tool. Paths stay vault-relative; resolved against cwd. `mkdir -p` (via Bash) precedes Write when the `YYYY/MM-MMMM/YYYY-MM-DD` directory doesn't exist. Post-write `wc -c` verifies the file cleared a 500-byte floor (frontmatter alone is ~300; a real note clears).
- `cowork:onboard-scheduled-jobs` becomes the single conversational entry-point post-`brew upgrade sauce`:
  - **Auto-delegates** to `cowork:bootstrap-vault` when `not-bootstrapped`.
  - **Brief natural-language preambles** before every question (~1-3 sentences: what + why + recommended default).
  - **New top-level "bulk defaults" question** before the per-orch walk: "Apply engagement-type defaults to all 5 prompts now?" with 4 options (a yes-skip-customized / b yes-overwrite-customized / c per-orch walk / d skip prompts entirely).
  - **Hardened Option-(a) copy** uses `Read` + `Write` (filesystem) with explicit overwrite + byte-count assertion + hard error on missing source.
  - **Customization-aware overwrite guard**: bulk mode classifies each prompt file ("stub" ≤200 chars / "default" matches engagement-template ±10% / "custom" otherwise). Path (a) skips "custom" with Notice; path (b) confirms per-file.
  - **Re-runnable**: detects existing scheduled tasks + non-stub prompts and offers skip/update/reconfigure per section.
- `cowork:date-context` and vault-config reads stay on MCP (not failure-prone; deferred to follow-on).
- `gather-{calendar,gmail,imessage}`, `ensure-daily-note`, `bootstrap-vault` MCP usage stays put (deferred).

### `cowork:midday-tripwire` orchestrator SKILL.md

**Preflight step 2** changes from `If render_aspects.finance_block != "include", exit silently` to:

> Load engagement-type manifest; capture `engagement.tripwire_aspects`. If empty array OR field absent, exit silently. Otherwise proceed; gather + decide branches per-aspect below.

**Gather (steps 5-7)** become aspect-gated:

```
5. If "cc_drift" in tripwire_aspects:
     Use Skill cowork:gather-finance-cc-today { ... }; capture cc_signal
6. If "calendar_drift" in tripwire_aspects:
     Use Skill cowork:gather-calendar { engagement_id, mode: "drift-check",
       horizon: "today+4h", timezone: ... }; capture calendar_signal
7. If "queue_growth" in tripwire_aspects:
     Use Skill cowork:gather-projects { engagement_id, mode: "tripwire-delta",
       since: <yesterday EOD ISO> }; capture queue_signal
```

**Decide (step 8)** widens severity logic:

```
8. Compute severity from collected signals:
   - alert if any of: red CC charge, ≥1h calendar drift in next 4h,
                     ≥10 queue items since yesterday EOD
   - warn  if any of: yellow CC charge, 0.5-1h calendar drift,
                     3-9 queue items
   - green if none
   If green → exit silently (no note; atomic-note absence = green).
```

**Write step (call to write-run-note-midday-tripwire)** passes structured signals:

```
{
  engagement, date, weekday, month_name, severity,
  signals: { cc: cc_signal, calendar: calendar_signal, queue: queue_signal },
  body: composed_body,
  prompt_source: "spice/cowork/prompts/midday-tripwire.md",
  warning
}
```

### `cowork:gather-calendar` and `cowork:gather-projects` — modes

Add `## Modes` sections.

**gather-calendar `drift-check` mode**: when `mode == "drift-check"` is passed, scope the gather to the `horizon` window (e.g. `"today+4h"`), compare today's planned slots against current state (events moved / cancelled / running long per Outlook/Google indicator), and return `{ markdown, drift_minutes, drifted_events: [...] }`. Skill emits `gather-skipped` cleanly when no calendar MCP is available (existing v0.71.0 MCP routing pattern preserved).

**gather-projects `tripwire-delta` mode**: when `mode == "tripwire-delta"` is passed, count items added since the `since` anchor that are in states `["approval_requested", "review_pending", "blocked"]`. Return `{ markdown, new_count, items: [...] }`.

Both skills' existing default mode (`mode` unset) keeps current behavior; `## Modes` is additive.

Each grows 3 new sections (insert after existing `## Steps`, replace the v0.71.0 `## Body shape` section). Plus the write step migrates to filesystem.

**Per-skill display-name literal:**

| Skill | Display name literal |
| --- | --- |
| write-run-note-morning-briefing | Morning Briefing |
| write-run-note-midday-tripwire | Midday Tripwire |
| write-run-note-eod-review | EOD Review |
| write-run-note-finance | Finance Snapshot |
| write-run-note-weekly-review | Weekly Review |

**New `## Title composition` section** (per skill):

> Before composing the body, set frontmatter `title` to: `<Display Name> — <weekday>, <month_name> <D>, <year>` where `<D>` is the integer day (no leading zero). Example for Friday 2026-05-22 morning briefing: `"Morning Briefing — Friday, May 22, 2026"`. Year and integer day come from the `date` input.

**New `## Adaptive body skeleton` section** (uniform across all 6 skills):

> The body MUST contain these 5 structural markers in this order; CONTENT inside each marker adapts to the engagement and the gather outputs. Skip sections whose gather output is empty; add custom sections inside `> [!example]+` blocks when the engagement has signal the standard sections don't cover.
>
> 1. `SpaceNavButtons` dataviewjs block (verbatim, first thing after frontmatter close).
> 2. `> [!info]- Today at a glance` admonition — 1 paragraph synopsis distilled from gather outputs.
> 3. ≥1 `> [!example]+ <emoji> <Section title>` per-section block with markdown table OR bullets. Standard sections (calendar / email / projects / threads / finance) shown only when their gather has data. Tables use the v0.71.0 canonical column headers (Calendar: `| Time | Event | Attendees | Link |`; Email: `| Subject | Sender | Intent |`; Projects: `| Project | Status | Next action |`; Finance accounts: `| Account | Balance | Δ this week |`; Finance txns: `| Date | Merchant | Amount | Category |`).
> 4. `> [!warning] <section> unavailable` blocks for any `gather-skipped` returns, at the position the affected section would have rendered. Also append the reason to frontmatter `warnings:` array.
> 5. `> [!tip] <emoji> Today's focus` closing admonition — 2-3 sentence focus paragraph + concrete first action.

**New `## Pre-write self-check` section** (uniform across all 6 skills):

> BEFORE calling the Write tool, verify your composed output against this checklist. If any item fails, return `{ path, status: "failed:contract-violation:<field>" }` and do NOT write.
>
> Frontmatter checks:
> - [ ] `type:` matches the canonical value for this skill
> - [ ] `title:` is present and non-empty
> - [ ] `summary:` is present and non-empty (1-2 sentences, ~150-250 chars)
> - [ ] `engagement_id:`, `day:` (or `week:` / `month:` for weekly/monthly), `generator:`, `prompt_source:` present
>
> Body checks (regex-scan the composed body string):
> - [ ] First non-frontmatter line is a `SpaceNavButtons` dataviewjs fence
> - [ ] At least one `> [!info]-` admonition present
> - [ ] At least one `> [!example]+` admonition present
> - [ ] Closing `> [!tip]` admonition present
> - [ ] For each entry in `warnings[]`, a matching `> [!warning]` admonition present
>
> On any failure, the returned `status` field names which check failed (e.g., `failed:contract-violation:body-missing-info-admonition`). The orchestrator surfaces this in a Notice and skips downstream state-update steps.

**`## Steps` step 5 (write) rewrite** — replaces today's `mcp__obsidian__create_note` call:

> 5a. **Ensure parent directory exists.** Use the Bash tool: `mkdir -p "<dirname(path)>"` where `<path>` is the composed vault-relative path resolved against cwd.
> 5b. **Write the file.** Use the Write tool with `file_path: <path>` and the composed contents (frontmatter + body). The Write tool overwrites existing files (matches v0.65.0 atomic-note contract: overwrite-last-write-wins).
> 5c. **Verify.** Use the Bash tool: `wc -c "<path>"` and confirm the byte count clears a 500-byte floor (frontmatter alone is ~300, so a real note clears). On undersized return `{ path, status: "failed:write-undersized:<bytes>" }`.

### 5 cadence orchestrator SKILL.md bodies

Each of `cowork:morning-briefing`, `cowork:midday-tripwire`, `cowork:eod-review`, `cowork:weekly-review`, `cowork:monthly-review` grows two enhancements:

**1. Handle `failed:contract-violation:*` status from write-run-note**:

The existing write-step pattern says `If status starts with "failed:", emit Notice ... and exit. Do not run state-update steps after a failed write.` That pattern already covers `failed:contract-violation:*` — but the Notice text broadens to surface which contract field failed. Pattern:

> If `status` starts with `"failed:contract-violation:"`, emit Notice `cowork:<orch> aborted -- contract violation: <field>`. Do not run state-update steps. Exit non-zero.
> Else if `status` starts with `"failed:"`, emit Notice `cowork:<orch> aborted -- write failed: <status>`. Do not run state-update steps. Exit.

**2. Bulletproof empty-prompt branch**:

The existing step 14 of morning-briefing (and analogues in the other 4) says: `When prompt_body is empty, set run_body = "" and warning = "empty_prompt". Otherwise warning = null.`

Today's accuris failure proved Claude freelances past this when the prompt is empty. Rewrite to:

> When `prompt_body` is empty:
> - Set `warning = "empty_prompt"`.
> - Compose `run_body` as the skeleton-compliant stub:
>   - `SpaceNavButtons` block
>   - `> [!info]- Today at a glance\n> (Prompt body empty — edit <prompt_source> to customize what this run emits.)`
>   - `> [!example]+ 📋 Status\n> No prompt body to drive content; this run is a placeholder.`
>   - `> [!tip] ✏️ Next action\n> Edit \`<prompt_source>\` to define what this scheduled job should emit when it fires.`
> - Set `summary = "Stub run — prompt body at <prompt_source> is empty."`
> - The write-run-note's self-check passes (5 markers + summary + title all present).

This guarantees that even an empty-prompt run produces a contract-compliant note (rather than freelancing rich content with no markers, which is what today's accuris run did).

```
supported_cadences, tripwire_aspects, render_aspects.

## Detect scheduled-tasks MCP availability (step 3)

Preamble: "Each cadence has a prompt body that shapes what the atomic note emits

  → spice/cowork/prompts/<orch>.md (using filesystem Read + Write tools).
  Log: "Wrote <orch>.md (<bytes> bytes)" per file.
  On (a): skip "custom"-classified files with Notice "Kept your customized <orch>.md".
  On (b): for each "custom" file, ask "Overwrite custom <orch>.md? (y/n)"; default n.
  On missing engagement-template source: emit hard error + exit (don't silent fallback).
Path on (c): proceed to step 5 with the existing per-orch (a)/(b)/(c) walk
  (preserving today's behavior with added preambles).
Path on (d): skip prompt-body step; continue with step 5 cadence + step 6 registration.

For each of the 5 orchestrators (in order: morning-briefing, midday-tripwire,

     <list of orchestrator | cron | next-fire-time>

   To customize any prompt body, edit spice/cowork/prompts/<orch>.md

```

## Risks

- **Self-check is still Claude-side.** A determined freelance could emit markers literally with nonsense content. Contract enforces SHAPE, not quality. Acceptable trade-off per Q1.
- **Filesystem write path assumes cwd == vault root.** The scheduled-tasks MCP fires jobs with cwd at the vault root, so this holds in production. `check-vault-routing { required: ["filesystem"] }` catches the cases where it doesn't (defensive).
- **`mkdir -p` + `Write` is not atomic.** If a crash lands between mkdir and write, you get an empty directory. Self-healing on next run; acceptable.
- **Bulk-mode (a) classifier heuristic.** The 200-char stub threshold + ±10% default-body-length window is heuristic. Edge cases (a user who lightly tweaked a default) may be misclassified. Documented; user has the (b)/(c)/(d) options to override.
- **Tripwire heuristics** (1h drift, 10/3 queue items) are starting numbers, not tuned. Documented as such; tunable via per-engagement prompt customization in future cycles.
- **gather-projects + gather-calendar new `mode:` plumbing.** Small but real surface change in those gather skills' SKILL.md bodies. Adding `## Modes` sections in S2 — narrowly scoped.
- **engagement-template prompt trim (S7) could regress per-engagement guidance** if I trim too aggressively. Conservative: keep all engagement-specific content (scope hints, voice, section emphasis); only remove redundant body-shape marker descriptions.
- **Multi-session execution drift.** The handoff prompt mechanism (see "Multi-session execution & handoff prompts" above) is the mitigation. Every session-closing stage must commit an updated handoff file; every session-opening read of this design doc must also read the handoff file.
- **Historical midday-tripwire notes carry `severity: yellow|red`.** After S3, the rule_fragment regex is `^(warn|alert)$`. The validator will start flagging pre-v0.74.0 midday-tripwire notes on `/audit` runs. Mitigation: documented as expected migration noise; users can either delete the historical notes (they're atomic, ephemeral) or accept the audit findings. No automatic backfill — the historical severity values are still semantically meaningful and editable in-place if a user wants to migrate manually.
