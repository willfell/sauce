# Intake slice-scope guardrails — design

**Cycle:** v0.280.0 · **Date:** 2026-08-03 · **Component:** delivery 0.4.1 → 0.5.0

## Problem

Card intake (`.agents/skills/card-intake/scripts/card-intake.js`) is the only
sanctioned planning writer to the board. It already refuses *under*-specified
slices (empty `touch_zones` / `acceptance_tests` / `applicable_guides` /
`trap_warnings`, uncovered carried findings, contract violations). It had no
*upper* bound.

Two failure modes exploited that gap:

1. **Program-in-one-card.** A single execution slice can declare an unbounded
   number of touch zones, acceptance tests, and risk dimensions. Such a slice is
   a program hidden in one card — it cannot be reviewed or merged whole, so the
   loop churns on it indefinitely.

2. **Accreting 1:1 supersession chain.** When a slice fails review, intake mints
   a successor that supersedes it and carries its findings forward. Nothing
   capped the carried-findings conjunction, so a mis-scoped slice could spawn a
   chain of 1:1 successors, each carrying an ever-larger acceptance conjunction
   that review can never pass whole. Observed: one TV-2 slice spun **27
   supersessions and merged nothing.**

Both are the same root cause — a slice whose scope is too large to ever close —
and both are only detectable at mint, before the loop invests a cycle in work it
will never land.

## Approach

Add mint-time **ceilings** enforced in `card-intake.js`, with the thresholds
living in the delivery schema registry (`policies.slice_scope_caps`), never as
literals in JS. Thresholds:

| Cap | Value | Rationale |
| --- | :---: | --- |
| `touch_zones` | 6 | A slice touching >6 zones is cross-cutting enough to be a program. |
| `acceptance_tests` | 12 | >12 acceptance behaviors is a conjunction review won't pass whole. |
| `risk_dimensions` | 3 | >3 distinct risk categories is a multi-concern slice. |
| `carried_findings` | 12 | A successor carrying >12 findings proves an accreting 1:1 chain. |

Two checks, mirroring the existing lower-bound idiom (`for … of field`):

- **`slice_scope_ceiling`** in `validateCard` — refuses an execution card whose
  `touch_zones` / `acceptance_tests` / `risk_dimensions` exceed their cap.
  `risk_dimensions` is counted **pre-normalization** (the raw card field, before
  `deliveryContract` dedups + maps synonyms) — deliberately strict, and
  documented inline, because the concern is authored scope, not the collapsed
  set.
- **`carried_findings_ceiling`** in `validateSupersede` — refuses a successor
  carrying more than the cap, with an instruction to decompose the predecessor
  into independently mergeable slices that each carry a share of the findings
  rather than supersede 1:1.

Every refusal message names the offending field, the count, the cap, and the
remediation (**decompose**), so the caller knows exactly what to do.

## Why the schema registry

`policies.slice_scope_caps` sits beside the existing `policy_strength`,
`high_risk_zone_prefixes`, and `epic_forbidden_execution_fields` policy knobs.
The registry is the single source of truth for delivery policy; `card-intake.js`
reads `delivery.registry.policies.slice_scope_caps` and each check is a no-op if
its cap is absent, so the guardrails degrade safely and the thresholds are
tunable without touching code. Per the code-conventions guide, thresholds never
live as literals in JS.

## Non-goals / deferred

- **Guardrail #2 — supersession-depth circuit-breaker (DEFERRED).** A second
  guardrail was scoped: in `scripts/autoloop/codex-coordinator.js`
  `discardCardCore`, walk `superseded_by` backward and refuse a discard at chain
  depth ≥ 3, returning `awaiting_user_decision`. It was deferred because
  `discardCardCore` is the shared primitive behind **both** `commandDiscard` and
  `commandReap` (the batch corpse-cleaner). Injecting a new
  `awaiting_user_decision` return there is not a bounded change: it is a new
  refusal contract that ripples into station projection, the reap batch loop
  (which would then refuse legitimately reaping pre-existing deep chains), lock
  semantics, and the loop's receipt handling — and it is arguably the wrong
  layer (the break belongs at the supersession-*minting* decision, not the
  discard/reap primitive). See the result doc's carry-forward for the intended
  design. The carried-findings ceiling shipped here already blocks the accreting
  chain at its source (mint), which is the failure mode #2 targets.
