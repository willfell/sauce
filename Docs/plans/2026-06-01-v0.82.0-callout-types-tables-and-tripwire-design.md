# v0.82.0 — callout-types-tables-and-tripwire (design)

**Status:** design — pending plan + execution.
**Date:** 2026-06-01.
**Cycle topic slug:** `callout-types-tables-and-tripwire`.
**Predecessor:** v0.81.1 (cowork-slash-doc-fix), workshop `0.81.1` closed 2026-05-30.
**Trigger:** Will's first real morning-briefing run on accuris (2026-06-01, post-microscope-authoring) surfaced three concrete UX gaps the v0.79+v0.80+v0.81 cohort didn't address:

1. **All kind callouts render in the same color.** Every MCP section is `> [!example]+ <kind_title>`, so the v0.79.0 per-type CSS (which DOES distinguish info/warning/tip/note/quote/example/success/caution/danger correctly) gives all 5-6 kind sections the same purple/lavender example color. Per-TYPE colors work; per-KIND distinction does not.
2. **No tables, all bullet lists, even for inherently tabular data.** The `gather-from-served-by/SKILL.md` Step 3 output contract explicitly says *"Bulleted lines preferred (no tables — cross-vendor portability)"*. For ADO board state + GitHub PR queues, this actively hurts — the data has 3+ structured columns per item and renders far better as a table.
3. **midday-tripwire on accuris is a silent no-op.** The w2-fte engagement-type manifest at `platform/blueprints/cowork/engagement-types/w2-fte.json` doesn't include `midday` in `supported_cadences` AND doesn't define `tripwire_aspects`. The midday-tripwire orchestrator silently exits when `tripwire_aspects` is empty/absent. Will enabled `midday: true` in vault-config but the manifest override wins — silent no-op for weeks.

All three are real, all three are addressable as a coherent cohort. v0.82.0 closes them.

## 2. Architecture findings (from v0.79.0 + v0.80.0 + v0.81.0 anchors)

- **The callout type is determined at gather time.** `gather-from-served-by-helper.js` line ~61 hardcodes the expected prefix as `> [!example]+ ${kind_title}\n` and validates against it. The TYPE is `example`. No mechanism currently parameterizes this. v0.82.0 adds the parameter.
- **Per-kind config is the natural home.** `prefs.mcps.<kind>` already carries kind-specific config (served_by, surface_kinds, notes/what_matters, etc.). Adding `callout_type` per kind follows the existing pattern. Default mapping (when absent): chat → `info`, finance → `warning`, calendar → `tip`, email → `quote`, ado → `example`, github → `note`. Any unknown kind → `example` (preserves v0.81.x behavior).
- **Default mapping lives in `read-user-preferences-helper.js`** as a constant. The helper resolves each kind's callout_type at parse time (explicit override OR default OR `example`). Orchestrators consume the resolved value — they don't redo the mapping logic.
- **The output contract is one SKILL.md section.** `gather-from-served-by/SKILL.md` Step 3 has the dispatch contract template that says "Return ONE `> [!example]+ <kind_title>`" + "Bulleted lines preferred (no tables — cross-vendor portability)". Both WS-A and WS-B touch this same section. Single coherent edit.
- **Engagement-type manifests are STOCK files.** `platform/blueprints/cowork/engagement-types/<type>.json` ships in cowork's `files[]`. Editing the workshop source + bumping cowork triggers re-materialization in consumer vaults on next `sauce update`. Accuris vault picks up the new w2-fte definition automatically.
- **CS-MIG-1 unchanged** — no new skills, no new commands, no new claude_surface[] entries. Counts stay at 38 skill entries / 47 total contributions.

## 3. Sub-deliverable A — Per-kind callout types

### 3.1 User-side schema

In `spice/cowork/context/user-preferences.md`, the `mcps.<kind>` block gains an optional `callout_type` field:

```yaml
mcps:
  chat:
    served_by: "Read_and_Send_iMessages"
    callout_type: info   # optional — defaults to per-kind mapping below if absent
    ...
```

Valid values: any of Obsidian's built-in callout types (`info`, `note`, `tip`, `success`, `warning`, `caution`, `example`, `quote`, `danger`). Validation: helper coerces to lowercase + falls back to `example` if invalid.

### 3.2 Default mapping (when `callout_type` absent)

Hardcoded in `read-user-preferences-helper.js`:

```javascript
const DEFAULT_CALLOUT_TYPE_BY_KIND = {
    chat: "info",          // blue — conversational signals
    finance: "warning",    // amber — money matters
    calendar: "tip",       // green — anchors / conflicts
    email: "quote",        // gray — quiet / filtered
    ado: "example",        // purple — board state ("example of work")
    github: "note",        // sky blue — code state
};

function resolveCalloutType(kind_name, kind_block) {
    const explicit = (kind_block && kind_block.callout_type || "").toLowerCase().trim();
    const valid = new Set(["info","note","tip","success","warning","caution","example","quote","danger"]);
    if (explicit && valid.has(explicit)) return explicit;
    return DEFAULT_CALLOUT_TYPE_BY_KIND[kind_name] || "example";
}
```

The helper exposes `prefs.mcps[kind].callout_type` as the resolved value (explicit override OR default mapping OR `example`). Orchestrators read the resolved field — no per-orchestrator default logic.

### 3.3 Gather-from-served-by contract change

**Inputs frontmatter** gains: `callout_type: string` (default `example` when absent).

**Helper:** `gather-from-served-by-helper.js`
- Destructure `callout_type` from input (default to `"example"` if undefined/null/empty).
- Update the expected prefix: `const expectedPrefix = \`> [!${callout_type}]+ ${kind_title}\n\`;`
- All other validation stays identical.
- Success return adds `callout_type_used: callout_type` (mirrors `hard_rules_applied` / `siblings_used` pattern).

**SKILL.md Step 3** updates the dispatch contract template:

```
**Output contract**:
Return ONE `> [!<callout_type>]+ <kind_title>` markdown callout (where `<callout_type>` is the input field; defaults to `example` when absent).
- Aim for ≤200 words.
- Render data in tables OR bullets, whichever gives the highest information density per vertical inch. Tables for structured data (3+ columns per item: IDs, timestamps, lanes, links); bullets for narrative or single-axis lists. Mixed within one callout is fine (e.g., table for items + bullet for cross-item context).
- Honor what_matters as the gather contract.
- Window: <range.start> to <range.end> (timezone: <timezone>).
```

This single edit covers both WS-A (`<callout_type>` parameterization) and WS-B (table softening).

### 3.4 Orchestrator passthrough

Each of the 5 atomic-note orchestrators (morning-briefing / midday-tripwire / eod-review / weekly-review / monthly-review) reads `callout_type` per kind in the gather loop:

```
callout_type:        prefs.mcps[entry.kind_name].callout_type,   # resolved by read-user-preferences-helper
```

The helper already does the default resolution — orchestrators just pass through.

### 3.5 Boundary contract (already covered)

`callout_type` is a USER-set field in `user-preferences.md`. v0.76.0's existing USER-table row covers it (the file is materialize_once-preserved). No new boundary contract entry needed.

## 4. Sub-deliverable B — Tables in gather contract

### 4.1 The single Step 3 edit (same edit as WS-A)

The "Bulleted lines preferred (no tables — cross-vendor portability)" line gets replaced by the table-or-bullet decision rule (see §3.3 above).

### 4.2 Why this works

v0.78.0's "no tables — cross-vendor portability" rationale was that cross-MCP uniformity prevents some MCPs from rendering well (chat threads, free-text emails). But:
- Per-kind microscopes (v0.79.0) already allow per-kind overrides via `## Output shape`. Tables can be specified per kind.
- Tables for tabular data is a clear win (ADO, GitHub, finance category breakdowns, calendar event lists).
- The agent picks rendering per the data shape — same agent already handles per-kind output_shape directives from microscopes.

The softening is information-positive: more flexibility, no enforcement loss (the microscope still wins).

### 4.3 What the agent will do post-S6

When composing a callout:
1. Read what_matters (the microscope body or kind's notes) — has explicit `## Output shape` directives the agent follows
2. Read the gather contract Step 3 — now says "tables OR bullets, pick what fits"
3. Decision: structured data (≥3 columns) → table; narrative/single-axis → bullets; mixed → both within one callout

For Will's accuris ADO microscope (with the 2026-06-01 hot-fix that explicitly says "render board items as markdown tables"), the new contract aligns — no more "we want tables but the contract says bullets" conflict.

## 5. Sub-deliverable C — w2-fte engagement-type fix

### 5.1 The diagnosis

Will's accuris 2026-06-01 midday-tripwire run reported:
> *"Pre-flight step 2 resolves to an early silent exit: the w2-fte engagement-type manifest defines no tripwire_aspects field (and the engagement entry in vault-config.md doesn't set one either). Per the orchestrator contract, an absent tripwire_aspects defaults to [], and an empty list means the engagement has no tripwire signals — the orchestrator exits silently without writing an atomic note."*

Also: `w2-fte.json` lists `supported_cadences: [morning, eod, weekly]` — midday isn't in the list. But vault-config has `midday: true`. The manifest override wins → silent no-op.

### 5.2 The fix

Edit `platform/blueprints/cowork/engagement-types/w2-fte.json`:
- Add `"midday"` to `supported_cadences` array
- Add `"tripwire_aspects": ["calendar-drift", "queue-growth", "pr-review-backlog", "chat-urgency"]`

### 5.3 Tripwire aspect rationale (for w2-fte)

For a w2-fte mid-workday check at 12:30 PM, the high-leverage signals:
- **calendar-drift** — meetings added/moved this afternoon vs morning brief; new conflicts; on-call shifts
- **queue-growth** — new ADO tickets assigned to you since morning; tickets newly moved to your lane
- **pr-review-backlog** — PRs awaiting your review piling up beyond a threshold (e.g., >3 or >24h old)
- **chat-urgency** — new @-mentions in inner-circle channels since morning brief; unread DMs from inner_circle senders

These map to existing MCPs (M365 Teams + Calendar + Email; ADO; GitHub). The midday-tripwire orchestrator iterates `tripwire_aspects` and emits per-aspect signals when present.

### 5.4 Scope decision: w2-fte only

Other engagement-types (consulting, personal) also lack tripwire_aspects but Will only reported the w2-fte/accuris case. Stay focused. consulting + personal can be follow-up cycles when those vaults need midday.

## 6. Failure-mode matrix

| Failure | Detected at | Response |
|---|---|---|
| User sets `callout_type: foo` (invalid type) | helper resolution | Coerce to lowercase; if not in valid set, fall back to default mapping; log warning row (no user-visible error). |
| Kind not in `DEFAULT_CALLOUT_TYPE_BY_KIND` | helper resolution | Fall back to `example` (preserves v0.81.x behavior). |
| Gather composes callout with WRONG callout_type (validation fails) | helper validation | Return `failed:bad-output` with reason. Same posture as v0.79.0's hard-rules contract failure. |
| Microscope `## Output shape` says "use bullets" but data is tabular | agent decides | Microscope wins (it's the user's explicit override). Gather contract is permissive, not prescriptive. |
| w2-fte vault has `midday: false` after v0.82.0 ships | vault-config (USER-owned) | midday-tripwire silently no-ops as before. User opts in via vault-config. |
| w2-fte vault has `midday: true` + tripwire_aspects all yield zero signals (quiet day) | orchestrator | Emit a single-line `[!success]` "Quiet midday — no tripwires triggered" callout. Don't silent-no-op (that hid the bug). |

**Legacy preservation.** v0.81.x consumer vaults that don't set `callout_type` on any kind get the default mapping → 5 distinct colors. No action required on user end. Pure additive improvement.

## 12. Open questions resolved during design

- **Q: Should `callout_type` live in `mcps.<kind>` or in `personality.callout_types` (a global map)?** A: per-kind. Mirrors existing patterns (surface_kinds, vip_senders, etc. are per-kind). The default mapping is the global piece.
- **Q: Default `email` to `quote` vs `note`?** A: `quote`. Email is the "quiet" kind in Will's setup (heavily filtered); gray quote tone fits semantically. User can override.
- **Q: Should the gather helper validate `callout_type` matches the kind's recorded preference?** A: No — the orchestrator passes the resolved value; helper just validates the prefix matches what was passed. Don't double-validate.
- **Q: Tables in gather contract — should there be a HARD rule like ">=3 columns → must table"?** A: No. Soft decision rule. The agent picks. User microscope output_shape overrides anything.
- **Q: w2-fte tripwire_aspects — calendar/queue/PR/chat — does midday-tripwire's SKILL.md already know how to handle these aspects?** A: Will's accuris run report shows the orchestrator already reads tripwire_aspects + iterates per-aspect. Need to verify in the plan stage S8 by reading midday-tripwire/SKILL.md before writing the engagement-type fix; if any aspect names are unrecognized, document inline + decide whether to ship anyway (agent will gracefully degrade per-aspect) or rename to match what's in the SKILL.md.
