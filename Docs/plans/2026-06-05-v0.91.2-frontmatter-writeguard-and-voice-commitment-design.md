## 0. Why this cycle

Today's accuris morning briefing on the laptop (post-v0.91.0 deploy + Layer 1 prompt wrapper applied) wrote to the canonical path successfully (v0.91.1 wasn't deployed yet but the prompt wrapper held). BUT the resulting atomic note had:

1. **Wrong frontmatter type:** `type: cowork-run-note` instead of canonical `type: cowork-morning-briefing`. Missing required fields (`generator`, `prompt_source`, `summary`, `title`). Extra non-canonical fields (`cadence`, `date`, `generated_at`). Result: `SpaceDailyDashboard` panel queries by canonical type and missed the note entirely.

2. **Lost microscope `## Output shape` adherence:** chat microscope mandates utilization-snapshot → inner-circle-first → urgency-tiered action list. Today's note had a single dense prose paragraph for chat instead.

3. **Lost voice/personality:** user-preferences specify `vibe: casual` + `notes: "Facts only. Light on exclamation marks. Not 'uppidy'. Conversational and warm."` Chat microscope voice says "Casual, thorough, real. Tough-love / trash-talk register is welcome." Today's note reads as neutral-formal LLM output. Compare with yesterday's headspace briefing which nailed the casual/punchy register.

All three are the same LLM-attention failure class. Deterministic fixes catch the frontmatter; prose-imperative fixes raise the floor on voice/microscope but can't 100% guarantee adherence.

## 1. Fix A — frontmatter write-guard in 5 write-run-note sub-skills

Mirror v0.91.1's path write-guard pattern. Add a new `### v0.91.2 frontmatter write-guard: canonical frontmatter enforcement (SECOND CHECK)` clause right after the v0.91.1 path write-guard in each of:
- write-run-note-morning-briefing/SKILL.md
- write-run-note-midday-tripwire/SKILL.md
- write-run-note-eod-review/SKILL.md
- write-run-note-weekly-review/SKILL.md
- write-run-note-monthly-review/SKILL.md

Clause text (parametrized per orchestrator):

```markdown
### v0.91.2 frontmatter write-guard: canonical frontmatter enforcement (SECOND CHECK)

After the path check, validate the composed frontmatter BEFORE the Write tool fires. The canonical frontmatter for this sub-skill is:

```yaml
type: cowork-morning-briefing       # MUST be this EXACT string
engagement_id: <engagement_id>
day: "<YYYY-MM-DD>"                  # ISO date, not weekday name
generator: cowork:morning-briefing@1.0.0
prompt_source: <path>
title: <composed title>
summary: <1-2 sentence headline, ~150-250 chars>
created_at: <ISO timestamp>
warnings: [<list>]                   # OPTIONAL — only when warnings exist
```

REJECT and return `{ path, status: "failed:contract-violation:wrong-frontmatter:<field>" }` if:

1. `type:` is missing OR != exact canonical value `cowork-morning-briefing` (NOT `cowork-run-note`, NOT `cowork-briefing`, NOT any other variant).
2. Any of `engagement_id`, `day`, `generator`, `prompt_source`, `title`, `summary` is missing or empty.
3. Frontmatter contains non-canonical fields like `cadence:`, `date:` (use `day:` instead), `generated_at:` (use `created_at:` instead).
4. `day:` is not in `YYYY-MM-DD` ISO format (e.g. `Friday` is invalid; `2026-06-05` is valid).

This is the v0.91.2 deterministic backstop for the orchestrator's Step 17 post-write verify, which depends on the LLM reaching it. The write-guard runs BEFORE the file lands on disk; if the LLM composes wrong frontmatter, the write is refused.
```

## 2. Fix C — voice/microscope verbal commitment extension in 5 orchestrators

Extend v0.91.1's Step 1b verbal-commitment Notice to ALSO commit to voice + microscope adherence. Updated Step 1b text (parametrized):

```markdown
1b. **Verbal commitment (v0.91.1 + v0.91.2).** Before any other action, emit Obsidian Notice and treat it as a binding commitment for this run:

   ```
   cowork:morning-briefing committing to:
     PATH: spice/cowork/daily/<YYYY>/<MM-Month>/<YYYY-MM-DD>/morning-briefing.md (NOT spice/daily/...)
     TYPE: cowork-morning-briefing (canonical frontmatter type)
     VOICE: follow user-preferences.personality.notes verbatim AND personality.vibe / formality / length
     MICROSCOPES: for each kind in prefs.priorities with a microscope at spice/cowork/prompts/per-mcp/<kind>/microscope.md, follow that microscope's `## Output shape` directives verbatim for the kind's callout
   ```

   Four purposes: (1) commit path so the v0.91.1 path write-guard never fires; (2) commit type so the v0.91.2 frontmatter write-guard never fires; (3) commit voice so the LLM applies personality + voice contract to body composition; (4) commit microscope adherence so each kind's callout follows its microscope's `## Output shape`. The Notice creates an audit trail in the Obsidian Notice log if any commitment is violated.
```
