## Lessons

1. **Universal-grammar consolidation.** The inline-dataview-field grammar (`[project::]`, `[priority::]`, `[due::]`, `[scheduled::]`) had existed since v0.118.0 but only the create path (`ToDoCreateTask.serializePayloadToLine`) could emit it. v0.127.0 promotes it to a bidirectional contract via a single mechanism (parse + serialize + write + edit). **Pattern to repeat:** when an existing serializer is consumed by multiple producers, promote its inverse + writer to a mechanism so consumer surfaces stay symmetric. The cycle thesis ("the inline-field grammar is a universal task language already; what's missing is one parser, one writer, one editor") generalized cleanly across all four consumer surfaces (meeting, project-todo, to-do, edit-modal).

2. **Stable-anchor sentinels over display markers.** Per `Docs/agent-guides/code-conventions.md` § "Stable anchors vs display markers", `<!-- ACTION_ITEMS_MARKER -->` + `<!-- TODAY_CAPTURE_MARKER -->` are the correct anchor primitives because `SectionLabel` is explicitly headless DOM (no `data-section` attribute, no `id`, no addressable DOM hook). This pattern was reaffirmed by v0.118.1's parseRegistry-keyed-on-H2 incident — keying on SectionLabel visible text is fragile across renames; HTML-comment sentinels are stable. Both NEW sentinels ship in source templates + inline_body + are back-injected by `_healNoteChromeBody` for existing notes.

3. **customjs static-on-instance trap (third recurrence).** `ToDoCreateTask.serializePayloadToLine` was declared `static`; `task-interactions.js` called it as `customJS.ToDoCreateTask.serializePayloadToLine(payload)`. customjs stores **instances**, not constructors — static methods are `undefined` on the stored instance. Same shape as v0.118.0's `RecurrenceParser.isSupported/matches` + `TaskParser.parseTasks` fix. Surfaced via `run-customjs-contract.js` at S9 preflight time. **In-cycle PATCH (to-do 0.12.0 → 0.12.1)** added the instance delegator on `serializePayloadToLine` above the static. Source order matters — the contract checker's `.find()` returns the first match, so the instance method must appear before the static. **RULE for future cycles** (reaffirms v0.118.0 lesson): any class consumed via `customJS.X.method` MUST expose that method as an instance method (statics are fine only for in-file callers + Node harnesses).
