## Surface changes

Consumer-visible changes after `sauce update --bump-pins` to v0.84.0:

- **NEW `spice/cowork/memory/<engagement_id>/` directory** — materializes on install (via `onboard-scheduled-jobs` first run after upgrade; not a `files[]` entry). Each day's memory accumulates as a single append-only `YYYY-MM-DD.md` file. STOCK row added to `cowork-customization-contract.md` marking these files as USER-data (NOT overwritten by `sauce update`).
- **NEW `cowork:capture-tick` orchestrator** — fires on the `tick` cadence (tight 1-hour range, same dispatch_mode + plan_dispatch pattern as `midday-tripwire`). Appends one time-stamped tick entry to the current day's memory file. Accepts `engagement_id` + optional `tick_notes` input.
- **NEW `cowork:synthesize-day` orchestrator** — fires on the `synthesize_day` cadence (EOD window). Reads all tick entries in the current day's memory file, synthesizes a daily summary callout, and appends it below the tick stream. Pure append; never rewrites prior tick entries.
- **`cowork:morning-briefing` wire-through** — new pre-flight step 3a reads `spice/cowork/memory/<engagement_id>/<yesterday>.md` (or most recent file if yesterday absent). When found, injects a `[!info]+ Memory context (<date>)` callout block into the briefing body above the kind sections. Null-data-gated: clean skip when no memory files exist (no degradation for vaults without the tick cadence).
- **Engagement-type schema 0.3.1 → 0.4.0** — `w2-fte.json`, `personal.json`, `consulting.json` each gain `supported_cadences[]` + `default_cadences[]` fields; `tick` + `synthesize_day` added to both arrays.
- **`cowork-customization-contract.md` STOCK row** — `spice/cowork/memory/**` marked as USER-data (written by capture-tick; never overwritten by sauce update; user may delete or archive freely).
- **`cowork:onboard-scheduled-jobs` Cowork.md resolver + customization contract** — updated to walk `supported_cadences` from the materialized engagement-type JSON and register `tick` + `synthesize_day` cadence entries in the consumer vault's Cowork.md nav table.

## NEW lessons surfaced

### 1. Tick orchestrator reuses morning-briefing engine without code duplication

`cowork:capture-tick` mirrors `midday-tripwire`'s dispatch_mode + plan_dispatch pattern verbatim, just with a tight 1-hour range. No new gather sub-skills shipped — the existing `gather-from-served-by` surface serves the tick write path without modification. **Lesson:** when extending the cowork orchestrator surface with a new cadence, mirror the dispatch_mode-prefs pattern as the canonical engagement-aware contract. Resist the impulse to define new sub-skills just because the cadence is new; audit whether an existing sub-skill already covers the surface.

### 2. Single-file-per-day write contract simplified vs file-per-tick

Original design proposed `HH-tick.md` × N files per day (one file per tick event). User pivot to a single append-only `memory.md` (later `YYYY-MM-DD.md`) per (engagement, day) reduced downstream consumer complexity substantially: `morning-briefing`'s pre-flight step 3a reads 1 file instead of glob + merge + sort. Vault navigation is also cleaner — one file per day is browsable; N tick files per day is noise. **Lesson:** append-only single-file write contracts are easier for downstream consumers AND for vault navigation than file-per-event. Prefer append unless there is a hard technical reason for separate files (e.g., conflict resolution in a multi-writer scenario).

### 3. Backward-compat null-data gating let memory layer ship without breaking v0.83.x consumers

`morning-briefing`'s new pre-flight step 3a + body composition gracefully skip when memory files are absent (vault has not yet run `capture-tick`). No degradation for vaults that deploy v0.84.0 but have not registered the tick cadence yet, or for vaults that are upgrading from v0.83.x and have zero memory accumulation. **Lesson:** for additive consumer-surface changes (new pre-flight step, new body callouts), gate on null-data-equals-skip-cleanly so prior-version vaults continue working seamlessly. This is the same pattern as v0.79.0's microscope null-data gate — write the skip branch first, then the happy path.

### 4. Workshop dogfood version-skip on in-cycle blueprint edits

S5 surfaced the FLN-v821-2 pattern again: when bumping engagement-type schema mid-cycle, the install loop short-circuited cowork (subscription pin = installed pin = 0.23.0, unchanged in-cycle). The implementer used direct `cp` to materialize the updated engagement-types JSONs to `spice/cowork/context/engagement-types/`. On consumer vaults this is fine because their installed pin will move 0.22.0 → 0.23.0 (different from current), triggering the full install loop. But the dogfood pattern reveals: when in-cycle blueprint edits don't co-occur with the same-cycle's version bump, the workshop dogfood material may drift from source until the next blueprint bump. **Lesson:** for in-cycle blueprint edits that need fresh dogfood materialization, either bundle them with the blueprint version bump OR use the direct-cp workaround explicitly (document which files were copied and from where).

### 5. Pre-existing exact-version pins surface at S5

HC-V0740-1 (engagement-type version 0.3.1) + HC-V0710-1c (cowork-memory missing `discriminator_tags` entry) failed at S7's preflight because S5/S6 added/changed values that the test fixtures hardcoded. These were not S5/S6 bugs — they were pre-existing fixture drift waiting for the right cycle to surface. The S7.1 fix closed both gaps in a single follow-up commit. **Lesson:** any cycle that adds canonical types OR bumps engagement-type versions should grep for exact-version assertions across the whole test suite at S0 plan time, not at S7 preflight failure time. Reinforces FLN-v821-1 (V0750-VERSION exact-pin) + the v0.83.0 lesson 3 (test-fixture obsolescence at surface change).

## Carry-forwards

### Newly surfaced at v0.84.0

1. **FLN-v84-1 — Tier 2 (weekly synthesis) + Tier 3 (monthly synthesis) deferred.** The cowork memory architecture has 4 tiers; Tier 0 (capture-tick) + Tier 1 (synthesize-day) shipped. Tier 2 (weekly synthesis across daily summaries) + Tier 3 (monthly synthesis across weekly summaries) are well-specified in the design doc but deferred. v0.85.0 MINOR candidate.

2. **FLN-v84-2 — wire-through to midday-tripwire / eod-review / weekly-review / monthly-review deferred.** Each of these orchestrators could read recent memory (parallel to morning-briefing's step 3a wire-through). Each needs its own pre-flight step + body composition update. Deferred to avoid an unbounded scope. v0.85.0+ MINOR candidate (could bundle with FLN-v84-1).

3. **FLN-v84-3 — memory retention / compression policy.** Memory files accumulate indefinitely. At 1-2 ticks/day × ~50 lines/tick, a year-long active engagement accumulates ~73k lines across 365 daily files. Eventually a compression policy (rolling summarization, or date-based archival past N days) will be needed. Design-only candidate; no harness changes until compression logic ships.

4. **FLN-v84-4 — Smart Connections semantic retrieval over memory notes.** The memory accumulation in `spice/cowork/memory/**` is a natural corpus for semantic similarity queries. Future cycle could wire `sc-bridge` (or equivalent) to surface relevant past context beyond the most-recent-file read. Aligns with the long-standing Smart Connections candidate (project_smart_connections_candidate.md in machine memory).
