## 1. Workstream A — wikilink hard-rule promotion (closes FLN-v89-9)

### Problem

v0.89.1's "Known people in scope" dispatch-contract section instructs `**[[<basename>]]**` emission as a SOFT prompt at the bottom of Step 3. The chat microscope's `## Output shape` section (the user's canonical per-item-line spec) is in the middle of the dispatch contract as the deep `what_matters`. The LLM follows the explicit format spec (specifying `Who: sender resolved to canonical display name`) and ignores the soft prompt below it. Empirically observed today: zero wikilinks emitted across all named people in chat section.

### Fix

Promote wikilink emission from a soft prompt (in the dispatch-contract "Known people in scope" section) to a **canonical platform-default HARD RULE** injected universally into `effective_hard_rules[]` by `read-user-preferences-helper.js`. Hard rules already appear BEFORE the microscope output-shape body in the dispatch contract and are explicitly labeled "non-negotiable, apply verbatim to ALL output". Adding the wikilink rule there gives it structural precedence over microscope format specs.

#### A.1 New canonical hard rule

Add to `composeEffectiveHardRules()` in `platform/blueprints/cowork/helpers/read-user-preferences-helper.js`:

```
"When the dispatch contract's 'Known people in scope' section names a person, emit their basename as **[[<basename>]]** every time the person is mentioned in narrative, callout titles, callout bodies, and tables. Microscope ## Output shape per-item-line specs do NOT override this rule. On miss (person not in 'Known people in scope'), emit as **<plaintext basename>** without wikilink syntax."
```

Inserted at the TOP of `effective_hard_rules[]` (before user-authored `personality.hard_rules`) so it composes first. Always-on; non-disable-able in v1 (FLN-v89-5 — `wikilink_people` disable-path — remains queued and will give vaults that don't want wikilinks an opt-out in a later cycle).

#### A.2 Dispatch contract structural ordering

In `gather-from-served-by` Step 3 (the dispatch contract composition), reaffirm: Hard rules block precedes microscope body. No structural change needed; v0.79.0 already established this order. Add a one-line prose note in the SKILL.md that the order is INTENTIONAL (microscope MUST NOT override hard rules) to prevent regression.

#### A.3 Microscope authoring contract update

In `platform/blueprints/cowork/helpers/edit-microscope-helper.js`, update `composeMicroscope()` so NEW microscopes (created by `/cowork microscope <kind>` from v0.90.0 onward) include a small `## Person mentions` section that POINTS TO the canonical hard rule:

```markdown
## Person mentions

This microscope's `## Output shape` per-item-line spec does not control person-name format. The canonical platform hard rule (injected by `read-user-preferences-helper.js` into every dispatch contract's "Hard rules" block) is the authority: emit `**[[<basename>]]**` for people in "Known people in scope", `**<basename>**` for misses.
```

For EXISTING microscopes (accuris's already-authored `per-mcp/chat/microscope.md`), the platform-default hard rule takes effect IMMEDIATELY at gather-time tomorrow morning. NO user re-authoring of microscope.md required. The hard rule is injected by the platform; the microscope is consulted as `what_matters` but the hard rule overrides format conflicts.

## 3. Workstream C — cowork:discover-people microscope-extraction (NEW v0.28.0 sub-skill)

### Skill placement + invocation

- Orchestrator at `platform/blueprints/cowork/skills/orchestrators/discover-people/SKILL.md`
- Reachable via slash: `/cowork discover-people [<engagement_id>]`
- Engagement is OPTIONAL; if absent, default-if-one (auto-pick the sole engagement) or ask-if-many (prompt user)
- User-invoked only; never cron-scheduled

### Helper file

`platform/blueprints/cowork/helpers/discover-people-helper.js` — single pure-JS module exporting:

- `parseInnerCircleFromMicroscope(microscope_body) → string[]` — parse `## What matters` section, extract names from "Inner circle (people)" + "elevation" prose. Returns canonical name strings as written in prose, before normalization.
- `parsePromotionRowsFromSibling(sibling_body) → Array<{name, canonical_name, status, source_kind}>` — parse `people-aliases.md` tables: "Inner circle entry" + "Elevation-only names" + "Observed frequent collaborators" rows. Status from "Promote to inner circle?" column (`confirm` / `promoted` / `skip` / blank → `confirm`).
- `parseStakeholdersFromVaultConfig(vault_config_yaml, engagement_id) → string[]` — extract from `engagements[<id>].stakeholders[]`, `engagements[<id>].manager` (single string), `engagements[<id>].direct_reports[]` (when present).
- `aggregateCandidates({microscopeNames, siblingRows, vaultConfigNames}) → Array<{canonical_name, sources: Array<{source_type, source_kind?, source_path}>, status_from_sibling}>` — dedup on canonical_name (case-insensitive); each candidate carries its source provenance for the review table.
- `classifyCandidate({candidate, resolveResult, current_inner_circle, suppress_list}) → "CREATE_AND_PROMOTE" | "PROMOTE_EXISTING" | "ALREADY_PROMOTED" | "SUPPRESS"` — pure decision based on inputs.
- `composePersonNoteStub({canonical_name, aliases, sources}) → string` — frontmatter + body for new spice/people/<basename>.md. Frontmatter: `name`, `aliases` array (v0.6.0 typed-alias schema; at minimum `{type: "name", value: <basename>}` if any aliases discovered). Body: minimal pointer + provenance comment.
- `composeUpdatedSibling(sibling_body, name_status_map) → string` — flip "Promote to inner circle? confirm" → "promoted" for each name in the map. Idempotent (already-promoted rows untouched).
- `composeUpdatedVaultConfig(vault_config_body, engagement_id, names_to_append) → string` — append names to `engagements[<id>].inner_circle_people[]`. Idempotent (dedup against existing entries).
- `composeReviewTable(candidates_with_status) → string` — markdown table grouped by status, with source-provenance column. For the batch-confirm interaction.
- `composeReport({applied, skipped, sources_scanned, engagement_id}) → string` — markdown summary written to stdout AND optionally to a result atomic note (v0.28.0 scope: stdout only).

All pure: no I/O, no MCP calls, no throws. Receives parsed strings; returns strings.

### Orchestrator step flow

```
1. Pre-flight: cowork:check-vault-routing {required: ["obsidian"]}
2. Resolve target engagement:
   - If input.engagement_id provided + valid → use it
   - Else read vault-config.md engagements[]:
     - 1 engagement → auto-pick
     - >1 engagements → ask user one question with multiple-choice options
3. Discover candidates:
   a. List spice/cowork/prompts/per-mcp/*/ via obsidian MCP
   b. For each kind dir: read microscope.md (if present) → parseInnerCircleFromMicroscope
   c. For each kind dir: read people-aliases.md (if present) → parsePromotionRowsFromSibling
   d. Read vault-config.md → parseStakeholdersFromVaultConfig(_, engagement_id)
   e. aggregateCandidates({...}) → candidates[]
4. Classify each candidate:
   a. For each candidate: call cowork:resolve-person {input: candidate.canonical_name, prefer_type: "name", engagement_id}
   b. Read current_inner_circle from vault-config.md engagements[<id>].inner_circle_people[]
   c. Compute suppress_list from people-aliases.md "Personal / non-work senders" suppress sections across all kinds
   d. classifyCandidate({candidate, resolveResult, current_inner_circle, suppress_list}) → status
5. Compose review table via composeReviewTable; print to chat
6. Ask user (single batch confirm): "Apply these N actions? (y / n / specific row numbers to skip, e.g. 'skip 3,7,12')"
7. Parse response:
   - y → all proposed actions
   - n → exit without writes
   - "skip <list>" → apply all EXCEPT listed row numbers
8. On apply:
   a. For each CREATE_AND_PROMOTE: call composePersonNoteStub; write spice/people/<basename>.md via mcp__obsidian__obsidian_put_content (only if NOT already existing — landmine #12-style backup convention)
   b. For each CREATE_AND_PROMOTE and PROMOTE_EXISTING: collect basename into names_to_append
   c. Read vault-config.md, composeUpdatedVaultConfig(body, engagement_id, names_to_append), write back
   d. For each people-aliases.md file touched: write .bak per landmine #12, then composeUpdatedSibling(body, name_status_map), write back
9. Compose final report via composeReport; print to stdout
```

### UX guarantees

- Idempotent re-run: re-running shows only candidates NOT in current `inner_circle_people` and NOT in suppress-list. Previously-declined candidates re-appear (naive re-discovery). Writes are deduplicated.
- Per landmine #12: ANY edit to `.obsidian/`-allowlisted or user-owned files requires `.bak`. Per landmine #19: paths are hardcoded (`spice/people/`, `spice/cowork/context/vault-config.md`, `spice/cowork/prompts/per-mcp/`); no glob walk from arbitrary roots.
- Microscope.md is USER-OWNED — never written by this skill.
