# Note-chrome wave 1 + foundation closure + hygiene — design (v0.124.0)

## Mission

Third plan of the note-chrome standard arc. The `section-label` (v0.122.0) and
config-driven `breadcrumb` (v0.123.0) mechanisms are LIVE on all four consumer
vaults with zero drift. This cycle **broadcasts the standard** across three more
blueprints and **closes the remaining foundation items** in one bundled release:

1. **Adoption wave 1** — `meetings`, `scratch`, daily `to-do` declare breadcrumb
   trails and conform to the chrome grammar.
2. **Foundation closure** — `lint-note-chrome.js` gate, `nav-buttons`/`accent-button`
   bug fixes, `openInReadMode()` helper, and the canonical `note-chrome.md` guide.
3. **Pre-adoption hygiene** — `project_name` FM backfill heal + retroactive
   schemas-index entries.

This is the **largest single cycle of the arc**: 7 component bumps + 2 heal
migrations + a new preflight gate + the canonical doc. It is intentionally
bundled per owner request. Implementation is decomposed into independently
testable tasks (§8) under one `v0.124.0` bump / one PR.

## Decided in brainstorming (2026-06-17)

- **Scope:** all three buckets ship together as v0.124.0 (owner choice).
- **Heal posture:** Option B — template injection **plus** a consolidated
  chrome-heal that backfills existing notes (owner choice). Existing
  meetings/scratch/scratch-day/todo-daily notes get the breadcrumb call injected
  and static `## H2` rewritten, so old + new notes render identically.
- **Lint scope:** Option B — full `## H2` conformance. `lint-note-chrome.js`
  bans `## H2` in managed blueprint templates, enforces the chrome `---` grammar,
  and requires a `breadcrumb` declaration per manifest.
- **§2 SectionLabel tradeoff (ratified):** content `## H2` → `SectionLabel`
  everywhere, accepting that SectionLabel is a rendered `<div>` not a heading —
  so converted sections leave the Obsidian outline and `[[note#Heading]]` anchors
  break. Cost is deliberate and documented in `note-chrome.md`; the `.sauce-backup`
  snapshot makes the heal reversible; meeting/scratch notes are ephemeral and
  rarely heading-anchored.
- **Month tier:** comes from the physical `MM-MMMM` folder via `path:N`. No new
  resolver primitive; `breadcrumb` mechanism JS does **not** change (stays 0.1.0).
  Month renders as the raw folder string (`06-June`) — accepted cosmetic, per
  [[feedback-breadcrumb-registry-grammar]].

## 1. Wave-1 breadcrumb trails

All three blueprints are month-foldered, so every trail tier maps to a real
`path:N` segment or a literal. Per-blueprint `breadcrumb: { types: { ... } }`
blocks are added to each manifest (shape mirrors `platform/blueprints/project/manifest.json`).
Registry dispatch key is `(blueprint, fm:type)`.

### meetings
- Leaf path: `spice/meetings/notes/YYYY/MM-MMMM/<title>-YYYY-MM-DD.md`
  → `path:0=spice 1=meetings 2=notes 3=YYYY 4=MM-MMMM 5=<file>`
- Leaf `type: meeting`. Monthly hub has no `type` → renders nothing (correct).

```json
"meeting": {
  "ancestors": [
    { "label": "lit:Meetings" },
    { "label": "path:4" }
  ],
  "current": { "label": "file:basename" }
}
```
Trail: `Meetings / 06-June / <meeting title>`

### scratch
- Leaf path: `spice/scratch/YYYY/MM-MMMM/YYYY-MM-DD/Scratch-YYYY-MM-DD-HH-mm.md`
  → `path:0=spice 1=scratch 2=YYYY 3=MM-MMMM 4=YYYY-MM-DD 5=<file>`
- Leaf `type: scratch`; day-hub `type: scratch-day` at the same depth minus the file.

```json
"scratch": {
  "ancestors": [
    { "label": "lit:Scratch" },
    { "label": "path:3" },
    { "label": "path:4",
      "link": "spice/scratch/{path:2}/{path:3}/{path:4}/Scratch-Day-{path:4}.md" }
  ],
  "current": { "label": "fm:time|file:basename" }
},
"scratch-day": {
  "ancestors": [
    { "label": "lit:Scratch" },
    { "label": "path:3" }
  ],
  "current": { "label": "path:4" }
}
```
Leaf trail: `Scratch / 06-June / 2026-06-17 (→ day hub) / 14:30`
Day-hub trail: `Scratch / 06-June / 2026-06-17`

### to-do (daily only)
- Leaf path: `spice/to-do/YYYY/MM-MMMM/ToDo-YYYY-MM-DD.md`
  → `path:0=spice 1=to-do 2=YYYY 3=MM-MMMM 4=<file>`
- Leaf `type: to-do`. (Project To-Do `type: project-todo` is already owned by the
  project blueprint — out of scope.)

```json
"to-do": {
  "ancestors": [
    { "label": "lit:To-Do" },
    { "label": "path:3" }
  ],
  "current": { "label": "file:basename" }
}
```
Trail: `To-Do / 06-June / ToDo-2026-06-17`

### Open verification (resolve in plan)
- Whether a stable top-level hub note exists for meetings/scratch/to-do that the
  `lit:` root segment could link to. If none, the root stays plain text (current
  proposal). Do **not** invent a hub.
- `current` label polish (e.g. strip the `ToDo-` prefix or `.md` date) is a
  cosmetic-only follow-up; ship the basename first.

## 2. Template conformance

Inject the breadcrumb block at the very top of each managed template, before the
first nav view, with **no `---` between breadcrumb and the global nav bar**
(precedent: `platform/blueprints/to-do/templates/Project To-Do.md`):

```dataviewjs
await dv.view("{{views_path}}/customjs-guard", { class: "Breadcrumb" });
```

Then convert static content `## H2` → `SectionLabel`:

| Template | Current `## H2` | Action |
| --- | --- | --- |
| `meetings/templates/Meeting.md` | `## Attendees`, `## Agenda`, `## Notes`, `## Action Items` | → `SectionLabel` (first uses `top: true`) |
| `scratch/templates/Scratch Day Hub.md` | `## Today's Scratch` | → `SectionLabel` |
| `scratch/templates/Scratch.md` | — (none) | breadcrumb inject only |
| `to-do/templates/Today To-Do.md` | — (none) | breadcrumb inject only |

`SectionLabel` calls follow the Project To-Do shape:
```dataviewjs
await dv.view("{{views_path}}/customjs-guard", { class: "SectionLabel", args: [{ text: "Notes" }] });
```
`SectionLabel` manages its own hairline (`top: true` suppresses it); the chrome
`---` grammar applies only between nav tiers.

Manifest `depends_on` additions:
- **meetings:** add `breadcrumb >=0.1.0` + `section-label >=0.1.0`.
- **scratch:** add `breadcrumb >=0.1.0` + `section-label >=0.1.0`.
- **to-do:** already depends on both — add the daily registry contribution only.

## 3. Consolidated chrome-heal migration

`applyNoteChromeHeal()` in `platform/install.js`, modeled byte-for-byte on
`applyDocsHubButtonRepair`:
- Per-note `try/catch`; one `.sauce-backup` snapshot before any write.
- **Idempotent:** skip injection if a `Breadcrumb` view is already present; skip
  rewrite if the `## H2` is already a `SectionLabel` block.
- **Fails loud, never throws** — collects per-note errors into the installer
  report; one bad note never aborts the run.
- **Stable-anchor matching:** key on the dataviewjs invocation substring + the
  note's frontmatter `type`, **never** on display markers (per landmines).

Targets (existing notes):
- `type: meeting` → inject breadcrumb; rewrite the 4 `## H2` → SectionLabel.
- `type: scratch` → inject breadcrumb.
- `type: scratch-day` → inject breadcrumb; rewrite `## Today's Scratch` → SectionLabel.
- `type: to-do` (daily) → inject breadcrumb.

Plus the **seed-vault family**: fixtures carrying the pre-heal shape + portable
sentinels + asserts proving (a) post-heal render parity and (b) idempotency on a
second pass. See `Docs/agent-guides/migration-regression-net.md`.

## 4. Pre-adoption hygiene

### project_name FM backfill heal
`map`/`kanban`/`task-note` breadcrumb labels fall back to `path:2` (the slug) when
`fm:project_name` is absent, so mixed-case projects show the slug instead of the
display name. Add a heal (`applyProjectNameBackfill()` or fold into the existing
project heal family) that backfills `project_name` from the project note's display
name. Same safety posture as §3. Seed-vault family included.

### schemas-index parity
Add `nav-buttons-registry` and `entity-create-registry` entries to
`platform/schemas-index.json` (kind `data-file`, owner the respective mechanism),
matching the v0.123.0 `breadcrumb-registry` entry. `npm run lint-schemas` gates
source-file existence.

## 5. Foundation closure

### lint-note-chrome.js (new)
`scripts/lint-note-chrome.js`, wired into `release:preflight` **after**
`seed:rebaseline` (per [[lesson-execfilesync-maxbuffer]] ordering note). Rules:
- Chrome region (top of every managed template): breadcrumb view present and
  first; exactly one `---` between nav tiers, no doubles, no blank-line gaps.
- **No `## H2`/`### H3`** in managed blueprint templates.
- Every blueprint manifest that renders Breadcrumb declares a `breadcrumb` block.
- Self-test fixture so the gate is itself covered.

### Button fixes
- **nav-buttons** (MINOR): `flex-wrap: wrap` on the row + label-span ellipsis
  safety net so long labels wrap/truncate instead of overflowing.
- **accent-button** (PATCH/MINOR): replace the `cssText` rebuild on hover with
  individual style-property mutation to kill the New Doc / New Section jitter.

### openInReadMode helper
Add `openInReadMode(file)` to the `convenience` mechanism (MINOR). Route every
create+open site through it so brand-new notes open in read/preview, never
edit-with-title-selected:
- `entity-create.js` (both `openFile` sites)
- `nav-buttons` action handlers
- `project-task-create-listener.js` (+ any other `openLinkText`/`openFile` create sites)

### Docs
- Generalize `Docs/agent-guides/project-blueprint-ui.md` → `Docs/agent-guides/note-chrome.md`:
  vault-wide chrome grammar, button rules, open-mode rule, breadcrumb-declaration
  schema, the **no-`## H2` / SectionLabel-everywhere** rule **and its outline/anchor
  tradeoff**, and migration posture.
- Add a CLAUDE.md "Further reading" router row for `note-chrome.md`.
- Add a `Docs/landmines.md` entry: managed templates conform to note-chrome grammar;
  heal existing notes via migration, never hand-edit.

## 6. Version lockstep + deploy

Bumps (every source change → lockstep, gated by `node scripts/check-version-sync.js`):
1. Component versions: `meetings`, `scratch`, `to-do`, `project` (project_name heal),
   `nav-buttons`, `accent-button`, `convenience`.
2. `platform/manifest.json` catalogue entries for each.
3. `package.json` → `0.124.0`.
4. `platform/manifest.json` `workshop_version` → `0.124.0` (install.js + lint change).
5. `ranch/platform-subscription.json` pins (workshop self-sub).
6. `platform/test/seed-vault/ranch/platform-subscription.json` pins (seed;
   `workshop_version` stays lagged).
- **breadcrumb mechanism: NO JS change → stays 0.1.0** (consumes more registry entries).

### Deploy traps (all load-bearing)
1. **[[lesson-bump-pins-no-transitive-add]]** — meetings + scratch newly
   `depends_on` breadcrumb + section-label. Each consumer vault subscribed to
   those blueprints must have breadcrumb + section-label in its
   `ranch/platform-subscription.json` **before** `sauce update`, or the installer
   skips them. Patch with the v0.123.0 `jq` one-liner per vault.
2. **[[lesson-wizard-default-mechs-lags-catalogue]]** — `DEFAULT_MECHANISMS_CHECKED`
   already lists breadcrumb + section-label; no wizard change needed. Re-verify.
3. **[[feedback-no-workflow-yaml-push-via-claude]]** — no `.github/workflows/*.yml`
   edits via Claude; route to owner if needed.
4. Branch protection on main; `enforce_admins: false` → owner `gh pr merge --admin`.
5. **Worktree gotcha** — verify every Write with `git status --short` from the worktree.
