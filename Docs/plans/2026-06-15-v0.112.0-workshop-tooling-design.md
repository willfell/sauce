# v0.112.0 design — workshop tooling

## 0. Posture

Four independent zero-dep node scripts (+ one doc), each one file, each `node <path>` invokable, each idempotent. No shared library — each script reads what it needs and writes what it owns. Failure modes are loud + non-fatal (warn + continue when individual signals miss).

All scripts live under `scripts/` (already where `dev-sync.sh`, `check-version-sync.js`, `preflight/` live). All wired via npm scripts in `package.json` for discoverability.

Versioning posture: workshop 0.111.3 → **0.112.0** (MINOR). All blueprint and mechanism versions UNCHANGED. The bump is justified by the new surface; no migration required because workshop-internal tooling doesn't ship to consumers.

```
  (use --fresh to re-run)
```

### 1.2 Inputs

- `platform/manifest.json` → workshop_version + blueprint versions + mechanism count.
- `git` shell-outs: `git status -sb`, `git log --oneline -5`, `git rev-list --count origin/main..HEAD`, `git rev-parse --short HEAD`.
- `Docs/plans/*-result.md` → sorted by filename date prefix (which encodes cycle date); take top 3. Frontmatter `cycle_arc:` for short label.
- `Docs/plans/*-brief.md` and `*-design.md` and `*-plan.md` — match prefix against existing `*-result.md`; any orphans = in-flight.
- The most recent `*-result.md` → grep `## Carries forward` section, list bullets.
- `.workshop-status-cache.json` (gitignored) → last-known harness counts + timestamp.

### 1.3 Flags

- `--fresh` — re-run helper-cases + behavioral harness + preflight; update cache.
- `--json` — emit machine-readable JSON instead of formatted prose (for downstream tooling).
- `--no-color` — disable ANSI codes (default detect TTY).

### 1.4 Error handling

- If `platform/manifest.json` missing → exit 2 with "not in a workshop root."
- If `git` not available → fall back to "git unavailable" line; everything else still prints.
- If `Docs/plans/` empty or missing → prints "no result docs found" for that section.
- All path resolution relative to script's `__dirname/..` so it works regardless of cwd.

### 1.5 Implementation notes

- No deps; uses `child_process.spawnSync` for git, `fs.readFileSync` for everything else.
- Color via raw ANSI (`\x1b[32m...\x1b[0m`) — no `chalk`.
- ~250 LOC budget.

## 2. `scripts/regen-cycle-status.js` — cycle-status auto-update (Cycle #15)

### 2.1 Contract

```
$ node scripts/regen-cycle-status.js [--check] [--verbose]
```

**Default:** rewrites `Docs/agent-guides/cycle-status.md § Current` to reflect the most recent `Docs/plans/*-result.md`. Idempotent (re-running on a fresh file = no-op).

**`--check`:** dry-run; exits 1 if drift detected (cycle-status doesn't match what regen would produce); exits 0 if in-sync. Diff printed to stderr.

### 2.2 Algorithm

1. Discover all `Docs/plans/*-result.md` files. Sort by filename date prefix DESC.
2. Take the most recent. Parse frontmatter `cycle_arc:` + content's `## What shipped` section.
3. Parse current `Docs/agent-guides/cycle-status.md`:
   - Identify `## Current` section (delimiter: from `## Current` to next `## ` at same level).
   - Identify each historical entry (`- **Workshop version (previous):** \`X.Y.Z\``).
4. Construct the desired `## Current` block:
   - `**Workshop version:** \`X.Y.Z\` (closed YYYY-MM-DD)` — from `platform/manifest.json` + result-doc filename date.
   - `**Most recent cycle:**` — one-paragraph summary from the result doc (truncated to ~400 chars + "See {result-doc-path}.").
5. If the existing `## Current` workshop_version differs from manifest, DEMOTE the existing current to a `**Workshop version (previous):**` entry and INSERT the new current at the top.
6. Write the file back.

### 2.3 Drift backfill

The cycle-status file currently lists v0.108.0 as current. Workshop is at 0.111.3. Five missed closes (v0.109.0 / v0.110.0 / v0.110.1 / v0.110.2 / v0.110.3 / v0.110.4 / v0.110.5 / v0.111.0 / v0.111.1 / v0.111.2 / v0.111.3 — actually 11 missed). On first run, the script SHOULD insert all missed entries as `(previous)` rows in descending order. Heuristic: walk every `*-result.md` newer than the current `## Current` workshop_version's close date.

If the user wants minimal disruption, the script supports `--current-only` to update only the top entry and leave the historical list untouched. Default mode is full sync.

### 2.4 Failure modes

- Result doc has no `cycle_arc:` frontmatter → script falls back to filename for the version label; emits warning.
- Multiple `*-result.md` files for the same cycle version → take the newest by mtime.
- The current `## Current` block can't be parsed → script refuses to write, prints the unparseable section, exits 3.

### 2.5 `--check` mode in CI

After one clean run (post-drift backfill), wire `node scripts/regen-cycle-status.js --check` into `release:preflight` to catch future cycles that ship without updating cycle-status. NOT wiring in v0.112.0 — wait for one clean cycle first.

## 3. `scripts/scaffold-behavioral-harness.js` — per-cycle harness scaffold (Cycle #12)

### 3.1 Contract

```
$ node scripts/scaffold-behavioral-harness.js <cycle-id> <topic-slug>
```

**Example:**
```
$ node scripts/scaffold-behavioral-harness.js v01120 workshop-tooling
→ wrote platform/test/run-v01120-workshop-tooling.js (412 lines)
   wire it into release:preflight in package.json (added between run-v01103-monthly-overview.js and the closing quote).
```

### 3.2 What gets emitted

The boilerplate from `run-v01103-monthly-overview.js` (the canonical zero-dep template):

- Opening doc-comment block with cycle-id + coverage map placeholder.
- `WORKSHOP` + helper-dir constants resolved from `__dirname`.
- `passed` / `failed` / `failures` counters + `ok()` + `eq()` + `approxEq()` helpers.
- `makeEl()` DOM stub (Obsidian-style `createEl` chain).
- `walkTree` / `collectText` helpers.
- `makeStrictDA` + `makeStrictDv` (Dataview-proxy stubs from v0.111.3-CF1).
- `loadClass(filename, className)` helper.
- Two empty section placeholders: `// SECTION 1 — TODO: behavioral cases here` and `// SECTION 2 — TODO: migration / contract cases here`.
- Verdict footer block.

### 3.3 Flags

- `--force` — overwrite target if it exists (default: refuse).
- `--dry-run` — print to stdout instead of writing.

### 3.4 Failure modes

- `<cycle-id>` not matching pattern `v\d+` → exit 2 with format hint.
- `<topic-slug>` not matching pattern `[a-z][a-z0-9-]*` → exit 2.
- Target path exists without `--force` → exit 3.

### 3.5 Wiring guidance

The script prints a one-line reminder to wire into `package.json`'s `release:preflight` chain. It does NOT auto-edit `package.json` (too easy to corrupt a long single-line script field). Manual edit is one Edit tool call.

## 8. Out-of-scope (explicit)

- No `sauce` CLI extension (brew tap stale; no consumer benefit yet).
- No interactive scaffolder (zero-dep promise).
- No CI gating on `regen-cycle-status --check` (wait one clean cycle).
- No replacement of `dev-sync.sh` (already works).
- No `sauce doctor --finance` (brainstorm #14 — separate cycle).
- No `cowork:doctor` (brainstorm #18 — separate cycle).

## 9. Decisions locked at brainstorm

1. **Pure standalone scripts, not `sauce` verbs.** Avoids brew-tap dependency. Consumer vaults never see these.
2. **Zero-dep node + bash.** Same posture as the rest of `scripts/`. No `chalk` / `commander` / `inquirer`.
3. **One script per cycle item.** No shared lib. Each script reads what it needs.
4. **`regen-cycle-status` defaults to full-sync.** `--current-only` is the escape hatch, not the default. User opted into automation; full-sync is the point.
5. **Scaffold script does NOT auto-edit `package.json`.** Prints a reminder; manual edit is one tool call. Avoids long-single-line-script field corruption.
