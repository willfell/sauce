### 0.2 Diagnosis (verbatim, for the record)

1. **Template errors creating People.** `platform/blueprints/people/manifest.json` declares a `templater_folder_templates[]` entry binding `spice/people/` → `Template, People.md`. The `+ New Person` button (entity-create@0.1.0) writes a complete file (frontmatter + inline_body) at `spice/people/<Name>.md`. Templater then auto-fires its template against the just-written file: writes a second frontmatter block, attempts `<%* await tp.file.move("spice/people/" + tp.file.title) %>` on a file already at destination. Net: double frontmatter / literal `<% tp ... %>` text in body / Templater error toast.
2. **`people:` field is dead.** Meeting.md Templater template writes both `attendees: [[Name]]` and `people: [[Name]]` from the same input array. Validator rule for `spice/meetings/notes/**/*.md` requires only `attendees`. MeetingsHubCards subtitle reads `attendees`. `PeopleRendering.renderMentionList(mode: "mentioning_person")` walks `file.outlinks` (body wikilinks + any YAML wikilinks Dataview surfaces as outlinks) — works regardless of which field is populated. No reader looks at `people:` specifically. The field exists only in the entity-create button's `frontmatter_template` as empty `[]` and in the Templater template as duplicated `attendees`.
3. **Naming pattern over-strict.** `^[A-Z][a-zA-Z'\\- ]+ [A-Z][a-zA-Z'\\- ]+\\.md$` requires "First Last". Rejects mononyms ("Madonna"), 3-part names ("John Paul Smith"), diacritics ("Élise Martin"), prefixes ("Dr. Strange"). Audit flags as errors; chip renderer marks as Unknown.
4. **No autocomplete in Meeting attendees prompt.** Meeting.md Templater template uses `tp.system.prompt("Attendees (comma-separated, e.g., Stefan de Pagter, Alex Palacios):", "")` — free text. User has no way to see which People already exist; mistyped names create orphan wikilinks that don't resolve.

## 1. Scope

### 1.1 §1 `people` blueprint — single canonical creation path + naming-rule relaxation

**Location.** `platform/blueprints/people/manifest.json`, `platform/blueprints/people/templates/Template, People.md`.

**Changes.**

1. **Remove** `templater_folder_templates[]` entry binding `spice/people/` → `Template, People.md`. The entity-create button becomes the only canonical creation path. `Template, People.md` survives in `files[]` so users can `Insert template → Template, People.md` manually into a blank note (escape hatch for paste-import workflows).
2. **Remove** the `<%* await tp.file.move("spice/people/" + tp.file.title) %>` line from `Template, People.md`. (With the folder-template binding gone, this line is dead anyway; cleaner to nuke explicitly for future readers.)
3. **Relax** `rule_fragments[0].fragment.naming_pattern` from `^[A-Z][a-zA-Z'\\- ]+ [A-Z][a-zA-Z'\\- ]+\\.md$` to `^[A-ZÀ-Ý][A-Za-zÀ-ÿ'’\\.\\- ]*\\.md$`. New pattern accepts:
   - Mononyms — `Madonna.md`, `Cher.md`
   - Diacritics — `Élise Martin.md`, `Søren Højberg.md`
   - Multi-part — `John Paul Smith.md`
   - Honorifics with periods — `Dr. Strange.md`
   - Apostrophes (straight + curly) — `O'Brien.md`, `O’Brien.md`
   - Hyphens — `Mary-Anne Smith.md`
   And rejects: lowercase-leading (`will fellhoelter.md`), digit-leading (`123Person.md`), special chars (`Steve!.md`), empty (`.md`).
4. **Version bump.** `manifest.json` `version: "0.4.0" → "0.5.0"`. Description gets a v0.5.0 trailer paragraph describing the consolidation (per repo convention; see existing manifest description for v0.2.0, v0.4.0 trailer patterns).

### 1.2 §2 `meetings` blueprint — suggester-loop autocomplete + `people:` mirror

**Location.** `platform/blueprints/meetings/manifest.json`, `platform/blueprints/meetings/templates/Meeting.md`.

**Changes.**

1. **Replace** the entire opening `<%* ... -%>` block at the top of `Meeting.md` (the one containing the `tp.system.prompt("Attendees…")` call) with a suggester loop. The frontmatter block immediately below is then re-written per item 2. Body bullet-list block at the bottom keeps iterating `attendees[]` unchanged.

   ```js
   <%*
   // SUGGESTER_LOOP_V0880 — regression sentinel; do not remove.
   const peopleFiles = app.vault.getMarkdownFiles()
     .filter(f => f.path.startsWith("spice/people/") && f.basename !== "People")
     .map(f => f.basename)
     .sort();

   const SENTINEL_ADD = "+ Add new person…";
   const SENTINEL_DONE = "Done — finish meeting";
   const attendees = [];

   while (true) {
     const options = [SENTINEL_DONE, SENTINEL_ADD, ...peopleFiles.filter(n => attendees.indexOf(n) === -1)];
     const labels  = options.slice();
     const picked = await tp.system.suggester(labels, options, true,
       attendees.length === 0
         ? "Pick first attendee (or Done to skip)"
         : `Pick another attendee (${attendees.length} so far) or Done`);
     if (picked === undefined || picked === SENTINEL_DONE) break;
     if (picked === SENTINEL_ADD) {
       const newName = await tp.system.prompt("New person name (First Last, mononym OK):", "");
       if (!newName) continue;
       const trimmed = newName.trim();
       if (!trimmed) continue;
       // Best-effort create; if file exists, silently fall through to add-to-attendees.
       const stubPath = `spice/people/${trimmed}.md`;
       const existing = app.vault.getAbstractFileByPath(stubPath);
       if (!existing) {
         try {
           await app.vault.create(stubPath, `---\ntype: person\ncreated_at: "${tp.date.now("YYYY-MM-DDTHH:mm:ssZ")}"\naliases: []\n---\n\n# [[${trimmed}]]\n\n## Notes\n-\n`);
           peopleFiles.push(trimmed);
           peopleFiles.sort();
         } catch (e) {
           // Swallow — duplicate or invalid name; user can retry.
         }
       }
       if (attendees.indexOf(trimmed) === -1) attendees.push(trimmed);
       continue;
     }
     if (attendees.indexOf(picked) === -1) attendees.push(picked);
   }
   -%>
   ```

2. **Write `people:` mirroring `attendees:`** in the frontmatter loop. New template frontmatter block:

   ```yaml
   attendees:
   <%* for (const attendee of attendees) { tR += `  - "[[${attendee}]]"\n`; } -%>
   people:
   <%* for (const attendee of attendees) { tR += `  - "[[${attendee}]]"\n`; } -%>
   ```

   At creation, `people:` is byte-identical to `attendees:`. User can append discussed-but-absent people manually post-creation. (Cowork-driven population is slice D's territory.)

3. **Body bullet list stays unchanged** — still emits `- [[Name]]` for each attendee in the Attendees section. The `## Attendees` dataviewjs block above the bullets continues to use `mode: "mentioned_in_note"` (which reads body wikilinks); no contract change there.

4. **Entity-create button path (`new_entity_buttons[0]`) — no changes** in slice A. Button-driven creation still produces `attendees: []`, `people: []` empty. Adding a button-side suggester prompt requires extending the `entity-create` mechanism with a new prompt type (`people-multi`) — that's slice B's job.

## 2. Data flow

### 2.1 Person creation — before vs after

**Before (broken):**

1. User clicks `+ New Person` in `spice/people/People.md`.
2. entity-create resolves destination `spice/people/Will Fellhoelter.md`, writes frontmatter + inline_body.
3. Obsidian detects new file in `spice/people/` → Templater folder-template binding fires.
4. Templater opens `Template, People.md`, re-templates the file: writes second frontmatter block above existing one, attempts `tp.file.move(...)` against a file already at destination (no-op or error), leaves literal `<% tp ... %>` text where the templater syntax couldn't resolve (because the file already had non-templater content).
5. **Result:** double-frontmatter file / broken body / templater error toast / file may not show in PeopleHubCards depending on how badly the frontmatter got mangled.

**After:**

1. User clicks `+ New Person`.
2. entity-create writes `spice/people/Will Fellhoelter.md` — frontmatter + inline_body.
3. Templater folder-template binding does not exist → no auto-fire.
4. File correct. PeopleHubCards (folder-scoped) picks it up immediately.

### 2.2 Meeting creation via Templater Meeting.md insert — before vs after

**Before:**

1. User opens blank note, runs `Insert template → Meeting.md`.
2. Templater prompts `Attendees (comma-separated, e.g., Stefan de Pagter, Alex Palacios):`. User types from memory.
3. Frontmatter written: `attendees: [[Stefan de Pagter]]`, `people: [[Stefan de Pagter]]` (duplicate, but undocumented). Body bullet list shows `- [[Stefan de Pagter]]`.
4. If "Stefan" doesn't exist as `spice/people/Stefan de Pagter.md`, the wikilink dangles. No discovery path; no creation prompt.

**After:**

1. User runs `Insert template → Meeting.md`.
2. Suggester loop opens with all existing `spice/people/*.md` + `+ Add new person…` + `Done`.
3. User picks names one at a time. Each picked name accumulates into `attendees[]`.
4. `+ Add new person…` prompts for a name, runs `app.vault.create` with minimal `type: person` frontmatter, adds to `peopleFiles[]` (so it's pickable for the next iteration of the loop) and to `attendees[]`.
5. User picks `Done`. Template writes `attendees: [[..]]` and `people: [[..]]` (mirrored) in frontmatter; body bullet list iterates `- [[Name]]`.
6. All wikilinks resolve (because either pre-existing or just created in step 4).

### 2.3 Meeting creation via entity-create button — unchanged

The button path on `Meeting Hub.md` still prompts only for title, writes empty `attendees: []` and `people: []` arrays + `SpaceNavButtons` body. User opens the file, types attendees manually in the body bullet list. **This path doesn't gain autocomplete in slice A** — that's a slice B feature requiring the entity-create mechanism to support a `people-multi` prompt type.

### 2.4 Render flow — unchanged

- `PeopleHubCards` (`scripts/people-hub-cards.js`) — folder-scoped Dataview query over `spice/people` (excluding `People.md`). Picks up every file, including freshly-stubbed ones from the suggester loop.
- `PeopleRendering.renderChip` — looks up file by linkpath via `app.metadataCache.getFirstLinkpathDest`. Resolves cleanly for all new names that match the relaxed naming pattern.
- `PeopleRendering.renderMentionList(mode: "mentioning_person")` — walks `file.outlinks`. Both `attendees:` and `people:` frontmatter wikilinks count as outlinks per Dataview semantics, so the mirror double-strengthens the backlink graph at zero cost.
- `MeetingsHubCards` — subtitle reads `attendees`. Unchanged.
- `BacklinkPanel` `entityType: "person"` — unchanged; reverse-query on any outlink to a `spice/people/*.md` target.

**Emergent property.** Mirroring into `people:` means every person referenced in a meeting frontmatter shows up in person-note backlink panels even before the body bullet list is read. Sets up slice E (brain-map rollups) for free.

### 3.4 Suggester-loop edge cases

| Scenario | Behavior |
| --- | --- |
| No people exist | Loop shows just `Done` + `+ Add new person…`. First attendee creates the first person. |
| User dismisses suggester (Esc) | `picked === undefined` → break loop. attendees stays empty `[]`. Body bullet list emits `-` placeholder per current fallback. |
| User picks same person twice (race / re-pick) | Filter `peopleFiles.filter(n => attendees.indexOf(n) === -1)` removes already-picked names from subsequent iterations. |
| `+ Add new person…` with empty input | `if (!trimmed) continue;` → re-enters loop without modifying state. |
| `+ Add new person…` with name colliding existing file | `getAbstractFileByPath` non-null → skip `vault.create`; still adds to `attendees[]`. |
| `+ Add new person…` with name failing safe-filename (e.g. contains `/`) | `vault.create` throws → caught → `attendees[]` still gets the name (orphan wikilink; user notices and renames). Acceptable in slice A; slice B adds explicit validate-then-warn. |

### 3.5 Templater "Insert template" workflow preservation

After slice A:
- `Template, People.md` is still in `files[]` and accessible via `Insert template → Template, People.md`. User can paste-import a person note from elsewhere into a blank file in any folder, then run Insert template, and the body will scaffold correctly. (The `tp.file.move` line is gone, so the user is responsible for putting the file in `spice/people/` themselves — acceptable tradeoff for escape-hatch workflow.)
- `Meeting.md` is still in `files[]` AND still bound as folder template for `spice/meetings/notes`. Suggester loop now fires on both "Insert template" and folder-create paths.

### 3.6 Cross-blueprint version interlock

`people@0.5.0` and `meetings@0.7.0` ship in the same workshop cycle but install independently. No `depends_on` bumps needed — neither blueprint adds an API surface the other consumes.

### 3.7 Rollback

- `people@0.5.0 → 0.4.0`: re-adds the templater_folder_template binding → restores the bug. **Not safe to roll back.** Mitigation: dogfood install in workshop catches issues pre-tag; smoke + preflight gates.
