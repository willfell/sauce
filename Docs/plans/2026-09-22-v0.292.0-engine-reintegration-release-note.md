# v0.292.0 release note (draft): the engine

**Cycle:** 2026-09-22 · **Version:** workshop 0.291.1 → 0.292.0 (predicted; the bumper computes it from the squashed PR title `feat(engine)!: node-based agent execution as the core of Sauce`) · **Design:** [`engine-reintegration.md`](engine-reintegration.md)

## What this release is

Sauce now ships an engine at its core. A note in your vault declares a graph of typed nodes and edges; `sauce run <note>` executes it, each agent step in its own git worktree, and writes the results back into the note. The delivery loop that Sauce ran for the last three months (a launchd job, a coordinator, gates, a review quorum) is still here as the `mayo` plugin, and its slice pipeline is now also a shipped graph the engine can run.

## Upgrade

```bash
brew upgrade willfell/sauce/sauce
cd <vault> && sauce update
sauce audit --engine
```

`sauce update` subscribes the vault to the `engine` mechanism (always-on) and materializes `/sauce`, the `engine:run` skill, the `Sauce Graph` template, and `ranch/engine/`. `sauce audit --engine` prints `Engine surface intact` when that landed. Repeat per vault.

## Try it in two minutes

1. In Obsidian, create a note from the `Sauce Graph` template. Set `repo:` to a git checkout, or leave it empty for a graph that only reads the vault.
2. `sauce run "<note>" --dry-run` shows the plan and refuses anything the validator dislikes (unknown node type, dangling edge, a cycle with no retry budget).
3. `sauce run "<note>" --worker fake --follow` rehearses the whole graph with the test double; `--worker claude-code` or the node's own `worker:` runs the real thing.
4. Open the note: the `## Runs` section shows every node's outcome, and a `human` node leaves a checkbox for you.

## What changed for existing vaults

- Every subscription gains the `engine` mechanism at the catalogue version. `.claude/commands/sauce.md` and `.claude/skills/engine/` are now installer-managed in every vault; shadow with `.claude/commands.local/` if you need a local variant.
- `platform-claude` is formally always-on (it was always-on by convention).
- The workshop's `/sauce-autoloop` and `/sauce-pipeline` commands, the two-hour plist sample, and the Scout queue are gone. Unattended cadence is `sauce run <note> --install-launchd`.
- Nothing in `.loop/config.json`, the coordinator ledger, or the `/mayo:*` surface changed. `/mayo:run` gains an opt-in engine mode; the prose pipeline stays the default until one live epic completes through the graph and its ledger has been diffed against a coordinator run of the same shape.

## Known limits

Single machine. Worktrees are the only isolation. Workers block the tick. No join or fan-in nodes yet. The `claude-code` and `codex` adapters are thin shell-outs; the `fake` worker is the one the harnesses drive end to end. Full list in [`Docs/engine.md`](../engine.md) § Limitations.
