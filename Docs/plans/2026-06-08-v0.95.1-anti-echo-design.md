# v0.95.1 cowork-anti-echo — design

> [!info]+ Status
> DRAFT awaiting user spec review. Plan phase opens after approval.

## 0. Origin

Surfaced 2026-06-07 evening while explaining the cowork memory layer end-to-end. The framing question that opened the thread: *does cowork limit creativity for the sake of consistency?* Honest audit: form is constrained for memory continuity (load-bearing), voice is parameterized to be the **user's** fingerprint (not a generic AI's), content is generative — BUT the memory loop has an unaddressed gravity well.

The mechanism: yesterday's synthesis lands in tomorrow's prompt → tomorrow's output gets shaped by that frame → tomorrow's tick captures the reshaped behavior → next synthesis confirms the frame. The user is in the loop (reads the frame → behaves according to it → tick captures the behavior). This is the **echo**. No shipped or planned cycle pushes against it. v0.87 semantic retrieval will *amplify* it.

The sketch at `Docs/plans/2026-06-07-v0.96.x-anti-echo-sketch.md` proposed three composable knobs and queued them for v0.96.0+. The 2026-06-08 brainstorm session made three binding decisions:

1. **Scope:** all three knobs ship in this cycle (not split across cycles per sketch §3).
2. **Slot:** anti-echo jumps the line — becomes v0.95.1. The v0.95.1-migrator design parks for v0.96.0+ resurrection.
3. **Approach:** Production-grade with opt-in everywhere — LLM-based theme extraction, bootstrap Y/N integration, no auto-enabling.

## 1. Scope

Ship three composable knobs that intervene at the three closure points of the echo loop. ALL THREE in one bundled MINOR cycle.

| Closure point | Knob | Cadence |
|---|---|---|
| synthesize-day picks one narrative thread | Knob 1 — `render_aspects.anti_echo` (per-fire callout) | per atomic-note fire |
| morning-briefing reads yesterday's frame | Knob 3 — `lens_shift` cadence (weekly cold MB) | weekly (default Saturday 07:00) |
| Same theme reappears N days running | Knob 2 — `cowork:capture-frame-drift` (background tripwire) | daily, post-synthesize-day |

### 1.1 What ships

- New render aspect: `anti_echo`
- New tripwire aspect: `frame_drift`
- New cadence: `lens_shift`
- New atomic-note type: `cowork-morning-briefing-cold`
- New 13th key in plan-dispatch contract: `excluded_themes[]`
- New sub-skill: `cowork:capture-frame-drift`
- New helpers: `capture-frame-drift-helper.js` (new); extensions to `dispatch-plan-helper.js`, `compose-body-helper.js`, `compose-scheduled-job-wrappers-helper.js`
- New CustomJS class: `CoworkLensShiftCards`
- New Daily Hub section: `## Lens-shift companions`
- Bootstrap-vault gains TWO new Y/N questions per engagement (anti-echo bundle; lens_shift separate)

### 1.2 What does NOT ship (out of scope)

- Semantic retrieval anti-echo (separate problem; addressed when v0.87 ships).
- Auto-pruning of memory.md ticks or syntheses (no retention policy in scope).
- Voice-contract anti-echo (voice is the *user's* fingerprint, not the loop closure mechanism).
- Cross-engagement anti-echo (per-engagement scope strictly).
- Auto-update-prefs (the v0.96.0+ "sibling" — anti-echo is the safety net, ships before).
- The v0.95.1-migrator schema migration (parks; resurrects v0.96.0+).
- Theme-extraction prompt-cache optimization (additive future PATCH if cost grows).

### 2.3 Knob interaction model: independent render

The three knobs share NO runtime data dependencies. Each operates at a distinct architectural point:

- **Knob 1** reads yesterday's `memory.md` via the existing `read-memory` sub-skill → emits one extra callout per atomic note via compose-body.
- **Knob 2** reads the last 5 day-syntheses → emits a drift warning into TODAY's `memory.md` post-synthesize-day; tomorrow's `read-memory` extension picks it up and injects into MB's "Yesterday at a glance."
- **Knob 3** fires MB with `read_memory: false` (via `--cadence lens_shift` flag) → writes a cold-companion atomic note with a distinct `type:`.

Per the brainstorm's YAGNI decision: anti-echo and the existing v0.95.0 `semantic-echoes` callout render INDEPENDENTLY when both are enabled. No cross-knob gating logic.

### 2.4 Layered-preferences integration

The three knobs slot into the v0.95.0 `engagement.overrides` schema as follows:

| Knob | Engagement-type default | Override key | Override value |
|---|---|---|---|
| K1 | `render_aspects.anti_echo: "skip"` | `engagement.overrides.render_aspects.anti_echo` | `"include"` to enable |
| K2 | `tripwire_aspects` does NOT include `"frame_drift"` | `engagement.overrides.tripwire_aspects` | `[...bundle, "frame_drift"]` to enable (REPLACES bundle per v0.95.0 semantics) |
| K3 | `lens_shift` in `supported_cadences` but NOT `default_cadences` | `engagement.cadences.lens_shift` | object with `cron` + (optional) `enabled` keys |

### 2.5 Defaults posture (Approach B — opt-in everywhere)

- ALL engagement-types ship `render_aspects.anti_echo: "skip"`
- ALL engagement-types ship `tripwire_aspects` WITHOUT `"frame_drift"`
- NO engagement-types ship `lens_shift` in `default_cadences`
- Bootstrap-vault adds TWO Y/N questions per engagement → flips opt-ins

Rationale: matches the v0.95.0 spine's posture (knobs available, defaults conservative). Aligns with the "platform generalizability intent" memory note — sauce ships the safety net AVAILABLE to all, ENABLED for none.

## 3. Knob 1 design — anti_echo render aspect

### 3.1 Behavior

When `render_aspects.anti_echo == "include"` for an engagement, the morning-briefing / midday-tripwire / eod-review atomic notes get one extra callout near the end of the body — naming something today's gather surfaced that yesterday's carry-forward bullets did NOT name (or explicitly says "today's gather largely continued yesterday's threads").

The explicit-null branch is load-bearing: if the LLM manufactures novelty when there genuinely is none, output gets noisy. The "say so explicitly" instruction keeps the LLM honest AND produces the signal Knob 2 needs to detect drift (`explicit_null` flag).

### 3.2 Surface changes (5 files)

| File | Change |
|---|---|
| `engagement-types/{personal,w2-fte,consulting}.json` | Add `render_aspects.anti_echo: "skip"` default (3 files) |
| `helpers/dispatch-plan-helper.js` | New exported `deriveExcludedThemes(yesterdayMemory)` — returns string array of raw carry-forward bullets (no extraction; compose-body LLM does the semantic compare) |
| `skills/skills/plan-dispatch/SKILL.md` | When `render_aspects.anti_echo == "include"`, invoke `deriveExcludedThemes`; emit `excluded_themes[]` as the 13th contract key. Otherwise emit `[]` |
| `helpers/compose-body-helper.js` | New `injectAntiEchoCallout(body, excluded_themes, voice_contract)` — appends a `[!question] Outside yesterday's frame` callout when `excluded_themes.length > 0` |
| `skills/orchestrators/{morning-briefing,midday-tripwire,eod-review}/SKILL.md` | Read `excluded_themes` from plan-dispatch contract; pass to compose-body (3 files) |

### 3.3 Data flow

```
read-memory (existing sub-skill, unchanged)
  └─→ yesterdayMemory.carry_forward_bullets = [
        "Q3 planning: any reply from Diana yet?",
        "Tickets 705679 + 706012 still In Review",
        "Saturday cabin trip — confirm route w/ Sarah" ]

plan-dispatch (modified — new branch in pre-flight)
  └─→ if render_aspects.anti_echo == "include":
        excluded_themes = deriveExcludedThemes(yesterdayMemory)
                       // returns the bullets verbatim
      else:
        excluded_themes = []

compose-body (modified — new helper function)
  └─→ if excluded_themes.length > 0:
        body += injectAntiEchoCallout(excluded_themes, voice_contract)
        // injects "> [!question] Outside yesterday's frame
        //         > {{LLM-fill: ONE item from today's dispatch that doesn't
        //         relate to any of {{excluded_themes.join(' | ')}}.
        //         If nothing qualifies, write 'today's gather largely
        //         continued yesterday's threads.'}}"
```

### 3.4 Eligible cadences

`morning-briefing`, `midday-tripwire`, `eod-review` only. `weekly-review` and `monthly-review` SKIP — different granularity, "outside yesterday's frame" doesn't translate to weekly/monthly horizons.

### 3.5 Error / edge cases

- Yesterday's `memory.md` missing (first day of engagement, gap, machine downtime) → `excluded_themes = []` → callout skipped. No error emitted.
- `memory.md` present but `[!tip] Carry-forward` callout missing or empty → same: `excluded_themes = []` → callout skipped.
- `deriveExcludedThemes` parser fails (malformed callout from hand-edits) → returns `[]` + emits ONE structured warning to memory.md frontmatter `warnings:` field. Doesn't crash the run.
- Re-bootstrap behavior: existing engagements with no override are NOT auto-flipped; user must answer Y again. Existing engagements WITH the override preserve their setting (idempotent).

### 3.6 Voice contract integration

The injected callout prompt receives the engagement's `voice_contract` so the explicit-null phrasing inherits personality. Casual-personal might emit "honestly, today was just more of the same Q3 stuff"; professional-w2-fte emits canonical neutral phrasing.

## 4. Knob 2 design — capture-frame-drift

### 4.1 Behavior

Once per day post-synthesize-day, ONE LLM call extracts the dominant themes from the last 5 day-syntheses. Deterministic helper code evaluates three drift rules. If ANY fires, a `[!warning]- Frame may be stuck` callout is appended to TODAY's `memory.md` between the synthesis and `## Ticks` sections. Tomorrow's MB picks it up via the existing read-memory pathway and injects into "Yesterday at a glance."

### 4.2 Surface changes (4 new + 3 modified)

| File | Status | Change |
|---|---|---|
| `skills/skills/capture-frame-drift/SKILL.md` | NEW | Pre-flight + LLM theme extraction + drift evaluation + write |
| `helpers/capture-frame-drift-helper.js` | NEW | `extractThemes(syntheses) → ThemeBundle[]` (LLM); `evaluateDrift(bundles, atomicNotes) → DriftReport`; `composeDriftCallout(report, voice_contract) → string` |
| `skills/orchestrators/synthesize-day/SKILL.md` | MODIFIED | New post-write step (pre-done): READ capture-frame-drift; guarded by `plan.tripwire_aspects.includes("frame_drift")`. capture-frame-drift opens today's memory.md and APPENDS the `[!warning]- Frame may be stuck` callout body + ADDS frontmatter keys `frame_drift_flagged: true` and `frame_drift_at: <ISO>` (additive to v0.84.0 memory.md frontmatter schema; no schema-file update needed since memory.md frontmatter is runtime-shaped) |
| `engagement-types/{personal,w2-fte,consulting}.json` | MODIFIED | Schema permits `"frame_drift"` value in `tripwire_aspects`; defaults still EXCLUDE it (3 files) |
| `skills/skills/read-memory/SKILL.md` | MODIFIED | Extend extraction: pick up `[!warning]- Frame may be stuck` callout from memory.md if present; surface in returned `yesterdayMemory.drift_warning` |
| `skills/orchestrators/morning-briefing/SKILL.md` | MODIFIED | When `yesterdayMemory.drift_warning` is non-null, inject into "Yesterday at a glance" prompt body |
| `skills/skills/plan-dispatch/SKILL.md` | MODIFIED (tiny) | No new key — just permits `"frame_drift"` as a valid `tripwire_aspects` value |

### 4.3 Theme extraction (LLM call)

ONE call per fire per engagement. Model: `claude-haiku-4-5` (sufficient for theme extraction).

```
Input: 5 most recent memory.md synthesis sections + their carry-forward bullets
       (~150 tokens each = ~750 input tokens total)

Prompt: "For each day below, extract: (1) 1-3 dominant themes (2-4 words
        each), (2) the single most-named subject (person, project, or topic).
        Return JSON: [{day: 'YYYY-MM-DD', themes: [string], top_subject: string}]"

Output: ~200 tokens JSON
```

**Cost:** ~$0.0014/fire/engagement → ~$0.50/year/engagement at daily firing. Negligible.

**"Last 5 days" definition:** 5 most recent days WITH a synthesis (not 5 calendar days). Weekend gaps handled cleanly — Mon-Tue-Wed-Thu-Fri counts as 5 even if Sat/Sun have no run.

### 4.4 Drift rules (deterministic, evaluated in helper)

| Flag | Rule | Trigger threshold |
|---|---|---|
| `frame_repeat` | Same theme STRING (case-insensitive equality after trim) appears in ≥4 of 5 days' `themes[]` lists | 4/5 |
| `subject_dominance` | Same `top_subject` value (case-insensitive equality after trim) in ≥3 of 5 days | 3/5 |
| `explicit_null` | Exact phrase "today's gather largely continued yesterday's threads" found via file grep (not LLM) in last 3 days' MB / midday-tripwire / EOD atomic notes (all three Knob-1-eligible cadences) | 3 consecutive |

ANY flag triggers the callout. Multiple flags can compose — the callout lists which fired.

### 4.5 Write target — TODAY's memory.md

```markdown
[frontmatter — adds: frame_drift_flagged: true, frame_drift_at: <ISO>]

# Daily memory — Monday, June 8, 2026

> [!info]- Today's pattern (synthesis)
> ...

> [!tip] Carry-forward to tomorrow
> ...

> [!warning]- Frame may be stuck     ← NEW
> Drift flags fired: {{frame_repeat | subject_dominance | explicit_null}}.
> The {{theme | subject}} {{phrase}} has appeared in {{N of last M}} days.
> Is this still the live frame, or has the system locked onto a stale spine?
> Consider: enable `lens_shift` cadence for a cold-MB perspective tomorrow,
> or revise vault-config.md engagement.overrides.

## Ticks
...
```

### 4.6 Tomorrow's MB pickup

Tomorrow's MB pre-flight already calls `read-memory`. `read-memory` is extended:
- Existing behavior: returns `synthesis_paragraph`, `carry_forward_bullets`, `last_ticks[]`
- New behavior: also returns `drift_warning: string | null` (the body of the `[!warning]- Frame may be stuck` callout if present)

MB's compose-body injects `drift_warning` into the "Yesterday at a glance" callout when non-null.

### 4.7 Error / edge cases

- Fewer than 5 days of syntheses (new engagement, recent install) → skip evaluation entirely. No callout, no warning, no LLM call.
- LLM call fails (timeout, malformed JSON) → emit ONE structured warning to today's memory.md `warnings:` frontmatter; skip drift evaluation. Doesn't crash synthesize-day.
- LLM returns valid JSON but no themes extractable → no flags fire → no callout.
- Today's memory.md doesn't exist post-synthesize-day → can't happen (synthesize-day just wrote it). If race condition: emit warning, skip.
- read-memory extension fails to parse `[!warning]- Frame may be stuck` → returns `drift_warning: null`; MB silently skips injection. Doesn't crash MB.

### 4.8 Voice contract integration

`composeDriftCallout(report, voice_contract)` inherits engagement personality. Casual-personal: "heads up — Q3 has been the spine for 4 days running. Still the real frame?" Professional-w2-fte: canonical neutral phrasing.

## 7. Trade-offs

### 7.1 Accepted

1. **Bundled-MINOR risk.** Knob 2's drift detection ships before any production data validates it. Synthetic test fixtures cover the deterministic helper logic; real-world tuning of thresholds (4/5, 3/5, 3 consecutive) treated as a v0.95.x PATCH followup if needed.
2. **LLM call dependency for Knob 2.** ~$0.50/year/engagement at daily firing. Cost of paraphrasing-robust theme detection. Grep alternative explicitly rejected (Approach A) because echo dynamics emerge precisely where paraphrasing happens.
3. **Knob 3 doubles MB cost on Saturdays per engagement with lens_shift enabled.** Accepted because weekly, not daily.
4. **Knob 1 explicit-null repetition can feel spammy.** Three days in a row of "today's gather largely continued yesterday's threads" IS the signal Knob 2 needs to detect. Not noise — diagnostic.
5. **Visual-only pairing for Knob 3 (no `companion_to:` frontmatter).** Race-free + simpler. Cost: if CustomJS breaks, user sees notes individually instead of paired. Graceful degradation acceptable.
6. **~27-37 HC sub-assert additions.** Comparable to historical MINORs; smoke corpus grows linearly with surface added.
7. **Two new bootstrap Y/N questions.** Adds ~30s per engagement at interview. Discoverability over silence.

### 7.2 Rejected (this brainstorm)

1. **Mutually exclusive anti-echo vs semantic-echoes.** YAGNI — both render independently. Cross-knob gating logic deferred until empirical UX issue surfaces.
2. **`companion_to:` frontmatter linkage for Knob 3.** Visual pairing via CustomJS slug-match is race-free and equally functional.
3. **Auto-enable anti-echo for personal engagement-type (Approach C).** Conflicts with platform-generalizability intent.
4. **Keyword-grep theme extraction (Approach A).** Fails on paraphrasing exactly where echo dynamics emerge.
5. **Split into 3 sequential cycles (sketch §3 sequencing).** User chose bundled MINOR; accepted Knob 2 validation risk in §7.1.1.
6. **Single bootstrap question covering all three knobs.** Knob 3 has materially different cost (doubles MB cost weekly) — separate Y/N for explicit consent.

### 7.3 Preserved from sketch (not relitigated)

- "Force a second narrative thread in synthesize-day" — rejected at sketch time; preserved.
- "Auto-prune stale carry-forwards" — deferred to future cycle; preserved.
- "Cold-twin every day" — rejected at sketch time; preserved (Saturday-only).
