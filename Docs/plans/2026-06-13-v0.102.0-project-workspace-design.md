# v0.102.0 — project workspace (sections + meetings link)

## TL;DR

The project blueprint's Docs Hub renders doc-notes as a flat row list with no
search, no hierarchy, and no way to connect them to meetings. Accuris's
`global-k8s` project has 31 docs of varying kinds (design specs, runbooks,
inventories, scratchpads, execution logs) — flat layout has stopped scaling.
Three platform-level moves, two blueprint MINORs, one mechanism MINOR:

1. **Sections.** Doc-notes get foldered under `docs/<section-slug>/`. Two
   platform-default sections — `Knowledge` and `Notes` — ship for every
   project. Projects can override via `sections: [Knowledge, Notes, ...]`
   in project frontmatter. Docs carry `section:` frontmatter mirroring the
   folder (folder wins on conflict). Tags do orthogonal categorization
   (`#spec`, `#adr`, `#runbook`, `status/active`).

2. **Confluence-style Docs Hub.** Hub renders one labeled bucket per section,
   each as a row card list (preserving the v0.100.0 row aesthetic). One
   `+ New <Section>` button per bucket via `presetPrompts` — no section
   picker on click. `ProjectDocsSections` (new helper) replaces
   `ProjectDocsCards` on the hub view.

3. **Project ↔ Meetings link.** Singular `project: "[[ProjectName]]"` field
   on meeting frontmatter (optional). Project note grows a "Meetings" panel
   above the BacklinkPanel showing the 5 most-recent meetings linked to it,
   with a "+ New meeting for this project" button via `presetPrompts`.
   Meeting Hub rows gain a project pill when set.

Plus an adjacent fix: Sauce install configures Obsidian's default
attachment/new-note paths to `spice/resources/{attachments,notes}/`
(currently left at vault root, scatters new files).

v0.102.1 fast-follow (1-2 days after v0.102.0 dogfood): in-page filter input,
dynamic tag chips, scoped-search button — pure UX layer on top of finalized
section structure; zero schema change.

## Decisions (locked at brainstorm, 2026-06-13)

| Question | Decision |
| --- | --- |
| Section UX model | Filesystem subfolders as source of truth, Confluence-style buckets on hub, tag-based facets orthogonal, template consistency per section |
| Section source | Platform defaults + per-project override (Knowledge, Notes as defaults; arbitrary custom sections allowed) |
| Default count | 2 (Knowledge, Notes) — not 3 — based on user's framing. Specs/ADRs/Runbooks live as tags inside Knowledge, not as a third folder |
| Bucket: Knowledge | Ripened/long-lived reference (specs, decisions, research, runbooks, infrastructure inventory) |
| Bucket: Notes | Raw/short-lived (scratchpads, drafts, execution logs, ticket trackers, stubs) |

## Section 1 — Schema changes

Three frontmatter additions; all backward-compatible.

**Project note** — one new optional field:
```yaml
sections: [Knowledge, Notes]   # optional override; absent/empty = platform defaults
```
Renderer treats absent or empty array as `[Knowledge, Notes]`. Entries are
strings; the rendered label is the verbatim string, the folder slug is
`slugify(entry)` (lowercase, dashes for spaces). Strings preserve casing in
the UI (so `"Customer Research"` shows as such, lives in
`docs/customer-research/`).

**Doc-note** — one new field:
```yaml
section: "Knowledge"           # mirrors parent folder name verbatim
```
Required on new docs (set automatically by EntityCreate from the
`presetPrompts.section` carried in the per-section button). Existing docs
get this field added during migration (defaulting to `"Knowledge"`).

**Meeting note** — one new optional field:
```yaml
project: "[[Global K8s]]"      # singular wikilink; optional
```
Absent or empty = no project link; meeting doesn't surface on any project's
Meetings panel. Set via the new optional `project` prompt at meeting
creation, or by hand-editing.

## Section 2 — Folder layout & migration (Strategy A)

**New project folder layout:**
```
spice/projects/<slug>/
├── <Project Name>.md
├── <slug>-board.md
├── Project Map.md
└── docs/
    ├── Docs.md                 # hub (view rewritten)
    ├── knowledge/              # platform-default
    │   └── <doc>.md
    ├── notes/                  # platform-default
    │   └── <doc>.md
    └── <custom-section-slug>/  # any user-defined section
        └── <doc>.md
```

**Migration step (`applyProjectSectionsMigration`, new install hook):**

1. Walk every project under `spice/projects/<slug>/`.
2. For each project's `docs/` folder:
   - Skip if `docs/knowledge/` already exists (idempotency guard — already
     migrated).
   - Create `docs/knowledge/` and `docs/notes/` (empty initially; only
     `knowledge/` will receive content under Strategy A).
   - For each `docs/*.md` file (excluding `Docs.md`):
     - Move to `docs/knowledge/<filename>`.
     - Edit frontmatter: add `section: "Knowledge"` if absent. Leave all
       other frontmatter untouched.
   - For each existing immediate subfolder of `docs/` other than the two new
     defaults (e.g. global-k8s's `docs/plans/`):
     - Add the folder's display label (titlecase of slug, e.g. `"Plans"`)
       to the parent project's `sections[]` if not already present.
     - For each doc inside, add `section: "Plans"` (verbatim label) to
       frontmatter if absent. Files don't move.
3. After all `docs/` walking, update the parent project's frontmatter:
   - If `sections:` is absent, set to platform defaults + any custom
     sections discovered: e.g. `[Knowledge, Notes]` or
     `[Knowledge, Notes, Plans]` for global-k8s.
   - If `sections:` is present, leave alone (user explicit; even if the
     filesystem grew a new folder, the user owns the field).

**Reversibility:** Manually undo via `mv docs/knowledge/* docs/` and removing
the `section:` frontmatter field. Re-running install won't re-migrate
because `docs/knowledge/` will exist; user can rerun by deleting that
folder first.

**No-op cases (skipped):** Projects with no `docs/` folder, projects whose
`docs/` contains only `Docs.md`, projects already showing `docs/knowledge/`.

## Section 3 — Docs Hub view rewrite (`ProjectDocsSections`)

New CustomJS helper class at
`platform/blueprints/project/helpers/project-docs-sections.js`. Replaces the
existing `ProjectDocsCards` invocation in the Docs Hub template.

**Behavior:**

- Reads parent project frontmatter (`project_slug` from hub frontmatter →
  `spice/projects/<slug>/<Project>.md`) to get `sections[]`. Falls back to
  `[Knowledge, Notes]` if absent.
- For each section, in declared order:
  - Render a `<h3>{{section}}</h3>` label.
  - Render the `+ New <Section>` button via
    `customJS.EntityCreate.render(dv, { instance: "doc-note", presetPrompts: { section: <section> } })`.
  - Dataview-query: `dv.pages('"spice/projects/<slug>/docs"').where(p => p.type === "doc-note" && (p.section === <section> || /* fallback */ inSectionFolder(p.file.folder, <slug-of-section>)))`.
  - Sort `file.mtime` desc.
  - Render via `customJS.BeaconCards` with `layout: "row"` and the same
    `meta` callback shape v0.100.0 established (`created <MMM D> · edited <relative>`).
  - Empty state per bucket: card-style stub "No docs in {{section}} yet —
    use **+ New {{section}}** above" (rendered by BeaconCards' empty-array
    handling with custom message).
- After all declared sections, render an **Unfiled** trailing bucket
  containing any doc-note whose `section:` value doesn't match any declared
  section (covers user-renames-section drift). Include a one-click "Add
  '{{value}}' to project sections" affordance per orphan-value group.

**Edge cases:**

- Project's `sections[]` contains a section but no folder exists yet → render
  the bucket with empty state; the `+ New <Section>` button creates the
  folder on first doc.
- Doc has frontmatter `section:` but lives in a different folder → folder
  wins for placement; an inline warning chip ("section frontmatter
  mismatch — drag to confirm") appears on the row. Reconciled the next
  time the user edits the doc (lint helper writes `section: <folder>`).
- Two docs with same name in different sections → handled by Obsidian's
  unique-path resolution; both surface in their respective buckets.

**v0.102.1 placeholder:** Helper accepts a `filterContext` param defaulting
to `null` (no filter). v0.102.0 ships without invoking it; v0.102.1 wires
the filter UI to populate it.

## Section 4 — EntityCreate `presetPrompts` (mechanism 0.5.0)

EntityCreate gains one new optional param on the `.render()` call:
```js
EntityCreate.render(dv, {
  instance: "doc-note",
  presetPrompts: { section: "Knowledge" }   // NEW
})
```

Behavior:
- For each prompt key matching a `presetPrompts` entry, **skip the prompt UI
  entirely** and use the preset value directly as the prompt's answer.
- All other prompts (e.g. `name`) still render as today.
- Validation runs against the preset value the same way as user-typed
  values; if the preset fails validation, throw at render time (developer
  error, not user error).

This is additive — calls without `presetPrompts` behave exactly as today.

Used by:
- One `+ New <Section>` button per section on the Docs Hub
  (`presetPrompts: { section: <section> }`).
- The `+ New meeting for this project` button on the Project note
  (`presetPrompts: { project: "[[<This Project>]]" }`).

## Section 5 — Project note: Meetings panel (`ProjectMeetingsPanel`)

New CustomJS helper at
`platform/blueprints/project/helpers/project-meetings-panel.js`. Rendered on
the Project note template between the existing Workstreams section and the
existing Mentions / BacklinkPanel section.

**Panel structure:**
```
## Meetings
[+ New meeting for this project]                ← EntityCreate w/ project preset
[5 most recent meeting rows]
[View all N meetings →]                          ← only if N > 5; expands inline
```

**Query:** `dv.pages('"spice/meetings/notes"').where(p => p.type === "meeting" && p.project && p.project.path === <this project>.file.path)`, sorted by `date` desc, take(5).

**Row shape:** `📅 <YYYY-MM-DD> · <title> · <N attendees>` — clickable wikilink
opens the meeting note. Style consistent with `ProjectDocsSections` rows
(same BeaconCards row layout, smaller font).

**Empty state:** "No meetings linked to this project yet. Use **+ New meeting
for this project** above, or add `project: \"[[<This Project>]]\"` to an
existing meeting's frontmatter."

**Expansion:** "View all N meetings" toggle renders the full list inline
beneath the recent-5 (same row format, no separate page).

## Section 6 — Meetings blueprint MINOR (0.8.0)

Three changes in `platform/blueprints/meetings/`:

1. **Manifest schema:** Add `project` to the meeting frontmatter template
   (`frontmatter_template`):
   ```yaml
   project: ""    # optional wikilink to parent project
   ```
   Default empty string (renders as no link); set by EntityCreate prompt at
   creation time if user picks a project.

2. **EntityCreate registry entry for `meeting`:** Add a new optional prompt:
   ```json
   {
     "key": "project",
     "label": "Project (optional)",
     "kind": "select",
     "options_source": "all_projects",
     "default": "(none)",
     "required": false
   }
   ```
   The `options_source: "all_projects"` is a new EntityCreate capability:
   resolves to `dv.pages().where(p => p.type === "project").file.name` plus
   a `"(none)"` sentinel. Selecting `(none)` results in empty string in
   frontmatter. Selecting a project name wraps in `"[[<name>]]"`.

3. **Meeting Hub row enhancement:** The daily Meeting Hub
   (`Meetings-YYYY-MM-DD.md`) row helper gains a project-pill: when a
   meeting's `project` is set, render an inline pill with the project name
   between the title and attendee count: `📅 09:00 Cowork sync · [Global K8s] · 3 attendees`.
   Cheap visual reinforcement of the bidirectional link.

## Section 7 — Adjacent install fix: vault default paths

**Why:** Sauce install currently leaves Obsidian's "Files & Links" defaults
at "Vault folder", which scatters new attachments and new notes at the
vault root and clutters the namespace. Headspace-sauce has the corrected
settings already applied by hand (confirmed at
`/Users/willfellhoelter/notes/sauce/headspace-sauce/.obsidian/app.json`);
codifying makes that posture the platform default.

**New install step:** `applyVaultDefaultPaths` (idempotent, runs every install).

1. Ensure `spice/resources/` exists (new platform namespace).
2. Ensure `spice/resources/notes/` exists with `.gitkeep`.
3. Ensure `spice/resources/attachments/` exists with `.gitkeep`.
4. Read `.obsidian/app.json`. For each of the three keys
   (`newFileLocation`, `newFileFolderPath`, `attachmentFolderPath`):
   - If the key is **absent** or set to a **default-equivalent value**
     (`newFileLocation === "root"` or empty paths), write the canonical
     values:
     ```json
     "newFileLocation": "folder",
     "newFileFolderPath": "spice/resources/notes",
     "attachmentFolderPath": "spice/resources/attachments"
     ```
   - If the key is **already customized** (e.g. headspace-sauce's
     `attachmentFolderPath: "spice/resources/attachments"` matches; another
     user might have `attachments/` at root), **leave alone — no clobber**.
5. Update `CLAUDE.md` workshop directory map to register `spice/resources/`
   as a platform namespace alongside `spice/`, `ranch/`, `.claude/commands/`,
   `.claude/skills/`. Managed via `claude_surface[]` rewrite.

**Marker region:** A new `claude-surface` block for the directory map row
(or extend the existing `claude_surface[]` Directory Map block to include
`spice/resources/`).

## Section 11 — Risks & open questions

| Risk | Mitigation |
| --- | --- |
| Migration is destructive (moves 29 docs in global-k8s alone). If it fails partway, vault state could be inconsistent. | `applyProjectSectionsMigration` runs per-project transactionally: stage moves in a temp list, only execute if all moves resolve cleanly. Log every move to install log for hand-undo. |
| Doc-note `section:` frontmatter drifts from folder location (user moves file without updating field, or vice versa). | Folder wins. The `ProjectDocsSections` view shows a "section frontmatter mismatch" chip on affected rows; lint reconciles on next edit. Unfiled bucket catches orphans. |
| `presetPrompts` may conflict with EntityCreate's existing validation logic if a preset value violates a prompt constraint. | Validation runs against preset values too; if violation, throw with a clear developer-facing error at render time. No silent fallback. |
| Custom-section subfolders from old projects might match unrelated content (e.g. a hypothetical project with a `docs/scripts/` subfolder used for code, not docs). | Migration only adds subfolders to `sections[]` if at least one `*.md` file inside has `type: doc-note` frontmatter. Skips non-doc subfolders. |
| Obsidian's `.obsidian/app.json` may have other settings we don't want to touch. | Read-modify-write the JSON, only touching the three known keys. Preserve all other keys verbatim. |
| Meeting `project:` wikilink doesn't auto-update if user renames a project. | Obsidian's `alwaysUpdateLinks: true` (already set in headspace-sauce; honored by Sauce's bootstrap) updates wikilinks across the vault on rename. Out-of-band rename = user responsibility. |

**Open question (defer to plan-time):**

- **Lint helper for folder/frontmatter reconciliation:** does this live in
  `ProjectDocsSections` (render-time, lazy), or as a separate
  `applyProjectDocSectionLint` install step (eager, scheduled)? Recommend

## Section 13 — v0.102.1 design preview (for plan-time continuity)

Three components, all layered into `ProjectDocsSections`:

1. **Filter input** (above section buckets) — text input. On keypress,
   passes value as `filterContext.text` to `ProjectDocsSections`. Each
   section's row list filters in-memory by matching `file.name` (always)
   + `frontmatter.tags` (substring) + first 200 chars of `file.content`
   (substring). Section header shows "({{visible}} of {{total}})" while
   filter active.
2. **Tag chips** (between filter input and section buckets) — dynamic
   from `getMostUsedTags(allDocsInProject, top: 8)`. Click toggles chip
   active; multi-select AND logic. `filterContext.tags = [chip1, chip2]`.
3. **Scoped search button** (icon button next to filter input) — click
   opens Obsidian global search panel with
   `path:"spice/projects/<slug>/docs" ` pre-filled. Uses
   `workspace.openLinkText` or the global-search API; verify at plan-time
   which is canonical.

Status pill ("Filtering: `ingress + #spec` — 3 of 31 docs") renders above
sections when any filter is active, with a clear-all button.

No schema change. Stays a self-contained CustomJS extension.
