# v0.107.0 — finance defaults + groups + budget summary

## TL;DR

Every monthly budget today starts as an empty `categories: []` and gets typed in by hand. Same for paychecks. This cycle introduces two per-vault defaults notes — `spice/finance/Budget Defaults.md` and `spice/finance/Paycheck Defaults.md` — edited via dialogue-driven widgets (no manual YAML), and an additive `seed_from_defaults` schema field on the entity-create mechanism so the `+ New Budget` / `+ New Paycheck` clicks pre-populate the new entity from defaults. Budget categories grow a `group` field (user-defined groups like Essential / Extra / Neutral / Travel — ordered, snapshot per budget for immutability of history). `BudgetCategoriesEditor` v2 renders grouped sections with per-group sub-totals; `BudgetSummary` widget renders a three-band rollup at the top of every budget (totals + variance, month-progress vs spent-progress pacing, per-group mini-cards). Migration: append-only `groups: []` + `group: "Unassigned"` backfill on existing budgets, with a pre-write `.sauce-backup` snapshot. Defaults files create-if-absent — never overwritten. Data preservation is non-negotiable; the spec enumerates every write boundary and the audit safety net.

## Section 2 — Data model (frontmatter shapes)

### `Budget Defaults.md` (NEW)

```yaml
---
type: budget-defaults
groups:
  - Essential
  - Extra
  - Neutral
  - Travel
categories:
  - { group: Essential, name: Rent,        planned: 2200 }
  - { group: Essential, name: Groceries,   planned: 500 }
  - { group: Travel,    name: Travel Misc, planned: 50 }
  - ...
created_at: "..."
cssclasses: [wide]
---
```

- `groups[]` is **ordered**. Editor renders categories in that group order across the file.
- `categories[*].group` is a free string. Editor validates against `groups[]` and forces a picker — user cannot type a free-form group from the modal.
- Reorder groups, rename a group (cascades via re-assign helper across all category rows), and reassign a category's group are all dialogue-driven.

### `Paycheck Defaults.md` (NEW)

```yaml
---
type: paycheck-defaults
expenses:
  - { item: Rent,          amount: 2200, category: Rent,    url: "" }
  - { item: Phone bill,    amount: 13,   category: Phone,   url: "" }
  - { item: CC payoff min, amount: 200,  category: Loans,   url: "" }
  - ...
created_at: "..."
cssclasses: [wide]
---
```

- No groups. Paycheck expenses are flat.
- `category` is a free string. Editor autocompletes via `<datalist>` from Budget Defaults' category names. Falls back to plain text if Budget Defaults absent.

### `Budget-YYYY-MM.md` (post-v0.5.0 — additive only)

```yaml
---
type: budget
month: 2026-07
groups: [Essential, Extra, Neutral, Travel]                          # NEW — snapshot from defaults at create time
categories:
  - { group: Essential, name: Rent, planned: 2200, actual: 0 }       # NEW field per item: group
  - ...
created_at: "..."
cssclasses: [wide]
---
```

- Budget carries its **own** `groups[]` snapshot. Renaming a group in defaults later does NOT propagate. Financial history immutable.
- Categories whose `group` doesn't appear in `groups[]` render under an auto-injected "Unassigned" group at the end. Auto-injected only — never written to frontmatter.

### `Paycheck-YYYY-MM-DD.md` (post-v0.5.0 — no schema change)

Existing shape preserved. `expenses[*]` already has `{item, amount, category, paid, url}`. Defaults copy with `paid: false` added.

### Rule fragment deltas

- NEW: `spice/finance/Budget Defaults.md` — `type: "budget-defaults"`, `groups[]: string array`, `categories[]: array`. Naming pattern `^Budget Defaults\.md$`.
- NEW: `spice/finance/Paycheck Defaults.md` — `type: "paycheck-defaults"`, `expenses[]: array`. Naming pattern `^Paycheck Defaults\.md$`.
- MODIFIED budget rule: adds optional `groups[]: string array`. `categories[*].group` is editor-enforced rather than rule-enforced (rule_fragments don't deep-validate object members today — same posture as existing `categories[*].planned/actual`).

### Edge cases

- **Group deletion in defaults** — if categories use the group, dialogue blocks and offers a "Reassign N categories to:" picker. If user dismisses, the group stays.
- **Defaults missing on `+ New Budget` click** — entity-create logs Notice (`"Budget Defaults.md not found; creating empty budget"`) and falls back to the empty `frontmatter_template.categories`. Never crashes.
- **Category's group not in the budget's snapshot** — render under auto-injected "Unassigned" group at the end of the editor.

## Section 3 — entity-create `seed_from_defaults` extension

entity-create mechanism gets ONE additive optional field per button. Mechanism 0.5.0 → 0.6.0 MINOR.

### Schema

```json
{
  "seed_from_defaults": {
    "source_path":   "{{module_directory}}/Budget Defaults.md",
    "source_array":  "categories",
    "dest_array":    "categories",
    "carry_arrays":  ["groups"],
    "per_item_set":  { "actual": 0 }
  }
}
```

| Field | Purpose |
| --- | --- |
| `source_path` | Vault-relative path to defaults file. Templated (`{{module_directory}}`, `{{prompts.*}}`, etc.). |
| `source_array` | Name of the frontmatter array to copy from the defaults file. |
| `dest_array` | Name of the frontmatter key to write to in the new entity. Defaults to the same name as `source_array`. |
| `carry_arrays` | Additional top-level frontmatter arrays to also copy verbatim from defaults to the new entity. Used for budgets to carry the `groups[]` snapshot. |
| `per_item_set` | Object of fields to merge into EVERY copied item before write (e.g., `actual: 0` for budgets; `paid: false` for paychecks). |

### Scaffold flow (modification to `entity-create.js`)

1. Resolve prompts (existing).
2. Substitute tokens into `frontmatter_template` (existing).
3. **NEW: if `seed_from_defaults` present**:
   1. Read `source_path` (substitute tokens first).
   2. Parse frontmatter via `app.metadataCache.getFileCache(file).frontmatter`.
   3. Extract `source_array` → must be an array. Defensive copy.
   4. For each copied item, shallow-merge `per_item_set` fields.
   5. Extract each `carry_arrays[k]` from defaults frontmatter; defensive copy.
   6. Inject `dest_array: <copied>` into the final frontmatter, AND inject each `carry_arrays[k]: <copied>` — but only if the template's value for that key is empty/missing (template wins on conflict; protects authored frontmatter_template overrides).
4. Write file (existing).

### Finance manifest wiring (excerpt)

### Error handling (defensive, non-blocking)

| Case | Behavior |
| --- | --- |
| Defaults file missing | `new Notice("Budget Defaults.md not found; creating empty budget")`. Continue with template's empty array. |
| `source_array` is not an array | Notice warning. Continue with template empty array. |
| Individual item malformed (missing `name`, etc.) | Copy as-is. Editor renders what it has — never drops items silently. |
| Defaults file unreadable (permissions etc.) | Notice. Continue with empty. |

### Backward compatibility

`seed_from_defaults` is optional. Every existing `new_entity_buttons[*]` entry across all blueprints (project's New Doc, meetings' New Meeting, etc.) ignores the field. No breakage.

## Section 5 — `BudgetSummary` widget

### Placement

Top of every Budget note, between the status badge and the `## Categories` heading. New dataviewjs block:

```dataviewjs
await dv.view("ranch/views/customjs-guard", { class: "BudgetSummary" });
```

Block lives in both `templates/Budget Template.md` AND the budget entry of `new_entity_buttons[*].inline_body` (lockstep, mirrors v0.16.0 template-body/NewXButton-body lockstep).

### Layout

```
┌─────────────────────────────────────────────────────────────────┐
│  PLANNED  $5,500       ACTUAL  $5,840      VARIANCE  +$340 (+6.2%) │  Band 1
│─────────────────────────────────────────────────────────────────│
│  Day 13 of 30 — 43% of month elapsed                            │  Band 2
│  [===========>            ] 43%   elapsed                       │
│  [==================>     ] 67%   spent                         │
│  ⚠ Pace: AHEAD by +24 pts                                       │
│─────────────────────────────────────────────────────────────────│
│  ┌─────────┐  ┌─────────┐  ┌─────────┐  ┌─────────┐             │  Band 3
│  │ESSENTIAL│  │  EXTRA  │  │ NEUTRAL │  │ TRAVEL  │             │
│  │4050→5700│  │ 400→1400│  │ 300→650 │  │ 200→1000│             │
│  │+41% over│  │+250%over│  │+117%over│  │+400%over│             │
│  └─────────┘  └─────────┘  └─────────┘  └─────────┘             │
└─────────────────────────────────────────────────────────────────┘
```

### Compute (pure derivation from `page` frontmatter)

| Quantity | Source |
| --- | --- |
| `total_planned` | `sum(page.categories[].planned)` |
| `total_actual` | `sum(page.categories[].actual)` |
| `variance` | `total_actual - total_planned` |
| `variance_pct` | `variance / total_planned * 100` (guard div-by-zero) |
| `month_days` | `daysInMonth(page.month)` |
| `today_day` | `today.getDate()` (current month only) |
| `elapsed_pct` | `today_day / month_days * 100` |
| `spent_pct` | `total_actual / total_planned * 100` |
| `pace` | `spent_pct - elapsed_pct` |
| Per-group totals | `sum(categories.filter(c => c.group === g).planned/actual)` for each `g` in `page.groups[]` |

### Status-aware rendering

Mirrors `FinanceStatus.derive` for `"budget"`:

| Status | Band 1 | Band 2 | Band 3 |
| --- | --- | --- | --- |
| Planning (future month) | Planned only ($X across N categories) | Hidden | Show planned only |
| In Progress (current month) | Full | Full (with ⚠/✓/↓ pace indicator) | Full (planned → actual) |
| Done (past month) | Full + "CLOSED" tag | Replace pace with "Closed: spent X of planned Y" | Full (final state) |

### Pace indicator

| Pace value | Symbol | Color | Meaning |
| --- | --- | --- | --- |
| `pace > +10` | ⚠ AHEAD by +N pts | red | spending faster than month elapsed |
| `-10 ≤ pace ≤ +10` | ✓ on pace | green | tracking month elapsed |
| `pace < -10` | ↓ BEHIND by N pts | muted | spending slower than month |

### Per-group card color

Matches `BudgetCategoriesEditor` sub-total colors — green (actual ≤ planned), amber (≤ 110%), red (> 110%). For groups with `planned == 0`, show `—` instead of variance.

### Edge cases

- `page.categories` empty → entire widget renders as "Empty budget — add categories below."
- `page.groups` empty → Band 3 skipped; Bands 1+2 still render.
- `page.month` malformed → Band 2 month-progress skipped; Bands 1+3 still render.

### Re-render

Obsidian auto-re-renders DataviewJS blocks when frontmatter changes (via `processFrontMatter`). When `BudgetCategoriesEditor` mutates a category's `actual`, `BudgetSummary` recomputes naturally. No explicit coupling.

### Read-only

Never writes frontmatter. Pure derivation.

## Section 6 addendum — Data-preservation guarantees (non-negotiable)

### What this cycle touches, and how

| Action | Files affected | Semantics |
| --- | --- | --- |
| Migration adds `groups: []` | Existing `Budget-*.md` | Append-only — only added if field is missing. Never removed. |
| Migration adds `category.group: "Unassigned"` | Existing budget categories | Append-only — only added if field is missing. Existing categories' `name` / `planned` / `actual` NEVER altered. |
| Defaults file scaffolding | `Budget Defaults.md` + `Paycheck Defaults.md` | Create-if-absent only. If file exists, installer does NOT touch it — your filled-in defaults survive every future `sauce install`. |
| `seed_from_defaults` at `+ New Budget` click | Only the brand-new budget being created | Reads defaults, copies to the NEW entity. Existing budgets/paychecks NEVER re-seeded retroactively. |
| BudgetSummary widget | Any Budget note (read) | Read-only. Computes from frontmatter; never writes back. |

### What this cycle never touches

- Existing paychecks, invoices, time-logs, boards (no schema change to any of these — paycheck `expenses[]` shape is already compatible).
- Anything outside `spice/finance/`.
- Anything inside `spice/finance/` that isn't a `Budget-*.md` (the existing `Budgets.md` hub gets the ⚙ Defaults link added but its other content is untouched; `Finance.md` UNCHANGED).

### Belt-and-suspenders

1. **Atomic writes** — migration writes via Obsidian's `processFrontMatter` (the same primitive `FinanceFrontmatter` uses; survives YAML edge cases per v0.16.0 lessons). No partial writes.
2. **Per-vault snapshot before migration** — `applyFinanceMigrations` takes a `.sauce-backup/<timestamp>/spice/finance/budgets/` snapshot of every `Budget-*.md` BEFORE backfill writes anything. Mirrors the existing Safeguard-1 snapshot pattern (v0.101.0 cycle). Recoverable.
3. **Per-file failure-loud** — one bad budget logs Notice (`"Budget-2026-06.md migration failed: <reason> — file left unchanged"`) and continues. A broken file blocks itself, never cascades.
4. **Idempotent** — re-running detects "all categories already have group; no work to do" and no-ops. Diff log shows empty work list.
5. **Pre-write audit log** — Notice + console line per file: `"Migrating Budget-2026-06.md — adding 4 group fields (Unassigned)"`.
6. **Post-migration sentinel** — final Notice: `"Finance migration: N budgets touched, M categories backfilled to 'Unassigned'. 0 categories modified beyond add."`

If `Budget Defaults.md` already exists with content (e.g., user pre-created or restored from backup), the installer skips creation entirely.
