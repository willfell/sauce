# v0.111.3 CF-1 — MonthlyOverview coverage expansion

## Why a single-doc mini-cycle

The three scenarios closed here were explicitly **deferred** at v0.110.3 ship time with the rationale "only worth wiring if X." They scope cleanly: each is test-only, additive, and bounded. A full brief/design/plan/result split would be ceremony for ~80 lines of code. One doc captures motivation + execution + verdict + lessons.

## What this CF closes

The v0.110.3 result doc listed three "lower priority — would round out but not load-bearing" gaps:

1. **Real-Dataview proxy semantics test.** Array stubs can mask the helper drifting toward `Array.prototype.*` methods that Dataview's `DataArray` proxy doesn't expose.
2. **Performance ceiling.** No bound on render time at realistic vault scale (100 paychecks × 20 expenses; 50 debts × 30 balance_history entries).
3. **Cross-year month-key boundary.** December budget viewed in January — paychecks dated 2027-01-* must not bleed into the December bucket.

All three now have coverage in `platform/test/run-v01103-monthly-overview.js` Section 3.

## What shipped

### Section 3 of `run-v01103-monthly-overview.js` — coverage expansion

**Stricter Dataview-proxy stub (`makeStrictDA` / `makeStrictDv`).** A non-Array iterable that exposes ONLY the methods Dataview documents on `DataArray`: `.where(fn) → DA`, `.sort(keyFn, dir) → DA`, `.limit(n) → DA`, `.first()`, `.array()`, `.length`, `Symbol.iterator`. Critically excludes `.filter` / `.map` / `.reduce` / `.find`. If the helper ever calls a stripped method, the test throws `TypeError`.

```javascript
function makeStrictDA(items) {
  const inner = (items || []).slice();
  return {
    _kind: "DataArray",
    get length() { return inner.length; },
    where(fn) { /* returns DA */ },
    sort(keyFn, dir) { /* returns DA */ },
    limit(n) { /* returns DA */ },
    first() { return inner[0]; },
    array() { return inner.slice(); },
    [Symbol.iterator]() { /* native iterator */ },
  };
}
```

## Why these cases now (not later)

Three small forcing functions:

1. **Coverage ratchet.** Once a deferred test exists in a result doc, it stays deferred. Closing them while context is fresh costs ~30 minutes; closing them in a cold session is hours of re-derivation.
2. **Catch-cost asymmetry.** Each of the three failure modes (Array-method drift, perf regression, year-boundary bleed) is invisible until a user reports it. Six months later, the user-report → reproduce → fix loop is days. The test catches it in CI on the offending commit.
3. **Bound + log over assert.** `MO-PERF-1` uses a 1s bound (current actual: ~2ms — 500x headroom). That's a smoke test, not a benchmark. CI hardware variance won't flake it. If render goes O(n²) on either axis, it fails immediately.

## What this CF intentionally did NOT do

- **No production-code change.** `monthly-overview.js` and `applyFinanceBudgetMonthlyBandInjection` are byte-identical pre/post this CF.
- **No version bump.** Test-only additions don't trigger workshop / blueprint / mechanism version changes. Pure additive coverage.
- **No `.sauce-backup` snapshot.** Not applicable — no body migration here.
- **No new HC family.** Existing `caseV01103BehavioralHarnessShipped` was extended in-place because the new asserts share the same proof shape ("the harness file contains case X").

## Lessons

1. **Single-doc mini-cycles are the right shape for test-only follow-ups.** A 4-doc cycle for a pure-test additive PR is ceremony. One doc with `kind: brief+design+plan+result` captures everything without splitting context.
2. **"Lower priority — only worth if X" should still get a date-bound check-in.** The three scenarios were marked "only worth if signal observed." But the cost asymmetry (~30 min now vs days later) means closing them proactively beats waiting for signal. Treat deferred-test lists as a 1-week sweep, not an indefinite parking lot.
3. **Strict proxy stubs as regression nets work better than loose Array-inheritance stubs.** The Array-based `makeDA` I shipped at v0.110.3 passed all happy-path math tests but would silently allow drift. The non-Array `makeStrictDA` is ~30 lines and proves the helper survives without `Array.prototype.*` — that's a contract test, not just a happy-path test.
