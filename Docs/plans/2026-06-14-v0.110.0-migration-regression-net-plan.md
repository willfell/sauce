### Stage S2 — Seed vault generation + scripts

**Goal:** Generate the synthetic seed vault from a bootstrap+install run, commit it. Author the rebaseline + prev-snapshot scripts.

**Sub-steps:**

- [ ] Write `Scripts/rebaseline-seed.js`:
  - Read CLI args: `--dry-run` (print diff, don't write).
  - Resolve `repoRoot` via `path.resolve(__dirname, "..")`.
  - `seedDir = path.join(repoRoot, "platform/test/seed-vault")`.
  - Create `tmpDir` via `fs.mkdtempSync(path.join(os.tmpdir(), "sauce-rebaseline-"))`.
  - `copyDir(seedDir, tmpDir)` (recursive, hidden files preserved).
  - `execFileSync("node", ["platform/install.js", "--vault", tmpDir, "--auto-approve"], { cwd: repoRoot, stdio: "inherit" })`.
  - If `--dry-run`: `diffTree(seedDir, tmpDir)` → print summary, exit 0.
  - Else: `fs.rmSync(seedDir, { recursive: true, force: true })` then `copyDir(tmpDir, seedDir)`.
  - Always: `fs.rmSync(tmpDir, { recursive: true, force: true })`.

- [ ] Write `Scripts/seed-prev-snapshot.js`:
  - `seedDir = path.join(repoRoot, "platform/test/seed-vault")`.
  - `prevDir = path.join(repoRoot, "platform/test/seed-vault-prev")`.
  - If `prevDir` exists: `fs.rmSync(prevDir, { recursive: true, force: true })` (overwrite).
  - `copyDir(seedDir, prevDir)` (recursive, hidden files preserved).
  - Log: "Snapshotted seed-vault → seed-vault-prev (<file count> files)".

- [ ] Author `platform/test/seed-vault-prev/README.md`:
  ```
  # seed-vault-prev
  This directory holds a snapshot of `seed-vault/` from one cycle ago. Populated by
  `Scripts/seed-prev-snapshot.js` at cycle close. Used as a safety net to compare

  This directory is intentionally empty in the foundation cycle (v0.110.0); the first
  real snapshot lands at the close of the next cycle that ships migrations.
  ```

- [ ] Generate the seed vault. From repo root, run an ad-hoc Node script (or in a tmp scratch dir):

### Stage S3 — Harness + helpers

**Goal:** Build the harness with initial assert families. Make it green against the seed.

**Sub-steps:**

- [ ] Write `platform/test/helpers/seed-vault-helpers.js`:
  - `parseFrontmatter(content)` — returns `{frontmatter: {...}, body: "..."}`. Use a simple regex-based YAML parser (no js-yaml — zero-dep). Mirror style from any existing helper if one exists; otherwise write a minimal block-scalar parser sufficient for sauce's frontmatter shapes (string, list-of-strings, list-of-objects).
  - `readNote(vaultPath, relPath)` — `fs.readFileSync(path.join(vaultPath, relPath), "utf8")`.
  - `assertFileExists(vaultPath, relPath, label, ok)` — wraps `fs.existsSync`.
  - `assertFrontmatterKey(vaultPath, relPath, key, expected, label, ok)`.
  - `assertBodyContains(vaultPath, relPath, substring, label, ok)`.
  - `assertFilePreserved(seedPath, vaultPath, relPath, label, ok)` — byte-compare seed vs. post-install vault.
  - `copySeedToTmp(seedPath)` — recursive copy to `fs.mkdtempSync(path.join(os.tmpdir(), "sauce-seed-"))`; returns tmp path.
  - `runInstall(vaultPath, repoRoot)` — `execFileSync("node", [path.join(repoRoot, "platform/install.js"), "--vault", vaultPath, "--auto-approve"], { ... })`. Returns `{ code, stdout, stderr }`.
  - `diffTree(a, b)` — returns `{ added: [...], removed: [...], changed: [...] }` (relative paths).

- [ ] Write `platform/test/run-seed-migrations.js`:
  - Use same `ok(label, cond, detail)` + `pass / fail` counter style as `run-integration-smoke.js`.
  - Resolve `repoRoot` via `path.resolve(__dirname, "../..")`.
  - `seedPath = path.join(repoRoot, "platform/test/seed-vault")`.
  - **Phase A — Install + Shape (HC-V01100-SEED-INSTALL-* + SEED-SHAPE-*):**
    - Copy seed → tmp.
    - Run install. Assert `code === 0`. Capture stdout for history-line check.
    - Assert `ranch/platform-installed.json` exists, valid JSON, has `entries[]` array, last entry has expected keys (`mechanism`, `version`, `applied_at`).
    - Assert root directories exist: `spice/`, `ranch/`, `.claude/`, `Docs/Meta/` (if applicable).
    - Assert blueprint directories exist: `spice/cowork/`, `spice/finance/`, `spice/daily/`, `spice/projects/`, `spice/meetings/`, `spice/scratch/`, `spice/to-do/`, etc.
  - **Phase B — Frontmatter (HC-V01100-SEED-FM-*):**
    - Assert hub-note frontmatter shapes for the hubs that the install materializes — Cowork.md, Budgets.md, Debts.md, Paychecks.md, Projects (per-project not present in fresh vault), Daily Hub, Weekly Hub, Monthly Hub (whichever apply).
  - **Phase C — Preservation (HC-V01100-SEED-PRESERVE-*):**
    - Assert the 3 hand-authored notes preserved bit-for-bit between seed and post-install.
  - **Phase D — claude_surface (HC-V01100-SEED-CLAUDE-*):**
    - Assert `CLAUDE.md` exists; contains `claude-surface:directory-map BEGIN` + matching END marker; contains `claude-surface:skills-index BEGIN/END`; contains `claude-surface:resolvers BEGIN/END`.
  - **Phase E — Idempotency (HC-V01100-SEED-IDEMP-*):**
    - Run install a second time on the same tmp vault. Assert exit 0.
    - `diffTree(firstInstallSnapshot, secondInstallVault)` — only delta should be `ranch/platform-installed.json` history entries (timestamps change). Assert every other path is byte-identical.
  - Print summary: `Tests: ${pass}/${pass+fail}`. Exit 1 if any fail.

- [ ] Run locally: `node platform/test/run-seed-migrations.js`. Iterate until all green.

- [ ] Commit: `feat(test): v0.110.0 S3 — run-seed-migrations harness + helpers`.

- [ ] Push.

    ```
    ## #25 — manual edits to `platform/test/seed-vault/`

    The seed vault is the canonical input to the migration regression harness.

        npm run seed:prev && npm run seed:rebaseline
    ```

## Risks during implementation

1. **The seed-vault generation step might require fiddly subscription editing.** If the bootstrap doesn't auto-subscribe every blueprint, we need to edit `ranch/platform-subscription.json` between bootstrap and install. Handle this in S2 with explicit editing.

2. **The headless installer might balk at some path or template not being available in a clean tmp vault.** Mitigation: existing `run-bootstrap.js` and `run-integration-smoke.js` already exercise this path; if they pass, the install path is viable.

3. **CI matrix surfaces path-case issues macOS-vs-Ubuntu.** Mitigation: use `path.join` everywhere; avoid hardcoded path separators; use `fs.statSync(p).isDirectory()` not string heuristics.

4. **The first PR push triggers CI but the new harness is the FIRST run.** It may fail in CI even if it passed locally (env diffs). Mitigation: iterate quickly on push-fail-fix loop.
