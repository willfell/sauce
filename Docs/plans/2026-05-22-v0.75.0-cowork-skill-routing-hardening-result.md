## What shipped

### Workstream A — Cowork skill-routing hardening (three layers)

**Layer 1 — READ-form rewrites.** All `Use Skill cowork:<X>` references in 6 orchestrator SKILL.md files (`morning-briefing`, `midday-tripwire`, `eod-review`, `weekly-review`, `monthly-review`, `onboard-scheduled-jobs`) are rewritten to the explicit `READ .claude/skills/cowork/<path>/SKILL.md in full ... then apply ...` form — approximately 60 mechanical rewrites across the 6 files. This closes the multi-context-Claude-Code gap: when a scheduled-tasks-MCP-driven agent session doesn't automatically load sub-skill SKILL.md bodies, the orchestrator now explicitly instructs the READ before acting.

Both case forms (`Use Skill` and `use Skill`) required the fix; a case-insensitive grep in S0 found ~48 references but the implementer caught 12 additional lowercase variants, bringing the total to ~60.

**Layer 2 — Post-write structural verification.** Each of the 5 atomic-note-writing orchestrators (`morning-briefing`, `midday-tripwire`, `eod-review`, `weekly-review`, `monthly-review`) grows a post-write verification step: re-reads the written file, regex-scans structural markers + frontmatter fields, and on any miss: (a) deletes the malformed file, (b) returns `failed:contract-violation:<field>`. This is a durable backstop even if Layer 1's READ instruction is ignored by a future session.

**Layer 3 — Enriched scheduled-tasks prompts.** `onboard-scheduled-jobs` Step 6 (Register tasks) now emits two prompt forms — direct-call (one-liner) and a pasted-verbatim enriched form — that explicitly instruct the cron agent to READ each sub-skill's SKILL.md before honoring its action. Consumers can paste the enriched form directly into their scheduled-tasks MCP entries via a per-vault audit + update recipe.

**Harness:** `run-cowork-smoke.js` gains `HC-V0750-A1..A5`. HC-V0750-A1 is a fail-closed audit check: it greps all orchestrator SKILL.md bodies for any remaining naked `Use Skill cowork:` (case-insensitive) and fails if any are found — guaranteeing no regressions in future cycles.

### Workstream B — Smart Connections semantic retrieval

**New mechanism: `smart-connections-bridge@0.1.0`.** A Node.js CLI (`sc-bridge`) that reads Smart Connections' `.smart-env/multi/*.ajson` index files, runs the same `TaylorAI/bge-micro-v2` embedding model SC uses (via `@xenova/transformers`), and exposes three ops: `index-status`, `semantic-search`, and `find-related`. `{{module_directory}}` variable substitution is applied to ajson entity paths; the bridge degrades gracefully (exit-code 1 + JSON `{ "error": ... }`) when the vault has no SC index or no multi-ajson files.

**New sub-skill: `cowork:gather-semantic-related`.** Calls sc-bridge with the appropriate op, parses the result, and renders a `> [!example]+ 🧩 Related context` callout block. Semantic index age (computed from the index's `last_updated_at` timestamp vs. the note's target date) is interpolated into the Synopsis callout as a `Semantic index age:` lag-line. Missing or error states degrade to a one-line warning without aborting the orchestrator.

**SC integration in three orchestrators:**
- `morning-briefing`: per-event `semantic-search` capped at 5 events; each event's related notes rendered as a sub-callout inside the briefing body.
- `eod-review`: `find-related` on today's daily note path.
- `weekly-review`: aggregated `find-related` across the week's daily notes with dedupe + cohesion ranking.

**Engagement-aware:** new `render_aspects.semantic_related: "include"` field on all three engagement-type JSON files (`personal`, `w2-fte`, `consulting`); default is `"include"`, opt-out is `"skip"`. The orchestrators branch on this field before invoking `gather-semantic-related`.

**Harness:** `run-smart-connections-bridge.js` with `HC-V0750-B1..B12` (12 test vectors across 5 fixture vaults: empty, no-multi, ready, corrupt, module-dir).

### Workstream C — Engagement-types path-resolution fix

`onboard-scheduled-jobs` Step 2 (engagement-type discovery) previously tried to read engagement-type manifests from an in-vault path that doesn't exist at consumer install time. S12 rewrites Step 2 to resolve the workshop manifest path via `workshop_manifest_path` (mirroring `bootstrap-vault` step 74's established pattern), making engagement-type field discovery reliable for all consumer contexts.

### Workstream D — `sauce update --bump-pins` flag (FLN-v67-7 close)

A new `--bump-pins` flag on `sauce update` reads the brew-installed workshop's `platform/manifest.json`, derives the target versions for all subscribed blueprints and mechanisms, and overwrites `ranch/platform-subscription.json` with the updated pins before running the update. Closes FLN-v67-7 (the "4-vault manual pin-bump loop" deploy-chain friction since v0.67.3).

Note: `--bump-pins` does not work for workshop-self-install because the workshop's own `platform-installed.json` lacks a `workshop_path` field. Workshop dogfood path remains `node platform/test/run-install.js .`. This is a v0.75.1 carry-forward (see below).

## Lessons

1. **Cross-cycle test-assertion staleness reactivated.** S1's READ-form rewrites broke 3 pre-existing assertions: `cowork:write-run-note-morning-briefing` literal substring in the morning-briefing SKILL.md and 2× `cowork:bootstrap-vault` literal substring in onboard-scheduled-jobs. Fixed at S4 follow-up (`0e75874`). Same lesson as v0.74.0 lesson #1: **audit ALL `HC-*` assertions for stale literals before preflight**, not after. This is a recurring cross-cycle failure mode — worth adding as an explicit pre-preflight gate in `build-test-verify.md`.

2. **Install paths differ between workshop source and consumer install.** Orchestrators in the workshop source live at `platform/blueprints/cowork/skills/orchestrators/<name>/SKILL.md` but install to `.claude/skills/cowork/<name>/SKILL.md` (no `skills/orchestrators/` segment). Sub-skills install to `.claude/skills/cowork/skills/<name>/SKILL.md` (with a `skills/` segment). The initial S1 spec used the wrong path for `bootstrap-vault`; caught and fixed. **Lesson:** document this two-path invariant (orchestrators vs. sub-skills) explicitly in `code-conventions.md` to avoid recurring spec confusion.

3. **Case-insensitive Use-Skill grep needed.** S0's grep used capital-U `Use Skill cowork:` and counted 48 references. The S1 implementer caught 12 additional lowercase `use Skill cowork:` variants. Both case forms have the same multi-context-Claude-Code ambiguity problem and both needed the READ-form fix. **Lesson:** all future cowork-ref audits must use case-insensitive grep (`-i`); HC-V0750-A1's regex is now case-insensitive to close the gap permanently.

4. **Synthetic test vectors must match real embedding dim.** The initial S6 fixture used 4-dimensional synthetic vectors, but real `TaylorAI/bge-micro-v2` query embeddings are 384-dimensional — cosine similarity returned garbage. Updated fixtures to pre-computed real 384-dim vectors. **Lesson:** when scaffolding a harness for an ML-adjacent mechanism, always confirm the model's output dimensionality first and use vectors computed from that model for test fixtures.

5. **`@xenova/transformers` model cache lives in `node_modules/.cache/`** — not `~/.cache/huggingface/transformers/`. The Python `transformers` library uses the `~/.cache/` path; the JS `@xenova/transformers` package uses its own project-local cache. **Lesson:** don't assume JS and Python transformers libraries share cache paths; `.gitignore` and `.npmignore` may need entries for `node_modules/.cache/` if model weights are large.

6. **`{{module_directory}}` substitution source is workshop manifests, not `ranch/platform-installed.json`.** `ranch/platform-installed.json` carries `module_directory: null` per-blueprint at runtime. The canonical source is `platform/blueprints/<bp>/manifest.json`'s `module_directory` field. The sc-bridge has both code paths (test fixtures use `platform-installed.json`; real consumer falls back to reading workshop manifests). **Lesson:** treat `platform-installed.json` as a post-install state record, not a source of blueprint metadata.

7. **`sauce update --bump-pins` doesn't work for workshop self-install.** The workshop's own `platform-installed.json` lacks a `workshop_path` field (it would be circular). `--bump-pins` in a workshop-as-vault context silently fails to find the workshop path and exits without updating pins. v0.75.1 candidate fix: detect the workshop-as-vault case and use `cwd` as `workshop_path`. Workshop dogfood path remains `node platform/test/run-install.js .`.

8. **`.local/` needed in `platform/audit/sanctioned-dirs.js`.** sc-bridge.js installs its CLI binary under `.local/`, which is a legit sauce-managed path but was not in the audit walker's sanctioned-dirs list. S15 added it; without the addition the post-install `/audit` command would flag `.local/` as an untracked unknown directory. **Lesson:** any new mechanism that installs into a novel top-level directory must add that directory to `sanctioned-dirs.js` in the same stage.

9. **CS-MIG-1 hardcoded sub-skill counts in `run-claude-surface.js` need bumping** when adding any new sub-skill to a blueprint. S8 added `gather-semantic-related` and the count gates in `run-claude-surface.js` had to be bumped from 41→42 / 32→33. **Lesson:** treat the CS-MIG-1 count as a schema invariant: whenever adding a new `skills[]` entry to any blueprint manifest, always grep `run-claude-surface.js` for hardcoded counts and bump them in the same commit.
