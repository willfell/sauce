# v0.117.4 — to-do regression-net + cycle-close backfill (PATCH)

## Nature of the cycle

Pure test-debt + documentation hardening for code that **already shipped** in v0.116.0 → v0.117.3. No new consumer-facing behavior. Per explicit user decision (2026-06-15) the cycle carries a real `workshop_version` bump 0.117.3 → 0.117.4 for monotonic release hygiene, with the full release leg: branch + PR + CI → tag → brew → redeploy all three consumer vaults → seed rebaseline.

**Honest tradeoff (acknowledged):** the consumer redeploy is a **no-op** — no new migration runs and the `to-do` blueprint version is unchanged (stays 0.5.3), so vault users see nothing change. The brew + 3-vault redeploy is ceremony for a clean tagged release, not a behavior delivery.

## Why now

The v0.116.0 → v0.117.3 arc shipped a large surface (8 new customjs classes, recurrence engine, +New Task dialog, per-project To-Do notes, SectionLabel visual polish, three fast-follow PATCHes) and the regression net never caught up. The arc already cost one load-bearing bug — the v0.116.0 template-never-updated silent `Write` no-op, caught only by post-deploy user smoke. Locking in the migration + contract + behavioral net is the direct antidote, and it must land before the Option-B polish MINOR (which touches live render code) builds on top of it.

**Two distinct gaps discovered:**

1. **Wiring gap.** `run-todo-carryover/dialog/materialize` are git-tracked and green standalone (21 / 19 / 23 ok lines) but **absent from the preflight chain** — they run on no one's CI and on no tag.
2. **Coverage gap for the v0.117.x deltas.** Even with the three wired, these remain untested by any harness:
   - `ToDoDailyProjectGroups._normalizeProjectName` — the **load-bearing v0.117.3 fix** (Dataview Link-object coercion that fixed the meeting-task-for-project bug). Zero coverage.
   - `ToDoDailyProjectGroups._collectMeetingTasksForProject` per-meeting try/catch resilience (one malformed meeting must not blank the whole array — the actual v0.117.3 root cause).
   - `ToDoDailyUnassignedMeetings` render — **not loaded by any harness.**
   - `ToDoCreateTaskInit` — not loaded (`run-todo-dialog` only loads `ToDoCreateTask`).

This map is why the design diverges from the handoff's proposed new `run-v0117-todo-overhaul.js`: `ToDoDailyProjectGroups` is already loaded by `run-todo-materialize`, so a fresh 30-case file would mostly duplicate. We **extend** the existing harnesses instead.

## Feasibility note (verified before asserting)

`applyToDoBlueprintMigration` is invoked **unconditionally** on every install (`platform/install.js:1112`, idempotent vault scan, not behind a version gate). Therefore it fires against pre-migration anchors added to the seed **even though the `to-do` blueprint version is unchanged**. The SEED-MIGRATE family is viable. (Confirmed per the "verify-helpers-before-design" rule — `Docs/agent-guides/build-test-verify.md` § Cycle lessons.)

## Scope — six parts

### Part 2 — Behavioral coverage for the v0.117.x deltas (permanent, every-run)

Extend in place; no new harness file.

- **`run-todo-materialize.js`** (already loads `ToDoDailyProjectGroups`):
  - `_normalizeProjectName` — 6 input shapes resolve to `"Sauce"`: plain `"Sauce"`, `"[[Sauce]]"`, `"[[path/Sauce|Sauce]]"`, Link object `{path:"Sauce"}`, Link object `{display:"Sauce"}`, array `[{path:"Sauce"}]`; plus `null` → `""`/skip without throwing.
  - `_collectMeetingTasksForProject` resilience — an array containing one malformed meeting (e.g. a `project` value whose access throws) still returns matches from the well-formed meetings (no whole-array blank).
  - `ToDoDailyUnassignedMeetings.render` — load + render against the DOM/Dataview stubs already present in this file; assert section renders and excludes project-assigned meeting tasks.
- **`run-todo-dialog.js`**:
  - Load `ToDoCreateTaskInit`; assert it initializes without throwing under the stub app.
  - Dialog SectionLabel-anchor insertion (v0.117.2): inserting a task anchors on the `SectionLabel` "Today" block, with the three-tier fallback (SectionLabel → legacy H2 → EOF-without-new-heading) and **no** orphan `## Today` H2 created.
- Pure-helper exercises of the migration sub-functions where cheaply loadable (`_rewriteH2ToSectionLabel`, `_reshapeToV040`, `_healMisplacedSentinels`) against in-memory fixtures — these give permanent transform coverage independent of the seed (which ratchets forward at rebaseline).

### Part 3 — HC-V0117-* source contracts (`run-helper-cases.js`)

### Part 4 — HC-V0116-SEED-MIGRATE-* end-to-end (`run-seed-migrations.js` + seed extension)
