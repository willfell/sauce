# v0.91.0 — cowork:find-missing-people skill

Status: DRAFT (spec for v0.91.0 MINOR).

## 0. Why this cycle

`cowork:discover-people` (v0.28.0+) populates `inner_circle_people` from microscope prose + sibling tables + vault-config structured fields. But there's a complementary gap: atomic notes (morning-briefing / eod-review / etc.) emit `[[Name]]` wikilinks for people surfaced from memory ticks (synthesize-day output) OR from gather output. When the target `spice/people/<Name>.md` doesn't exist, Obsidian renders the wikilink dim ("greyed out"). The headspace morning briefing on 2026-06-05 has `[[Ellen Senders]]` dimmed because Ellen Senders wasn't promoted via discover-people (she's not in the chat microscope's "Inner circle" section — she's in "Open loops" / elevation sections).

A complementary skill that **scans recent atomic notes for unresolved wikilinks** and offers to batch-create person-note stubs fills this gap deterministically. After running it, every previously-dimmed `[[Person]]` wikilink resolves to a real (stub) person note.

## 3. Helper functions (pure)

File: `platform/blueprints/cowork/helpers/find-missing-people-helper.js`

- `scanAtomicNoteForWikilinks(body) → string[]` — extracts every `[[Name]]` from a single atomic-note body. Pattern: `/\[\[([^\]|#]+)\]\]/g`. Captures the link target (group 1).
- `filterToPersonShapedWikilinks(wikilinks) → string[]` — filters out non-person wikilinks: paths containing `/` (e.g. `[[spice/cowork/memory/...]]`), embeds starting with `!`, internal anchors with `#`, and link targets that don't look like person names (rejects digits, special chars; requires capitalized first letter; 1-4 tokens).
- `aggregateWikilinksAcrossNotes(noteSurfaces) → Array<{name, surfaced_in: [{path, date}], first_seen, last_seen, count}>` — given array of `{path, body, date}` entries, scans each + dedups names + accumulates surface metadata.
- `filterToMissingPeople(candidates, existing_person_basenames) → candidates[]` — diffs against existing person notes; returns only candidates whose basename doesn't exist.
- `composePersonNoteStubFromSurfaces({canonical_name, surfaced_in, first_seen, last_seen, count}) → string` — frontmatter (v0.6.0 typed-alias schema + `created_by: cowork:find-missing-people`) + body with `[!info]- Discovered by cowork:find-missing-people` callout listing the source atomic-note wikilinks.
- `composeReviewTable(missingCandidates) → string` — markdown table grouped by surface-count tier: HIGH (>5 mentions), MEDIUM (2-5), LOW (1). Row format: `| # | Name | Mentions | First seen | Last seen | Sources |`
- `composeReport({applied, skipped, scanned_count, days_back, engagement_id}) → string` — final markdown report.

## 4. Orchestrator step flow

```
1. Pre-flight: cowork:check-vault-routing { required: ["obsidian"] }
2. Resolve target engagement (default-if-one, ask-if-many) — identical to discover-people
3. Compute date range:
   - Today = context.today
   - Window start = today - days_back days
   - Build list of (YYYY, MM-Month, YYYY-MM-DD) tuples for the date range
4. Enumerate atomic notes:
   - For each date in window, list spice/cowork/daily/<YYYY>/<MM-Month>/<YYYY-MM-DD>/*.md
   - Capture as noteSurfaces[] with {path, body (read via Obsidian MCP), date}
5. Aggregate wikilinks:
   - DPH = require(helper)
   - For each note: bodyWikilinks = DPH.scanAtomicNoteForWikilinks(body)
   - candidatesRaw = DPH.aggregateWikilinksAcrossNotes(noteSurfaces)
   - candidates = DPH.filterToPersonShapedWikilinks(candidatesRaw)  // applies to each name in turn
6. Enumerate existing person notes:
   - mcp__obsidian__obsidian_list_files_in_dir("spice/people/")
   - existing_basenames = filter .md files; strip extension
7. Filter to missing:
   - missing = DPH.filterToMissingPeople(candidates, existing_basenames)
8. Review:
   - tableMd = DPH.composeReviewTable(missing)
   - Print to chat
9. Batch confirm: ask user y / n / skip <list>
10. Apply (if confirmed):
    - For each missing candidate in apply_set:
      - stubMd = DPH.composePersonNoteStubFromSurfaces(candidate)
      - Write via mcp__obsidian__obsidian_put_content to spice/people/<basename>.md
11. Optional: ask user "Promote any of these to engagement.inner_circle_people too? (y/n/skip <list>)"
    - On y: call composeUpdatedVaultConfig from discover-people-helper (reuse v0.90.3 fix)
12. Report: composeReport + final Notice
```

## 8. Risks

1. **Person-shape filter could under- or over-extract.** Mitigation: KNOWN_NON_PERSON_NAMES reused from discover-people-helper.js (v0.90.3); same false-positive list. User batch-confirm gate remains the final filter.
2. **Wikilinks pointing to legitimate non-person notes (e.g., `[[Some Project]]`).** Mitigation: shape filter requires capitalized-word names; project notes typically don't fit person-name shape. Worst case: false positive in review table → user `skip <row>`.
3. **Scanning 30 days × 5 cadences per day = 150 files** — performance acceptable for Obsidian MCP at small vault sizes. Larger vaults could be slow; default 30 days keeps scope bounded.
