## What shipped

### NEW per-vault `Debt Defaults.md`

Per-vault defaults file scaffolded create-if-absent at install time. Stores `debts: []` with per-row configuration `{kind, name, current_balance, credit_limit, apr, min_payment, planned_monthly_payment, url, opened_date}`. Edited via `DebtDefaultsEditor` widget (flat-table + modal). Mirrors v0.107.0 Budget Defaults / Paycheck Defaults pattern.

### NEW `spice/finance/debts/` sub-area

Flat per-debt entity layout: `spice/finance/debts/Debt-<Name>.md`. Each entity carries frontmatter `{type: debt, kind, name, current_balance, credit_limit, apr, min_payment, planned_monthly_payment, url, opened_date, last_updated, balance_history[]}`. `balance_history[]` is an auto-snapshot append: every save through `DebtConfigEditor` that changes `current_balance` prepends `{date: today, balance: prev, source: install-seed | manual | skill}` to the history. The `skill` source slot is reserved for v0.109.x cowork integration; v0.108.0 itself writes only `install-seed` (at deploy) and `manual` (user edit).

Hub note `spice/finance/debts/Debts.md` shows: SpaceNavButtons + FinanceNavRow (hub-debts) + DebtsHubSummary three-band rollup + DebtsCards grid.

### 6 NEW widgets (finance helpers)

- **`DebtsHubSummary`** — hub-level three-band: totals (debt + monthly interest + monthly attack + weighted-avg APR + projected zero-debt date), per-kind progress strip, per-debt mini pill-cards sorted by balance DESC.
- **`DebtSummary`** — per-debt three-band: numbers (balance + APR + monthly interest + planned attack + projected payoff date + Edit-balance pill), sparkline of `balance_history[]` with delta pill, paydown progress bar for CC kind.
- **`DebtsCards`** — mini-card grid renderer for the Debts.md hub. Mirror of `BudgetsCards`/`PaychecksCards`.
- **`DebtDefaultsEditor`** — per-vault Debt Defaults flat-table + modal editor. 9 fields per debt (kind dropdown · name · balance · credit_limit cc-only · apr · min · planned · url · opened).
- **`DebtConfigEditor`** — per-debt edit modal. Triggered from `DebtSummary`'s "Edit balance" pill. Auto-snapshots prior `current_balance` to `balance_history[]` with `source: manual` on save.
- **`FinanceNavRow`** — single context-aware nav class replacing the three deleted `BudgetNavButtons`/`PaycheckNavButtons`/`InvoiceNavButtons`. Detects 9 modes from `file.path` + `type` frontmatter. Renders hub modes DIRECTLY (cross-hub nav + `+ New X` via `EntityCreate.render` + `Defaults` link via `AccentButton.render`) — no delegation because `FinanceHubActions` did NOT ship on the lineage this cycle landed on (see § Architectural notes below).

### Paycheck ↔ debt glue

Paycheck `expenses[*]` schema gains optional `debt: "[[Debt-X]]"` wikilink. When set:
- **At runtime**: `PaycheckExpensesEditor` resolves the debt via `metadataCache.getFirstLinkpathDest`, renders a colored chip (`Apple Card · 12% paid`) after the Category cell; chip color band is red (< 33%) / amber (33-66%) / green (> 66%) based on paydown progress (1 - balance/credit_limit). Chip click navigates to the debt entity. In the row-edit modal, amount + url cells are locked read-only with tooltip "From debt entity — edit there via DebtConfigEditor".
- **At scaffold time**: entity-create 0.7.1's new `seed_from_defaults.resolve_wikilinks` field handles the resolution. Paycheck's `new_entity_button` declares `resolve_wikilinks: { field: "debt", merge: { planned_monthly_payment: "amount", url: "url" } }` — when `+ New Paycheck` fires, each expense row with a `debt:` wikilink has its `amount` overwritten with the linked debt entity's `planned_monthly_payment` and `url` with the debt entity's `url`. Source of truth = debt entity.

### 4 NEW installer migrations

All headless-safe (regex YAML mutation + `adapter.read` / `adapter.write`, no `processFrontMatter`), append-only, marker-guarded for idempotency, with `.sauce-backup/<timestamp>/` snapshots before any write. Wired into extended `applyFinanceMigrations` orchestrator.

1. **`applyFinanceDebtScaffolding`** — create-if-absent for `spice/finance/debts/` folder + `Debts.md` hub + `Debt Defaults.md` (empty `debts: []`).
2. **`applyFinanceBudgetGroupSeed`** (CF-3 polish #6+#7) — seeds `groups[]` on existing `Budget-*.md` from current Budget Defaults; case-insensitive name-matches `group: "Unassigned"` categories to their Defaults-declared group. Marker `__group_seed_migrated: v0.108.0`.
3. **`applyFinancePaycheckDefaultsDebtLinking`** — walks Paycheck Defaults CC payment rows, regex name-matches to debt entities, sets `debt: "[[Debt-<slug>]]"` wikilink, strips inline `url:` (debt entity now canonical). Marker `__debt_links_migrated: v0.108.0`.
4. **`applyFinanceNavRowMigration`** — vault-wide regex sweep rewriting `customJS.{Budget,Paycheck,Invoice}NavButtons.render(...)` calls in dataviewjs blocks to `customJS.FinanceNavRow.render(dv)`. Marker comment `<!-- finance-nav-row-v0.6.0 -->` above each rewritten block.

## Architectural notes

**1. Main reset + divergence.** The other session's worktree migration reset `main` back to v0.107.0 close just as this cycle started. CF-3 work (PaycheckSummary, FinanceHubActions, BudgetSummary "Difference" rename) did NOT exist on the lineage v0.108.0 was built against. Design + plan corrected mid-flight (post-state-check). FinanceNavRow renders hub modes directly without delegating to a non-existent FinanceHubActions class. Workshop bump 0.107.0 → 0.108.0 was monotonic on this lineage.

**2. Push state at cycle close.** After S6 self-install, `git pull --rebase origin main` hit conflicts because origin/main had CF-3 (f60aa95) + v0.109.0 projects design + plan + 4 stages from the other session. To avoid mid-flight merge of 9 commits + scope creep, cycle was completed locally without push or tag. **DECISION PENDING:** see § Carries forward.

**3. Old nav-button helper files not auto-deleted on consumer installs.** The installer's file-installation step is create/overwrite — it does not remove files for entries that were removed from `files[]`. After v0.108.0 install, the three old `*-nav-buttons.js` files remain on disk in consumer vaults but no code references them. Harmless. Future cleanup candidate: a generic `applyOrphanedHelperCleanup` step that diffs current manifest `files[]` against `ranch/scripts/<blueprint>/` and deletes stragglers. Out of scope here.

**4. Debt entity initial seeding is manual at deploy.** `applyFinanceDebtScaffolding` only creates the hub + empty Defaults. It does NOT iterate `Debt Defaults.debts[]` and create one entity per row. For headspace, the 6 Debt-*.md entities were written manually in this deploy session. Future enhancement: `applyFinanceDebtScaffolding` could optionally read Defaults' `debts[]` and create-if-absent each entity. Out of scope here.

## Lessons

1. **Pull origin BEFORE starting a multi-stage workshop cycle.** I assumed `main` matched my session-start git log snapshot. The user's worktree migration changed main's tip mid-conversation, and the other session pushed CF-3 + v0.109.0 commits I didn't fetch. By S7, the divergence was 9 vs 10 commits with overlapping file edits. Cost: a graceful-but-unpushed cycle close + a pending merge decision.
2. **Workshop convention vs writing-plans skill granularity is reconcilable.** The plan's stage-level (S1-S7) granularity fit the workshop's commit-after-each-stage convention; sub-step bullets gave bite-sized granularity within each stage. Implementer subagents handled this well.
3. **HC test regex widening at version-bump time is a recurring pattern.** Two pre-existing HC families (`FA7-MANIFEST` finance version regex; `FA7-ENTITY` count assertion) needed widening this cycle. Worth factoring into a future plan template: "every cycle adds at least one widening edit somewhere."
4. **Subagent-driven-development with the workshop's HC test gate as the spec-compliance check works fine.** Each implementer subagent ran `node platform/test/run-helper-cases.js` as their gate; the harness IS the spec compliance check. No separate spec-reviewer subagents needed. Code-quality review can happen on the final merged result.
