## Headline

PATCH closing the v0.127.0 §F gap: `_healNoteChromeBody` step 6 had injected the `<!-- TODAY_CAPTURE_MARKER -->` sentinel but **not** the `TodayCaptureEditableList` dataviewjs renderer block. Existing pre-v0.127.0 daily notes ended up with the anchor but no editable-list UI — defeating click-to-edit on any daily note created before the deploy.

## Root cause

The v0.127.0 §F design specified two things: a marker (anchor) + a renderer (the dataviewjs block that reads tasks scoped by the anchor). Both shipped in the **template** (`Today To-Do.md`) for NEW daily notes. But `_healNoteChromeBody` step 6 only injected the **marker** into EXISTING daily notes — the renderer block was missed. Result: 18 existing daily notes in the accuris vault (and matching counts in headspace + ero) had the marker but no renderer; the `TodayCaptureEditableList` class was never invoked on them.

The v0.127.0 step 6 guard was `if (type === 'to-do' && !out.includes(TODAY_CAPTURE_MARKER))` — a single all-or-nothing guard. A note with the marker present (from v0.127.0 heal) and no renderer would short-circuit before the renderer logic could even exist.

## Fix

Split the v0.127.0 single-guard into two independent guards inside step 6:

```javascript
if (type === 'to-do') {
  // (a) Inject marker if absent.
  if (!out.includes(TODAY_CAPTURE_MARKER)) { /* ... */ }
  // (b) Inject TodayCaptureEditableList block if absent. Position:
  // immediately after the marker line.
  if (!out.includes('class: "TodayCaptureEditableList"')) { /* ... */ }
}
```

This makes the heal **resumable**: a v0.127.0 half-pass (marker only) becomes a v0.127.1 full-pass (renderer added). A fully-healed note (both present) stays unchanged.

## Lessons captured

1. **Heal-step pairing.** When a v0.127.0 step injects an anchor that a v0.127.0 renderer block reads, both must be injected together — splitting the guard so the renderer back-fills on partial-pass is the resumable shape. A single all-or-nothing guard breaks resumability. RULE for future heal additions: every anchor-renderer pair gets paired guards, not nested.

2. **Pre-deploy regression coverage gap.** v0.127.0's `run-task-interactions.js` harness covered the mechanism's logic but NOT the install.js heal's end-to-end shape. The bug only surfaced on actual consumer vaults. Add a `run-v0127*-today-capture-editable-list-render` integration test that LOADS a pre-deploy daily note through `_healNoteChromeBody` and asserts the post-heal body actually invokes `TodayCaptureEditableList`. (Done as part of v0.127.1's `run-v01271-today-capture-renderer-heal.js`.)

3. **PATCH-tolerant version pins are a documented win.** v0.127.0 S9 introduced PATCH-tolerant regex (`/^0\.12\.\d+$/`) for the to-do blueprint pin after the in-cycle 0.12.0 → 0.12.1; v0.127.1 widens the workshop-version pins to the same shape. Reinforces landmine #16 hygiene — write the regex at the time of the cycle bump, not when the next PATCH hits the wall at preflight.
