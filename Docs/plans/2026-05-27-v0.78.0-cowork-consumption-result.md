## Outcome summary

v0.78.0 closes the consumption gap that v0.76.0 + v0.77.0 left open: the
five cowork atomic-note orchestrators (morning-briefing, midday-tripwire,
eod-review, weekly-review, monthly-review) now READ the user-owned
`spice/cowork/context/user-preferences.md` file at fire-time and shape
their output accordingly. Priorities reorder the `[!example]+` callout
blocks (first-in-priorities = first-rendered = highest-attention); the
voice-contract personality block (vibe / formality / pep_talk / length /
notes) gets composed into a prompt prefix that scopes only the narrative
sections (synopsis, tip) — tabular example callouts are unaffected. Two
new vendor-agnostic sub-skills do the heavy lifting:
`cowork:read-user-preferences` (pure parse + status code) and
`cowork:gather-from-served-by` (one gather path for BOTH
`override_classified` known-kind MCPs and user-defined `custom_kind`
MCPs, dispatched inline against the namespace recorded by v0.77.0's
`served_by` breadcrumb).

The legacy fallback path is bit-for-bit preserved: when
`user-preferences.md` is missing, seed-shape, or malformed, every
orchestrator falls through to the v0.77.0 hardcoded gather sequence
unchanged. In-position `[!warning]` callouts replace example blocks for
kinds that are unclassified, disconnected at capture time, or whose
served_by namespace is unreachable at fire time (no more silent gaps).
14 new HC-V0780-* test cases live in `run-cowork-smoke.js`; the file
count stays at 23. Forcing function: the accuris vault's 2026-05-27
morning-briefing.md atomic note ignored captured priorities,
personality, and the user's three classified custom kinds (ADO,
Backstage, NewRelic) entirely — v0.78.0 makes the next fire honor all
three.

## Behavioral changes

**5 orchestrators consume `user-preferences.md`.** Each of
morning-briefing / midday-tripwire / eod-review / weekly-review /
monthly-review SKILL.md gains:

- **Step 3b (read prefs).** Calls `cowork:read-user-preferences`
  sub-skill; receives `{ prefs, status }`.
- **Step 3c (plan dispatch).** When `status === "ok"`, builds an ordered
  `dispatch_plan[]` from `prefs.priorities[]` and `prefs.mcps`. When
  `status === "empty"` or `"malformed"`, sets `dispatch_mode: "legacy"`
  and uses the v0.77.0 hardcoded gather sequence verbatim.
- **Gather phase (steps 5–12).** Becomes a priority-ordered loop:
  canonical-vendor kinds (calendar served by Google_Calendar, email
  served by Gmail) dispatch to the v0.77.0 vendor-locked gather skills;
  `override_classified` kinds (M365 UUID gateway, etc.) and
  `custom_kind` kinds (ADO / GitHub / Backstage) dispatch to the new
  `cowork:gather-from-served-by` sub-skill. Unclassified / disconnected
  / unreachable kinds emit in-position `[!warning]` callouts in place of
  the example block.
- **Step 13b (voice contract).** Composes a 1–4 sentence prompt prefix
  from `prefs.personality` (vibe / formality / pep_talk / length /
  notes); injected before the composing-agent reads the body prompt;
  scoped to narrative sections (synopsis, tip) only.
- **Step 14 (compose).** Calls the new `compose-body-helper.js`
  end-to-end: takes `{ prefs, dispatch_plan, gather_results }` →
  emits a body skeleton with priority-ordered Example blocks, custom
  Example titles (e.g., `ado` instead of one of the 4 hardcoded kinds),
  and warning callouts in position.

**Legacy fallback bit-for-bit preserved.** Workshop self-install dogfood
(which has an empty `user-preferences.md`) produces a morning-briefing
structurally identical to v0.77.0 — same gather sequence, same example
block order, no voice-contract prefix, no warning callouts. The only
visible diff is a new Notice line at top of body stating
`Preferences: not captured (fallback to defaults).` The HC-V0780-D1 +
D2 cases gate this byte-equivalence.

**Two new vendor-agnostic sub-skills (4 new managed surfaces):**

- `cowork:read-user-preferences` — SKILL.md + `read-user-preferences-helper.js`. Pure read; status code; no MCP calls; no side effects. Helper exports `readUserPreferences({ vaultRoot })` returning `{ prefs, status, reason? }`.
- `cowork:gather-from-served-by` — SKILL.md + `gather-from-served-by-helper.js`. Dispatches inline against the namespace recorded by v0.77.0's `served_by` breadcrumb; produces a callout block honoring the per-kind `what_matters` free-text and the kind's question shape (canonical for `override_classified`; free-form for `custom_kind`).

Two new helpers (`dispatch-plan-helper.js`, `compose-body-helper.js`)
support the orchestrators' new steps; not exposed as sub-skills.

## Known follow-ups (carry-forward to v0.79.0+)

**Consumption-layer refinements:**

- **`kind_title` field on `mcps.<kind>` blocks.** v0.78.0 uses the bare
  kind key (`chat`, `ado`, `github`) as the rendered Example title. A
  future `kind_title:` field on each MCP block would let users supply a
  prettier display string (e.g., `Microsoft Teams chat` instead of
  `chat`). Pure cosmetic; deferred.
- **Personality hard rules.** v0.78.0's voice-contract prefix is 1–4
  sentences of guidance composed from prefs.personality. A future
  expansion would let users declare HARD rules (e.g., `never use the word
  'leverage'`, `always lead with a number`) that get appended as a
  separate "hard rules" block the composing agent must honor verbatim,
  not interpret.
- **`inherits_from:` cross-vault preferences.** Allow one vault's
  user-preferences.md to declare it inherits from another vault's
  (`inherits_from: ../other-vault/spice/cowork/context/user-preferences.md`).
  Resolution-order spec + cycle-detection guard required.

**Adaptive-detection refinements (carry-forward from v0.77.0):**

- **Expanded known-kinds catalog.** Current v2 schema has 4 known
  capabilities (calendar, email, chat, finance). Strong v0.79.0
  candidates: drive (Google Drive / Dropbox / S3), code-platform (GitHub
  / GitLab), project-tracker (Linear / Jira / ADO), monitoring
  (NewRelic / Datadog / PagerDuty). Each gets a hand-curated question
  set in context-builder + a `tool_patterns[]` entry in
  `mcp-skill-map.json`.
- **Promote frequently-used custom kinds to known.** Once post-v0.78.0
  deployment usage data exists, identify the top-N most-common
  user-defined custom kinds and promote them into the known catalog so
  they get hand-curated question sets instead of free-text
  `what_matters`.

**v0.76.0 carry-forward (still open):**

- **5 cowork prompts** in `files[]` without `materialize_once` (still
  `.bak`'d-and-overwritten on reinstall via v0.2.0 Option B). Promote
  to strict-USER or formalize the `.bak` behavior. Deferred to v0.79.0
  or later.

**Lighter v0.75.x carry-forwards (still open):**

- `--subscribe <mech>=<ver>` CLI flag — new-in-workshop mechanism

- HC-V0751-A1 registry-driven — hardcodes 3 engagement-type names;
