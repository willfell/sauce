# v0.128.0 — project-todo click-to-edit (design)

## Mission

Extend click-to-edit from daily To-Do `## Today` to Project To-Do `Owned Tasks` using the same reused `ToDoCreateTask` modal (`editExisting` mode unchanged). Establishes a third anchor sentinel `<!-- OWNED_TASKS_MARKER -->` symmetric with v0.127.x's `TODAY_CAPTURE_MARKER` + `ACTION_ITEMS_MARKER`. Generalizes `TodayCaptureEditableList` into a type-agnostic `EditableTaskList` driven by a `sectionAnchor` config arg. Fixes one v0.127.0 anchor-mismatch bug (`appendTask` for project-todo) while we're touching the surface.

The cycle thesis: v0.127.0 §F's universal-task-edit contract was scaffolded for one consumer surface (today daily). v0.128.0 proves the architecture by **promoting that consumer to multi-surface** with zero changes to the modal, the writer, or the parser — only a config arg on the renderer and a new anchor on the mechanism.

## §A — `task-interactions@0.2.0` extension

### New surface

```
TaskInteractions.ownedTasksAnchor() → "<!-- OWNED_TASKS_MARKER -->"
TaskInteractions.injectOwnedTasksMarker(body) → string (pure transform)
TaskInteractions.findTaskLines(content, "ownedTasks") → Array<{ idx, line, parsed }>
```

`ownedTasksAnchor()` mirrors `todayCaptureAnchor()` + `actionItemsAnchor()` literally — third member of the same family.

`injectOwnedTasksMarker(body)`:
- Idempotent guard via `body.includes(ownedTasksAnchor())`.
- Find the literal substring `class: "SectionLabel", args: [{ text: "Owned Tasks" }]` OR (NEW — see §A.fix) `class: "SectionLabel", args: [{ text: "Owned Tasks", top: true }]`. Either match accepted.
- Walk forward to the closing fence of that block. Insert marker on its own line immediately after, with one blank line above + below the marker.
- Returns body unchanged when no Owned Tasks SectionLabel block exists.

`findTaskLines(content, "ownedTasks")`:
- Same shape as the existing `"todayCapture"` + `"actionItems"` paths in the L207-L245 `findTaskLines` static method.
- Anchor = `ownedTasksAnchor()`; start AFTER the marker line.
- Stop condition: next SectionLabel block OR next `## ` heading OR EOF. The Project To-Do template's next block is `text: "From Meetings"` SectionLabel → that's the natural terminator.
- Fence-aware via the existing `fenceDepth` counter.

### §A.fix — `appendTask` project-todo anchor loosen (v0.127.0 bug)

Current code at L335: `const needle = 'class: "SectionLabel", args: [{ text: "Owned Tasks" }]'` (no `top: true`).

**Problem:** v0.127.0's workshop template `Project To-Do.md` has `top: true`, but `entity-create` materialization in older project-todo notes ships WITHOUT `top: true`. When the meeting → New Task button writes to a consumer project-todo file with `top: true` in the SectionLabel, the literal-string `needle` doesn't match → fallback path (append-to-end-of-file) fires silently. User saw this in the v0.127.0 smoke test: `verify dual write` didn't actually land in `Graphene To-Do.md` (graphene's note has `text: "Owned Tasks"` without `top: true`, which DOES match the v0.127.0 needle — so this case worked. But files with `top: true` would silently fall through).

**Fix:** Replace single-string `needle` matcher with a regex that accepts BOTH forms:

```javascript
const ownedTasksRe = /class:\s*"SectionLabel",\s*args:\s*\[\{\s*text:\s*"Owned Tasks"(?:\s*,\s*top:\s*true)?\s*\}\]/;
// scan lines for first match
let labelLineIdx = -1;
for (let i = 0; i < lines.length; i++) {
  if (ownedTasksRe.test(lines[i])) { labelLineIdx = i; break; }
}
```

Same shape used in `injectOwnedTasksMarker`. One literal becomes one regex; behavior is a strict superset of v0.127.0's; no consumer breaks.

### §A.append — appendTask for project-todo with marker preference

Update `appendTask` `type === "project-todo"` branch to prefer the marker over the SectionLabel scan, mirroring how the `"to-do"` and `"meeting"` branches work:

```javascript
} else if (type === "project-todo") {
  const marker = TaskInteractions.ownedTasksAnchor();
  let working = body;
  if (!working.includes(marker)) {
    working = TaskInteractions.injectOwnedTasksMarker(working);
  }
  if (working.includes(marker)) {
    const lines = working.split("\n");
    let markerLineIdx = -1;
    for (let i = 0; i < lines.length; i++) {
      if (lines[i].includes(marker)) { markerLineIdx = i; break; }
    }
    // Insert immediately AFTER the marker line + blank.
    lines.splice(markerLineIdx + 1, 0, "", line);
    newContent = lines.join("\n");
  } else {
    // Marker injection failed (no Owned Tasks SectionLabel either) — fall back
    // to v0.127.0 SectionLabel-fence-append behavior with the loosened regex.
    // [v0.127.0 fallback code with §A.fix regex]
  }
}
```

The marker-preferred path makes project-todo's writer **insertion-order stable**: new tasks always go to the same exact line position relative to the marker, regardless of how many tasks already live below it. Same property as meeting + to-do branches.

## §B — `TodayCaptureEditableList` → `EditableTaskList` (generalize)

### Rename rationale

The class is now scoped via a config arg — its name shouldn't lie about being today-only. v0.128.0 renames the class + the source file:

- Old: `today-capture-editable-list.js` exports `class TodayCaptureEditableList { ... }`
- New: `editable-task-list.js` exports `class EditableTaskList { ... }`

### New signature

```javascript
class EditableTaskList {
  async render(dv, opts = {}) {
    // opts.sectionAnchor: "todayCapture" | "ownedTasks" — REQUIRED for v0.128.0 callers.
    // Backward-compat: when opts missing or undefined, default to "todayCapture"
    // (matches v0.127.0 behavior so any cached/stale invocation keeps working).
    const sectionAnchor = (opts && opts.sectionAnchor) || "todayCapture";
    // ... existing render logic, but pass sectionAnchor to findTaskLines.
  }
}
```

The existing render logic at L20-L100 of `today-capture-editable-list.js` is structurally unchanged — only:
1. Add `opts` argument + `sectionAnchor` extraction.
2. Pass `sectionAnchor` to `customJS.TaskInteractions.findTaskLines(content, sectionAnchor)`.
3. Tweak the empty-state message to be section-agnostic ("No tasks yet. Add a checkbox above." stays — same hint applies to both surfaces).

### Back-compat shim for v0.127.x notes

Some daily notes materialized at v0.127.0/v0.127.1 carry the dataviewjs invocation `class: "TodayCaptureEditableList"`. The to-do blueprint's `customjs_classes[]` array currently includes that name. To avoid breaking those notes on the FIRST install after v0.128.0:

1. The new `EditableTaskList` class is the canonical primary registration.
2. A 3-line back-compat alias is registered in the same source file as `EditableTaskList`:
   ```javascript
   // Back-compat alias (v0.128.0): legacy notes invoke TodayCaptureEditableList.
   // Heal step 6 rewrites the invocation to EditableTaskList on next install;
   // until then, the alias keeps existing notes rendering.
   class TodayCaptureEditableList extends EditableTaskList {}
   ```
3. The `customjs_classes[]` array in `to-do/manifest.json` lists BOTH names so both register.
4. `_healNoteChromeBody` step 6 is extended to ALSO rewrite legacy invocations: when scanning a to-do note, if it contains `class: "TodayCaptureEditableList"` substring, rewrite to `class: "EditableTaskList", args: [{ sectionAnchor: "todayCapture" }]`. Two passes: existing v0.127.x notes auto-migrate on next install; new notes get the canonical form from the template.

After ~2-3 cycles when consumer notes have all converged, the alias + `customjs_classes[]` entry for `TodayCaptureEditableList` can be retired (carry-forward).

## §C — Project To-Do template

### Template changes

`platform/blueprints/to-do/templates/Project To-Do.md` currently emits:

```
... chrome ...
SectionLabel("Owned Tasks", top: true)
SectionLabel("From Meetings")
ToDoDailyProjectGroups(scope: "project-todo")
```

Becomes:

```
... chrome ...
SectionLabel("Owned Tasks", top: true)

<!-- OWNED_TASKS_MARKER -->

EditableTaskList(sectionAnchor: "ownedTasks")

SectionLabel("From Meetings")
ToDoDailyProjectGroups(scope: "project-todo")
```

The marker + renderer block live BETWEEN the Owned Tasks SectionLabel and the From Meetings SectionLabel — exactly the scope `findTaskLines("ownedTasks")` walks.

Raw `- [ ]` lines users type in the editor anywhere between the marker and the From Meetings SectionLabel get rendered as clickable rows by `EditableTaskList`.

## §D — Installer heal

### Step 7 (NEW) — project-todo paired guards

After v0.127.1's split-guard pattern, the new step 7 takes the same shape but for project-todo:

```javascript
if (type === 'project-todo') {
  const ownedTasksRe = /class:\s*"SectionLabel",\s*args:\s*\[\{\s*text:\s*"Owned Tasks"(?:\s*,\s*top:\s*true)?\s*\}\]/;
  // Find the matching SectionLabel line.
  let labelLineIdx = -1;
  const lines = out.split("\n");
  for (let i = 0; i < lines.length; i++) {
    if (ownedTasksRe.test(lines[i])) { labelLineIdx = i; break; }
  }
  if (labelLineIdx !== -1) {
    // Walk forward to closing fence.
    let closingFenceIdx = -1;
    for (let i = labelLineIdx + 1; i < lines.length; i++) {
      if (lines[i].trimStart().startsWith("```")) { closingFenceIdx = i; break; }
    }
    if (closingFenceIdx !== -1) {
      // (a) Inject marker if absent.
      if (!out.includes(OWNED_TASKS_MARKER)) {
        // Splice "" + marker + "" after closing fence.
        const insertAt = closingFenceIdx + 1;
        lines.splice(insertAt, 0, "", OWNED_TASKS_MARKER, "");
        out = lines.join("\n");
      }
      // (b) Inject renderer block if absent.
      if (!out.includes('class: "EditableTaskList"')) {
        const refreshed = out.split("\n");
        const markerIdx = refreshed.findIndex(l => l.includes(OWNED_TASKS_MARKER));
        if (markerIdx !== -1) {
          const rendererBlock = ['', '```dataviewjs', 'await dv.view("ranch/views/customjs-guard", { class: "EditableTaskList", args: [{ sectionAnchor: "ownedTasks" }] });', '```'];
          refreshed.splice(markerIdx + 1, 0, ...rendererBlock);
          out = refreshed.join("\n");
        }
      }
    }
  }
}
```

Independent guards (lesson from v0.127.1) — half-pass becomes full-pass on next install; fully-healed note stays unchanged.

### Step 6 update — TodayCaptureEditableList → EditableTaskList rewrite

In the existing step 6 (to-do, v0.127.1 split guards), add a third guard:

```javascript
// (c) Rewrite legacy TodayCaptureEditableList invocations to EditableTaskList.
if (out.includes('class: "TodayCaptureEditableList"')) {
  out = out.replace(
    /class:\s*"TodayCaptureEditableList"\s*\}/g,
    'class: "EditableTaskList", args: [{ sectionAnchor: "todayCapture" }] }'
  );
}
```

Bounded regex matches only the customjs-guard invocation form; preserves any incidental text mentioning the class name.
