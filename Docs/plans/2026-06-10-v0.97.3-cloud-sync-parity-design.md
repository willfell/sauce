# v0.97.3 cloud-sync-parity — design

> [!info]+ Status
> AUTO-EXECUTE authorized per user instruction (direct push, no PRs). Push gated to S5 with explicit user approval. SHIPPED 2026-06-10.

## 0. Origin

v0.97.2 closed the wrapper-delegation hole by adding an `ANTI-DELEGATION (NON-NEGOTIABLE)` directive and a date-resolution `PRELUDE` block to every composed scheduled-job wrapper. The fix worked when the sync was driven locally via the sauce CLI: `compose-scheduled-job-wrappers-helper.js` ran in Node, prepended the directive + PRELUDE around the orchestrator-instructions body, and the wrapper went out to the cron task fully guardrailed.

But when the sync runs in claude.ai's Cowork UI (cloud-side), there is no Node runtime. The cloud LLM can only read markdown files from the vault and substitute tokens. It does not execute JS helpers. So the guardrail-verify step inside the cloud sync orchestrator looked at `orchestrator-instructions/*.md` and `_shared-clauses.md`, searched for `ANTI-DELEGATION (NON-NEGOTIABLE)`, found it nowhere, and correctly refused to push the wrapper (because, from its perspective, the wrapper was missing the v0.97.2 guardrail).

This was the right call by the cloud sync — but the source of truth was wrong. The guardrail text lived only in the JS helper as a literal string. Locally-driven syncs would silently produce different output from cloud-driven syncs.

## 1. Scope

### 1.1 What ships

- **Three new shared clauses** in `_shared-clauses.md`: `anti_delegation_clause`, `prelude_block`, `done_block`. They are markdown headings (`## anti_delegation_clause`, etc.) parsed by the helper's existing `_loadSharedClauses` parser.
- **Six orchestrator-instructions cadence files updated** — each references the new clauses at top + bottom via `{{shared.anti_delegation_clause}}` / `{{shared.prelude_block}}` / `{{shared.done_block}}`. The top references go AFTER the closing `---` of the file's existing frontmatter; the bottom reference goes at the very end of the file.
- **JS composer stripped of literal text** — the `composeFromOrchestratorInstructions(...)` function no longer prepends ANTI-DELEGATION text or appends DONE text; the wrapper-construction block at the bottom of the function is replaced with a single `return _substituteStaticTokens(template, tokens)` line. Pure substituter.
- **11 new HC sub-asserts** (HC-V0973-CSP-1..11) verifying cadence-side references, clause-side definitions, and that the helper source no longer contains the literal text.

### 1.2 What does NOT ship

- Touching `scheduled-job-contract.json` — the contract shape didn't change (no shared_clauses changes are needed in the contract because the contract's `shared_clauses` block is a STATIC inline string map used by the legacy `wrapper_template` rail; the orchestrator-instructions Rail T uses the markdown-file shared-clauses parsed at compose time). `contract_version` stays 0.35.1.
- Touching wrapper-shape, fire-time tokens, or per-cadence steps — purely a "where does the text live" migration. Composed-wrapper output is structurally identical to v0.97.2 (still contains ANTI-DELEGATION, PRELUDE, DONE substrings). HC-V0972-AD-* and HC-V0972-DP-* still GREEN.
- Any new behavior at fire time — the cron LLM sees the same wrapper text it would have seen under v0.97.2 locally-composed.

## 2. Architecture overview

### 2.1 Cycle identity

- **Workshop:** 0.97.2 → **0.97.3** PATCH
- **Cowork blueprint:** 0.35.2 → **0.35.3** PATCH
- **scheduled-job-contract.json `contract_version`:** **UNCHANGED at 0.35.1**
- **Mechanism count:** unchanged (17)
- **Codename:** `cloud-sync-parity`

### 2.2 Why parity matters

The cowork sync architecture is now multi-rail:

- **Local rail** — `sauce reconcile-cowork` (deprecated) or the manual `/cowork sync-scheduled-jobs` flow from a local Claude Code session: the JS composer runs in Node, reads `orchestrator-instructions/<cadence>.md`, substitutes tokens, produces a wrapper.
- **Cloud rail** — claude.ai's Cowork UI scheduled task: the cloud orchestrator reads the same `orchestrator-instructions/<cadence>.md` files via Obsidian MCP, substitutes tokens via its own LLM-driven substituter, and produces a wrapper.

For these two rails to converge on byte-identical output, ALL load-bearing wrapper content must live in a vault file that BOTH rails can read. Any text that exists only in JS literals is invisible to the cloud rail. v0.97.2 produced a JS-only guardrail; v0.97.3 migrates it to vault sources.

### 2.3 The shared-clause migration

Three blocks move from JS literals (`compose-scheduled-job-wrappers-helper.js`) to markdown headings in `_shared-clauses.md`:

1. **`anti_delegation_clause`** — verbatim paragraph from v0.97.2 banning subagents / Task() / Agent().
2. **`prelude_block`** — 4-step fire-time setup, parameterized via `{{$timezone}}` + `{{$engagement_id}}` tokens so the cloud rail can substitute the engagement's actual timezone (no more hardcoded "America/Denver").
3. **`done_block`** — trailing notice + "Generated against sauce X + cowork Y + contract Z" footer, parameterized via `{{$cadence}}` + `{{$engagement_label}}` + `{{$workshop_version}}` + `{{$cowork_version}}` + `{{$contract_version}}` tokens.

Each cadence file references all three via `{{shared.*}}` placeholders:

- Top of file (after frontmatter, before the `# cowork:<cadence> — orchestrator-instructions` header): `{{shared.anti_delegation_clause}}` then `{{shared.prelude_block}}`.
- Bottom of file (after Harness testing / Performance / Failure modes): `{{shared.done_block}}`.

### 2.4 The JS composer simplification

`composeFromOrchestratorInstructions(...)` becomes a 5-step pipeline:

1. Load orchestrator-instructions file
2. Resolve conditional `{{#if cadence_mode == ...}}` branches
3. Substitute `{{shared.<key>}}` from parsed `_shared-clauses.md`
4. Compute static token map (`engagement_id`, `engagement_label`, `timezone`, `voice_notes`, `priorities`, `mcp_dispatch_lines`, `inner_circle`, `workshop_version`, `cowork_version`, `contract_version`, `cadence`, `cadence_mode`, `frontmatter_type`, `title_template`)
5. Substitute `{{$<token>}}` (leaves `{{$today_*}}` + computed-at-emit tokens literal for fire-time resolution)

After Step 5, the function `return`s. No more wrap-with-PRELUDE-and-DONE step.

### 2.5 Test coverage

11 new HC sub-asserts (HC-V0973-CSP-1..11):

- **CSP-1..6** (6) — each cadence file contains `{{shared.anti_delegation_clause}}` + `{{shared.prelude_block}}` + `{{shared.done_block}}` references.
- **CSP-7..9** (3) — `_shared-clauses.md` defines `## anti_delegation_clause` / `## prelude_block` / `## done_block` heading blocks.
- **CSP-10..11** (2) — `compose-scheduled-job-wrappers-helper.js` source no longer contains `ANTI-DELEGATION (NON-NEGOTIABLE)` or `PRELUDE — fire-time setup` as literals.

Pre-existing HC-V0972-AD-1..7 + HC-V0972-DP-1..4 still GREEN — the strings are still in the composed output, just sourced from `_shared-clauses.md` now instead of JS literals. The asserts don't care where the text came from.

## 3. Cost considerations

Net-zero. Same characters in the composed wrapper, just sourced from a markdown file instead of a JS string literal. No new MCP calls, no new sub-skills, no new fire-time behavior.

## 4. Risk analysis

### 4.1 What could go wrong

- **A subscriber doesn't re-sync after deploy.** Cloud sync continues to see v0.97.2-shape vault files (no `{{shared.anti_delegation_clause}}` reference) and aborts. Mitigation: ship + brew + `sauce update --bump-pins` per vault. Cloud sync will then see the v0.97.3-shape files and succeed.
- **Cloud LLM's `{{shared.*}}` substituter doesn't handle the new keys.** Unlikely — the same substitution pattern is already used for `{{shared.dataviewjs_block}}`, `{{shared.voice_clause}}`, etc. Three more keys via the same mechanism.

### 4.2 What CAN'T go wrong

- Composed wrapper changes shape. Locally-composed wrappers via `compose-scheduled-job-wrappers-helper.js` produce structurally-identical output to v0.97.2 — same ANTI-DELEGATION text, same PRELUDE, same DONE. Verified by HC-V0972-AD/DP staying GREEN.

## 5. Out-of-scope (parked)

- Migrator that auto-updates pre-v0.97.3 vault files in-place (some other vaults may need a one-shot sweep). Currently relying on `sauce update --bump-pins` to overwrite from workshop.
- Per-skill SemVer + per-skill versioning CI — still queued.
- v0.97.1 launchd grace removal — still queued for v0.98.0+.

## 6. Action required post-deploy

User runs `sauce update --bump-pins` against each consumer vault (workshop dogfood + headspace; accuris pending separate machine). This materializes the v0.97.3 `_shared-clauses.md` + 6 cadence files into the consumer's `spice/cowork/data/orchestrator-instructions/` dir. THEN user runs `/cowork sync-scheduled-jobs` from claude.ai's Cowork UI — the cloud LLM reads the updated vault sources, sees all three guardrail substrings, passes verify, and pushes the new wrappers to live scheduled tasks via `update_scheduled_task` MCP.
