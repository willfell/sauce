# v0.124.1 patch — to-do link paren fix + double-divider heal refinement

Two small fixes surfaced during the v0.124.0 rollout review (accuris). Both root-caused + verified.

## Task A — To-Do task link: balanced parens in URLs

**Bug:** `_renderTaskHTML` in `platform/blueprints/daily/helpers/space-daily-dashboard.js` (~L1259) finds the markdown-link URL end with `text.indexOf(")", closeBracket + 2)` — the FIRST `)`. Teams deep-link URLs contain literal parens (`channelName=Developer%20Enablement%20(Lounge)`), so the URL truncates at the inner `)` and the tail (`&createdTime=...&ngc=true)`) leaks as escaped literal text. Verified repro confirms a balanced-paren scan captures the full URL with zero leak.

**Fix:** replace the `indexOf(")")` with a CommonMark-style balanced-paren scan:
```javascript
// find the closing paren, allowing balanced parens inside the URL
let depth = 0, closeParen = -1;
for (let k = closeBracket + 2; k < text.length; k++) {
  const c = text.charAt(k);
  if (c === "(") depth++;
  else if (c === ")") { if (depth === 0) { closeParen = k; break; } depth--; }
}
if (closeParen >= 0) {
  const linkText = text.slice(i + 1, closeBracket);
  const url      = text.slice(closeBracket + 2, closeParen);
  tokens.push({ kind: "mdlink", text: linkText, url });
  i = closeParen + 1;
  continue;
}
```

**Test:** add to `run-renderer.js` (it already loads `SpaceDailyDashboard` and tests methods). A task with a Teams URL containing `(Lounge)` → `_renderTaskHTML` returns a single `<a href="<full url>">chat</a>` and NO leaked `&createdTime` text. Also a control case: a normal `[text](url)` (no inner parens) still renders correctly, and balanced nested parens `((a))` work.

**Bump:** daily blueprint 0.13.7 → 0.13.8 (PATCH).

## Task B — Double-divider heal refinement

**Bug:** healed existing meeting notes show a markdown `---` + SectionLabel hairline (double divider) before Agenda/Notes/Action Items. The old template had `---` + blank line + `## Heading`; `_healNoteChromeBody`'s H2 conversion only drops a `---` directly adjacent to the heading, so the blank-line-shielded `---` survived. New-from-template notes are clean; ~151/154 healed meetings on each vault have it.

**Fix:** in `platform/install.js` `_healNoteChromeBody`, add a normalization pass (after breadcrumb injection + H2→SectionLabel conversion) that removes a `---` line immediately preceding (across blank lines only) a ` ```dataviewjs ` block whose body contains `SectionLabel`, leaving exactly one blank line before the SectionLabel block. This:
- cleans ALREADY-HEALED notes (their SectionLabel blocks exist with a leftover `---` before them), AND
- cleans freshly-converted notes in the same pass.
Safety: ONLY a `---` whose next non-blank content is a SectionLabel **dataviewjs block** is removed (chrome-targeted; a user `---` before prose is untouched). Idempotent: after removal there is no `---` before the SectionLabel, so a second pass is a no-op.

**Seed test:** ensure a meeting fixture exercises the blank-line-shielded `---` (real pre-heal template shape: `SpaceNavButtons``` then `---` then blank then `## Heading`). Add `HC-V01241-SEED-DBLDIV-*` asserts: post-heal, no `---` line immediately precedes a SectionLabel block; and idempotency (second install byte-identical). Reuse the existing chrome-heal fixture family; adjust the fixture to include the blank-line-shielded divider if it doesn't already.

**Bump:** install.js change → `workshop_version` 0.124.1.
