## Motivation

The v0.74.0 cycle shipped a Pre-write self-check inside each `write-run-note-<orch>` SKILL.md that enforces 5 structural body markers + `title:` / `summary:` frontmatter. **The contract only fires when the agent's Skill tool actually loads the sub-skill body.** In multi-context Claude Code invocations — scheduled-tasks-MCP-driven cron fires, multi-machine sessions, IDE plugins with different skill-loading models — `Use Skill cowork:<X>` gets interpreted as natural-language intent ("do the thing X implies") instead of a directive to load X.md and follow its sections. The body-shape contract is never consulted; the agent writes an ad-hoc note that misses the v0.74.0 contract. **Observed in practice; this is the primary motivation for v0.75.0.**

As a parallel deliverable, the cycle also lands semantic retrieval via Smart Connections — the third retrieval mode in cowork's information-access toolkit, alongside filesystem + ripgrep (lexical/structural) and the Obsidian Local REST API (live runtime ops). Two v0.74.0 carry-forwards round out the cycle: the S6 engagement-types path-resolution fix in onboard-scheduled-jobs Step 2, and FLN-v67-7 `sauce update --bump-pins` for consumer subscription auto-bump (felt the manual cost in v0.74.0's 4-vault deploy and will again here).

The three retrieval-mode framing (post-v0.75.0):

| Need | Path |
|---|---|
| Lexical / structural / bulk edits | filesystem + ripgrep |
| Semantic "what's conceptually related to X" | **NEW** — sc-bridge CLI over `.smart-env/multi/*.ajson` |
| Live runtime ops (Dataview eval, Templater, active-file) | Obsidian Local REST API |

## Observed gaps

### The "Use Skill" trap (Workstream A driver)

Concrete failure surface in real-fire output today: when an orchestrator instruction says `Use Skill cowork:write-run-note-morning-briefing with {...}`, an agent in a session that has cowork registered as discoverable skills loads the sub-skill body and the 5-marker + title/summary check fires. In a session that does NOT have vault-side skills registered (scheduled-tasks MCP fires the orchestrator with a stripped-down prompt, multi-machine via remote control, IDE plugin with a different skill loader), the agent treats the instruction as intent: "the orchestrator wants a note written," composes a plain `## Heading`-based body, omits the admonition markers, and skips the frontmatter title/summary fields. The note is written, the orchestrator emits its Notice as if everything succeeded, and the violation is invisible until a downstream consumer trips over the missing markers.

The fix has three layers, all designed to ship together because they double-cover the same failure surface:

- **Layer 1 — Harden the orchestrator instruction.** Every `Use Skill cowork:<X>` reference in an orchestrator SKILL.md gets rewritten to a `READ .claude/skills/cowork/skills/<X>/SKILL.md ... then apply ...` form that names the file path and the body-shape sections explicitly. Removes the soft "Use Skill" ambiguity.
- **Layer 2 — Post-write structural verification.** After each write-run-note-* call returns success, the orchestrator reads the file back and regex-scans for the required markers + frontmatter. On any miss it deletes the file and returns `failed:contract-violation:<field>`. Catches violations even when Layer 1 is bypassed; the agent literally cannot ship a non-compliant note because the orchestrator verifies it.
- **Layer 3 — Enriched scheduled-tasks prompts.** When `cowork:onboard-scheduled-jobs` registers a task, the registered prompt grows from `Use skill cowork:<orch> with { engagement_id: "<id>" }` to a longer form that explicitly tells the agent to READ each sub-skill's SKILL.md and honor its sections. Shifts enforcement upstream to the prompt that triggers the orchestrator, so the agent enters the orchestrator already primed.

An audit-grep harness check guards against future regressions: every `Use Skill cowork:` reference in an orchestrator SKILL.md must be followed within 200 characters by a `READ .claude/skills/cowork/` path mention. Fail-closed on any naked reference.

A fourth option (inlining the full self-check checklist into every orchestrator body composition step) was considered and rejected: it trades file size for redundancy but doesn't fix the root cause — the agent can still skip the inlined section if it decides the orchestrator's intent is "write the file." Layer 2's verification step ("read back the file and check these markers") is harder to skip than a composition-time paragraph.

### `.smart-env/` layout reality (Workstream B context)

Two concrete on-disk facts that shaped the SC design:

1. **Layout is `.smart-env/multi/<sanitized-path>.ajson`**, NOT the flat `smart_sources.ajson` + `smart_blocks.ajson` that the community MCP servers (dan6684, msdanyg) assume. accuris has 3079 such files; ero has 501; headspace has none yet (plugin installed but never indexed); barebones has neither (and stays that way — regression target). Each `.ajson` is a single-line JSON-ish object: `"smart_sources:<path>": {"path":"...","last_embed":{...},"embeddings":{"TaylorAI/bge-micro-v2":{"vec":[...]}}}`.
2. **Path keys contain `{{module_directory}}` placeholders** — the index doesn't store raw vault-rooted paths. Any reader must substitute these against the consumer vault's blueprint module-directory registry.

Both facts argue strongly against depending on a community MCP server. We vendor a thin reader.

SC plugin version on indexed vaults: **4.3.0**. Embedding model: **TaylorAI/bge-micro-v2** (384-dim, local, no API/cost). `smart_env.json` config: `smart_sources.min_chars = 200`.

## Workstream A — Cowork skill-routing hardening

### Layer 1 — Orchestrator instruction rewrite

**Rewrite target.** Every `Use Skill cowork:<sub-skill>` reference inside an orchestrator SKILL.md (and inside `onboard-scheduled-jobs/SKILL.md`'s sub-skill references) gets rewritten to a `READ + apply` form. The exact replacement template depends on the sub-skill class:

**For write-run-note-* references (most rigorous):**
```
READ .claude/skills/cowork/skills/write-run-note-<orch>/SKILL.md in full —
paying particular attention to its ## Title composition, ## Adaptive body
skeleton, and ## Pre-write self-check sections — then apply those contracts
before performing the write described in its ## Steps section with
{ ...inputs... }.
```

**For gather-* / update-* / state sub-skill references (generic):**
```
READ .claude/skills/cowork/skills/<sub-skill>/SKILL.md in full and follow
its ## Steps section with { ...inputs... }.
```

**For check-vault-routing / date-context / ensure-daily-note (lightweight preflight):**
Same generic READ form; these have no body-shape contract but the discipline of explicitly loading the sub-skill removes the multi-context ambiguity.

**Affected file count (approximate, to be confirmed in S1):**
- `morning-briefing/SKILL.md` — ~15 references
- `midday-tripwire/SKILL.md` — ~10 references
- `eod-review/SKILL.md` — ~12 references
- `weekly-review/SKILL.md` — ~14 references
- `monthly-review/SKILL.md` — ~14 references
- `onboard-scheduled-jobs/SKILL.md` — ~4 references
- **Total: ~69 mechanical rewrites** across 6 files (authoritative count comes from S0's grep audit).

The Layer 1 commit is a single bulk pass: all 6 files in one S-stage. Mechanical pattern; no behavior change at runtime in registered-skill sessions; significant behavior change in non-registered-skill sessions (the agent now has unambiguous instructions).

### Layer 2 — Post-write structural verification step

Each of the 5 orchestrators that writes an atomic note (`morning-briefing`, `midday-tripwire`, `eod-review`, `weekly-review`, `monthly-review`) grows a new verification step immediately after the existing `write-run-note-*` call.

The verification step's contract is spelled out inline in each orchestrator SKILL.md (no new sub-skill — sub-skills are exactly the loading mechanism we don't trust here). Pattern:

```
After cowork:write-run-note-<orch> returns status, if status starts with
"failed:" exit per the v0.74.0 contract handler. Otherwise:

1. Re-read the written file via the Read tool at <atomic_note_path>.
2. Capture frontmatter as parsed_frontmatter (YAML between leading ---
   markers); capture body as the remainder.
3. Assert required frontmatter fields exist and are non-empty:
   - title:
   - summary:
   - type:
   - (cadence-specific) warning: when the orchestrator passed warning;
     severity: for midday-tripwire only.
4. Regex-scan body for required structural markers:
   - SpaceNavButtons dataviewjs block (anywhere in body)
   - At least one "> [!info]- " callout (Synopsis)
   - At least one "> [!example]+ " callout
   - "> [!tip] " callout (closing)
   - For midday-tripwire only: "> [!warning] " or "> [!example]+ 🚨"
5. On ANY frontmatter-field miss or marker miss:
   a. Delete the file via Bash: rm -f <atomic_note_path>
   b. Emit Obsidian Notice "cowork:<orch> aborted -- contract-violation: <field>"
      (where <field> is the missing field name or marker name)
   c. Return non-zero exit; do NOT run state-update steps.
6. On all-pass: continue to State step per current v0.74.0 flow.
```

The 5 orchestrator SKILL.md files each grow this ~15-line block, slotted between the existing write step and the existing State step. The deletion-on-miss is aggressive but the user's explicit preference: a failed-contract file in the vault would be worse than no file at all (the next scheduled fire overwrites; absence is its own signal).

### Layer 3 — Enriched scheduled-tasks prompts

`cowork:onboard-scheduled-jobs/SKILL.md` Step 6 (Register tasks) currently composes:

```
prompt: Use skill cowork:<orch> with { engagement_id: "<engagement.id>" }
```

Step 6 changes to:

```
prompt: Use skill cowork:<orch> with { engagement_id: "<engagement.id>" }.
        When the orchestrator instructs you to use a sub-skill
        (cowork:write-run-note-*, cowork:gather-*, etc.), READ that
        sub-skill's SKILL.md from .claude/skills/cowork/skills/<name>/ and
        strictly follow its sections including any "## Pre-write self-check"
        checklist before proceeding with the action described in
        "## Steps". Return failed:contract-violation:<field> on any miss.
```

This applies to BOTH the direct-mode (`mcp__scheduled-tasks__create` / `update`) and paste-mode (paste-ready block) branches in Step 6. The paste-mode block grows the same enriched body so the user-pasted prompt carries the discipline upstream.

For pre-v0.75.0 onboardings (the 20 existing entries across 4 vaults — see Appendix), the user runs the immediate-mitigation recipe before re-firing schedules. Going forward, all `cowork:onboard-scheduled-jobs` invocations register the enriched form.

### Audit harness check

A new HC-V0750-A1 case in `run-cowork-smoke.js`:

```
For each orchestrator SKILL.md AND onboard-scheduled-jobs SKILL.md:
  body = read the file as text
  for each match of /\bUse Skill cowork:[a-z\-]+\b/g in body:

    assert that ".claude/skills/cowork/" appears within that window

```


The harness is a fail-closed audit; passing today means no naked references exist; passing on future cycles means new references continue to ship with READ companions.

## Workstream B — Smart Connections semantic retrieval

### Architecture overview

Three new pieces, three modified pieces.

**New:**
- `platform/mechanisms/smart-connections-bridge/sc-bridge.js` — Node CLI binary. Three ops: `index-status`, `semantic-search`, `find-related`. Reads `.smart-env/multi/*.ajson` directly. Substitutes `{{module_directory}}` placeholders against the consumer vault's module-directory registry. Vendors `TaylorAI/bge-micro-v2` via `@xenova/transformers`. Returns JSON on stdout. Cold-load cost: ~2–3s on accuris's 3079 files; acceptable for once-per-orchestrator use. No persistent cache in v0.1.0.
- `platform/mechanisms/smart-connections-bridge/manifest.json` — version `0.1.0`; `files[]` materializes `sc-bridge.js` into `.local/mechanisms/smart-connections-bridge/`.
- `platform/blueprints/cowork/skills/skills/gather-semantic-related/SKILL.md` — new cowork sub-skill. Calls `sc-bridge` via Bash. Renders the `> [!example]+ 🧩 Related context` callout. Returns markdown + structured `hits[]` + `index_age_minutes`. Gracefully skips when no index.
- `platform/test/run-smart-connections-bridge.js` — focused harness covering the bridge I/O contract.

**Modified (Workstream B's footprint inside cowork):**
- `morning-briefing`, `eod-review`, `weekly-review` SKILL.md files — each grows a Gather step calling `gather-semantic-related` + a Write-step instruction interpolating the related-context block + lag-age into the body. (These same files ALSO get Workstream A's Layer 1 + Layer 2 changes — separate commits, separate stages.)
- `write-run-note-morning-briefing`, `write-run-note-eod-review`, `write-run-note-weekly-review` SKILL.md files — `## Adaptive body skeleton` section grows the optional `> [!example]+ 🧩 Related context` callout entry.
- `platform/blueprints/cowork/manifest.json` — new skills[] entry; 0.13.0 → 0.14.0.
- Engagement-type manifests (personal/w2-fte/consulting) — additive `render_aspects.semantic_related: "include"`; 0.2.0 → 0.3.0.

### Approaches considered and rejected for Workstream B

- **Depend on a community MCP server** (dan6684 / msdanyg). Rejected: community servers assume the older flat-file layout, but SC 4.3.0 on these vaults uses `multi/<sanitized>.ajson` per-source with `{{module_directory}}` placeholders. Pinning to undocumented community-server-version semantics is fragile.
- **MCP server vendored as the primary interface.** Rejected for v0.75.0 in favor of a Node CLI. Adds a long-running process + per-vault config registration. The workshop already ships native Node scripts; CLI is idiomatic. MCP wrapper can be added in a later cycle without changing the CLI surface.
- **Inline SC ops inside the cowork blueprint with no new mechanism.** Rejected: catalogue-entry tax is small; semantic retrieval is generic enough that future blueprints (project, daily, journal) plausibly want it. Mechanism harness gives isolation-level testing.

### Bridge CLI surface

#### `sc-bridge index-status --vault <root>`

```json
{
  "index_status": "ready" | "absent" | "stale-config",
  "vault_root": "/abs/path",
  "smart_env_dir": "/abs/path/.smart-env",
  "embedding_model": "TaylorAI/bge-micro-v2",
  "source_count": 3079,
  "index_max_mtime_iso": "2026-05-22T18:10:00Z",
  "index_age_minutes": 192
}
```

- `ready` — `.smart-env/multi/` exists with ≥1 parseable `.ajson` AND `smart_env.json` is readable.
- `absent` — `.smart-env/` doesn't exist OR `multi/` is empty.
- `stale-config` — `smart_env.json` declares an embedding model whose vectors aren't present in sampled `.ajson` (defensive; covers model swaps).

#### `sc-bridge semantic-search "<query>" --vault <root> [--top-k 3] [--min-similarity 0.45] [--exclude-glob "<pattern>"]`

Embeds `<query>` via `TaylorAI/bge-micro-v2`. Computes cosine sim against every source vector. Returns:

```json
{
  "index_status": "ready",
  "index_age_minutes": 192,
  "query": "<query>",
  "hits": [
    { "path": "spice/projects/.../README.md", "title": "<title>", "similarity": 0.6814, "snippet": "..." }
  ]
}
```

`path` is the substituted vault-relative path (`{{module_directory}}` resolved). `snippet` is the first ~200 chars of the source file (Read on disk).

#### `sc-bridge find-related "<vault-rel-path>" --vault <root> [--top-k 3] [--min-similarity 0.45] [--exclude-glob "<pattern>"]`

Loads the anchor file's embedding from `multi/<sanitized>.ajson`. If absent, returns `{ hits: [], skipped: "anchor-not-indexed" }`. Otherwise: cosine against all others, dedupe self, return top-K above `--min-similarity`.

#### Common flags (apply to every op)

- `--vault <root>` — required.
- `--quiet` — suppress stderr progress logs (used when bridge is invoked from inside a Skill via Bash).
- `--json` — reserved for future toggling; stdout is JSON regardless.

#### Exit codes

- `0` — success (including `index_status: "absent"` — normal return).
- `2` — invalid arguments.
- `3` — vault inaccessible.
- `4` — index parse error (zero files parseable). Returns `{ index_status: "error", error: "...", offending_path: "..." }`.

Single corrupt `.ajson` files are skipped with a stderr warning; only **zero** parseable files triggers exit 4.

#### `{{module_directory}}` substitution

SC stores source paths with a `{{module_directory}}` placeholder (e.g., `{{module_directory}}/cards/2026/05-May/cowork.md`). The bridge resolves these placeholders against the consumer vault's blueprint module-directory registry. The canonical source of that map is **TBD-verify-in-S5** — most likely `ranch/platform-installed.json`'s `blueprints[]` array (where each entry already carries the blueprint id and the module-directory invariant), but the exact field name needs S5 confirmation. If the map isn't present in the form sc-bridge needs, S5 either ships it via the mechanism's install step or derives it at bridge runtime from `platform/blueprints/*/manifest.json` `module_directory` fields read from `workshop_path`.

#### Performance posture (v0.1.0)

Cold-load all `.ajson` files per invocation. ~2–3s on accuris (3079 sources). No batching, caching, or persistent indexing. If aggregate latency in morning-briefing (potentially 5 calls per fire) proves painful in dogfood, v0.75.x adds `--batch` (JSON-on-stdin) + `.local/cache/sc-bridge-index.bin`.

#### Dependencies

- `@xenova/transformers` for the embedding model.
- No filesystem-write side effects from the bridge.

### `cowork:gather-semantic-related` sub-skill

#### Inputs

```
{
  mode: "find-related" | "semantic-search",
  anchor: string,            // required when mode == "find-related"
  query: string,             // required when mode == "semantic-search"
  top_k: int,                // optional, default 3
  min_similarity: float,     // optional, default 0.45
  exclude_globs: list[str],  // optional default ["spice/cowork/daily/**", "spice/cowork/weekly/**", "spice/cowork/monthly/**", ".obsidian/**", ".smart-env/**"]
  callout_title: string      // optional, default "Related context"
}
```

#### Output

```
{
  status: "ready" | "skipped:no-index" | "skipped:anchor-not-indexed" | "skipped:no-hits-above-floor",
  index_age_minutes: int | null,
  markdown: string,
  hits: [ { path, title, similarity, snippet } ]
}
```

#### Steps

1. **Probe.** `sc-bridge index-status --vault $(pwd) --quiet`. Parse stdout JSON. Capture `index_status`, `index_age_minutes`.
   - `absent` or `error` → return `{ status: "skipped:no-index", markdown: "", hits: [] }`.
   - `ready` or `stale-config` → continue.
2. **Query.** Compose appropriate `sc-bridge` call from `mode`. Capture JSON output.
3. **Branch on hits.**
   - Bridge returned `skipped: "anchor-not-indexed"` → return `{ status: "skipped:anchor-not-indexed", markdown: "", hits: [], index_age_minutes }`.
   - `hits.length == 0` → return `{ status: "skipped:no-hits-above-floor", markdown: "", hits: [], index_age_minutes }`.
   - Else continue.
4. **Render markdown.**
   ```
   > [!example]+ 🧩 <callout_title>
   > - [[<title>]] — <snippet truncated to 80 chars> (sim <similarity:.2f>)
   > - ...
   ```
5. **Return.** `{ status: "ready", index_age_minutes, markdown, hits }`.

#### Orchestrator integration contract

- Sub-skill called once per anchor (morning per-event) / once total (eod) / once per week-day with aggregation in orchestrator (weekly).
- Orchestrator always interpolates `> Semantic index age: <N>m` inside the existing `> [!info]- Synopsis` callout, derived from `index_age_minutes`.
- When status starts with `skipped:no-index` or `skipped:anchor-not-indexed`, orchestrator appends a one-line `> [!warning]- Semantic index not available` callout near the synopsis. Only once even if multiple per-event calls skipped. No warning for `skipped:no-hits-above-floor`.
- The new Related-context callout slots into the v0.74.0 adaptive body skeleton's optional-example-block region; pre-write self-check passes unchanged.
- All Workstream B references to this sub-skill in orchestrator SKILL.md files use the Workstream A Layer 1 READ-companion form (no naked `Use Skill cowork:gather-semantic-related`).

## Workstream C — Engagement-types path-resolution fix (S6 carry-forward)

### Bug

Today's `onboard-scheduled-jobs/SKILL.md` Step 2 (line 66) reads:

> Load the engagement-type manifest from the registry at `spice/cowork/engagement-types/<engagement.type>.json` (consumer override) or `platform/blueprints/cowork/engagement-types/<engagement.type>.json` (workshop fallback — but in-vault context can only reach the consumer path; check-vault-routing already validated).

False premise: cowork's `manifest.json` `files[]` block does not ship `engagement-types/*.json` into consumer vaults. Confirmed: neither accuris nor ero has `spice/cowork/engagement-types/`. The fallback to workshop path is what's actually needed but the current SKILL doesn't exercise it correctly.

### Fix

Mirror `bootstrap-vault` step 8 / line 74's pattern. Rewrite Step 2's manifest-load block to:

```
After capturing `engagement`, resolve the engagement-type manifest:

1. Read ranch/platform-installed.json via Read tool; capture workshop_path
   (absolute path to the brew-installed workshop).
2. Compose workshop_manifest_path = workshop_path +
   "/platform/blueprints/cowork/engagement-types/" + engagement.type + ".json".
3. Read workshop_manifest_path via Read tool; parse JSON. Capture as
   type_manifest_workshop.
4. Check for consumer override at spice/cowork/engagement-types/<engagement.type>.json
   via Bash test -f. If present, Read and parse; capture as type_manifest_consumer.
   Else type_manifest_consumer = null.
```

### Failure modes

- Workshop manifest file missing → hard error.
- Consumer override malformed → soft warning, fall back to workshop-only.

### Scope

Does NOT ship `engagement-types/*.json` into consumer vaults. Does NOT change `check-vault-routing`. Does NOT touch `bootstrap-vault`.

## Workstream D — `sauce update --bump-pins` (FLN-v67-7 carry-forward)

### Behavior

`sauce update --bump-pins` reads the brew-installed workshop's `platform/manifest.json`, then rewrites the consumer vault's `ranch/platform-subscription.json`:

- Top-level `workshop_version` bumps.
- Each entry in `pinned.mechanisms[]` bumps to workshop manifest's mechanism version.
- Each entry in `pinned.blueprints[]` bumps to workshop manifest's blueprint version.
- New-in-workshop items NOT in consumer's `pinned[]` → left alone (opt-in preserved).
- Removed-from-workshop items still in `pinned[]` → warning, pin left alone.

After rewrite, normal `sauce update` runs.

### CLI surface

```
sauce update [--bump-pins] [--dry-run] [--keep-comparators]
```

### Edge cases

- Workshop manifest not parseable → exit non-zero, subscription untouched.
- `--bump-pins` outside a consumer vault → hard error.
- Empty diff → no-op message, continue to update.

### Files touched

`scripts/sauce-update.js` (or wherever `sauce update` dispatches), `commands/install.md`, `Docs/agent-guides/build-test-verify.md`.

## Appendix — Scheduled-tasks MCP prompt-edit recipe (immediate mitigation for Layer 3)

Twenty existing scheduled-tasks MCP entries across the four consumer vaults need their prompt text replaced with the Layer 3 enriched form. This is a manual user-side task to run **after `brew upgrade sauce`** picks up v0.75.0 but **before the next cron fire** that would have used the old prompt.

### Per-vault audit (run from inside Obsidian via Claude Code session in the consumer vault)

```
mcp__scheduled-tasks__list { }
```

Filter the returned list for tasks whose name matches `cowork-<orch>-<engagement>`. Expected count per vault:

- **accuris-sauce** (w2-fte): 5 tasks — morning / midday / eod / weekly / monthly
- **ero-sauce** (consulting): 5 tasks
- **headspace-sauce** (personal): 5 tasks
- **barebones**: 0 or up to 5 depending on whether cowork is onboarded there yet (verify; this vault is the regression target so may be untouched)

### Replacement prompt template

For each task with id `<task_id>`, orchestrator `<orch>`, engagement `<engagement.id>`:

```
mcp__scheduled-tasks__update {
  task_id: "<task_id>",
  prompt: "Use skill cowork:<orch> with { engagement_id: \"<engagement.id>\" }. When the orchestrator instructs you to use a sub-skill (cowork:write-run-note-*, cowork:gather-*, etc.), READ that sub-skill's SKILL.md from .claude/skills/cowork/skills/<name>/ and strictly follow its sections including any \"## Pre-write self-check\" checklist before proceeding with the action described in \"## Steps\". Return failed:contract-violation:<field> on any miss."
}
```

### Per-vault checklist

For each of the 4 vaults:

- [ ] Run `mcp__scheduled-tasks__list { }` and record the list of `cowork-*` task IDs.
- [ ] For each task ID, run the `update` call above with the matched orchestrator/engagement.
- [ ] Verify by re-running `list { }` and inspecting each task's prompt text contains the "READ that sub-skill's SKILL.md" substring.
- [ ] Tick the per-vault box: [accuris] [ero] [headspace] [barebones]

### Going forward

Once v0.75.0 is deployed and the immediate-mitigation recipe is run, **future `cowork:onboard-scheduled-jobs` invocations register the enriched form by default** (Step 6 ships the new prompt template). The recipe applies only to the existing 20 entries. New entries don't need it.

### Failure mode if skipped

If the recipe is not run, the existing 20 entries continue to fire with the old `Use skill cowork:<orch> with { engagement_id: "<id>" }` prompt. In sessions where vault-side skills aren't registered, the v0.74.0 body-shape contract still won't fire — Layer 2's post-write verification step (shipped as part of v0.75.0's S2) will catch the violation and delete the non-compliant file. The recipe is "preferred" rather than "required" because Layer 2 is the durable backstop; the recipe is the friction-reducer that prevents files from being written and immediately deleted.
