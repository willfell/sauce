# v0.104.0 — search & filter for the section-hub model

## TL;DR

The original v0.102.0 ask had three items — sections, meetings link, **search**. Search was deferred to v0.102.1; the v0.103.0 reframe into hierarchical section hubs changed the search shape. This cycle closes the search ask against the new model. One new `DocSearch` CustomJS helper is consumed by both `ProjectDocsIndex` (Docs.md, cross-section scope) and `SectionHub` (within-section scope). The helper renders a text filter input + dynamic tag chips + a scoped-Obsidian-search button. Filtering is in-memory, real-time, AND-logic across text + selected tags. Empty filter = show everything (no behavior change). No schema changes; pure UX layer.

## Decisions (locked at brainstorm)

| Question | Decision |
| --- | --- |
| Where does search live? | Docs.md (project-wide cross-section recursive scope) + Section Hub depth 1 (within-section scope, includes sub-section docs) + Sub-Section Hub depth 2 (within-sub-section scope only) |
| Single helper or three? | ONE `DocSearch` helper accepting `{ projectSlug, scopePath, recursive }` — scope is determined by the host hub note |
| What does the filter match against? | (1) `file.name`, (2) `frontmatter.tags`, (3) first 200 chars of `file.content`. Substring-fuzzy. Combined via AND with active tag chips |
| Tag chips source | Dynamic — scan all docs in scope, surface the 8 most-used tags. Click chip = AND filter on that tag |
| Filter UI layout | Input box on first line; tag chips wrap below; status pill ("filtering: X of Y") above section/doc cards when active |
| Scoped-Obsidian-search button | Inline button next to filter input. Clicking opens Obsidian's global search pre-filled with `path:"spice/projects/<slug>/docs"` (or the section-scoped path). The escape hatch for full-body fuzzy search |
| Empty-filter behavior | Identical to v0.103.0 — sections + docs render as today |
| Active-filter behavior on Docs.md | Section CARDS still render, but each card's doc count = filtered count; per-section doc list (if expanded) is filtered. NO section is hidden — user can always see all sections |
| Active-filter behavior on Section Hub | Docs list narrows to matches. Sub-section cards (depth 1) stay visible but their counts reflect filtered docs |
| Persistent filter state | NO. Filter is per-render. Fresh re-open = empty filter. Keeps UX predictable; reduces vault config surface area |
| Frontmatter changes | NONE. Search reads existing `file.name` / `tags` / `content`. No schema migration |
| Migration | NONE needed (pure additive UI). v0.104.0 install only ships the new helper + extends existing helpers to invoke it |

## Section 1 — Concept overview

**One new helper, two integration points.**

`DocSearch` (~150 LOC) — renders a filter UI strip at the top of any docs view. Returns a `filterContext` object that downstream renderers consume:
```js
{ text: string, tags: string[], hasActiveFilter: boolean }
```

`ProjectDocsIndex` (extended) — accepts an optional pre-rendered `filterContext`; if present, narrows section card counts + per-section doc lists.

`SectionHub` (extended) — same. Within-section scope.

**Filter UI** sits between the nav buttons and the content:
```
Breadcrumb
[SpaceNavButtons] [ProjectNavButtons]
---
🔎 [search input.....................]  [tag] [tag] [tag] [#refresh] [🔎 native]
status pill: "Filtering: 'ingress' + #spec — 3 of 31 docs"   (only when active)
---
<sections / docs as today>
```

## Section 2 — `DocSearch` helper

Lives at `platform/blueprints/project/helpers/doc-search.js`.

```javascript
class DocSearch {
  /**
   * Renders the filter UI + returns a filterContext consumable by ProjectDocsIndex / SectionHub.
   *
   * @param dv  Dataview
   * @param opts {
   *   projectSlug: string,        // for scoped-search button
   *   scopePath: string,          // e.g. "spice/projects/global-k8s/docs" or ".../knowledge"
   *   recursive: boolean,         // true for Docs.md; false for Section Hub leaf
   *   onChange: (ctx) => void     // re-render callback
   * }
   * @returns initial filterContext { text: "", tags: [], hasActiveFilter: false }
   */
  render(dv, opts) {
    const allDocs = dv.pages(`"${opts.scopePath}"`).where(p => p.type === "doc-note");
    const tagCounts = this._countTags(allDocs);
    const topTags = Object.entries(tagCounts).sort((a, b) => b[1] - a[1]).slice(0, 8).map(e => e[0]);

    const container = dv.el("div", "", { cls: "doc-search-strip" });
    container.style.cssText = "display: flex; flex-direction: column; gap: 6px; margin: 8px 0;";

    const ctx = { text: "", tags: new Set(), hasActiveFilter: false };

    // Row 1: input + scoped-search button
    const row1 = container.createEl("div");
    row1.style.cssText = "display: flex; gap: 8px; align-items: center;";
    const input = row1.createEl("input", { attr: { type: "text", placeholder: "Filter docs by title, tags, or content…" } });
    input.style.cssText = "flex: 1; padding: 6px 10px; border-radius: 6px; border: 1px solid var(--background-modifier-border); background: var(--background-secondary); color: var(--text-normal);";

    const nativeBtn = row1.createEl("button", { text: "🔎 Search" });
    nativeBtn.style.cssText = "padding: 6px 12px; border-radius: 6px; cursor: pointer; border: 1px solid var(--interactive-accent); background: transparent; color: var(--interactive-accent); font-size: 0.85em;";
    nativeBtn.title = "Open Obsidian native search scoped to this folder";
    nativeBtn.addEventListener("click", () => {
      const query = `path:"${opts.scopePath}" `;
      app.commands.executeCommandById("global-search:open");
      setTimeout(() => {
        const searchInput = document.querySelector(".workspace-leaf-content[data-type='search'] input[type='search']");
        if (searchInput) { searchInput.value = query; searchInput.dispatchEvent(new Event("input")); }
      }, 100);
    });

    // Row 2: tag chips
    let chipsRow = null;
    if (topTags.length > 0) {
      chipsRow = container.createEl("div");
      chipsRow.style.cssText = "display: flex; flex-wrap: wrap; gap: 4px;";
      for (const tag of topTags) {
        const chip = chipsRow.createEl("span", { text: `#${tag}` });
        chip.style.cssText = "padding: 2px 8px; border-radius: 10px; background: var(--background-modifier-active-hover); color: var(--text-muted); font-size: 0.78em; cursor: pointer; user-select: none;";
        chip.addEventListener("click", () => {
          if (ctx.tags.has(tag)) {
            ctx.tags.delete(tag);
            chip.style.background = "var(--background-modifier-active-hover)";
            chip.style.color = "var(--text-muted)";
          } else {
            ctx.tags.add(tag);
            chip.style.background = "var(--interactive-accent)";
            chip.style.color = "var(--text-on-accent)";
          }
          this._updateActive(ctx);
          opts.onChange?.(ctx);
        });
      }
    }

    // Row 3: status pill (only when active)
    const statusRow = container.createEl("div");
    statusRow.style.cssText = "font-size: 0.78em; color: var(--text-muted); min-height: 1em;";

    input.addEventListener("input", () => {
      ctx.text = input.value.trim();
      this._updateActive(ctx);
      const totalDocCount = allDocs.length;
      if (ctx.hasActiveFilter) {
        statusRow.textContent = `Filtering: "${ctx.text}"${ctx.tags.size > 0 ? " + " + Array.from(ctx.tags).map(t => `#${t}`).join(" ") : ""}`;
      } else {
        statusRow.textContent = "";
      }
      opts.onChange?.(ctx);
    });

    return ctx;
  }

  _countTags(pages) {
    const counts = {};
    for (const p of pages) {
      const tags = Array.isArray(p.tags) ? p.tags : (p.file?.tags || []);
      for (const t of tags) {
        const clean = String(t).replace(/^#/, "");
        if (!clean || clean === "doc-note") continue;
        counts[clean] = (counts[clean] || 0) + 1;
      }
    }
    return counts;
  }

  _updateActive(ctx) {
    ctx.hasActiveFilter = ctx.text.length > 0 || ctx.tags.size > 0;
  }

  /**
   * Pure-function matcher used by consumers. Given a doc page + filterContext, returns true if doc matches.
   */
  static matches(page, ctx) {
    if (!ctx || !ctx.hasActiveFilter) return true;
    if (ctx.text) {
      const needle = ctx.text.toLowerCase();
      const name = (page.file?.name || "").toLowerCase();
      const tagList = (Array.isArray(page.tags) ? page.tags : (page.file?.tags || [])).map(t => String(t).toLowerCase());
      const tagText = tagList.join(" ");
      if (!name.includes(needle) && !tagText.includes(needle)) return false;
    }
    if (ctx.tags && ctx.tags.size > 0) {
      const tagList = (Array.isArray(page.tags) ? page.tags : (page.file?.tags || [])).map(t => String(t).replace(/^#/, ""));
      for (const required of ctx.tags) {
        if (!tagList.includes(required)) return false;
      }
    }
    return true;
  }
}
```

## Section 3 — Integration with existing helpers

**`ProjectDocsIndex` extended:**
- At the top, before rendering sections, call `customJS.DocSearch.render(dv, { projectSlug, scopePath: "spice/projects/<slug>/docs", recursive: true, onChange: (ctx) => this._rerender(ctx) })`.
- Maintain a `currentCtx` on the instance for re-renders.
- Section card meta = doc count filtered by `DocSearch.matches(p, ctx)`.
- `_rerender(ctx)` clears the dv container's child nodes from the section cards onward, then re-renders sections with the new ctx. (Or simpler: full re-render via `dv.container.empty()` + recursive `render(dv)` call with a fresh `currentCtx`.)

**`SectionHub` extended:**
- Same pattern. `scopePath` = the section's folder (`docs/<section_slug>` for depth 1; `docs/<parent_slug>/<section_slug>` for depth 2).
- `recursive: true` for depth 1 (includes sub-section docs in the search scope); `recursive: false` for depth 2.

**Re-render strategy:** simplest path is full re-render of the container on every keystroke. Performance is fine for <500 docs in any single project (typical accuris case). For very large projects, debounce input by 100ms.

## Section 7 — Out of scope

- Persistent filter state across sessions (deferred — keep UX predictable for v0.104.0).
- Full-text body search beyond first 200 chars (use the scoped-search button for that).
- Saved searches / pinned filters.
- Filter result export.
- Cross-project search (each project's hubs are scoped to themselves).
- Dashboard widget expansion (kanban heatmap, status timeline) — separate v0.104.x patches.
- Tag autocomplete on the input (just chip selection or typing a tag in the input box works).

## Section 8 — Risks + mitigations

| Risk | Mitigation |
| --- | --- |
| Re-render on every keystroke might lag on large projects. | Debounce input by 100ms. accuris global-k8s has 31 docs — well below any performance concern. |
| Tag chips noise — too many irrelevant low-count tags. | Top-8 cap. Excludes the universal `doc-note` tag (which every doc has) from the chips. |
| Native search button might fail if Obsidian's command API surface changes. | Fall back: if `executeCommandById` fails, render a notice + log. Don't break the rest of the UI. |
| User filters Docs.md, switches to a section hub — filter state is lost. | Acceptable per "no persistent state" decision; the user can re-filter in the section hub. |
| `frontmatter.tags` may be stored as Dataview Link arrays or string arrays. | `_countTags` and `matches` both normalize via `String(t).replace(/^#/, "")`. |
