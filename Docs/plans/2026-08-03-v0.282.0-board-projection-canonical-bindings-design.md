# Board-projection canonical bindings — design

**Cycle:** v0.282.0 · **Date:** 2026-08-03 · **Components:** intake + coordinator

## Problem

The `ero-egnyte-mcp` parent board froze. Actively-worked epics sat in **In
Planning** while their slices were `implementing`/`parked` in the ledger; one
epic showed **In Progress** with no active claim. The coordinator kept advancing
phases in `.git/sauce-autoloop/state.json`, but every projection onto the
Obsidian board notes threw and was swallowed into the record's
`projection_error`. Machine state and human-visible state diverged silently —
the worst possible failure shape for a board whose entire job is to be the
Director's view.

## Root cause (systematic-debugging Phase 1)

Two independent modes, both reproduced before any fix.

### Mode 1 — mints are born un-projectable (LIVE, not just legacy data)

The projection contract (`codex-coordinator.js` `canonicalEpicProjection` →
`canonicalWorkspacePath`) requires **vault-relative** paths rooted at
`physicalProjectPrefix(cardsRoot)` — the prefix found by locating
`/spice/projects/` on disk.

`card-intake.js` derived that prefix from **caller input** instead:

```js
function projectPrefix(spec) {
  const source = normalizePath(spec.source_board || '');
  return source && !path.isAbsolute(source) ? path.posix.dirname(source) : '';
}
```

`plugins/loop/skills/intake/SKILL.md` instructs the planner to pass
`board_path = config.board_path_abs` (**absolute**) and no `source_board` at
all. So the prefix collapsed to `''`, and three separate outputs went wrong at
once:

| Surface | Written | Contract wants |
| --- | --- | --- |
| atlas `source_board` / `kanban_board` | the absolute `spec.board_path`, verbatim | `<prefix>/<board>.md` |
| atlas `epic_board` | `tasks/<E>/board/<E>-board.md` | `<prefix>/tasks/…` |
| slice `task_parent` / `source_board` / `kanban_board` | `tasks/<E>/…` | `<prefix>/tasks/…` |

Every projection then threw `epic atlas <E> does not bind its canonical parent
board`.

**Verified live, not assumed.** A reproduction minted a fresh epic through the
real intake rail into a canonical `<vault>/spice/projects/<slug>/` shape using
exactly the skill's arguments, then ran the real `canonicalEpicProjection`
against the result. Output: absolute `source_board`, project-relative
`epic_board`/`task_parent`, and `PROJECTION THREW`. The current mint chain — not
only historical data — produces un-projectable epics.

### Mode 2 — discard orphans its own sub-board line

`discardCardCore` chose its board target from a **successful** projection only:

```js
const targetBoardPath = epicSurface ? epicSurface.boardPath : boardPath;
```

`canonicalEpicProjection` is wrapped in `try/catch → epicSurfaceError`, so any
refusal (including a Mode-1 atlas) left `epicSurface = null` and the discard
fell back to the **parent** board. The parent board never carries slice lines,
so `removeBoardCard` removed nothing — and the note was unlinked anyway. The
surviving sub-board line then made `canonicalEpicMembers` /
`deriveEpicProjection` throw `epic slice <X> note is missing` for **every**
sibling, permanently.

This is the cascade: a Mode-1 failure manufactures Mode-2 orphans, and each
orphan poisons the epic independently of the original cause.

### Live confirmation

A read-only sweep ran the real contract against all 63 epics of the live board:

- `Build Observability and Metrics`, `Config Truth and Guarded Deploys` — Mode 1
  (absolute atlas `source_board`).
- `Toolset Value and Answer Quality` — 3 slices with project-relative `task_parent`.
- `Build Observability and Metrics` — 2 orphaned sub-board lines (`BO-1`,
  `BO-1a`), both superseded predecessors, exactly as the cascade predicts.

A cross-vault scan found the same rot beyond the reported board:
`ero-sauce/planner-agent-integration` and **`headspace-sauce/spice/projects/sauce`**
(the sauce project's own board). That is what made a reusable heal the right
shape rather than a one-off script.

## Approach

Three pieces, each independently TDD'd.

1. **Intake derives, never trusts.** `physicalProjectPrefix(cardsRoot)` mirrors
   the coordinator's function of the same name — the authority the contract
   checks against — so what a mint writes and what projection demands cannot
   drift. It returns `''` (rather than throwing) for a root outside
   `spice/projects`, and `projectPrefix` falls back to the old caller-derived
   behavior there, keeping the deliberately non-canonical test fixtures green.
   `parentBoardRef(spec)` supplies the canonical parent-board reference to both
   the atlas and slice renderers.

2. **Discard resolves its board physically.** `owningEpicBoardPath(cardPath,
   cardsRoot)` derives the owning sub-board from the note's own directory: a
   canonical slice lives flat beside its epic board, so the board is knowable
   without the projection contract. Guarded the same way as every other discard
   unlink (regular non-symlink file, physical descendant of `cardsRoot`,
   `board_role: epic`). A failed epic surface can no longer manufacture an
   orphan.

3. **`heal-epic-bindings` — reusable repair.** `--dry-run` reports, `--apply`
   repairs: drifted atlas/slice binding fields rewritten to the canonical form
   computed from `physicalProjectPrefix`, and sub-board lines whose slice note is
   gone pruned. Touches only those fields and lines — never bodies, ledger state,
   worktrees, or lane placement.

### Why no spec handshake

`reconcile-metadata --parked-rebind` requires a content-addressed spec because it
rebinds **ledger** state over a finite named card set from operator-supplied
operands. `heal-epic-bindings` derives its entire target state from the on-disk
canonical form, so recomputing at apply time is exactly as safe as replaying a
recorded intent, and the verb is idempotent by construction — replay is a no-op.
Adding a handshake would buy nothing and add a failure mode.

## Alternatives rejected

- **Loosen the projection contract to accept absolute paths.** The contract is
  the thing keeping a same-titled note elsewhere from satisfying a board line.
  Weakening it to match a broken writer inverts the dependency.
- **Fix only the data.** The reproduction proved the mint chain is live-broken;
  a data-only fix regenerates the same rot on the next mint.
- **Prune orphans in `reap` only.** `reap`'s residue removal is ledger-driven
  (`record.phase === 'discarded'`), and the coordinator ledger is local per
  clone — orphans created by another clone are invisible to it. The heal reads
  the boards themselves.

## Out of scope (carry-forward)

`platform/test/run-sticky-notes-render-guards.js` is **flaky on `main`** (3 of 6
runs on an unmodified base tree failed with `PERF-7-HARNESS: asynchronous
fixtures did not finish`). Unrelated to this cycle and deliberately not folded
in, but it sits inside the release gate and can wedge `prepare-release`.
