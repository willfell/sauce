# v0.84.0 cowork-memory-layer — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to execute this plan stage-by-stage. Each stage = one implementer dispatch + one spec compliance review + one code quality review. **DO NOT pause for user approval between stages** — this cycle is authorized for autonomous overnight execution. The ONLY hard stop is the USER APPROVAL GATE at the very end (post-S8, before tag + deploy).

**Goal:** Ship Tier 0 (hourly tick) + Tier 1 (daily synthesis) of the cowork continuous-memory architecture, with morning-briefing wired through to consume yesterday's synthesis + overnight ticks as enriched context.

**Architecture:** Add 2 new orchestrators (`cowork:capture-tick` hourly, `cowork:synthesize-day` EOD) + extend `morning-briefing` with a new pre-flight step 3a reading recent memory. Memory lives at `spice/cowork/memory/<engagement>/YYYY/MM-MMMM/YYYY-MM-DD/memory.md` (single file per engagement per day; ticks appended hourly during waking hours; synthesis section replaced at EOD). Engagement-types JSONs extended with `tick` + `synthesize_day` cadences (default true on all 3 engagement types). Memory notes discoverable via cowork hub + activity-feed Recent Activity sections.

**Tech Stack:** Existing cowork blueprint structure (orchestrator SKILL.md template; canonical types + rule_fragments; claude_surface[] materialization; static-validator harness in `run-cowork-smoke.js`).

**Design reference:** `Docs/plans/2026-06-01-v0.84.0-cowork-memory-layer-design.md` (commit `3569179`).

**Cycle conventions (NON-NEGOTIABLE):**

- Direct-push to `origin/main`. NO worktree, NO feature branch, NO PR.
- One commit per stage. Conventional-commits format. **NO `Co-Authored-By` trailer.**
- Use explicit `git add <paths>` per stage. **NEVER `git add -A`** (per landmine + v0.23.0 lesson g).

### Task S2.1: Create `platform/blueprints/cowork/skills/orchestrators/capture-tick/SKILL.md`

Use the existing `morning-briefing/SKILL.md` as the template precedent for structure. The new orchestrator's SKILL.md follows the same section layout. Required content:

**Frontmatter:**

```yaml
---
name: cowork:capture-tick
description: Hourly tick — captures lean deltas across the engagement's MCP kinds (calendar/email/chat/finance/projects/threads per prefs.priorities) within a tight 1-hour window. Appends a collapsed [!example]- callout to spice/cowork/memory/<engagement_id>/YYYY/MM-MMMM/YYYY-MM-DD/memory.md (creating the file on the first tick of the day). Background memory layer — does NOT write to spice/cowork/daily/, does NOT touch the daily note. Reused by cowork:morning-briefing and cowork:synthesize-day downstream as continuity context. Phrasings = "capture this hour", "tick", "memory dump", "log this hour for engagement".
schedule: Cron-driven hourly during waking hours (default 7am-10pm; 16 ticks/day per engagement)
scope: shared
tags: [cowork, orchestrator, tick, memory, background]
---
```

**Body sections** — write each using the morning-briefing/midday-tripwire structure as the template. Required content per section:

1. **`# cowork:capture-tick`** — H1 + 1-2 paragraph overview explaining the tick's role + write contract. Mention: single file per (engagement, day) at the canonical path; appends not overwrites; uses tight 1-hour range; background-only (no daily-note link).

2. **`## Inputs`** — `{ engagement_id: string }` block (same shape as midday-tripwire).

3. **`## Pre-flight`** — steps 1 (check-vault-routing), 2 (resolve engagement via vault-config + Read engagement-type manifest at `spice/cowork/context/engagement-types/<engagement.type>.json` per v0.83.0 canonical path), 3 (date-context), 3b (read-user-preferences), 3c (resolve `last_tick_at` — read today's memory.md if it exists; extract frontmatter `last_tick_at`; default to start-of-day if absent), 4 (NO ensure-daily-note — tick doesn't touch daily). The dispatch_mode + plan_dispatch logic matches midday-tripwire's step 3c verbatim BUT with `range.start = last_tick_at` (or start-of-day fallback) and `range.end = <now-ISO>`.

4. **`## Gather`** — loop over `dispatch_plan[]` from step 3c, invoke gathers with the tight range. Mirror midday-tripwire's gather phase except:
   - The range arg is `{ start: last_tick_at, end: now }` instead of today's full day.
   - `gather-from-served-by` receives the same tight range in its `range` input.
   - Canonical kinds (calendar, email, chat, etc.) use their existing gather-skills with the tight range argument.
   - DO NOT run the engagement-type-aspect gathers (semantic_related, finance) at tick cadence — too expensive per-hour. Those are eod-review's job.
   - Each kind's gather output is captured as `tick_blocks[kind_name] = { markdown, status }`. Kinds with status != "ready" produce `kind: "warning"` blocks (warning callout) for inclusion in tick body. Kinds whose gather returned empty markdown are EXCLUDED entirely (deltas-only).

5. **`## Decide`** — Compute `tick_summary` (≤140 chars one-liner — e.g. "1 new email; calendar quiet; threads stable"). Compose body for the tick callout.

6. **`## Write`** — Step N (compose), N+1 (Read-Or-Create today's memory.md):
   - Compose `tick_block_md` = a single collapsed `[!example]-` callout titled `HH:MM Tick` (where HH:MM is `<now>`'s hour + 00) containing the per-kind gather outputs as `**KindTitle:**` bold-prefix lines.
   - Compose `today_memory_path` per the canonical convention.
   - If the file does NOT exist: scaffold the full skeleton (frontmatter with `tick_count: 1`, `last_tick_at: <now>`, `synthesized: false`, `created_at: <now>`, `day: <today-YYYY-MM-DD>`, `engagement_id: <id>`, `type: cowork-memory`, `summary: <tick_summary>`); H1 title; `[!info]- Today's pattern (synthesis)` placeholder callout reading "Synthesis pending — will fire at <synthesize-day cron time>."; `[!tip] Carry-forward to tomorrow's morning-briefing` placeholder reading "Pending synthesis."; `## Ticks` section header; the new tick_block_md as the first entry.
   - If the file DOES exist: parse frontmatter; verify `day` matches today (else fall through to fresh-create — never write to a stale-day memory file); bump `tick_count` by 1; set `last_tick_at: <now>`; update `summary: <tick_summary>` (running summary, replaced by synthesize-day at EOD). Append the new tick_block_md to the `## Ticks` section (before EOF, after the last tick callout).
   - Use the existing v0.74.0 atomic-write-with-pre-write-self-check pattern. Pre-write self-check enumerates: frontmatter has type/engagement_id/day/created_at/last_tick_at/tick_count/summary; body has H1 + synthesis placeholder + carry-forward placeholder + `## Ticks` header + ≥1 tick callout. On any miss → `failed:contract-violation:<field>`.

7. **`## Verify`** — re-Read the just-written file; assert all frontmatter fields present; assert at least N tick callouts present (where N = the new tick_count); on miss, delete + Notice + exit non-zero per the v0.74.0 pattern.

8. **`## Done`** — Empty section (matches existing convention).

9. **`## Harness testing`** — Brief paragraph noting that S1 HC-V0840-A1..A3 sub-asserts validate the SKILL.md prose contract; runtime behavior is validated post-deploy via the consumer-side tick fire.
