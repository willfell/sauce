## What shipped (one-paragraph summary)

v0.77.0 replaces namespace-regex MCP detection (v0.76.0) with
tool-pattern signatures. Workstream B reworks `mcp-skill-map.json` to
schema v2.0.0 and adds the `detectCapabilities` helper that classifies
MCP namespaces by inspecting their tool NAMES (`list_events` +
`create_event` identifies a calendar capability regardless of namespace
string). The capability-subset model lets one MCP namespace satisfy
multiple kinds via tool-set membership — Outlook M365 (UUID namespace)
detected as calendar + email + chat from one namespace. Workstream C
ships fully-adaptive unknown-MCP handling: namespaces not matching any
known pattern surface in an interactive loop where the user classifies
as known-override or custom (with free-text `what_matters` round-tripped
through YAML literal-block form). Workstream D + E rename the v1
schema's `mcps.gmail` → `mcps.email` and `mcps.imessage` → `mcps.chat`
via the new `migrateV1ToV2` helper that applies declarative
`rename_from_v1` hints from the v2 schema on every load. Workstream F's
schema validation folded into S1/S2 — every load asserts
`schema_version == "2.0.0"` before classification proceeds. 11 new
harness cases (HC-V0770-A1..A3, B1..B2, C1..C4, D1, E1). v0.78.0 will
wire the 5-orchestrator consumption of `user-preferences.md` (originally
planned for v0.77.0; deferred to ensure the capture side was right
first).

Cowork 0.15.0 → 0.16.0. Workshop 0.76.0 → 0.77.0.
smart-connections-bridge unchanged at 0.1.1. Engagement-types unchanged
at 0.3.1.
