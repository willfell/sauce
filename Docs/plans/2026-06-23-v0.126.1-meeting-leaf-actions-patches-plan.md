## Task 2: Bug 2 + Bug 3 — Edit Attendees search filter + gated Add button

**Files:** `helpers/meeting-leaf-actions.js`.

**Steps:**
- [ ] In `_onEditAttendees`, refactor the initial list-render into a `redrawList(filter)` helper that takes a filter string (default empty), clears `list`, computes the merged candidate set `[...new Set([...people, ...selected])].sort()`, filters by `name.toLowerCase().includes(filter.toLowerCase())` OR `selected.has(name)` (selected entries always show), and re-runs `renderRow` over the filtered set.
- [ ] Call `redrawList("")` initially in place of the current `.forEach(renderRow)`.
- [ ] Wire `addInput.oninput = () => { redrawList(addInput.value.trim()); updateAddButton(); }`.
- [ ] Add an `updateAddButton()` helper that sets `addBtn.disabled` to `true` when the trimmed input is empty OR when any `people[]` entry matches case-insensitively, and updates `addBtn.textContent` to either `Add` (disabled) or `Add "<typed name>" as new person` (enabled).
- [ ] Call `updateAddButton()` once after creating `addBtn` so initial state is correct.
- [ ] In the existing `addBtn.onclick` handler, after a successful stub creation, ALSO call `addInput.value = ""` (already done) + `redrawList("")` + `updateAddButton()` to reset to default state.

**Verification:**
- [ ] Static-helper tests in `run-meeting-leaf-actions.js` still pass (no static-helper signatures changed).
- [ ] Smoke test in browser after deploy: type "jas" — list filters to entries containing "jas". Type a non-existent string — Add button enables with dynamic label. Clear input — list shows full set again.

## Risk + rollback

- **Risk:** Bug 2/3 changes to `_onEditAttendees` introduce a JS exception that breaks the modal. Mitigation: changes are additive (oninput handler + new helper functions); existing renderRow + save paths untouched. Verify by clicking Edit Attendees post-deploy.
- **Risk:** dropping the leading `dv` from PeopleRendering args breaks some other consumer that relied on it. Mitigation: nothing in this repo passes `dv` as a positional data arg to renderMentionList; the helper signature has always been `(dv, query, opts)` and customjs-guard has always prepended `dv`. Audit other call sites:
  - [ ] `grep -rn "renderMentionList" platform/ ranch/` — confirm no other invocation passes `dv` inside `args[]`.
- **Risk:** Bug 5 turns out to be a separate root cause and the v0.126.1 fix doesn't address it. Mitigation: Task 3 explicitly defers in that case; doesn't block ship.
- **Rollback:** revert the manifest + helper changes; bump workshop 0.126.1 → 0.126.2 with the revert.
