# v0.98.0 — synopsis-density rewrite design

## Problem

The five cadence orchestrators (morning-briefing, midday-tripwire, eod-review, weekly-review, monthly-review) emit atomic notes whose default reading-load is microscope-by-microscope walls. Today's accuris morning brief (`spice/cowork/daily/2026/06-June/2026-06-10/morning-briefing.md`) leads with `> [!info]- Today at a glance` (collapsed by default) followed by four `> [!example]+` per-kind callouts (open by default — Chat, Calendar, GitHub, ADO) and a `> [!tip] Today's focus` close. The chat callout alone carries eight named-person blocks at 2–4 lines each plus a "Inner circle - channels" sub-section. The synopsis exists but is hidden behind a default-collapsed disclosure and competes with all per-kind blocks for first-read attention. The user expressed the friction explicitly (memory `project_v098_brainstorm_direction.md`, 2026-06-10):

> "Reports too long, too much reading, not enough summarization. ... long term it will give me the info that I need before I need it."

The brief shape today emphasizes COVERAGE (every kind enumerated, every active item described). The user wants emphasis on PREDICTION (the highest-blocking action first; cross-kind dependencies as connective tissue; per-kind detail behind a click). The `[!tip] Today's focus` callout already attempts the prediction role at the bottom of the brief — but it duplicates work the synopsis should be doing and trains the reader to scroll past detail to find it.

The output-shape contract is composed at two sites today:

1. `platform/blueprints/cowork/content/data/orchestrator-instructions/<cadence>.md` — lines ~191-199 of `morning-briefing.md` carry the inlined strings: `synopsis_md = "> [!info]- Today at a glance\n> ..."` (collapsed-by-default) and `closing_md = "> [!tip] Today's focus\n> ..."`. Memory-log fallback prose at line ~134 also references `[!info]- Today at a glance`. Equivalent sites exist in the four other cadence files.
2. `platform/blueprints/cowork/content/context/engagement-templates/{personal,w2-fte,consulting}/prompts/<cadence>.md` — line 13 carries the `## Today at a glance` H2 (the per-bundle prose seed for the synopsis) and line 33 carries `## Today's focus` (the seed for the closing callout). 15 prompt files total (3 templates × 5 cadences).

Per-kind callouts use `[!example]+` (open) per the compose-body output-shape contract inlined into the wrappers at v0.97.4. The string lives downstream of the orchestrator-instructions but upstream of compose-body-helper.js — currently rendered by the LLM following the wrapper's contract section. Some compose-body fixtures (`platform/blueprints/cowork/helpers/fixtures/compose-body/case-*/expected-assertions.json`) pin the open-by-default expectation.

### Why workshop MINOR (not PATCH)

The brief shape that consumers see is materially different — different callout structure, different default-expand state, different lead-paragraph contract. A consumer running `sauce update --bump-pins` and reading the next morning's brief will see a visibly-changed shape. Per sauce convention, user-visible contract changes are MINOR.

### Why cowork MINOR (not PATCH)

Same reasoning. The compose-body output-shape contract is the consumer-facing API of the brief. Changing the lead callout title, the default-expand state of per-kind blocks, and removing the closing callout is a contract change. MINOR per the cowork blueprint convention used in v0.31.0, v0.32.0, v0.33.0, v0.35.0.

### Why orchestrator-instructions is the right edit site

v0.97.x landed the wrapper architecture where each cadence orchestrator carries an inlined output-shape contract section. The contract strings (`synopsis_md`, `closing_md`, per-kind `[!example]+` headers) live in `content/data/orchestrator-instructions/<cadence>.md`. The wrapper SKILL.md reads this file at fire time and follows the contract. Changing the strings here propagates to all 5 cadences via a single composition pattern — no per-wrapper SKILL.md edit needed beyond the orchestrator-instructions files themselves.

The engagement-template prompts (`content/context/engagement-templates/<bundle>/prompts/<cadence>.md`) provide the per-engagement-bundle prose SEED for the synopsis. Their H2 headings (`## Today at a glance`, `## Today's focus`) name the sections the LLM composes from. Renaming the H2 there keeps the per-bundle prose flowing into the new synopsis section; deleting `## Today's focus` retires the prose seed for the deleted callout.

## The new lead-callout contract

### File
`platform/blueprints/cowork/content/data/orchestrator-instructions/<cadence>.md` (×5).

### Composition rules (verbatim — to be embedded as a `## Synopsis composition rules` section near the existing `synopsis_md` site)

```
The synopsis is a single paragraph rendered inside a `> [!info]+ What matters
today` callout (cadence variant — see § Per-cadence title strings below). The
callout is OPEN by default; it is the reader's first stop and is expected to
carry the load of the brief on its own.

Compose the paragraph per the following rules. Voice contract (vibe,
personality, hard_rules) still applies on top of these rules; structural rules
WIN on conflict.

  1. Length: ≤ 80 words. Hard cap. Prefer 50-60.
  2. First sentence names the highest-blocking action concretely — a PR number,
     a person + decision, an inbound + ask. Never opens with "Today is...",
     "You have...", "There are N...".
  3. Thread cross-kind dependencies as connective tissue when present (e.g.
     "...which gates today's 10am with Stefan..."). Don't enumerate per-kind
     ("first chat, then calendar, then..."); the reader can drill into each
     `[!example]-` callout.
  4. Beyond the lead action, name at most 3 distinct must-knows. Order by
     blocking-effect, not by kind.
  5. If the day is genuinely quiet (no actionable items, no inbox debt, no
     blocking calendar conflicts), say so PLAINLY: "Quiet day — standup +
     Stefan 1:1, nothing else needs attention." Do not pad.
  6. Predict the next user action; do not describe the last LLM gather.
```

| Cadence | Lead callout title | Synopsis frames |
| --- | --- | --- |
| morning-briefing | `What matters today` | predict today's blocking actions |
| midday-tripwire | `What changed since morning` | compress tripwire severities + new arrivals |

### Per-kind callout default-expand

The output-shape contract section in each orchestrator-instructions file currently emits per-kind callouts as `> [!example]+ <title>` (open by default). v0.98.0 changes the single `+` → `-`. Implementation: one regex/sed replace per file in the section that generates the per-kind callout header.

### Closing callout removal

The `closing_md` composition (currently `> [!tip] Today's focus` + body) is REMOVED from `synopsis_md` + `closing_md` composition. The composer no longer emits any `[!tip]` close. The engagement-template prompt's `## Today's focus` H2 + body becomes dead prose; v0.98.0 retires it from the engagement-template-prompts as well.

Net: each brief loses ~60 words of duplicated lead-of-action prose.

### `[!info]+ What matters today` callout (verbatim sketch — morning cadence)

```markdown
> [!info]+ What matters today
> Review Zhenzhen's SND prod PR #353 first — it's blocking
> content-registry-prod provisioning. 8am with Stefan on GitHub
> Enterprise migration shapes DENALI 704107 next steps. Three
> multi-region stories in flight (708804/709111/709112). Ben + Stale
> fixed Doc DB writes — us-west-2 back in. No reply debt overnight;
> standup at 9.
```

(76 words. Lead action concrete + named. Three follow-on items ordered by blocking effect. Cross-kind connective tissue across chat + calendar + ADO + GitHub. Voice = casual per the engagement's personality contract.)

### Empty-day fallback

When the dispatch-plan returns no actionable items (no blocking PR, no inbox debt, no calendar conflicts, no tripped tripwires), the synopsis MUST say that plainly. Sketch:

```markdown
> [!info]+ What matters today
> Quiet day. Standup at 9 and Stefan 1:1 at 10 — both routine. Nothing in chat or PRs blocks. Use the slack to advance the multi-region scope (708804) or close out the SCHEELS card reissue follow-up.
```

(40 words. Acknowledges quiet, names what IS scheduled, suggests a use for the time. Voice still applies.)

### Frontmatter `summary:` field

The brief's frontmatter `summary:` field today carries a 1-line title-like summary written by compose-body. v0.98.0 keeps the field; the `summary:` value becomes a 1-sentence reduction of the synopsis paragraph (the first sentence of the synopsis, roughly). Dataview consumers continue to query it. No schema change.

## The cohesion sweep (what each orchestrator becomes)

Five orchestrators × one change pattern:

1. Open `content/data/orchestrator-instructions/<cadence>.md`.
2. Replace the existing `synopsis_md = "> [!info]- ..."` composition site with `synopsis_md = "> [!info]+ <per-cadence title>\n..."`.
3. Delete the `closing_md = "> [!tip] Today's focus\n..."` composition site and its callsite in the final body assembly.
4. In the per-kind callout emit section, change `[!example]+` → `[!example]-`.
5. Append the `## Synopsis composition rules` section per § The new lead-callout contract above.
6. Update the memory-log fallback prose (morning-briefing.md line ~134) to reference the new title.

The wrapper SKILL.md files in `skills/orchestrators/<cadence>/SKILL.md` need no direct edit — they consume the orchestrator-instructions file at fire time and follow whatever contract it carries.

## The engagement-template prompt sweep

15 files × one change pattern:

1. Open `content/context/engagement-templates/<bundle>/prompts/<cadence>.md`.
2. Rename `## Today at a glance` → `## What matters today` (or the per-cadence variant per the title table).
3. Move the prose body of `## Today's focus` UNDER the renamed `## What matters today` H2 (so the per-engagement seed prose for predicted-next-action becomes part of the synopsis seed, not a separate section).
4. Delete the now-empty `## Today's focus` H2.

The per-bundle prose seeds are author-curated content (some bundles have rich prose under each H2, some have placeholder). The merge under one H2 is straightforward; the LLM composes from the merged prose at fire time per the new synopsis composition rules.

## Forward arc — v0.98.1 + v0.98.2 (sketches)

### v0.98.1 — questionnaire expansion + free-text capture

**Goal.** Replace today's per-kind boolean Rail L ticks with per-item ticks + per-kind frequency knobs + a free-text feedback field. Persist captured signal in a parseable schema. Capture only; no parse-back or ingest yet (v0.98.2 does that).

**Key design moves:**

1. **Stable item-IDs.** Compose-body emits each surfaced person-block / PR-row / ADO-story-row with a trailing `^item-<stable-key>` block-ID. Key = `hash(kind + identifier)` — day-stable so longitudinal signal accrues. Block-IDs render invisibly in reading mode.

2. **New Rail L shape** (replaces today's per-kind boolean ticks; see brainstorm session for full sketch):

   ```markdown
   > [!todo]+ Was today useful?
   > <!-- cowork:feedback-capture v=1 -->
   >
   > > [!summary]- Chat — items
   > > - [ ] [[#^item-chat-zhenzhen|Zhenzhen PR #353 thread]]
   > > - [ ] [[#^item-chat-ben-stale|Ben/Stale Doc DB infra]]
   > > - [ ] [[#^item-chat-justin-juan|Justin/Juan UDV reporting]]
   > >
   > > **Fire chat:** `[ ] less` `[ ] same` `[ ] more`
   >
   > > [!summary]- GitHub — items
   > > - [ ] [[#^item-github-pr-353|PR #353 awaiting review]]
   > >
   > > **Fire GitHub:** `[ ] less` `[ ] same` `[ ] more`
   >
   > ### Free-text feedback
   >
   > ```feedback
   > (Type prose here.)
   > ```
   ```

3. **Sentinel for v0.98.2 parse:** HTML comment `<!-- cowork:feedback-capture v=1 -->` at top of the Rail L callout. v0.98.2 reconciler greps for the sentinel + parses the markdown structure beneath it.

4. **Surfaces hit (sketch — full design at v0.98.1 cycle open).** compose-body output contract gains item-ID emit rules; new helper `composeFeedbackCapture(plan, surfaced_items)` builds the Rail L sub-callouts; 5 cadences' Rail L body updates (eod-review primary; the other 4 cadences' Rail L stays kind-level OR gains a one-tap "this brief was useful: [ ] yes [ ] no" — open question).

5. **learned_weights schema stays at version 2** for v0.98.1 (capture only — no writes yet). v0.98.2 bumps to 3.

**Open v0.98.1 questions to resolve at cycle open:**

- Frequency knob granularity — 3-way (`less / same / more`) or 5-way (`much-less / less / same / more / much-more`)?

### v0.98.2 — reconciler free-text + per-item-tick ingest

**Goal.** Close the loop. The `cowork:reconcile-cowork` orchestrator reads captured feedback corpus, produces structured deltas, writes them to `learned_weights` / microscopes / `what_matters` strings — with an audit trail. Voice/personality changes are PROPOSED, never auto-applied.

**Pipeline (sketch — full design at v0.98.2 cycle open):**

1. **Trigger.** Reconciler fires on existing cadence (daily during warmup, weekly post-warmup). On each fire, reads the last N days of EOD reviews (and any cadence brief carrying a `<!-- cowork:feedback-capture v=1 -->` sentinel).

2. **Parse structured signal (deterministic).** Per-item ticks → looked up against the item-ID hash registry → rolled up per-kind, per-person, per-channel weight nudges. Frequency knobs → direct weight delta (`less = -0.05`, `more = +0.05`; clamped `0 .. 1`).

3. **Parse free-text (LLM pass).** New sub-skill `cowork:ingest-feedback` runs an LLM pass with a structured-output prompt: "Read this user's feedback prose. Extract structured intents: (a) per-person/channel/topic uprank/downrank, (b) voice corrections, (c) coverage gaps, (d) other. Return as deltas with proposed write-targets." Model: Sonnet 4.6 (cost-fast — open question).

4. **Apply with audit trail.**
   - All deltas logged to `spice/cowork/memory/<engagement>/feedback-deltas.md` (append-only changelog: date + delta + source quote).
   - `learned_weights` numeric updates: applied directly with clamp + log.
   - Microscope `what_matters` strings: append-only — never rewrite the contract; user prunes later.
   - Personality/voice changes: PROPOSED only — surface in next-day morning brief as a callout "Voice tweak proposed: [...]. Apply via /cowork apply-voice-deltas?"
   - Coverage gaps: written to `spice/cowork/memory/<engagement>/coverage-queue.md`.
