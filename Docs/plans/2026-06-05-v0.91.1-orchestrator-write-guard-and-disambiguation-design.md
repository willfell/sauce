## 0. Why this cycle

Live run of accuris morning-briefing scheduled job on the willfell laptop (post-v0.91.0 deploy) STILL wrote the atomic note to `spice/daily/2026/06-June/Friday-2026-06-05.md` instead of the canonical `spice/cowork/daily/2026/06-June/2026-06-05/morning-briefing.md`. This is the same wrong-path failure mode that v0.90.2 shipped to prevent.

### Why headspace works but accuris fails

The accuris consumer vault's CLAUDE.md contains LEGACY accuris content from before the vault adopted cowork — non-negotiables like *"Daily notes are gateways"* + *"Naming: daily YYYY-MM-DD-DayName.md"* + a `Daily | spice/daily | /daily` resolver row. These signals compete with the cowork orchestrator's `[!warning]+ CRITICAL` callout. The LLM, attention-constrained, defers to the vault-canonical CLAUDE.md rather than the skill-body callout.

Headspace's CLAUDE.md doesn't have the legacy daily-note convention rows, so the v0.90.2 callout suffices there.

Prose-only fixes have an LLM-attention ceiling. v0.91.1 adds DETERMINISTIC backstops.

## 1. Fix A — write-guard in 5 `cowork:write-run-note-<orchestrator>` sub-skills

Add a `## Pre-write self-check (v0.91.1 write-guard)` clause to each of:
- `write-run-note-morning-briefing/SKILL.md`
- `write-run-note-midday-tripwire/SKILL.md`
- `write-run-note-eod-review/SKILL.md`
- `write-run-note-weekly-review/SKILL.md`
- `write-run-note-monthly-review/SKILL.md`

The clause REJECTS any computed write path that matches the daily-blueprint shape (`spice/daily/<YYYY>/<MM-Month>/<weekday>-<YYYY-MM-DD>.md`) and returns `failed:contract-violation:wrong-output-path:<actual-path>`. Deterministic backstop: even if the LLM invokes the sub-skill with the wrong path arg, the sub-skill itself refuses.

Insertion point: at the TOP of each sub-skill's existing `## Pre-write self-check` section, AS THE FIRST CHECK before any structural-marker checks.

Sample clause text (parametrized per orchestrator):

```markdown
### v0.91.1 write-guard: canonical output path enforcement (FIRST CHECK)

Before any other pre-write check, validate the computed write path. The canonical path for this sub-skill is:

`spice/cowork/daily/<YYYY>/<MM-Month>/<YYYY-MM-DD>/morning-briefing.md`

REJECT and return `failed:contract-violation:wrong-output-path:<computed-path>` if the computed path:

1. Starts with `spice/daily/` (that's the daily-blueprint surface, NOT cowork atomic notes).
2. Has a filename matching `<weekday>-<YYYY-MM-DD>.md` shape (daily-note naming convention).
3. Doesn't contain the `spice/cowork/daily/` prefix.

Even if the orchestrator's calling code passes a wrong path, this guard catches it. This is the deterministic backstop for v0.90.2's [!warning]+ CRITICAL orchestrator callout (prose-only; LLM-attention-bounded).
```

## 2. Fix B — claude_surface disambiguation row

Add a new `claude_md_row` to the cowork manifest:

```json
{
  "kind": "claude_md_row",
  "table": "resolvers",
  "row": {
    "topic": "Cowork Atomic Notes (cron output)",
    "path": "{{module_directory}}/daily/",
    "command": "(cron-only — NOT spice/daily/)"
  }
}
```

After v0.91.1 install on consumer vaults, the auto-generated resolvers table in CLAUDE.md gains this row. LLMs reading the table see BOTH `spice/daily` (daily-blueprint) AND `spice/cowork/daily/` (cowork atomic notes) with topic disambiguation. The "(cron-only — NOT spice/daily/)" command field explicitly cites the trap.

### C.2 Step 17 extension: misdirection check

After the existing Step 17 (re-read + structural verify at canonical path), add Step 17b:

```markdown
17b. **Misdirection check (v0.91.1):** if the Step 17 file-exists check at the canonical path FAILED (the canonical-path file doesn't exist), do not assume the write silently failed — instead probe for the misdirected-write location:

   - Check `spice/daily/<YYYY>/<MM-Month>/<weekday>-<YYYY-MM-DD>.md` via `mcp__obsidian__obsidian_get_file_contents`.
   - If that file EXISTS and was modified within the last 10 minutes → the LLM wrote to the wrong path despite the [!warning]+ CRITICAL callout + verbal commitment. ABORT loudly with Notice:

     ```
     cowork:morning-briefing ABORTED -- write misdirected to spice/daily/<weekday>-<YYYY-MM-DD>.md instead of canonical spice/cowork/daily/<YYYY>/<MM-Month>/<YYYY-MM-DD>/morning-briefing.md. The misdirected file is at <path>. Move it manually OR delete it + re-run. Verbal-commitment Notice from pre-flight Step 1b should have prevented this; v0.91.1 write-guard + Step 17b are the deterministic backstops.
     ```

   - Do NOT auto-move (risk of clobbering user content). User-driven cleanup.
```

## 6. Risks

1. **Write-guard depends on LLM invoking the sub-skill.** If the LLM writes directly via Write/Edit/obsidian_put_content without invoking the write-run-note sub-skill at all, the guard never executes. Mitigation: combine with Fix C (Step 17b misdirection check) which catches the symptom even when the LLM bypasses the guard.

2. **Misdirection check uses a 10-minute mtime threshold.** Heuristic; if the LLM session takes >10 min between writing the misdirected file and reaching Step 17b, the check could miss the file. Acceptable for v0.91.1; future iteration could compare specific content fingerprints.

3. **Verbal-commitment Notice is prose-imperative.** Same LLM-attention class as the [!warning]+ CRITICAL callout — could be missed. Acceptable: it's one layer of three.
