# v0.101.0 — verbal feedback everywhere

## TL;DR

v0.99.0 made the EOD feedback section prose-first; the other FOUR cadences
(morning-briefing, midday-tripwire, weekly-review, monthly-review) still emit the
v0.96.0 kind-checkbox-only rail. The user opened a morning brief, saw only
checkboxes, and wants verbal feedback EVERYWHERE — applied at the bottom of every
scheduled job, feeding the loop that makes tomorrow better.

Three moves, one MINOR:

1. **Capture v=4 — one shape on all five briefs.** The one-tap `Useful: yes/no`
   line + free-text typing box render on top of EVERY brief's feedback callout.
   Below the box, EOD keeps its exact v=3 per-item Mattered/Didn't-like lists +
   frequency knobs; the four other cadences render one collapsed kind checklist
   (the old checkbox content, demoted to garnish). The old `rating-block` shape
   stops being EMITTED; its parser lives forever for the historical corpus.
2. **Per-cadence satisfaction (schema 5).** Satisfaction entries become
   `{day, cadence, useful}` — up to five taps a day coexist, and the doctor
   (next cycle) can grade each cadence separately ("morning trends yes, midday
   trends no"). Prose-derived global sentiment writes to the same channel and
   wins over the tap on disagreement. Additive normalizer; NO destructive
   migration; warmup/graduation rules untouched.
3. **Prose ingest generalized.** The 03:00 reconciler extracts intents from up to
   five typing boxes per day, each tagged `source_cadence`; an intent applies at
   most once per (day, intent, kind, entity). Global sentiment moves satisfaction
   + engagement ONLY — kind weights move only on kind/entity-scoped prose. NEW
   symmetry fix: downrank prose scoped to a kind (no entity) counts as that
   kind's SKIP (mirror of v0.99.0's uprank-counts-as-tick).

No new scheduled job; contract 0.35.1 expected to hold (zero new substitution
tokens — the kind checklist reuses the existing `rating_kind_lines` computed
token); no new installer write surface under user-owned paths.

## Goal

User framing verbatim (2026-06-12 PM, post-v0.99.0/v0.100.x deploy):

> "I want for you to add a mechanism where I get to provide feedback, verbal
> feedback on what I liked and didn't like, and then that also gets utilized
> within this process to get better and better every day. Should be something
> that is applied at the bottom of every scheduled job." [...] "thinking big here"

The user is a prose-first sparse-signal feedback giver (never built the tick
habit; v0.99.0 rebuilt the loop around that). Prose IS the primary channel —
v0.101.0 puts that channel on every brief, not just EOD.

Per `Docs/cowork-vision.md`, this cycle advances **Adaptive memory loop**
(dimension 3 — the primary feedback channel now exists at every touchpoint) and
**Quality observability** (dimension 6 — the satisfaction series becomes
cadence-resolvable, the doctor's KPI upgrade).

## Contracts in detail

### C1 — Capture v=4 (compose-feedback-capture-helper.js + _shared-clauses.md)

- `feedback_capture_template` becomes the single shape for all five cadences.
  Callout title goes cadence-neutral: `> [!todo]+ Was this useful?` (avoids a
  new substitution token; title is not a parse anchor — the sentinel is).
  Subtitle line unchanged ("One tap, a line of prose, or ticks — anything
  counts. Tomorrow's brief adjusts overnight.").
- Section order is contract: (1) one-tap `Useful:` line, (2) tagged
  ```feedback``` fence with the `<kind>:` placeholder convention, (3) per-cadence
  blocks: EOD → per-item Mattered/Didn't-like sub-callouts + knob rows (EXACT
  v=3 mechanics, byte-comparable modulo sentinel); non-EOD → ONE collapsed
  `> > [!summary]- Kinds — quick ticks` sub-callout of kind checkboxes (computed
  per surfaced kind, same source as today's `{{$rating_kind_lines}}`), (4)
  sentinel `<!-- cowork:feedback-capture v=4 -->`.
- `composeFeedbackCapture(opts)` gains cadence awareness (opts already carries
  enough shape — exact mechanism per existing signature at S1 plan time).
- `_parsePrior` tolerates v=1, v=2, v=3, AND v=4 priors. Re-fire preserves: tap
  state, prose, per-item ticks + knobs (EOD), kind-checklist ticks (non-EOD).
- **Transition nicety:** on the first v=4 fire over a same-day prior carrying the
  LEGACY `rating-block` marker (upgrade day), prior kind ticks are preserved into
  the new checklist via the existing `parseRatingCallout` output. Nothing is lost
  on upgrade day.
- Tasks-plugin trailing-annotation tolerance applies to every tick line AND the
  tap line (existing posture).
- ZERO new substitution tokens expected. If implementation surfaces one, it MUST
  land in the wrapper composer's token registry in the same commit (v0.98.2
  lesson 6; registry location confirmed at S1.0 — see Ground truth 4).

### C4 — Ingest generalization (learn-from-checks + ingest-feedback helpers)

- `parseFeedbackCapture` learns the v=4 kind-checklist section (state machine
  gains one section type; mirrored-parser lockstep with `_parsePrior` cross-
  reference comments maintained — v0.98.2 lesson 3). Kind-level mapping for
  non-EOD v=4 notes: ticked kind → `{kind, ticked: true}`; surfaced-but-unticked
  → `{kind, ticked: false}` (identical semantics to the legacy rating parse).
- Satisfaction: `appendSatisfaction(totals, day, useful, opts)` gains
  `opts.cadence` (required for new writes). Entry shape `{day, cadence, useful}`;
  same-(day, cadence) re-log overwrites; window trims entries whose `day` is
  older than 30 days relative to the appended day (belt-and-suspenders cap: 200
  entries). Runs per note with a boolean tap, ALL day classes (existing 13f
  posture).
- Prose-derived sentiment: NEW intent `satisfaction` in the Step 3.6 allowlist
  (uprank | downrank | voice_correction | coverage_gap | frequency |
  **satisfaction** | other); requires NO kind; NEW `proposed_target` value
  `satisfaction-series` (allowlist grows to five). Disposition: append to the
  satisfaction series for the note's source_cadence; on disagreement with that
  note's tap, PROSE WINS (the typed word is higher-intent than a tap).
  Prose-derived sentiment only ever occurs on ENGAGED days by construction
  (non-placeholder prose = ENGAGED).
- source_cadence: every extracted intent is tagged with the cadence of the note
  whose typing box produced it; recorded in `feedback-deltas.md` audit lines and
  voice-proposal `source:` fields (e.g. `(midday-tripwire 2026-06-13)`). NO
  per-cadence rendering machinery this cycle — the tag is data accrual for the
  doctor.
- Dedup: an accepted intent applies at most once per (day, intent, kind, entity)
  across ALL of yesterday's notes ("github: too much" at midday AND EOD = one
  delta). Dedup happens at the disposition layer; both occurrences appear in the
  audit log (second tagged `[pending] dedup`).
- Downrank-skip symmetry: `applyIntentKindTicks` RENAMES to
  `applyIntentKindObservations` (the function now emits skips, not just ticks —
  keeping the old name would be the same misnomer class as the parked
  evaluateWarmup rename; per-touch hygiene since the helper is edited anyway;
  all call sites + OI restatements update in the same commit). Behavior: uprank
  prose scoped to a kind = kind tick (existing); downrank prose scoped to a kind
  WITHOUT a named entity = kind skip (NEW). Downrank naming an entity keeps
  today's entity-delta-only path (a complaint about one person must not skip the
  whole kind).
- `classifyEngagementDay` semantics UNCHANGED (already any-note-based). Multiple
  taps without other signal across several notes is still TAP-ONLY.
