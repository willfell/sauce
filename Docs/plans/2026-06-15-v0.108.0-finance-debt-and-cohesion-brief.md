## What the user asked for next (v0.108.0 ask, verbatim summary)

### 1. NEW: long-term debt sub-area in finance

Quote: *"another area or section within the finance blueprint that's called debt long-term. It's going to be focused on all debt and paying it off."*

- New `spice/finance/debts/` sub-area mirroring budgets/paychecks/invoices structure.
- Hub: `spice/finance/debts/Debts.md` (or `Debt.md` — naming TBD at brainstorm).
- Sub-section for **credit card debt** first; later expansion to student loan debt + other.
- Per-debt entity at `spice/finance/debts/<slug>/Debt-<slug>.md` (or flat — TBD).
- Each debt entity carries frontmatter: `{type: debt, kind: "credit-card"|"student-loan"|..., name, current_balance, credit_limit (cc only), apr, min_payment, planned_monthly_payment, url, opened_date, target_payoff_date}`.

### 2. Dashboard at top of debt notes (and the debt hub)

Same three-band rollup family as BudgetSummary / PaycheckSummary:
- **DebtSummary** (per-debt entity): Current balance + APR + monthly interest + planned monthly attack + projected payoff date. Maybe a "balance trajectory" mini-chart.
- **DebtsHubSummary** (on Debts.md hub): Total debt across all cards/loans, total monthly paydown commit, weighted-avg APR, total monthly interest cost, projected zero-debt date. Per-debt pill-cards (one per debt, colored by paydown progress).

### 3. Configure-and-create UX

- New entity-create entry `debt` with `seed_from_defaults` from a new `Debt Defaults.md` per-vault config.
- The defaults file holds a list of debts the user wants tracked, with their current configuration. New debt entities scaffold from there.
- BUT — debt entities also need ongoing balance updates. The user said "manually updating the debt amounts by looking at [Copilot/issuer site] and then going to the configuration for the credit card debts and updating it." So the editor widgets (DebtsEditor / DebtConfigEditor) need to support per-debt edit modals that update current_balance + apr + min_payment.

### 4. Glue paychecks ↔ debts ↔ budgets together

Quote: *"when I create a new paycheck, it automatically adds in the debt section to outline and put in the payments for those if that makes sense"*

- **Paycheck Defaults already has credit-card payment lines** (Apple Card, Capital One Platinum, etc. — populated in CF-3). These DON'T currently know they're debt payments.
- v0.108.0 should:
  1. Add a `debt_id` (or `debt_ref` wikilink) optional field on paycheck `expenses[*]` so each expense can point at a debt entity.
  2. When a new paycheck scaffolds from Paycheck Defaults, also pull in `planned_monthly_payment` from each linked debt — or pull the full set of debts as a "Debt Payments" section in the paycheck.
  3. Render debt-payment expenses with a special pill (color-coded by paydown progress) in `PaycheckExpensesEditor`.
  4. `url` field on debt-payment expenses defaults to the issuer's pay-bill URL (already in Paycheck Defaults for some — Capital One, Discover, etc.).

### 5. Monthly cohesion dashboard

Quote: *"look at a month like let's say July and be able to see how much was I paid by adding up the paychecks within that month, look at the budget for that month, see and correlate how much is with each, and then also look at debt and see how much was paid off."*

- Aggregate dashboard at the **top of the monthly Budget note** (or a new Monthly hub at `spice/finance/months/<YYYY-MM>/<YYYY-MM>.md`?) that reads:
  - Paychecks for the month (sum of paycheck_amount across `spice/finance/paychecks/<YYYY-MM-*>/`).
  - Budget for the month (this is the current `Budget-<YYYY-MM>.md` — already exists).
  - Debt deltas for the month (sum of debt payments made, debt-balance change month-over-month).
- Headline math: **income − total spending − debt paydown** = net cashflow for the month. Color-coded red/green.
- Quotes worth preserving: *"how much was paid, did I spend more than I make, did I spend less than I make, how much did I put towards debt? Was there a loss or was there more debt added that month?"*

### 6. Button standardization across finance

Quote: *"button standardization for budgets for paychecks for invoices for debt that ensures standardization with buttons within the mechanisms that to a whole lie [are tied] to navigate within it all using buttons that match the criteria for patterns, and are all using the same mechanism to display them by being context where what file it's in and what's there."*

- CF-3 shipped `FinanceHubActions` for the four hubs (Finance, Budgets, Paychecks, Invoices). Extend it for Debts hub.
- BUT — currently the per-entity nav buttons (`BudgetNavButtons`, `PaycheckNavButtons`, `InvoiceNavButtons`) are SEPARATE classes per blueprint, each with hard-coded behavior. The user wants ONE mechanism that figures out "what file am I on" and renders the right buttons.
- Design candidate: **`FinanceNavRow`** widget — single class, context-aware. Detects the current file via path prefix + `type` frontmatter (`budget`, `paycheck`, `invoice`, `debt`, `budgets-hub`, `paychecks-hub`, etc.) and renders:
  - Hub mode: same as `FinanceHubActions` today.
  - Entity mode: per-entity context row (current entity name + parent hub link + sibling entities + Finance hub).
  - This would deprecate `BudgetNavButtons` / `PaycheckNavButtons` / `InvoiceNavButtons`. Keep them aliased for backward compat or migrate templates.

## Open design questions (resolve in next-session brainstorm)

1. **Debt entity granularity** — one note per debt (`Debt-apple-card.md` flat) or one note per debt + sub-folder ecosystem (mirrors invoices)? Probably flat — debts don't have per-month sub-entities like invoices.
2. **Debt naming** — `Debt-Apple-Card.md` slug-based filename? Or just `Apple Card.md`?
3. **Balance updates** — manual via DebtConfigEditor only, or also auto-pull from Copilot MCP at install time / via a scheduled job? User said "manually" — so widget-driven. But Copilot MCP could be a one-shot helper button ("Pull balances from Copilot").
4. **APR + min_payment storage** — frontmatter (yes) or also a `balance_history[]` array for trajectory? Probably yes, with a sub-widget for entering balance snapshots over time.
5. **Monthly dashboard location** — new `Monthly-<YYYY-MM>.md` note? Or extend `Budget-<YYYY-MM>.md` to also be the monthly hub? Or new hub at `spice/finance/months/<YYYY-MM>.md`?
6. **Debt payments in paycheck expenses** — do paycheck expense items LINK to debt entities (`debt: "[[Debt-Apple-Card]]"`), or do paychecks have a separate `debt_payments: []` array? Linking is cleaner.
7. **Issuer pay-bill URLs** — currently the user has them in Paycheck Defaults `url:`. For debt entities, store on the debt entity itself (`url:`) so the link travels with the debt regardless of which paycheck pays it.
8. **Headspace existing data** — the user has `/Users/willfellhoelter/notes/sauce/headspace-sauce/Finance/Debt/Credit Debt Payoff Tracker.md` with active strategy notes. v0.108.0 design needs a migration path: do we read this file's prose to seed debt entities, or do we leave it as historical context and start fresh with the new structured data?
9. **Existing skill** — `spice/cowork/skills/gather-cc-debt-snapshot/SKILL.md` exists and reads Copilot for daily CC snapshots. v0.108.0 should compose with this skill (read its output) or extend it.
10. **FinanceNavRow vs. keeping per-blueprint nav-buttons** — clean migration or aliases for backward compat? Lean toward clean migration since CF-3 already opened the door.
