## 0. Cycle prelude — brainstorm decisions (verbatim, for the record)

Five architectural choices locked during the brainstorm clarifying-question pass:

1. **Sequencing:** WS1 (v0.89.1) before WS2 (new connector-agnostic people-discovery skill, queued v0.90.x+).
2. **Resolver firing mechanism:** Hybrid pre-resolve + soft prompt. Orchestrator pre-resolves `engagement.inner_circle_people` to a deterministic allowlist; dispatch contract carries the allowlist verbatim AND a soft instruction to resolve ambient names mid-dispatch.
3. **Cycle scope:** PATCH — dispatch envelope only. No `cowork:edit-microscope` authoring update. No microscope audit prompt. FLN-v89-9 stays queued. User microscopes stay 100% user-owned.
4. **Pre-resolve locus:** NEW pure JS helper `resolve-inner-circle-helper.js`. NOT a new sub-skill (would force MINOR per sauce convention). Helper exports a single function; orchestrator SKILL.md prose drives the resolve-person loop and invokes the helper to shape the output.
5. **Stage shape:** Approach A foundation-first (5 stages, 5 commits) mirroring v0.89.0 cadence.

### 0.1 Bundled daily fix

Added at user request during clarifying-question pass: SpaceDailyDashboard `_resolveTitle` falls through to `p.file.aliases[0]` and stringifies typed-alias objects (`{type, value}`) as `"[object Object]"`. Bug surfaced on the workshop vault's daily-activity panel when a newly-created v0.6.0 person note has a typed alias. Falls in scope because:
- Touches `platform/blueprints/daily/helpers/space-daily-dashboard.js` (daily PATCH bump)
- Co-located with the people-cohesion arc (v0.6.0 typed aliases are the trigger)
- Pure defensive fix, no install-surface change, fits PATCH cadence
- Easier to ship in the same cycle than separately

### 0.2 Versioning conflict resolution

Initial brainstorm answer paired PATCH scope with a new sub-skill `cowork:resolve-inner-circle`. Surfaced as a conflict during clarifying-question pass: a new SKILL.md file in `files[]` is a new install surface, which sauce convention treats as MINOR (per v0.85.0 / v0.87.0 / v0.89.0 cycles all bumping cowork MINOR for a new sub-skill). Resolution: drop the new sub-skill; keep PATCH; move the abstraction to a pure JS helper without a SKILL.md face. Trade-off: orchestrator SKILL.md prose carries the loop-step language instead of delegating to a sub-skill. Acceptable for PATCH cadence; FLN candidate if the orchestrator-side duplication becomes onerous.

## 1. Scope

### 1.1 §1 NEW pure helper `resolve-inner-circle-helper.js`

**Location.** `platform/blueprints/cowork/helpers/resolve-inner-circle-helper.js`. Pure JS — no MCP, no side effects.

**Exports.**

```js
function composeInnerCircleAllowlist(resolverOutputs) {
  // Inputs: Array of cowork:resolve-person output objects, one per inner_circle_people name.
  //   Each entry: { resolved, person_link, person_basename, matched_via,
  //                 collision_warning, aliases_by_type, _input?: string }
  //   _input is the original name string the caller resolved (orchestrator threads it through
  //   so the helper can surface unresolved names alongside the resolver outputs).
  // Outputs: {
  //   resolved: [
  //     { name, person_link, person_basename, aliases_by_type, matched_via, collision_warning }
  //   ],
  //   unresolved: [<original input string>, ...],
  //   phone_filter_list: [<E.164 string>, ...]   // union of aliases_by_type.phone across resolved
  // }
}

module.exports = { composeInnerCircleAllowlist };
```

**Semantics.**

- `resolved[]`: one entry per resolver output where `resolved === true`. `name` field is the orchestrator-supplied original input string (so downstream agents can match the verbatim engagement-config name). `person_link` and `person_basename` come straight from the resolver. `aliases_by_type` echoed verbatim for downstream LLM consumption.
- `unresolved[]`: original input strings where the resolver returned `resolved === false`. Preserves engagement-config order.
- `phone_filter_list[]`: deduped union of all `aliases_by_type.phone` arrays across `resolved[]`. Used by morning-briefing to populate gather-imessage's existing E.164 `inner_circle` contract.
- Helper is idempotent on null/empty input → returns `{resolved: [], unresolved: [], phone_filter_list: []}`.
- Drops malformed entries silently (entries without `_input`, entries with non-array `aliases_by_type.phone`, etc.).

**No reliance on cowork:resolve-person internals.** The helper consumes already-resolved outputs; the orchestrator does the per-name MCP loop.

**Out of scope for §1.1.**

- No MCP calls inside the helper (caller is responsible for invoking `cowork:resolve-person`).
- No engagement-config schema read (caller is responsible for sourcing `inner_circle_people`).
- No deduplication of identical input names (assume caller's engagement config is clean).
- No collision-warning aggregation across multiple resolved entries (caller surfaces).

## 3. Edge cases & migration

### 3.1 Empty `inner_circle_people`

- Helper returns `{resolved: [], unresolved: [], phone_filter_list: []}`.
- gather-from-served-by dispatch contract omits the "Known people in scope" preamble AND the bullet-list (no allowlist available).
- The ambient soft-prompt paragraph still applies — LLM may still call `cowork:resolve-person` for observed names.
- Morning-briefing passes empty `inner_circle: ""` to gather-imessage (existing contract; previously meant "no filter").

### 3.2 All inner-circle names unresolved

- `resolved` empty, `unresolved` populated, `phone_filter_list` empty.
- Same dispatch behavior as §3.1 (allowlist empty → ambient-only mode).
- Notices + warnings emit per name.
- Distinguishable from §3.1 by the `warnings[]` content.

### 3.3 Engagement type doesn't support inner-circle (e.g., consulting)

- The 5 orchestrators read `engagement.inner_circle_people` regardless of type. Engagement-type schema 0.5.0 already allows the field per-type.
- For engagement types where the field is unset / absent → skip pre-resolution silently (same as §3.1).
- No type-gating in the pre-resolution step itself; gating remains at gather-imessage's existing `personal`-only gate.

### 3.4 Microscope explicitly instructs plaintext

- gather-from-served-by SKILL.md retains "microscope `## Output shape` directives ALWAYS WIN" precedence.
- A microscope that says "emit plaintext display name" still wins locally.
- v0.89.1 does NOT close this gap (FLN-v89-9 stays queued).
- Verify during S3 dogfood whether accuris chat microscope's "resolved canonical display name via people-aliases.md" language causes real-world plaintext leak for Stefan. If so, FLN-v89-9 promotes to next-cycle candidate.

### 3.5 `cowork:resolve-person` MCP unavailable

- Each per-name resolve call returns the null shape (per v0.89.0 contract).
- Helper sees `resolved: false` entries → all names land in `unresolved[]`.
- Allowlist is empty; ambient soft-prompt still applies but it'll also hit null-shape outputs at dispatch time.
- Atomic note renders with plaintext + warnings for every inner-circle name. Acceptable graceful degradation.

### 3.6 Collision warnings

- `composeInnerCircleAllowlist` echoes `collision_warning` per resolved entry.
- gather-from-served-by dispatch contract includes the collision warning in the "Known people in scope" entry when present (e.g., `(aliases ...; collision: Steve A | Steve B)` — textual `collision:` marker only, no emoji glyph, per `no_emojis` compatibility).
- Real-world deploy with collisions surfaces the marker in atomic-note callouts; user can disambiguate manually.
