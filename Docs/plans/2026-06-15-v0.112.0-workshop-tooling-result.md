## Architectural notes

1. **Pure standalone scripts, not `sauce` CLI verbs.** Avoids brew-tap dependency (still stale at v0.84.0). Consumer vaults never see these. If/when brew tap bumps, the scripts can be promoted to `sauce workshop-status` / `sauce regen-cycle-status` verbs in a follow-up cycle.
2. **One script per cycle item.** No shared lib. Each script reads what it needs and writes what it owns. Failure modes are loud + non-fatal (warn + continue when individual signals miss).
3. **macOS-case-insensitive `/Scripts/` gitignore workaround.** The `.gitignore` line `/Scripts/` (capitalized for the workshop's own `Scripts/` activation dir) collides with `scripts/` (lowercase, my target) on case-insensitive macOS filesystems. Three new files force-added past the rule (`scripts/workshop-status.js` / `scripts/regen-cycle-status.js` / `scripts/scaffold-behavioral-harness.js`) — same workaround used at `1085f13` for `scripts/dev-sync.sh`. A v0.112.1 PATCH candidate: rewrite `.gitignore` to use `**/Scripts/sauce` + `**/Scripts/activate.sh` (specific paths) instead of the `/Scripts/` directory rule.
4. **Scaffold script's template diverges from future harnesses' actual structure.** Acknowledged. If v0.113.0+ behavioral harnesses need different boilerplate, the script is one Edit tool call away from updating. Not a maintenance burden in practice.

## Lessons

1. **Tooling-first cycles compound across all subsequent cycles.** Every fresh session paid the 5-10 tool-call onboarding tax. After v0.112.0, one command (`npm run status`) replaces it. The benefit is invisible per-session but visible across weeks — every future cycle starts faster.
2. **Single-doc mini-cycles work for test-only PRs (v0.111.3-CF1), but multi-stage cycles work for tooling sprints.** The 7-stage v0.112.0 cycle had clear handoff points; each stage delivered something verifiable. Resisted the urge to collapse to 1-3 commits — the trace is useful for "when did `regen-cycle-status` ship" debugging.
3. **Auto-edit refusal pays off.** Scaffold script intentionally does NOT touch `package.json release:preflight`. The single-line scripts field is fragile; a misplaced quote breaks all CI. Manual edit is cheap; auto-edit is risky.
4. **macOS case-insensitivity is a recurring gitignore footgun.** Third documented incident (`dev-sync.sh` at 1085f13, then three more files this cycle). Worth a `.gitignore` cleanup PATCH to use specific paths rather than the directory rule.
5. **regen-cycle-status backfill scope decision is meaningful.** Forward-only refresh (default) preserves v0.108.0's full prose by demoting + appending it. Full-history backfill (would have to re-derive v0.109.0 / v0.110.0..2 summaries from their result docs) is a bigger lift; queued as v0.112.1 if signal arrives that the missing history is needed. Right call to ship forward-only first.
