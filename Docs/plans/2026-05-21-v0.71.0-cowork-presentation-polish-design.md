# v0.71.0 — Cowork Presentation Polish (design)

**Cycle:** workshop v0.71.0
**Date:** 2026-05-21
**Scope:** `cowork` 0.11.0 → **0.12.0**; `activity-feed` 0.4.0 → **0.5.0**; `daily` 0.10.1 → **0.11.0**; `_canonical-vocab.json` grows `display_names` map.

## Problem

After v0.68.0 enforced the cowork atomic-note contract and v0.70.x rebuilt the daily Activity panel with the framed renderer + bucket merge, six presentation-layer gaps surfaced when running scheduled cowork jobs against the accuris-sauce vault:

1. **Atomic-note body is plain markdown.** Bodies render as flat `## H2` + bulleted lists. Zero use of Obsidian admonitions, no tables for calendar/email/finance/project data. Bland and visually flat.
2. **No 1–2 sentence summary on cards/feeds.** `CoworkLatestRuns` (`platform/blueprints/cowork/helpers/cowork-latest-runs.js:92-98`) slices the first ~200 chars of body text as a subtitle. There is no curated TL;DR. The `SpaceDailyDashboard` activity panel shows only the filename.
3. **Ugly kebab-case display names.** On the cowork hub Activity panels (which surface cadence-aware groups), the group headers render as `cowork-morning-briefing`, `cowork-eod-review`, etc. (Note: v0.70.0 partially solved this on the *daily dashboard* by bucket-merging into one `cowork` group; the cowork hubs still need per-cadence display names.)
4. **Atomic notes lack nav buttons at top.** Every other note type (scratch, project, meeting, daily, weekly, monthly) opens with a `SpaceNavButtons` dataviewjs block immediately after frontmatter. Cowork atomic notes open with `## Today at a glance` directly.
5. **Cowork hub ActivityFeed panels bleed every blueprint.** The cowork Daily/Weekly/Monthly Hub ActivityFeed calls pass no `blueprints:` filter, so they surface scratch + project + meeting + person + everything alongside the cowork runs they should focus on.
6. **Accuris jobs fail trying to call Google Calendar.** `gather-calendar/SKILL.md` hardcodes the `mcp__claude_ai_Google_Calendar__*` MCP. Accuris (a w2-fte engagement) has no Google Calendar — its calendar lives in Outlook/Teams. There is no per-runtime detection or graceful degradation. Same architectural risk exists for `gather-gmail` and `gather-imessage`.

Two carry-forward items from v0.70.0 also intersect this cycle's scope and can be closed inline:
- "Color individual `cowork-*` sub-type pills" (today they render neutral grey).
- "Optional one-line preview content for collapsed groups" — the `summary:` field this cycle introduces is the natural source.

## Solution overview

Six coordinated changes, layered on top of activity-feed v0.4.0's framed renderer + bucketRules substrate:

1. **`display_names` map** in `_canonical-vocab.json` for the 6 cowork-* atomic-note types. Consumed by an additive `groupLabels` opt on the activity-feed mechanism.
2. **`summary:` required frontmatter field** on all 6 cowork atomic-note types. Validator enforces; write-run-note-* sub-skills emit; render layer prefers `summary` over body-substring.
3. **Nav-button block** prepended as the first body element in every atomic note rendered by a write-run-note-* sub-skill.
4. **Cowork hub ActivityFeed panels** scoped to cowork-* types only, using the framed renderer + cadence-ordered `groupOrder` + `groupLabels` + `getSubtitle` reading the summary field.
5. **Runtime MCP-availability detection** in `gather-calendar`, `gather-gmail`, `gather-imessage`. Skills enumerate MCP options in priority order, pick first-available, emit `gather-skipped: <reason>` cleanly when none. Engagement-type manifests stay declarative (no `mcp_calendar` field). Orchestrators surface warnings as frontmatter + inline admonitions.
6. **Body-shape contract** in the 6 write-run-note-* sub-skill bodies: admonitions (`> [!info]-` synopsis, `> [!example]+` per-section, `> [!tip]` close, `> [!warning]` for skipped gathers), markdown tables for calendar/email/project/finance data, summary emission as the final step before write. Default per-engagement prompts stay short and engagement-specific; body-shape lives workshop-side.

Two bonus deliverables from v0.70.0 carry-forwards:
- **`groupPreviewBuilder` opt** on activity-feed: collapsed groups show a one-line preview (e.g., "Cowork (3) — Punch through prod-deploy approvals; resolve Karen handover scheduling…"), sourced from the most recent run's `summary` field.
- **Cowork-* sub-type pill colors** in `_BLUEPRINT_PILL_COLORS` (daily blueprint): six entries within the blue family, so per-row pills in the bucket-merged daily dashboard carry cadence signal.

## Detailed changes

### `_canonical-vocab.json` — display-name map

Add top-level `display_names` object alongside the existing `types` array:

```json
{
  "types": ["cowork-morning-briefing", "cowork-midday-tripwire", "cowork-eod-review",
            "cowork-finance-snapshot", "cowork-weekly-review", "cowork-monthly-review", ...],
  "display_names": {
    "cowork-morning-briefing": "Morning Briefing",
    "cowork-midday-tripwire":  "Midday Tripwire",
    "cowork-eod-review":       "EOD Review",
    "cowork-finance-snapshot": "Finance Snapshot",
    "cowork-weekly-review":    "Weekly Review",
    "cowork-monthly-review":   "Monthly Review"
  }
}
```

No version field on the rules file. Consumers import and look up by type-string.

### `activity-feed` → 0.5.0

**Two new opts** (both additive; the existing v0.4.0 framed/bucketRules/groupOrder behavior unchanged):

- `groupLabels: Record<string, string>` (default `{}`) — applied at framed-renderer's `.sauce-group-label.textContent` resolution: `groupLabels[key] || humanCase(key)`. Activity-feed stays type-agnostic; the caller supplies the map.
- `groupPreviewBuilder?: (pages: Page[]) => string` (default omitted) — when supplied AND the group is `defaultClosed`, the renderer appends `— <builder(pages)>` to the group summary header text after the existing `(N)` count. The renderer truncates the builder's return at 80 characters and appends a single trailing `…` when truncated. When the builder returns empty string or the opt is omitted, the existing count-only header is preserved.

Manifest bump 0.4.0 → 0.5.0. Description appends a v0.5.0 paragraph naming the new opts.

### `cowork` → 0.12.0

**`platform/blueprints/cowork/manifest.json` rule_fragments** — add to each of the 6 atomic-note types' `required_frontmatter`:

```json
"summary": { "required": true, "type": "string" }
```

Affected types: `cowork-morning-briefing`, `cowork-midday-tripwire`, `cowork-eod-review`, `cowork-finance-snapshot`, `cowork-weekly-review`, `cowork-monthly-review`. The existing validator enforces `required: true` per the rule-fragment pattern; absence fails closed.

**The 6 write-run-note-* sub-skills** at `platform/blueprints/cowork/skills/skills/write-run-note-{morning-briefing,midday-tripwire,eod-review,finance,weekly-review,monthly-review}/SKILL.md` grow a `## Body shape` section instructing Claude to emit, in order:

1. **SpaceNavButtons block** (always first, immediately after frontmatter close):

   ````markdown
   ```dataviewjs
   await dv.view("ranch/views/customjs-guard", { class: "SpaceNavButtons" });
   ```
   ````

2. **Top-of-body synopsis admonition**:

   ```markdown
   > [!info]- Today at a glance
   > <one-paragraph synopsis distilled from gather outputs>
   ```

3. **Per-section blocks** wrapped in `> [!example]+ <emoji> <Section title>` admonitions. Section data renders as:
   - Calendar: `| Time | Event | Attendees | Link |`
   - Email triage: `| Subject | Sender | Intent |`
   - Project status: `| Project | Status | Next action |`
   - Finance accounts: `| Account | Balance | Δ this week |`
   - Finance transactions: `| Date | Merchant | Amount | Category |`
   - Open threads / focus paragraphs: bullets

4. **Warnings** (only when any gather emitted `gather-skipped`):

   ```markdown
   > [!warning] <section name> unavailable
   > <one-line reason from gather output>
   ```

   Placed at the position the affected section would have rendered.

5. **Closing focus admonition**:

   ```markdown
   > [!tip] <emoji> Today's focus
   > <closing 2-3 sentence paragraph + first-action recommendation>
   ```

6. **`summary:` frontmatter emission** as the final compose step before write. 1–2 sentences, ~150–250 chars. Per-cadence lead-in:
   - Morning briefing: today's headline meeting + tone.
   - Midday tripwire: tripwire kind + severity + one-line action.
   - EOD review: day's main win/miss + carryover.
   - Finance: dominant numeric signal (e.g., "Discretionary spend $X this week; 2 cards above target").
   - Weekly/monthly review: period's headline outcome.

**`gather-calendar`, `gather-gmail`, `gather-imessage` SKILL.md** bodies grow a `## MCP routing` section enumerating the MCPs each skill can use, in priority order, with runtime detection logic:

```markdown
## MCP routing

This skill can pull <kind> data from any of the following MCPs, in priority order:

1. <Provider A> — `mcp__<...>__<primary tool>` (note availability)
2. <Provider B> — `mcp__<...>__*` (when wired by user)
3. <Provider C> — `mcp__<...>__*` (when wired by user)

At runtime: introspect on the available tool list. Pick the first MCP whose primary tool
is available. If none are available, do NOT attempt the call. Instead emit:

  gather-skipped: no <kind> MCP available in this Claude Code runtime

Pass `warning: <kind>_unavailable` up to the orchestrator so the atomic note's frontmatter
records it for downstream consumers.
```

Orchestrators (the 5 cadence + finance) accept `warning:` fields from gather outputs and surface them as both:
- a `warnings: string[]` array on the atomic note's frontmatter (e.g., `warnings: [calendar_unavailable, gmail_unavailable]`); the field is optional and omitted when empty.
- a body-shape `> [!warning]` admonition at the position the affected section would have rendered.

The cowork rule_fragments grow an optional `warnings: { type: "string[]" }` field on the 6 atomic-note types (not `required: true` — most runs will omit it).

**15 default per-engagement prompts** at `platform/blueprints/cowork/content/context/engagement-templates/{personal,w2-fte,consulting}/prompts/{morning-briefing,midday-tripwire,eod-review,weekly-review,monthly-review}.md` are updated:
- Drop hardcoded MCP names (e.g., "Google Calendar") from instruction prose.
- Add one-line gather-skipped handling: "If a section's gather emitted `gather-skipped`, render the section's heading with a single `> [!warning]` admonition naming what was unavailable, and continue."
- All engagement-specific guidance (render_aspects, scope hints, which sections to skip) is preserved.

**Cowork hub templates** at `platform/blueprints/cowork/content/spice/cowork/{Daily Hub.md, Weekly Hub.md, Monthly Hub.md}` (exact source paths TBD by implementer — wherever the blueprint sources the hub templates that are materialized to the consumer vault). Each gets an updated ActivityFeed call:

```js
args: [{
  scope: "today",  // "week" for Weekly Hub, "month" for Monthly Hub
  groupBy: "blueprint",
  framed: true,
  limit: 50,
  blueprints: ["cowork-morning-briefing", "cowork-midday-tripwire", "cowork-eod-review",
               "cowork-finance-snapshot", "cowork-weekly-review", "cowork-monthly-review"],
  groupOrder: ["cowork-morning-briefing", "cowork-midday-tripwire", "cowork-eod-review",
               "cowork-finance-snapshot", "cowork-weekly-review", "cowork-monthly-review"],
  groupLabels: <imported from _canonical-vocab.json display_names>,
  getTitle: p => p.frontmatter?.engagement_id || p.file?.name,
  getSubtitle: p => p.frontmatter?.summary || ""
}]
```

The cowork-blueprint helper that reads `_canonical-vocab.json` may need to expose a `coworkDisplayNames()` accessor for use in the dataviewjs block. Implementer decides the import shape.

Manifest bump 0.11.0 → 0.12.0.

## Risks

- **Activity-feed's `summary` HTML element name collides with our `summary:` frontmatter field.** Cosmetic; the implementer must keep DOM-layer `summary` element references and data-layer `frontmatter.summary` reads distinct. Test #2 explicitly exercises both.
- **Line numbers from S0 exploration are stale post-v0.70.x.** Implementer must re-locate every symbol anchor (`_renderGroupedByBlueprint`, `_renderFramedGroup`, framed `<summary>` header construction) by symbol/pattern, not line.
- **Workshop catalogue + per-component manifest lockstep (v0.70.1 lesson).** S10 must bump both `platform/manifest.json` catalogue rows AND per-component `platform/blueprints/<name>/manifest.json` OR the installer skips with stale-pin errors. Pre-flight grep recommended.
- **Test-pin cascade across run-*.js harnesses (v0.70.0 lesson #4).** S9 must grep for stale version pins across all `platform/test/run-*.js` files before preflight to catch the AF / FA4 / FA6 pin chain.
- **Runtime MCP-availability introspection mechanics.** Claude Code surfaces its tool list to the model at session start; the gather-* skills' `## MCP routing` section instructs the model to use that information. If the introspection model later changes (e.g., dynamic tool registration), the gather skills may need to grow a tool-availability helper. Out-of-scope this cycle.
- **Per-engagement prompt update collision.** Users who customized their `spice/cowork/prompts/*.md` files (option (c) at cowork:onboard-scheduled-jobs time) will NOT auto-receive the new defaults. They keep their custom body. The body-shape contract lives workshop-side in write-run-note-*, so this still produces polished output — the per-engagement file just contributes less. Documented in S12 result-doc.
