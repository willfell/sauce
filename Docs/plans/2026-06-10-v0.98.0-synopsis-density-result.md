# v0.98.0 synopsis-density rewrite — result

## TL;DR

Shifts the five cadence atomic notes (morning-briefing, midday-tripwire, eod-review, weekly-review, monthly-review) from a coverage-emphasis shape (every kind enumerated, every per-kind callout open by default, `[!tip] <closing>` at the bottom) to a prediction-emphasis shape (one open `[!info]+ <per-cadence title>` lead callout carrying ≤80-word predictive synopsis; all per-kind callouts collapsed by default behind a click; bottom closing callout REMOVED). The contract change lives at the orchestrator-instructions layer (the LLM-followable composition rules in `content/data/orchestrator-instructions/<cadence>.md`) plus a parallel sweep of the per-engagement-bundle engagement-template prompt headings — scope discovered to be narrower than the plan predicted (3 morning-briefing prompt files only, not all 15).

No new helper exports, no new sub-skill, no new data file, no schema delta on vault-config.md. compose-body-helper.js gained code edits to drop the closing_md contract from the output shape (validation + body assembly + `+` → `-` sigil flip on per-kind wrappers) — scope expanded during S1.4 when fixture preflight surfaced helper-encoded contract that the plan assumed lived only at the OI layer.

Architectural posture: where v0.97.4 made the BEHAVIOR of the brief contractually correct via deterministic backstops in write-atomic-note-helper.js, v0.98.0 makes the SUBSTANCE of the brief lead-of-action correct via composition rules the LLM follows. First cycle of the v0.98.x substance arc (density → questionnaire+capture → ingest). The shelved v0.95.0 cowork-spine arc gains a PARKED banner — its cohesion-sweep premise was obsoleted by the v0.97.x wrapper architecture.

## Goal

Per the user direction captured in memory `project_v098_brainstorm_direction.md` (2026-06-10):

> "Reports too long, too much reading, not enough summarization. ... long term it will give me the info that I need before I need it."

The brief shape today emphasizes COVERAGE (every kind enumerated, every active item described). The user wants emphasis on PREDICTION (the highest-blocking action first; cross-kind dependencies as connective tissue; per-kind detail behind a click). v0.98.0 ships the lead-callout density rewrite as the first cycle of the v0.98.x substance arc. v0.98.1 expands the EOD questionnaire (per-item ticks + per-kind frequency knobs + free-text feedback field). v0.98.2 closes the loop with reconciler free-text + per-item-tick ingest into `learned_weights`.

### The Synopsis composition rules section (verbatim)

Each cadence's `content/data/orchestrator-instructions/<cadence>.md` gains an EOF section:

```
## Synopsis composition rules (v0.98.0 contract)

The synopsis is a single paragraph rendered inside a `> [!info]+ <cadence-title>`
callout. The callout is OPEN by default; it is the reader's first stop and is
expected to carry the load of the brief on its own.

Compose the paragraph per the following rules. Voice contract (vibe,
personality, hard_rules) still applies on top of these rules; structural rules
WIN on conflict.

  1. Length: ≤ 80 words. Hard cap. Prefer 50-60.
  2. First sentence names the highest-blocking action concretely — a PR number,
     a person + decision, an inbound + ask. Never opens with "Today is...",
     "You have...", "There are N...".
  3. Thread cross-kind dependencies as connective tissue when present (e.g.
     "...which gates today's 10am with Stefan..."). Don't enumerate per-kind
     ("first chat, then calendar, then..."); the reader can drill into each
     `[!info]-` / `[!tip]-` / `[!example]-` per-kind callout.
  4. Beyond the lead action, name at most 3 distinct must-knows. Order by
     blocking-effect, not by kind.
  5. If the day is genuinely quiet (no actionable items, no inbox debt, no
     blocking calendar conflicts), say so PLAINLY: "Quiet day — standup +
     Stefan 1:1, nothing else needs attention." Do not pad.
```

(Rule 6 from the design — "Predict the next user action; do not describe the last LLM gather" — was folded into the rule-5 / first-sentence-concrete framing during S1.2 to avoid lecture-vs-rule confusion; the contract still binds.)

## Discoveries and lessons

### 1. Engagement-template H2s are per-bundle, not per-cadence

The plan's S1.3 rename table assumed all 15 prompts shared cadence vocabulary (`## Today's recap`, `## Week in review`, etc.). On-disk reality: 13 of 15 use per-bundle author guidance H2s (e.g. `## Flagged charges`, `## Today's wins`, `## ⏭ Next week setup`, `## ⏱ Billable hours snapshot`). Only the 3 morning-briefing files happen to carry the OLD `## Today at a glance` + `## Today's focus` verbatim. SCOPE NARROWED to those 3 files; the other 12 are author-content and were left untouched. **Lesson for future cycles: verify on-disk vocabulary before designing per-file rename sweeps. A `grep -n '^## ' platform/blueprints/cowork/content/context/engagement-templates/*/prompts/*.md` at design time would have surfaced the 13/15 author-content reality before the plan's 15-file table was committed.**

### 2. compose-body-helper.js encoded the OLD output shape

The plan assumed orchestrator-instructions OI changes drove rendered output; the helper code was supposed to be neutral. Discovery during S1.4: the helper had closing_md validation, hardcoded `+` per-kind sigil in `_wrapCallout` + `_computeAssertions`, closing-line body-assembly emit. Scope expanded to: flip per-kind sigil to `-`, drop closing_md validation, drop closing-line body emit, drop closing_md destructure (with no-op tolerance for legacy inputs containing the key). Regenerated 8 `expected-body.md` files alongside. **Lesson: helper code can encode shape contracts that should be at the OI layer; v0.97.x wrapper architecture should have surfaced this earlier. When designing a "string-level contract change at the OI layer only" cycle, grep the helper for the shape literals (`[!example]+`, `closing_md`, etc.) at design time to confirm they don't live both places.**

### 3. Pre-existing shim path mismatch (carry-forward, NOT v0.98.0-introduced)

`.claude/skills/cowork/morning-briefing/SKILL.md` references `<vault>/.claude/skills/cowork/data/orchestrator-instructions/morning-briefing.md` which does not exist post-install (actual runtime path is `spice/cowork/data/orchestrator-instructions/morning-briefing.md`). Pre-existing — NOT introduced by v0.98.0. Carry-forward candidate for a future cycle (likely v0.98.0.x PATCH or v0.99.0).
