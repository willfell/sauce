# v0.112.0 — Monthly cohesion + paycheck-debt enrichment + Finance landing

## Scope

Three interlocking capabilities ship together in one MINOR cycle (scope option **A**, confirmed at brainstorm):

- **A. PaycheckDebtBand** — a three-band debt-rollup section on every `Paycheck-<YYYY-MM-DD>.md`.
- **B. Months sub-area** — new `spice/finance/months/` with an on-demand `Month-<YYYY-MM>.md` entity (aggregation dashboard + free-text body) and a `Months.md` hub.
- **C. FinanceHubSummary** — the first real landing content on `Finance.md` (currently only a nav row): a debt-forward hero + secondary KPI tiles.

All three share aggregation math, so a new **FinanceMath** helper class is built first and is the foundation the three widgets consume.

This is additive. No mechanism changes, no entity-create schema changes, no contract bump. Established posture throughout: headless-safe migrations, `.sauce-backup/<timestamp>/` snapshots, marker-guarded idempotency, per-file failure-loud, one-line `FinanceNav` everywhere, no emojis, no Claude commit trailer.

## Brainstorm decisions (resolved)

| # | Question | Decision |
|---|---|---|
| Scope | A / B / C | **A — all three in v0.112.0 MINOR** |
| Q1 | Month scaffolding | **On-demand only** (`+ New Month`). No install auto-iteration, no data-driven auto-cards. Month note also carries a **free-text writing body** below the dashboard. |
| Q2 | MonthlyOverview placement | **Month = superset; Budget keeps its band.** Each note stands alone. |
| Q3 | PaycheckDebtBand shape | **Three-band** (consistent with DebtSummary / BudgetSummary). |
| Q4 | MonthsCards click-through | Hub = static list of created Month cards (compact stat line); dashboard lives on the Month note. |

| Q6 | Completeness gate | **Moot** under on-demand — hub lists created entities; no gate needed. |
| Q7 | Finance landing | **Debt-forward hero + secondary tiles.** Resurrect FinanceHubCards' `dv`-shim sub-render pattern; content is new. |
| Arch | Math sharing | **Extract FinanceMath; new widgets only consume it.** MonthlyOverview + DebtsHubSummary untouched this cycle (convergence is a carry-forward). |

## Architecture

### Module layout (new)

```
spice/finance/months/
  Months.md              # hub — FinanceNav + MonthsCards
  Month-<YYYY-MM>.md      # on-demand entity — FinanceNav + MonthDashboard + free-text body
```

Flat per-month entity (mirrors `debts/`, NOT foldered like `paychecks/`/`invoices/`).

### New CustomJS classes (5)

Each is its own file under `helpers/`, one class declaration per file, no `"use strict"`, no module-level functions, nothing after the closing brace (enforced by `caseV01104CustomJsClassFilesAreClean`).

#### 1. `FinanceMath` (`helpers/finance-math.js`) — static-only helper

Canonical home for shared math. Static methods only (precedent: `DocSearch.matches`, `MonthlyOverview.PALETTE`). Pure derivation; never reads `dv.current()`, never writes. Callers pass already-read pages.

Reads (thin wrappers over `dv.pages(...)`, fail-soft to `[]`/`null`):
- `readDebts(dv)` → debt pages (`type === "debt"`)
- `readPaychecksForMonth(dv, monthKey)` → paychecks whose `pay_period_start` starts with `monthKey`
- `readBudgetForMonth(dv, monthKey)` → the single `type === "budget"` page with `month === monthKey`, else `null`

Debt aggregates:
- `debtTotals(debts)` → `{ totalBalance, monthlyInterest, plannedAttack, weightedApr, zeroDebtDate }` — canonicalizes DebtsHubSummary L35-52. `zeroDebtDate` is `"—"` when `plannedAttack − monthlyInterest <= 0`.

Month aggregates:
- `monthIncome(paychecks)` → Σ `paycheck_amount`
- `monthSpending(budget)` → Σ `categories[].actual`
- `monthExpensesTotal(paychecks)` → Σ `expenses[].amount` (all expenses, for Paycheck Totals)
- `monthDebtPaid(paychecks)` → Σ `expenses[].amount` where `paid === true` and `debt` is a non-empty wikilink string
- `debtPaidByDebt(paychecks, { paidOnly })` → `Map<debtLink, { amount, count }>` (per-debt breakdown; `paidOnly` toggles the `paid` filter)

Reconciliation (Q5):
- `measuredMovement(debts, monthKey)` → `{ delta, perDebt: Map<name, {opening, closing, delta, hasSignal}>, hasSignal }`.
  - For each debt: **opening** = balance of the latest `balance_history[]` snapshot dated strictly before `monthKey`'s first day; **closing** = balance of the latest snapshot dated on/before `monthKey`'s last day. Per-debt `hasSignal` requires both to exist (and differ in date). `delta = closing − opening` (negative = paid down).
  - Nearest-at-or-before each boundary, so sparse history still yields a signal and precision improves as snapshots densify. Strictly better than MonthlyOverview's intra-month first/last.
- `reconcile(paydownApplied, measuredMovement)` → `{ paydownApplied, measuredDrop, interestAndCharges }` where `measuredDrop = −measuredMovement.delta` (positive = balances fell) and `interestAndCharges = paydownApplied − measuredDrop` (positive = paydown outran the measured drop, i.e. interest/new charges ate the difference).

Formatting:
- `fmtMoney(n, opts)` → mirror MonthlyOverview `_fmtMoney` (thousands separators, optional `signed`).

Month-key helpers:
- `monthBounds(monthKey)` → `{ first: "<YYYY-MM>-01", lastExclusive: "<next-month>-01" }` for snapshot boundary comparisons (string compare is safe for ISO dates).

#### 2. `MonthsCards` (`helpers/months-cards.js`)

Renders on `Months.md`. Lists `Month-<YYYY-MM>` entities (`type === "month"`), sorted `month` DESC. Each card: month label + compact stat line (income / spending / debt paydown for that month, via FinanceMath), click → `openLinkText`. Empty state: "No months yet. Use + New Month to start one." Embed-deduped (`.fmc-root`), read-only.
- **Display window:** render the most recent 24 month cards; if more exist, append a muted "+N earlier" line. (Caps unbounded growth; years away in practice, but free to add now.)

#### 3. `MonthDashboard` (`helpers/month-dashboard.js`)

Renders on `Month-<YYYY-MM>.md` above the note's free-text body. Guard `page.type === "month"`; embed-deduped (`.mdash-root`); read-only. `monthKey` from `page.month` or filename `Month-(\d{4}-\d{2})`.

Three sections:
- **Budget Analysis** — `readBudgetForMonth`. Planned vs actual totals + variance, per-group rollup (planned/actual/variance, color-coded like BudgetSummary). If no budget: muted "No budget for this month" + a `+ New Budget`-style link to Budgets hub (link only — creation stays on the Budgets hub).
- **Paycheck Totals** — `readPaychecksForMonth`. Σ `paycheck_amount` (income), Σ expenses, paycheck count; optional per-paycheck mini-rows (date + amount, click-through).
- **Debt Changes** — the reconciliation model. Header line: Paydown applied · Measured movement · Interest/charges (derived). Per-debt rows from `debtPaidByDebt` + `measuredMovement.perDebt`; a debt lacking two boundary snapshots shows "snapshot pending" for its measured cell (paydown still shown). When no debt activity at all: muted "No debt activity this month."

Below the dashboard the scaffold seeds a `## Notes` heading — the free-text writing area (Q1). MonthDashboard does not touch it.

#### 4. `PaycheckDebtBand` (`helpers/paycheck-debt-band.js`)

Renders on `Paycheck-*` between PaycheckSummary and PaycheckExpensesEditor. Guard `page.type === "paycheck"`; embed-deduped (`.pdb-root`); read-only. Resolves `expenses[].debt` wikilinks to debt entities at render time.

Three-band (Q3):
- **B1 totals** — debt paydown this paycheck = Σ debt-linked `expenses[].amount` (with a `(X paid / Y pending)` split sub-line); # debts hit; % of `paycheck_amount` going to debt.
- **B2 per-debt rows** — for each distinct linked debt: name, amount in this paycheck, the linked debt's live `current_balance`, paydown-progress chip (`1 − balance/credit_limit` coloring, reused from DebtsHubSummary/PaycheckExpensesEditor). Click → open the debt entity.
- **B3 footer** — aggregate linked-debt balance + planned monthly attack snapshot (from the resolved debt entities).

If the paycheck has no debt-linked expenses: render nothing (no empty band noise).

#### 5. `FinanceHubSummary` (`helpers/finance-hub-summary.js`)

Renders on `Finance.md` (top hub). Guard: only when `filePath === "spice/finance/Finance.md"` (so it never leaks onto other notes); embed-deduped (`.fhs-root`); read-only.
- **Hero** — TOTAL DEBT (large) + projected ZERO-DEBT DATE, with weighted APR + monthly attack as sub-stats (via `debtTotals`). The attack-debt north star. If no debts: a muted "No debt tracked" hero that links to the Debts hub.
- **Secondary tiles** (below hero), each click-through to its sub-hub:
  - This-month budget progress — `readBudgetForMonth(now.YYYY-MM)`: spent / planned + % through month. → Budgets.
  - Latest paycheck — most recent paycheck by `pay_period_start`: amount + date. → Paychecks.
  - Open invoices — count + Σ `amount` of invoices not `Done` (via `FinanceStatus.derive`). → Invoices.

Reuses FinanceHubCards' `dv`-shim pattern only if a tile embeds a cards sub-render; primary surface is KPI tiles.

## Component boundaries (isolation check)

- **FinanceMath** — pure functions; depends only on page shapes. Testable in isolation via IIFE-eval (the v0.110.5 harness pattern). The single source of truth other widgets call; changing a formula is a one-file edit.
- **MonthsCards / MonthDashboard / PaycheckDebtBand / FinanceHubSummary** — each a self-contained renderer that reads `dv.current()`/`dv.pages`, calls FinanceMath for numbers, and paints DOM. None writes. Each guards its own `type`/path and embed-dedupes. A widget can change its layout without touching FinanceMath or any sibling.
- **FinanceNav** — additive case entries; the new modes don't alter existing ones.
- **Migrations** — each independent, marker-guarded, snapshot-backed; safe to re-run.
