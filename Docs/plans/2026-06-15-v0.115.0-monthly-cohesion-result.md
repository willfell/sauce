### 1. NEW `spice/finance/months/` sub-area

On-demand `+ New Month` flow creates `Month-<YYYY-MM>.md` entities. Hub `Months.md` lists created Month notes via `MonthsCards` (sorted DESC by `month`, capped at 24 with overflow line). Each Month entity body holds (a) `MonthDashboard` with Budget Analysis + Paycheck Totals + Debt Changes reconciliation, then (b) a `## Notes` free-text writing area.

### 2. NEW `FinanceMath` static-only helper class

Canonical home for shared aggregation math. Powers all new widgets. Methods: `readDebts`, `readPaychecksForMonth`, `readBudgetForMonth`, `monthBounds`, `debtTotals` (totalBalance / monthlyInterest / plannedAttack / weightedApr / zeroDebtDate), `monthIncome`, `monthSpending`, `monthExpensesTotal`, `monthDebtPaid`, `debtPaidByDebt`, `measuredMovement` (nearest-boundary snapshots per debt — strictly better than MonthlyOverview's intra-month first/last), `reconcile` (paydown applied vs measured drop → derived interest/charges), `fmtMoney`. Existing `MonthlyOverview` + `DebtsHubSummary` are NOT refactored this cycle (convergence is a carry-forward).

### 3. NEW `MonthDashboard` widget

Three-section read-only dashboard on every `Month-<YYYY-MM>.md`. Debt Changes uses the reconciliation model: paydown applied (Σ paid debt-linked expenses) + measured drop (per-debt nearest-boundary balance_history snapshots, "snapshot pending" when fewer than 2 boundary snapshots) + interest/charges (derived gap). Sharpens as `balance_history[]` densifies; the future `gather-cc-debt-snapshot` cowork skill will feed it automatically.

### 4. NEW `MonthsCards` widget

Hub grid (DESC by month, 24-card window, +N earlier overflow). Click → openLinkText to the month note.

### 5. NEW `FinanceHubSummary` widget

Debt-forward landing on `Finance.md` (path-guarded). Hero = TOTAL DEBT + projected ZERO-DEBT DATE + sub-stats (weighted APR / monthly attack / monthly interest). Three secondary tiles: this-month budget progress (bar + days-in-month sub-line), latest paycheck, open invoices (via `FinanceStatus.derive`). Each tile click-throughs to its sub-hub. No-debt fallback hero.

### 6. FinanceNav extension

## Lessons

1. **Build the shared-math foundation first when fan-out is real.** FinanceMath was scoped before any widget. The 3 new widgets each have a 5-15 line render path that delegates ALL arithmetic to FinanceMath. The implementer subagent for Stage A could focus purely on DOM + section shape because the math was already proven. The original brainstorm flagged 5 copies of "project the zero-debt date" as a risk; foundation-first turned that into zero copies.

2. **Concurrent-session collision recovery cost only a version rebaseline.** The plan's content remained authoritative; only `0.112.0 → 0.115.0` and `0.8.0 → 0.9.0` swept. No widget redesign, no architectural change. When a parallel session lands a competing tag, don't rewrite the spec — rebaseline the numbers and add the lockstep fix the intervening cycle missed. Here: `Paycheck Template.md` was out of sync with the manifest `inline_body` after v0.114.0 shipped PaycheckDebtBand to the inline_body but not the template. The rebaseline commit (v0.115.0 B) bundled the lockstep fix at negligible cost.

3. **`balance_history[]` boundary-snapshot semantics matter at month boundaries.** MonthlyOverview's intra-month `_mom` (first/last snapshot within the month) silently shows "no signal" until you have snapshotted twice in one month. FinanceMath.`measuredMovement` switches to nearest-at-or-before each boundary, so even sparse history yields a signal as soon as you have ANY snapshot before the month plus ANY snapshot during/after. Precision improves automatically as cadence densifies. The widget UX ("snapshot pending" per debt) reflects the per-debt signal state rather than the aggregate.
