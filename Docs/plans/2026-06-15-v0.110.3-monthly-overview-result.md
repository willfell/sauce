### NEW `MonthlyOverview` widget

`platform/blueprints/finance/helpers/monthly-overview.js` — pure read-only three-band rollup at the top of every Budget-YYYY-MM.md, ABOVE BudgetSummary:

- **Band 1** — Headline: Income · Spending · Debt paydown · **Net cashflow** (colored). Math: `income − spending − debtPaid = netCash`. Tone: green if positive; amber if loss ≤ 10% of income; red otherwise.
- **Band 2** — Debt mini-row: total debt balance (Σ `current_balance` across debts) + MoM delta (sourced from `balance_history[]` snapshots at first-of-month / last-of-month per debt; falls back to "No MoM signal yet" pill).
- **Band 3** — Tiny audit footer: paycheck count + debt entity count.

Data reads:
- **Income** — `Σ paycheck_amount` across `dv.pages('"spice/finance/paychecks"')` where `pay_period_start.startsWith(monthKey)`.
- **Spending** — `Σ categories[*].actual` on this Budget.
- **Debt paydown** — flatten `expenses[]` across the in-month paychecks, filter `paid: true && typeof debt === "string"`, sum `amount`.

Defensive against undefined / non-array / non-number — `typeof` guards everywhere; no try/catch in math.

### NEW `applyFinanceBudgetMonthlyBandInjection` installer migration

Append-only body migration on every `Budget-YYYY-MM.md`. Anchor priority:

2. BudgetSummary dataviewjs block → inject BEFORE.
3. FinanceStatus.renderBadge block → inject AFTER.

Wired into `applyFinanceMigrations` orchestrator AFTER `applyFinanceBudgetBodyMigration` and BEFORE `applyFinancePaycheckBodyMigration`.

### Bundled regression fixes (parallel-session work in same v0.110.3 commit)

Four user-reported v0.110.2 regressions were fixed in the same commit:

1. **`BudgetNavButtons unavailable` / `PaycheckNavButtons unavailable`** on entity bodies — v0.108.0's `applyFinanceNavRowMigration` only matched DIRECT `customJS.<X>NavButtons.render()` calls. Vaults whose nav-button calls had been converted to the customjs-guard form already (via an earlier guard migration) had bodies like `class: "BudgetNavButtons"` that never got rewritten. Fix: NEW `applyFinanceNavRowGuardFormMigration` sweeps `spice/finance/**` for guard-form class strings referencing deleted classes; idempotent + `.sauce-backup`.
2. **Duplicate finance nav section on top hub** — `spice/finance/Finance.md` rendered both `SpaceNavButtons` AND `FinanceHubActions(here: "finance")`. Fix: NEW `applyFinanceTopHubNavRowDedup` strips the FinanceHubActions block from `Finance.md` only.

Fix: NEW `applyFinanceDefaultsNavRowInjection` injects the block into Defaults notes that lack it.
4. **Template residue** — `Budget Template.md` + `Paycheck Template.md` still referenced `BudgetNavButtons` / `PaycheckNavButtons` (deleted classes) — fixed in same commit to use `FinanceNavRow`.

## Architectural notes

1. **In-flight bundling.** The session started with a v0.110.3 cycle ALREADY in progress (`applyFinanceNavRowGuardFormMigration`, `applyFinanceTopHubNavRowDedup`, `applyFinanceDefaultsNavRowInjection`) addressing four regression reports. The MonthlyOverview work layered cleanly on top — both efforts share `applyFinanceMigrations` orchestrator wiring, and both shipped under the same workshop bump 0.110.2 → 0.110.3 / finance 0.6.2 → 0.6.3. Single integrated PATCH commit `f37aa52` captures the bundle; the dogfood follow-up `f59fe99` ships the post-HC-wiring install artifacts.

2. **Workshop self-install doesn't exercise the migration.** The workshop has no `spice/finance/budgets/<month>/Budget-*.md` files of its own, so `applyFinanceBudgetMonthlyBandInjection` logs `0 scanned, 0 touched` during workshop dogfood. The migration's regression net is the per-cycle behavioral harness (run-renderer.js R-FF8 widget-embed-dedup confirms shape) + the HC-V01103-MO-IDEM idempotency unit test on `_injectMonthlyBand`.

3. **No `.sauce-backup` snapshot policy.** The new migration is append-only marker-guarded body mutation, matching `applyFinanceBudgetBodyMigration` (v0.107.0 CF-2) which has been incident-free across v0.107.0 → v0.108.0 → v0.110.0 → v0.110.3. Snapshot cost across 12+ months × N years of budgets per consumer outweighed the documented value.

## Lessons

1. **Mid-cycle in-flight bundling is reconcilable when both efforts share an orchestrator.** The v0.110.3 cycle started with regression-fix work already in the working tree (uncommitted modifications to `applyFinanceMigrations` orchestrator + 3 new migration helpers). My MonthlyOverview brief/design/plan + helper + migration layered on top without conflict because both efforts wire into the same orchestrator function. Both got committed in one integrated PATCH (`f37aa52`).

2. **Per-cycle VERSION-pin sweep at S4 is mandatory.** Re-confirms landmine #16. The other session's commit bumped workshop_version 0.110.2 → 0.110.3 without sweeping the 13 hardcoded `"0.110.2"` assertion values in `run-helper-cases.js`. My S4 added the sweep; would have been a CI fail otherwise.

3. **Workshop self-install is a useful contract verifier even when the cycle doesn't touch a workshop-subscribed blueprint.** Finance is consumer-only on the workshop, so MonthlyOverview deploy can't be sanity-checked at the workshop root. But the workshop dogfood still validated:
   - install.js syntax (the new `applyFinanceBudgetMonthlyBandInjection` function loads cleanly).
   - `module.exports` registration works (no missing-export crash).
   - The orchestrator wiring change doesn't break workshop-subscribed blueprint installs.

4. **Anchor-regex priority with multi-tier fallback is the right pattern for body migrations.** `_injectMonthlyBand` priority list (BudgetSummary marker → BudgetSummary block → FinanceStatus.renderBadge block → frontmatter close) handles four distinct lineages of Budget bodies (pre-v0.107.0 / v0.107.0 / v0.107.0-CF-2 / v0.108.0+) without per-lineage detection. Same pattern as `_migrateBudgetBody` and `_migratePaycheckBody`.
