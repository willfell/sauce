# v0.99.0 — sparse-signal feedback

## TL;DR

Makes the v0.98.x learning loop correct for a user who gives sparse, prose-flavored
feedback. Today a surfaced-but-unticked kind counts as a SKIP, skips push weights
down (~−0.04/day) and count toward warmup graduation — so a never-ticking user
uniformly demotes everything, and after graduation (headspace: 2026-06-16) the
silence-built weights become authoritative and can gather-skip kinds on quiet days.
Even with zero observations, the kind formula's decay term (`w × 0.98`) walks
weights toward the 0.10 floor (~35 days of pure decay to cross the 0.50 demote
threshold). Silence currently means "user doesn't care"; for this user it means
"user doesn't tick."

Three moves, one MINOR:

1. **Engagement-gated days (ingest side).** Each (engagement, day) is classified
   ENGAGED / TAP-ONLY / SILENT by re-reading yesterday's notes at 03:00. Only
   ENGAGED days emit observations, run decay, and progress warmup. SILENT days
   leave zero trace on weights (audit line only). A lazy one-tap can never demote
   anything. Silence can never build authority.
2. **Prose-first capture (v=3).** The free-text typing box moves to the TOP of the
   EOD feedback section with a one-tap `Useful: [ ] yes [ ] no` pair above it;
   per-item Mattered/Didn't-like lists + knobs keep their exact v=2 mechanics but
   render below, collapsed. A `<kind>:` line-prefix in the prose gets deterministic
   section scoping (the LLM interprets intent but cannot mis-route the kind).
3. **Satisfaction series (schema 4).** The one-tap logs a rolling 30-day yes/no
   series into `learned_weights.totals` — the platform's first cheap KPI, and the
   primary input for the v0.99.1 doctor's self-grading digest. `learned_weights`
   bumps schema 3 → 4; the one-time migration keeps weights + tick counts, ZEROES
   silence-contaminated skip counters, and forces every kind back into warmup —
   defusing the 2026-06-16 silent-graduation deadline by construction.

No new scheduled job; no contract bump (0.35.1 holds); no new installer write
surface under user-owned paths. Cloud jobs pick everything up via one
`align-scheduled-jobs` run per vault post-deploy (Docs/cloud-cowork/, the real
invocation surface per v0.98.2 Discovery 7).

(dimension 3 — the loop now learns correctly from sparse signal instead of
mis-learning from silence) and seeds **Quality observability** (dimension 6 — the
satisfaction series is the doctor's first KPI).

## Decisions locked at brainstorm (2026-06-11)

## Contracts in detail

### C1 — Capture v=3 (compose-feedback-capture-helper.js + eod-review OI + _shared-clauses)

- Section order inside `> [!todo]+ Was today useful?`: (1) one-tap line
  `Useful: [ ] yes [ ] no`, (2) tagged ```feedback fence with placeholder prose
  naming the `<kind>:` convention, (3) per-kind collapsed sub-callouts (EXACT v=2
  mechanics: shared `^item-<kind>-<sha>` block-IDs, Mattered + Didn't-like lists,
  knob row), (4) sentinel `<!-- cowork:feedback-capture v=3 -->`.
- `_parsePrior` accepts v=1, v=2, AND v=3 priors (re-fire preserves tap state,
  prose, ticks, knobs, ambiguity flags). The one night of v=2 notes stays readable
  forever, as does the v=1 night.
- One-tap parse: `yes` ticked → `satisfaction: true`; `no` → `false`; BOTH →
  ambiguous (no log, preserved visually); NEITHER → `null`. Tasks-plugin trailing
  `✅/📅 YYYY-MM-DD` tolerance applies (same regex posture as every tick line).
- EOD-only. Weekly/monthly keep the rating-block shape (carry-forward unchanged).
- `_shared-clauses.md` `feedback_capture_template` reorders to v=3. NO new
  substitution tokens expected (one-tap line is static template text). If
  implementation surfaces a new `{{$token}}`, it MUST land in
  `KNOWN_SUBSTITUTION_TOKENS` in the same commit (v0.98.2 lesson 6).

### C2 — Day classification + gated ingest (learn-from-checks + ingest-feedback helpers + reconcile-cowork OI)

- NEW deterministic classifier (ingest-feedback-helper.js):
  `classifyEngagementDay({notes}) → "engaged" | "tap_only" | "silent"`.
  ENGAGED iff any note for that engagement/day contains ≥1 item tick (Mattered or
  Didn't-like), ≥1 kind-checkbox tick (rating-block cadences), ≥1 knob ≠ `same`,
  or a non-empty typing box. TAP-ONLY iff only the one-tap is set. SILENT
  otherwise.
- ENGAGED day: existing pipeline runs in full — `updateWeights` (decay included),
  entity deltas, knob deltas, warmup progress, `engaged_days[]` append.
  Kind-level observation rule extends: a kind counts TICKED if it has ≥1
  mattered-tick OR ≥1 uprank-intent prose line scoped to it; surfaced kinds with
  neither count as skips (the engaged-day semantics the user chose).
- TAP-ONLY day: append to `satisfaction[]` + audit line `[satisfaction]`. NOTHING
  else — no `updateWeights` call, no decay, no warmup, no `engaged_days[]` entry.
- SILENT day: audit section still written with the `no feedback signal` line
  (v0.98.2 contract preserved). No weight file rewrite beyond migration-on-first-
  touch (see C4).
- Entity decay (`w' = 1.00 + (w − 1.00) × 0.995`) also runs ONLY on engaged days;
  idempotency via `feedback_ingested_days[]` unchanged.
- `<kind>:` prefix fast path: a typing-box line matching
  `/^([a-z][a-z0-9_-]*):\s+(.+)/i` where group 1 case-insensitively matches a
  kind in the engagement's dispatch set is pre-bound to that kind BEFORE Step 3.6;
  the LLM classifies intent (uprank/downrank/frequency/voice/coverage) but CANNOT
  re-scope the kind. Non-matching prefixes (e.g. a person's name) fall through to
  the unmodified LLM extraction.

### C3 — Schema 4 (learned_weights, user-preferences.md frontmatter)

```yaml
learned_weights:
  schema_version: 4
  engagements:
    <eng>:
      per_kind: { ... unchanged shape (weights, ticks, skips, warmup,
                  per_person/per_channel/per_topic) ... }
      totals:
        notes_scanned: N
        notes_with_any_tick: N
        scanned_days: [...]            # unchanged — every processed day
        engaged_days: [...]            # NEW — rolling, engaged days only
        feedback_ingested_days: [...]  # unchanged idempotency key
        satisfaction: [                # NEW — rolling 30 entries
          { day: "2026-06-12", useful: true },
        ]
        warmup_until: null             # superseded — see graduation rule
```

- Graduation rule: warmup ends when `engaged_days.length >= 7` AND the kind's
  `ticks + skips >= 7` (counters only grow on engaged days going forward, so both
  counts are silence-free). `warmup_until` (date-based) is retired as the
  graduation driver; field kept for shape tolerance, set null.
- `normalizeLearnedWeightsV4(raw)` extends the V3 normalizer: tolerates on-disk
  2 / missing / "1.1.0" / 3 / 4. Same block-scoped `.bak`-first write contract.

### C4 — One-time migration (3 → 4, applied at first post-deploy ingest)

Per engagement, per kind: **keep** `weight` and `ticks` (real signal), **zero**
`skips` (silence-contaminated), **force** `warmup: true`. `engaged_days[]` and
`satisfaction[]` initialize empty. Effect: headspace keeps its 2 experimental
days' ticks but sheds all silence-built demotion pressure and re-enters warmup
with a 7-engaged-day runway; accuris is equivalent to fresh. Migration is
idempotent (schema_version stamp gates it) and runs inside the existing
`.bak`-first rewrite — a corrupted write is recoverable from `.bak` exactly as
today.

### C5 — OI layer (single atomic commit, v0.98.1 lesson 3)

- `reconcile-cowork.md`: NEW Step 3.4 (day classification, restating C2's
  deterministic contract inline per the pure-MCP posture); Step 3.5/3.6 gated on
  ENGAGED; Steps 4-5 conditional call-site language; Step 5.5 gains
  `[satisfaction]` audit line tag; SILENT-day "no feedback signal" line retained.
- `eod-review.md`: Step 4 prose describes v=3 order (tap → box → collapsed lists).
- `_shared-clauses.md`: `feedback_capture_template` → v=3.
- `morning-briefing.md`: UNCHANGED (voice proposals etc. untouched).
