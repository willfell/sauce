## Motivation

The v0.74.0 cycle (cowork-orchestrator-rigor) shipped body-shape self-checks, the tripwire-aspects model, and filesystem-first writes. The v0.65.0–v0.74.0 trajectory has built out two of three retrieval modes for cowork's information-access toolkit:

- **Lexical / structural** — filesystem + ripgrep (headless, fast, no deps) — v0.74.0 filesystem-first path.
- **Live runtime ops** — Obsidian Local REST API for Dataview eval, Periodic Notes templates, active-file.

This cycle adds the third mode: **semantic retrieval** via Smart Connections (SC) embeddings. SC is already installed and indexed across 3 of 4 consumer vaults (accuris, ero — both at SC v4.3.0; headspace has SC plugin but no `.smart-env/` yet; barebones has neither and stays that way). The shipping target is to surface conceptually-related notes inside cowork orchestrator output — *without* requiring Obsidian to be running (the cron-fired orchestrators run headless).

The user's three retrieval-mode decision rule (post-v0.74.0):

| Need | Path |
|---|---|
| Lexical / structural / bulk edits | filesystem + ripgrep |
| Semantic "what's conceptually related to X" | **NEW** — sc-bridge CLI over `.smart-env/multi/*.ajson` |
| Live runtime ops (Dataview eval, Templater, active-file) | Obsidian Local REST API |

## Reality check from the real vaults

Two concrete on-disk facts that shaped the design:

1. **Layout is `.smart-env/multi/<sanitized-path>.ajson`**, NOT the flat `smart_sources.ajson` + `smart_blocks.ajson` files the community MCP servers (dan6684, msdanyg) assume. accuris has 3079 such files; ero has 501; headspace has none yet. Each `.ajson` is a single-line JSON-ish object: `"smart_sources:<path>": {"path":"...","last_embed":{...},"embeddings":{"TaylorAI/bge-micro-v2":{"vec":[...]}}}`.
2. **Path keys contain `{{module_directory}}` placeholders** — the index doesn't store raw vault-rooted paths. Any reader must substitute these against the consumer vault's module-directory map (encoded in `ranch/platform-installed.json`).

Both facts argue strongly against depending on a community MCP server. We vendor a thin reader instead.

SC plugin version on indexed vaults: **4.3.0**. Embedding model: **TaylorAI/bge-micro-v2** (384-dim, local, no API/cost). `smart_env.json` config: `smart_sources.min_chars = 200` (sources shorter than 200 chars don't get embedded).

## Architecture overview

Three new pieces, three modified pieces.

### New

- **`platform/mechanisms/smart-connections-bridge/sc-bridge.js`** — Node CLI binary. Three ops:
  - `sc-bridge index-status --vault <root>`
  - `sc-bridge semantic-search "<query>" --vault <root> [...]`
  - `sc-bridge find-related "<vault-rel-path>" --vault <root> [...]`

  Reads `.smart-env/multi/*.ajson` directly. Substitutes `{{module_directory}}` placeholders against `ranch/platform-installed.json`'s module-directory map. Vendors the same embedding model SC uses (`TaylorAI/bge-micro-v2` via `@xenova/transformers`). Returns JSON on stdout. Cold-load cost: ~2–3s on accuris's 3079 files; acceptable for once-per-orchestrator use. No persistent cache in v0.1.0 (flagged followup).

- **`platform/mechanisms/smart-connections-bridge/manifest.json`** — version `0.1.0`; `files[]` materializes `sc-bridge.js` into `.local/mechanisms/smart-connections-bridge/`.

- **`platform/blueprints/cowork/skills/skills/gather-semantic-related/SKILL.md`** — new cowork sub-skill. Calls `sc-bridge` via Bash. Renders the `> [!example]+ 🧩 Related context` callout. Returns markdown + structured `hits[]` + `index_age_minutes`. Gracefully skips when no index.

- **`platform/test/run-smart-connections-bridge.js`** — focused harness covering bridge I/O contract.

### Modified

- **morning-briefing**, **eod-review**, **weekly-review** SKILL.md files — each grows a Gather step calling `gather-semantic-related` + a Write-step instruction interpolating the related-context block + lag-age into the body.
- **write-run-note-morning-briefing**, **write-run-note-eod-review**, **write-run-note-weekly-review** SKILL.md files — `## Adaptive body skeleton` section grows the optional `> [!example]+ 🧩 Related context` callout entry.
- **onboard-scheduled-jobs/SKILL.md** Step 2 — workshop_path resolution fix (S6 carry-forward).
- **`platform/blueprints/cowork/manifest.json`** — new skills[] entry; 0.13.0 → 0.14.0.
- **Engagement-type manifests** (personal/w2-fte/consulting) — additive `render_aspects.semantic_related: "include"`; 0.2.0 → 0.3.0.
- **`sauce update`** CLI — new `--bump-pins` flag (FLN-v67-7 carry-forward).

### Approaches considered and rejected

- **Depend on a community MCP server** (dan6684 / msdanyg). Rejected: community servers assume the older flat-file layout, but SC 4.3.0 on these vaults uses `multi/<sanitized>.ajson` per-source with `{{module_directory}}` placeholders. Pinning to undocumented community-server-version semantics is fragile.
- **MCP server vendored as the primary interface.** Rejected for v0.75.0 in favor of a Node CLI. Adds a long-running process + per-vault config registration. The workshop already ships native Node scripts (claude-surface walker, validator); CLI primitive is idiomatic. MCP wrapper can be added in a later cycle without changing the CLI surface.
- **Inline SC ops inside the cowork blueprint with no new mechanism.** Rejected: catalogue-entry tax is small; semantic retrieval is generic enough that future blueprints (project, daily, journal) plausibly want it. Mechanism harness gives isolation-level testing.

## Bridge CLI surface

### `sc-bridge index-status --vault <root>`

```json
{
  "index_status": "ready" | "absent" | "stale-config",
  "vault_root": "/abs/path",
  "smart_env_dir": "/abs/path/.smart-env",
  "embedding_model": "TaylorAI/bge-micro-v2",
  "source_count": 3079,
  "index_max_mtime_iso": "2026-05-22T18:10:00Z",
  "index_age_minutes": 192
}
```

- `ready` — `.smart-env/multi/` exists with ≥1 parseable `.ajson` AND `smart_env.json` is readable.
- `absent` — `.smart-env/` doesn't exist OR `multi/` is empty.
- `stale-config` — `smart_env.json` declares an embedding model whose vectors aren't present in sampled `.ajson` (defensive; covers model swaps).

### `sc-bridge semantic-search "<query>" --vault <root> [--top-k 3] [--min-similarity 0.45] [--exclude-glob "<pattern>"]`

Embeds `<query>` via `TaylorAI/bge-micro-v2`. Computes cosine sim against every source vector. Returns:

```json
{
  "index_status": "ready",
  "index_age_minutes": 192,
  "query": "<query>",
  "hits": [
    { "path": "spice/projects/.../README.md", "title": "<title>", "similarity": 0.6814, "snippet": "..." }
  ]
}
```

`path` is the substituted vault-relative path (`{{module_directory}}` resolved). `snippet` is the first ~200 chars of the source file (Read on disk, not the embedding).

### `sc-bridge find-related "<vault-rel-path>" --vault <root> [--top-k 3] [--min-similarity 0.45] [--exclude-glob "<pattern>"]`

Loads the anchor file's embedding from `multi/<sanitized>.ajson`. If absent (file too short to embed, or not indexed), returns `{ hits: [], skipped: "anchor-not-indexed" }`. Otherwise: cosine against all others, dedupe self, return top-K above `--min-similarity`.

### Common flags (apply to every op)

- `--vault <root>` — required.
- `--quiet` — suppress stderr progress logs (used when bridge is invoked from inside a Skill via Bash).
- `--json` — reserved for future toggling; stdout is JSON regardless.

### Exit codes

- `0` — success (including `index_status: "absent"` — normal return, not an error).
- `2` — invalid arguments (missing `--vault`, unknown op).
- `3` — vault inaccessible (path doesn't exist, no read perms).
- `4` — index parse error (zero files parseable). Returns `{ index_status: "error", error: "...", offending_path: "..." }`.

Single corrupt `.ajson` files are skipped with a stderr warning; only **zero** parseable files triggers exit 4. This keeps a single bad file from disabling semantic retrieval.

### `{{module_directory}}` substitution

SC stores source paths with a `{{module_directory}}` placeholder (e.g., `{{module_directory}}/cards/2026/05-May/cowork.md`). The bridge resolves these placeholders against the consumer vault's blueprint module-directory registry. The canonical source of that map is **TBD-verify-in-S1** — most likely `ranch/platform-installed.json`'s `blueprints[]` array (where each entry already carries the blueprint id and the module-directory invariant), but the exact field name needs S1 confirmation. If the map isn't present in the form sc-bridge needs, S1 will need to either (a) ship it via the mechanism's install step, or (b) derive it at bridge runtime from `platform/blueprints/*/manifest.json` `module_directory` fields read from `workshop_path`. Verify in S1 before S2 implementation.

### Performance posture (v0.1.0)

Cold-load all `.ajson` files per invocation. ~2–3s on accuris (3079 sources). Acceptable for once-per-orchestrator use. Bridge does not implement batching, caching, or persistent indexing in v0.1.0. If aggregate latency in morning-briefing (potentially 5 calls per fire) proves painful in dogfood, v0.75.x adds `--batch` (JSON-on-stdin) + a memory-mapped cache at `.local/cache/sc-bridge-index.bin`. Flagged followup, not in scope.

### Dependencies

- `@xenova/transformers` for the embedding model (vendored; same model SC uses).
- No filesystem-write side effects from the bridge itself. Pure read-only over `.smart-env/`, file content (for snippets), and `ranch/platform-installed.json` (for module-directory substitution).

## `cowork:gather-semantic-related` sub-skill

### Inputs

```
{
  mode: "find-related" | "semantic-search",
  anchor: string,            // required when mode == "find-related" (vault-relative path)
  query: string,             // required when mode == "semantic-search"
  top_k: int,                // optional, default 3
  min_similarity: float,     // optional, default 0.45
  exclude_globs: list[str],  // optional default ["spice/cowork/daily/**", "spice/cowork/weekly/**", "spice/cowork/monthly/**", ".obsidian/**", ".smart-env/**"]
  callout_title: string      // optional, default "Related context"
}
```

### Output

```
{
  status: "ready" | "skipped:no-index" | "skipped:anchor-not-indexed" | "skipped:no-hits-above-floor",
  index_age_minutes: int | null,
  markdown: string,
  hits: [ { path, title, similarity, snippet } ]
}
```

### Steps

1. **Probe.** `sc-bridge index-status --vault $(pwd) --quiet`. Parse stdout JSON. Capture `index_status`, `index_age_minutes`.
   - `absent` or `error` → return `{ status: "skipped:no-index", markdown: "", hits: [] }`.
   - `ready` or `stale-config` → continue.
2. **Query.** Compose appropriate `sc-bridge` call from `mode`. Capture JSON output.
3. **Branch on hits.**
   - Bridge returned `skipped: "anchor-not-indexed"` → return `{ status: "skipped:anchor-not-indexed", markdown: "", hits: [], index_age_minutes }`.
   - `hits.length == 0` → return `{ status: "skipped:no-hits-above-floor", markdown: "", hits: [], index_age_minutes }`.
   - Else continue.
4. **Render markdown.**
   ```
   > [!example]+ 🧩 <callout_title>
   > - [[<title>]] — <snippet truncated to 80 chars> (sim <similarity:.2f>)
   > - ...
   ```
5. **Return.** `{ status: "ready", index_age_minutes, markdown, hits }`.

### Orchestrator integration contract

- Sub-skill called once per anchor (morning per-event) / once total (eod) / once per week-day with aggregation in orchestrator (weekly).
- Orchestrator always interpolates `> Semantic index age: <N>m` inside the existing `> [!info]- Synopsis` callout, derived from `index_age_minutes`. Even when `hits[]` is empty — the freshness number surfaces every fire.
- When status starts with `skipped:no-index` or `skipped:anchor-not-indexed`, orchestrator appends a one-line `> [!warning]- Semantic index not available` callout near the synopsis. Only once, even if multiple per-event calls all skipped. No warning for `skipped:no-hits-above-floor` (index is fine, just nothing matched).
- The new Related-context callout slots into the v0.74.0 adaptive body skeleton's optional-example-block region; pre-write self-check passes unchanged (existing regex allows multiple `> [!example]+` markers).

## `sauce update --bump-pins` (FLN-v67-7 carry-forward)

### Behavior

Today, `sauce update` (inside a consumer vault) does the brew-installed-workshop → vault sync but does NOT touch `ranch/platform-subscription.json` — that file pins workshop_version + per-blueprint versions and the consumer must hand-bump before re-running.

`sauce update --bump-pins` reads the brew-installed workshop's `platform/manifest.json` (canonical source), then rewrites the consumer vault's `ranch/platform-subscription.json`:

- Top-level `workshop_version` bumps to workshop manifest's `workshop_version`.
- Each entry in `pinned.mechanisms[]` bumps to workshop manifest's mechanism version for that id.
- Each entry in `pinned.blueprints[]` bumps to workshop manifest's blueprint version for that id.
- Mechanisms/blueprints in the workshop manifest but NOT yet in the consumer's `pinned[]` → left alone (subscription opt-in preserved).
- Mechanisms/blueprints in `pinned[]` but missing from the workshop manifest → warning emitted, pin left intact (manual de-subscription required).

After rewrite, the normal `sauce update` flow runs.

### CLI surface

```
sauce update [--bump-pins] [--dry-run] [--keep-comparators]
```

- `--bump-pins` opts in. Default behavior unchanged.
- `--dry-run` (existing or added) shows diff without writing.
- `--keep-comparators` rewrites `^0.13.0`-style comparators as `^0.14.0` instead of canonical-version.

### Output (success)

```
sauce: bumping subscription pins from workshop manifest at
       /opt/homebrew/Cellar/sauce/0.75.0/platform/manifest.json
  workshop_version: 0.74.0 -> 0.75.0
  pinned.blueprints.cowork: 0.13.0 -> 0.14.0
  pinned.mechanisms.smart-connections-bridge: (new -- skipped, not subscribed)
  ... (others unchanged)
sauce: subscription updated; running standard sauce update flow.
```

### Edge cases

- Workshop manifest not parseable → exit non-zero, subscription untouched.
- `--bump-pins` outside a consumer vault → hard error: `sauce: --bump-pins requires a consumer vault; cwd must contain ranch/platform-subscription.json`.
- Empty diff → `sauce: subscription pins already match workshop; nothing to bump.` Continue to normal update flow.

### Files touched

Only one substantive code change in `scripts/sauce-update.js` (or equivalent dispatch). Plus `commands/install.md` and `Docs/agent-guides/build-test-verify.md` updates to reference the new flag.
