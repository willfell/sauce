## 1. Cycle motivation — one skill, two-axis audit

| Axis | Detection | Severity | UX |
|---|---|---|---|
| **Dangling reference** | microscope.md `## References` names a sibling that doesn't exist on disk | High — the agent reads the reference and tries to "use `vip-list.md`" but the file isn't there; agent falls back to no-reference behavior silently | `[!warning]` callout per kind |
| **Orphan sibling** | Sibling file exists on disk but isn't named in microscope.md `## References` | Medium — the gather still injects it (orchestrator step 2c globs the dir), but the agent has no narrative guidance for it | `[!info]` callout per kind |

Both checks live in one skill (`cowork:audit-siblings`) because they share the same vault traversal + share the same use-case ("after I finish a microscope-authoring round, did I leave anything inconsistent?").

**Posture: pure read-only.** No writes. No MCP gather calls. No prompts to fix automatically — surfaces findings, lets the user decide. (Future cycle could add a `--fix` mode that auto-removes dangling references or auto-appends orphan references; explicitly deferred.)

**Cycle scope:** workshop `0.80.1 → 0.81.0` MINOR. cowork blueprint `0.19.0 → 0.20.0` MINOR (new skill + new claude_surface[] entry → CS-MIG-1 counts WILL bump 37→38 / 46→47). Pure additive.

## 2. Architecture findings (from v0.80.0 anchors)

- **Helper-first posture.** v0.80.0's `composeSibling` + `composeMicroscope`'s `## References` block establish the parsing surface. v0.81.0's audit reads what those wrote. Symmetry: writer → reader.
- **Pure helper at `platform/blueprints/cowork/helpers/audit-siblings-helper.js`** (new file). Exports two functions: `parseReferences(microscope_body) → string[]` (extracts names from `## References` block) and `auditSiblings({ kinds_dir_listing, microscope_bodies }) → { dangling: [{kind, name}], orphans: [{kind, name}] }` (pure audit). Both deterministic, harness-testable, no fs or MCP.
- **SKILL.md does the I/O.** The `audit-siblings/SKILL.md` orchestrator-tier skill enumerates `prefs.priorities` kinds → reads each per-kind dir + microscope.md (if present) → calls `auditSiblings()` with the gathered state → renders findings as callouts. Same pattern as `edit-microscope` (helpers pure; SKILL.md owns the MCP/fs surface).
- **Orchestrator dest convention** (v0.79 FLN-v79-4 → v0.80.1 FLN-v79-4 closed): top-level orchestrator → `{{skills_dir}}/audit-siblings/SKILL.md` (NOT nested under `skills/`). Same pattern as `edit-microscope` + `morning-briefing`.
- **Slash command:** `/cowork audit-siblings` (audit all kinds) + `/cowork audit-siblings <kind>` (single-kind audit). The orchestrator handles both shapes — if a positional arg is provided, scope to that kind; else iterate `prefs.priorities`.

## 3. Helper exports (pure)

### 3.1 `parseReferences(microscope_body) → string[]`

**Input:** the full markdown body of a `microscope.md` file (post-frontmatter-strip).

**Output:** ordered array of sibling filenames extracted from `## References` blocks. Empty array if no `## References` section.

**Parsing rules:**

- Find any header matching `/^##\s+References(\s+\(added\))?\s*$/m` (matches both the seed-from-notes branch's `## References` and the deepen-pass branch's `## References (added)`).
- Under each matching header, capture lines matching `/^-\s+\*\*([^*]+\.md)\*\*\s+—/` (bullet starting with `- **<name>.md** — `).
- Stop capturing at the next `## ` header.
- Multiple `## References` blocks (seed + deepen-pass) all contribute; results deduplicated by name (first occurrence wins; preserves the seed-pass entries with role).
- Empty `<name>` is filtered.

**Test cases (HC):**
- `HC-V0810-A1` — seed-pass References block with 2 entries → `["contacts-map.md", "vip-list.md"]`
- `HC-V0810-A2` — no References section → `[]`
- `HC-V0810-A3` — deepen-pass References (added) block with 1 entry → `["contacts-map.md"]`
- `HC-V0810-A4` — both seed + deepen-pass blocks → dedupe across them

### 3.2 `auditSiblings({ kinds_dir_listing, microscope_bodies }) → { dangling, orphans }`

**Input:**

- `kinds_dir_listing` — object `{ <kind_name>: [<filename>, ...] }` mapping each kind to the list of `.md` files in its `per-mcp/<kind>/` dir. List should already be filtered to exclude `microscope.md` and `^_.*\.md$` files (caller's responsibility — SKILL.md does the glob + filter).
- `microscope_bodies` — object `{ <kind_name>: <body string> }` mapping each kind to its `microscope.md` body (post-frontmatter-strip), OR omitted/null for kinds without a microscope.

**Output:**

```
{
  dangling: [{kind, name}, ...],  // referenced in microscope but file absent
  orphans:  [{kind, name}, ...],  // file exists but not referenced
}
```

Both arrays sorted by `(kind, name)` for stable output.

**Audit logic:**

For each kind in the union of `Object.keys(kinds_dir_listing)` and `Object.keys(microscope_bodies)`:
- `referenced` = `parseReferences(microscope_bodies[kind] || "")` (Set)
- `existing` = `new Set(kinds_dir_listing[kind] || [])`
- For each name in `referenced` but NOT in `existing` → push `{kind, name}` to `dangling`
- For each name in `existing` but NOT in `referenced` → push `{kind, name}` to `orphans`

Kinds with neither a microscope nor any siblings contribute nothing (no-op).
Kinds with siblings but no microscope contribute orphans for each sibling (because there's nothing to reference them).

**Test cases (HC):**
- `HC-V0810-B1` — kind has microscope.md referencing `vip-list.md` + file is absent → 1 dangling, 0 orphans
- `HC-V0810-B2` — kind has microscope.md (no References) + `vip-list.md` file → 0 dangling, 1 orphan
- `HC-V0810-B3` — clean state (microscope.md references all existing files; no missing; no extra) → 0/0
- `HC-V0810-B4` — kind with no microscope.md + sibling files present → 0 dangling, N orphans (one per file)
- `HC-V0810-B5` — kind with microscope.md + no siblings → 0/0
- `HC-V0810-B6` — output sorted by `(kind, name)` deterministically across multiple kinds

## 4. `cowork:audit-siblings` SKILL.md

**Path:** `platform/blueprints/cowork/skills/orchestrators/audit-siblings/SKILL.md`
**Dest (consumer):** `{{skills_dir}}/audit-siblings/SKILL.md`
**Slash command:** `/cowork audit-siblings` (no-arg) or `/cowork audit-siblings <kind>` (single-kind)

### 4.1 Inputs frontmatter

```yaml
inputs:
  kind: string | null   # optional positional; null → audit all kinds in prefs.priorities
```

### 4.2 Steps (in SKILL.md prose)

1. **Read preferences.** Call `cowork:read-user-preferences` to load `prefs` (specifically `prefs.priorities` list).

2. **Resolve scope.** If input `kind` is set → `kinds = [kind]` (after verifying it's in `prefs.priorities`; if not, return error). Else → `kinds = prefs.priorities`.

3. **Gather per-kind state.** For each `kind_name` in `kinds`:
   - List the contents of `spice/cowork/prompts/per-mcp/<kind_name>/` via `mcp__obsidian__list_files_in_dir`. Treat dir-not-found as empty.
   - Filter to `*.md`, EXCLUDE `microscope.md` and `^_.*\.md$`. The remaining list goes into `kinds_dir_listing[kind_name]`.
   - Read `microscope.md` via `mcp__obsidian__get_file_contents` if present (treat not-found as absent). Strip leading frontmatter; capture as `microscope_bodies[kind_name]`.

4. **Call the helper.** `const { dangling, orphans } = auditSiblings({ kinds_dir_listing, microscope_bodies });` (helper at `platform/blueprints/cowork/helpers/audit-siblings-helper.js`).

5. **Render findings.** For each `{kind, name}` in `dangling`:
   ```
   > [!warning] Dangling sibling reference
   > Kind: <kind>
   > `microscope.md`'s `## References` names `<name>` but no such file exists at `spice/cowork/prompts/per-mcp/<kind>/<name>`.
   > Did you delete the sibling? Or forget to scaffold it? Re-run `/cowork microscope <kind>` to re-author + scaffold, or hand-edit `microscope.md` to remove the dangling reference line.
   ```
   For each `{kind, name}` in `orphans`:
   ```
   > [!info] Orphan sibling file
   > Kind: <kind>
   > `<name>` exists at `spice/cowork/prompts/per-mcp/<kind>/<name>` but is not listed in `microscope.md`'s `## References` section.
   > The gather will still inject it (siblings are glob-discovered, not microscope-driven), but `microscope.md` should document why this sibling exists. Re-run `/cowork microscope <kind>` and during step 4 the skill will record a `{name, role}` reference; or hand-add a `- **<name>** — <your role description>` line to `microscope.md`'s `## References` section.
   ```

6. **Summary.** If `dangling.length === 0 && orphans.length === 0`:
   ```
   > [!success] All sibling files consistent
   > Audited <N> kind(s) — no dangling references, no orphan files.
   ```
   Else emit a one-line totals tail: `Audited <N> kinds; <D> dangling reference(s), <O> orphan file(s).`

### 4.3 Outputs frontmatter

```yaml
outputs:
  dangling: list[{kind, name}]
  orphans: list[{kind, name}]
  kinds_audited: int
```

(Helper return shape echoed verbatim + a count for the summary line.)

## 5. Failure-mode matrix

| Failure | Detected at | Response |
|---|---|---|
| `prefs.priorities` empty | SKILL step 2 | Emit `[!info]` "No kinds in prefs.priorities — nothing to audit. Run `/cowork preferences` first." Exit cleanly. |
| Specified `kind` not in priorities | SKILL step 2 | Emit `[!warning]` "Kind `<kind>` is not in your `prefs.priorities`. Available kinds: <list>." Exit cleanly. |
| `per-mcp/<kind>/` dir missing for ALL kinds | SKILL step 3 | All `kinds_dir_listing` arrays empty + `microscope_bodies` empty → audit returns `{dangling: [], orphans: []}` → summary `[!success]` (nothing to inconsistency). Functionally correct. |
| `microscope.md` present + non-empty + no `## References` section | helper | `parseReferences` returns `[]` → no dangling possible; orphans flagged for every sibling file in the dir (since none are referenced). Correct behavior — the user authored a microscope without recording siblings. |
| Malformed `## References` entry (wrong bullet shape) | helper | Regex skips it; entry not in `referenced` set; if the file actually exists, it gets flagged as orphan. Acceptable graceful degradation. |
| Sibling file with frontmatter | SKILL step 3 | Frontmatter-stripping applies to microscope.md only; siblings listed by filename, not body. Frontmatter doesn't affect audit. |

**Legacy preservation:** vault with no `per-mcp/` dir at all → audit returns clean. Pre-v0.81.0 vaults aren't broken (the skill is new + opt-in via slash command).

## 11. Carry-forward (deferred to a follow-up cycle, by design)

Explicit FLN candidates surfaced during this design but OUT of v0.81.0 scope:

- **`--fix` mode for audit-siblings** — auto-remove dangling references from microscope.md; auto-append orphan references with a TODO role string. Skip for now; the audit is informational + the user is the one who knows the intended state.
- **Validation of `## References` role strings** — e.g., flag refs where `role` is empty or "TBD" or "(role unspecified)". The v0.80.0 helper emits `(role unspecified)` as a fallback when role is missing; audit could flag those as "needs role text." Defer until a real pattern of TODO-roles surfaces in practice.
- **Pre-commit hook** — auto-run audit-siblings whenever microscope.md or per-mcp/<kind>/ changes. Would catch inconsistency at write-time. Out of scope; users can run `/cowork audit-siblings` on demand.
- **Multi-vault audit** — audit all consumer vaults from the workshop in one pass. Mostly useful for maintainers, not end-users.
- **Sibling-body validation** — verify each sibling file is non-empty + has a heading + has a table or list. Currently the audit only checks existence/reference symmetry. Body validation is opt-in via a future `--strict` flag.

## 12. Open questions resolved during design

- **Q: Single skill with two checks, or two skills (one per axis)?** A: Single skill. Both checks share vault traversal + same use-case ("after authoring, did I leave anything inconsistent?"). Splitting would force the user to run two commands.
- **Q: Should orphan detection be opt-in?** A: No. Orphans are silently degrading (briefing lacks narrative for the sibling); user should know.
- **Q: Render mode — single combined callout, or per-finding callouts?** A: Per-finding. Each callout is independently scannable + copy-pasteable into a microscope re-author prompt.
- **Q: What about kinds in `prefs.priorities` but not yet authored (no microscope.md + no siblings)?** A: Audit skips them silently — there's nothing to be inconsistent about. The user-supplied gap path (v0.80.0) is the right tool for scaffolding initial state, not the audit.
- **Q: `[!success]` callout type — is it in the v0.79.0 styling palette?** A: Yes — `sauce-callouts.css` defines per-type color for `success` (rose-pine-light green / melange-dark green). Safe to use.
