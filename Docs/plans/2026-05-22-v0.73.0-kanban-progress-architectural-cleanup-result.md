## What shipped

### Part A — `kanban-status-sync@0.2.0`: startup-script architecture

NEW `KanbanStatusSyncInit` customjs class at `platform/mechanisms/kanban-status-sync/kanban-status-sync-init.js`. Registered in each consumer's `.obsidian/plugins/customjs/data.json:startupScriptNames[]` via the mechanism manifest's `customjs_startup_scripts[]` field.

`invoke()` is the customjs entry point:
1. `_registerResyncCommand()` adds the Part C command (idempotent via `_commandRegistered` guard).
2. `_runStartupSync()` awaits Dataview-readiness (`_waitForDataview` polls `app.plugins.plugins.dataview?.api` every 250ms up to 30s), then calls `customJS.KanbanStatusSync.syncAllBoards(dv, today)`. Cache-hit on subsequent invocations (per the v0.72.1 once-per-day cache).

`SpaceDailyDashboard.render` no longer references `customJS.KanbanStatusSync.syncAllBoards`. The dashboard reads pre-synced frontmatter; the sync runs once per session at startup, never inside the dataviewjs hot path.

### Part B — `activity-feed@0.7.0` + `daily@0.13.0`: persisted `<details>` state

State persists to `ranch/cache/dashboard-section-state.json` (best-effort; missing-file or malformed-JSON falls back to default-open semantics). Schema:

```json

  "states": {
    "sauce-daily-dashboard:tasks":    true,
```

Added to `SpaceDailyDashboard`:

- `_writeSectionStateKey(key, value)` — async; last-write-wins, creates `ranch/cache/` on first write.
- `_renderSection` accepts `stateKey` + `sectionState` opts; overrides `defaultOpen` when state has a value; attaches a `toggle` event handler that writes back.

Added to `ActivityFeed`:

- `render()` made `async`; reads `groupState` once per render (guard: real `app.vault.adapter` only, so Node harness path stays synchronous).

- `_renderFramedGroup` overrides the `!isClosed` default with persisted state per-group; toggle event writes back.

### Part C — manual re-sync command

Inside `KanbanStatusSyncInit.invoke()`:

```javascript
app.commands.addCommand({
  id: "kanban-status-sync:resync-now",
  name: "Sauce: Re-sync kanban boards",
  callback: async () => {
    customJS.KanbanStatusSync._lastSyncDay = null;
    customJS.KanbanStatusSync._lastSyncResult = null;
    const dv = app.plugins.plugins.dataview?.api;
    const today = window.moment ? window.moment().format("YYYY-MM-DD") : new Date().toISOString().slice(0,10);
    const r = await customJS.KanbanStatusSync.syncAllBoards(dv, today);
    new Notice(`Kanban re-sync: ${r.synced} synced, ${r.archived} archived across ${r.boards} boards`, 6000);
  },
});
```

Surfaces via Cmd+P → "Sauce: Re-sync kanban boards".

## Lessons + carry-forwards

1. **Architecture lesson — never put bookkeeping inside the dataviewjs hot path.** v0.72.0 shipped the inline `syncAllBoards` trigger; we then layered a cache (v0.72.1) on top to mask the re-render storm. Both were patches against a structural mistake. The root fix is moving the work to the boot path. Future: any persistent state mutation tied to a render surface should run at vault startup or via an explicit user command, never as a render side-effect.
2. **Harness lesson — `app` shimming in the Node harness has subtle async semantics.** Type-of guards must check for a real `vault.adapter`, not just `typeof app !== "undefined"`, when deciding whether to enter an `await` path. Otherwise calling an async function that hits an `await` yields back to the caller and breaks synchronous DOM assertions.
3. **Landmine #16 reaffirmed.** Workshop self-install short-circuited (skipped re-materialization of the kanban-status-sync mechanism + the new init file) until the version bumps landed. Plan accommodated this by deferring `node platform/test/run-install.js .` until AFTER the cycle-close bumps. If you forget, the symptom is a missing materialized file + a missing `startupScriptNames[]` entry — fix is to bump.
4. **Test description-version assertions decay.** AF-V065 ("description mentions 0.2.0") was a v0.2.0-era regression-protection assert. The v0.7.0 trim invalidated it. Replaced with a forward-looking check (description mentions current shipping version). Same pattern applies to FA6-MANIFEST + AF-1d + KSS-1d — they're maintenance-coupled to every cycle close.
5. **Smart-connections diagnostic — still open.** The user has NOT yet temporarily disabled smart-connections in accuris to confirm/refute the strong-correlation hypothesis. The v0.73.0 fix ships regardless — both Part A (remove our code from the hot path) and Part B (state survives re-renders) are net wins independent of who's firing the re-render. If the user reports back: a confirmed correlation becomes landmine #24 candidate (dataviewjs blocks re-execute on smart-connections embedding-queue activity); a refutation routes to the next cycle's investigation queue.
6. **`groupPreviewBuilder` gating decision** — documented inline + in cycle-history. Builder fires for manifest-`defaultClosed[]`, NOT state-closed groups. Future cycle that revisits this should respect the contract or land a manifest knob (`previewOnStateClose: true`) instead of changing the default.
7. **FLN-v67-7 still unresolved** — consumer subscription pin auto-bump remains a manual step. The deploy phase of this cycle ran a 4-vault `node -e "..."` loop to bump pins, then `cd && sauce update --force` per vault. Candidate `sauce update --bump-pins` flag deferred to a future cycle.
