# v0.95.1 design — `sauce migrate-config`

This is the design for the cycle that closes the v0.95.0 backward-compat one-cycle window. v0.95.0 introduced an additive optional `overrides: {}` block on engagement records in `spice/cowork/context/vault-config.md` with backward-compat reads in `composeFinalPreferences` + `_parseEngagementByIdFromYaml`. v0.95.1 ships a migrator that inserts the empty block into every engagement record AND removes the backward-compat fallback in the same PR.

## Goal

Engagement records become guaranteed to carry an explicit `overrides:` block. The layered preferences tree (`bundle ⨁ overrides ⨁ ad_hoc → final`, locked Q4 in cowork-vision) reaches its terminal shape: `overrides` is no longer optional. Engagement-types remain pure named knob bundles per Q2.

## Non-goals

- **Not a general migration engine.** v0.95.1 ships a one-shot helper named for its specific job. If v0.96.0+ needs another schema migration, that cycle ships its own helper.
- **Not a frontmatter repair tool.** Pre-existing malformed vault-config.md (closing-fence missing, unbalanced fences, etc.) causes the migrator to abort with a Notice. A separate cycle owns frontmatter repair if needed.
- **Not staggered.** Migrator + backward-compat fallback removal land in the same PR. The 2-consumer-vault posture (user-controlled upgrade order) makes the atomic cutover safe.
- **Not an `applied-migrations.json` tracker.** Idempotency comes from content-detection (re-reading vault-config.md and skipping engagements that already have the block). No state file.

## Invocation surface

```bash
sauce migrate-config              # default: dry-run + report what would change
sauce migrate-config --apply      # write .bak + modified vault-config.md
```

NEW top-level verb mirroring `sauce migrate-frontmatter` + `sauce migrate-layout` shape. Default is dry-run (per `cmd-migrate-frontmatter.js` precedent — the safer default for any write-side migration); opt into writes with `--apply`. No flag on `cmd-update.js`; that verb stays focused on bump-pins.

Deploy sequence per consumer vault:

```bash
sauce update --bump-pins      # pin cowork 0.32.0 → 0.32.1 + workshop 0.95.0 → 0.95.1
sauce migrate-config          # dry-run review
sauce migrate-config --apply  # commit migration
```

Two separate invocations make the dry-run review the default path — the user sees what will change before any write hits disk.

## Migrator behavior (per engagement record)

The vault-config.md frontmatter contains an engagements list. For each engagement block:

1. **Locate the engagement block.** Start at `^- id: <slug>` and end at the next `^- id: ` line OR the frontmatter closing `\n---\n`.
2. **Scan the block for an existing `overrides:` key.** Match `^\s*overrides:\s*` anywhere in the block. This catches BOTH compact (`overrides: {}`) AND multi-line block-header (`overrides:` followed by indented children).
3. **If present → skip.** Record in `skipped[]`. Idempotent re-runs hit this branch.
4. **If absent → splice in `  overrides: {}`** as a new line immediately after the engagement's last known property key, before the engagement-block terminator. Indent to match the engagement's existing field indentation (2-space convention per current schema).
5. **Record in `changed[]`.**

Splice point selection:
- Walk the engagement block bottom-up until finding the last non-empty, non-comment line whose indentation matches the field-level indent (2 spaces by current convention).
- Insert the new line immediately after that.
- This preserves any trailing comments or blank lines at the block's end.

## Helper shape

NEW file: `platform/blueprints/cowork/helpers/migrate-vault-config-helper.js` (alongside `dispatch-plan-helper.js`, `read-user-preferences-helper.js`, etc.).

```js
// migrate-vault-config-helper.js — v0.95.1
//
// Pure helper. No I/O. Caller passes file content as string; helper returns
// modified string + per-engagement report. Caller writes .bak + modified.
//
module.exports = {
  addEmptyOverridesBlock,   // (content: string) → { modified, changed, skipped, errors }
  // module-private (test access):
  _findFrontmatterBoundaries,
  _findEngagementBlocks,
  _hasOverridesKey,
  _spliceOverridesBlock,
  _detectIndentation,
};
```

Per existing convention, the helper is wired into cowork's `manifest.json` `files[]` so it materializes into consumer vaults at `spice/cowork/helpers/migrate-vault-config-helper.js`. The CLI verb (in workshop `platform/cli/`) requires it via the same workshop-resolved path the other cowork helpers use.

`addEmptyOverridesBlock` return shape:
```js
{
  modified: "<modified file content>",
  changed: ["accuris", "headspace"],         // engagement ids that got the block inserted
  skipped: ["workshop"],                     // engagement ids that already had the block
  errors: [],                                // hard errors (malformed frontmatter, etc.)
}
```

If `errors[]` is non-empty, `modified === content` (no change to caller's input). Caller MUST check `errors[]` before writing.

## CLI command wiring

NEW file `platform/cli/cmd-migrate-config.js` mirroring `cmd-migrate-frontmatter.js` shape (test-hook seam, `_parseFlags`, `run`). Sketch:

```js
// platform/cli/cmd-migrate-config.js — `sauce migrate-config` verb (v0.95.1).
//
// Inserts an empty `overrides: {}` block into every engagement record in
// spice/cowork/context/vault-config.md that doesn't already carry one.
// Default mode is dry-run; --apply is the only write site.

"use strict";
const fs = require("fs");
const path = require("path");

// Test-hook seam (mirrors cmd-bootstrap / cmd-migrate-frontmatter).
exports._helperImpl = null;

exports._parseFlags = function(argv) {
  const flags = { apply: false };
  for (const a of argv || []) {
    if (a === "--apply") flags.apply = true;
  }
  return flags;
};

exports.run = async function(ctx, args) {
  const flags = exports._parseFlags(args);
  const vaultRoot = ctx.vaultRoot;
  const target = path.join(vaultRoot, "spice/cowork/context/vault-config.md");

  if (!fs.existsSync(target)) {
    console.error(`error: no vault-config.md at ${target}`);
    process.exit(2);
    return;
  }

  const content = fs.readFileSync(target, "utf8");
  const helper = exports._helperImpl
    || require(path.join(vaultRoot, "spice/cowork/helpers/migrate-vault-config-helper.js"));
  const result = helper.addEmptyOverridesBlock(content);

  if (result.errors.length > 0) {
    console.error(`migrate-config aborted: ${result.errors.join("; ")}`);
    process.exit(2);
    return;
  }

  const changedSummary = result.changed.length === 0
    ? "(none)"
    : `${result.changed.length} (${result.changed.join(", ")})`;
  const skippedSummary = result.skipped.length === 0
    ? "(none)"
    : `${result.skipped.length} (${result.skipped.join(", ")})`;

  if (!flags.apply) {
    console.log(`[dry-run] would change: ${changedSummary}`);
    console.log(`[dry-run] would skip:   ${skippedSummary}`);
    console.log(`re-run with --apply to write changes.`);
    return;
  }

  if (result.changed.length === 0) {
    console.log(`migrate-config: no-op (all ${result.skipped.length} engagement(s) already have overrides:)`);
    return;
  }

  fs.copyFileSync(target, `${target}.bak`);
  fs.writeFileSync(target, result.modified);
  console.log(`migrate-config applied: changed ${changedSummary}; skipped ${skippedSummary}`);
  console.log(`backup: ${target}.bak`);
};
```

Dispatch wiring lands in `platform/cli/sauce-cli.js` (NOT `registry.js`, which is the per-machine vault registry). Three sites:

1. `VERBS` const map at top — add `"migrate-config": "./cmd-migrate-config.js"`.
2. Dispatch if-branch (mirroring the `migrate-frontmatter` branch shape):
   ```js
   if (verb === "migrate-config") {
       const cmd = require(VERBS["migrate-config"]);
       const testCtx = opts || {};
       await cmd.run(testCtx, rest);
       return;
   }
   ```
3. Usage strings — the `unknown verb` error message + the `cmd-help.js` help text both list available verbs; add `migrate-config` to both.

## Backward-compat fallback removal (atomic in same PR)

Three sites change in `dispatch-plan-helper.js`:

### Site 1 — `composeFinalPreferences`

```js
// BEFORE (v0.95.0):
function composeFinalPreferences({ bundle, overrides, ad_hoc_prefs }) {
  const ov = overrides || {};   // ← backward-compat fallthrough
  // ... merge bundle ⨁ ov ⨁ ad_hoc_prefs
}

// AFTER (v0.95.1):
function composeFinalPreferences({ bundle, overrides, ad_hoc_prefs }) {
  if (overrides === undefined || overrides === null) {
    throw new Error("composeFinalPreferences: overrides is required (run `sauce migrate-config --apply`)");
  }
  // ... merge bundle ⨁ overrides ⨁ ad_hoc_prefs
}
```

### Site 2 — `_parseEngagementByIdFromYaml`

```js
// BEFORE (v0.95.0):
return {
  ...engagement,
  overrides: parsedOverrides || null,   // ← backward-compat synthesis
};

// AFTER (v0.95.1):
return parsedOverrides
  ? { ...engagement, overrides: parsedOverrides }
  : { ...engagement };                  // no overrides field; caller detects + throws
```

### Site 3 — `readEngagement`

```js
// BEFORE (v0.95.0):
return { engagement, bundle, overrides: engagement.overrides, status: "ok" };

// AFTER (v0.95.1):
if (engagement.overrides === undefined) {
  return {
    engagement: null, bundle: null, overrides: null,
    status: "failed:engagement:missing-overrides",
    reason: `engagement ${engagement_id} has no overrides: block; run \`sauce migrate-config --apply\``
  };
}
return { engagement, bundle, overrides: engagement.overrides, status: "ok" };
```

## Failure modes

| Token | Cause | Surface | Recovery |
|---|---|---|---|
| (helper) `errors[]` non-empty + `modified === content` | malformed frontmatter (closing fence missing/unbalanced) OR `engagements:` list absent | migrator | abort CLI verb with exit code 2; vault-config.md untouched |
| (CLI) `process.exit(2)` | helper reported errors | `sauce migrate-config` (dry-run) or `--apply` | user hand-fixes frontmatter, re-runs |
| (orchestrator runtime, NEW) `failed:engagement:missing-overrides` | post-v0.95.1 cron fires against engagement with no `overrides:` block (migration not yet run, or block hand-deleted) | orchestrator pre-flight step 3b | `plan.dispatch_mode = "legacy"`; orchestrator emits Notice citing `prefs_status`; falls through to legacy gather |

## Risks + mitigations

| Risk | Likelihood | Mitigation |
|---|---|---|
| Frontmatter round-trip corruption (v0.90.3-style closing-fence bug) | LOW (surgical insertion preserves bytes; no re-emit) | Approach 1 selected over Approach 2 for this reason; HC-V0951-A4 multi-engagement fixture asserts byte-identical preservation of unchanged engagements |
| User upgrades brew BEFORE running migrator → next cron hits `failed:engagement:missing-overrides` | MEDIUM | Orchestrator's legacy-mode fallthrough preserves atomic-note generation; Notice cites the recovery command (`sauce migrate-config --apply`); brew-tap PR body documents the per-vault deploy step |
| Workshop's own vault-config.md (dogfood) hits the migration in S2 | EXPECTED | S2 dogfood install runs the migrator against the workshop vault-config.md as part of normal dogfood flow; sets the precedent for consumer deploys |
| 7-day v0.95.0 observability window finds a regression that demands a v0.95.0.x PATCH before v0.95.1 | MEDIUM | v0.95.1 design durable regardless of v0.95.0.x; ship v0.95.0.x first if needed, then v0.95.1; design doc commits tonight so the work doesn't decay if delayed |
| `--migrate-config` runs against a vault with NO cowork blueprint installed (e.g., bare consumer that doesn't subscribe to cowork) | LOW | Helper aborts with `errors: ["no vault-config.md at <path>"]`; CLI exits 2; documented in failure-modes table |

## Deliberate omissions (queue as v0.95.1.x / v0.96.0+ FLNs)

- **FLN-v951-1** — `sauce migrate-config` could chain off `sauce update --bump-pins` (auto-invoke on every pin bump). Deferred per safer-default sequencing decision (explicit verb makes the write opt-in via `--apply`); revisit if invoking three commands per vault proves friction-y.
- **FLN-v951-2** — Pre-migration dry-run preview in CLI emits the would-be diff (line-by-line splice). Deferred; current default dry-run reports only changed/skipped ids.
- **FLN-v951-3** — Migrator does NOT touch the workshop vault's OWN engagement-types JSONs (e.g., adding new top-level knobs). Out of scope; engagement-types schema is owned by the cowork blueprint's manifest sync flow.
- **FLN-v951-4** — A general migration registry pattern (the rejected Approach 2 from this design's brainstorm). If v0.96.0+ ships 2+ migrations within a few cycles, revisit; one-shot helpers are sufficient through v0.95.x.
- **FLN-v951-5** — Pre-existing partial `overrides:` blocks with malformed YAML inside (e.g., `overrides: render_aspects:` with a key missing its value). The migrator's `_hasOverridesKey` detection regex matches "any overrides: line" and skips — does NOT validate the inner content. Out of scope; rely on `_parseEngagementByIdFromYaml`'s existing parse-error surfacing.
