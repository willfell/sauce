# Breadcrumb Mechanism Promotion Plan (v0.123.0)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Design spec:** `Docs/plans/2026-06-17-v0.123.0-breadcrumb-mechanism-design.md` (registry shape, resolver grammar, project type mapping, parity-proof contract).

**Goal:** Promote `Breadcrumb` from a project-blueprint helper into a shared config-driven `breadcrumb` mechanism. Per-blueprint manifest blocks aggregate into `ranch/breadcrumb-registry.json` at install time. Project migrates onto the mechanism as the byte-identical proof case. to-do drops its `project >=1.21.0` dependency and depends directly on `breadcrumb >=0.1.0`.

**Architecture:** Class name stays `Breadcrumb` (customJS singleton-by-class-name → live-render, no body migration). Mechanism is purely generic — knows zero blueprint paths. Resolver grammar = `fm:|path:|file:|lit:` atoms + `slug:` transform + `|`-fallback chains + `{atom}` link templates + optional `when:` ancestor gates.

**Tech Stack:** Plain Node CustomJS class; headless DOM stub tests; Node JSON I/O for registry.

**Ships as:** v0.123.0 (workshop 0.122.0 → 0.123.0). Second plan of the note-chrome standard arc, after v0.122.0 (section-label).

## Task 2: Generalize Breadcrumb to read from `ranch/breadcrumb-registry.json`

**Files:**
- Modify: `platform/mechanisms/breadcrumb/breadcrumb.js`
- Modify: `platform/test/run-breadcrumb.js` (Phase 2 — resolver tests + project parity)

This task rewrites the class body to be registry-driven. The legacy hardcoded project paths + type-dispatch are replaced by:
1. `_loadRegistry()` — read `ranch/breadcrumb-registry.json` via `app.vault.adapter.read`; tolerate missing/malformed (render nothing).
2. `_findTypeEntry(cur)` — first-match scan over `Object.values(registry.contributions)` looking for `types[cur.type]`. One-time `console.warn` on collision.
3. `_resolveAtom(atom, dv)` — switch on prefix: `fm:<field>` / `path:<n>` / `file:basename|stem` / `lit:<text>` / `slug:<atom>`.
4. `_resolveChain(chain, dv)` — `|`-split; first non-empty atom wins.
5. `_resolveTemplate(tpl, dv)` — `{...}` interpolation; returns `null` if any slot empty.
6. `_evalWhen(whenObj, dv)` — `{ "fm:<field>": "present" | "absent" | "<literal>" }` AND-conjoined.
7. `_renderHTML(segments)` — emit the same wrapper + separators + anchor/span shapes as the legacy helper. CSS class on wrapper stays `project-breadcrumb`.

Keep utility helpers (`_stripLink`, `_slugify`, `_escape`) verbatim from the legacy file.

- [ ] **Step 1: Rewrite `breadcrumb.js`**

Replace the class body with the generalized implementation. The full rewrite is non-trivial; the implementing subagent should reference §2 + §3 of the design doc for grammar + semantics, and the legacy snapshot at `platform/test/fixtures/breadcrumb-legacy.js` for the exact HTML shape to preserve.

Key HTML invariants the rewrite must preserve byte-for-byte:
- Outer wrapper: `dv.el("div", "", { cls: "project-breadcrumb" })` with inline style `"font-size: 0.85em; color: var(--text-muted); margin-bottom: 8px;"`.
- Each ancestor segment is `_link(label, vaultPath)` → `<a class="internal-link" data-href="${vaultPath}" href="${vaultPath}" target="_blank" rel="noopener" aria-label="[[${vaultPath}|${escapedLabel}]]">${escapedLabel}</a>`.
- Current segment is `_currentLabel(label)` → `<span style="font-weight:600; color: var(--text-normal);">${escapedLabel}</span>`.
- Separator: `' <span style="opacity:0.5;"> / </span> '` (note the spaces inside the join string).
- `wrap.innerHTML = parts.join(' <span style="opacity:0.5;"> / </span> ')`.

Empty-trail behavior: if zero segments resolve → do NOT create the wrapper (skip `dv.el` entirely; render nothing).

Inject a stub `app.vault.adapter.read` that returns a hand-authored test registry. Inject a `customJS` global (no-op) for symmetry with runtime.

Cases to cover:
- BR5: `fm:project_name` resolves frontmatter field.
- BR6: `path:2` returns 2nd path segment of `current.file.path`.
- BR7: `file:basename` returns `current.file.name`.
- BR8: `lit:Docs` returns `"Docs"`.
- BR9: `slug:fm:section` slugifies the FM value.

- BR12: link template with empty slot → segment renders as plain label (no `<a>`).
- BR13: `when: { "fm:depth": "2" }` gates ancestor; renders only when FM matches.
- BR14: `when: { "fm:section": "present" }` evaluates non-empty correctly.
