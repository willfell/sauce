## What shipped

Built in strict dependency order (S1→S6) with a green gate per surface (landmine #27 mitigation), not a single big-bang preflight.

### Engine — `FinanceMath.computePlanState` (S1)

NEW instance method `computePlanState(dv, monthKey)` on `FinanceMath` plus helpers `readPlan` / `readSavings` / `glide` / `simulateAvalanche`. One entrypoint, every widget a thin view — no widget re-implements a formula. The envelope is **income-bound and constant across glide tiers** (when savings steps down a tier the freed money rolls to attack: `floor − fixed − minimums − attack_above_minimums − tier1_savings`). Avalanche allocation ranks active debts by `avalanche_order_by` (APR desc, tie-break smaller balance), routes the whole `attack.total` to one target with automatic roll on payoff, and honors `attack_target_override` (which generalizes the headspace month-1 Apple util-bump). Month-by-month payoff simulation (capped 600 iters, non-converge → `months: Infinity` / `zeroDebtDate: "—"`), overflow 80/20 when actual income exceeds floor, one-month-skip what-if (`weeksSlipped`), and prior-month overage carry (live-derived `effective = base − overageCarry`, never written). Degrade-gracefully across no-plan / no-debts / no-savings / no-budget / `income_floor: 0`.

### Scaffolds + migrations (S3)

3 NEW headless-safe migrations folded into `applyFinanceMigrations`: `applyFinancePlanScaffolding` (create-if-absent `Finance Plan.md` with the §3.1 safe defaults), `applyFinanceSavingsScaffolding` (create-if-absent `spice/finance/savings/` + `Savings.md` hub + one `Savings-Emergency-Fund.md` at balance 0), and `applyFinancePlanBandInjection` (inject the `PlanBand` block atop every `Budget-*.md`, marker-guarded `<!-- plan-band-v0.10.0 -->`, `.sauce-backup/<ts>/` snapshot before each write, anchor priority marker → above monthly-overview → above budget-summary → after frontmatter). Scaffolders are create-if-absent (no snapshot, never overwrite); the band injector is append-only + idempotent. All per-file failure-loud (catch + history warning; never abort install). `Savings.md` also ships as a `content/` file (belt-and-suspenders, mirroring debts).

### Widgets + nav (S4)

5 NEW helpers, all thin read-only views of `computePlanState` (single `async render`, embed-dedup, status colors green `#16a34a` / amber `#b45309` / red `#dc2626`):

- **`FinancePlanDashboard`** (on `Finance Plan.md`) — compute-live cockpit: B1 Envelope (`base − carry = effective · planned · spent · left` + over-flag), B2 Allocation (per-card `min+attack=total`, target highlighted, savings contribution + tier chip, `[ Apply to entities ]`), B3 Rollup (total debt · savings `bal → target` · weighted APR · zero-debt date + killOrder · what-if · conditional overflow). Apply opens a confirm-modal showing every write as a `before → after` diff, then writes each debt's `planned_monthly_payment` + the Paycheck Defaults Savings row (`contribution ÷ pay_periods_per_month`) via `FinanceFrontmatter.update` (runtime path). Idempotent re-apply is a no-op. **No silent mutation.**
- **`PlanBand`** (atop every Budget) — over-envelope flag (`planned > effective`).
- **`SavingsSummary` / `SavingsConfigEditor` / `SavingsCards`** — clones of the Debt trio with **inverted delta** (rising balance is good) + a glide-tier chip; `SavingsConfigEditor` snapshots-on-save (`source: "manual"`).
- **`FinanceHubSummary`** gains a compact Plan tile (envelope left + zero-debt date, links to `Finance Plan.md`).
- **`FinanceNav`** gains `config-plan` / `hub-savings` / `entity-savings` modes + a Savings cross-hub row + a `piggy-bank` icon.

## Lessons (load-bearing)

1. **A migration-bearing finance cycle MUST bump the blueprint version.** `applyFinanceMigrations` only runs when the finance item is NOT version-short-circuited by the installer. If the manifest version is unchanged, the seed harness installs over a same-version item, the migration never fires, and the new `HC-V0128-SEED-MIGRATE-PLAN-*` asserts go red for a reason that looks like a migration bug but is actually a version no-op. Bump the blueprint version **and** the seed's subscription pin so the seed exercises the migration path.

2. **The workshop catalogue finance-version is a THIRD edit site (landmine #24).** Beyond the blueprint manifest (`version`) and the workshop self-subscription pin, `platform/manifest.json` `blueprints[].finance.version` must move too. Missing it surfaces at install time as `event: "skip"` with `"subscription pins finance@X but workshop has Y"` → exit 1 with **empty stderr** — a silent failure that reads like a crash. Triple-site every finance version bump: blueprint manifest + subscription pin + workshop catalogue row.

3. **`npm run seed:rebaseline` ratchets multi-test FIXTURES into post-migration shape.** The rebaseline naively rewrites the Legacy Project section-hub anchors that several other harnesses pin (it folded them into healed shape), breaking `HC-V01190-PROJ` + `HC-V01241-SECHUB`. After a rebaseline in a migration cycle, restore those specific fixtures from `seed-vault-prev` (sanctioned per landmine #26) — rebaseline only the files the new migration legitimately touches, not the whole tree.

4. **Mid-cycle merge of `origin/main`'s v0.127.1 — resolved by superseding.** v0.127.1 landed on main while this cycle was open. Version conflicts were resolved by keeping `0.128.0` (it supersedes 0.127.1), adopting their PATCH-tolerant `/^0\.128\.\d+$/` `HC-V0127-VERSION` regex form (so a future PATCH doesn't break the assert), and merging **both** new harnesses into `release:preflight`. When a cycle eats a mid-flight release, keep the higher version and union the test surfaces — don't pick one chain.

## Carry-forwards (named, not dropped)

- **G7 Copilot sync skill** — the natural next finance cycle. `gather-budget-actuals` + `gather-cc-debt-snapshot` writing `categories[].actual` / `balance_history[]` with `source: "skill"`, plus a savings-balance sync. The dashboard works with typed actuals until then. (`source: "skill"` is already reserved in the schema.)
- **Apply → Paycheck Defaults granularity normalization** — scaffolded paychecks carry full-monthly `planned_monthly_payment` on debt rows but per-check on the Savings row. Apply writes the Savings row per-check to match convention; the systemic paycheck-row-granularity fix is its own cycle.
- **`DebtsHubSummary` / `MonthlyOverview` → `FinanceMath` convergence** — pre-existing carry-forward; `simulateAvalanche` could supersede `debtTotals.zeroDebtDate`. Out of scope here.
- **Multi-savings glide weighting** — the glide reads a single Emergency Fund; multiple savings accounts (sinking funds) exist as entities but only the Emergency Fund drives the tier in v0.10.0.
