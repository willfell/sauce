# v0.107.0 projects visual overhaul — design brief

> **Quick-reference card.** Full scope + verbatim user quotes live in the seed handoff at `Docs/prompts/2026-06-15-post-v0.106.0.1-next-cycle-handoff.md`. The brief is a tight scan; the handoff is source of truth.

## Cycle framing

A **deliberate visual + navigation overhaul of the project blueprint as a whole**, plus standardization across every project-related note (project hub, `Docs.md`, section hubs, doc-notes, project Map / Board, task notes). User intent: make the blueprint feel cohesive and intentional, not the additive accretion it currently is. Spans 6 areas (A–F below).

## Section A — Projects Hub (`spice/projects/Projects.md`) search

> "loading up the actual Projects hub spice/projects/Projects.md — it doesn't look too bad, but potentially adding in that search bar like you did with the other mechanism, would be great."

Add the **DocSearch-equivalent filter strip** above the projects card grid. Reuse the v0.104.0 DocSearch pattern (permanent strip + transient results container, persistent filter state via v0.106.0 localStorage, debounce via v0.106.0 150ms) — scoped to projects (filter on `type: project` notes by name + tags). Implementation choice at brainstorm: new helper `ProjectsHubSearch` OR generalize DocSearch into a reusable `EntitySearch` mechanism (decision affects whether other future hubs — meetings, finance — share the surface).

## Section B — Project page (`<Project Name>.md`) rewrite

Current shape (verbatim): Status → ProjectStatusWidget; Workstreams → ProjectWorkstreamManager; Mentions → BacklinkPanel; Project Notes & Referenced By → ProjectNotesCards + ProjectReferencedByCards. **Six requested changes:**

1. **Status section** — drop the `## Status` H2 label (keep the widget). User: *"Status is fine, but we don't need the 'Status' above it, as well as it doesn't need that match gap vertically between other sections."* Tighten vertical spacing.
2. **Workstreams** — keep, but move LOWER. User: *"I just believe that it should maybe go lower?"*
3. **Mentions section** — REMOVE entirely. User: *"The mentions section should go away."*
4. **Project Notes & Referenced By callout** — REMOVE entirely. User: *"The project notes and referenced by should go away as well."*
5. **NEW Meetings section** — add. User: *"There should be a 'Meetings' Section, showing a list of cards of meetings that are connected to the project, showing maybe 3 Max, displaying the people who attended, to do items for it, etc, like we do visually within `await dv.view('ranch/views/customjs-guard', { class: 'SpaceDailyDashboard' });` for meetings."* Read first: `SpaceDailyDashboard` helper's meeting-card rendering — that's the visual reference. Cap at 3 meeting cards. Each shows attendees + action items (open task count) + maybe summary line. **This is DIFFERENT from the v0.102.0 `ProjectMeetingsPanel`** (which only showed date + name + attendee count); v0.107.0 enriches per the SpaceDailyDashboard pattern. May bump `meetings_blueprint` to 0.9.0 if new manifest surface is needed.
6. **`BacklinkPanel` machinery** — keep available for OTHER consumers (cowork uses it); just stop rendering it on project pages.

## Section C — Docs landing (`Docs.md`) section card metadata + ordering

> "It's not bad, but sections should have maybe some more meta data within it, not sure what, but it just looks bland. Like, showing details of last updated, and ordering that way would be good."

Section cards on `Docs.md` currently show name + doc-count meta. Add: **last-updated timestamp** (most recent doc-note mtime in the section); **order section cards by last-updated DESC**; possibly most recent doc title as a subtitle. Implementation: extend `ProjectDocsIndex._renderResults()` section card synthesis to compute and include the last-updated field. Sort `sections` array by computed last-updated before rendering.

## Section D — SectionLabel shared rendering primitive

> "Opening up a section.. visually it's not bad, But the styling for Sub-Sections and Docs just... could usually have a spice up. Every use of 'Sub-sections' - that text, that's within `await customJS.SectionHub.render(dv);` could utilize a makover, as it tends to just look bleh? Maybe a '---' would help with that around these sections to separate things, as well as making the text smaller. They're everywhere in this blueprint and it needs to be fixed"

Replace `dv.header(3, …)` with a custom small-text styled label + `---` separator above. Apply consistently to `SectionHub`, `ProjectDocsIndex`, and the new project-page Meetings section. **Build a shared `SectionLabel` rendering primitive** (e.g. `_renderSectionLabel(parent, text)`) and use it in every project-blueprint helper that draws a section label. Decision at brainstorm: per-blueprint helper OR small new mechanism shared across cowork / meetings / projects.

## Section E — Breadcrumb universal + `breadcrumb-v1.17.0` marker cleanup

> "do you see how within some notes, there is `await dv.view('ranch/views/customjs-guard', { class: 'Breadcrumb' });` like within spice/projects/global-k8s/docs/knowledge/testing-knowledge.md — well, I really like it, and I want that implemented every where it can as well, while trying to remove the `<!-- breadcrumb-v1.17.0 -->` that shows, I hate when that shit shows, but functionality wise it's very useful."

**Two parallel asks.** (1) Add Breadcrumb to every project-related note that doesn't already have one: project hub `<Project Name>.md` (currently NO breadcrumb — add as first block); `Docs.md` (has it from v0.103.0 — keep); section hub / sub-section hub (has it — keep); doc-note (has it from v0.103.0 migration via marker — keep; v0.105.0 dropped the marker from the template); Project Map, Project Board (currently no breadcrumb — add); task notes (add). (2) **Remove the `<!-- breadcrumb-v1.17.0 -->` marker from existing migrated doc-notes.** The marker was v0.103.0's idempotency guard for `_migrateDocNote`; it has done its job. New installer step `applyDocNoteBreadcrumbMarkerCleanup` walks every doc-note + strips the marker (idempotent — if absent, no-op). The marker has already been removed from the template (v0.105.0) so future doc-notes won't carry it.

## Section F — Standardization / consistency audit

> "Standardization on appearence, UI / Nav Patterns, ensuring it's consistent for projects will be great. That's what I'm looking for."

Audit every project-blueprint helper. Establish a small set of shared rendering primitives: `Breadcrumb` (already exists — extend usage); `SectionLabel` (new — replaces all per-helper `dv.header(3, …)`); `EntitySearch` (potential — generalize DocSearch for projects hub); `MetaChipStrip` (potential — generalize the dashboard chips for any hub-like surface). Document the standard in a new agent-guide `Docs/agent-guides/project-blueprint-ui.md` so future helpers conform.
