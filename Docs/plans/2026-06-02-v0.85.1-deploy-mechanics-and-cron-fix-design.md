## 1. Scope

### 1.1 §1 `_resolveWorkshopPath` generalization (FLN-v85-1)

**Problem.** v0.85.0's defensive hardening assumed `libexec/`-named ancestor (brew Cellar layout). Active-pantry layout has no `libexec/` ancestor — the workshop checkout lives at e.g. `~/Documents/obsidian/sync/workshop/sauce`. Auto-detection returns `null`; `installed.workshop_path` is also null on consumers that haven't set it explicitly; the function throws.

**Fix.** Walk ancestors looking for any dir containing `platform/manifest.json` (parseable). Covers all 3 layouts uniformly:
- brew Cellar: `/opt/homebrew/Cellar/sauce/<v>/libexec/platform/manifest.json` → ancestor at `/opt/homebrew/Cellar/sauce/<v>/libexec`.
- active-pantry: `~/Documents/obsidian/sync/workshop/sauce/platform/manifest.json` → ancestor at `~/Documents/obsidian/sync/workshop/sauce`.
- in-vault pantry (legacy): `<vault>/pantry/platform/manifest.json` → ancestor at `<vault>/pantry`.

Verification: parse the candidate's manifest; it must have `workshop_version` top-level field. Reject false positives.

### 1.2 §2 Auto-populate `installed.workshop_path` on first resolve

When `_resolveWorkshopPath` returns a valid path AND `installed.workshop_path` was null/stale, WRITE the resolved path back into `ranch/platform-installed.json` for future runs. Idempotent. Eliminates per-run ancestry walks (perf) AND surfaces the resolution decision for debugging.

### 1.3 §3 Synthesize-week default cron `0 17 * * 5` → `30 17 * * 5`

**Problem.** Friday's synthesize-day fires at user's typical 17:20 slot. Synthesize-week at 17:00 fires BEFORE synthesize-day, sees only 4 synthesized days (Mon–Thu), drops Friday from the week roll-up.

**Fix.** Move synthesize-week default to `30 17 * * 5` (Friday 17:30) — after synthesize-day's 17:20. Captures Friday's data.

**Surfaces touched:**
- `platform/blueprints/cowork/skills/orchestrators/synthesize-week/SKILL.md` frontmatter `schedule:` line.
- `platform/blueprints/cowork/skills/orchestrators/onboard-scheduled-jobs/SKILL.md` cadence walk `Default cron suggestion:` line.

### 1.4 §4 `sauce update` active-pantry drift warning

**Problem.** Active-pantry workshop checkout drifts silently behind origin/main. Today's accuris incident: active-pantry was 189 commits behind, v0.85.0 fix never ran. User had no signal until trying `--bump-pins` and getting OLD code behavior.

**Fix.** When `sauce update` resolves workshop_path to an active-pantry checkout (NOT brew Cellar), `git fetch origin --quiet` + check `git rev-list --count HEAD..origin/main`. If > 0, emit a Notice:

```
sauce: active-pantry workshop is N commits behind origin/main.
   Pull with: cd <workshop-path> && git pull --ff-only origin main
```

Don't auto-pull (respects user agency); warn loudly so it surfaces before the next deploy.

## 3. Risks + mitigations

### 3.1 `_resolveWorkshopPath` false-positive on unrelated `platform/manifest.json`

A user's working tree might contain a directory unrelated to sauce with a `platform/manifest.json` file. The ancestry walk could resolve to that.

**Mitigation:** parse the candidate manifest; require `workshop_version` top-level field. Reject otherwise. Sauce manifests universally carry this; foreign manifests won't.

### 3.2 Active-pantry drift warning false-positive

If the user is offline, `git fetch` fails silently. Drift check could be inaccurate.

**Mitigation:** wrap fetch in try/catch; emit a different Notice on fetch failure ("network unavailable, drift check skipped"). Don't block the install.

### 3.3 Cron change breaks existing accuris scheduled job

Accuris already has `cowork-synthesize-week-accuris` registered with `0 17 * * 5`. The cron-default change only affects NEW onboard runs.

**Mitigation:** v0.85.1 install.md upgrade section explicitly notes existing scheduled jobs won't auto-update — user must manually adjust via scheduled-tasks MCP. One-line operation.
