## What shipped

Two coherent UX-polish workstreams (WS-A + WS-B) on top of the v0.79+v0.80+v0.81 structural foundation. WS-C as originally designed turned out to have a wrong premise and was dropped after S0 investigation (see §"WS-C investigation finding" below).

### WS-A — per-kind callout types

`read-user-preferences-helper.js` gains `DEFAULT_CALLOUT_TYPE_BY_KIND` (chat → `info`, finance → `warning`, calendar → `tip`, email → `quote`, ado → `example`, github → `note`), `VALID_CALLOUT_TYPES` (9 Obsidian built-ins), and `resolveCalloutType(kind_name, kind_block)`. The kind-block iteration loop in `readUserPreferences` now populates `entry.callout_type` per kind: explicit `callout_type` from user-preferences.md is coerced to lowercase, validated, and accepted; invalid or missing values fall back to the per-kind default mapping; unknown kinds fall back to `example` (preserves pre-v0.82.0 behavior).

`gather-from-served-by-helper.js` accepts a new `callout_type` input (default `"example"` when absent, null, empty, or invalid — VALID guard mirrors `resolveCalloutType`'s posture). `expectedPrefix` now parameterized as `> [!${callout_type}]+ ${kind_title}\n`. Success return adds `callout_type_used` (mirrors `hard_rules_applied` / `siblings_used` echo pattern).

5 atomic-note orchestrators (morning-briefing, midday-tripwire, eod-review, weekly-review, monthly-review) pass `callout_type: prefs.mcps[entry.kind_name].callout_type` in the gather loop alongside `hard_rules` and `siblings`. Identical anchor across all 5 (confirmed at S6.1).

Net behavior: morning briefings now render 5-6 kind sections in 5-6 visually-distinct colors via the v0.79.0 per-type CSS. Backward-compatible — vaults without explicit `callout_type` per kind get the default mapping automatically. User-overridable per kind by adding `callout_type: <type>` to `mcps.<kind>` in `user-preferences.md`.

### WS-B — tables in gather contract

`gather-from-served-by/SKILL.md` Step 3 output contract template's "Bulleted lines preferred (no tables — cross-vendor portability)" prohibition replaced with a decision rule: "Render data in tables OR bullets, whichever gives the highest information density per vertical inch. Use tables for structured data with 3+ columns per item (IDs, timestamps, lanes, links); use bullets for narrative or single-axis lists. Mixed within one callout is fine." Microscope `## Output shape` directives explicitly noted as overriding.

Per the v0.82.0 handoff doc's empirical evidence: WS-B is **contract-truthing**, not load-bearing. The 2026-06-01 second accuris morning brief already produced tables for GitHub when the microscope said to — the old "no tables" line wasn't blocking. WS-B aligns SKILL.md prose with what the agent already does. Honest documentation is still valuable.

### WS-C — DROPPED (see §"WS-C investigation finding")

## WS-C investigation finding (S0)

The plan's WS-C premise was: "w2-fte engagement-type manifest defines no `tripwire_aspects` field; the midday-tripwire orchestrator silently exits when `tripwire_aspects` is empty/absent. Fix: edit workshop `engagement-types/w2-fte.json` to add `midday` to `supported_cadences` + `tripwire_aspects: [calendar-drift, queue-growth, pr-review-backlog, chat-urgency]`."

S0 investigation found three problems with this premise:

1. **w2-fte.json already has both fields.** `midday` was added to `supported_cadences` and `tripwire_aspects: ["calendar_drift", "queue_growth"]` was defined back in **v0.13.0** (commit `ef5995e`, 2026-04-XX). The plan was written against a stale read.

2. **Aspect naming convention is snake_case, not kebab-case.** The midday-tripwire orchestrator (`platform/blueprints/cowork/skills/orchestrators/midday-tripwire/SKILL.md`) recognizes three aspect handlers: `cc_drift` (gather-finance-cc-today), `calendar_drift` (gather-calendar), `queue_growth` (gather-projects). The plan's `calendar-drift`/`queue-growth`/`pr-review-backlog`/`chat-urgency` (kebab-case) wouldn't match any handler.

3. **engagement-type JSONs aren't materialized to consumer vaults.** Cowork's manifest declares engagement-types in `engagement_types[]` (line 569) — `{id, manifest}` pointers — but the `.json` manifests are NOT in `files[]`, so they never reach consumer vaults. Accuris on this machine has NO `pantry/` dir (only the legacy `pantry.legacy.20260512-223749.bak/`) — confirming the JSONs are unreachable at runtime on the consumer side. So even if v0.82.0 edited the workshop JSON, the change wouldn't reach accuris.

The actual root cause of the observed "midday-tripwire silent no-op" on accuris remains undiagnosed in this cycle. Likely candidates:
- Accuris's installed cowork version may have a stale w2-fte.json at the time of run (timing-of-deploy issue).
- The agent on accuris's machine couldn't locate the engagement-type manifest at all → defaulted `tripwire_aspects` to `[]` → silent exit.
- A vault-specific override in vault-config.md masked the manifest values (low likelihood — none observed on this machine's synced copy).

**Carry-forward to v0.83.0+:** design a real engagement-type-accessibility fix. Three candidates:
- (a) Add engagement-type JSONs to cowork's `files[]` so they materialize to `spice/cowork/context/engagement-types/*.json`. Update midday-tripwire/SKILL.md to reference the materialized path. Pure additive; consumer-visible install surface change.
- (b) Embed `tripwire_aspects` (and any other manifest-derived fields the orchestrators consume) per-engagement in vault-config.md. cowork:bootstrap-vault seeds defaults from the workshop manifest at bootstrap time. Cleanest user-facing model; requires bootstrap-vault skill edits + vault-config schema bump.
- (c) Hardcode aspect mappings per engagement type into the orchestrator SKILL.md. Least elegant, but minimal scope.

Folded into v0.82.0's handoff (FLN-v82-1).

## Sequencing observations (v0.82.0 cycle)

- **Plan-vs-reality divergence at S0 is healthy.** The plan's `S0.4` check explicitly flagged "Capture the actual aspect-name format the SKILL.md expects... otherwise proceed with design defaults." Without the in-stage live-read discipline (a v0.79.0+ convention), v0.82.0 would have committed an unworkable WS-C with wrong-case aspect names that wouldn't match any orchestrator handler.
- **Test fixtures must use the helper's real API.** The plan's S1 fixtures called `helper.readUserPreferences(raw)` (string arg) instead of the canonical `helper.readUserPreferences({ vaultRoot })` pattern. Adapted at the S2 verification step by rewriting fixtures with `os.mkdtempSync` + write to `spice/cowork/context/user-preferences.md` (mirrors HC-V0780-A* pattern). Future plan-template wisdom: when writing test fixtures, cite the canonical test pattern (existing HC case ID) rather than re-deriving the API.
- **parseYamlIsh's flat-key regex `[a-z_]+` silently drops hyphenated keys.** Discovered while debugging HC-V0820-A4 (originally used `my-custom-kind`; switched to `notion` for an underscore-compatible test kind). Pre-existing limitation, independent of v0.82.0 but worth noting for any future v0.83+ harness work that wants to exercise custom hyphenated kinds.
- **ranch/rules/cowork.json continues accumulating duplicate rule_fragments per cycle.** The install process appends 15 path_glob rule_fragments to ranch/rules/cowork.json every dogfood run (file is now ~7900 lines with 13 copies of each fragment). Pre-existing bug, NOT introduced by v0.82.0; every cycle since at least v0.78.0 has committed the same +630-line delta. Worth a dedicated FLN cleanup cycle.

## Carry-forward (deferred to follow-up cycles)

- **FLN-v82-1 (HIGH PRIORITY): engagement-type-accessibility fix.** Three candidate designs (see §"WS-C investigation finding"). Required for any engagement-type-driven orchestrator behavior to actually reach consumer vaults. Accuris midday-tripwire silent no-op fix depends on this.
- **FLN-v82-2: ranch/rules/cowork.json dedup.** Install appends rather than dedupes rule_fragments; file has bloated to ~7900 lines. Add unique-key dedup at install-time (probably in `applyRuleFragment` or wherever fragments are merged).
- **FLN-v82-3: parseYamlIsh hyphenated-key support.** Pre-existing limitation: flat-key regex `[a-z_]+` rejects keys with hyphens (silently drops them). Custom kinds with hyphenated names (e.g., `lharries-whatsapp`) can't appear in user-preferences.md. Widen regex to `[a-z_][a-z0-9_-]*`.
- **Per-callout-type default microscope output_shape recipes** (from v0.82.0 design §11) — e.g., `warning` → table-heavy default. YAGNI for now; microscopes do this per-kind via `## Output shape`.
- **Callout-type validation harness** (from v0.82.0 design §11) — separate harness that walks all 5 orchestrators + verifies the default mapping covers all kinds in any consumer vault's user-preferences.
- **CSS theming for non-builtin callout types** (from v0.82.0 design §11) — sauce-callouts.css covers the 9 Obsidian built-ins. Custom callout types like `[!finance-summary]` would need new CSS rules.
