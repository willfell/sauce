## Lessons

1. **Same-day PATCH after first live run is the right shape.** v0.93.0 closed at ~17:00; user ran it at ~17:30; drift surfaced; FLN-v93-8 + v93-9 logged at 18:00; both shipped at ~19:00. Fast-follow PATCHes after first-real-run are how the workshop validates design choices against actual consumer data. Pattern matches v0.85.1 / v0.90.1 / v0.90.2 precedents.

2. **The orchestrator LLM autonomously discovered the MCP path.** User prompted "can you utilize the claude cowork mcp to update these scheduled jobs idempotently?" — orchestrator found `update_scheduled_task` in its tool surface, applied the diff-then-update pattern correctly on first try (preserved cron + skipped out-of-scope tasks). FLN-v93-9 just codifies the workflow into SKILL.md prose so every future run does it without prompting.

3. **Adapter ≠ schema change.** FLN-v93-8 makes the helper accept richer prefs shapes WITHOUT changing the output contract. All 12 existing byte-identical fixtures pass unchanged. The helper signature is a superset of v0.93.0's. This is the right pattern for fast-follow PATCHes — extend acceptance, preserve emission.

4. **Schedule preservation is the load-bearing rule.** The user's live crons (morning 06:30 / weekly Friday 04:00 / monthly 1st 04:00) deliberately diverge from contract's `schedule_hint` documentation (08:00 / 17:30). The MCP push MUST NOT "correct" these. v0.93.1 codifies this as a hard non-negotiable in the `## Apply` step 22.
