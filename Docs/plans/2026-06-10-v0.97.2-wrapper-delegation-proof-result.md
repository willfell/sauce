## Open observations

The delegation regression is fundamentally a model-behavior class — accuris's LLM made a different choice than headspace's at the same fire-time. The wrapper architecture itself was correct. v0.97.2's three knobs add behavioral guardrails to the wrapper so the same-input → wrong-output failure mode is no longer possible (or at least, much less likely).

Lesson learned: when generating prompt bodies that an LLM will execute, NEVER provide example values (`e.g. "Tuesday"`) — the LLM may copy them literally. Always drive the LLM at the tool/command that resolves the value at execution time.

Lesson learned: the `READ <skill> ... follow its Steps section` pattern is a delegation invitation. The cron LLM can interpret it as "launch a subagent to handle that work" — which structurally guarantees wrong output (subagent has no anti-delegation directive, no context from the parent wrapper). When the work CAN be inlined into a step-list, inline it. Delegation should be an explicit choice, not an architectural opening.
