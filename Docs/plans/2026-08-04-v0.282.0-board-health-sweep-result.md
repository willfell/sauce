# Board-health sweep — result

**Closed:** 2026-08-04 · **Version:** workshop 0.281.7 → 0.282.0 · **Workstream:** loop-integrity program #1 (treats disease B — "the system prefers to continue quietly over stopping loudly")

## What shipped

A report-only `board-health` coordinator verb whose five checks start from the
**board, not the ledger**. That single inversion closes the blind spot behind
both v0.281.1 failures: all fifteen pre-existing checks iterate
`Object.values(state.cards)`, so a board member with no ledger record was
*unreachable* — which is why `EM-4/5/6` sat unreported and why a frozen board
raised no alarm for days.

## The five checks (as landed)

| # | Check | Ledger needed | Source |
| --- | --- | --- | --- |
| 1 | Untracked board member claiming progress (`in_progress`/`parked`/`blocked`/`completed`; pre-claim `planning` exempt) | no | new set-difference walk, board-first |
| 2 | Epic whose `canonicalEpicProjection` throws (seeded with its first existing slice) | no | reused `canonicalEpicProjection` |
| 3 | Binding drift + orphan sub-board lines (counts + `heal-epic-bindings --dry-run --json` remedy) | no | reused `planEpicBindingHeal` |
| 4 | Derived slice roll-up vs painted parent lane, agreement reported when the epic carries untracked members | yes | reused `deriveEpicProjection` + `epicProjectionMapping` |
| 5 | Records carrying `projection_error` | yes | existing status logic |

Degradation is explicit: `ledger: "present"|"empty"|"absent"` in every receipt,
`checked.records: 0` when unchecked, checks 4–5 skipped (never failed) without
a ledger. `no_op: true` stays reachable on a healthy ledgerless board.

## Failure posture (all test-pinned)

- Per-epic isolation: a throwing epic becomes an `unprojectable_epics` finding;
  siblings and even the throwing epic's own members (check 1 runs before
  projection) stay checked.
- Sweep-level failure is loud: `board_unreadable` / `cards_root_invalid` /
  `state_unreadable` refusals, `ok: false`, never `no_op: true`.
- Held selector lock → clean `skipped: true` receipt carrying **no findings**,
  zero writes.
- Note-write failure → findings preserved in the receipt beside `note_error`;
  a body-only `Board Health.md` fails closed and is never rewritten.

## Vault note

`spice/projects/<slug>/Board Health.md`, schema `sauce.board-health.v1`,
written only with `--write-note` (read-only is the default). Loop Station's
write discipline inherited verbatim: scaffold once (stock `BoardHealth`
customjs-guard body), frontmatter-only thereafter, unchanged findings preserve
the note **byte-for-byte with zero writes** — the payload deliberately carries
no timestamp, so mtime means "when board health last changed". Lists capped at
20 with explicit overflow counts.

## Process

superpowers:writing-plans → superpowers:test-driven-development. Every `BH-*`
case was driven red → green with the failure watched and committed per
behavior (9 commits). `BH-NOOP`/`BH-READONLY` passed on first run — their
behavior had been forced by earlier red tests — and were committed as
regression pins. Live read-only smoke before the PR: the verb run against this
workshop's own bound board reported 20 epics / 183 slices / 124 records and
surfaced real untracked-completed members (per-clone ledger gaps — exactly the
ambiguity workstream 4 exists to remove).

## Spec interpretations (Director-visible)

1. **Check 1 exempts pre-claim `planning`.** A literal set difference reports
   every unclaimed slice and makes `no_op: true` unreachable on any non-empty
   ledgerless board, contradicting the spec's explicit reachability
   requirement.
2. **`lane_divergence` membership:** disagreement OR the epic has untracked
   members. A fully healthy epic emits nothing, keeping "`no_op` when every
   class is empty" consistent with agreement reporting.
3. **`BoardHealth` renderer deferred.** The note body is the stock
   customjs-guard block per spec; until a renderer ships the guard shows its
   standard unavailable hint and the data lives in frontmatter.

## Lessons

- **The board-first inversion found real divergence immediately.** The first
  live read-only run against the workshop's own board surfaced dozens of
  untracked-completed members from per-clone ledger gaps. The sweep makes the
  local-ledger ambiguity *visible*; workstream 4 (durable ledger) removes it.
  Sizing note for workstream 3: most of these are legitimate cross-clone
  completions, so the untracked count alone overstates rail-leaving — the
  Director should read the note per-project, not aggregate it.
- **Landmine #30 struck again** (`/Scripts/` gitignore case-folds onto
  `scripts/` on APFS): tracked files under `scripts/` stage with `git add -u`,
  new files need `git add -f`. Already documented; no landmines.md change.
