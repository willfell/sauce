# v0.107.0 Result — finance defaults + groups + budget summary

## What shipped

Closed the monthly-budget data-entry pain end-to-end in a single ship:

**Per-vault defaults notes** (scaffolded create-if-absent; never overwritten by future installs):
- `spice/finance/Budget Defaults.md` — `groups[]` + `categories[{group, name, planned}]`.
- `spice/finance/Paycheck Defaults.md` — `expenses[{item, amount, category, url}]`.

**Three new CustomJS widgets:**
- `BudgetDefaultsEditor` — two-pane (groups + categories) dialogue-driven editor. Group reorder + cascade-rename + reassign-on-delete.
- `PaycheckDefaultsEditor` — flat list editor with `<datalist>` Category autocomplete from Budget Defaults.
- `BudgetSummary` — read-only three-band rollup on every Budget note (totals + variance, month-progress + pace indicator, per-group cards).

**Mechanism extension** (`entity-create` 0.6.0 → 0.7.0 MINOR ADDITIVE):
- New optional `seed_from_defaults` schema field on `new_entity_buttons[*]`. At scaffold time, reads the defaults file, deep-copies `source_array`, applies `per_item_set`, carries top-level `carry_arrays`, and injects only when `frontmatter_template`'s value for the dest key is empty/missing (template wins on conflict). Defensive — missing/malformed defaults surface as Notice + fall back to empty array.

**`BudgetCategoriesEditor` v2:** grouped `<details>` sections per `page.groups[]` + per-group SUBTOTAL line (planned / actual / variance, color-coded green/amber/red) + auto-injected "Unassigned" group for orphans. Add/Edit modal grows a Group dropdown.

**`PaycheckExpensesEditor`:** Category text input grows `<datalist>` autocomplete from Budget Defaults' category names. Free text still accepted; falls back gracefully when defaults missing.

**Installer migration** (`applyFinanceMigrations` block):
- `applyFinanceDefaultsScaffolding` — create-if-absent for both defaults notes. Never overwrites user content. Mirrors `applyDocsBackfill` posture.
- `applyFinanceCategoriesGroupBackfill` — append-only `groups: []` + per-category `group: "Unassigned"` backfill on every existing `Budget-*.md`. Pre-write `.sauce-backup/<timestamp>/spice/finance/budgets/` snapshot (Safeguard-1 pattern). Per-file failure-loud; idempotent.

**Templates + content:**
- `Budget Template.md` adds the `BudgetSummary` block above `## Categories` (lockstep with `new_entity_buttons[].budget.inline_body`).
- `Budgets.md` + `Paychecks.md` hubs gain a small ⚙ Defaults link next to the existing `+ New` button.
- `categories[*].group` field added to budget frontmatter; `groups[]` snapshot added to budget top-level frontmatter.

## In-cycle CF — CF-1 (finance 0.5.0 → 0.5.1)

**Trigger:** Deploy to headspace failed — `applyFinanceCategoriesGroupBackfill` called `tp.app.fileManager.processFrontMatter`, which is **unavailable in headless install** (install.js runs as a Node CLI; Obsidian-runtime APIs aren't there).

**Fix:** Replace `processFrontMatter` with regex-based YAML mutation via a new `_backfillBudgetGroupsFromText(body)` pure function. Mirrors the v0.103.0 `_migrateDocNote` posture (adapter.read + body-text mutation + adapter.write). Append-only semantics preserved.

**Headspace verification post-CF-1:** `Budget-2026-06.md` 4 categories all received `group: "Unassigned"` + `groups: []` added; names/planned/actuals UNCHANGED (Taco 850/200, Gas 400/0, Restaurants 700/0, Subscriptions 80/0). Pre-migration `.sauce-backup/<timestamp>/spice/finance/budgets/2026-06/Budget-2026-06.md` exists with original copy.

**Lesson** (carries forward): **Headless installer cannot use Obsidian-runtime APIs.** Any installer step that mutates frontmatter on existing files MUST use adapter.read + body-text mutation + adapter.write. The mirror precedent is `_migrateDocNote` (v0.103.0) — `_migrateProjectSectionsToWikilinks` is the canonical regex-walk pattern. processFrontMatter is fine for Obsidian-runtime helpers (the editor widgets via `FinanceFrontmatter.update`) but NOT for installer migrations.
