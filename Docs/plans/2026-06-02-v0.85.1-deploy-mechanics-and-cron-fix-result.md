## Summary

**PATCH addressing two distinct v0.85.0 post-deploy findings, closing FLN-v85-1 + a synthesize-week Friday-timing miss.** v0.85.0 §0.1 had shipped defensive hardening to `_resolveWorkshopPath` based on the design's hypothesis that the deploy-time bug was stale-Cellar-keg specific — that hypothesis turned out to be incomplete. Real-world `sauce update` on accuris exposed a different layout the v0.85.0 heuristic didn't cover: the active-pantry checkout (`.../Documents/obsidian/sync/workshop/sauce/`) has no `libexec/`-named ancestor. v0.85.0's ancestry walk silently failed and fell back to the stale `installed.workshop_path`, dropping the bump-pins fix.

v0.85.1 generalizes the helper to walk for ANY ancestor with a valid sauce manifest (`platform/manifest.json` parseable + `workshop_version` field present) via a new `_isValidWorkshopRoot()` helper — covers brew Cellar libexec, active-pantry, and in-vault pantry uniformly. `installed.workshop_path` auto-populates on first successful resolve so future runs short-circuit without re-walk. Separately: v0.85.0's synthesize-week default cron `0 17 * * 5` (Friday 17:00) fired BEFORE synthesize-day's `0 17 17 * * 1-5` at 17:20, so the week roll-up captured only Mon-Thu synthesized data — Friday was always dropped. Default moved to `30 17 * * 5` (Friday 17:30). Final piece: a new `_warnIfActivePantryDrift()` helper surfaces N-behind state loudly when `sauce update` resolves to an active-pantry checkout that's stale vs `origin/main` — pre-empts future "deploy fix never ran because the workshop was N-behind" situations.

## Surface changes

- **§1 `_resolveWorkshopPath` generalization (FLN-v85-1 CLOSED).** New `_isValidWorkshopRoot(dir)` helper in `platform/cli/cmd-update.js` probes `<dir>/platform/manifest.json` + verifies `workshop_version` field present. `_resolveWorkshopPath` ancestry walk now uses this predicate instead of the v0.85.0 `path.basename(dir) === "libexec"` check. Resolution precedence preserved (argv → installed.workshop_path → ancestry walk). Covers 3 deploy layouts uniformly: brew Cellar (`.../libexec/platform/manifest.json`), active-pantry (`.../sauce/platform/manifest.json`), in-vault pantry (`.../pantry/platform/manifest.json`).
- **§2 Auto-populate `installed.workshop_path`.** `handleBumpPins` writes the resolved path back to `ranch/platform-installed.json` after first successful resolve when it diverges (or was null). Idempotent on subsequent runs. Future `sauce update --bump-pins` invocations short-circuit without re-walk; the resolution choice is now durable + debuggable from disk state.
- **§3 Synthesize-week default cron `0 17 → 30 17`.** Friday's synthesize-day fires at 17:20 (cron `20 17 17 * * 1-5`). v0.85.0's synthesize-week default of `0 17 * * 5` fires BEFORE synthesize-day, sees only Mon-Thu synthesized, drops Friday from the week roll-up. Fixed in `platform/blueprints/cowork/skills/orchestrators/synthesize-week/SKILL.md` schedule line + `onboard-scheduled-jobs/SKILL.md` cadence walk entry (rationale text updated from "after the typical weekly-review slot" to "after the typical synthesize-day slot so Friday's data is captured"). **Existing scheduled jobs registered at v0.85.0 onboard won't auto-update** — install.md upgrade section documents the one-line manual MCP adjustment.
- **§4 Active-pantry drift warning.** New `_warnIfActivePantryDrift(workshopPath)` helper in `cmd-update.js`. Detects active-pantry layout (heuristic: resolved path does NOT contain `/Cellar/`) + runs `git fetch origin --quiet` (10s timeout) + `git rev-list --count HEAD..origin/main`. If N > 0, emits a stderr Notice with the suggested `git pull --ff-only origin main` command. Best-effort: fetch failures emit a different Notice + don't block install. Wired into `run()` after `_resolveWorkshopPath` so it fires for both `--bump-pins` and plain `sauce update`.
- **§5 Test-fixture hermeticity (collateral S1 + S1 polish).** 4 pre-existing fixtures (caseV0760B2/B3/B4 + 6 `_bpRun` callers + HC-V0850-G1) updated for hermeticity — the generalized resolver now accepts the real sauce repo's ancestry as a valid workshop root (since tests run from inside the repo), so tests relying on resolver STRICTNESS (e.g., expecting failure when given a synthetic tmp workshop) need explicit `_callerFile` injection or `--workshop-path` pins to stay isolated. ## NEW lessons

1. **FLN surfacing pattern: design-doc hypothesis was insufficient until real-world deploy on accuris exposed the active-pantry layout case.** v0.85.0 §0.1 hardening shipped was correct for the brew Cellar libexec case but missed the broader heuristic — the active-pantry layout doesn't have a `libexec/`-named ancestor at all, so the v0.85.0 walk fell through to the stale `installed.workshop_path`. **Lesson:** when a deploy-time bug is hypothesized but not yet reproducible at design time, ship the fix BUT explicitly mark it as "validation owed at deploy" in the FLN tracker, and budget a follow-up PATCH for the case the hypothesis missed. v0.85.0's `Real-world validation owed at deploy (FLN-v85-1)` callout did exactly this; the v0.85.1 cycle was the follow-through.

2. **Test-fixture hermeticity: when a refactor makes a helper MORE permissive, existing tests that relied on resolver STRICTNESS break.** The generalized `_resolveWorkshopPath` now accepts the real sauce repo's ancestry as valid (since tests run from inside the repo), so fixtures that expected the helper to fail given a synthetic tmp workshop instead found the real repo and "succeeded" against it. Mitigation: explicit `_callerFile` injection (used in HC-V0851-A1..A3) OR `--workshop-path` pin (used in HC-V0850-G1 polish + 6 `_bpRun` callers + caseV0760B2/B3/B4). **Plan-template addition candidate:** when generalizing a resolution heuristic, grep the test suite for fixture sites that depend on the prior strictness BEFORE landing the refactor.

3. **Cron-default design must account for the downstream cadence-graph ordering, not just the upstream slot.** v0.85.0 defaulted synthesize-week to `0 17 * * 5` assuming the only constraint was "after weekly-review at 14:30" — true in isolation, but Friday's synthesize-day at 17:20 was the actual blocker. The week roll-up depends on the synthesized daily file for the day it's firing, so the synthesize-week cadence must come AFTER the latest Friday synthesize-day. **Lesson:** future cycles introducing new cadences should walk the full cadence-graph (everything that fires on the same weekday + everything the new cadence reads) before choosing a default cron time.

4. **Auto-populate pattern: writing back to `ranch/platform-installed.json` after first successful resolve is a clean way to short-circuit future runs.** Mirrors v0.74.0's pattern for other resolved-once fields. Idempotent (no-op when value unchanged), debuggable (the resolution choice is visible on disk), and avoids re-walking on every `sauce update` invocation. **Lesson:** when a helper does runtime path-resolution that's expensive OR ambiguous, write the resolved value back to a durable config file so subsequent runs (a) skip the resolution entirely and (b) surface the choice for inspection.
