# v0.88.2 — orphan-folder-template-cleanup — result

**Second hot-fix PATCH following v0.88.0 + v0.88.1 deploys** — closes the underlying double-fire bug that v0.88.0 was originally supposed to fix.

## What landed

- `people@0.5.1 → 0.5.2` — declares `removed_templater_folder_templates: ["spice/people"]` so the installer purges the v0.4.0-era stale Templater folder-template binding from each consumer vault's `.obsidian/plugins/templater-obsidian/data.json`.
- **install.js** — NEW helper `applyTemplaterFolderTemplateRemovals(tp, manifest, variables, history, git)` mirrors the shape of `applyTemplaterFolderTemplates`. Called inside `installItem` immediately BEFORE the apply helper so removals + re-adds compose correctly. Idempotent (no-op after first removal); backup-on-edit to `<target>.sauce-backup`; failure-loud (Notice + history); honors landmine #12.
- Workshop `0.88.1 → 0.88.2`. Preflight `version-sync ok: 0.88.2` ALL GREEN.

## Why

v0.88.0 removed the `templater_folder_templates[]` block from the people blueprint manifest. The HC tests asserted the binding was gone from the manifest. They did NOT assert anything about the corresponding entry in each consumer vault's local `.obsidian/plugins/templater-obsidian/data.json`. **The installer is additive-only on those bindings** — `applyTemplaterFolderTemplates` adds new entries but never removes old ones.

Result: every consumer vault that had `people@0.4.0` installed previously (i.e. all of them) **still had** the stale `{ folder: "spice/people", template: "ranch/templates/Template, People.md" }` entry in its Templater data.json after the v0.88.0/v0.88.1 deploys. Creating a new person via `+ New Person` still triggered Templater on file landing → double-fire → broken note → `PeopleRendering.renderMentionList: unknown mode undefined` toasts. **The user-facing bug v0.88.0 was supposed to fix persisted.**

Surfaced when the user (post-v0.88.1 deploy on their second machine) created `spice/people/test person.md` and saw the same renderMentionList errors as before. Confirmed by inspecting all 4 deployed vaults on my machine — all still had the stale binding.

This is the structural gap. The right fix is a manifest-level cleanup directive that the installer respects:

```json
{
  "name": "people",
  "removed_templater_folder_templates": ["spice/people"]
}
```

`applyTemplaterFolderTemplateRemovals` reads this list, scans `data.folder_templates[]`, removes any entry whose `.folder` matches (after lenient substitution), backs up + writes. Idempotent across re-runs. Generalizes for any future blueprint that needs to retire a binding.
