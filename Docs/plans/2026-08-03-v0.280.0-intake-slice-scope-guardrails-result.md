**Closed:** 2026-08-03 · **Version:** delivery 0.4.1 → 0.5.0 · workshop 0.279.1 → 0.280.0

## What shipped

Mint-time slice-scope ceilings in card intake — the only sanctioned planning
writer — so a program-sized slice or an accreting 1:1 supersession chain is
refused at mint with a decompose instruction, instead of thrashing the loop
through dozens of supersessions that merge nothing (the TV-2 failure: one slice
spun 27 supersessions).

**Files touched:**

- `platform/mechanisms/delivery/data/delivery-schema.json` — new
  `policies.slice_scope_caps = { touch_zones: 6, acceptance_tests: 12,
  risk_dimensions: 3, carried_findings: 12 }` beside the existing policy knobs.
- `.agents/skills/card-intake/scripts/card-intake.js` — `SLICE_SCOPE_CAPS`
  sourced from the registry; a `slice_scope_ceiling` upper-bound check in
  `validateCard` (touch_zones / acceptance_tests / risk_dimensions) mirroring the
  existing non-empty lower-bound loop; a `carried_findings_ceiling` check in
  `validateSupersede`. Every refusal names the field, count, cap, and the
  decompose remediation. Thresholds are read from the registry, never literals.
- `platform/test/run-card-intake.js` — four over-cap refusals + one at-the-cap
  positive proving a legitimate bounded slice still mints.

## Carry-forward

- **Guardrail #2 — supersession-depth circuit-breaker (DEFERRED, not shipped).**
  Intended design: in `scripts/autoloop/codex-coordinator.js` `discardCardCore`,
  before writing the tombstone, walk `superseded_by` backward through
  `state.cards`; at chain depth ≥ 3 refuse and return `awaiting_user_decision`
  with reason `supersession_depth_exceeded` and a decompose remediation, plus a
  coordinator test. Deferred because `discardCardCore` is the shared primitive
  behind **both** `commandDiscard` and `commandReap` (the batch corpse-cleaner):
  a new `awaiting_user_decision` return there is not a bounded change — it
  ripples into station projection, the reap batch loop (which would then refuse
  legitimately reaping pre-existing deep chains), lock semantics, and the loop's
  receipt handling, and it arguably belongs at the supersession-*minting*
  decision rather than the discard/reap primitive. The carried-findings ceiling
  shipped this cycle already blocks the accreting chain at its source (mint),
  which is what failure mode #2 targets; the depth breaker is defense-in-depth at
  the discard boundary and should be scoped as its own slice with the reap
  interaction designed explicitly. File via `/loop:intake` when picked up.
