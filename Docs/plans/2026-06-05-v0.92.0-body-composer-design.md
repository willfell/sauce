# v0.92.0 — body composer design

## 1 — Context

### 1.1 — Why this cycle exists

Live evidence on 2026-06-05 (accuris morning briefing on laptop): all HARD rules from the v0.91.x stack fired correctly (canonical path, canonical frontmatter, canonical SpaceNavButtons dvjs block, M365 connectivity dispatch, microscope-driven content, wikilinks). The SOFT body-composition rule (orchestrator Step 14 — the spec at line 292 of morning-briefing/SKILL.md) was DROPPED:

- No `[!info]- Today at a glance` synopsis callout.
- No per-kind `[!<type>]+ <title>` callouts (chat→info, calendar→tip, email→quote, github→note, ado→example per v0.82.0 default mapping).
- No `[!tip] Today's focus` closing callout.
- No memory callouts (overnight tick v0.85.0 + semantic echoes v0.87.0 + memory log backlink v0.85.0).

The note rendered as plain `##` markdown headers. Today's evidence file at `/Users/willfellhoelter/notes/sauce/accuris-sauce/spice/cowork/daily/2026/06-June/2026-06-05/morning-briefing.md` was manually rewrapped post-run as the working artifact (with `warnings: [manually_rewrapped_post_run_for_v0.82.0_callout_styling]` in frontmatter).

### 1.2 — Root cause

Orchestrator SKILL.md is >500 lines. Step 14 is buried at line 292 surrounded by exception-handling prose for engagement-template fallback / sentinel detection / voice contract / semantic interpolation. The LLM's attention budget exhausted on top-of-file hardened rules + inline gather instructions + the user-prompt body; Step 14's composition spec didn't reach actionable salience.

This is structurally identical to:
- v0.90.2's wrong-path failure (Step 16 write spec ignored, daily-blueprint path used instead) — fixed by v0.91.1 write-guard.
- v0.91.2's wrong-frontmatter failure (Step 16 frontmatter spec ignored) — fixed by v0.91.2 frontmatter write-guard.
- v0.91.3's hallucinated SpaceNavButtons invocation (Step 17 pattern spec ignored) — fixed by v0.91.3 dvjs canonical-pattern check.

**Pattern:** long-orchestrator prose contracts get dropped in favor of higher-salience signals. The v0.91.x stack added DETERMINISTIC write-guards (path / frontmatter / dvjs canonical pattern) in sub-skills as backstops for the corresponding prose contracts. The body-shape contract has no such backstop. v0.92.0 adds the 4th layer.

### 1.3 — Same-day weekly-review evidence

The same machine ran weekly-review the same day and produced rich, correctly-structured output **without consulting the orchestrator at all**. That run worked because the user-prompt body was directly executable. The morning-briefing orchestrator's prose burden is now load-bearing for cases where the user-prompt body isn't sufficient on its own — and that prose burden has crossed the LLM-attention ceiling.

The v0.92.0 composer arc creates the architectural space for a subsequent v0.92.x or v0.93.x cycle to trim orchestrator prose to ~50-line dispatchers (currently FLN-v92-2). v0.92.0 itself does NOT do that trim; it introduces the composer + deterministic backstop so the trim becomes safe.

## 4 — `compose-body-helper.js` API contract

Pure JS, no dependencies, no I/O, no clock, no randomness. Deterministic: same inputs → byte-identical `body_md`. Standard sauce pure-helper pattern (matches v0.85.0 / v0.86.0 / v0.87.0).

### 4.1 — Signature

```js
composeBody({
  cadence,              // "morning-briefing" | "midday-tripwire" | "eod-review" | "weekly-review" | "monthly-review"

  // Pre-rendered top-of-body (orchestrator owns the canonical block; composeBody splices)
  nav_buttons_block,    // the canonical dataviewjs block INCLUDING triple-backtick fences

  // Pre-rendered synopsis callout (orchestrator wraps prose in [!info]- <title>)
  synopsis_md,          // full callout string (e.g. "> [!info]- Today at a glance\n> <one-paragraph synopsis>")

  // Pre-rendered memory callouts (from existing v0.85.0 / v0.87.0 helpers; each null/empty = omit cleanly)
  memory_callouts: {
    yesterday_md,       // from composeMemoryCallouts() — yesterday tier
    overnight_md,       // from composeMemoryCallouts() — overnight tier
    echoes_md,          // from composeSemanticEchoesCallout()
    backlink_md         // from orchestrator inline v0.85.0 backlink construction
  },

  // Priority-ordered MCP-kind blocks (composeBody wraps each in canonical callout)
  ordered_blocks: [{
    kind,               // "chat" | "calendar" | "email" | "github" | "ado" | "warning" | ...
    callout_type,       // sourced from prefs.mcps[kind].callout_type per v0.82.0
    title,              // ≤60 chars, no newlines
    body_md             // multi-line markdown; composeBody prefixes each line with "> "
  }],

  // Engagement-type-aspect blocks (semantic_related, finance, ...)
  engagement_type_blocks: [{
    kind,               // "semantic" | "finance" | future kinds
    callout_type,       // platform-canonical, passed by orchestrator
    title,
    body_md
  }],

  // Pre-rendered closing callout (orchestrator wraps prose in [!tip] <title>)
  closing_md            // full callout string (e.g. "> [!tip] Today's focus\n> <2-3 sentences>")
}) → { body_md: string, body_assertions: string[], status: "ok" | "failed:<reason>" }
```

### 4.2 — Canonical output order

```
<nav_buttons_block>
<blank line>
<synopsis_md>
<blank line>
<memory_callouts.yesterday_md>      ← omit cleanly when empty
<memory_callouts.overnight_md>      ← omit cleanly when empty
<memory_callouts.echoes_md>         ← omit cleanly when empty
<blank line, only if at least one of the three above rendered>
<ordered_blocks[0] wrapped as `> [!<callout_type>]+ <title>` + body lines `> ` prefixed>
<blank line>
<ordered_blocks[1] wrapped ...>
<blank line>
...
<engagement_type_blocks[0] wrapped ...>
<blank line>
...
<closing_md>
<blank line>
<memory_callouts.backlink_md>       ← omit cleanly when empty (last thing in body per v0.85.0 spec)
```

Note the backlink placement: `memory_callouts` struct groups all 4 memory pieces by data-source convenience, but composeBody dispatches them to TWO canonical positions: yesterday/overnight/echoes at the top (between synopsis and ordered_blocks), backlink at the very bottom (after closing). Matches v0.85.0 Step 14 spec at orchestrator line 310-317.

### 4.3 — Null-omit semantics

(Matches v0.84.0 / v0.85.0 / v0.87.0 helper conventions.)

- Any input string that is `null`, `undefined`, `""`, or whitespace-only → OMITTED cleanly. No orphan blank lines, no `>` ghost-fragments.
- `ordered_blocks` or `engagement_type_blocks` empty array → that whole section is skipped, no orphan separators.
- ALL memory_callouts fields empty → skip the entire memory cluster (no blank lines between synopsis and first ordered_block).

### 4.4 — Cadence-specific behavior

The `cadence` parameter is VALIDATED (must be one of the 5 known cadences) but does NOT affect output shape or per-field validation rules — those are uniform across all 5 cadences. Cadence flavor comes from prose content (synopsis + closing prose, ordered_blocks composition, voice contract), not from skeleton variance. The parameter exists for: (a) failure-token namespacing (`failed:input:unknown-cadence:<value>` when an invalid cadence is passed), (b) golden-fixture name lookup, (c) future per-cadence behavior if it ever emerges.

Uniform validation rules across all 5 cadences:

- **Required fields (non-empty):** `nav_buttons_block`, `synopsis_md`, `closing_md`.
- **Required arrays (may be empty):** `ordered_blocks`, `engagement_type_blocks`.
- **Per-block validation:** `callout_type` must be one of (`info`, `tip`, `quote`, `note`, `example`, `warning`). Unknown → reject.

### 4.5 — Callout wrapping rules

For each `ordered_blocks[i]` or `engagement_type_blocks[i]`:

```
> [!<callout_type>]+ <title>
> <body_md line 1>
> <body_md line 2>
> 
> <body_md line N — blank lines in body become `> ` empty-blockquote lines>
```

- Always `+` fold (expanded).
- Title literal (no escaping, upstream-validated to ≤60 chars + no newlines).
- Body lines prefixed with `> ` literally; existing `> ` in body becomes `> > ` (nested blockquote).
- Trailing whitespace on body lines stripped before prefixing.

### 4.6 — `body_assertions[]` return value

composeBody returns alongside `body_md` an array of canonical substrings the body contains. Used by the v0.92.0 write-guard (Section 6) for deterministic shape verification.

Assertions include:
- The nav-buttons block opener (e.g. `"```dataviewjs\nawait dv.view(\"ranch/views/customjs-guard\", { class: \"SpaceNavButtons\" });"`).
- The synopsis callout first line (e.g. `"> [!info]- Today at a glance"`).
- Conditional (only when input was non-empty): first line of each memory callout (`"> [!quote]- Yesterday's last memory"`, etc.).
- Per `ordered_blocks[i]`: rendered callout header (e.g. `"> [!info]+ Chat (Teams)"` — combines kind's canonical callout_type AND title; catches both v0.82.0 mapping violations AND title drift).
- Per `engagement_type_blocks[i]`: same pattern.
- Closing callout first line (e.g. `"> [!tip] Today's focus"`).

### 4.7 — Error tokens

Returned in `status` field; `body_md = ""` and `body_assertions = []` when status is any `failed:*` value.

- `failed:input:missing-cadence`
- `failed:input:unknown-cadence:<value>`
- `failed:input:missing-nav-buttons-block`
- `failed:input:missing-synopsis`
- `failed:input:missing-closing`
- `failed:input:malformed-ordered-block:<index>:<field>` (field = `kind` | `callout_type` | `title` | `body_md`)
- `failed:input:malformed-engagement-type-block:<index>:<field>`
- `failed:input:unknown-callout-type:<value>:<index>`

### 4.8 — Idempotence + purity

- Pure function: no I/O, no clock, no randomness.
- Same input → byte-identical output (testable by golden fixtures).
- No mutation of input args.

## 6 — Body-shape write-guard additions to 5 `write-run-note-<cadence>` sub-skills

### 6.1 — Architectural choice: Path 1 (decoupled, composer-emitted assertions)

The write-guard verifies body via `body_assertions[]` passed from composeBody through the orchestrator to write-run-note. Decoupled — write-run-note has no `cowork/helpers/` imports today; this stays true. Substring matching is fast, fixture-testable, and AUTHORITATIVE (assertions originate from composeBody's emission — they're what composeBody actually produced, not a guess).

Path 2 (rejected): re-invoke composeBody inside write-run-note. Strongest check but creates cross-module dependency.

### 6.2 — Changes to each `write-run-note-<cadence>/SKILL.md`

**(a) `## Inputs` section** — add:

```yaml
body_assertions: string[]
```

with docstring: "List of canonical substrings the composed body MUST contain; computed by `cowork:compose-body` and passed through by the orchestrator. The body-shape write-guard verifies each one is present in body."

**(b) `## Pre-write self-check` section** — add v0.92.0 sub-section AFTER the v0.91.3 dvjs check, BEFORE the existing v0.78.0 structural-marker checks:

```markdown
### v0.92.0 body-shape write-guard: canonical callout markers (FOURTH CHECK)

After the path / frontmatter / dvjs checks pass, validate the composed `body` against
the canonical assertion list passed in via `body_assertions`.

REJECT and return `{ path, status: "failed:contract-violation:body-shape:<reason>" }` if:

1. `body_assertions` input is missing, null, or not an array → `body-shape:no-assertions-input`
   (indicates the orchestrator skipped `cowork:compose-body`).
2. `body_assertions` is an empty array → `body-shape:empty-assertions` (composeBody emitted
   no markers — defensive reject).
3. For each `assertion` in `body_assertions`: if `body.includes(assertion)` is false →
   `body-shape:missing-assertion:<index>:<first-40-chars-of-assertion>`.

The orchestrator surfaces this as a Notice + exit non-zero per the existing v0.91.x pattern.
```

**(c) Existing v0.78.0 structural-marker checks PRESERVED** (≥1 info, ≥1 example, closing tip, navbuttons) as belt-and-suspenders behind body_assertions. Reasoning: static invariants regardless of inputs; body_assertions is the strong check; structural markers are the weak fallback.

**(d) Failure-token taxonomy additions:**

- `failed:contract-violation:body-shape:no-assertions-input`
- `failed:contract-violation:body-shape:empty-assertions`
- `failed:contract-violation:body-shape:missing-assertion:<index>:<truncated-substring>`

### 6.3 — Four-layer defense ordering inside `## Pre-write self-check`

Matches the actual ordering in today's `write-run-note-morning-briefing/SKILL.md` (FIRST CHECK at line 123, SECOND CHECK at line 137, THIRD CHECK folded into the body-marker checks at line 169 — the v0.91.3 dvjs check is structurally last among the v0.91.x layers):

1. v0.91.1 path guard (`wrong-output-path`) — FIRST CHECK.
2. v0.91.2 frontmatter guard (`wrong-frontmatter:<field>`) — SECOND CHECK.
3. v0.91.3 dvjs canonical pattern (`wrong-dvjs-pattern`) — THIRD CHECK (currently part of body-marker regex; v0.92.0 keeps the dvjs check separately, immediately before the body-shape sub-section).
4. **v0.92.0 body-shape guard (`body-shape:<reason>`) — FOURTH CHECK, NEW.**
5. v0.78.0 belt-and-suspenders structural markers (`body-missing-*`) — kept.
6. v0.78.0 frontmatter completeness (`frontmatter-missing-*`) — kept.

### 6.4 — Cross-cadence consistency

All 5 write-run-note sub-skills get the IDENTICAL v0.92.0 sub-section verbatim (with cadence-specific examples updated per cadence). HC harness asserts each sub-skill's `## Pre-write self-check` section contains the canonical sub-section header + the 3 failure tokens.

### 6.5 — No new helper for the write-guard

The guard logic is small (~10 lines of in-SKILL.md prose) and per-sub-skill specific. No `body-shape-validator-helper.js` is added. FLN-v92-1 queued for the day the 5 copies invite refactor.
