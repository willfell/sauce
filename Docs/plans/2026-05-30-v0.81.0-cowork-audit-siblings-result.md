## What shipped

New pure-read-only orchestrator-tier skill `cowork:audit-siblings` (`/cowork audit-siblings [<kind>]`). Closes the silent-degradation gap v0.80.0 left open: when a user authors siblings (per v0.80.0's sibling-file convention) and then deletes/renames a file or hand-edits `microscope.md`'s `## References` section, inconsistency was previously only caught by reading a shallow morning briefing. v0.81.0 surfaces both axes — **dangling references** (microscope.md names a sibling that doesn't exist; `[!warning]` per finding) and **orphan files** (sibling exists but isn't referenced; `[!info]` per finding) — and emits `[!success]` when clean.

**Components:**

1. **New pure helper** `platform/blueprints/cowork/helpers/audit-siblings-helper.js`. Exports `parseReferences(microscope_body) → string[]` (regex-driven extraction from `## References` and `## References (added)` blocks; em-dash separator required to match `composeMicroscope`'s output; dedupes across both header forms; first occurrence wins) and `auditSiblings({ kinds_dir_listing, microscope_bodies }) → { dangling, orphans }` (two-axis check; deterministic sort by `(kind, name)`; pure — no fs, no MCP).

2. **New orchestrator-tier SKILL.md** at `platform/blueprints/cowork/skills/orchestrators/audit-siblings/SKILL.md` (flattens to `{{skills_dir}}/audit-siblings/SKILL.md` per FLN-v79-4 dest convention). 6 prose steps: (1) read prefs, (2) resolve scope (`kind` input optional; defaults to all of `prefs.priorities`), (3) gather per-kind state via `mcp__obsidian__list_files_in_dir` + `mcp__obsidian__get_file_contents` (PURE — no gather calls), (4) call `auditSiblings` helper, (5) render findings as `[!warning]` / `[!info]` callouts per finding, (6) summary `[!success]` or `[!info]` rollup.

3. **Em-dash UX hardening note** added inline to SKILL.md step 5 per S2 code-review feedback (M3): documents that hand-editing a `## References` bullet with a hyphen instead of em-dash silently produces a false orphan flag, since the parser regex (`/^-\s+\*\*([^*]+\.md)\*\*\s+—/`) matches the exact em-dash `composeMicroscope` writes.

4. **Manifest claude_surface[] entry** added to `platform/blueprints/cowork/manifest.json` (orchestrator entry alongside `morning-briefing`, `edit-microscope`). CS-MIG-1 hardcoded counts in `run-claude-surface.js` bumped 37→38 skill entries / 46→47 contributions in lockstep (per FLN-v79-5).

5. **Boundary-contract doc** `Docs/agent-guides/cowork-customization-contract.md` gains a v0.81.0 paragraph noting `audit-siblings` is pure SAUCE-OWNED + read-only against USER-owned per-mcp data; no boundary impact.

## Sequencing observations + corrections (for next-cycle learning)

- **Em-dash UX hardening note (M3 finding) discovered at S2 code review.** The helper's `ENTRY_RX` regex requires em-dash `—` (U+2014) between `**<name>**` and the role description, matching what `composeMicroscope` emits. Code review pointed out that a user hand-editing a `## References` bullet with a hyphen (`-`) or en-dash (`–`) would silently produce a false orphan flag — the sibling exists, but the parser doesn't see it referenced. Folded into S4 as an inline SKILL.md note rather than as an additional helper case, since (a) the helper's behavior is correct (matches what the writer emits), and (b) the UX surface is the SKILL.md prose telling the user what em-dash looks like.

- **CS-MIG-1 lockstep dance worked cleanly.** S5's failing test (bump expected count from 37→38 / 46→47) preceded S6's manifest entry addition. This was a deliberate test-first sequencing per FLN-v79-5's still-open observation that the hardcoded counts must move in lockstep. Two-stage dance (S5 fail-first, S6 manifest-fix) keeps the test harness honest: if S6 had landed first, the harness would silently start producing 47 contributions while the assertion still expected 46, hiding the actual code change behind a "ALL GREEN" lie. **FLN-v79-5 remains open** — auto-derive the count from the materialize list rather than hardcoding.

- **S7 semver-regex discovery.** During S7 the workshop's preflight broke on three test files that had hardcoded semver-regex assertions `/^0\.(8|9|1\d)\.\d+$/` — accepting only cowork versions 0.8.x-0.19.x. Bumping cowork to 0.20.0 broke all three:
  - `platform/test/run-cowork-smoke.js`
  - `platform/test/run-claude-surface.js`
  - `platform/test/run-helper-cases.js`

  Widened inline at S7 to `/^0\.(8|9|[12]\d)\.\d+$/` (accepts 0.8.x-0.29.x). New FLN-v81-1 candidate: the pattern still has a future ceiling at 0.30.x. Either refactor to a version-comparison helper or compute from manifest.

- **Subagent-driven-development executed per `superpowers:subagent-driven-development`.** Each code stage went through implementer + spec reviewer + code quality reviewer dispatch where appropriate. Tight stages (S3 single-test addition, S5 mechanical 3-line edit) used inline spot-checks rather than full reviewer dispatch — judgment call consistent with v0.80.1 FLN-v801-3's codification ("docs-only and trivially-mechanical stages may spot-check inline at orchestrator's discretion").

- **Two-axis check is symmetric to v0.80.0's writer.** v0.80.0's `composeMicroscope` wrote `## References` blocks; v0.81.0's `parseReferences` reads them. The helper-first posture (helper handles deterministic logic; SKILL.md handles fs + MCP I/O) carried over from v0.80.0 cleanly. Future cycle: when adding a writer, anticipate the reader counterpart; symmetry reduces silent-degradation surface.

## §11 carry-forward (deferred to a follow-up cycle)

Per the design's explicit §11 list — NOT in v0.81.0 scope:

1. **`--fix` mode for audit-siblings** — auto-remove dangling references from microscope.md; auto-append orphan references with a TODO role string. v0.81.0 is informational only.
2. **Validation of `## References` role strings** — flag empty / `TBD` / `(role unspecified)` role text. Defer until a real pattern of TODO-roles surfaces in practice.
3. **Pre-commit hook** — auto-run audit-siblings on microscope.md or per-mcp/<kind>/ changes. Out of scope; on-demand via `/cowork audit-siblings` for now.
4. **Multi-vault audit** — audit all consumer vaults from the workshop in one pass. Maintainer-only utility.
5. **Sibling-body validation** — verify each sibling file is non-empty + has heading + has table/list. Currently the audit only checks existence/reference symmetry. Opt-in via a future `--strict` flag.

## Cycle-specific FLNs surfaced during v0.81.0 execution

- **FLN-v81-1: semver-regex ceiling.** Three test files (`run-cowork-smoke.js`, `run-claude-surface.js`, `run-helper-cases.js`) had assertions `/^0\.(8|9|1\d)\.\d+$/` accepting only cowork versions 0.8.x-0.19.x. Bumping cowork to 0.20.0 broke them; widened inline at S7 to `/^0\.(8|9|[12]\d)\.\d+$/` (accepts up to 0.29.x). Future ceiling at 0.30.x — refactor to a version-comparison helper, or compute the accepted range from the manifest at test-load time so it auto-tracks.

- **FLN-v81-2: M3 em-dash UX hardening surfaced at code review.** The S2 code-quality reviewer noted that the regex's em-dash requirement is correct (matches what `composeMicroscope` writes) but is invisible to users hand-editing `microscope.md`. Folded into SKILL.md prose at S4 rather than as a code change. Future plan-template wisdom: when a parser depends on a non-obvious character (em-dash, NBSP, zero-width joiner), document the requirement in the SKILL.md prose that the user will see, not just in the helper code comments.
