# v0.78.0 — cowork-consumption (design)

**Status:** design — pending plan + execution.
**Date:** 2026-05-27.
**Cycle topic slug:** `cowork-consumption`.
**Predecessor:** v0.77.0 (cowork-adaptive-detection), tag `v0.77.0`, HEAD `17de73d`.
**Trigger:** v0.77.0 shipped the capture layer (tool-pattern detection + capability-subset model + unknown-MCP custom-kind handling). On accuris, the user successfully captured a 5-MCP `user-preferences.md` (priorities, personality, calendar/email/chat as M365-UUID-served override_classified, ado/github as custom_kind, all with rich `what_matters` blocks). Immediately afterward the scheduled `cowork:morning-briefing` cron job fired against accuris and produced an atomic note that ignored all of it — priorities order, personality voice, custom kinds, and override_classified routing. The morning-briefing orchestrator was written before `user-preferences.md` existed; it has no code path that reads or honors it. v0.78.0 closes that gap across all 5 atomic-note orchestrators.

---

## 1. Cycle motivation

Three coupled workstreams against a single minor release (v0.78.0).

**Workstream A — read + priority-reorder + personality.** Build a new `cowork:read-user-preferences` sub-skill that parses `spice/cowork/context/user-preferences.md` and returns `{ prefs, status }`. Wire all 5 atomic-note orchestrators (morning-briefing, midday-tripwire, eod-review, weekly-review, monthly-review) to call it in pre-flight. Replace each orchestrator's hardcoded gather loop with a single loop driven by `prefs.priorities[]`. Compose a 5-line "voice contract" from `prefs.personality` (vibe / formality / pep_talk / length / notes) and prepend it to the orchestrator's prompt body before the composing-agent reads — applies to narrative sections only (frontmatter summary, `[!info]-` synopsis, `[!tip]` closing). Tabular `[!example]+` callouts are not voice-modified (their content comes from gather sub-skills under contract).

**Workstream B — vendor-agnostic gather for `override_classified` kinds.** On accuris, `mcps.calendar.served_by` is the Microsoft 365 UUID gateway (`45224a84-...`) — not Google Calendar. Same for email and chat. The existing `cowork:gather-calendar` is hardcoded to `mcp__claude_ai_Google_Calendar__*` tools. When `override_classified: true`, the orchestrator cannot assume the served_by namespace exposes the kind's canonical tool names. The gather has to use whatever tools the namespace actually exposes.

**Workstream C — gather for `custom_kind` kinds.** On accuris, `mcps.ado` and `mcps.github` are user-defined custom kinds (no entry in `mcp-skill-map.json`, no `cowork:gather-<kind>` skill exists). Each has a `served_by` namespace and a free-text `what_matters` block. The orchestrator has to gather from these namespaces too.

B and C collapse into ONE new sub-skill — `cowork:gather-from-served-by` — that takes `{ kind_name, kind_title, served_by, what_matters, question_set_answers?, today, range, timezone }`, enumerates the calling agent's `mcp__<served_by>__*` tools at fire time, dispatches the agent to gather per `what_matters`, and returns a `[!example]+ <kind_title>` markdown callout. The existing 3 vendor-locked gather sub-skills (gather-calendar, gather-gmail, gather-imessage) stay untouched and continue to handle the canonical-vendor case.

Together: A makes the orchestrators prefs-aware; B+C makes the prefs ACTIONABLE on environments like accuris where no canonical vendor MCP is present.

## 3. Workstream A — read + priority-reorder + personality

### 3.1 New sub-skill: `cowork:read-user-preferences`

Lives at `platform/blueprints/cowork/skills/skills/read-user-preferences/SKILL.md` (~80 lines).

**Inputs:** none (vault-relative path is fixed: `spice/cowork/context/user-preferences.md`).

**Outputs:**
```yaml
{
  prefs: {
    priorities: [<kind_name>, ...],
    personality: {
      vibe:      <string|null>,
      formality: <string|null>,
      pep_talk:  <boolean|null>,
      length:    <string|null>,
      notes:     <string|null>
    },
    mcps: {
      <kind_name>: {
        served_by:            <namespace>,
        what_matters:         <string>,
        connected:            <boolean>,
        captured_at:          <YYYY-MM-DD>,
        custom_kind:          <boolean (default false)>,
        override_classified:  <boolean (default false)>,
        ...kind-specific answer fields preserved verbatim (calendar: surface_event_kinds / include_all_day / quiet_hours_strategy; email: surface_kinds / inbox_zero_threshold / vip_senders / ignore_lists; chat: inner_circle / inner_circle_channels / surface_kinds / suppress_quiet_hours; finance: TBD per question set; custom kinds: free-form per user-preferences.md)
      },
      ...
    }
  },
  status: "ok" | "empty" | "malformed",
  reason: <string when status != ok>
}
```

**Steps (~7):**
1. Read `spice/cowork/context/user-preferences.md` via `mcp__obsidian__get_file_contents`. If missing → `{ status: "empty", reason: "file_not_found" }`.
2. Strip leading `---` … `---`; parse as YAML. On parse error → `{ status: "malformed", reason: <parse error> }`.
3. Assert `type: cowork-user-preferences`. If missing → `malformed`.
4. Apply existing v1→v2 migration helper (renames `mcps.gmail` → `mcps.email`, `mcps.imessage` → `mcps.chat`). Idempotent.
5. If `priorities == []` OR `mcps == {}` → `{ status: "empty", reason: "unpopulated_seed" }`.
6. Coerce missing optional fields to defaults (`personality.notes ?? null`, `mcps[kind].connected ?? false`, `mcps[kind].custom_kind ?? false`, `mcps[kind].override_classified ?? false`).
7. Return `{ prefs, status: "ok" }`.

**Implementation backing:** `platform/blueprints/cowork/helpers/read-user-preferences-helper.js` (~60 lines) exports `readUserPreferences({ vaultRoot })`. SKILL.md delegates to the helper so HC cases exercise the parser directly.

### 3.2 Pre-flight wiring — new step 3b in each of the 5 orchestrators

Add after `date-context` (step 3), before `ensure-daily-note` (step 4):

> **3b. READ `.claude/skills/cowork/skills/read-user-preferences/SKILL.md`** in full and follow its `## Steps` section with `{}`. Capture as `prefs_result = { prefs, status, reason }`. Capture `prefs = prefs_result.prefs` (may be empty when `status != "ok"`). Do NOT abort on `status != "ok"`; continue with legacy fallback.

### 3.3 New step 3c — dispatch planning (orchestrator-internal)

> **3c. Plan dispatch table.** If `prefs_result.status != "ok"`, set `dispatch_mode = "legacy"` and skip to step 5 (existing v0.77.0 gather loop unchanged). Emit Notice `cowork:<orch> -- user-preferences <status> (<reason>); using engagement-template defaults`.
> 
> Else (`status == "ok"`), set `dispatch_mode = "prefs"` and build `dispatch_plan[]` as an ordered list, one entry per `prefs.priorities[i]`:
> 
> ```
> for kind_name in prefs.priorities:
>   if kind_name not in prefs.mcps:
>     dispatch_plan.push({ kind_name, action: "warn", reason: "not_classified" })
>   else if prefs.mcps[kind_name].connected == false:
>     dispatch_plan.push({ kind_name, action: "warn", reason: "not_connected" })
>   else if prefs.mcps[kind_name].served_by not in check_vault_routing_result.reachable_namespaces:
>     dispatch_plan.push({ kind_name, action: "warn", reason: "served_by_unreachable" })
>   else if prefs.mcps[kind_name].custom_kind == true:
>     dispatch_plan.push({ kind_name, action: "gather_from_served_by",
>                         served_by: <ns>, what_matters: <text>,
>                         kind_title: titleCase(kind_name) })
>   else if prefs.mcps[kind_name].override_classified == true:
>     dispatch_plan.push({ kind_name, action: "gather_from_served_by",
>                         served_by: <ns>, what_matters: <text>,
>                         question_set_answers: <kind-specific answers>,
>                         kind_title: canonicalTitle(kind_name) })
>   else (canonical-vendor known kind):
>     dispatch_plan.push({ kind_name, action: "gather_canonical",
>                         gather_skill: mcp_skill_map.kinds[kind_name].gather_skill })
> ```
> 
> Where:
> - `titleCase(kind_name)` — capitalize first character of each whitespace-or-underscore-separated word; e.g., `ado` → "Ado", `github` → "Github", `monitoring` → "Monitoring".
> - `canonicalTitle(kind_name)` — fixed lookup: `calendar` → "Calendar", `email` → "Email", `chat` → "Chat", `finance` → "Finance".

### 3.4 Voice-contract prompt prefix

After step 13 (read prompt body) and before step 14 (compose run-body), insert step 13b:

> **13b. Compose voice contract prefix.** If `prefs_result.status == "ok"` AND `prefs.personality` has any non-null field (vibe / formality / pep_talk / length / notes), compose:
>

> - Vibe: <prefs.personality.vibe or "default">

> - Length: <prefs.personality.length or "default">
> - Notes: <prefs.personality.notes verbatim, single-line>
> 
> Apply this voice ONLY to narrative sections (frontmatter summary, [!info]- synopsis, [!tip] closing). Do NOT apply to tabular [!example]+ blocks (their content comes from gather sub-skills and is contractually shaped).
> 
> ---
> 
> ```
> 
> Prepend this prefix to `prompt_body`. The combined string becomes the input to step 14 composition. If personality fields are all null OR `prefs_result.status != "ok"`, prefix is empty string and `prompt_body` passes through unchanged.

## 4. Workstream B + C — `cowork:gather-from-served-by`

### 4.1 New sub-skill

Lives at `platform/blueprints/cowork/skills/skills/gather-from-served-by/SKILL.md` (~120 lines).

**Inputs:**
```
{
  kind_name:            <string>,                     // "calendar" | "email" | "chat" | "ado" | <custom>
  kind_title:           <string>,                     // markdown section title for the [!example]+ callout
  served_by:            <namespace>,                  // e.g., "45224a84-ce0e-459b-a016-909ab178ad8c"
  what_matters:         <string>,                     // free-text gather contract from user-preferences.md
  question_set_answers: <object|null>,                // null for custom_kind; populated for override_classified known kinds
  today:                <YYYY-MM-DD>,
  range:                { start: <YYYY-MM-DD>, end: <YYYY-MM-DD> },
  timezone:             <IANA>                        // e.g., "America/Denver"
}
```

**Outputs:**
```
{
  markdown:        <"> [!example]+ <kind_title>\n> ...">,
  status:          "ready" | "skipped:no-tools" | "failed:served-by-unreachable" | "failed:bad-output" | "failed:<reason>",
  served_by_used:  <namespace>,                       // echoes input
  tools_used:      [<tool_name>, ...],                // for audit
  reason:          <string when status != "ready">
}
```

**Steps (~9):**
1. Enumerate the calling agent's tool list. Filter to `mcp__<served_by>__*`. Capture as `available_tools[]`. If empty → `{ status: "skipped:no-tools", reason: "served_by namespace exposes no tools in this session" }`.
2. Optional reachability probe: pick one cheap list/get-style tool from `available_tools` and call it with a minimal argument. On `MCP_UNAVAILABLE` or equivalent → `{ status: "failed:served-by-unreachable" }`. Skip the probe when `available_tools.length == 1` or when no obvious list-verb exists (degrade gracefully — let the agent's later calls surface unreachability).
3. Compose internal dispatch prompt for the gathering agent:
   - Header: `"Gather <kind_name> data for <today> from MCP namespace <served_by>."`
   - Inject `what_matters` verbatim under `"**What matters**:"`.
   - If `question_set_answers != null`, inject as `"**Captured answers**:"` YAML block.
   - List `available_tools` so the agent knows what's reachable.
   - Specify output contract: `"Return ONE > [!example]+ <kind_title> markdown callout. Aim for ≤200 words. Bulleted lines. No tables (output shape is intentionally loose for cross-vendor portability). Honor what_matters as the gather contract."`
   - Inject `range` and `timezone`.
4. **Agent dispatch (inline).** The orchestrator's executing agent IS the calling agent. The SKILL.md instructs the executing agent to compose the dispatch prompt mentally, then directly invoke the chosen `available_tools[]` and compose the callout. We do NOT spawn a subagent (subagent dispatch loses MCP tool access).
5. Capture returned markdown. Validate:
   - Must start with `> [!example]+ ` followed by `kind_title`.
   - Must NOT contain unescaped triple-backticks at top level (preserves callout integrity).
   - Length sanity: ≥ 80 chars (one-line "no data" callout is fine; sub-minimum suggests truncation).
6. On validation failure → `{ status: "failed:bad-output", reason: <regex-miss-name> }`.
7. Return `{ markdown, status: "ready", served_by_used, tools_used }`.

### 4.2 Orchestrator gather phase — single priority-ordered loop

When `dispatch_mode == "prefs"`, replace v0.77.0 gather steps 5-12 with:

> **5. Iterate `dispatch_plan[]` in order.** For each entry:
> 
> ```
> for entry in dispatch_plan:
>   if entry.action == "warn":
>     warning_md = composeWarningCallout(entry.kind_name, entry.reason, prefs.mcps[entry.kind_name])
>     ordered_blocks.push({ kind_name: entry.kind_name, markdown: warning_md, kind: "warning" })
>   elif entry.action == "gather_canonical":
>     # invoke existing gather skill (gather-calendar, gather-gmail, gather-imessage, gather-finance-yesterday, gather-projects, gather-threads)
>     result = invoke(entry.gather_skill, { engagement_id, date_today, ... })
>     ordered_blocks.push({ kind_name: entry.kind_name, markdown: result.markdown, kind: "example" })
>   elif entry.action == "gather_from_served_by":
>     result = invoke("cowork:gather-from-served-by", {
>       kind_name: entry.kind_name,
>       kind_title: entry.kind_title,
>       served_by:  entry.served_by,
>       what_matters: entry.what_matters,
>       question_set_answers: entry.question_set_answers,
>       today: context.today,
>       range: <orchestrator-specific window per the table below>,
>       timezone: engagement.timezone || "America/Denver"
>     })
>     if result.status == "ready":
>       ordered_blocks.push({ kind_name: entry.kind_name, markdown: result.markdown, kind: "example" })
>     else:
>       warning_md = composeWarningCallout(entry.kind_name, result.status, prefs.mcps[entry.kind_name])
>       ordered_blocks.push({ kind_name: entry.kind_name, markdown: warning_md, kind: "warning" })
> ```
> 
> After the loop, run engagement-type-aspect gathers (semantic_related per render_aspects, finance_block per render_aspects) per their existing contracts. Append their markdown to `aspect_blocks[]` AFTER `ordered_blocks[]` at body composition time.

When `dispatch_mode == "legacy"`, execute the v0.77.0 gather steps 5-12 verbatim. `ordered_blocks[]` stays empty; legacy gather outputs flow through their existing composition slots.

**Per-orchestrator default `range`** for `gather-from-served-by` invocations:

| Orchestrator | range.start | range.end |
|---|---|---|
| morning-briefing | `context.today` | `context.today + 2 days` |
| midday-tripwire | `context.today` | `context.today` |
| eod-review | `context.today` | `context.today` |
| weekly-review | `context.week_start` (Monday of `context.today`) | `context.week_end` (Sunday) |
| monthly-review | first day of `context.today`'s month | last day of `context.today`'s month |

### 4.3 `composeWarningCallout` — canonical warning strings

Three reasons map to three canonical wordings (no paraphrasing — test fixtures match exactly):

```
not_classified:
> [!warning] <kind_title> not classified
> Kind `<kind_name>` appears in priorities[] but has no entry in mcps in user-preferences.md.
> Run `/cowork preferences` to classify this kind.

not_connected:
> [!warning] <kind_title> not connected at capture time
> Kind `<kind_name>` was captured with `connected: false` on <captured_at>.
> Re-run `/cowork preferences` after the MCP is connected.

served_by_unreachable:
> [!warning] <kind_title> served-by namespace unreachable
> Kind `<kind_name>` is served by `<served_by>`, but that MCP namespace is not reachable in this session.
> Verify the MCP is connected (check `claude mcp list`), then re-run.
```

The same `served_by_unreachable` wording is reused when `gather-from-served-by` returns `status: skipped:no-tools` or `status: failed:served-by-unreachable` (semantically equivalent for the user).

When `gather-from-served-by` returns `status: failed:bad-output`, emit:

```
> [!warning] <kind_title> gather failed (output validation)
> Kind `<kind_name>` gathered from `<served_by>` but the returned markdown failed structural validation: <reason>.
> File a sauce issue if this recurs.
```

`kind_title` in all warnings derives via the same `titleCase` / `canonicalTitle` rules from §3.3.

## 5. Body composition contract — write-run-note adaptive skeleton changes

Each of the 5 `write-run-note-<orch>` SKILL.md files gets the same edits in its `## Adaptive body skeleton` section:

**Addition 1: Example blocks render in priority order.**

> When the orchestrator passes `ordered_blocks[]` (priority-ordered), emit them in array order. The first `[!example]+` block is the highest-priority kind, last is the lowest. Engagement-type-aspect blocks (semantic_related, finance_block from render_aspects) render AFTER all priority-ordered blocks. When the orchestrator passes no `ordered_blocks[]` (legacy fallback / dispatch_mode == "legacy"), section ordering matches the v0.77.0 hardcoded order.

**Addition 2: Custom Example titles are accepted.**

> `[!example]+ <title>` callouts no longer require the title to match a known section name. Title may be any short string (≤60 chars, no newlines). Pre-write self-check's `body-missing-example-admonition` rule still applies (≥1 example admonition required), but no longer scopes the match to a fixed title set.

**Addition 3: Voice contract is applied to narrative sections.**

> When the orchestrator-composed body includes a `Voice contract:` prefix block (introduced by the literal line `Voice contract (from spice/cowork/context/user-preferences.md):`), the composing-agent applies it to:
> 
> - frontmatter `summary` (1-2 sentences)
> - `[!info]- Today at a glance` paragraph
> - `[!tip] Today's focus` paragraph and closing action
> 
> The voice contract MUST NOT influence:
> 
> - SpaceNavButtons block (verbatim)
> - `[!example]+` callouts (their content comes from gather sub-skills, structurally constrained)
> - `[!warning]` callouts (their wording is a canonical contract from the orchestrator)

**Pre-write self-check unchanged.** No new contract-violation codes. Existing checks (`frontmatter-missing-title`, `body-missing-navbuttons`, `body-missing-example-admonition`, `body-missing-tip-admonition`, `body-missing-warning-admonition-for-<key>`) all still apply — the skeleton is more permissive, not different-shaped.

## 6. Failure-mode matrix

| Failure | Detected at | Response | Body impact |
|---|---|---|---|
| `user-preferences.md` missing | pre-flight 3b | `status: empty` → LEGACY PATH | Body matches v0.77.0 byte-clean (modulo `prefs_status: empty` frontmatter + new Notice) |
| `user-preferences.md` malformed YAML | pre-flight 3b | `status: malformed` → LEGACY PATH | Same as missing |
| `priorities: []` or `mcps: {}` | pre-flight 3b | `status: empty` → LEGACY PATH | Same as missing |
| `priorities[]` references absent `mcps[]` kind | pre-flight 3c | In-position `[!warning] not classified` callout; skip gather | Body shrinks by one Example, gains one Warning. Priority order preserved |
| `mcps[kind].connected == false` | pre-flight 3c | In-position `[!warning] not connected at capture time` callout; skip gather | Same |
| `served_by` not in `check-vault-routing` reachable set | pre-flight 3c | In-position `[!warning] served-by unreachable` callout; skip gather | Same |
| `gather-from-served-by` returns `skipped:no-tools` | gather | Same canonical `served_by_unreachable` warning callout | Same |
| `gather-from-served-by` returns `failed:bad-output` | gather | `[!warning] <kind> gather failed (output validation)` callout; log to frontmatter `warnings[]` | Body gets the warning; orchestrator does NOT abort |
| `gather-from-served-by` raises | gather | Treat as `failed:bad-output` | Same |
| Canonical `gather-<kind>` returns `gather-skipped` | gather | Existing v0.77.0 behavior — in-position `[!warning] <section> unavailable` | Same as v0.77.0 |
| `write-run-note` returns `failed:contract-violation:*` | write | Abort cleanly, emit Notice, skip state updates | Existing v0.77.0 behavior preserved |

**Legacy path bit-for-bit preservation rule:** a vault with `priorities: []` (the workshop seed) MUST produce a v0.78.0 morning-briefing that diffs byte-clean against the same vault running v0.77.0 (modulo the new `prefs_status: empty` frontmatter field and the new Notice).
