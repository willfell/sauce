## What shipped (Phase 0)

- **`scripts/release/lib/semver-inc.js`** — vendored zero-dep `parse` / `inc` / `maxLevel` / `RANK`.
- **`scripts/release/lib/conventional.js`** — vendored zero-dep `parseCommit` (header + `!` + `BREAKING CHANGE`/`BREAKING-CHANGE` footer + `Release-As:` footer) and `bumpLevel` (standard semver, pre-1.0 aware).
- **`scripts/release/compute-release.js`** — attribution (commit files → component via manifest `path` prefix; shared roots → umbrella), `computePlan`, `applyPlan` (updates catalogue + per-component manifests + ranch pins + package.json; **never** the contract), changelog, `getCommits`/`lastTag` git readers, and a CLI: **dry-run by default, writes only under `--write`.**

## Grounding findings that reshaped scope (verify-before-design wins)

These were discovered by reading the real code and **corrected the brainstorm design before any code was written** — the reason the lockstep collapse is staged rather than rushed:

1. **`scripts/` is zero-dep by house rule** (`rebaseline-seed.js`: "Zero-dep. Node built-ins only."). Overrode the brainstorm's "over libs" call → vendored a ~40-line classifier + ~15-line semver-inc instead of adding `semver` + `conventional-commits-parser`. Strictly safer for CI `--omit=dev`; matches convention.
2. **`contract_version` is NOT a cowork mirror** — it's `0.35.1` while cowork is `0.40.2`, an independently hand-versioned contract. Landmine #20's "mirror exactly" wording is stale. The bumper explicitly does **not** touch it (asserted: HC-V0129-RELEASE-WRITE-G).
3. **`ranch/platform-subscription.json` can lead `package.json`/`manifest` within a minor** — the existing version assertions are within-minor range regexes (`/^0\.128\.\d+$/`) precisely to tolerate this. Any Phase 0b snapshot collapse must preserve that tolerance (major.minor compare, allow patch drift).
4. **Two version records per component** (catalogue in `platform/manifest.json` + each `platform/<path>/manifest.json`) plus the ranch pin — all hand-synced; the catalogue is hand-maintained (no generator). `applyPlan` updates all of them.
5. **`.gitignore` `/Scripts/` collides with `scripts/`** on case-insensitive macOS (`core.ignorecase=true`) — `git add` of a *new* file under `scripts/` silently no-ops (the git cousin of `lesson_write_tool_silent_noop`). Must `git add -f`, **one path per invocation** (even multi-path `-f` dropped a file). Existing tracked `scripts/` files are unaffected. Left `.gitignore` alone (intentional workshop-root mask; my files are force-added + tracking-verified).
