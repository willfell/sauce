# v0.80.0 — cowork-sibling-files (design)

**Status:** design — pending plan + execution.
**Date:** 2026-05-30.
**Cycle topic slug:** `cowork-sibling-files`.
**Predecessor:** v0.79.0 (cowork-microscope), workshop `0.79.0` closed 2026-05-29, HEAD `492bc6d`.
**Trigger:** v0.79.0 introduced three resolution paths in `cowork:edit-microscope`'s gap-finding step (`resolvable-in-gather` / `mcp-ceiling` / `user-supplied`). The first two are fully implemented — `resolvable-in-gather` instructs the gather to call an additional MCP tool (e.g., iMessage's `search_contacts`); `mcp-ceiling` surfaces a recommendation to swap the MCP (e.g., `lharries/whatsapp-mcp`). The third path, **`user-supplied`**, is a placeholder: the `classifyGap` helper returns `{ resolution: "user-supplied", note: "maintain a sibling file (e.g. contacts-map.md) the gather reads" }` and `edit-microscope/SKILL.md` step 4 says "offer to maintain a sibling file (e.g. `per-mcp/<kind>/contacts-map.md`)" — but the gather has no mechanism to discover OR read sibling files, and `edit-microscope` has no mechanism to scaffold them. v0.80.0 closes this third path: defines the per-kind sibling-file convention, wires gather-side discovery + injection, and extends `edit-microscope` to scaffold siblings inline when the user-supplied gap surfaces.

**The thesis.** `user-supplied` gaps surface every time a USER has knowledge the MCP doesn't expose: phone-number→name mappings for chat MCPs, account-ID→nickname mappings for finance, project-code→description mappings for ADO, VIP lists for any inbox. v0.79.0's microscope contract is the deep gather instruction; sibling files are the deep gather *data*. Together they make the briefings reflect the user's mental model of their own data, not the MCP's flat representation.

## 2. Architecture findings (from v0.79.0 anchors)

- **The convention's hook already exists.** `edit-microscope/SKILL.md` step 4 and `edit-microscope-helper.js:35` (`classifyGap` user-supplied note) both name `contacts-map.md` as the example sibling. v0.80.0 makes the convention real on both sides (authoring + consumption).
- **The gather's dispatch contract is the natural injection point.** `gather-from-served-by/SKILL.md` Step 3 ("Compose dispatch contract") is where `what_matters` is injected verbatim and (since v0.79.0) `**Hard rules ...**` block is appended. Sibling files slot in between: after `what_matters`, before hard rules.
- **The orchestrator already reads per-kind files at dispatch time.** v0.79.0 added step 2b: for each `kind_name`, read `per-mcp/<kind_name>/microscope.md` if present. Step 2c mirrors this for sibling files (glob + read).
- **Boundary preservation is already covered.** `HC-V0760-A1`'s `FOCUSED_USER_PATHS` was extended in v0.79.0 S12 with `spice/cowork/prompts/per-mcp/finance/microscope.md` — but the structural check uses an exact-path match, not a glob. The check is enforced as "no listed USER path appears in cowork files[] without materialize_once." Adding `microscope.md` covered the design's per-mcp/** glob via one representative entry. v0.80.0 needs no FOCUSED_USER_PATHS extension because sibling files use the SAME directory and posture — they're already covered by construction (per-mcp/** is not in cowork files[] at all). A new behavioral guard (HC-V0800-F1) mirrors `HC-V0790-F1`'s synthetic-workshop pattern for a non-microscope sibling file.
- **edit-microscope's helper is pure and dry-runnable.** v0.79.0's `composeMicroscope` + `classifyGap` + `resolveKind` exports already exist as pure functions exercised by HC-V0790-E1..E3. v0.80.0 adds `composeSibling` to the same module — same posture (pure, no fs/MCP, harness-testable).

## 3. Sub-deliverable A — sibling-file convention

### 3.1 The artifact

`spice/cowork/prompts/per-mcp/<kind>/<name>.md` — any markdown file in the per-kind microscope dir EXCEPT `microscope.md` itself and any file whose name starts with `_`.

- **USER-owned and never overwritten.** NOT in cowork's `files[]`; created on demand by `cowork:edit-microscope` (or by hand). `sauce update`/`reinstall` never touch sibling files by construction (same posture as `microscope.md` from v0.79.0).
- **Read-and-followed, not invoked.** A context file the gather reads verbatim — NOT a registered Claude Code skill.
- **Format is opaque markdown.** No schema, no validation. Common shapes: a markdown table (e.g., `| phone | name |` for `contacts-map.md`), a bulleted list (e.g., `vip-list.md`), or free prose (e.g., a project-code glossary). The agent reads the file and applies it per microscope.md's narrative guidance.
- **Underscore-prefix escape.** Files named `_*.md` are NEVER injected — convention reserves these for the user's drafts / archived versions / scratch material that lives in the same dir but should not reach the gather.
- **No filename schema.** `contacts-map.md`, `vip-list.md`, `account-aliases.md`, `project-codes.md` — all valid; user picks what works for them. Convention recommends `kebab-case-purpose.md`.

### 3.2 Boundary contract (already covered + one note)

- v0.79.0's `Docs/agent-guides/cowork-customization-contract.md` USER table already lists `spice/cowork/prompts/per-mcp/**/*.md`. v0.80.0 adds one explicit sentence: *"Sibling files alongside `microscope.md` follow the same posture — USER-owned, NOT in `files[]`, never overwritten; scaffolded on demand by `cowork:edit-microscope`'s user-supplied gap path."* No new table row.
- `HC-V0760-A1` `FOCUSED_USER_PATHS` needs no extension (the v0.79.0 microscope.md entry is the representative for the whole per-mcp/** glob — the structural check is fail-closed on the glob's posture).
- A new behavioral guard `HC-V0800-F1` mirrors v0.79.0's `HC-V0790-F1` scaffold (synthetic workshop + write sentinel at a non-microscope sibling path + reinstall + assert byte-identical + no .bak).

## 4. Sub-deliverable B — discovery + injection

### 4.1 Orchestrator discovery (step 2c)

Each of the 5 atomic-note orchestrators gains a new step 2c immediately after the existing step 2b (microscope read):

> **2c. Read per-kind sibling files.** For each `kind_name` in `prefs.priorities`, list the contents of `spice/cowork/prompts/per-mcp/<kind_name>/` via `mcp__obsidian__list_files_in_dir` (treat dir-not-found as empty). Filter the result to `*.md` files, excluding `microscope.md` and any filename matching `^_.*\.md$`. For each remaining file, read its body via `mcp__obsidian__get_file_contents`, strip any leading frontmatter, and append `{ name: <filename>, body: <stripped body> }` to `siblings[kind_name]`. Kinds without a per-mcp dir, or with only `microscope.md` + `_*.md` files, get `siblings[kind_name] = []`.

This step is PURE — no MCP gather calls, no writes. It builds in-memory state alongside `microscopes[]` (from step 2b) for the gather phase.

### 4.2 Gather-loop wiring (per-orchestrator)

In each orchestrator's `gather_from_served_by` input object inside the priority loop, add one line:

```
siblings: siblings[entry.kind_name] || []
```

This sits alongside the existing `hard_rules: prefs.effective_hard_rules` line from v0.79.0. No other change.

### 4.3 `gather-from-served-by` contract change

**Inputs frontmatter** gains: `siblings: list[{name, body}]`.

**SKILL.md** gets a new section AFTER `## Hard rules` and BEFORE `## Dry-run mode`:

```markdown
## User-supplied reference

When the orchestrator passes a non-empty `siblings[]` input, inject each entry into the dispatch contract (Step 3) directly after the `**What matters:**` block and before the `**Hard rules ...**` block, formatted as:

**User-supplied reference: <name>**

<body>

The agent reads these as additional context and applies them per the microscope.md narrative (which by convention names each sibling and its role — e.g., "Use `contacts-map.md` to resolve sender phone numbers to display names before composing the callout"). Empty `siblings[]` → omit the section entirely. Sibling files are USER-owned context, never gather-shaped output; they bind the agent's INPUT, not its output structure.
```

**Helper** (`gather-from-served-by-helper.js`):
- Destructure `siblings` from input.
- Return new field `siblings_used: Array.isArray(siblings) ? siblings.map(s => s.name) : []` echoed in the success return (mirrors `hard_rules_applied`).

### 4.4 Why opaque markdown (not typed parsers)

Selected during brainstorming Q2. Typed lookup-and-substitute (pre-agent deterministic substitution) would be more powerful for the specific iMessage phone→name case but requires per-sibling schema definitions + parsers — and breaks the "general convention" promise (each new sibling type = new parser). Opaque injection is the YAGNI move: mirrors v0.79.0's hard_rules → prompt-level-trust model (the agent reads the rules and applies them; we don't post-process). Future cycle can add a hard-rule-style post-processor (see §11) if agent compliance proves insufficient.

## 5. Sub-deliverable C — `cowork:edit-microscope` authoring extension

### 5.1 New helper exports

- **`composeSibling({ kind_name, gap, suggested_name })`** → `{ name, body, status }`. Deterministic; harness-testable. Returns a starter template:
  - `name`: caller's `suggested_name` (helper does NOT pick; the SKILL flow proposes one and the user confirms; helper just uses what it's given).
  - `body`: a markdown skeleton — heading + one-paragraph "what this file is for" preamble derived from the gap + an empty markdown table whose columns are inferred from the gap text via simple regex heuristics:

    | Gap signal | Inferred columns |
    |---|---|
    | `/phone|number/i` | `\| phone \| name \|` |
    | `/email/i`        | `\| email \| name \|` |
    | `/account|id\b/i` | `\| id \| nickname \|` |
    | `/vip|priority/i` | `\| id \| reason \|` |
    | (no signal)       | `\| key \| value \|` |

  - `status`: `"ok"`.
- **`composeMicroscope` extension** — add an optional `siblings_to_reference: [{ name, role }]` arg. When non-empty, append a `## References` section enumerating each: `- **<name>** — <role>`. Order preserved. The deepen-pass branch (when `existing` is set) appends `## References (added)` to the existing content's appendix block.

`composeSibling` does NOT write to disk and does NOT check for overwrites — those are SKILL.md / agent responsibilities. The skill checks `mcp__obsidian__get_file_contents` for the path before invoking the helper; if the file exists, the skill tells the user to hand-edit and SKIPS the sibling creation for that gap.

### 5.2 SKILL.md step 4 user-supplied flow

In `edit-microscope/SKILL.md`, the existing `user-supplied` bullet under step 4 is expanded into a sub-flow:

1. Compute a suggested filename from the gap text (helper-side heuristic — same regex map as `composeSibling`'s column inference, plus a fallback to `<gap-slug>.md`).
2. Ask the user: *"I'd suggest creating `per-mcp/<kind>/<suggested_name>` with a starter template — preview below. Create it? (Y/n, or supply a different filename)"*. Show the preview from `composeSibling`.
3. On YES: pre-check whether the file already exists via `mcp__obsidian__get_file_contents` on `spice/cowork/prompts/per-mcp/<kind>/<name>` (treat not-found error as absent → safe to scaffold). If absent:
   - Write the body to `spice/cowork/prompts/per-mcp/<kind>/<name>` via `Write` tool.
   - Record `{ name, role }` in an in-memory `siblings_to_reference` list, where `role` is a one-line "use this for <X>" derived from the gap (the agent picks a concise wording; the user can hand-tune microscope.md later).
4. On YES but the pre-check found the file already exists: tell the user, skip the scaffold, prompt them to hand-edit — but STILL record `{ name, role }` in `siblings_to_reference` so the existing sibling gets the reference line in microscope.md if missing.
5. On NO: skip — proceed to the next gap.
6. At step 6 (compose/refine microscope.md), pass `siblings_to_reference` into `composeMicroscope` so the `## References` section lands in the same write.

### 5.3 Re-run behavior

On a re-run of `/cowork microscope <kind>`:
- Step 2 (read existing microscope.md) is unchanged.
- The skill ALSO lists existing sibling files in `per-mcp/<kind>/` (for display only — "your existing siblings: contacts-map.md, vip-list.md"). No auto-edit.
- New `user-supplied` gaps surfaced in this pass scaffold NEW siblings (subject to same-name guard in 5.2 step 4).
- **OUT OF SCOPE for v0.80** (deferred): interactive editing of existing sibling content (add/remove entries via the skill); a `/cowork sibling <kind> <name>` dedicated skill; sibling-file versioning / changelog. See §11.

### 5.4 Boundary safety

The skill only ever writes under `spice/cowork/prompts/per-mcp/<kind>/`. Refuses to write `microscope.md` (use the existing edit-microscope flow) or any `_*.md` filename (reserved for user drafts) via the sibling path. Consent-gated per the existing v0.79.0 ask-before-acting posture.

## 6. Failure-mode matrix

| Failure | Detected at | Response |
|---|---|---|
| `per-mcp/<kind>/` dir absent | orchestrator step 2c | `siblings[kind] = []`; gather omits the section. Byte-identical to v0.79.x for that kind. |
| Dir present, only `microscope.md` + `_*.md` files | step 2c | Same — empty siblings array. |
| Sibling file unreadable (MCP error / permission issue) | step 2c | Log a `siblings_read_failed` warning row; skip that file, continue with the rest. Best-effort. |
| Empty sibling body (after frontmatter strip) | step 2c | Skip silently — don't inject an empty reference block. |
| Same-name conflict at scaffold time | edit-microscope step 5.2.4 | Skill detects via `mcp__obsidian__get_file_contents` (exists? non-empty?), tells user, records reference but doesn't overwrite. Never clobbers a USER file. |
| Microscope absent but siblings present | orchestrator | Siblings inject normally; agent has no narrative guidance → uses them as raw reference. Degraded but functional (matches v0.79.0's "no microscope = canonical/override fallback" pattern). |
| `siblings_to_reference` entry whose file was NOT written (Write failed mid-flow) | edit-microscope step 6 | Drop that entry from the list before calling `composeMicroscope`. Don't emit a References line for a nonexistent file. |
| User puts a sibling in the dir manually (no microscope reference) | gather | Still injected (glob-based discovery). Agent treats as raw reference. No microscope-narrative guidance, but no harm. |
| Sibling content very large (>50KB) | step 2c | Inject anyway. The 80-char floor in gather-helper applies only to `agent_markdown` output, not input context. Future cycle could add a soft-limit warning (FLN). |

**Legacy preservation.** A vault with no sibling files (only `microscope.md` or no per-mcp dir at all) MUST produce a v0.80.0 briefing that diffs byte-clean against v0.79.x. Enforced by the v0.79.0 no-microscope legacy guards still passing.

## 11. Carry-forward (deferred to a follow-up cycle, by design)

Explicit FLN candidates surfaced during this design but OUT of v0.80.0 scope:

- **Interactive editing of existing siblings** — `cowork:edit-microscope` re-runs scaffold NEW siblings but don't edit existing ones (the user hand-edits the markdown table). A future skill or extended flow could read an existing sibling, ask the user to add/remove entries one at a time, and write back.
- **Dedicated `/cowork sibling <kind> <name>` skill** — separate slash command for sibling-only edits, decoupled from the microscope authoring loop. Brainstorming Q3 alternative; deferred.
- **Typed sibling parsers + deterministic pre-agent substitution** — instead of opaque markdown context, parse known sibling shapes (e.g., `contacts-map.md` as YAML phone→name) and pre-resolve identifiers in MCP responses before the agent composes. Brainstorming Q2 alternative; deferred (YAGNI — start with opaque, add typing if friction surfaces).
- **Hard-rule-style post-processor for sibling-application compliance** — mechanical pass that verifies every phone number in a chat callout actually maps to a name from `contacts-map.md` (when one is referenced). v0.80.0 is prompt-level trust only.
- **Sibling-file versioning / changelog** — track how a sibling deepens over time (the `_*.md` escape hatch is the closest thing to an archive convention; formal versioning is deferred).
- **Multiple-microscope-per-kind** — currently one `microscope.md` per kind. Could allow `microscope-morning.md` / `microscope-eod.md` for cadence-specific contracts. Deferred.
- **Soft-limit warning for very large sibling files** — no enforcement in v0.80.0; if a user drops a 1MB markdown table into per-mcp/<kind>/, the gather injects it whole. A future cycle could warn at orchestrator step 2c (e.g., `>50KB`).
- **Sibling-file-aware reverse audit** — given a microscope.md that references `contacts-map.md`, check the file exists; warn if a `## References` entry points to a missing file. Useful but deferred.
