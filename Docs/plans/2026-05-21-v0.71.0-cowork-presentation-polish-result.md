## What shipped

- **`_canonical-vocab.json` `display_names` map** — top-level object mapping the 6 cowork-* atomic-note type strings to human-readable labels ("Morning Briefing", "EOD Review", etc.). Single source of truth.
- **`activity-feed@0.5.0`** — two additive opts on the v0.4.0 framed-group renderer:
  - `groupLabels: Record<string, string>` — caller-supplied display-name map; falls back to `_humanCase(key)` when absent. Activity-feed stays type-agnostic.
  - `groupPreviewBuilder: (pages) => string` — when supplied AND the group is in `defaultClosed[]`, appends ` — <text>` to the group header after `(N)` count. Truncated at 80 chars with `…` ellipsis. Empty return preserves count-only header.
  - `getSubtitle: (page) => string` also wired through the framed renderer (`metaBuilder` takes precedence when both passed).
- **`cowork@0.12.0`** — atomic-note contract grows `summary:{required:true,type:string}` + `warnings:{required:false,type:string[]}` on the 6 atomic-note rule_fragments. 6 `write-run-note-<orch>` sub-skills grow a uniform `## Body shape` section instructing Obsidian-native rendering: SpaceNavButtons block at top, `> [!info]- Today at a glance` synopsis, `> [!example]+` per-section blocks with markdown tables (calendar/email/projects/finance), `> [!warning]` for skipped gathers, `> [!tip]` close, and curated 1-2 sentence `summary:` frontmatter. 3 gather skills (`gather-{calendar,gmail,imessage}`) grow `## MCP routing` sections — at runtime introspect on the available tool list, pick first-available, emit `gather-skipped: no <kind> MCP available` cleanly when none. 15 per-engagement default prompts drop hardcoded MCP names + add gather-skipped handling. 3 cowork hub templates (Daily/Weekly/Monthly Hub) adopt the framed renderer with scoped `blueprints:` + cadence-ordered `groupOrder` + inline `groupLabels` (mirrors canonical-vocab — canonical-vocab.json isn't materialized as a standalone file in consumer vaults).
- **`daily@0.11.0`** — `SpaceDailyDashboard` consumes activity-feed v0.5.0's new opts. `getSubtitle` returns `frontmatter.summary` on cowork-* pages; `groupPreviewBuilder` returns the most-recent page's summary for `defaultClosed` groups (closes v0.70.0 carry-forward "one-line preview for collapsed groups"). `_renderActivityMeta` grows a minimal cowork-aware block appending a `.sauce-meta-subtitle` span with the curated summary on cowork-* rows. `_BLUEPRINT_PILL_COLORS` refactored to spread+extend, adding 6 cowork-* sub-type entries (morning=blue, midday=yellow, eod=purple, finance=cyan, weekly=pink, monthly=red) — closes v0.70.0 carry-forward "color individual cowork-* sub-type pills".

## Lessons

- **Test-label prefix scheme `HC-V07X` is ambiguous.** The pre-existing convention used `X` as the *patch* digit of v0.70.x (so v0.70.1 = V071). Reusing `V071` for v0.71.0 collided with three existing test families (`HC-V071-1` from v0.70.1; `AF-V071-1/2/3` from v0.4.1 strict-created_at). Resolved by switching this cycle's new asserts to `HC-V0710-*` + `AF-V0710-*` (4-digit zero-padded form). Future cycles should adopt the padded form going forward. Documented in plan errata-2 (commit `67f07be`) and the spec self-review.
- **Plan vs reality: `discriminator_tags`, not `types`.** The plan + design doc both referenced a fictional top-level `types` array in `_canonical-vocab.json`. The actual schema uses `discriminator_tags`. Caught by S1 implementer as NEEDS_CONTEXT. Resolution: substitute `discriminator_tags` everywhere; orphan-check intent preserved (all 6 cowork-* values were already in `discriminator_tags`). Documented in plan errata-3 (commit `6908096`).
- **Plan vs reality: `p.summary`, not `p.frontmatter.summary`.** This codebase accesses Dataview frontmatter via `p.<field>` directly (Dataview surfaces frontmatter at the top level of `p`). The 3 cowork hub templates I wrote in S8 used `p.frontmatter.summary` — worked in test fixtures (fake-dv builds explicit `frontmatter:` sub-objects) but would have been undefined in production. Caught by the S10 implementer's observation while reading existing helper code. Fixed in S10 follow-up commit `ee4e5d7`. **Lesson for future planning:** when writing Dataview-consumer code, grep existing helpers for the frontmatter-access idiom before drafting the new code. Don't trust JS-engine-frontmatter intuitions (which often expect `.frontmatter` sub-object) — Dataview pages flatten the keys.
- **Plan gap: CoworkLatestRuns helper was unscoped.** The design doc called for CoworkLatestRuns to prefer the curated `summary` over the body slice for the row preview, but no stage explicitly listed `cowork-latest-runs.js` in its file list. The helper edit landed in the S10 follow-up commit alongside the Dataview-access fix. **Lesson:** when surfacing a new frontmatter field across multiple consumers, audit ALL helper files reading the affected pages, not just the obvious renderer. CoworkLatestRuns reads `latest.summary` directly (same Dataview convention) and is now summary-preferring.
- **Pin cascade across run-*.js harnesses (v0.70.0 lesson #4 reaffirmed).** Task 3 bumped activity-feed manifest 0.4.1 → 0.5.0 and updated `run-activity-feed.js` pins (AF-1d + AF-V065), but missed the cross-harness pin `FA6-MANIFEST-activity-feed` in `run-helper-cases.js`. Surfaced by S4 implementer during full helper-cases regression. Mirrored the v0.70.0 commit `6877962` follow-up pattern with commit `dbafc51`. **Lesson:** when bumping a per-component manifest, grep `"<name>"` + `"<old-version>"` across ALL `platform/test/run-*.js` files BEFORE committing.
- **Hub-template hardcoded display-name map is the right trade-off.** The 3 cowork hub dataviewjs blocks need a 6-entry map to label group headers, but `_canonical-vocab.json` isn't materialized as a standalone file in consumer vaults (validator merges it via `extends:` into per-blueprint rules). Rather than introducing a new materialization path or customjs accessor, we hardcoded the 6 entries inline with a comment pointing to the canonical source. Bounded maintenance (6 entries × 3 files = 18 cells to keep in sync). The single source-of-truth lives at the platform level; consumer-side duplication is a leaf-node aesthetic concern.
