### FLN-v79-2 — `install.js` CLI handler (S1 + S2)

`platform/install.js` gains a CLI handler block gated on `require.main === module`. Previously the file exported only `async function(tp)` for Templater and silently ignored any shell flags; the canonical dogfood invocation `node platform/install.js --vault . --auto-approve` (used across CLAUDE.md / `Docs/agent-guides/build-test-verify.md` / plan templates) did nothing. The new handler parses `--vault <path>` plus passthrough flags (`--auto-approve` / `--decline-all`) and delegates to `platform/test/run-install.js` via `spawnSync`, propagating the subprocess exit code.

**Two in-stage hardening fixes** added during S2 code review:

- `--vault` with no value detection — without this guard, `--vault --auto-approve` would silently consume `--auto-approve` as the vault path, then the install would proceed with `--auto-approve` swallowed (no actual auto-approval). Now exits 2 with a clear error message.
- Mutual exclusion check for `--auto-approve` / `--decline-all` — passing both is nonsensical; exits 2 early instead of letting `run-install.js` resolve the conflict implicitly.

### FLN-v80-1 — HC-V0800-A1 glob regex softening (S3)

`platform/test/run-cowork-smoke.js` HC-V0800-A1's per-mcp glob regex was over-strict — it required the literal substring `per-mcp/<kind_name>/*.md` (with the glob inline) in the orchestrator step 2c prose. The semantically-identical split phrasing "list … per-mcp/<kind_name>/ … files matching `*.md`" failed the regex despite expressing the same contract. S3 collapses the original single-regex `assertTrue` into a `hasLiteralGlob || hasSplitPhrasing` boolean OR (7-line change). **Sub-assert count unchanged at 1** — the two regex tests collapse into a single boolean. Plan-template wisdom: either soften the regex this way or codify the literal-glob phrasing in the plan-template HC skeleton.

### FLN-v79-3 — 80-char `agent_markdown` floor documented (S4)

`Docs/agent-guides/build-test-verify.md` gains a new `## Writing HC cases` subsection documenting `cowork:gather-from-served-by`'s 80-char `agent_markdown` floor with the canonical 4-line fixture pattern (the `> [!example]+ Chat\n> - Alice: …\n> - Bob: …\n> - Carol: …` skeleton) and the +1-bullet fix that recovers an under-floor test fixture. v0.79.0 plan's HC-V0790-B3/D1 input was 78 chars; this section makes the floor and the canonical recovery pattern discoverable upfront.

### FLN-v79-4 — orchestrator-vs-sub-skill dest convention (S4)

`Docs/agent-guides/architecture.md` gains an orchestrator-vs-sub-skill dest convention paragraph: orchestrators flatten to `{{skills_dir}}/<name>/SKILL.md`; sub-skills nest under `{{skills_dir}}/skills/<name>/SKILL.md`. The v0.79.0 plan's S11.4 default put a new orchestrator's dest under the nested form (would have created a path mismatch); corrected inline. The new paragraph means future plan-template defaults can be cross-checked against an authoritative doc.

### FLN-v80-2 — landmine #16 narrative extended (S4)

`Docs/landmines.md` entry #16 narrative extended with the v0.80.0 + v0.80.1 observation that `materializeClaudeSurface` keeps SKILL.md dests current per-install regardless of the per-item version short-circuit. v0.79.0's close had documented landmine #16 as more load-bearing than v0.80.0's actual experience showed (per-stage installs DID propagate SKILL.md changes despite the per-item version-key short-circuit); the extended narrative records the corrective observation for future plans, which can stop predicting "deferred to S11" for SKILL.md dest drift.

## Sequencing observations + corrections (for next-cycle learning)

- **HC-V0801-A1 fixture growth ~8× plan estimate.** The S1 fixture was sketched in the plan as a tiny synthetic workshop with install.js + minimal mechanisms. At S2 the fixture grew substantially to support actually-spawning install.js as a subprocess (vs. just exercising its module exports): the real consumer-bootstrap pattern required workshop install.js + symlinked `mechanisms/` + an `installer-stub.js` dispatcher (for the existing harness's resolution path) + `git init` to satisfy `gitState`'s 40-char sha assertion. The first HC case in run-install.js to spawn install.js end-to-end; future end-to-end install.js HC cases can reuse the fixture skeleton.
- **In-stage code review caught 2 CLI handler hardening gaps.** S2's implementer-only pass missed `--vault` with no value (would silently consume the next flag) and the `--auto-approve` / `--decline-all` mutual-exclusion check. Both surfaced in the spec reviewer + code quality reviewer passes; folded in same-stage. Carry-forward: CLI handlers with positional args should always be reviewed for "value missing" + "mutually exclusive flags" + "flag-as-value" failure modes.
- **S3 regex relaxation was minimal.** 7-line change. Original single-regex `assertTrue` collapsed into `hasLiteralGlob || hasSplitPhrasing` boolean OR. Sub-assert count stayed at 1 (the regex variants collapse into one boolean test). Both reviews ran in parallel (small change, low blast radius).
- **S4 (docs-only) spot-checked inline rather than dispatched.** Pure-markdown changes to three docs (build-test-verify.md, architecture.md, landmines.md) with no behavioral risk; judgment call. The subagent-driven-development flow's reviewer dispatch is most valuable for code changes with semantic effects; pure-prose additions are within the orchestrator's normal review-and-commit capacity.
- **Subagent-driven-development executed per `superpowers:subagent-driven-development`.** Each code stage (S1, S2, S3) went through implementer → spec reviewer → code quality reviewer dispatch. S3's reviews ran in parallel (small change). S4 (docs) reviewed inline. S5 chore stage ran self-review only (version bumps + dogfood verification).
- **No blueprint/mechanism bumps.** This is a pure workshop PATCH — install.js CLI handler change is a code change with no `claude_surface[]` entry change; harness softening + doc additions don't touch consumer surfaces. Subscription pins refreshed only because workshop_version moved.

## Cycle-specific FLNs surfaced during v0.80.1 execution

- **FLN-v801-1: HC fixture growth surprise.** The S1 plan estimate (~5 lines) for HC-V0801-A1's synthetic consumer-bootstrap fixture undershot the S2 reality (~8× growth) because subprocess-spawning install.js end-to-end requires more scaffolding than module-import-only HC cases (symlinks, dispatcher stub, git init for sha-state assertion). Future plans for subprocess-spawning HC cases should budget a larger fixture upfront, or reuse this fixture skeleton.
- **FLN-v801-2: CLI handler review checklist worth codifying.** S2's in-stage review caught --vault no-value detection + --auto-approve/--decline-all mutual exclusion — two failure modes that a checklist would have surfaced before review. Candidate skill addition or plan-template note: "for any CLI handler with positional flags, verify (a) value-missing detection per positional flag; (b) mutual-exclusion among boolean flags; (c) unknown-flag rejection vs. passthrough behavior is explicit".
- **FLN-v801-3: S4 docs-only judgment call codification.** Skipping reviewer dispatch for pure-markdown changes worked here but is an undocumented heuristic. Worth a one-line note in `superpowers:subagent-driven-development` SKILL.md: "code stages dispatch implementer + reviewers; docs-only stages may spot-check inline at orchestrator's discretion".
