## Architecture delta (one paragraph)

v0.95.0 codified a 12-key plan-dispatch contract + `engagement.overrides` schema enabling per-engagement knob composition. v0.95.1 EXTENDS that contract by ONE key (`excluded_themes[]`, 13th) — derived from yesterday's memory.md carry-forward bullets when `render_aspects.anti_echo == "include"`, empty otherwise (always present). The three knobs share NO runtime data dependencies: **Knob 1** reads yesterday's memory via the existing `read-memory` sub-skill → emits one extra `[!question] Outside yesterday's frame` callout per MB/midday/EOD atomic note via `injectAntiEchoCallout` in compose-body. **Knob 2** reads the last 5 day-syntheses post-synthesize-day → ONE LLM call (`claude-haiku-4-5`, ~$0.50/year/engagement) extracts themes → deterministic `evaluateDrift` checks three flags (`frame_repeat ≥4/5`, `subject_dominance ≥3/5`, `explicit_null 3 consecutive`) → on any flag firing, appends `[!warning]- Frame may be stuck` callout to today's memory.md between synthesis section and `## Ticks` + frontmatter additions `frame_drift_flagged: true` + `frame_drift_at: <ISO>`; tomorrow's MB picks it up via read-memory's NEW `drift_warning` field (4-key return shape). **Knob 3** fires `cowork:morning-briefing --cadence lens_shift` weekly (default Saturday 07:00) with pre-flight steps 3a (read-memory) + 3a.5 (gather-semantic-related) SKIPPED → writes a "cold" companion atomic note with NEW `type: cowork-morning-briefing-cold` + slug `morning-briefing-cold-<engagement>.md`; `CoworkLensShiftCards` CustomJS renders warm + cold pair side-by-side on Daily Hub via slug-match (no `companion_to:` frontmatter — race-free). Each knob defaults OFF; bootstrap-vault interview adds 3 NEW opt-in Y/N questions per engagement so discoverability is high without conscripting anyone. Migrator design + plan (4 prior commits `d2d4e2c` / `2a2c00a` / `d11dae2` / `df214dd`) PARKED to v0.96.0+ with top-of-doc memos.

## Lessons (for v0.95.2 and beyond — 6 NEW)

### Lesson 1 — Bundled-MINOR with 3 distinct knobs fits in 17 stages when each follows the same template

Knob 1 / Knob 2 / Knob 3 each followed an identical four-step template (TDD-RED → helper → contract wiring → orchestrator wire-through). The parallel structure made the plan navigable + the commit history readable. **Carry-forward:** future bundled-MINOR cycles with N independent surfaces should adopt this template (RED → helper → contract → wire-through per surface). Where surfaces share data dependencies, fold them; where independent, parallelize the stage labels (S1.x / S2.x / S3.x).

### Lesson 2 — LLM theme extraction is the cold path; deterministic eval is the hot path

`claude-haiku-4-5` cost is negligible at daily firing (~$0.50/year/engagement; 5 syntheses → ~750 input tokens → ~200 output JSON tokens → ~$0.0014/fire). Don't optimize prematurely on prompt-caching or batch extraction — the deterministic-helper layer (`evaluateDrift`) is the hot path that fires every drift check; the LLM call is the once-per-day cold path. Theme-extraction prompt-cache optimization explicitly listed as out-of-scope in design § 1.2 + reserved as additive future PATCH if cost grows. **Carry-forward:** when introducing any LLM call as a tripwire dependency, calculate annual cost at daily firing FIRST; if <$1/year/engagement, the LLM dependency is "free" enough to skip optimization.

### Lesson 3 — Visual pairing via slug-match avoids race conditions cleanly

Knob 3's design considered `companion_to:` frontmatter linkage for warm/cold MB pair identification. Rejected in favor of CoworkLensShiftCards scanning for both notes by slug-pattern within the same day folder. No frontmatter coordination = no race conditions when warm + cold MB run in parallel = simpler. Cost: graceful degradation only — if CustomJS class breaks, user sees notes individually instead of paired. **Carry-forward:** when two cadences write companion atomic notes, prefer slug-match in the rendering layer over coordinated frontmatter writes between cadences. Coordination via shared filesystem state is fragile; coordination via render-time pattern-match is robust.

### Lesson 4 — activity-feed type-discovery mode matters; verify in S0.5 BEFORE writing RED tests

S0.5 verified activity-feed uses ENUMERATED type-filtering mode (not pattern-match `cowork-*` prefix), which required adding `cowork-morning-briefing-cold` to the allowlist before any cold-MB note would surface on Daily Hub. Had the mode been PATTERN-MATCH, S0.5 would have been a no-op verification. Codifying this as a dedicated S0.5 stage (not buried inside S3) prevented test-time surprise where K3 fixtures would have produced atomic notes that silently failed to surface in the activity feed. **Carry-forward:** any cycle introducing a NEW atomic-note `type:` value MUST verify activity-feed allowlist mode in S0 / S0.5 before writing RED tests. Add this as an explicit pre-flight item alongside helper-signature re-grep (v0.93.3 lesson 5.1).

### Lesson 5 — Top-level contract keys over embedded struct shapes for composability

Knob 1's `excluded_themes[]` was initially considered as a nested key inside `render_aspects.anti_echo` (struct shape: `render_aspects.anti_echo: { mode: "include", themes: [...] }`). Final design promoted `excluded_themes` to a top-level 13th contract key. Reasoning: composability with future tripwires (Knob 2's drift_warning surfaces tomorrow's MB via the read-memory shape, NOT plan-dispatch contract — different boundary) and with future Knobs that ALSO need yesterday-memory access without re-coupling to render_aspects. Top-level keys are easier to evolve independently. **Carry-forward:** when a new render-aspect needs additional runtime data, prefer a new top-level contract key over embedding inside the aspect's value. Render-aspect values stay as scalar opt-in/opt-out signals; contract data lives at top-level.

### Lesson 6 — Migrator parking pattern: status memos + brainstorm-state crosslink

v0.95.1 slot was originally allocated to a `sauce update --migrate-config` migrator (4 prior commits: design + 2 amends + plan). Re-prioritized to anti-echo at brainstorm time. Parking executed cleanly in S0.6: top-of-doc `> [!warning]+ Status: PARKED 2026-06-08` memos added to both migrator design + plan docs; brainstorm-state doc's v0.95.1 row + v0.96.0+ row updated to reflect the swap. The 4 prior commits remain preserved on disk + referenced in the parking memos — execution-ready when migrator resurrects. **Carry-forward:** when re-prioritizing displaces a queued cycle, the displacement is a 5-minute doc-only commit: parking memo on each displaced doc + brainstorm-state row update + (if a brainstorm-state doc exists) updated cell crosslinking. No code state churn required. Codify "parking memo + state crosslink" as a standard S0.x stage label for any future cycle that displaces queued work.
