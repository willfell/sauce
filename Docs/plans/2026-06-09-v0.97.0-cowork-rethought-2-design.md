# v0.97.0 cowork-rethought-2 — design

> [!info]+ Status
> DRAFT awaiting user spec review. Plan phase opens after approval.

## 0. Origin

Three days, three cycles. v0.96.0 shipped Rails W (sidecar), D (auto-discovery), L (per-kind learning). v0.96.1 patched the multi-engagement nesting + added Rail H (heartbeat). v0.96.2 hotfixed the daily-dashboard tsKeys filter.

Then production reality: looking at both vaults' 2026-06-09 morning briefings, NONE of the v0.96.x machinery is firing. The accuris note literally says *"This briefing was generated in simplified mode due to autonomous scheduled execution. Full orchestrator features (plan-dispatch, microscopes, gather-from-served-by) were not fully implemented in this run."*

The root cause: **claude.ai's Cowork UI cron environment doesn't load orchestrator SKILL.md files.** The cron LLM operates from the wrapper template prompt text + Obsidian MCP file reads only. Everything we authored inside SKILL.md bodies — the structured-output writer, the kind classifier, the sidecar schema, the rating callout emit, the heartbeat check — is dead code in production.

The headspace 2026-06-09 morning briefing is a counter-example: rich, voice-perfect prose. The LLM CAN produce excellent output from the wrapper template + MCP reads. The gap isn't capability — it's that the orchestrator instructions never reach the LLM.

This cycle confronts the architectural mismatch head-on:
- **The wrapper template IS the orchestrator** (Rail T).
- **Single-source orchestrator instructions** live in shared markdown (Rail O), substituted into both the wrapper template and a thin SKILL.md shim.
- **Sidecar emission via Obsidian MCP** instead of a Node helper the cron LLM can't execute (Rail S).
- **Auto-sync via `update_scheduled_task`** pushes wrapper changes programmatically — no manual paste (Rail A).
- **Local reconciler** runs nightly via launchd to update `learned_weights`, run `check-heartbeat`, backfill missing sidecars — pure Node, no LLM, runs against both vaults from this machine (Rail R).

## 1. Scope

Five independent rails ship as one bundled v0.97.0 MINOR.

### 1.1 The five rails

- **Rail O (Orchestrator-instructions).** Per-cadence shared markdown source at `data/orchestrator-instructions/<cadence>.md`. SKILL.md becomes a 5-line shim pointing to it. compose-helper substitutes `{{$tokens}}` + `{{shared.<key>}}` from `_shared-clauses.md` into the wrapper template. **Single source of truth replaces the SKILL.md vs wrapper-template duplication.**

- **Rail T (Wrapper templates inline orchestrator).** Wrapper template emitted into claude.ai's Cowork UI task prompt body becomes a complete, self-contained orchestrator. Cron LLM never has to find or load a SKILL.md — every step is in the prompt. Static tokens substituted at sync time; `{{$today_*}}` tokens stay literal (resolved at fire time by the LLM via PRELUDE Step 1 to eliminate the timestamp-drift class).

- **Rail S (Sidecar via Obsidian MCP).** Wrapper instructs LLM to write `.cowork.json` sidecar via `obsidian_put_content` immediately after writing the `.md`. No Node helper at fire time. Eventually-consistent: if sidecar write fails (rare), reconciler backfills overnight.

- **Rail A (Auto-sync via `update_scheduled_task`).** `cowork:sync-scheduled-jobs` becomes claude.ai-Cowork-UI native. Uses `list_scheduled_tasks` + `update_scheduled_task` + `create_scheduled_task` to push wrapper changes programmatically. Schedule preservation invariant: cron fields never touched. No manual paste.

- **Rail R (Local reconciler).** NEW `sauce reconcile-cowork [--all-vaults]` CLI subcommand. Pure Node + filesystem. New launchd plist fires nightly at 03:00 MT. Walks atomic notes + sidecars across both vaults; parses rating callouts; updates `learned_weights:` frontmatter; runs `check-heartbeat`; backfills missing sidecars from `.md` prose. One-time launchd install via `--install-launchd` flag.

### 1.2 What ships

## 3. Rail O design — orchestrator-instructions (single source)

### 3.1 File location

Workshop source:
```
platform/blueprints/cowork/content/data/orchestrator-instructions/
  ├── morning-briefing.md
  ├── midday-tripwire.md
  ├── eod-review.md
  ├── weekly-review.md
  ├── monthly-review.md
  └── _shared-clauses.md
```

Consumer-vault materialized at install:
```
<vault>/.claude/skills/cowork/data/orchestrator-instructions/<same files>
```

### 3.2 Per-cadence file shape (morning-briefing canonical)

Each cadence file is the FULL step-by-step orchestrator with `{{$token}}` substitutions. Sections:

1. Substitution tokens table (declared at top of file)
2. Step 0 — Pre-flight (vault routing, engagement resolve, date, user-preferences, inner-circle aliases)
3. Step 1 — Memory (yesterday's synthesis + carry-forward + drift_warning if v0.95.1 Knob 2 fired)
4. Step 2 — Gather priority loop (per-kind MCP calls with microscope adherence + inner-circle wikilink emission)
5. Step 3 — Compose body (synopsis → yesterday-at-a-glance → per-kind callouts → today's focus)
6. Step 4 — Rating callout (Rail L; if learning_enabled !== false; idempotent re-fire preserves [x])
7. Step 5 — Detection callout (Rail D; if pending_confirmations non-empty)
8. Step 6 — Anti-echo callout (v0.95.1 Knob 1; if render_aspects.anti_echo == include)
9. Step 7 — Write .md via `obsidian_put_content` (canonical frontmatter + dvjs block + body)
10. Step 8 — Write .cowork.json sidecar via `obsidian_put_content` (Rail S — v0.97.0 NEW)
11. Step 9 — State updates (active-threads, weekly-snapshot)
12. Step 10 — Done notice

Per-cadence variations: cadence name, frontmatter type, output path template, included/excluded steps. midday-tripwire skips microscopes. weekly/monthly use `week:` / `month:` instead of `day:`. lens_shift (v0.95.1 cold MB) is a conditional branch in morning-briefing.md that skips Steps 1 + 2c (memory + semantic gather) and switches frontmatter type.

### 3.3 SKILL.md becomes a 5-line shim

```markdown
---
name: cowork:morning-briefing
description: Engagement-aware morning briefing. Reads data/orchestrator-instructions/morning-briefing.md for the canonical step-list.
---

# cowork:morning-briefing

Read `<vault>/.claude/skills/cowork/data/orchestrator-instructions/morning-briefing.md` in FULL via the Read tool. Follow every step exactly. Inputs: `engagement_id` (required). Substitute `{{$engagement_id}}` with the input value when following the steps.
```

Local Claude Code invocations (`/cowork morning-briefing accuris`) work via: SKILL.md → Read tool → orchestrator-instructions/morning-briefing.md → step-by-step execution.

### 3.4 `_shared-clauses.md` content

Reusable clause blocks referenced via `{{shared.<key>}}` from per-cadence files:

| Shared key | Content |
|---|---|
| `dataviewjs_block` | Canonical `await dv.view("ranch/views/customjs-guard", { class: "SpaceNavButtons" })` fenced block |
| `connectivity_authority_clause` | "trust user-preferences.mcps served_by + connected as runtime authority" paragraph |
| `microscope_clause` | "for each kind, READ microscope.md and follow its ## Output shape directives" paragraph |
| `voice_clause` | "apply personality.notes verbatim AND personality.{vibe, formality, length, pep_talk}" paragraph |
| `sidecar_schema_template` | Canonical .cowork.json shape with substitution slots for cadence-specific values |
| `rating_callout_template` | `> [!todo]+ Was today useful?` markup with per-kind checkbox lines + sentinel |
| `detection_callout_template` | `> [!info]+ Cowork detected a new MCP` markup |
| `anti_echo_callout_template` | v0.95.1 Knob 1's `> [!question] Outside yesterday's frame` |
| `frontmatter_base` | Common frontmatter keys (type/engagement_id/title/summary/created_at) |

When compose-helper substitutes `{{shared.sidecar_schema_template}}` in a per-cadence file, it inlines that block. The wrapper template thus carries full schema/callout markup inline — but the source-of-truth is the shared file.

### 3.5 Substitution tokens (canonical set)

**Static (substituted at sync time):**
- `{{$engagement_id}}`, `{{$engagement_label}}`, `{{$timezone}}`
- `{{$voice_notes}}`, `{{$voice_summary}}`
- `{{$priorities}}` (comma-separated kind list)
- `{{$mcp_dispatch_lines}}` (per-kind served-by lines)
- `{{$inner_circle}}` (comma-separated person aliases)
- `{{$schema_version}}`, `{{$workshop_version}}`, `{{$cowork_version}}`, `{{$contract_version}}`

**Fire-time (literal in wrapper; LLM resolves at fire time per PRELUDE Step 1):**
- `{{$today_date}}` — YYYY-MM-DD ISO
- `{{$today_weekday}}` — e.g. Tuesday
- `{{$today_month_name}}` — e.g. June
- `{{$today_year}}` — e.g. 2026
- `{{$today_dirpath}}` — `<YYYY>/<MM-Month>/<YYYY-MM-DD>`
- `{{$today_ymd_compact}}` — YYYY-MM-DD compact

Fire-time resolution eliminates the timestamp-drift class entirely (the bug fixed in v0.96.2 — cron fires past midnight stamping yesterday's wrapper-cached date into today's `day:` field).

## 4. Rail T design — wrapper templates inline the full orchestrator

### 4.1 Wrapper template structure

After Rail T, each (cadence × engagement) wrapper template has this shape:

```
You are running cowork:<cadence> for engagement {{$engagement_id}} ({{$engagement_label}}).

# Step PRELUDE — fire-time setup

1. Resolve today's date in {{$timezone}}. Capture today_date/weekday/month_name/year/dirpath/ymd_compact.
2. Read vault-config + user-preferences + people-aliases via Obsidian MCP.

# Orchestrator step-list

<everything from orchestrator-instructions/<cadence>.md, statically substituted>

# Step DONE

N. Emit Obsidian Notice `cowork:<cadence> complete -- {{$engagement_label}} {{$today_date}}`.

---

Generated against sauce {{$workshop_version}} + cowork {{$cowork_version}} + contract {{$contract_version}}.
```

The PRELUDE is identical across cadences. The body is per-cadence from orchestrator-instructions. The closing line is identical.

### 4.2 compose-scheduled-job-wrappers-helper.js — what changes

Current helper (v0.93.0+): reads `wrapper_template` string field from scheduled-job-contract.json, substitutes `{{$tokens}}`.

After Rail T:
- `wrapper_template` field in scheduled-job-contract.json **goes away**. Replaced by `wrapper_template_source: "orchestrator-instructions/<cadence>.md"` pointer.
- Helper:
  1. Loads `orchestrator-instructions/<cadence>.md`
  2. Loads `_shared-clauses.md`
  3. Substitutes `{{shared.<key>}}` from `_shared-clauses.md`
  4. Substitutes static `{{$<token>}}` from engagement/prefs/contract context
  5. Wraps with PRELUDE prefix + DONE suffix
  6. Returns composed wrapper string

### 4.3 lens_shift variant

`orchestrator-instructions/morning-briefing.md` is shared between warm + cold MB. Carries a `{{$cadence_mode}}` substitution (`warm` or `lens_shift`). Conditional branches inside the file via `{{#if cadence_mode == "lens_shift"}}...{{else}}...{{/if}}` template syntax substitute the right branch at compose time. Cold mode skips Step 1 (memory) and Step 2c (semantic gather); uses frontmatter type `cowork-morning-briefing-cold`.

### 4.4 Migration: SKILL.md content moves to orchestrator-instructions

Each of the 5 existing cadence SKILL.mds migrates its step-by-step content VERBATIM into `orchestrator-instructions/<cadence>.md`. lens_shift's cold-MB branch (added v0.95.1) migrates INTO morning-briefing.md as the `{{#if cadence_mode == "lens_shift"}}` conditional branch — no separate lens_shift SKILL.md exists. v0.95.x and v0.96.x invariants preserved (anti-echo, rating callout, detection callout, lazy-init learned_weights — invocations relocated to orchestrator-instructions; semantics unchanged).

## 5. Rail S design — sidecar via Obsidian MCP

### 5.1 Compose-time data the LLM has

At sidecar emit (orchestrator-instructions Step 8), the cron LLM knows:
- Every kind that emitted a callout (from gather priority loop) → `surfaced_kinds[]`
- Per item: kind, callout_type, title, stable_key → derive deterministic `item_id`
- Composed frontmatter (just authored it)
- Yesterday's memory state → `memory_used`
- Pending_confirmations from kind-classifier → `plan_dispatch.pending_confirmations_count`
- Render aspects applied per engagement-type-override → `render_aspects_applied[]`

Encoding as JSON is serialization, not re-analysis.

### 5.2 Sidecar emit step (Step 8 in each orchestrator-instructions file)

```markdown
### Step 8 — Write `.cowork.json` sidecar

After successfully writing the .md file in Step 7:

1. Construct sidecar payload following {{shared.sidecar_schema_template}}.
2. Write via `mcp__<obsidian>__obsidian_put_content` to
   `spice/cowork/daily/{{$today_dirpath}}/<basename>.cowork.json`.
3. Non-fatal on failure: emit Notice `cowork:<cadence> sidecar write failed for
   <basename>.cowork.json — .md persisted; reconciler will retry tonight`. Do NOT
   delete the .md.
```

### 5.3 Eventually-consistent guarantee

- Primary write (.md): atomic, always succeeds or fails as a unit.
- Secondary write (.cowork.json): best-effort during same fire. Almost always succeeds.
- Reconciler safety net: nightly walk detects `.md` without companion `.cowork.json` → reconstructs from .md prose. Lossier (item-level features cannot be recovered without LLM), but always eventually present.

### 5.4 v0.96.0 helpers — status post-Rail-S

| Helper | Status |
|---|---|
| `write-atomic-note-helper.js` | Retained for HC tests + local Claude Code invocations. NOT called by orchestrator-instructions. Documented as "legacy / harness-only" in JSDoc. |
| `validate-sidecar-helper.js` | KEPT — called by reconciler (Rail R) for nightly post-hoc schema validation. |
| `data/schemas/<cadence>@1.0.0.json` | KEPT — consumed by reconciler validation. |

### 5.5 Re-fire idempotency

Same-day re-fire:
1. Step 4 (rating callout): read prior file → parse `cowork:rating-block` sentinel → preserve `[x]` ticks.
2. Step 7 (write .md): overwrite via `obsidian_put_content` — last-write-wins.
3. Step 8 (write .cowork.json): overwrite. `generated_at` reflects latest fire; `item_id` stable.

No merge logic — just overwrite. Rating-callout tick preservation is the only field needing continuity.

## 6. Rail A design — auto-sync via `update_scheduled_task`

### 6.1 Execution environment

`cowork:sync-scheduled-jobs` becomes claude.ai-Cowork-UI native. SKILL.md frontmatter declares required tools:

```yaml
required_tools:
  - list_scheduled_tasks
  - update_scheduled_task
  - create_scheduled_task
  - obsidian_get_file_contents
  - obsidian_put_content
```

If invoked from Claude Code CLI (no scheduled-task tools), aborts cleanly: *"This skill requires claude.ai Cowork UI. Run `/cowork sync-scheduled-jobs` from your claude.ai Cowork chat to use the scheduled-task MCP."*

### 6.2 Sync skill execution flow

```
Invoked as: /cowork sync-scheduled-jobs [--engagement <id>] [--dry-run]

1. Verify scheduled-task MCP tools loaded; abort with help if not.
2. Read vault context (vault-config + user-preferences + orchestrator-instructions + _shared-clauses + scheduled-job-contract).
3. Compose wrapper bodies per (cadence × engagement) pair via LLM-driven substitution.
4. list_scheduled_tasks → map name → task_id → current prompt.
5. Compute diff: changed (update needed) / new (create needed) / orphan (warn-not-delete) / schedule-preserved invariant.
6. Execute (skip if --dry-run):
   - For each changed: update_scheduled_task({ task_id, prompt: <new> }) — cron field NEVER set.
   - For each new: create_scheduled_task({ name, cron: <default-from-contract>, prompt: <new>, enabled: true }).
   - For each orphan: emit warning line; no destructive action.
7. Update spice/cowork/scheduled-jobs.md audit table (versions, per-(cadence × engagement) row, last_synced_at, status).
8. Report: N updated / N created / N warnings / N schedule-preserved.
```

### 6.3 Schedule preservation invariant

`update_scheduled_task` calls ONLY pass `task_id` + `prompt`. NEVER `cron`, NEVER `enabled`, nothing else. User-tuned schedules (weekly-review Friday 04:00 not 17:30, capture-tick hourly, etc.) preserved across syncs.

For NEW tasks via `create_scheduled_task`: use cadence's `default_cron` from scheduled-job-contract.json as starting point. User tunes after.

### 6.4 LLM-driven substitution

Sync SKILL.md provides Substitution Protocol section:
- Token enumeration (which `{{$tokens}}` and `{{shared.}}` keys exist)
- Resolution rules (each value's source)
- Example substitutions
- Validation: after substitution, no `{{$` or `{{shared.` should remain in composed string

LLM does N×M substitutions per invocation (currently 2 engagements × 5 cadences = 10). Each is reading 2-3 files + applying ~12 replacements. Bounded; sync invoked rarely (post-cycle, post-version-bump).

### 6.5 Error handling

| Failure | Behavior |
|---|---|
| list_scheduled_tasks returns error | Abort cleanly. Report MCP unavailability. |
| One update_scheduled_task error | Log per task; continue with rest. Final report includes failure list. |
| Missing context file for one engagement | Skip that pair; warn; continue. |
| Compose produces invalid output | Skip that pair; warn; continue. |
| Audit file write failure | Non-fatal; report; don't undo API pushes. |

`--dry-run` flag: steps 1-5 only. Print what WOULD happen.

### 6.6 Naming convention + idempotency

Existing live tasks: `cowork-<cadence>-<engagement_id>` (e.g. `cowork-morning-briefing-accuris`). Sync uses same convention for creates. Re-runs are idempotent: byte-comparison diff. If workshop hasn't changed versions, sync produces same composition → no API calls.

## 7. Rail R design — local reconciler

### 7.1 New CLI subcommand

```
sauce reconcile-cowork [--vault <path>] [--all-vaults] [--engagement <id>] [--dry-run] [--install-launchd]
```

Default (no flags): equivalent to `--all-vaults`.

### 7.2 Vault-paths config

```
~/.sauce/vault-paths.json
{
  "schema_version": "1.0.0",
  "vaults": [
    { "path": "/Users/willfellhoelter/notes/sauce/accuris-sauce", "label": "accuris" },
    { "path": "/Users/willfellhoelter/notes/sauce/headspace-sauce", "label": "headspace" }
  ]
}
```

Auto-populated: each `sauce update --bump-pins` from a vault writes itself into this config (idempotent). Hand-edit acceptable.

### 7.3 Per-vault reconciliation flow

```
For each configured vault:
  1. Read vault-config.md → engagements[]
  2. For each engagement:
     a. Determine yesterday's date in engagement.timezone
     b. List atomic notes in spice/cowork/daily/<yesterday-dirpath>/
     c. For each .md without companion .cowork.json:
          → backfill sidecar from .md prose
          → write via fs.writeFile
     d. For each .cowork.json: validate against schemas/<cadence>@1.0.0.json (validate-sidecar-helper)
          → log validation warnings
     e. Parse rating callouts from each .md (parseRatingCallout)
          → aggregate ticks/skips per kind per engagement
     f. Read user-preferences.md frontmatter:
          → _normalizeLearnedWeights (auto-migrates v0.96.0→v0.96.1 shape if needed)
          → updateWeights(per_kind, observations)
          → evaluateWarmup(per_kind, days_since_first)
          → write back preserving all other frontmatter keys (.bak written before)
     g. Run check-heartbeat for this engagement:
          → walkCadenceSidecars(vault_root, engagement_id, days=30)
          → evaluateFreshness against cadence-freshness-windows.json
          → if missed > 0: append warning callout to today's memory.md
  3. Write reconciliation log entry
```

All helpers shipped in v0.96.0 + v0.96.1. Reconciler is the orchestration layer.

### 7.4 Sidecar backfill from .md prose

When `.md` lacks `.cowork.json`:

```javascript
function backfillSidecar(mdPath, mdContent, fileMtime) {
  const { frontmatter, body } = parseMarkdownFrontmatter(mdContent);
  const surfaced_kinds = [];
  const calloutRx = /^> \[!example\]\+\s+(.+)$/gm;
  let m;
  while ((m = calloutRx.exec(body))) {
    const kind = inferKindFromCalloutTitle(m[1].trim(), engagementPriorities);
    if (kind && !surfaced_kinds.includes(kind)) surfaced_kinds.push(kind);
  }
  return {
    schema_version: "1.0.0",
    generated_by: `${frontmatter.generator || "cowork:unknown@?"} (reconciler-backfill@${VERSION})`,
    generated_at: fileMtime.toISOString(),
    cadence: cadenceFromFrontmatterType(frontmatter.type),
    engagement_id: frontmatter.engagement_id,
    frontmatter,
    surfaced_kinds,
    surfaced_items: [],
    render_aspects_applied: [],
    memory_used: { yesterday_present: false, drift_warning_present: false, echoes_count: 0 },
    plan_dispatch: { mode: "reconciler-backfill", kinds_dispatched: surfaced_kinds.length, warnings_emitted: 0 }
  };
}
```

Backfill is best-effort. `surfaced_items[]` empty (features lost). Rail L per-kind learning still works from rating-callout signal independent of items[].

### 7.5 Reconciliation log

Per-vault `spice/cowork/context/reconciler-log.md` — append-only, capped at last 30 entries (older auto-pruned). Each entry: timestamp, run_id, engagements processed, sidecar status (scanned + backfilled + validated), rating callouts parsed, learned_weights deltas per kind, check-heartbeat verdict.

### 7.6 Launchd plist

Template at `Docs/install/cowork-reconciler-launchd.plist.template`. `sauce reconcile-cowork --install-launchd`:

2. Writes to `~/Library/LaunchAgents/com.<user>.cowork-reconciler.plist`
3. `launchctl unload -w` (in case prior version loaded)
4. `launchctl load -w`

Schedule: nightly 03:00 local. RunAtLoad false (don't fire on launchd reload).

## 10. Trade-offs + open questions

### 10.1 Accepted trade-offs

1. Big cycle (~35-45 stages). Five rails interlock at design — phasing wastes effort.
2. LLM-driven substitution in sync skill — tedious but bounded.
3. Sidecar consistency is "eventually-by-tomorrow." Atomic dual-write impossible without Node in cron.
4. Lossy backfill for item-level features. Affects future per-item L2R (not shipped yet).
5. Launchd is macOS-only. Linux/Windows out of scope.
6. Single-machine reconciler. Both vaults processed from this machine.
7. Wrapper template size growth (~30 → ~200-400 lines). Within claude.ai limits.

### 10.2 Rejected

1. CI-time pre-composition of wrappers. Adds build infra.
2. `update_scheduled_task` from Claude Code CLI. Out of scope.
3. Cross-machine reconciler clustering. Sufficient single-machine.
4. Auto-deletion of orphan scheduled tasks. Always warn-not-delete.
5. Wrapper template as JSON-escaped string in scheduled-job-contract.json. Bad editing UX.

### 10.3 Open questions for plan phase

1. Exact compose-helper substitution algorithm + token list (Section 3.5 first-pass).
2. Sidecar backfill heuristic for surfaced_kinds inference (Section 7.4 sketches `inferKindFromCalloutTitle`).
3. vault-paths.json initialization timing (auto-add on `sauce update --bump-pins` from vault?).
4. Reconciler-log retention (30 entries vs calendar-month).
5. v0.96.0 upgrade-notice retirement from `_shared-clauses.md`.
6. `update_scheduled_task` API shape verification against live MCP tool schema.
