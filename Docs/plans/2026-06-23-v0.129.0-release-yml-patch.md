# v0.129.0 — `release.yml` patch (Phase 1, USER-APPLIED)

> **Why this is a doc, not a committed workflow edit:** Claude's OAuth scope rejects any push that touches `.github/workflows/*.yml` (see memory `feedback_no_workflow_yaml_push_via_claude`). So the workflow changes are authored here for **you** to apply + push. Phase 0 (the bumper engine + harness) is already merged via the PR; this turns it on.

## One-time setup before applying

1. **Create `RELEASE_PAT`** — a fine-grained Personal Access Token scoped to `willfell/sauce` with **Contents: Read and write** + **Pull requests: Read and write**. Add it as a repo secret named `RELEASE_PAT`. This is required because a tag pushed by the default `GITHUB_TOKEN` does **not** re-trigger the tag-keyed jobs in `release.yml` (GitHub's loop-prevention) — the PAT is what lets the auto-created tag fire the existing `preflight` + `bump-tap` jobs.
2. `TAP_PR_TOKEN` already exists (used by `bump-tap`) — no change.

## Change 1 — add three jobs to `.github/workflows/release.yml`

The file currently triggers only on tags (`on: push: tags: ['v*.*.*']`). Add a `push: branches: [main]` trigger and the three jobs below. The existing `preflight` + `bump-tap` jobs stay **unchanged** (they still key off the tag).

```yaml
on:
  push:
    tags:
      - 'v*.*.*'
    branches:
      - main        # ADD — enables the prepare/tag/seed jobs below

jobs:
  # ---------- existing preflight + bump-tap jobs stay as-is ----------
  # (they have no `if:` today; add this guard so they only run on tag pushes,
  #  not on the new main-branch pushes:)
  #   preflight:
  #     if: ${{ startsWith(github.ref, 'refs/tags/v') }}
  #   bump-tap:
  #     if: ${{ startsWith(github.ref, 'refs/tags/v') }}

  # ---------- NEW: maintain the standing release PR on every main push ----------
  prepare-release:
    if: ${{ github.ref == 'refs/heads/main' && !startsWith(github.event.head_commit.message, 'chore(release):') && !startsWith(github.event.head_commit.message, 'chore(seed):') }}
    runs-on: ubuntu-latest
    permissions:
      contents: write
      pull-requests: write
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0            # full history + tags for compute-release range
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
      - name: Compute + apply per-component + umbrella bumps
        run: node scripts/release/compute-release.js --write
      - name: Read computed version
        id: ver
        run: echo "version=$(node -e "console.log(require('./package.json').version)")" >> "$GITHUB_OUTPUT"
      - name: Open/update the standing release PR
        uses: peter-evans/create-pull-request@v6
        id: cpr
        with:
          token: ${{ secrets.RELEASE_PAT }}
          branch: release/next        # fixed branch — force-updated each push
          delete-branch: false
          commit-message: "chore(release): v${{ steps.ver.outputs.version }}"
          title: "chore(release): v${{ steps.ver.outputs.version }}"
          body: |
            Automated release PR — merging this tags **v${{ steps.ver.outputs.version }}** and ships to brew.

            `compute-release.js` computed these per-component + umbrella bumps from the conventional
            commits since the last `v*` tag. Review the version diff below, then merge to release.

  # ---------- NEW: on release-PR merge, create the tag (PAT so it re-triggers) ----------
  tag-on-release-merge:
    if: ${{ github.ref == 'refs/heads/main' && startsWith(github.event.head_commit.message, 'chore(release):') }}
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
          token: ${{ secrets.RELEASE_PAT }}
      - name: Create + push annotated tag
        run: |
          VERSION=$(node -e "console.log(require('./package.json').version)")
          if git rev-parse "v$VERSION" >/dev/null 2>&1; then
            echo "tag v$VERSION already exists — skipping"; exit 0
          fi
          git config user.name "sauce-release-bot"
          git config user.email "release-bot@users.noreply.github.com"
          git tag -a "v$VERSION" -m "v$VERSION"
          git push origin "v$VERSION"     # PAT push → fires the tag-keyed preflight + bump-tap jobs

  # ---------- NEW: post-merge seed rebaseline (NEVER on-branch — landmine) ----------
  rebaseline-seed:
    if: ${{ github.ref == 'refs/heads/main' && startsWith(github.event.head_commit.message, 'chore(release):') }}
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          token: ${{ secrets.RELEASE_PAT }}
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
      - run: npm install --omit=dev
      - name: Rebaseline seed (post-merge only)
        run: |
          npm run seed:prev
          npm run seed:rebaseline
      - name: Commit rebaselined seed
        run: |
          VERSION=$(node -e "console.log(require('./package.json').version)")
          git config user.name "sauce-release-bot"
          git config user.email "release-bot@users.noreply.github.com"
          git add platform/test/seed-vault platform/test/seed-vault-prev
          git diff --cached --quiet || git commit -m "chore(seed): rebaseline to v$VERSION"
          git push origin HEAD:main
```

## Change 2 — append a tap auto-merge step to the existing `bump-tap` job

The current `bump-tap` job ends with the `Open PR in tap` step (`peter-evans/create-pull-request`). Give that step `id: cpr_tap` (if not already) and append:

```yaml
      - name: Auto-merge the tap PR
        if: ${{ steps.cpr_tap.outputs.pull-request-number != '' }}
        env:
          GH_TOKEN: ${{ secrets.TAP_PR_TOKEN }}
        run: |
          gh pr merge "${{ steps.cpr_tap.outputs.pull-request-number }}" \
            --repo willfell/homebrew-sauce --squash --delete-branch \
          || gh pr merge "${{ steps.cpr_tap.outputs.pull-request-number }}" \
            --repo willfell/homebrew-sauce --squash --admin --delete-branch
```

(The `--admin` fallback covers the case where the tap later gains required checks; drop it if you prefer to require checks.)

## End-to-end flow once applied

```
push to main (your feature work)
  └─ prepare-release → compute-release --write → force-updates release/next → release PR reflects current bumps
you merge the release PR  (the one gate)
  └─ merge commit "chore(release): vX" lands on main
       ├─ tag-on-release-merge → pushes vX (via RELEASE_PAT)
       │     └─ release.yml tag jobs: preflight → bump-tap → AUTO-MERGE tap PR → brew upgrade serves vX
       └─ rebaseline-seed → seed:prev + seed:rebaseline → chore(seed) commit to main
```

## Caveats / refinements (safe to apply later)

- The `prepare-release` `if:` already skips `chore(release):` and `chore(seed):` head commits so the bot doesn't loop on its own output. If `compute-release` finds no releasable change it writes nothing and `create-pull-request` opens no PR (harmless no-op).
- First run: hand-inspect the first one or two release PRs before merging (Phase 1 of the rollout) — `compute-release.js`'s `--dry-run` (`npm run release:plan`) shows the same computation locally.
- Branch protection: if you enable PR-gated protection on `main`, the `tag-on-release-merge` + `rebaseline-seed` pushes need the `RELEASE_PAT` identity exempted.
