Shipped as designed in `2026-06-02-v0.87.0-semantic-memory-retrieval-design.md` and planned in `2026-06-02-v0.87.0-semantic-memory-retrieval-plan.md`. 4 logical stages → 4 commits (S0 design+plan, S1 sub-skill + helper + MB wire-through + HC, S2 version bumps, S3 cycle-close). ## Summary

**MINOR closing FLN-v84-4 (carry-forward from v0.84.0+): Smart Connections semantic retrieval over the accumulated cowork memory corpus.** v0.85.0 + v0.86.0 wired all 5 atomic-note orchestrators to read recent memory (today / yesterday / this-week / this-month). v0.87.0 adds the orthogonal axis: **semantic similarity over the historical corpus** — surface the closest analogues to today's signal beyond the recency window. This is the compounding-intelligence layer: not just "what's happening today" but "this resembles patterns from <date> when <synthesis excerpt>."

Concretely: a NEW sub-skill `cowork:gather-semantic-memory` wraps the existing `smart-connections-bridge@0.1.1` `semantic-search` op behind a structured-output API; a NEW pure helper `composeSemanticEchoesCallout` renders a `[!quote]+ Echoes from your record` callout byte-identical to a golden fixture; morning-briefing gains a new pre-flight step 3b that composes anchor text from today's dispatch_plan + calendar + email summaries, invokes the sub-skill, and (when matches return) appends the Echoes callout after Overnight in the body. All paths are null-data gated — when sc-bridge is unavailable, the SC index is missing, the anchor is empty, the bridge times out, or no matches clear the `min_similarity: 0.45` threshold, the callout cleanly omits and MB output is byte-identical to v0.86.0. Auto-include in MB is the v0.87.0 default; a user-invokable `/cowork recall <query>` surface is deferred (FLN-v87-2).

## Surface changes

### §1 NEW `cowork:gather-semantic-memory` sub-skill

`platform/blueprints/cowork/skills/skills/gather-semantic-memory/SKILL.md` (FLN-v79-4 nested sub-skill dest). Wraps `sc-bridge semantic-search`. Inputs: `{ engagement_id, anchor_text, top_k, exclude_window, min_similarity }` per design § 1.1. Output: `{ found, matches[], anchor_text_used, exclusion_count, error }` where each match carries `{ path, similarity_score, day_or_week, tier, synthesis_excerpt }`. Tier 2 (synthesis.md) matches prioritized over Tier 1 (memory.md) when present at threshold; Tier 0 (per-tick) excluded from retrieval scope (the synthesized rollups carry the load-bearing signal).

Graceful failure modes — sub-skill never throws:
- `error: "empty_anchor"` — anchor_text empty/whitespace.
- `error: "sc_bridge_unavailable"` — sc-bridge binary not on PATH (mechanism not subscribed).
- `error: "index_unavailable"` — Smart Connections `.smart-env/multi/*.ajson` corpus absent/corrupt.
- `error: "timeout"` — sc-bridge spawn exceeds 10s.
- `found: true, matches: []` — all candidates filtered by `exclude_window` or below `min_similarity`.

### §2 NEW `composeSemanticEchoesCallout` helper

`platform/blueprints/cowork/helpers/compose-semantic-echoes-callout.js`. Pure function `composeSemanticEchoesCallout(gatherOutput) -> string`. Renders:

```markdown
> [!quote]+ Echoes from your record
> Patterns from your past that resemble today's signal:
> - **<day_or_week>** (similarity 0.NN) — _"<excerpt>"_
```

Per-match line: `> - **<day_or_week>** (similarity <score>) — _"<synthesis_excerpt>"_`. Italicized excerpt; 2-decimal similarity. Byte-identical to golden fixture (HC-V0870-B2). Returns empty string when `gatherOutput` is null OR `found: false` OR `matches.length === 0`.

### §3 morning-briefing step 3b + body composition wire-through

`platform/blueprints/cowork/skills/orchestrators/morning-briefing/SKILL.md` gains a NEW pre-flight step 3b after the v0.85.0 step 3a. Composes `anchor_text` from `dispatch_plan_summary` + today's `calendar_summary` + `email_summary` (≤500 chars total); when all three are empty, skips step 3b and sets `output_echoes = null`. Otherwise invokes `cowork:gather-semantic-memory` with `{ engagement_id, anchor_text, top_k: 2, exclude_window: "last-30d", min_similarity: 0.45 }`.

Body composition appends the Echoes callout after the Overnight callout (or after the synopsis if Overnight + Yesterday were both empty), BEFORE the v0.85.0 §0.3 `[!quote]- Memory log` backlink footer. Null-data clean-omit preserves byte-identical output when sc-bridge is unavailable or the corpus is thin.

**Step renumbering side-effect.** Inserting step 3b shifted the existing 3b (read-user-preferences) → 3c and the existing 3c (plan dispatch) → 3d. 3 cross-references inside the MB SKILL.md ("see step 3b" / "step 3c output") were updated in lockstep at S1.

## NEW lessons

1. **Sub-skill structural template is now firmly established.** v0.85.0 `cowork:read-memory` and v0.87.0 `cowork:gather-semantic-memory` follow identical SKILL.md section structure (`## Inputs` / `## Pre-flight` / `## Gather` / `## Decide` / `## Done` / `## Harness testing`), identical structured-output declaration posture (the output shape is declared inline in the SKILL.md prose so HC prose-lints can assert substrings), and identical graceful-failure-clause patterns (declared error tokens + null-data echo on failure modes; never-throws). **Lesson:** any future cowork sub-skill cycle should mirror this template — section ordering + output-shape declaration + graceful-failure clause. Two cycles is a pattern; a third would canonize it into `Docs/agent-guides/code-conventions.md` as the standard sub-skill SKILL.md shape.

2. **Step-numbering side-effects of inserting in MB's pre-flight.** Inserting a new step 3b shifted existing 3b/3c → 3c/3d; 3 cross-references inside the same SKILL.md needed updating. The HC suite caught the structural changes (new step 3b invocation reference) but did NOT catch the stale cross-references — those required a manual grep at S1 dogfood time. **Lesson:** future cycles inserting pre-flight steps into an orchestrator SKILL.md should grep for `step <N>` and `Step <N>` cross-references across the same file as part of the edit, before committing. Could codify as a plan-template line item; not yet a NEW FLN.

3. **Helper output rendering — collapsed vs expanded callouts have semantic meaning.** v0.87.0 chose `[!quote]+` (expanded by default) for the Echoes callout because semantic-retrieval results benefit from immediate visibility — the user wants to see the historical analogues without an extra click. v0.85.0 chose `[!quote]-` (collapsed by default) for the Memory log backlink because the backlink is navigational, not informational — clicking the chevron reveals the wikilink only when the user wants to pivot. **Lesson:** the `+` vs `-` suffix on Obsidian callouts is a UX decision, not a stylistic one. Information that's immediately useful goes in `+`; information that's an affordance for a possible future action goes in `-`.

4. **sc-bridge wrapping pattern — the sub-skill is the abstraction layer.** `cowork:gather-semantic-memory` is the abstraction layer between consumer orchestrators and the raw `sc-bridge` CLI. Orchestrators never invoke `sc-bridge` directly; they invoke the sub-skill, which wraps argument composition, JSON parsing, error mapping, and structured-output normalization. **Lesson:** future cycles wrapping other `sc-bridge` ops (e.g., `find-related`, `index-status`, hypothetical `embed-text`) should follow the same SKILL.md template — one sub-skill per op, structured-output API, graceful failure modes mapped to typed `error:` tokens, never-throws posture. The sub-skill is the contract surface; the bridge CLI is implementation detail.
