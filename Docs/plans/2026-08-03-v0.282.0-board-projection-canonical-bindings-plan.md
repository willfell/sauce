## TDD order (red → green watched at each step)

1. **Intake bindings.** New `canonicalVaultCase` fixture builds a real
   `<vault>/spice/projects/<slug>/` shape and mints with the skill's exact
   arguments (absolute `board_path`, no `source_board`). Asserts all six binding
   fields are vault-relative **and** that the freshly minted slice projects
   through the real `canonicalEpicProjection`.
   - RED: 6 failures — absolute `source_board`, project-relative `epic_board`,
     project-relative slice `source_board`/`task_parent`, and
     `PROJECTION THREW: epic atlas … does not bind its canonical parent board`.
   - GREEN: `run-card-intake` 256 passed / 0 failed (was 250/6).

2. **Discard orphan prevention.** Fixture reproduces the live Mode-1 shape (an
   absolute atlas `source_board`) so the epic surface genuinely refuses, then
   discards a parked slice. Asserts the receipt names the **epic sub-board** as
   its target, the line is gone, the sibling line survives, the note is deleted,
   and the parent board is byte-identical.
   - RED: `BPX-ORPHAN discard targets the slice's OWN epic sub-board, not the
     parent board`.
   - GREEN: 2598 assertions.

3. **`heal-epic-bindings`.** Fixture carries one broken epic (absolute atlas
   bindings, project-relative slice `task_parent`, one orphan line) and one
   already-canonical control epic. Asserts: the broken epic does not project
   beforehand; `--dry-run` reports the exact rewrites and writes nothing;
   `--apply` makes it project through the real contract, prunes only the orphan,
   preserves the slice body byte-for-byte, leaves the control epic
   byte-identical; replay is `no_op: true` and byte-stable.
   - RED: `commandHealEpicBindings is not a function`.
   - GREEN: 2618 assertions.
