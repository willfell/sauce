#### 2.1.1 §0.1 FLN-v83-2 `--bump-pins` blueprint-pin handling

**Surface.** `platform/cli/cmd-update.js#handleBumpPins` (line 59).

**Reproducer (from v0.83.0 + v0.84.0 deploy):** Consumer vault on `cowork@0.21.1` runs `sauce update --bump-pins` after `brew upgrade sauce` to v0.83.0 (which carries `cowork@0.22.0`). `--bump-pins` reads the brew-installed workshop's `platform/manifest.json`, sees `cowork: 0.22.0`, but fails to update `ranch/platform-subscription.json#blueprints[].cowork.version` from `0.21.1` to `0.22.0`. Next `sauce update` proceeds with the stale pin — cowork's `files[]` engagement-type JSONs never materialize on the consumer.

**Root cause hypothesis (verify at S1):** `handleBumpPins` likely walks the top-level pins but skips blueprints when the prior pin is N-2+ behind. The fix is to walk every blueprint declared in the workshop manifest and bump-pin unconditionally (with `--keep-comparators` opt to preserve existing comparator prefixes when the user wrote `^0.x.y` or `~0.x.y`).

**Fix shape:**
1. Read workshop `platform/manifest.json` → `workshop.blueprints[]` (target versions).
2. Read consumer `ranch/platform-subscription.json` → `subscription.blueprints[]` (current pins).
3. For each blueprint in workshop:
   - If subscription has no entry, append `{ name, version: <workshop version> }`.
   - If subscription has entry, replace `version` with workshop's value (preserving any leading `^` / `~` / `>=` comparator if `--keep-comparators` is set).
4. Same for mechanisms (already working per cycle history; verify no regression).
5. Same for top-level `workshop_version`.

**HC strategy.** §0.1 ships a failing test (HC-V0850-G1) that constructs a synthetic consumer subscription with `cowork: 0.21.1` and a workshop manifest with `cowork: 0.22.0`, runs `handleBumpPins` against the synthetic vault, asserts the consumer subscription's cowork pin is now `0.22.0`. Test lives in `platform/test/run-cli.js`.

#### 2.2.1 §1 NEW `cowork:read-memory` sub-skill

**Location.** `platform/blueprints/cowork/skills/skills/read-memory/SKILL.md` (nested under `skills/skills/` per v0.79.0 FLN-v79-4 sub-skill-vs-orchestrator dest convention).

**Frontmatter:**
```yaml
---
name: cowork:read-memory
description: Pure-read sub-skill that parses memory.md files at the canonical cowork memory path and returns structured data for downstream consumers. Single API surface every memory-aware orchestrator calls instead of re-implementing the file-glob + parse logic. Inputs declare engagement_id + tier + window; output is a structured object (synthesis + carry_forward + ticks + frontmatter). Failure mode is graceful null-data return (matches morning-briefing's v0.84.0 backward-compat gating).
scope: shared
tags: [cowork, sub-skill, memory, read]
---
```

**Inputs:**
```json
{
  "engagement_id": "<string, required>",
  "tier": "tick | day | week",
  "window": "yesterday | today | this-week | last-7d | { start: <ISO>, end: <ISO> }",
  "limit_ticks": <number, optional, default 6>
}
```

**Output (structured):**
```json
{
  "found": <boolean>,
  "tier": "<echoed from input>",
  "window_resolved": { "start": "<ISO>", "end": "<ISO>" },
  "files_read": ["<absolute or vault-relative path>", ...],
  "day_synthesis": {
    "engagement_id": "<string>",
    "day": "<YYYY-MM-DD>",
    "summary": "<≤200 chars>",
    "synthesis_paragraph": "<2-3 paragraphs voice-applied prose or null if not yet synthesized>",
    "carry_forward_bullets": ["<bullet>", ...],
    "tick_count": <number>,
    "synthesized": <boolean>,
    "synthesis_at": "<ISO or null>",
    "last_tick_at": "<ISO or null>"
  } | null,
  "week_synthesis": {
    "engagement_id": "<string>",
    "iso_week": "<YYYY-Www>",
    "summary": "<≤300 chars>",
    "weekly_pattern": "<3-5 paragraphs voice-applied prose or null>",
    "carry_forward_bullets": ["<bullet>", ...],
    "days_covered": <number>,
    "synthesis_at": "<ISO or null>"
  } | null,
  "ticks": [
    {
      "time": "HH:MM",
      "kindlist": ["chat", "calendar", ...],
      "summary_line": "<one-liner derived from tick body's bold-prefix lines>",
      "raw_callout_md": "<full callout source including header>"
    },
    ...
  ]
}
```

**Resolution rules:**

| `tier` | `window` | What gets read |
| --- | --- | --- |
| `day` | `yesterday` | yesterday's `memory.md` → populate `day_synthesis` only |
| `day` | `today` | today's `memory.md` → populate `day_synthesis` only |
| `tick` | `today` | today's `memory.md` → populate `ticks` array (most recent `limit_ticks` in chronological-reverse) + `day_synthesis` if present |
| `tick` | `yesterday` | yesterday's `memory.md` → populate `ticks` array similarly |
| `week` | `this-week` | THIS-WEEK's `<engagement>/<YYYY>/<MM-MMMM>/<YYYY-Www>/synthesis.md` → populate `week_synthesis` only |
| `week` | `last-7d` | Walks days yesterday → -6d; populates `ticks` aggregated across days; sets `day_synthesis` to the most recent synthesized day's data |
| any | explicit `{start, end}` | Walks day-by-day in the range; aggregates accordingly per `tier` |

**Failure modes (graceful — never throws):**
- File-not-found → return `{ found: false, tier, window_resolved, files_read: [], day_synthesis: null, week_synthesis: null, ticks: [] }`.
- Frontmatter parse error → return same shape; emit a Notice (debug-level) with the offending path.
- Filesystem read error → return same shape; emit a Notice.

**Pre-write self-check:** N/A — sub-skill is read-only.

**Implementation form.** SKILL.md ships with deterministic step-by-step prose for the agent to execute. The pure parsing logic CAN be extracted into a helper at `platform/blueprints/cowork/helpers/read-memory-helper.js` exporting `parseMemoryFile(rawMarkdown) -> ParsedMemory`. The helper is unit-testable directly (sub-asserts call it with raw markdown fixtures). The SKILL.md body invokes the helper at write-time and composes the structured output. This mirrors v0.79.0's `composeMicroscope` extraction (SKILL.md prose + pure helper for testable composition).

**Why structured-output over raw-markdown:**

| Constraint | Structured wins | Raw-md wins |
| --- | --- | --- |
| v0.85.0 MB byte-identical guarantee | needs `composeMemoryCallouts(structured) -> md` to reconstruct | trivially direct (same shape MB used in v0.84.0) |
| v0.86 wire-through to 4 orchestrators | each composes differently; structured lets each pick fields | each duplicates parse logic |
| v0.87 semantic retrieval | needs `tick_count`, `summary_line` for embedding context vector | must re-parse markdown per embedding op |
| v0.88 distill-week | scans `carry_forward_bullets` for recurring entities; structured trivially | regex over markdown is brittle |
| Test surface | unit-testable helper produces 1 shape | callers each test their own parse logic |

Structured wins on 4 of 5; raw-md wins only on the MB-refactor byte-identical cost which we pay once via the new `composeMemoryCallouts` helper.

description: End-of-week synthesis (Tier 2). - Compose `voice_contract` from `prefs.personality` + `effective_hard_rules`.
- Cap: `weekly_pattern` paragraph ≤300 words (~3 paragraphs); `carry_forward_bullets` ≤5.

**Write:**
1. Compose `week_synthesis_path` = `spice/cowork/memory/<engagement_id>/<YYYY>/<MM-MMMM>/<iso_week>/synthesis.md`.
2. Read-or-create the file. On create: scaffold full skeleton (frontmatter `type: cowork-weekly-synthesis`, `engagement_id`, `iso_week`, `week_start`, `week_end`, `days_covered`, `created_at`, `synthesis_at`, `summary`); H1 title `# Weekly memory — <ISO-week range>`; `[!info]+ Weekly pattern` callout with weekly_pattern body; `[!tip] Carry-forward to next week` callout with ≤5 bullets; `## Days included` H2 with a bulleted list of `[[<path-to-each-day-memory>|<YYYY-MM-DD> (N ticks)]]`.
3. Pre-write self-check: assert frontmatter has type/engagement_id/iso_week/synthesis_at/summary; body has H1 + Weekly pattern callout + Carry-forward callout + `## Days included` section. On miss → `failed:contract-violation:<field>` + exit non-zero.
4. Write file.

**Verify:** Re-read, assert frontmatter shape, assert callout titles present.

**Done:** Empty (per orchestrator convention).

**Logic (mirrors v0.84.0 MB body-composition prose verbatim):**

```javascript
function composeMemoryCallouts(outputYesterday, outputOvernight) {
    const yesterdayCalloutMd = composeYesterdayCallout(outputYesterday);
    const overnightCalloutMd = composeOvernightCallout(outputOvernight);
    return { yesterdayCalloutMd, overnightCalloutMd };
}

function composeYesterdayCallout(out) {
    if (!out || !out.found || !out.day_synthesis || !out.day_synthesis.synthesized) {
        return "";
    }
    const carryFwd = out.day_synthesis.carry_forward_bullets || [];
    const synthesis = out.day_synthesis.synthesis_paragraph || "";
    const compressed = compressSynthesisToLines(synthesis, 3); // v0.84.0 rule: ≤3 sentences
    const carryLines = carryFwd.length > 0
        ? carryFwd.map(b => `> - ${b}`).join("\n")
        : "> _(no carry-forward bullets)_";
    return [
        `> [!example]+ Yesterday at a glance`,
        carryLines,
        `> `,
        `> ${compressed}`,
        ``  // trailing newline
    ].join("\n");
}

function composeOvernightCallout(out) {
    if (!out || !out.found || !out.ticks || out.ticks.length === 0) {
        return "";
    }
    const tickLines = out.ticks
        .slice()
        .reverse()  // ticks come most-recent-first; v0.84.0 rendered oldest-first
        .map(t => `> - ${t.time} — ${t.summary_line}`)
        .join("\n");
    return [
        `> [!example]+ Overnight`,
        tickLines,
        ``  // trailing newline
    ].join("\n");
}

function compressSynthesisToLines(text, maxSentences) { /* ... */ }

module.exports = { composeMemoryCallouts, composeYesterdayCallout, composeOvernightCallout };
```

**Why a helper + not inline prose:** testability (golden-fixture). The helper is a pure function — passes fixture inputs through, asserts character-equal output. Inline prose can't be unit-tested.

**Why this pattern is non-invasive to v0.86+:** v0.86's wire-through to midday/eod/weekly/monthly will add similar compose helpers (e.g., `composeMidamMemoryCallout` for midday-tripwire's pre-flight injection). Each compose function targets one orchestrator's body. No premature abstraction.

## 6. Risks + mitigations

### 6.1 Polish prelude scope creep

Folding 4 carry-forwards into a 12-stage cycle increases the surface for plan-replacement-text drift mid-cycle (the v0.83.0 S3/S4 churn pattern).

**Mitigation:** stages S1–S4 are explicit polish bookends; each commits its own small surface change + its own HC sub-asserts. S5 RED tests draw a clear line between polish and core. Subagent-driven-development (per v0.84.0's autonomous-overnight pattern) keeps stage-to-stage handoffs disciplined.

### 6.2 Byte-identical guarantee on MB body refactor

If `composeMemoryCallouts` diverges from v0.84.0's hand-composed prose by even a single character (trailing whitespace, double newline, wikilink-pipe spacing), existing deployed vaults render different bodies.

**Mitigation:** golden-fixture test HC-V0850-C3..C5. Fixture files captured from v0.84.0's actual output at S0 (run MB once against a known memory.md state with v0.84.0's prose; capture stdout; commit fixture). S8 refactor is judged success only when fixture diff is empty. Fixture lives in `platform/test/fixtures/v0.85.0-mb-expected-*-callout.md`. NO downstream consumer is asked to migrate; their MB output continues unchanged.

### 6.3 read-memory API surface stability

The structured-output shape is load-bearing for v0.86+v0.87+v0.88. Changing it later breaks downstream consumers; v0.86 wire-through would need parallel updates to all 4 newly-wired orchestrators.

**Mitigation:** v0.85.0 design locks the shape (Section 2.2.1). Fields can grow ADDITIVELY in future cycles without breaking consumers — adding `week_synthesis` data alongside existing `day_synthesis` is fine; removing or renaming requires a coordinated MINOR bump. Future cycles MUST treat the structured output as a public API.

### 6.4 Engagement-type pin drift surfaces (FLN-v841-1)

S5 RED tests bump HC-V0740-1's exact-version pin 0.4.0 → 0.5.0. The v0.84.1 result documented 3 such test-pin sites: SHC-S1, FA6-MANIFEST, AF-1d, AF-V065. v0.85.0 surfaces a new one (HC-V0740-1's engagement-type schema). If any other exact-pin asserts the engagement-type version, S5 plan must grep them.

**Mitigation:** S5 plan adds a grep step `grep -nE '"0.4.0"|0\\.4\\.0' platform/test/ | grep engagement-type` to surface all engagement-type exact-pin sites BEFORE writing the new HC-V0850-D1. Update each in lockstep at S5; track in commit message.

### 6.5 `cowork:read-memory` performance under v0.87 semantic retrieval

At v0.85.0, read-memory reads at most 7 files (the past week). At v0.87.0, semantic retrieval over memory may invoke read-memory dozens of times per session for similarity scoring.

**Mitigation:** v0.85.0 does NOT add caching. Memory files are small (~200 lines, ~15KB max). 7 reads per invocation = ~100KB; well within filesystem cache bounds. v0.87.0 can add in-session caching (one-deep memoization keyed by `{engagement_id, tier, window}`) if profiling shows it matters. Premature optimization avoided.

### 6.6 ISO-week boundary edge cases

`synthesize-week` fires Friday at 17:00; an ISO week starts Monday and ends Sunday. Friday is mid-week (day 5 of 7), so synthesize-week captures Mon–Fri only.

**Mitigation:** This is **intentional**. The roll-up reflects the **work-week pattern** (Mon–Fri), not the full ISO week. Weekends are typically lower-tick days; including Sat/Sun would muddle the pattern. The synthesis-at timestamp captures the moment of synthesis; rendering can convey "Weekly memory — Mon June 1 to Fri June 5, 2026."

If the user wants Sat/Sun included, cron is configurable per engagement (e.g., `0 17 * * 0` for Sunday evening). Design ships the Friday default; per-engagement override is supported by onboard-scheduled-jobs.

### 6.7 Tier 3 (monthly synthesis) deferred — does v0.85.0 design choices preclude it?

The deep-path canonical layout `<engagement>/<YYYY>/<MM-MMMM>/<YYYY-Www>/synthesis.md` extends naturally to Tier 3 `<engagement>/<YYYY>/<MM-MMMM>/synthesis.md` (one level shallower, no week dir). New canonical type `cowork-monthly-synthesis` with similar rule_fragment. `cowork:read-memory` API extends with `tier: "month"` + `window: "this-month" | "last-30d"`. No v0.85.0 design choice precludes Tier 3.

**Mitigation:** Tier 3 ships in a future cycle. v0.85.0 design notes (this section) record the path shape for future consistency.

### 6.8 Memory file size growth (FLN-v84-3)

Tier 2 adds 1 file per (engagement, week) = ~52 files/year. Each ~3 paragraphs ≤300 words = ~5KB. Year-long accumulation per engagement = ~260KB. Across 4 vaults × 1 engagement each ≈ ~1MB Tier 2 + ~1.5MB Tier 1 = ~2.5MB total memory layer per year. Tractable.

**Mitigation:** Tier 2 itself **is** a form of compression — 7 daily syntheses → 1 weekly. Tier 3 will compress further. The retention/compression policy candidate (FLN-v84-3) remains open for a future design-only cycle.
