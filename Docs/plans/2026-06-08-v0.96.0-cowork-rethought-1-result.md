## Lessons learned

1. **Verify materialize_once behavior before designing migrations.** Design §7.2 assumed the installer would additively-merge new frontmatter sections into existing materialize_once files. S0.5 verification revealed installer SKIPS such files entirely (`platform/install.js:941-957`). Pivoted to lazy-init in learn-from-checks. Cost: ~30 minutes mid-cycle. Mitigation: S0.5 pre-flight verification — this is now formalized in the plan template.
2. **Test contract beats spec contract when they conflict.** Two cases where the test asserted a different shape than the spec described: `pending_confirmations` as string[] vs object[] (S2.3); `parseRatingCallout` returns `observations` field not `ticks` (S3.2). In both cases, subagents matched the test (the more concrete authoritative artifact). Documented inline.
3. **Banker's rounding matters at design-spec'd worked examples.** HC-L-3 hand-math expected `0.8205 → 0.820` (half-to-even). JS native `Math.round` rounds half-up. Helper has `_round()` with explicit half-to-even guard. The design's worked-example expectation drove the implementation, not vice-versa.
4. **base_priority semantics are testable.** S3.5 plan suggested `base_priority = i * 10` but HC-L-14 required projects (i=2, w=1.45) to leapfrog calendar (w=1.00, i=0). With base*10, the formula could never produce the leapfrog. The agent adjusted to `base_priority = i` to make the math work. Lesson: when arithmetic constants in the design might not satisfy the test, pick the constants that make the test pass and document inline.
5. **Engagement-types live in two places.** S2.4 caught that `engagement-types/{personal,w2-fte,consulting}.json` exists in BOTH `platform/blueprints/cowork/engagement-types/` AND `spice/cowork/context/engagement-types/`. Both must update or HC-V0830-A2 (JSON.stringify drift) fails. Followed v0.95.1 S1.4 precedent.
