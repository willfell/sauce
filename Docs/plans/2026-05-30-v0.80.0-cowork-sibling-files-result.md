## What shipped

### Sub-deliverable A — Sibling-file convention

- **`spice/cowork/prompts/per-mcp/<kind>/<name>.md`** (any markdown file in the per-kind dir EXCEPT `microscope.md` and any file matching `^_.*\.md$`) is now a USER-owned context surface alongside `microscope.md`. Same posture as `microscope.md` from v0.79.0: NOT in cowork's `files[]` (preservation by construction), never overwritten by `sauce update`/`reinstall`.
- **Underscore-prefix escape** (`_<name>.md`) is reserved for drafts/archives the user wants to keep in-dir but NOT inject. Orchestrators' step 2c filter excludes them.
- **No filename schema.** `contacts-map.md`, `vip-list.md`, `account-aliases.md`, `project-codes.md`, etc. — convention recommends `kebab-case-purpose.md` but the consumed surface is opaque markdown.

### Sub-deliverable B — Discovery + injection

- **Orchestrator step 2c** added to all 5 atomic-note orchestrators (morning-briefing / midday-tripwire / eod-review / weekly-review / monthly-review) immediately after the v0.79.0 step 2b (microscope read). For each `kind_name` in `prefs.priorities`: list `spice/cowork/prompts/per-mcp/<kind_name>/` via `mcp__obsidian__list_files_in_dir` (dir-not-found → empty), filter to files matching the `per-mcp/<kind_name>/*.md` glob, exclude `microscope.md` and `^_.*\.md$`, read each remaining file via `mcp__obsidian__get_file_contents`, strip leading frontmatter, append `{ name, body }` to `siblings[kind_name]`. Pure step: no MCP gather calls, no writes.
- **Gather-loop wiring** (5 orchestrators): each kind's `gather_from_served_by` input gains `siblings: siblings[entry.kind_name] || []` directly after the v0.79.0 `hard_rules: prefs.effective_hard_rules` line.
- **`cowork:gather-from-served-by` contract change.** Inputs frontmatter declares new `siblings: list[{name,body}]`. New `## User-supplied reference` section in `SKILL.md` body, slotting AFTER `## Hard rules` and BEFORE `## Dry-run mode`, instructs the agent to inject each sibling verbatim into the dispatch contract Step 3 under `**User-supplied reference: <name>**` blocks (after `<what_matters verbatim>` and the optional `**Captured answers**`, before `**Hard rules ...**`). Helper destructures `siblings` from input and echoes the injected filenames back as `siblings_used: list[string]` (mirrors `hard_rules_applied`).

### Sub-deliverable C — Authoring (`cowork:edit-microscope` step 4 user-supplied)

- **New helper export `composeSibling({ kind_name, gap, suggested_name })`** → `{ name, body, status }`. Pure, deterministic, harness-testable. Renders a starter sibling template with a heading + USER-OWNED preamble derived from the gap text + an empty markdown table whose columns are inferred from the gap text via `COLUMN_HEURISTICS` (in order: `/vip|priority/` → `(id, reason)`; `/phone|number/` → `(phone, name)`; `/email/` → `(email, name)`; `/account|\bid\b|alias/` → `(id, nickname)`; else `(key, value)`). Order matters — `vip|priority` first so a phrase like "vip priority phone numbers" classifies as `(id, reason)`.
- **`composeMicroscope` extension.** Accepts new optional `siblings_to_reference: [{ name, role }]` arg. When non-empty, appends `## References` to the seed-from-notes body and `## References (added)` to the deepen-pass branch — each rendered as `- **<name>** — <role>` (`(role unspecified)` fallback when role is omitted). When empty/absent, the section is omitted entirely. The v0.79.0 `<!-- v0.79.0 deepen pass -->` marker comment is preserved verbatim (audit-signal stability).
- **`edit-microscope/SKILL.md` step 4 user-supplied bullet** expanded into a 6-substep sub-flow: (1) compute suggested filename from gap text via the same column heuristic (phone → `contacts-map.md`; email → `senders-map.md`; account/id → `account-aliases.md`; vip → `vip-list.md`; else `<gap-slug>.md`); (2) preview the starter via `composeSibling`; (3) on YES, pre-check existence with `mcp__obsidian__get_file_contents` and either scaffold via `Write` (absent) or skip-but-still-record (present); (4) on NO, skip; (5) refuse `^_.*\.md$` and `microscope.md`; (6) pass `siblings_to_reference` into `composeMicroscope` at step 6.

### Boundary contract

- `Docs/agent-guides/cowork-customization-contract.md` per-mcp/** row's notes column gained one sentence documenting that siblings alongside `microscope.md` share the same USER-owned, not-in-`files[]`, never-overwritten posture; orchestrators discover them via step 2c (glob `*.md` excluding `microscope.md` and `_*.md`) and `gather-from-served-by` injects each verbatim under `**User-supplied reference: <name>**` blocks. No new table row — the existing per-mcp/** glob already covers the directory.

## Sequencing observations + corrections (for next-cycle learning)

- **A1 glob-regex prose mismatch (resolved inline at S7).** The plan's HC-V0800-A1 regex required the literal substring `per-mcp/<kind_name>/*.md` (or `per-mcp/<kind>/*.md`) in the orchestrator's step 2c prose. The plan's verbatim 2c prose said "list … `spice/cowork/prompts/per-mcp/<kind_name>/`" + separately "files matching `*.md`" — the regex didn't match because the literal glob string was split across two phrases. Fixed by adjusting the prose to "Filter the result to files matching the `per-mcp/<kind_name>/*.md` glob" — semantically identical, satisfies the contract. Applied identically across all 5 orchestrators in S7 + S8. Carry-forward FLN candidate: either soften the regex (allow split phrasing) or codify the literal-glob requirement in the plan template.
- **Landmine #16 short-circuit behaved as planned.** Pre-S11, `.claude/skills/cowork/*` dests caught up SKILL.md source edits per-install (in practice the global `materializeClaudeSurface` step ran regardless and propagated changes — the per-item version short-circuit did NOT prevent dest catch-up for SKILL.md surfaces in this cycle, contradicting the plan's stated worst-case expectation). S11's `.obsidian/` paths stayed clean (no styling changes this cycle). The full subscription bump in S11 still resolved the registry checksum drift and updated installed.json — a meaningful state change even though dests had been kept fresh per-stage.
- **`agent_markdown` fixture floor compliance.** All v0.80.0 HC cases that build `dry_run_answers.agent_markdown` (B1/B2/E1) used the canonical 4-line `> [!example]+ Chat\n> - Alice: …\n> - Bob: …\n> - Carol: …` skeleton well above the 80-char floor; v0.79.0's FLN-v79-3 trap avoided cleanly.
- **Dispatch-contract injection order.** `**User-supplied reference: <name>**` blocks slot between `<what_matters verbatim>` (+ optional captured answers) and `**Hard rules ...**`. SKILL.md prose B3 lint enforces the order; helper-side echo (siblings_used) does NOT depend on prose order, so the contract is documented-only (prompt-level trust, same posture as hard_rules).
- **No new harness files; file count stable at 23.** Per design §7 prediction.

## §11 carry-forward (deferred to a follow-up cycle, per design)

Design §11 items explicitly OUT of scope and unchanged here:

1. Interactive editing of EXISTING sibling content (add/remove rows via the skill; v0.80.0 scaffolds new siblings only, not edits to existing ones).
2. Dedicated `/cowork sibling <kind> <name>` slash command (separate from edit-microscope).
3. Typed sibling parsers + deterministic pre-agent substitution (vs. v0.80.0's opaque-injection model).
4. Hard-rule-style post-processor for sibling-application compliance (mechanical verification that every phone number in a chat callout maps to a `contacts-map.md` entry).
5. Sibling-file versioning / changelog (the `_*.md` escape is the closest thing to an archive convention today).
6. Multiple-microscope-per-kind (`microscope-morning.md` / `microscope-eod.md` for cadence-specific contracts).
7. Soft-limit warning for very large sibling files (>50KB injected whole today).
8. Sibling-file-aware reverse audit (verify `## References` entries point to extant files; warn on dangling).

## Cycle-specific FLNs surfaced during v0.80.0 execution

- **FLN-v80-1: HC-V0800-A1 glob-prose regex over-strict.** As described above — the plan's regex required the literal `per-mcp/<kind_name>/*.md` glob string but the plan's 2c prose split it. Resolved by amending the prose. Either soften the regex or codify the requirement in the plan template.
- **FLN-v80-2: landmine #16 less load-bearing than v0.79.0 close documented.** The cowork SKILL.md dest catch-up appears to happen per-install regardless of the per-item version short-circuit (at least for surfaces processed by `materializeClaudeSurface`). The plan's "deferred to S11" prediction was overly conservative for v0.80.0. Future plans can be less alarmist about mid-cycle .claude/ drift for SKILL.md edits.
- **FLN-v80-3: result doc structure stability.** The v0.79.0 + v0.80.0 result docs follow the same structure (what shipped → HC cases → version moves → stages → observations → carry-forward → FLNs). Worth codifying in a result-doc template skill if cycle-close documentation continues at this volume.
