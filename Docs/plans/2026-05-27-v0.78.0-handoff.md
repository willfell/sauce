## What shipped (one-paragraph summary)

v0.78.0 closes the consumption gap that v0.76.0 + v0.77.0 left open: the
5 cowork atomic-note orchestrators (morning-briefing, midday-tripwire,
eod-review, weekly-review, monthly-review) now READ
`spice/cowork/context/user-preferences.md` at fire-time and shape their
output accordingly — priority-ordered `[!example]+` blocks per
`prefs.priorities[]`, voice-contract prefix from `prefs.personality`
applied to narrative sections (synopsis, tip), in-position `[!warning]`
callouts for kinds that are unclassified / disconnected / unreachable.
Two new vendor-agnostic sub-skills do the heavy lifting:
`cowork:read-user-preferences` (pure parse + status code) and
`cowork:gather-from-served-by` (one gather path for BOTH
`override_classified` known kinds AND user-defined `custom_kind` kinds,
dispatched inline against the v0.77.0 `served_by` namespace). Legacy
fallback is bit-for-bit preserved when prefs are empty / missing /
malformed: every orchestrator falls through to the v0.77.0 hardcoded
gather sequence unchanged. 14 new HC-V0780-* harness cases (A1..A4,
B1..B3, C1..C4, D1..D2, E1) all in `run-cowork-smoke.js`. Cowork 0.16.0
→ 0.17.0. Workshop 0.77.0 → 0.78.0. Forcing function: the accuris
vault's 2026-05-27 morning-briefing.md ignored captured priorities,
personality, and the three classified custom kinds (ADO, Backstage,
NewRelic) entirely.

1. Call `cowork:read-user-preferences` and receive `{ prefs, status }`.
2. If `status === "ok"` and the vault has captured prefs (post-v0.76.0/v0.77.0 context-builder runs), reorder Example blocks per `prefs.priorities[]`, compose the voice-contract prefix from `prefs.personality`, and dispatch `override_classified` + `custom_kind` MCPs through `cowork:gather-from-served-by`.
3. If `status === "empty"` (no prefs captured) or `"malformed"`, fall through to the v0.77.0 hardcoded gather sequence — visible only as a new `Preferences: not captured (fallback to defaults).` Notice line at top of body.
