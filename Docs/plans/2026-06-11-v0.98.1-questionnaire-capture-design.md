# v0.98.1 — questionnaire expansion + free-text capture

## TL;DR

Replaces the EOD-only Rail L kind-checkbox rating-block with a richer capture surface: stable per-item `^item-<id>` block-IDs emitted by compose-body, per-item ticks pointing at those block-IDs, per-kind 3-position frequency knob (`less / same / more`), and a tagged fenced `` ```feedback…``` `` free-text block under a new `<!-- cowork:feedback-capture v=1 -->` sentinel. Capture-only this cycle; **no** `learned_weights` writes, **no** voice updates, **no** parse-back loop. v0.98.2 closes the loop via a `cowork:ingest-feedback` sub-skill that reads the captured corpus, produces structured deltas, and applies them with an audit trail.

EOD is the only cadence touched. Morning-briefing / midday-tripwire / weekly-review / monthly-review **keep** today's `{{shared.rating_callout_template}}` invocation unchanged. The existing `parseRatingCallout` helper stays for the other 4 cadences; a new `parseFeedbackCapture` is added alongside.

Architectural posture: deterministic-helpers-for-shape, OI-prose-for-voice. Item-IDs are computed in `compose-body-helper.js` (hash-stable across re-fires); the Rail L body is built in a **new** `compose-feedback-capture-helper.js`; the sentinel parse lives in `learn-from-checks-helper.js`. The eod-review OI Step 4 swaps one template invocation for one helper call. No LLM-driven structural computation (lesson v0.98.0 §2 — LLM-rendered shape contracts drift; deterministic helpers don't).

The first cycle that EXPLICITLY guards user-authored cowork content during update — pre-deploy snapshot recipe, post-install diff verification, and a § Out-of-scope `files[]` guard go into the design — anticipating v0.98.2's ingest writes that will land closer to the user-content edge.

## Goal

Per the user direction captured during the 2026-06-10 brainstorm (after the v0.98.0 close):

> "just saying thumbs up isn't enough. what if we added a section for didn't like? what if there was a section where i could provide feedback, and another job took what i liked, what i didn't like, my feedback, then updated the relevant files so that all scheduled jobs would then adjust the next day?"

The vision spans two cycles: **v0.98.1 captures** the signal in a parseable shape; **v0.98.2 ingests** the signal and applies deltas to `learned_weights` / microscopes / `what_matters` with an audit trail. This design covers v0.98.1 only.

Per `Docs/cowork-vision.md`, this cycle advances **Adaptive memory loop (write-side compounding)** — the capture surface is the prerequisite for the write-side. It also advances **Substance/Voice** by replacing a coarse kind-boolean signal with per-item + per-kind + prose signal.

Sub-decisions folded into Q4-A:
- Item-ID hash format: `^item-<kind>-<7-char-sha1>` of `<kind>:<canonical_identifier>`
- Re-fire preservation: preserve `[x]` state per item-ID + per knob position when prior sentinel = `v=1`; start fresh if only old `rating-block` sentinel exists
- Sentinel string: `<!-- cowork:feedback-capture v=1 -->`
- Sidecar schema bump: 1.0.0 → 1.1.0 additive (new optional `feedback_capture` field)
- Ambiguous-knob guard: preserve UI `[x]` state, flag sidecar `ambiguous_knobs: [<kind>]` so v0.98.2 ingest treats as no-signal

## Architecture overview

Three deterministic helpers cooperate. OI prose carries voice + composition; helpers carry shape.

```
                 EOD orchestrator (cowork:eod-review)
                              │
        ┌─────────────────────┼─────────────────────┐
        │                     │                     │
   Step 3e:              Step 4 (NEW):         Step 8 (existing):
   composeBody           composeFeedbackCapture writeAtomicNote
        │                     │                     │
        ▼                     ▼                     ▼
  compose-body-helper.js  compose-feedback-     write-atomic-note-
   (EXTENDED:             capture-helper.js     helper.js
    per-item ^item-<id>    (NEW: builds Rail L  (EXTENDED: sidecar
    block-IDs emitted      sub-callouts +       includes new optional
    on surfaced items)     parses prior_md)     feedback_capture field)
                                │
                                ▼
                          learn-from-checks-helper.js
                          (EXTENDED: adds parseFeedbackCapture +
                           FEEDBACK_SENTINEL_RX; preserves
                           parseRatingCallout for non-EOD cadences)
```

**Data flow:**

1. Step 3e composes the body via `composeBody({ surfaced_items_by_kind, ... })`. Per-kind callout assembly emits `^item-<kind>-<7-char-sha1>` block-IDs at the end of each surfaced item's line (person-block, PR-row, ADO-story-row, calendar-event, email-thread, finance-txn).
2. Step 4 calls `composeFeedbackCapture({ cadence: "eod-review", day, surfaced_items_by_kind, prior_md, knob_positions: ["less", "same", "more"] })` which:
   - Parses `prior_md` for the `cowork:feedback-capture v=1` sentinel (if present) — preserves `[x]` state per item-ID, per knob position, and free-text content
   - If `prior_md` has only the old `cowork:rating-block schema=1.0.0` sentinel → start fresh (one-time cosmetic break on v0.98.1 deploy day)
   - Returns `{ rail_md, sentinel, item_id_registry, sidecar_observability }`
3. Step 8 writes the sidecar with the new optional `feedback_capture` field carrying `{ sentinel_version, item_count, kinds_with_knobs, ambiguous_knobs }` for v0.98.2 fast-path observability.

**The other 4 cadences** (morning-briefing / midday-tripwire / weekly-review / monthly-review) keep their existing Step 4 invocation of `{{shared.rating_callout_template}}` and parse via existing `parseRatingCallout`. No change. The `_shared-clauses.md` file retains `rating_callout_template` *and* adds a new `feedback_capture_template`.

```markdown

> Tick items that mattered. Set per-kind frequency. Type prose for nuance. Tomorrow's brief adjusts overnight.
> <!-- cowork:feedback-capture v=1 -->
>

> > - [ ] [[#^item-chat-a7b3c9d|Zhenzhen PR #353 thread]]
> > - [ ] [[#^item-chat-b8c4d0e|Ben/Stale Doc DB infra]]
> > - [ ] [[#^item-chat-c9d5e1f|Justin/Juan UDV reporting]]
> >
> > **Fire chat:** `[ ] less` `[ ] same` `[ ] more`
>
> > [!summary]- GitHub — items
> > - [ ] [[#^item-github-d0e6f20|PR #353 awaiting review]]
> >
> > **Fire GitHub:** `[ ] less` `[ ] same` `[ ] more`
>
> > [!summary]- Calendar — items
> > - [ ] [[#^item-calendar-e1f7031|10am Stefan 1:1]]
> > - [ ] [[#^item-calendar-f2g8142|2pm CRD-273 review]]
> >
> > **Fire calendar:** `[ ] less` `[ ] same` `[ ] more`
>
> ### Free-text feedback
>
> ```feedback
> (Type prose here — anything you want cowork to know. Example: "stop surfacing Diana's emails", "I never read calendar after 3pm", "Brex bills are too noisy".)
> ```
```

The lead preamble mirrors the existing rating-callout's preamble pattern (one explanatory line) but reframes for the richer shape. Per-kind sub-callouts use `[!summary]-` (collapsed by default — matches v0.98.0's expand-on-demand posture; the user expands the kind they want to grade). Item-ticks are wikilinks back to the `^item-<id>` block-IDs emitted by compose-body in Step 3e (the link resolves in-file; block-IDs render invisibly in Obsidian reading mode).

## Item-ID hash scheme

`^item-<kind>-<7-char-sha1-prefix>` where SHA-1 input = `<kind>:<canonical_identifier>`.

| Kind | Canonical identifier | Example item-ID |
| --- | --- | --- |
| chat (thread) | `<channel_id>:<thread_ts>` | `^item-chat-a7b3c9d` |
| chat (person-block) | `person:<resolved_name>` | `^item-chat-b8c4d0e` |
| github | `<repo>#<pr_number>` | `^item-github-c9d5e1f` |
| ado | `<org>/<project>:<story_id>` | `^item-ado-d0e6f20` |
| calendar | `<event_id>` | `^item-calendar-e1f7031` |
| email | `<thread_id>` | `^item-email-f2g8142` |
| finance | `<source>:<line_item_id>` | `^item-finance-g3h9253` |

**Stability properties:**
- **Day-stable.** Same input → same hash within a day. Re-fire after the user has ticked items preserves correct linkage.
- **Cross-day-stable.** Channel + thread IDs, PR numbers, story IDs don't change across days. v0.98.2 ingest can roll up per-item signal longitudinally ("user ticked Zhenzhen's chat thread 12 times in the last 30 days → upweight that person").
- **Cross-kind-unique.** Kind prefix in the input + the 7-char hex give a collision-resistant unique key per item.
- **Invisible.** Block-IDs (`^item-…`) render as nothing in Obsidian reading mode. The wikilink `[[#^item-chat-a7b3c9d|Zhenzhen PR #353 thread]]` shows just `Zhenzhen PR #353 thread`.

## Idempotent re-fire contract

`parseFeedbackCapture(prior_md)` returns `{ ticks: Map<item_id, boolean>, knobs: Map<kind, position>, free_text: string, sentinel_version: "v=1" | null }`.

| Prior file state | Behavior |
| --- | --- |
| Prior has `cowork:feedback-capture v=1` sentinel | **Preserve.** All `[x]` state per item-ID, per knob position, and full free-text content carried forward into the regenerated Rail L. |
| Prior has only `cowork:rating-block schema=1.0.0` sentinel | **Start fresh.** One-time cosmetic break on v0.98.1 deploy day. No migration of kind-level ticks to per-item ticks (kind-level ticks don't map cleanly to per-item granularity). |
| Prior file doesn't exist | **First-fire.** Empty Rail L (all `[ ]`; empty free-text fence). |
| Prior has BOTH sentinels | **Pathological.** Treat as v=1; log a Notice to the sidecar. (This should not happen in practice — `composeFeedbackCapture` emits exactly one sentinel.) |
| Prior shows multiple `[x]` per kind's knob row (e.g. `[x] less [x] more`) | **Preserve UI state**, flag sidecar `ambiguous_knobs: [<kind>]` so v0.98.2 ingest treats the kind's knob as no-signal rather than computing `(-1)+(+1)=0`. |

## Sidecar observability (additive 1.0.0 → 1.1.0)

`platform/blueprints/cowork/data/schemas/eod-review@1.0.0.json` (filename stays per workshop convention; internal `schema_version` field bumps from `"1.0.0"` to `"1.1.0"`). Adds:

```json
"feedback_capture": {
  "type": "object",
  "required": false,
  "properties": {
    "sentinel_version": { "type": "string", "enum": ["v=1"] },
    "item_count": { "type": "integer", "minimum": 0 },
    "kinds_with_knobs": { "type": "array", "items": { "type": "string" } },
    "ambiguous_knobs": { "type": "array", "items": { "type": "string" } }
  }
}
```

Purpose: v0.98.2 ingest gets a fast-path "is there feedback to parse on this day?" check without re-reading the markdown body. `ambiguous_knobs` records the kinds where the user has multiple knob positions ticked — v0.98.2 ingest treats them as no-signal.

Additive only — pre-v0.98.1 EOD sidecars (without the field) still validate.

## User-content preservation safeguards (4)

The cowork installer is already an explicit allowlist — `platform/blueprints/cowork/manifest.json:files[]` declares the 109 (becoming ~111 with v0.98.1's new helper + shim) destinations the installer can write to. **ZERO** entries match `context/<engagement-id>/`, `memory/`, `daily/`, `weekly/`, `monthly/`, `snapshots/`, or `summaries/` — these paths are user-owned and cannot be touched by the installer. The `materialize_once: true` flag on `context/user-preferences.md` and all 5 `prompts/<cadence>.md` files ships them on first install and never overwrites them on update. Landmine #11 (module-directory invariant) confines cowork writes to `spice/cowork/` regardless.

v0.98.1 codifies these guarantees into actionable user-facing safeguards:

### Safeguard 1 — Pre-deploy snapshot recipe

Added to `commands/install.md` Upgrading section:

```bash
# Before running `sauce update --bump-pins`:
mkdir -p ~/cowork-snapshots
tar -czf ~/cowork-snapshots/$(basename "$PWD")-pre-v0.98.1-$(date -u +%Y%m%dT%H%M%SZ).tar.gz \
  spice/cowork/context/* \
  spice/cowork/memory \
  spice/cowork/daily spice/cowork/weekly spice/cowork/monthly \
  vault-config.md user-preferences.md
```

Snapshots live outside the vault tree (`~/cowork-snapshots/`) so future installs cannot clobber them. Restore is a single `tar -xzf <snapshot>` to a temporary dir for selective restore.

### Safeguard 2 — Post-install diff verification

```bash
# Just before `sauce update --bump-pins`:
touch ~/.sauce/pre-update-marker

# Run the update:
sauce update --bump-pins

# Verify NO user-owned file was touched:
find spice/cowork/context spice/cowork/memory -newer ~/.sauce/pre-update-marker -type f
# Expected output: EMPTY (no matches)
```

Sanity check that the structural guarantee held. Documented in install.md Upgrading section alongside Safeguard 1.

### Safeguard 3 — Explicit § Out-of-scope `files[]` guard (this design)

See § Out-of-scope below. Pinned in the design and enforced during S1.7 manifest update. The S1.7 plan stage includes an automated grep that fails CI if any `files[]` entry's `dest` matches the forbidden patterns.

### Safeguard 4 — Reaffirm `.bak` as single-shot tripwire

The installer already writes `.bak` files when overwriting. Useful tripwire ("did the installer touch this file?") but NOT a multi-version rollback path — the second install overwrites the first `.bak`. Documented in install.md Upgrading section: the dated tarball in Safeguard 1 is the durable rollback path; `.bak` is a same-session safety net.

## Forward arc — v0.98.2 (and v0.98.1.x candidates)

### v0.98.2 — reconciler free-text + per-item-tick ingest

Reads what v0.98.1 captures; closes the loop. Sketched in v0.98.0 design § Forward arc and elaborated here per user vision (2026-06-10):

> "another job took what i liked, what i didn't like, my feedback, then updated the relevant files so that all scheduled jobs would then adjust the next day"

**Pipeline:**

1. **Trigger.** Reconciler fires on existing cadence (daily during warmup, weekly post-warmup). Reads the last N days of EOD reviews where the sidecar `feedback_capture.item_count > 0`.
2. **Parse structured signal** (deterministic). Per-item ticks → rolled up per-kind, per-person, per-channel weight nudges via the item-ID hash registry. Frequency knobs → direct weight delta (`less = -0.05` / `same = 0` / `more = +0.05`; clamped to [0, 1]). Ambiguous knobs (per sidecar `ambiguous_knobs[]`) → skipped.
3. **Parse free-text** (LLM pass). NEW sub-skill `cowork:ingest-feedback` runs an LLM pass with a structured-output prompt: "Read this user's feedback prose. Extract structured intents: (a) per-person/channel/topic uprank/downrank, (b) voice corrections, (c) coverage gaps, (d) other. Return as deltas with proposed write-targets."
4. **Apply with audit trail.**
   - All deltas logged to `spice/cowork/memory/<engagement>/feedback-deltas.md` (append-only changelog: date + delta + source quote)
   - `learned_weights` numeric updates: applied directly with clamp + log (schema 2 → 3)
   - Microscope `what_matters` strings: append-only — never rewrite the contract; user prunes later
   - Personality/voice changes: PROPOSED only — surface in next-day morning brief as a callout "Voice tweak proposed: [...]. Apply via /cowork apply-voice-deltas?"
   - Coverage gaps: written to `spice/cowork/memory/<engagement>/coverage-queue.md`

- learned_weights schema 3 shape — `per_person.<name>.weight` flat, or nested under per-kind (`per_kind.chat.per_person.<name>.weight`)?

- Free-text LLM model — Sonnet 4.6 (cheap, fast — recommended) vs Opus 4.7 (smarter)?
- Reconciler cadence for feedback ingest — daily vs weekly?
