# Board-health sweep — design (pointer)

**Cycle:** 2026-08-04 · **Version:** workshop 0.281.7 → 0.282.0 · **Workstream:** loop-integrity program #1

The approved design for this cycle lives at
[`Docs/superpowers/specs/2026-08-04-board-health-sweep-design.md`](../superpowers/specs/2026-08-04-board-health-sweep-design.md)
(merged to `main` in PR #759 alongside the program decomposition,
[`Docs/superpowers/specs/2026-08-04-loop-integrity-program.md`](../superpowers/specs/2026-08-04-loop-integrity-program.md)).
It carries the receipt shape, the five checks, the vault-note write rules, the
failure-handling clauses, and the ten `BH-*` test cases; the design was settled
before implementation began and did not change during the cycle.

Three interpretations were decided at planning time (recorded in
[`Docs/superpowers/plans/2026-08-04-board-health-sweep.md`](../superpowers/plans/2026-08-04-board-health-sweep.md)
§ Spec interpretations, and in the result doc):

1. Check 1 exempts pre-claim `planning` notes, otherwise `no_op: true` would be
   unreachable on any non-empty ledgerless board — a state the spec explicitly
   requires to remain reachable.
2. `lane_divergence` emits an entry on disagreement OR when the epic carries
   untracked members (the "looked broken but was correct" case).
3. The `BoardHealth` customjs renderer does not exist yet; the scaffold body is
   the stock customjs-guard block per spec, and a renderer is render-layer work
   deferred with the spec's other deferred items.
