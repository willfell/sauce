# v0.110.3 brief — MonthlyOverview band

## The ask

For any given month — e.g. July 2026 — the user wants a single glance answer to "where did the money go and how much did I move on debt." This was the cohesion piece deferred from the v0.108.0 brief; it has been on the carry-forward list since 2026-06-15 and is now displaced four cycles (v0.109.0 projects-overhaul, v0.110.0 installer-healing, v0.110.1 + v0.110.2 race PATCHES).

The Budget note for that month — `spice/finance/budgets/<YYYY-MM>/Budget-<YYYY-MM>.md` — is the right home. One note per month. A "budget" and a "monthly view" are the same conceptual thing through different lenses; zero new sub-area, zero migration of existing user content, zero EntityCreate plumbing. `[[Budget-2026-07]]` is already the wikilink users type.

## Headline math

> income − spending − debt paydown = **net cashflow**

- **income** = Σ `paycheck_amount` across paychecks dated in this month (`pay_period_start` matches `YYYY-MM`).
- **spending** = Σ `categories[*].actual` on this Budget note (excludes debt-payment categories — see § Out-of-scope-on-day-one).
- **debt paydown** = Σ `expenses[*].amount` across paychecks dated in this month where `expenses[*].debt` is a resolvable wikilink AND `expenses[*].paid === true`. "What actually hit the books this month."
- **net cashflow** = income − spending − debt-paydown. Red if negative; green if positive.

The math intentionally does NOT use `balance_history[]` snapshots for the headline number. `balance_history` is a Band 2 secondary signal because:
- it reflects the bank's recorded balance, not necessarily the user's allocated payments;
- the user can adjust balance entries manually, which would skew the headline if it drove the math;
- "what hit the books" semantically matches the planned-attack worldview the finance blueprint already encodes.

## Render shape (three bands)

**Band 1 — headline.** Income · Spending · Debt paydown · **Net cashflow** (colored). Same palette as `BudgetSummary` (`#16a34a` green, `#b45309` amber, `#dc2626` red).

**Band 2 — debt mini-row.** Total debt balance (Σ `current_balance` across all `Debt-*.md`) + month-over-month delta. Delta sources: first-of-month + last-of-month entries in `balance_history[]` per debt where available; else current-balance for the as-of value with a "no MoM signal yet" pill.

**Band 3 — sources strip.** "N paychecks counted (sum $X) · M debt entities surveyed" — tiny audit footer so the user can sanity-check the inputs.

## Out-of-scope for v0.110.3

- **Debt-payment category exclusion semantics.** The first cut sums `categories[*].actual` straight — if the user is double-counting debt-payment categories alongside the new `expenses[*].debt: true paid` rollup, that overlap is a follow-up patch (v0.110.x). Document the math in the widget's UI so the user can spot the overlap themselves.
- **Inflow / outflow detail breakdown.** No per-paycheck or per-debt itemization on the band itself; the user clicks into the relevant Paycheck or Debt entity for that.
- **Projected month-end vs actual.** No pace math beyond what `BudgetSummary` already shows. The Overview band is income/spending/debt — `BudgetSummary` keeps the pace duty.
- **MoM trend chart.** Sparkline over the last 3-6 months is queued for v0.111.x once the band has been load-tested.
- **`gather-cc-debt-snapshot` skill composability** — v0.111.x carry-forward.
- **Brew tap formula bump** — still at 0.84.0; local-clone workshop_relative_path is canonical for both consumer vaults.
- **cowork:doctor** — displaced for the NINTH cycle.

## Risks

- **Existing finance lineage stale enough that the migration can't find the FinanceStatus.renderBadge block to anchor on.** Mitigation: fallback to inject after frontmatter close (same posture as `_migrateBudgetBody` / `_migratePaycheckBody`).
- **Debt entity reads happen at render time via `dv.pages('"spice/finance/debts"')`** — if the user has no debts (empty vault), Band 2 renders "No debt tracked" placeholder and Band 1 omits the debt-paydown column. No-data isn't an error.
- **Paycheck `expenses[*].debt` field semantically depends on v0.108.0's `applyFinancePaycheckDefaultsDebtLinking` having run.** For vaults where that migration hasn't fired yet (e.g. accuris, no debt sub-area), the debt-paydown number is `$0` and the band still renders correctly.
- **Month boundary edge cases.** A paycheck with `pay_period_start: 2026-07-31` is "July"; a paycheck with `pay_period_start: 2026-08-01` is "August". Use string-prefix match `YYYY-MM` on `pay_period_start`. Cross-month edge cases are not handled in v0.110.3 (out-of-scope).
