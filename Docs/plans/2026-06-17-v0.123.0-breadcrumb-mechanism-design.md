# Breadcrumb mechanism — design (v0.123.0)

## Mission

Promote `platform/blueprints/project/helpers/breadcrumb.js` into a shared `breadcrumb` mechanism with a config-driven type-dispatch registry, and migrate the project blueprint onto it as the proof case. Existing project notes must render **byte-identical** trails after the migration (e.g. `test-project / Docs / Architecture` — same labels, same wikilink targets, same separators, same DOM).

Class name stays `Breadcrumb` → customJS singleton-by-class-name → live-render, no body migration. Same trick used for `SectionLabel` in v0.122.0.

## Decided in brainstorming (2026-06-17)

- **Link form: template strings with `{<resolver>}` slots.** Mechanism stays purely generic — knows zero blueprint paths. Per-blueprint manifest declares its own link shapes.
- **Project-name fallback for map/kanban/task-note: `path:2` (slug).** Test-project parity is preserved (slug == name there); mixed-case projects accept a minor cosmetic regression that a later cycle can heal via a `project_name` FM backfill migration. Keeps v0.123.0 scope to live-render only.
- **Top-level hubs render nothing** (their `cur.type` simply isn't in the registry).
- **Trails INCLUDE the month segment** for date-organized blueprints (decided 2026-06-16; not undone here).
- **to-do drops `project >=1.21.0` and adds `breadcrumb >=0.1.0`** this cycle — the only reason to-do depended on project was for `Breadcrumb`. Section-label already its own mech (v0.122.0).

## 1. Registry shape + storage

`ranch/breadcrumb-registry.json` — aggregated at install time from per-blueprint manifest blocks. Mirrors `ranch/nav-buttons-registry.json` (NOT entity-create — no flattened `entries[]` view; runtime always dispatches by `(blueprint, type)`).

```json
{
  "schema_version": 1,
  "contributions": {
    "project": {
      "types": {
        "project":      { "ancestors": [ /* ... */ ] },
        "project-todo": { "ancestors": [ /* ... */ ] },
        "docs-hub":     { "ancestors": [...], "current": { /* ... */ } },
        "section-hub":  { "ancestors": [...], "current": { /* ... */ } },
        "doc-note":     { "ancestors": [...], "current": { /* ... */ } },
        "map":          { "ancestors": [...], "current": { /* ... */ } },
        "kanban":       { "ancestors": [...], "current": { /* ... */ } },
        "task-note":    { "ancestors": [...], "current": { /* ... */ } }
      }
    }
  }
}
```

Per-blueprint manifest declares a top-level `breadcrumb: { types: { ... } }` block. Installer's new `applyBreadcrumb(tp, manifest, ...)` step mirrors `applyNavButtons` byte-for-byte:

- read existing registry (preserve malformed JSON; C4 hardening — no silent overwrite);
- per-entry shape validation (skip bad entries; do not take whole contribution down);
- empty/missing `breadcrumb` block on a re-installing item → PRUNE that item's prior contribution;
- failures record history, never throw.

Subscription-aware prune at install top wipes contributions for fully-unsubscribed items (extends the existing prune step for nav-buttons + entity-create).

At render time, `Breadcrumb.render(dv)` walks `Object.values(registry.contributions)` looking for the first contribution whose `types[cur.type]` matches. Frontmatter `type` values are globally unique today, so first-match-wins is unambiguous. Collisions log a one-time `console.warn` and pick the first.

**Top-level hub case:** `cur.type` (e.g. `projects-hub`, no such type today on `Projects.md` — it has no type frontmatter) doesn't appear in any contribution → render nothing.

## 2. Resolver grammar

### Atoms (the leaf primitives)

| Atom | Resolves to |
|---|---|
| `fm:<field>` | `dv.current()[field]`, wikilink-stripped. Returns empty if absent or empty-string. |
| `path:<n>` | Nth segment (1-indexed) of `current.file.path` split on `/`. Empty if out of bounds. |
| `file:basename` | `current.file.name` (no `.md`). |
| `file:stem` | Alias for `file:basename` (reserve; same value today). |
| `lit:<text>` | Literal string `<text>`. Useful as a chain terminator. |

### Transform prefix (single-level)

| Transform | Meaning |
|---|---|
| `slug:<atom>` | Apply `_slugify` to the atom's result (lowercase, `[^a-z0-9]+` → `-`, trim leading/trailing `-`). Composes once; no `slug:slug:...` nesting. |

Why this transform exists: section-hub + doc-note link paths use slugified parent-section names (`spice/projects/{slug}/docs/{slug:fm:parent_section}/...`). Without `slug:`, every blueprint that wants slug-as-path-segment would need a `_slug` companion FM field. We use a transform instead of schema growth.

### Labels (`label` field on every segment)

A label is a **`|`-separated chain of atoms**. First atom whose value is non-empty wins. All-empty → label is empty (segment gets dropped from ancestors; current falls back to `file:basename`).

```text
fm:project_name|path:2          // FM if present, else 2nd path segment
fm:section|file:basename        // FM if present, else file basename
lit:Docs                        // always literal "Docs"
```

### Links (`link` field on ancestors; optional on current)

A link is a **template string** with `{<atom>}` interpolation slots. The same atom grammar applies inside `{...}`, including `|`-chains and `slug:` transforms.

```text
spice/projects/{path:2}/{fm:project_name|path:2}.md
spice/projects/{path:2}/docs/{slug:fm:section}/{fm:section}.md
```

**Missing-data semantics for links:** if ANY `{...}` slot resolves to empty → the link fails → the segment renders as plain LABEL (no anchor). The breadcrumb does NOT abort; just that segment loses its hyperlink.

### Conditional ancestors (`when` field)

Ancestor entries may declare an optional `when` object. The ancestor renders only if EVERY key matches.

| Predicate | Meaning |
|---|---|
| `"fm:<field>": "present"` | FM field is non-empty (after wikilink-strip). |
| `"fm:<field>": "<literal>"` | FM field equals literal value (after wikilink-strip). |
| `"fm:<field>": "absent"` | FM field is missing or empty (negation). |

Multiple keys AND-conjoin. No OR / nested boolean today; if a blueprint needs OR, declare two ancestor entries with mutually-exclusive `when` clauses.

```json
{
  "when": { "fm:depth": "2" },
  "label": "fm:parent_section",
  "link": "spice/projects/{path:2}/docs/{slug:fm:parent_section}/{fm:parent_section}.md"
}
```

### Current segment

`current` is OPTIONAL. Three shapes:

1. **Plain text (default per arc design)** — `{ "label": "<chain>" }` → renders bold, no link, no `cssclass`. If label resolves empty, fall back to `file:basename`.
2. **Linked** — `{ "label": "<chain>", "link": "<template>" }` → renders as a wikilink. If link template fails, falls back to plain text.
3. **Omitted** — no `current` key. The trail terminates at the last ancestor. Used for `type: project` (the project hub itself; today's behavior renders just the project-name wikilink, no trailing bold-text segment).

### Empty-trail short-circuit

If a type resolves to ZERO rendered segments (no ancestors matched + no current), the Breadcrumb renders nothing. Same as the "top-level hub" case from §1.

### Parity caveats (accepted)

- **map/kanban/task-note** today rely on `Breadcrumb._resolveProjectFromPath` to look up the project hub via `dv.pages(...)` and recover the human-readable `projectName`. Under the new grammar, fallback is `path:2` (the slug). Test-project parity is preserved (slug == name); mixed-case projects show the slug. Documented as a v0.124.x follow-up: heal migration that backfills `project_name` to map/kanban/task-note frontmatter, OR introduce a `lookup:` resolver primitive if multiple blueprints need it.
- **`type: project` renders as a wikilink-to-self** (single ancestor, no current). Matches today exactly.
- **`type: project-todo`** today has no explicit branch in `Breadcrumb` and falls through to `parts.join(' / ')` with just the project ancestor — same shape as `type: project`. Mapped identically.

## 4. Mechanism + installer + schemas-index

### Mechanism

`platform/mechanisms/breadcrumb/breadcrumb.js` — class `Breadcrumb`, methods:

- `async render(dv)` — public entry point called by `dv.view("ranch/views/customjs-guard", { class: "Breadcrumb" })`.
- `_loadRegistry()` — read `ranch/breadcrumb-registry.json` via `app.vault.adapter.read`; cache per Breadcrumb instance for the page's lifetime; treat missing/malformed as empty registry (silent render-nothing).
- `_findTypeEntry(cur)` — first-match scan across `Object.values(registry.contributions)`.
- `_resolveAtom(atom, dv)` — dispatch on prefix (`fm`, `path`, `file`, `lit`, `slug`); returns string.
- `_resolveChain(chain, dv)` — `|`-split, first non-empty.
- `_resolveTemplate(tpl, dv)` — `{...}` interpolation; returns null on any empty slot.
- `_evalWhen(whenObj, dv)` — predicate evaluation.
- `_renderHTML(segments)` — emit the same `<div class="project-breadcrumb">` wrapper + `<a class="internal-link">` segments + `<span style="font-weight:600;...">` current + `<span style="opacity:0.5;"> / </span>` separators that today's helper does.

CSS class on the wrapper stays `project-breadcrumb` (yes, the legacy name) for byte parity with existing notes' rendered output. A future cycle can rename to `breadcrumb` if there's a styling reason.

### Mechanism manifest

`platform/mechanisms/breadcrumb/manifest.json` — same shape as `section-label/manifest.json`:

```json
{
  "name": "breadcrumb",
  "version": "0.1.0",
  "description": "Shared breadcrumb primitive. customJS.Breadcrumb.render(dv) renders the trail above a note based on the per-blueprint type-dispatch declared in ranch/breadcrumb-registry.json (aggregated at install time from per-blueprint manifest `breadcrumb` blocks). Class name unchanged (Breadcrumb) — existing dv.view callers across project + to-do blueprints keep working. Promoted from the project blueprint helper at sauce v0.123.0; second plan of the note-chrome standard arc.",
  "depends_on": [
    { "name": "customjs-guard", "range": ">=1.0.0" }
  ],
  "customjs_classes": ["Breadcrumb"],
  "files": [
    { "source": "breadcrumb.js", "dest": "{{scripts_path}}/breadcrumb/breadcrumb.js" }
  ],
  "post_install": [],
  "rule_fragments": []
}
```

### Per-blueprint manifest block

Project's `platform/blueprints/project/manifest.json` gains a top-level `breadcrumb` block matching §3 verbatim. Drop the `helpers/breadcrumb.js` `files[]` entry. Add `breadcrumb >=0.1.0` to `depends_on`. Bump version `1.23.0 → 1.24.0` (MINOR — `depends_on` surface changed).

### Installer aggregation

New step in the per-item install loop, mirroring `applyNavButtons`:

```js
await applyBreadcrumb(tp, mech, variables, history, git);   // NEW v0.123.0
```

Posture identical to nav-buttons: C4 hardening on existing registry, per-entry validation, empty-block prunes prior contribution.

Subscription-aware prune extends the existing pattern: new `pruneBreadcrumbRegistry(...)` called from the install-top prune section alongside nav-buttons + entity-create.

### Schemas-index entry

```json
{
  "id": "breadcrumb-registry",
  "kind": "data-file",
  "owner": { "type": "mechanism", "name": "breadcrumb" },
  "source": "ranch/breadcrumb-registry.json",
  "consumers": [
    "platform/mechanisms/breadcrumb/breadcrumb.js"
  ],
  "notes": "Aggregated at install time from per-blueprint manifest `breadcrumb: { types: { ... } }` blocks via applyBreadcrumb in install.js. First-match-wins over contributions{} by current-note `type` frontmatter. Schema: { schema_version:1, contributions:{ <bp>:{ types:{ <type>:{ ancestors[], current? } } } } } where each segment has { when?:{}, label, link? } with `|`-chain labels + `{atom}` template links + `fm:`/`path:`/`file:`/`lit:` + `slug:` transform resolver grammar. See Docs/plans/2026-06-17-v0.123.0-breadcrumb-mechanism-design.md."
}
```

Kind `data-file` is the closest fit in today's `kind` enum. Precedent: cowork's `kind-titles.json` / `kind-patterns.json` use the same kind for installer-generated data files. (Neither nav-buttons-registry nor entity-create-registry is indexed today; v0.123.0 does not retroactively index them — out of scope. Tracked as v0.124.x candidate.)

New harness `platform/test/run-breadcrumb.js` (added to `release:preflight` chain). Asserts:

### BR1–BR4: relocation guards
- Mechanism file exists at `platform/mechanisms/breadcrumb/breadcrumb.js`.

- Mechanism manifest declares `customjs_classes: ["Breadcrumb"]`.
- Catalogue `platform/manifest.json` `mechanisms[]` contains `breadcrumb@0.1.0`.

### BR5–BR9: resolver primitives
- `fm:<field>` reads frontmatter; wikilink-stripped.
- `path:<n>` 1-indexed segment of `current.file.path`.
- `file:basename` returns basename without `.md`.
- `lit:<text>` returns literal.
- `slug:<atom>` slugifies the atom result.

### BR10–BR12: combinators
- `|`-chain returns first non-empty atom.
- All-empty chain → empty string.
- Link template returns `null` if any `{...}` slot is empty.

### BR13–BR14: `when` predicates
- `"fm:<field>": "present"` gates correctly (non-empty vs empty).
- `"fm:<field>": "<literal>"` gates on exact match.
