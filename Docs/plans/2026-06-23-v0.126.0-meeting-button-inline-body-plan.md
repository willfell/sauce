# Meeting button inline_body parity — implementation plan (v0.126.0)

**Goal:** Promote the entity-create `New Meeting` button's `inline_body` in `meetings/manifest.json` to full chrome parity with the Templater `Meeting.md` template — Breadcrumb + SpaceNavButtons + MeetingLeafActions + Attendees/Agenda/Notes/Action Items SectionLabels + PeopleRendering chip block. Closes the v0.125.0 omission where MeetingLeafActions was added to the Templater path + heal but not to the button creation path.

**Architecture:** Single-file manifest content change. No new helpers, no new mechanism, no new tests. Lockstep version bump + standard preflight + dogfood.

## Risk + rollback

- **Risk:** the inline_body content rendering wrong on real Obsidian (e.g., MeetingLeafActions block fires before its class is loaded). Mitigation: identical block ordering to `Meeting.md`, which has been in production since v0.125.0; same customjs-guard wrapping pattern.
- **Risk:** consumer vault's existing button-created meeting notes look different from new ones. Acceptable: heal already injects MeetingLeafActions; SectionLabels stay only on new notes (heal is conservative — see design §0).
- **Rollback:** revert the manifest change; bump workshop 0.126.0 → 0.126.1 with the revert; cycle close. (Not anticipated.)
