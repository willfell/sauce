# v0.101.0 — verbal feedback everywhere — result

## TL;DR

Puts the prose-first feedback channel v0.99.0 built for EOD on EVERY scheduled brief. Before this cycle, the other four cadences (morning-briefing, midday-tripwire, weekly-review, monthly-review) still emitted the v0.96.0 kind-checkbox-only rating callout — the user opened a morning brief, saw only checkboxes, and asked for verbal feedback everywhere, feeding the loop that makes tomorrow better. Three structural moves landed in one MINOR cycle:

1. **Capture v=4 — one shape on all five briefs.** The one-tap `Useful: [ ] yes [ ] no` line + the free-text typing box render on top of EVERY brief's feedback section. Below the box, EOD keeps its exact v=3 per-item Mattered/Didn't-like lists + frequency knobs; the four other cadences render ONE collapsed `Kinds — quick ticks` checklist (the old checkbox content, demoted to garnish — computed from the same surfaced-kind source via the existing `{{$rating_kind_lines}}` token, so ZERO new substitution tokens). The legacy `rating-block` marker stops being EMITTED; its parser lives forever for the historical corpus, and the write-guard accepts EITHER marker (`FEEDBACK_SENTINEL` OR the legacy `RATING_SENTINEL`). On upgrade day, a same-day prior carrying only the legacy marker surrenders its kind ticks into the new checklist via `parseRatingCallout` — nothing is lost.
2. **Per-cadence satisfaction (schema 5).** Satisfaction entries become `{day, cadence, useful}` — up to five taps a day coexist, and the doctor (next cycle) can grade each cadence separately ("morning trends yes, midday trends no"). `appendSatisfaction` gains `opts.cadence`; same-(day, cadence) re-log overwrites; the window trims by DAY (30) with a belt-and-suspenders 200-entry cap. `normalizeLearnedWeightsV5` extends the tolerance chain (2 / missing / "1.1.0" / 3 / 4 / 5, string-or-number, `Number()`-coerced gates, deep-copied returns). The 4 → 5 step is **PURELY ADDITIVE — NO skip-zeroing, NO warmup reset, NO counter changes**: schema-4-era `{day, useful}` entries gain `cadence: "eod-review"` (the only cadence that had a tap). Graduation rules untouched.
3. **Prose ingest generalized.** The 03:00 reconciler extracts intents from up to five typing boxes per day, each tagged `source_cadence`; an accepted intent applies at most once per (day, intent, kind, entity) across ALL of yesterday's notes (dedup at the disposition layer; second occurrence audit-logged `[pending] dedup`). NEW intent `satisfaction` (global sentiment, no kind required) + NEW `proposed_target` value `satisfaction-series`; prose WINS over the same note's tap on disagreement. NEW symmetry fix: downrank prose scoped to a kind WITHOUT a named entity counts as that kind's SKIP — the mirror of v0.99.0's uprank-counts-as-tick (`applyIntentKindTicks` RENAMED `applyIntentKindObservations`; it now emits skips, not just ticks). `classifyEngagementDay` semantics UNCHANGED — five taps without other signal across several notes is still TAP-ONLY.

No new scheduled job; no contract bump (0.35.1 holds); ZERO new substitution tokens; no new installer write surfaces under user-owned paths; mechanism count UNCHANGED at 17.

## Discoveries and lessons

### 1. The S1.0 fixture audit had a scope gap — goldens live under TWO roots

The S1.0 grep audit covered `platform/test/fixtures/` and concluded "no fixture dirs exist" — but compose goldens live under `platform/blueprints/cowork/helpers/fixtures/`. One CONSUMED compose-body golden needed regeneration at S1.2, and 5 UNCONSUMED compose-feedback-capture fixture dirs (regenerated to v=3 truth only one cycle ago at v0.99.0 S1.2.1) were consumed by ZERO runners and were DELETED at S1.2.1. This is a direct recurrence of v0.99.0 lesson #5 — last cycle we regenerated the orphans; this cycle we deleted them, which is the durable fix. **Lesson: fixtures without consumers rot silently — and the audit itself rots if it only greps the canonical fixture root. Enumerate EVERY fixture root (`platform/test/fixtures/` AND `helpers/fixtures/`) in the S1.0 sweep, and prefer deletion over regeneration for consumer-less dirs.**

### 2. Fixtures with impossible data are latent until code starts interpreting the field

HC-V0990-SCHEMA-A6's fixture carried the impossible date `"2026-05-32"` and passed GREEN for an entire cycle — the v0.99.0 `appendSatisfaction` treated `day` as an opaque string (same-day overwrite by equality; rolling window by entry count). The v0.101.0 day-window math PARSES the date, and the new code threw on the garbage. Superseded at S1.5 with a valid-date fixture. **Lesson: a fixture's data is only as validated as the code that reads it — impossible values survive as long as the field is opaque, then detonate the moment a later cycle starts interpreting it. When a new feature begins PARSING a previously-opaque field, audit every existing fixture that populates it.**

### 3. Per-task two-stage review caught 5 substantive issues across 4 stages — keep the habit

The spec + quality review after each implementation task (the v0.99.0 habit) caught: (a) an unfalsifiable warmup-reset pin (asserted nothing the migration could fail — S1.1.1); (b) a `learning_enabled: false` dispatch coverage gap (S1.1.1); (c) checklist kind dedup (duplicate surfaced kinds rendered twice — S1.2.2); (d) the item-mode/checklist kind-mapping collision in the reconcile OI (without scoping, a checklist note's `kind_ticks` and an item-mode note's mattered-tick rollup would double-count — S1.7.1); (e) stale schema-4 labels in the normalize prose (S1.7.1). All five were issues the 3am fire-time LLM or a future cycle would have hit. **Lesson: the two-stage review is paying for itself every cycle (4 review-driven fixes at v0.99.0, 5 here) — it stays a standing part of the stage cadence.**

### 4. The either-marker guard resolved the v0.99.0-era EOD discrepancy STRUCTURALLY

Ground truth 3 of the design flagged it and S1.0 confirmed it: `eod-review.md` Step 8.5 said to pass `surfaced_kinds_for_rating`, yet EOD bodies carried no rating-block marker — under a uniformly-driven guard, every EOD write would have failed `missing-rating-callout`. Rather than patching the OI prose to carve out EOD, S1.3's guard accepts EITHER marker and S1.6 makes all five orchestrators pass the array uniformly — the discrepancy class is now unrepresentable, not documented-around. **Lesson: when a contract discrepancy is found between prose and behavior, prefer the structural fix (make the guard accept the truth uniformly) over a prose carve-out — carve-outs are where the next cycle's 3am ambiguity lives.**

### 5. Pre-existing, out of scope: weekly/monthly Step 7 example paths contradict their tier headers

`weekly-review.md` and `monthly-review.md` Step 7 example paths say `spice/cowork/daily/...` while their own path headers declare the week/month tiers. Pre-existing (predates this cycle), discovered during the S1.7 OI sweep, deliberately NOT fixed here (out of the cycle's contract surface; v0.99.0 lesson #3 sweeps were scoped to the steps this cycle edited). **Lesson: logged as a carry-forward candidate — example paths in OI prose are fire-time instructions to a literal-minded LLM, so a contradicting example is a latent mis-write.**
