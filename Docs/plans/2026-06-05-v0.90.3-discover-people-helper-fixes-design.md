# v0.90.3 — discover-people helper bug fixes + prose-extraction fallback

Status: DRAFT (spec for v0.90.3 PATCH).
Bumps: workshop `0.90.2 → 0.90.3` PATCH; cowork `0.28.1 → 0.28.2` PATCH; mechanism count unchanged at 17.

## 0. Why this cycle

Live run of `/cowork discover-people headspace` (pre-v0.90.2) surfaced three concrete issues:

1. **`composeUpdatedVaultConfig` corrupts vault-config when `inner_circle_people` is `[]` (inline empty array).** LLM log: *"The helper's regex malformed the file — the closing `---` got consumed. Restoring from backup and doing the edit directly."* Root cause: the helper checks for `inner_circle_people:\s*$` (multi-line block header) but NOT for `inner_circle_people: []` (inline empty-array shorthand). When inline form is found, the function falls through to the "insert new block" branch without removing the inline line; the engagement-end boundary calculation goes wrong; the closing `---` gets consumed.

2. **`parseInnerCircleFromMicroscope` extracts too few candidates from prose-narrative microscopes.** Headspace's chat microscope embeds inner-circle people in `### 1. Inner circle first` prose paragraphs and "Going quiet" / "Open loops" / "Cadence sweep" sections with bold-name patterns (`**Diana** — 12 days since`), not in the structured `Inner circle (people): A, B, C` format the helper expects. Result: LLM had to manually extract names. Missed Ellen Senders + Mo Holton + Evie + Andres Cornejo + Galen Gossman + David Panlilio + Mrs. Panlilio + Tyler Igoe + Grace Fellhoelter who appear in atomic-note briefings but weren't promoted.

3. **No prose-extraction fallback in the orchestrator.** When the helper returns sparse candidates from a non-trivial microscope, there's no documented behavior for the LLM to fill the gap. The headspace LLM ad-libbed but the pattern isn't codified.

## 1. Fix B1 — composeUpdatedVaultConfig inline-empty handling

Update `discover-people-helper.js` `composeUpdatedVaultConfig()` to detect and replace `inner_circle_people: []` (inline empty array) with the multi-line block IN-PLACE.

Logic (pseudocode):

```
// Walk engagement block for inner_circle_people
for each line in engagement block:
    if line matches /^    inner_circle_people:\s*\[\s*\]\s*$/:
        // INLINE EMPTY ARRAY — replace in-place
        replace this line with:
            "    inner_circle_people:"
            ...names_to_append.map(n => `      - "${n}"`)
        return
    elif line matches /^    inner_circle_people:\s*$/:
        // MULTI-LINE BLOCK — find end and append
        ...existing logic...
        return
// Else: NOT FOUND — insert at engagement end (existing logic)
```

The inline-empty branch uses `lines.splice(inlineIdx, 1, ...newLines)` to atomically replace 1 line with N lines, preserving everything else.

## 2. Fix B2 — parseInnerCircleFromMicroscope prose patterns

Widen the parser to detect bold-name patterns in prose narrative. Add these passes (in order):

### B2.1 — Bold-name extraction in inner-circle-adjacent sections

After the existing `## What matters` extraction passes, ALSO scan for sections whose H3/H4 heading contains keywords: `inner circle`, `going quiet`, `cadence sweep`, `open loops`, `who you owe`, `reply owed`. Within each such section, extract bold-name patterns:

- `\*\*([A-Z][a-z]+(?:\s+[A-Z][a-z]+){0,2})\*\*` — bold-wrapped 1-3 capitalized words

This catches `**Diana**`, `**Mo Holton**`, `**Ellen Senders**`, `**Andres Cornejo**`, but also potentially false positives like `**EMS**` or `**Cap1 Platinum**`.

### B2.2 — Common-word filter

Filter the bold-name candidates to remove common false positives:

- All-caps single-word (likely abbreviation: EMS, AWS, etc.)
- Words appearing in a known cards/products/orgs list (Cap1 Platinum, Discover, Apple Card, SCHEELS, etc.) — provided as a small built-in list of common card/org names
- Words with non-letter characters (digits, special chars)

### B2.3 — Re-search whole-body for "going quiet" cadence-sweep mentions

If the `## What matters` section yields fewer than 3 candidates, ALSO search the entire microscope body (not just `## What matters`) for the same patterns. The headspace microscope's "Cadence sweep" section is at body level, not inside `## What matters`.

## 3. Fix B3 — Discover-people orchestrator prose-extraction fallback

Add a new Step 4.5 to `discover-people/SKILL.md` (between Step 4 aggregate and Step 5 classify):

```markdown
4b. **Prose-extraction fallback (v0.90.3):** if `candidates.length < 3` AND any microscope body length > 500 chars, perform LLM-side prose extraction as backup:
    - For each microscope body > 500 chars, scan for inner-circle-adjacent sections (H3/H4 headings containing 'inner circle', 'going quiet', 'cadence sweep', 'open loops', 'reply owed', 'who you owe').
    - Extract bold-wrapped or contextually-clear person names from those sections (skip abbreviations, card names, products, org names).
    - For each name found that isn't already in `candidates`, append with `source_type: "microscope-prose-llm"` and `source_kind` matching the microscope kind.
    - Continue to Step 5 classify.

    This fallback exists because the helper's regex patterns are intentionally conservative (avoid false positives); the LLM's contextual judgment catches what the regex misses. The user batch-confirm gate (Step 7) is the final filter against false positives.
```
