# v0.97.1 reconciler-as-cadence — design

> [!info]+ Status
> AUTO-EXECUTE authorized per user instruction "go through with implementing a fix and deploying it all the way through". Subagent-driven flow against main with push gated to S2.

## 0. Origin

v0.97.0 shipped Rail R as a NEW local-launchd surface (`sauce reconcile-cowork --install-launchd`) on the explicit reasoning that the reconciler's work (learned_weights update, heartbeat check, sidecar backfill) was "pure data" and "no LLM needed."

In production observation post-deploy: this created a SECOND automation surface alongside claude.ai's scheduled jobs. User feedback: *"I am utilizing scheduled jobs through claude cowork for this — so terminal command jobs aren't needed."*

The reconciler work IS doable by an LLM via Obsidian MCP only — it's just more MCP calls per fire. Walking 30 days of sidecars + parsing rating callouts + updating frontmatter is all `obsidian_get_file_contents` + `obsidian_put_content`. The Node helper was a simplification, not a necessity.

This patch consolidates automation back to ONE surface: claude.ai's scheduled jobs. The reconciler becomes a new cadence (`reconcile-cowork`) that fires nightly via the same Rail A mechanism as morning-briefing / midday-tripwire / etc.

## 1. Scope

### 1.1 What ships

- **NEW cadence:** `reconcile-cowork` in `scheduled-job-contract.json` (default cron `0 3 * * *` — nightly 03:00 local).
- **NEW orchestrator-instructions file:** `data/orchestrator-instructions/reconcile-cowork.md` — full LLM-driven reconciler step-list (mirror of pure-Node logic in `platform/mechanisms/cowork-reconciler/`, encoded as MCP-tool-driven steps).
- **NEW SKILL.md shim:** `skills/orchestrators/reconcile-cowork/SKILL.md` — 5-line shim per v0.97.0 single-source pattern.
- **DEPRECATE `sauce reconcile-cowork --install-launchd`:** emit deprecation notice + uninstall instructions; flag retired but flag still functional for one-cycle grace.
- **`sauce reconcile-cowork` CLI verb stays** as a manual `--dry-run` / one-off invocation path (useful for dev + local reconciliation of a specific vault).
- **Updated onboarding doc:** `Docs/install/v0.97-onboarding.md` becomes `v0.97.1-onboarding.md` — drops the `--install-launchd` step; single setup is `/cowork sync-scheduled-jobs` which now creates the reconcile-cowork task per vault.

### 1.2 What does NOT ship

- Removing the `cowork-reconciler` mechanism entirely — kept for the manual `sauce reconcile-cowork` CLI path
- Removing the launchd plist template — kept for users who genuinely want the local-cron path (documented as legacy/optional)
- Per-item L2R + memory salience + per-skill SemVer — still parked

## 3. The `reconcile-cowork` cadence

### 3.1 Wrapper template (composed via Rail T)

The wrapper for `reconcile-cowork` is composed the same way as other cadences — substitute static + shared tokens into `orchestrator-instructions/reconcile-cowork.md`, wrap with PRELUDE + DONE. Resulting prompt body ~200-300 lines.

The cron LLM fires at 03:00 (per the per-engagement default_cron), reads the wrapper, executes the step-list against the vault via Obsidian MCP.

### 3.2 Orchestrator-instructions step-list

Steps in `data/orchestrator-instructions/reconcile-cowork.md`:

1. **Pre-flight** — vault-config, user-preferences, date resolution (use TODAY's date; reconciler scans YESTERDAY's atomic notes)
2. **Compute yesterday's dirpath** — `<YYYY>/<MM-Month>/<YYYY-MM-DD>` for yesterday in `{{$timezone}}`
3. **List yesterday's atomic notes** via `obsidian_list_files_in_dir` on `spice/cowork/daily/<yesterday-dirpath>/`
4. **For each `.md` without companion `.cowork.json`** — read the `.md` via `obsidian_get_file_contents`, extract surfaced_kinds from `> [!example]+` callout headers via heuristic kind-inference (calendar/email/chat/messages/finance/projects/threads/github/ado), write a backfilled sidecar via `obsidian_put_content` with `generated_by: <orig-generator> (reconciler-backfill@0.97.1)` and `plan_dispatch.mode: "reconciler-backfill"`
5. **Parse rating callouts** — for each `.md`, locate the `> [!todo]+ Was today useful?` callout via the `<!-- cowork:rating-block schema=1.0.0 cadence=<X> day=<Y> -->` sentinel; extract per-kind `[x]`/`[ ]` ticks
6. **Aggregate observations** — collect (kind, ticked) tuples across all of yesterday's notes
7. **Read user-preferences.md** — `obsidian_get_file_contents`; parse frontmatter; locate or initialize `learned_weights:` block (lazy-init per v0.96.1 if absent)
8. **Compute new weights** — apply the update formula in LLM arithmetic:
   ```
   w_new = w_old * 0.98 + 0.15 * (ticks - 0.5*skips) / (ticks + skips + 5)
   clamp [0.10, 3.00]
   ```
   Update warmup state: graduate kind out of warmup when days_since_first >= 7 AND ticks+skips >= 7
9. **Write `.bak` backup** — read current user-preferences.md → write to `user-preferences.md.bak` via `obsidian_put_content`
10. **Write updated user-preferences.md** — compose new frontmatter with updated `learned_weights`, preserve all other frontmatter keys
11. **Run heartbeat check** — walk last 30 days of `spice/cowork/daily/<date>/*.cowork.json` via repeated `obsidian_get_file_contents`; compute last_fire_at per cadence (warm MB vs cold MB via frontmatter.type); evaluate against freshness windows (36h daily, 192h weekly, 840h monthly, 192h lens_shift)
12. **Append heartbeat warning callout** — if any expected cadence missed its window, append `> [!warning]+ Cron heartbeat anomaly` callout to today's `memory.md` (idempotent: regex-replace prior callout same-day)
13. **Append reconciler-log entry** — read `spice/cowork/context/reconciler-log.md` if exists; prepend new entry with timestamp + per-engagement summary (sidecars backfilled, validated; learned_weights deltas; heartbeat verdict); cap at last 30 entries
14. **Done** — emit Notice with summary counts

### 3.3 Per-engagement vs per-vault firing

Each engagement enabled for cowork gets its own `reconcile-cowork` scheduled task (mirror of how morning-briefing has one task per engagement). Task name: `cowork-reconcile-cowork-<engagement_id>` (e.g. `cowork-reconcile-cowork-accuris`, `cowork-reconcile-cowork-headspace`).

The orchestrator-instructions step-list scopes to ONE engagement (per the `{{$engagement_id}}` substitution). If a vault has multiple engagements, each engagement runs its own reconciler — they don't share state during a fire (engagement scope is intentional per v0.96.1 multi-engagement learned_weights nesting).

### 3.4 Cost considerations

Reconciler fire reads many files:
- Yesterday's atomic notes: ~3-5 files per engagement
- 30-day sidecar walk for heartbeat: up to ~150 files per engagement (5 cadences × 30 days)
- user-preferences.md: 1 read + 1 write
- memory.md: 1 read + 1 write (if heartbeat fires)
- reconciler-log.md: 1 read + 1 write

Total ~50-160 Obsidian MCP calls per fire per engagement. At 2 engagements × 1 fire/day = ~100-320 MCP calls daily for reconciler. Bounded. Not free but reasonable for nightly automation.

### 3.5 Schedule: nightly 03:00 local

`default_cron: "0 3 * * *"`. Same as the launchd plist v0.97.0 schedule. User can hand-tune in claude.ai's UI per their preference — sync preserves cron field (Rail A schedule-preservation invariant).

## 4. Sub-skill (no separate write-run-note)

Unlike morning-briefing / EOD / etc., reconcile-cowork doesn't write an atomic note. The output is structural file mutations (sidecars + user-preferences.md frontmatter + memory.md callouts + reconciler-log.md). No `cowork:write-run-note-reconcile-cowork` sub-skill needed.

Per scheduled-job-contract.json shape:
```json
"reconcile-cowork": {
  "schedule_hint": "03:00 daily",
  "default_cron": "0 3 * * *",
  "frontmatter_type": null,
  "output_path_template": null,
  "orchestrator_skill_name": "cowork:reconcile-cowork",
  "sub_skill_name": null,
  "cadence_tone_hint": "Silent on green; emits warning callouts only when anomalies detected.",
  "includes_microscopes": false,
  "wrapper_template_source": "orchestrator-instructions/reconcile-cowork.md"
}
```

## 5. CLI deprecation posture

`sauce reconcile-cowork --install-launchd` — emits:

```
[DEPRECATED v0.97.1] Local launchd reconciler is deprecated. The reconciler
now runs as a claude.ai scheduled job (cadence: reconcile-cowork). Run
`/cowork sync-scheduled-jobs` from your claude.ai Cowork UI chat to create
the cowork-reconcile-cowork-<engagement_id> scheduled task; it will fire
nightly at 03:00 local (default).

To uninstall any existing launchd job:
  launchctl unload -w ~/Library/LaunchAgents/com.<user>.cowork-reconciler.plist
  rm ~/Library/LaunchAgents/com.<user>.cowork-reconciler.plist

The --install-launchd flag will continue to work for one cycle (v0.97.x) as
a fallback. It will be removed in v0.98.0+.
```

Then proceeds with installLaunchd() — preserving the existing functionality for users mid-migration. Document the deprecation in the result doc + cycle-history.

`sauce reconcile-cowork` (without `--install-launchd`) keeps working unchanged — for manual `--dry-run` / one-off invocation.

## 6. Sync skill update (minimal)

`cowork:sync-scheduled-jobs` is already cadence-agnostic — it iterates `contract.cadences` and composes a wrapper per (cadence × engagement). Adding a new cadence to the contract automatically picks it up.

ONE small update: the sync skill needs to know that reconcile-cowork should fire per-engagement (not per-vault). Currently sync iterates engagements; this is already correct.

## 10. Trade-offs

### 10.1 Accepted

1. **Many MCP calls per fire.** ~50-160 calls per engagement per night. Larger than morning-briefing (~20 calls). Bounded; not free.
2. **LLM arithmetic for weight update.** Slightly less precise than Node's `Math.round` (floating-point edge cases); accepted because LLM precision is fine for {0.10..3.00} range with 3-decimal clamping.
3. **Per-engagement scheduled task** (not per-vault). Means N engagements = N reconciler tasks. Acceptable — matches the existing per-engagement scheduling pattern.
4. **One-cycle grace for `--install-launchd`.** Deprecation notice fires but underlying functionality preserved. Removed entirely in v0.98.0+ (TBD).
5. **`sauce reconcile-cowork` CLI verb (without flag) stays.** Useful for manual/dev/`--dry-run`. Not load-bearing but valuable.

### 10.2 Rejected

1. **Remove `cowork-reconciler` mechanism entirely.** Keeping it for manual `sauce reconcile-cowork` CLI invocation — useful for one-off reconciliation + dry-run.
2. **Remove launchd plist template.** Kept for users who prefer local-cron architecture (documented as legacy/optional in onboarding).
3. **Per-vault scheduled task aggregating all engagements.** Adds complexity — per-engagement is simpler + parallel-safe across engagements.
