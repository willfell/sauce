## Section A — Projects Hub search (`spice/projects/Projects.md`)

### Decision

**Generalize the existing `DocSearch` helper in-place. Do NOT add a new `ProjectsHubSearch` helper class.** Wire `ProjectsHubCards.render` to invoke `customJS.DocSearch.render` internally, the same way `ProjectDocsIndex` and `SectionHub` already do.

### Rationale

DocSearch already implements every piece needed (permanent strip + transient resultsContainer + localStorage state + 150ms debounce + scoped-search button + tag chips). It hardcodes three things that block reuse for projects:

| Hardcode | Today | Generalized |
|---|---|---|
| Entity predicate | `p.type === "doc-note"` (line 29) | `opts.entityFilter(p)` — defaults to existing predicate |
| Tag exclude (universal type tag) | `clean === "doc-note"` (line 180) | `opts.tagExclude: Set` — defaults to `new Set(["doc-note"])` |
| Placeholder text | `"Filter docs by title, tags, or content…"` | `opts.placeholder` — defaults to current |
| Scoped-search query prefix | `path:"${opts.scopePath}"` | unchanged — works for `spice/projects` too |

A second class (`ProjectsHubSearch`) would duplicate ~150 LOC of strip/persist/debounce wiring with zero new behavior. F (standardization) explicitly asks for shared primitives — DocSearch IS the shared primitive; we just unhardcode it.

### Implementation

`platform/blueprints/project/helpers/doc-search.js`:

- `render(dv, opts)` gains optional opts:
  - `entityType: string` — when set, used to build the default `entityFilter` AND added to default `tagExclude` (DRY: same name flows to both). Default: `"doc-note"`.
  - `entityFilter: (page) => boolean` — overrides `p.type === entityType` if caller needs more nuance. Default: derived from `entityType`.
  - `tagExclude: string[]` — additional tag names to exclude from the chip universe beyond the entity-type tag. Default: `[]`.
  - `placeholder: string` — input element's `placeholder=`. Default: `"Filter ${entityType}s by title, tags, or content…"` (humanised).
- Pages query at line 29 becomes:
  ```js
  const allPages = dv.pages(`"${opts.scopePath}"`)
    .where(opts.entityFilter || (p => p.type === (opts.entityType || "doc-note")));
  ```
- `_countTags`: excluded-set is `new Set([opts.entityType || "doc-note", ...(opts.tagExclude || [])])`.
- `matches(page, ctx)` — no change. Already entity-agnostic (operates on file.name + tags).

`platform/blueprints/project/helpers/projects-hub-cards.js`:

- `render(dv)` becomes:
  1. Invoke `customJS.DocSearch.render(dv, { entityType: "project", scopePath: "spice/projects", recursive: true, placeholder: "Filter projects by name or tag…", onChange: ctx => { this._filterCtx = ctx; ctx.resultsContainer.empty(); await this._renderInner(proxyDv); } })`.
  2. The existing chip strips (status / teams / products / group-by selector) + card grid move INTO `_renderInner(dv)`, rendered into `filterCtx.resultsContainer` via a proxyDv (same pattern as ProjectDocsIndex / SectionHub).
  3. The pages chain gains `.where(p => customJS.DocSearch.matches(p, this._filterCtx))` after the status-filter step.
- Net surface: Projects.md gets a text-input + tag-chip strip ABOVE the status/team/product chips. Both filters compose (text+tags AND status+team+product).

### Test surface

- run-helper-cases.js: extend the DocSearch case with a `entityType: "project"` invocation.
- run-helper-cases.js: ProjectsHubCards case asserts the new strip wraps the grid and filterCtx is applied.
- Manual smoke: Projects.md filter strip survives keystrokes (DocSearch v0.105.0 Issue 6 already guarantees this); status chip toggles continue to work alongside the new strip.

### Out of scope

- Promoting DocSearch to a top-level `cards`-style mechanism — premature; one extra consumer doesn't justify a mechanism split.

## Section D — `SectionLabel` shared primitive

### Decision

Ship as a **per-blueprint helper inside the project blueprint** (`platform/blueprints/project/helpers/section-label.js`). Not a cross-blueprint mechanism — cowork and meetings don't currently call `dv.header(3, …)`. Promotion to a mechanism is a future move IF a second blueprint adopts it. YAGNI today.

### API

```js
class SectionLabel {
  /**
   * Render a small, muted, uppercase-ish section label with a hairline divider above.
   *
   * @param dv     Dataview (real or proxyDv shim — anything with .container).
   * @param opts   { text: string, top?: boolean }
   *   text: the label text (escaped, no markdown parsing).
   *   top:  if true, no hairline above; default false (renders an <hr> above).
   *
   * Visual:
   *   <hr style="border-top: 1px solid var(--background-modifier-border); ...">
   *   <div style="font-size: 0.78em; text-transform: uppercase; letter-spacing: 0.05em;
   *               color: var(--text-muted); margin: 6px 0 4px; font-weight: 600;">
   *     {text}
   *   </div>
   */
  render(dv, opts) {
    if (!opts || !opts.text) return;
    const c = dv.container || dv;
    if (!opts.top) {
      const hr = c.createEl("hr");
      hr.style.cssText = "border: none; border-top: 1px solid var(--background-modifier-border); margin: 10px 0 6px 0;";
    }
    const lbl = c.createEl("div");
    lbl.textContent = String(opts.text);
    lbl.style.cssText = "font-size: 0.78em; text-transform: uppercase; letter-spacing: 0.05em; color: var(--text-muted); margin: 0 0 6px 0; font-weight: 600;";
  }
}
```

### Part 2 — Marker cleanup migration

**Change `_migrateDocNote`'s idempotency guard from the visible marker comment to a class-invocation substring.**

Current guard (install.js line 2733): `if (!out.includes("<!-- breadcrumb-v1.17.0 -->"))`.

New guard: `if (!out.includes('class: "Breadcrumb"'))`. The dataviewjs invocation IS the proof the block was injected; the marker is redundant.

The injected block no longer carries the marker line:

```js
const breadcrumbBlock = `\n\`\`\`dataviewjs\nawait dv.view("ranch/views/customjs-guard", { class: "Breadcrumb" });\n\`\`\`\n\n---\n`;
```

**NEW install step: `applyDocNoteBreadcrumbMarkerCleanup`**

Walks every `spice/projects/*/docs/**/*.md` file (via the same listing pattern `applyDocsHubButtonRepair` uses), reads body, and strips:

- The marker line `<!-- breadcrumb-v1.17.0 -->\n` itself.
- The immediately-preceding `\n` if it would leave a blank double-line at the top of the body (collapse `\n<!-- breadcrumb-v1.17.0 -->\n` → `\n`).

Idempotent: if the marker is absent, no-op. Write only when body changed. Stats reported: `cleaned_count` + `untouched_count` + per-file `info` history events under step `doc_note_breadcrumb_marker_cleanup`.

Dispatch wired in install.js after `applyProjectSectionsHubMigration` (which still runs idempotently for any v0.102.0-era vault that hasn't migrated yet) at line ~1108.

#### Why not strip marker inside `_migrateDocNote` itself

`_migrateDocNote` only runs when a project has a doc-note that doesn't have the breadcrumb-block yet — which means `_migrateDocNote` would no-op on already-migrated docs (since they ALL have the marker today). A standalone cleanup step is the cleaner separation: marker stripping is a one-shot cleanup independent of the migration's other responsibilities (frontmatter rewrites, body injection).

## Section F — Standardization agent-guide

### New file: `Docs/agent-guides/project-blueprint-ui.md`

Owner: the project blueprint. Stable surface for future helpers — the non-negotiable conventions that every project-blueprint helper MUST follow. Sections:

1. **Render primitives** (the four canonical helpers used everywhere):
   - `Breadcrumb` — trail of clickable parents, emitted as first block of every project-related note. Reads `cur.type`; supports project/docs-hub/section-hub/doc-note/map/kanban/task-note. Path-based fallback when frontmatter is incomplete.
   - `SectionLabel` — replaces every `dv.header(3, …)` call. Visual: hairline + small uppercase muted label. Helpers own their label; templates don't carry `## ...` H2s anymore.
   - `DocSearch` — entity-agnostic filter strip (text + tag chips + scoped-search button + localStorage + 150ms debounce). Pass `entityType` opt to scope to any blueprint type. Consumed by ProjectDocsIndex, SectionHub, ProjectsHubCards.
   - `EntityCreate` (mechanism, not blueprint helper) — the canonical `+ New X` button. Always rendered ABOVE the cards it would seed; always available even on empty surfaces.

2. **Section ordering convention** (project hub):
   - Nav buttons (Space + Project) → Status widget → Meetings → Workstreams. Status widget renders chip-only with no label (it IS the at-a-glance signal; no need to label it). Subsequent sections each emit their own SectionLabel.

3. **Spacing rules**:
   - No `---` horizontal rules between sections in `Template, Project.md` — SectionLabel emits its own hairline above.
   - No `## H2` headings inside project-related templates — helpers emit SectionLabel instead.
   - Empty helper output: render NOTHING (no info callouts, no placeholder text). Established v0.106.0.1.

4. **Naming convention**:
   - Helper file: `lowercase-kebab.js` under `platform/blueprints/project/helpers/`.
   - Helper class: PascalCase, single noun (`SectionLabel`, `Breadcrumb`, `DocSearch`).
   - Helper destination: `{{scripts_path}}/project/<same-kebab>.js`.

5. **Idempotency / marker conventions**:
   - **Do not use visible HTML comment markers** (`<!-- foo-vX.Y.Z -->`) as idempotency proxies. Use a class-invocation substring or a stable frontmatter-field presence check instead.
   - Marker comments that already shipped (e.g. `<!-- breadcrumb-v1.17.0 -->`) get cleanup migrations in a subsequent cycle.

6. **Card meta-line format**:
   - Lowercase first letter. " · " separator. No emoji.
   - Example: `12 docs · updated 2 hours ago`.
   - When the meta is plural-dependent, branch on count: `${n} doc${n === 1 ? "" : "s"}`.

7. **proxyDv shim pattern**:
   - When a helper renders into a DocSearch resultsContainer, build a `_makeProxyDv(dv, container)` that forwards `container`, `current`, `pages` to the real dv and mints `el / header / paragraph` onto the supplied container. Pattern verbatim from `section-hub.js` lines 195-213 + `project-docs-index.js` lines 196-213.

8. **Pointers**:
   - For the broader cross-blueprint non-negotiables, see [`code-conventions.md`](code-conventions.md).
   - For the installer migration-step pattern (used by S8 here), see the `applyDocsHubButtonRepair` reference impl at `platform/install.js` lines 2077–2130.

## Implementation order (cross-checks)

The 11-stage decomposition above is dependency-correct:

```
S1 (DocSearch params) ─┐
S2 (SectionLabel)     ─┤
                       ├─→ S3 (ProjectsHubCards wiring)     [needs S1]
                       ├─→ S4 (ProjectDocsIndex metadata)   [touches same file as S5]
                       ├─→ S5 (ProjectMeetingsPanel rewrite + SectionHub label adoption) [needs S2]
                       └─→ S6 (Template, Project.md)        [needs S5]
S7 (Breadcrumb extension + templates)
S8 (applyDocNoteBreadcrumbMarkerCleanup)
S9 (agent-guide)
S10 (bumps + dogfood)
S11 (cycle-close artifacts)
```

S4 + S5 both touch `project-docs-index.js` / `section-hub.js` respectively but in different regions; ordering between them is loose. S3 depends on S1's DocSearch opts being live. S6 depends on S5 because ProjectMeetingsPanel must render its own SectionLabel before the template drops `## Meetings`.

## Risks + mitigations

| Risk | Mitigation |
|---|---|
| Kanban-plugin breaks when Project Board.md gets a leading dataviewjs body block | S7 dogfoods Project Board breadcrumb early; if regression observed, drop Breadcrumb from Project Board.md only and document in agent-guide. |
| ProjectMeetingsPanel `_enrichMeeting` body-read happens on every render (slow on large vaults) | Same cost shape as SpaceDailyDashboard already pays; cap is 3 meetings × `app.vault.read` so ≤ 3 reads per project hub open. Acceptable. |
| DocSearch parameterization breaks existing doc-note callers | Defaults preserve existing behavior byte-for-byte; opts are pure-additive. run-helper-cases.js + accuris smoke catch any miss. |
| `applyDocNoteBreadcrumbMarkerCleanup` strips marker but leaves stray blank line | Cleanup regex normalizes whitespace boundary; idempotent re-run safe. Test fixture asserts exact-bytes equivalence after two runs. |
| Mentions / ProjectNotesCards / ProjectReferencedByCards helpers ship dead code | Documented in agent-guide as "deprecated for project page"; explicit sunset earmark for a future cycle once cross-blueprint consumer audit confirms no one needs them. |
| Workshop number collision repeats in a future parallel session | This design doc + cycle-history both stamp v0.109.0 explicitly. Cycle-status.md updated in S11 to show 0.108.0 reserved for finance, 0.109.0 closed by this cycle. |
