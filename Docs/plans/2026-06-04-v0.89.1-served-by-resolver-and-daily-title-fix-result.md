# v0.89.1 — served-by-resolver-and-daily-title-fix — result

**Workstream 1 of the post-v0.89.0 brainstorm handoff bundled with a daily title typed-alias guard.** PATCH cycle — dispatch envelope wiring only, no new install surface (helper-only blueprint additions), no user-microscope edits. Closes the load-bearing v0.89.0 gap where M365 / microscope-routed vaults (accuris) did not get gather-time `[[Person]]` wikilink emission across `gather-from-served-by`-routed kinds (chat / email / calendar / ado / github / finance).

## What landed

- **NEW pure JS helper `resolve-inner-circle-helper.js`** at `platform/blueprints/cowork/helpers/resolve-inner-circle-helper.js` exporting `composeInnerCircleAllowlist(resolverOutputs)`. Pure shape composer — no MCP calls, no I/O, idempotent on null/empty input. Takes an array of `cowork:resolve-person` outputs (one per `inner_circle_people` name, with the original input threaded as the `_input` field), returns `{ resolved: [{name, person_link, person_basename, aliases_by_type, matched_via, collision_warning}], unresolved: [<input>, …], phone_filter_list: [<E.164>, …] }`. Drops malformed entries silently; phone_filter_list deduplicates and preserves first-occurrence order. Hybrid pre-resolve + soft prompt architecture — orchestrator drives the per-name MCP loop; helper unifies the shape into a deterministic allowlist for downstream consumption. Materializes via the cowork manifest's `{{module_directory}}/helpers/` dest pattern (fixed at S3.1 — the initial S3 draft used a stale `{{helpers_dir}}` token that does not exist in the install runtime variable table).

- **`gather-from-served-by` envelope wiring** — `platform/blueprints/cowork/skills/skills/gather-from-served-by/SKILL.md` gains two new inputs (`inner_circle_resolved: list[{name, person_link, person_basename, aliases_by_type, matched_via, collision_warning}]`, `engagement_id: string`) and one new output (`inner_circle_resolved_count: integer`). A new Step 3 "Known people in scope" dispatch contract section injects the allowlist verbatim into the dispatch contract — bullets of `**<name>** → `[[<person_basename>]]` (aliases by type: phone=<JSON>, email=<JSON>, handle=<JSON>; collision: <basename | basename>)` — and a soft prompt instructs the executing agent to call `cowork:resolve-person { input, prefer_type, engagement_id }` for ambient names not in the allowlist, then emit `**[[<person_basename>]]**` on `resolved: true` / plaintext `**<observed>**` on `resolved: false`. The microscope `## Output shape` ALWAYS-WIN precedence line stays in place — FLN-v89-9 (microscope authoring contract update) intentionally stays queued; this PATCH only wires the envelope. When `inner_circle_resolved` is absent / empty, the preamble + bullet-list are omitted and the ambient soft-prompt paragraph still applies. `gather-from-served-by-helper.js` accepts + shape-validates the new inputs (entries missing `name: string` or `person_link: string` are dropped silently), echoes `inner_circle_resolved_count` on the success return shape.

- **5 atomic-note orchestrators wired** — `morning-briefing` refactors its existing v0.89.0 Step 2 inline phone-list union to use the new helper; `midday-tripwire`, `eod-review`, `weekly-review`, `monthly-review` each gain a NEW pre-resolution step before the kind-priority gather loop. Each orchestrator reads `engagement.inner_circle_people: string[]`, loops `cowork:resolve-person { input, prefer_type: "name", engagement_id }` per name with `_input` threading, invokes `composeInnerCircleAllowlist(resolverOutputs)`, threads `allowlist.resolved` as `inner_circle_resolved` + `engagement_id` into every `gather-from-served-by` invocation in the kind loop, and emits `Notice cowork: inner-circle name "<name>" unresolved` + `warnings: ["inner_circle_unresolved:<name>"]` (v0.85.0 plumbing) for each unresolved name. Morning-briefing additionally passes `allowlist.phone_filter_list.join(",")` to `gather-imessage`'s existing E.164 `inner_circle` input — the v0.89.0 contract preserved verbatim. The `write-run-note-morning-briefing` Step 2a inner-circle phone-list derivation block was converted at S2.1 to a documentation pointer redirecting agents to the orchestrator-side pre-resolution step (semantic overlap; the orchestrator now owns the loop). S3.1 also added an `orchestrator require-path` clarification — the `require("./resolve-inner-circle-helper.js")` snippet in each orchestrator's prose is illustrative; in production the helper is resolved via the materialized `{{module_directory}}/helpers/` path.

- **SpaceDailyDashboard `_resolveTitle` typed-alias guard** at `platform/blueprints/daily/helpers/space-daily-dashboard.js`. The pre-fix `aliases[0]` branch unconditionally stringified the first alias via `String(a0).trim()`, producing `"[object Object]"` when a person note had a people@0.6.0 typed alias (`{type: "name", value: "Foo"}`) — the daily-activity panel then rendered that literal string as the row title for newly-created person notes. The fix: a `_safe(v)` helper at the top of the function that returns `""` when the value would stringify to `"[object Object]"`, lets each branch short-circuit on junk and fall through to the next; the `aliases[0]` branch detects the typed-alias shape (`a0 && typeof a0 === "object" && typeof a0.value === "string"`) and uses `a0.value`. Bare-string alias back-compat preserved (`"LegacyAlias"` still resolves). Defensive `[object Object]` fallthrough catches Dataview Link wrappers and any other object leaks across `p.name` / `p.title` / `p.file.outline` paths. v0.13.5 JSDoc entry documents the rationale.

- **Version bumps** — workshop `0.89.0 → 0.89.1`, cowork `0.27.0 → 0.27.1` (PATCH — pure-additive helper + SKILL.md prose extensions; no new install surface — `claude_surface[]` unchanged), daily `0.13.4 → 0.13.5` (PATCH — `_resolveTitle` typed-alias guard). `package.json`, `platform/manifest.json` catalogue pins, `ranch/platform-subscription.json` pin bumps, V0750-VERSION cowork pin bumped `0.27.0 → 0.27.1`. Mechanism count unchanged at 17.

- **Cowork manifest dest pattern fix** (S3.1 fixup) — the initial S3 draft of the cowork manifest's new `files[]` entry for `resolve-inner-circle-helper.js` used `dest: "{{helpers_dir}}/cowork/resolve-inner-circle-helper.js"`. The `{{helpers_dir}}` token is not defined in the install runtime's variable table — the canonical pattern is `{{module_directory}}/helpers/` (matching the sibling `gather-from-served-by-helper.js` entry). Fixed at `0f95a1e` with `"tag": "platform"` annotation. Surfaced a NEW FLN candidate (FLN-v891-1, see below) — no preflight check rejects undefined substitution tokens in `files[].dest`.

## Why

**Origin.** Workstream 1 of the post-v0.89.0 brainstorm handoff (`Docs/prompts/2026-06-04-post-v0.89.0-served-by-and-discovery-brainstorm-handoff.md`); /remote-control session 2026-06-04 (`people-cohesion-3`). User framing: "Workstream 1 (v0.89.1 PATCH): wire `cowork:resolve-person` into `gather-from-served-by` so M365 / microscope-routed vaults actually get gather-time wikilink emission."

v0.89.0 shipped a load-bearing wikilink-emission convention for the three direct gather skills (iMessage / Gmail / Calendar) but left `gather-from-served-by` untouched. The accuris-sauce vault routes ALL its kinds (chat / email / calendar / ado / github / finance) through `gather-from-served-by` because they're behind the M365 connector + user-authored microscopes — so accuris atomic notes accumulated zero `[[Person]]` backlinks despite v0.89.0's `wikilink_people` hard rule being injected verbatim into the voice contract. The voice rule is soft; without an in-dispatch instruction to call the resolver mid-emission, the executing agent emitted `**Stefan de Pagter**` (plaintext bold) instead of `**[[Stefan de Pagter]]**`. **FLN-v89-6 closure** removes that gap: orchestrator pre-resolves the inner-circle deterministically, dispatch contract carries the allowlist verbatim, and a soft prompt instructs ambient resolver calls for any unrecognized name. Forward from this deploy, accuris atomic notes accumulate the same wikilink density that headspace and personal already enjoyed at v0.89.0.

**Bundled daily fix.** Added at user request during the brainstorm clarifying-question pass. SpaceDailyDashboard `_resolveTitle` was rendering newly-created person notes as `[object Object]` in daily-activity rows whenever `aliases[0]` was a v0.6.0 typed-object (`{type, value}`). Falls in scope because (a) it touches the same release surface (daily PATCH bump), (b) it's co-located with the people-cohesion arc (v0.6.0 typed aliases are the trigger), (c) it's a pure defensive fix with no install-surface change, and (d) it's easier to ship in the same cycle than separately.
