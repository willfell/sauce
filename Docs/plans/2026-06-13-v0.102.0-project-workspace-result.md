## Lessons (cycle-distinct)

### 1. Workshop manifest catalogue drifts from per-mechanism manifests — self-install catches it; preflight doesn't

`platform/manifest.json` carries a `mechanisms[]` + `blueprints[]` catalogue with names + versions. This catalogue is INDEPENDENT of the per-mechanism/per-blueprint `manifest.json` files. At S5, the per-mechanism manifests were bumped (entity-create 0.5.0, project 1.16.0, meetings 0.8.0, platform-claude 0.1.3) and `ranch/platform-subscription.json` was lockstep-swept — but the workshop's own catalogue in `platform/manifest.json` was NOT updated. The S6 workshop self-install ran first and bombed with skip notices ("subscription pins X@A.B.C but workshop catalogue has D.E.F"), rejecting the entire install. Fix landed at `ed48e93` (S6 catalogue sweep) before the dogfood materialization commit. **Lesson:** add a "catalogue cross-check" line to the S5 version-bump checklist — every per-mechanism/per-blueprint manifest bump REQUIRES a matching catalogue-row bump in `platform/manifest.json`. Codified as landmine #24.

### 2. `slugify` is NOT a pipe; it is a derive primitive only

The design Section 3 named the doc-note folder pattern as `docs/{{prompts.section|slugify}}/` (Jinja-style pipe). EntityCreate's substitution layer treats `slugify` as a derive primitive (a named transform applied during `_deriveSubstitution`), not as a `|`-piped Jinja filter. Caught at plan-time pre-empt + verified before authoring the manifest entry; the manifest actually uses the existing derive-key convention. **Lesson:** plan-time pre-empt prevented a S2 round-trip; verify-before-design on EntityCreate's substitution surface paid off (v0.94.0 lesson reinforcement — verify NAMED behavior + LOADING context before asserting at design layer).

### 3. `{{this.project_slug}}` is NOT in the EntityCreate substitution catalogue

ProjectMeetingsPanel's `+ New meeting` button needs to pass the current project's basename as the `project` preset. The instinct was `{{this.project_slug}}` (mirror of common templating shorthand), but EntityCreate's substitution catalogue at render time is `{{current_file.frontmatter.*}}` + `{{prompts.*}}` only — no `this` namespace. Verified by reading `entity-create.js` before authoring the helper. **Lesson:** when wiring presetPrompts from a render-time helper, the source token must come from the substitution catalogue documented in EntityCreate's schema; reach for `{{current_file.frontmatter.<field>}}` first.

### 4. Consumer regression is POST-release per `build-test-verify.md` — plan should not list it as a pre-tag gate

The plan listed consumer regression (re-running install on accuris-sauce + headspace-sauce) as a pre-tag gate. `Docs/agent-guides/build-test-verify.md` is explicit: `ranch/platform-config.json:workshop_relative_path` in each consumer points at the brew-installed sauce, NOT the dev repo, so pre-release consumer dogfood literally cannot reach the dev code. Consumer regression is run AFTER `brew upgrade sauce` lands. **Lesson:** post-release consumer dogfood is the canonical flow; pre-release dogfood is workshop-self-install only. Plan templates going forward should not name consumer regression as a pre-tag gate.

### 5. Lockstep version-pin updates in tests are an established pattern, not scope creep

The cycle had 4 distinct lockstep version-pin events across 5 commits (S3.1 project pin, S3.2 meetings pin, S5 workshop pin sweep, S6 catalogue sweep). Cases swept: DOC-2, R-WIKI-1, DOCS-INT-2, EC-2, FA2-MEETINGS-1, HC-V0880-MEETINGS-D, DHB-1, several VERSION-* cases. Each event touched 2-8 cases; net +116 sub-asserts is dominated by the NEW HC cases (EC + PDS + PMP + PROJ + MEET + PSM + VDP + CLAUDE-MD-RES), not the lockstep sweeps. **Lesson:** the per-cycle VERSION-pin sweep IS the cycle close — it's part of the contract, not an in-flight tax. The S5 checklist already covers this; reinforced here.
