**Status:** design — pending plan + execution.
**Date:** 2026-05-29.
**Cycle topic slug:** `cowork-microscope`.
**Predecessor:** v0.78.1 (cowork-consumption-fix), workshop `0.78.1` closed 2026-05-29, HEAD `651a160`.
**Trigger:** The headspace `cowork:morning-briefing` cron fired 2026-05-29 (note at `headspace-sauce/spice/cowork/daily/2026/05-May/2026-05-29/morning-briefing.md`). Prefs-mode dispatch + voice contract worked, but four gaps surfaced: (1) emojis appeared in the body — section-title glyphs (💬/💰/📅/📧), table glyphs (🔒/✅/🚨/💵), and a narrative ❤️ — because the user's "no emojis" preference lived only in Claude-memory, not in `user-preferences.md`; (2) every admonition rendered the same color in Obsidian; (3) the finance section, despite a `notes` block saying "monitor ALL spend, surface everything," was no deeper than the default; (4) the chat section was 4 bullets despite a privacy-limited MCP surface. The common thread behind (3)+(4): the per-MCP free-text `notes` block is too shallow a contract to drive a deep, grounded briefing. v0.79.0 introduces **microscope prompts** — per-kind, user-authored, strictly-user-owned deep gather contracts — plus the schema + plumbing to make "no emojis" real, plus a confirmed styling fix for the admonition colors.

## 2. Architecture findings (from exploration)

- **The microscope injection point already exists.** `cowork:gather-from-served-by` injects `what_matters` (mapped from the per-MCP `notes` block) verbatim into the gathering agent's dispatch contract (its Step 3). On headspace, finance/chat/email are all `override_classified` → they already route through this skill. So "microscope" = a richer, separate, strictly-user-owned `what_matters`.
- **Canonical gathers take no free-text contract.** `gather-finance-yesterday` is hardcoded to Brex `mcp__claude_ai_Brex__*`; `gather-calendar`/`gather-gmail`/`gather-imessage` are likewise vendor-locked with their own templated output and accept no free-text. Microscope therefore routes a kind through `gather-from-served-by` whenever a microscope contract exists for it (§3.2).
- **Emoji suppression is bigger than narrative.** v0.78.0's voice contract is *explicitly walled off* from `[!example]+` callouts (their content comes from gather sub-skills). A `no_emojis` field routed only through the voice contract would kill the narrative ❤️ but leave the 💬/💰 titles and 🔒/✅ table glyphs — which is where most of the emoji actually came from, since headspace finance/chat are served-by-path. Suppression must reach the gather dispatch + the write-run-note skeleton too (§4).
- **Admonition color is styling-side, not wrong-theme.** Headspace runs the vendored `Baseline` theme with Style Settings enabled. Baseline renders callouts *monochrome by default* — a single generic `--callout-color` (no per-type `--callout-info`/`-warning`/`-tip`/`-example` tokens; a "Monochrome" SS option exists) — and sauce's `style-settings-default.json` sets no callout key, so every callout inherits the one accent. Bounded fix in the `styling` mechanism (§5).
- **The MCP-depth audit validates the gap-finding premise.** Two *different* resolution paths, both of which `edit-microscope` should surface live: iMessage's `Read_and_Send_iMessages` already exposes `search_contacts` (number→name gap closeable inside the gather); the headspace `whatsapp` MCP is privacy-capped (status + recent-contacts only) so its ceiling is the MCP, not the contract — a richer server, `lharries/whatsapp-mcp` (whatsmeow-backed: `list_chats`/`list_messages`/`get_message_context`/`search`/`send`), exists (§6).

## 3. Workstream A — microscope prompts

### 3.1 The artifact

`spice/cowork/prompts/per-mcp/<kind>/microscope.md` — a SKILL.md-shaped contract file:

- **USER-owned and never overwritten.** It is NOT in cowork's `files[]`; it is created lazily by `cowork:edit-microscope` (the same preservation posture as `bootstrap-vault` seeding `vault-config.md`). `sauce update` / `sauce reinstall` therefore never touch it by construction.
- **Read-and-followed, not invoked.** It is a contract the gather reads in full and follows — NOT a registered Claude Code skill (the `.claude/skills/cowork/**` tree is STOCK and gets overwritten). Same authoring feel as a sub-skill; consumed by reading.
- **A directory, not a flat file**, to leave room for sibling files as the user iterates (e.g., `contacts-map.md` for the number→name gap, future `samples/`).

Internal structure (free-form but conventionally sectioned):

```markdown
## What matters
<the deep, ranked priorities for this kind>

## Tools & how to use them
<which mcp__<served_by>__* tools to call, in what order, how to combine —
 e.g. "resolve sender numbers to names via search_contacts BEFORE summarizing">

## Gaps & handling
<known MCP limitations + how to handle them — e.g. "WhatsApp MCP can't read
 message bodies; surface status only and note the ceiling">

## Output shape
<how the user wants the callout grounded/structured — the "brain map">
```

### 3.2 Consumption routing (orchestrator dispatch)

In each of the 5 atomic-note orchestrators' dispatch planning (the v0.78.0 step 3c), add ONE rule **before** the existing custom/override/canonical branches:

> **If `spice/cowork/prompts/per-mcp/<kind_name>/microscope.md` exists** →
> `dispatch_plan.push({ kind_name, action: "gather_from_served_by", served_by: <ns>, what_matters: <microscope body>, baseline_notes: <notes block>, kind_title: <title>, microscope: true })`

Consequence: **when a microscope exists, the kind always flows through `gather-from-served-by`** regardless of canonical-vs-override. The generic gather supplies the vendor knowledge a canonical skill would otherwise hardcode, and the microscope body *is* the deep contract. When no microscope exists, dispatch is exactly v0.78.0 (canonical stays canonical, override stays override). Requires the kind's `mcps` block to carry `served_by` (always true post-v0.77.0 capture).

### 3.3 The merge

`gather-from-served-by`'s `what_matters` becomes the **microscope body (primary)**, with the existing structured `notes` block appended as a `**Baseline preferences:**` trailer so nothing the user already captured is dropped. On first authoring, `edit-microscope` **seeds** `microscope.md` from the current `notes` so there's continuity from the day-one shallow contract to the deep one.

`gather-from-served-by` itself needs no structural change for WS-A — it already injects `what_matters` verbatim. (It gains a `hard_rules[]` input from WS-B; see §4.)

### 3.4 The capture skill — `cowork:edit-microscope`

A STOCK interactive orchestrator-style skill (lives at `platform/blueprints/cowork/skills/orchestrators/edit-microscope/SKILL.md`), reachable via `/cowork microscope <kind>`; `context-builder` hands off to it. **It is a discovery loop, not a form.** Steps:

1. **Resolve kind** — from the `<kind>` arg, or ask (list kinds from `user-preferences.md` `priorities`/`mcps`). Read that kind's `served_by` + existing `notes`/answers.
2. **Read existing `microscope.md`** if present — the *iteration anchor*; each re-run deepens the current contract rather than starting over.
3. **Enumerate `served_by` tools** — filter the agent's tool list to `mcp__<served_by>__*`; present capabilities to the user.
4. **Consent-gated live sample + gap-finding** — ask *"want me to pull a small sample so my questions are grounded in your real data?"* On consent, call cheap read tools, inspect real field shapes, and surface **gaps**, each with a resolution path:
   - *Resolvable-in-gather* → e.g. "I'll instruct the gather to resolve numbers→names via `search_contacts`."
   - *MCP-ceiling* → e.g. "this WhatsApp MCP can't read message content; consider `lharries/whatsapp-mcp`."
   - *User-supplied* → maintain a sibling file (e.g. `contacts-map.md`).
5. **Brainstorm preferences, one question at a time** — informed by tools + sample + gaps: what to surface, how to group, what to flag/ignore, and how to ground it into a usable "brain map."
6. **Compose/refine `microscope.md`** — seeded from `notes` on first run; structured per §3.1. Idempotent + iterative: re-runs read the existing file and append/refine, deepening over time.
7. **(Optional) update `user-preferences.md` `notes`** to a short pointer noting the deep contract lives in `per-mcp/<kind>/microscope.md`.

Carries a `dry_run_answers` input for harness testing (same pattern as `context-builder` and `gather-from-served-by`): pre-supplied `available_tools`, sample tool outputs, and user answers, so HC cases exercise kind-resolution / gap-detection / composition without live MCP calls.

**Posture note:** the skill is run interactively *by the user* against *their own* vault data, but live tool calls remain consent-gated per this repo's ask-before-acting culture (`Docs/agent-guides/asking-before-acting.md`).

## 4. Workstream B — `personality.hard_rules[]` + `no_emojis`

### 4.1 Schema (strict-additive to the `personality` block)

```yaml
personality:
  # ...existing fields unchanged (vibe / vibe_notes / formality / pep_talk / pep_talk_style / length)...
  no_emojis: true                       # convenience boolean (default false)
  hard_rules:                           # verbatim, do-not-interpret (default [])
    - 'never use the word "leverage"'
```

### 4.2 Effective-rules composition

`read-user-preferences` parses both with defaults (`no_emojis: false`, `hard_rules: []`) and builds one ordered `effective_hard_rules[]`:

```
effective_hard_rules = hard_rules
  + (no_emojis ? [CANONICAL_NO_EMOJI_RULE] : [])
```

where `CANONICAL_NO_EMOJI_RULE` is a fixed string (test fixtures match it verbatim):

> `Do not use any emoji or pictographic characters anywhere in the output — not in section/callout titles, not in inline prose, not in table cells.`

### 4.3 Propagation to all three surfaces

1. **Voice contract prefix** (existing v0.78.0 step 13b): append a `Hard rules (non-negotiable, apply verbatim):` block listing `effective_hard_rules`. Reaches narrative sections (the ❤️).
2. **`gather-from-served-by` dispatch**: new input `hard_rules: list[string]`, injected into the Step 3 dispatch contract under `**Hard rules (bind this callout's TITLE and BODY):**`. Reaches `[!example]+` titles + table glyphs — the dominant emoji source on served-by-path kinds.
3. **`write-run-note` skeleton** (all 5): one line in the adaptive-skeleton section — *"When the orchestrator passes `hard_rules[]`, they bind all agent-authored text, including `[!example]+` / `[!info]` / `[!tip]` titles and bodies."*

Canonical `[!warning]` callout strings are contract-fixed (and already emoji-free) and the voice contract is forbidden from touching them — `hard_rules` likewise do not rewrite them. STOCK gather templates (`gather-finance-yesterday` et al.) are already emoji-free per the existing "bare callout header" convention, so they need no change.

### 4.4 Why a lone boolean wouldn't work

v0.78.0's voice contract is explicitly walled off from `[!example]+` callouts, so emoji suppression *must* reach the gather dispatch — which is why this rides the general `hard_rules[]` plumbing rather than a narrow narrative-only flag. The general list is also a pre-existing queued candidate (cycle-status In-flight queue) and lets power users add arbitrary verbatim rules.

## 5. Workstream C — admonition color (`styling` MINOR 0.1.2 → 0.2.0)

**Root cause (confirmed):** Baseline renders callouts monochrome (single `--callout-color`, no per-type tokens) and sauce's `style-settings-default.json` sets no callout key, so info/warning/tip/example all inherit the one accent color.

**Fix:** ship a vendored snippet `sauce-callouts.css` that defines per-type `--callout-color` for both schemes (`rose-pine-light` light / `melange-dark` dark) — distinct, palette-harmonized hues for at least info / warning / tip / example / note — and add it to the `styling` manifest's `appearance.enabledCssSnippets` + vendored `files`/asset list.

**Why snippet over a Style-Settings key:** a snippet does not depend on the vendored theme's internal SS key names, which can drift when the theme is re-vendored. The snippet is theme-version-robust.

**Verification:** HC asserts the snippet is vendored AND listed in `appearance.enabledCssSnippets`. Because color differentiation is a *visual* property a unit test cannot fully confirm, **implementation MUST eyeball the rendered callouts in Obsidian** (per the workshop's "verify UI in the app" discipline) before the cycle closes.

## 6. Workstream D — MCP-depth audit (doc-only)

Recorded as recommendations; no sauce code change. Both are baked into `edit-microscope`'s gap-finding examples (§3.4):

- **iMessage — no swap.** `Read_and_Send_iMessages` exposes `read_imessages`, `search_contacts`, `get_unread_imessages`. The number→name gap ("messages but just numbers") is closeable *inside the gather* by instructing it to resolve senders via `search_contacts` before summarizing. WS-A's microscope contract carries that instruction.
- **WhatsApp — recommend evaluating a swap.** The headspace `whatsapp` MCP is privacy-capped (`check-whatsapp-status`, `list-recent-contacts` only); no prompt extracts content it does not expose, so its depth ceiling is the MCP. `lharries/whatsapp-mcp` (whatsmeow-backed local SQLite bridge) exposes `list_chats` / `get_contact_chats` / `get_chat` / `get_message_context` / `get_last_interaction` (+ message search/send per its README) — message-level depth. This is a user-side connector decision surfaced live by `edit-microscope`.

## 8. Failure-mode matrix

| Failure | Detected at | Response |
|---|---|---|
| `per-mcp/<kind>/microscope.md` absent | dispatch 3c | No microscope routing rule fires → behavior is exactly v0.78.0 for that kind |
| microscope file present but kind not in `priorities[]` | dispatch 3c | Not dispatched (priorities still gate ordering); file is inert until the kind is prioritized |
| microscope present but `served_by` unreachable | dispatch 3c / gather | Existing `served_by_unreachable` warning callout (v0.78.0 path) |
| `edit-microscope` invoked for an unclassified kind | step 1 | Skill prompts the user to run `/cowork preferences` first; does not write a file |
| user declines the live sample | step 4 | Skill proceeds enumerate-only (tool names + descriptions) — degraded but functional |
| `no_emojis: true` but a gather still emits an emoji | gather | Best-effort: `hard_rules` bind the dispatch; HC emoji-scan guards the composed-body contract; no hard post-processor in v0.79.0 (carry-forward §11) |
| `hard_rules`/`no_emojis` absent | read-user-preferences | Defaults (`[]` / `false`); voice contract + dispatch unchanged from v0.78.0 |
| `sauce-callouts.css` snippet present but Style Settings plugin absent | install | `styling` helpers already no-op when prereqs absent (v0.1.1 CF-1); snippet ships but theme falls back gracefully |

**Legacy preservation:** a vault with no `per-mcp/` dir, no `hard_rules`/`no_emojis`, and the prior `styling` config MUST produce a v0.79.0 briefing that diffs byte-clean against v0.78.x (modulo intentional new fields). Enforced by the existing legacy-fallback HC cases + a new no-microscope dispatch case.

## 11. Full vision + carry-forward (zero-context-gap handoff)

v0.79.0 ships a complete vertical slice: the per-kind microscope artifact, the MCP-aware iterative gap-finding capture skill, `hard_rules`/`no_emojis`, and the callout-color fix. The remaining scope is sequenced, not dropped — a follow-up cycle/chat can pick these up from this list:

- **`contacts-map.md` sibling-file convention** — format + gather-consumption for user-supplied number→name (and other identity) maps in `per-mcp/<kind>/`.
- **WhatsApp MCP-swap follow-through** — once a user adopts `lharries/whatsapp-mcp`, capture a deep WhatsApp microscope (message-level).
- **`samples/` sibling dir** — cached example outputs per kind, so `edit-microscope` can show "last time it looked like this."
- **Per-kind microscope versioning / changelog** — track how a contract deepened across iterations.
- **Hard-rule post-processor** — a mechanical emoji-strip / word-budget pass if the prompt-level `hard_rules` prove insufficient in practice (v0.79.0 is prompt-level only).
- **Promote frequent custom kinds + expanded known-kinds catalog** (drive / code-platform / project-tracker / monitoring) — already queued; microscope makes custom kinds first-class enough to defer this further.
- **Cross-vault `inherits_from`** for microscope contracts — share deep contracts across a user's vaults (queued alongside preferences inheritance).
- **Canonical-gather microscope parity** — currently a microscope forces served-by routing (covers all kinds). If a user wants a canonical skill's polished tables *plus* a microscope, design a hybrid; deferred until requested.
