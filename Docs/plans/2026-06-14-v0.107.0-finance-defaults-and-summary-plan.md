# v0.107.0 Finance Defaults + Groups + Budget Summary — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development.

**Goal:** Auto-populate monthly budgets and paychecks from per-vault defaults files; add user-defined groups + sub-totals to budgets; render a three-band Budget Summary at the top of every Budget note. End-to-end relief from the data-entry pain.

**Architecture:** ONE additive `seed_from_defaults` schema field on the entity-create mechanism. TWO new defaults notes per vault (`Budget Defaults.md`, `Paycheck Defaults.md`) scaffolded create-if-absent. THREE new CustomJS classes (BudgetDefaultsEditor, PaycheckDefaultsEditor, BudgetSummary). Existing BudgetCategoriesEditor + PaycheckExpensesEditor extended. Append-only migration on existing budgets backfills `group: "Unassigned"` per category.

**Tech Stack:** CustomJS, Dataview, Obsidian (`processFrontMatter`, `metadataCache`, `<datalist>`, `<details>`), JS installer (Node), platform-test harness.

**Spec:** `Docs/plans/2026-06-14-v0.105.0-finance-defaults-and-summary-design.md` (status APPROVED; rebased to v0.107.0).

**House conventions:**
- RED before GREEN; static-string regex asserts in `platform/test/run-helper-cases.js`.
- **No Claude commit trailer** (per `Docs/agent-guides/build-test-verify.md` release rule).
- No version bumps before S5.
- Data-preservation is non-negotiable — pre-migration `.sauce-backup` snapshot + atomic `processFrontMatter` writes + per-file failure-loud (per design Section 6 addendum).

  - Only inject if `frontmatter[destKey]` is empty/missing (template wins).
  - Inject each `seed_from_defaults.carry_arrays[k]` from defaults frontmatter same way.
- Call `_resolveSeedFromDefaults(button, frontmatter)` between the existing prompt-substitution step and the existing write call. Recorded in S0 verification.

## Stage S2 — Installer migration block

### Task 3: `applyFinanceMigrations` orchestrator + two steps

**Files:**
- Modify: `platform/install.js` (or installer file located at S0 step 3)
- Modify: `platform/test/run-helper-cases.js`

Implement per design Section 6 — two functions wrapped in an `applyFinanceMigrations(vault)` orchestrator:

**(a) `applyFinanceDefaultsScaffolding(vault)`:**
- Target paths: `<vault>/spice/finance/Budget Defaults.md` + `<vault>/spice/finance/Paycheck Defaults.md`.
- For each, if file missing: write content from `platform/blueprints/finance/content/Budget Defaults.md` / `Paycheck Defaults.md` (created at S5). Substitute `{{install_time}}` token to ISO now.
- If file exists: skip (Notice: `"Budget Defaults.md exists; preserving"`).
- Logs `[finance] defaults scaffolded: N created, M preserved`.

**(b) `applyFinanceCategoriesGroupBackfill(vault)`:**
- Pre-write snapshot: copy every `<vault>/spice/finance/budgets/**/Budget-*.md` to `<vault>/.sauce-backup/<ISO-timestamp>/spice/finance/budgets/<YYYY-MM>/Budget-<YYYY-MM>.md`. Use Node `fs.copyFileSync`. Use the same `<ISO-timestamp>` for the whole install run.
- For each Budget-*.md:
  - Read frontmatter via the existing installer YAML parser (the same one used by `_migrateDocNote`).
  - If `frontmatter.groups` missing → set `frontmatter.groups = []`.
  - For each `cat` in `frontmatter.categories ?? []`: if `cat.group` missing → `cat.group = "Unassigned"`.
  - If no changes needed → skip the file (no write).
  - Else write back via the installer's frontmatter-writing primitive (same one v0.103.0 uses for `_migrateDocNote`).
  - Per-file try/catch: on error, Notice + console log, continue.
- Logs `[finance] backfill: N budgets touched, M categories backfilled to "Unassigned", 0 modified beyond add`.

**Wire-in:** call `applyFinanceMigrations(vault)` from the main install loop after `applyProjectSectionsHubMigration` (or wherever blueprint-migrations live). Make sure it runs AFTER `applyFinanceDefaultsScaffolding` (in case backfill ever needs a defaults read in the future — though current scope doesn't require it).

### Task 8: `BudgetSummary` widget

**Files:**
- Create: `platform/blueprints/finance/helpers/budget-summary.js`
- Modify: `platform/test/run-helper-cases.js`

Implement per design Section 5 — three bands at the top of every Budget note:

- Band 1: PLANNED / ACTUAL / VARIANCE with $ and %.
- Band 2: Month-progress + spent-progress bars + pace indicator (⚠/✓/↓).
- Band 3: Per-group mini-cards (one per `page.groups[]` entry) with planned→actual + variance %.
- Status-aware: hides Band 2 for Planning (future month); replaces pace with "Closed: spent X of planned Y" for Done (past month).
- Pace thresholds: `pace > +10` → red ⚠; `-10 ≤ pace ≤ +10` → green ✓; `pace < -10` → muted ↓.
- Per-group card color: matches `BudgetCategoriesEditor` thresholds (green ≤ planned; amber ≤ 110%; red otherwise).
- Edge cases: empty categories → "Empty budget" message; malformed month → skip Band 2; planned=0 group → "—".
- Read-only — NEVER writes frontmatter.
- Embed-deduped.
