## What shipped

### Workstream A — Body-shape enforcement

Six `write-run-note-*` skills grow three new sections each:

- **`## Title composition`** — deterministic title formula using engagement_id + cadence + date (e.g., `accuris — Morning Briefing — 2026-05-22`). Title is required frontmatter (`title:`) and must match the formula exactly.
- **`## Adaptive body skeleton`** — five structural markers (`summary:`, `> [!info]- Synopsis`, `> [!example]+` section blocks, `> [!warning]` when a gather sub-skill reports unavailable, `> [!tip]` close). The skeleton adapts to cadence: morning-briefing has 4 example blocks; eod-review has 3; weekly-review has 2 (recap + forward-look); monthly-review has 2 (retrospective + planning).
- **`## Pre-write self-check`** — five-item checklist gated BEFORE the Write tool call. On any miss the skill returns `failed:contract-violation:<field>` and halts (no partial file written). The orchestrators (`morning-briefing`, `eod-review`, `weekly-review`, `monthly-review`) grow a handler for `failed:contract-violation:*` return status and a bulletproof empty-prompt branch that emits a skeleton-compliant stub rather than a blank note.

`cowork/manifest.json` gains `title: required` on all 6 atomic-note rule_fragments (morning-briefing, midday-tripwire, eod-review, finance, weekly-review, monthly-review). The midday-tripwire severity pattern widens from `^(yellow|red)$` to `^(warn|alert)$` in lockstep with Workstream B.

### Workstream B — Tripwire-aspects model

Three engagement-type JSON files grow `tripwire_aspects[]`:
- `personal.json`: `["cc_drift"]`
- `w2-fte.json`: `["calendar_drift", "queue_growth"]`; `supported_cadences` widens to include `"midday"`
- `consulting.json`: `["cc_drift", "calendar_drift", "queue_growth"]`; `supported_cadences` widens to include `"midday"`

The `cowork:midday-tripwire` orchestrator rewrites its preflight gate from finance-only (`engagement_type === "personal"`) to `tripwire_aspects.length > 0`, enabling it to fire for any engagement with at least one aspect. Per-aspect gather/decide branches fan out via the aspect list; severity uses the new `warn|alert` vocabulary throughout.

`cowork:gather-calendar` gains a `drift-check` mode: called when `tripwire_aspects` includes `calendar_drift`, returns a structured summary of meetings changed/cancelled/added within a rolling 48-hour window.

`cowork:gather-projects` gains a `tripwire-delta` mode: called when `tripwire_aspects` includes `queue_growth`, returns projects whose open task count grew since the last midday-tripwire run.

### Workstream C — Filesystem-first writes + single-command onboarding

All six `write-run-note-*` skills migrate their write step from `mcp__obsidian__create_note` to native tool sequence:
1. `Bash`: `mkdir -p <parent_dir>`
2. `Write`: write the fully-rendered body to the resolved path
3. `Bash`: `wc -c <path>` — byte-count assertion (fail if 0; surfaces truncation silently introduced by earlier MCP-path write failures)

`cowork:check-vault-routing` gains a `{ required: ["filesystem"] }` mode that verifies `spice/cowork/context/vault-config.md` is readable via the native `Read` tool (not MCP), confirming filesystem access before any write-run-note skill is invoked.

`cowork:onboard-scheduled-jobs` receives a full rewrite:

- **Step 0 (Welcome):** prints a preamble explaining what the skill does and what it will write.
- **Step 1 (Preflight):** auto-delegates to `cowork:bootstrap-vault` when `vault-config.md` is absent. Re-runnable detection: if jobs are already onboarded, asks whether to re-run (overwrite guard defaults to skip unless user explicitly confirms).
- **Step 2 (Bulk-defaults question):** single yes/no prompt — "Accept all default prompts? (a) Yes, use workshop defaults / (b) No, I'll customize each". Option (a) skips per-cadence preambles. Option (b) presents each cadence's preamble in sequence.
- **Step 3 (Per-cadence preambles):** for option (b), each cadence presents its workshop-default prompt text in a `> [!example]-` callout, then asks whether to keep, customize, or skip.
- **Step 4 (Filesystem Read+Write copy):** for each cadence in `enabled_cadences[]`, reads the workshop source from `platform/blueprints/cowork/content/context/engagement-templates/{type}/prompts/{cadence}.md` via `Read`, writes to `spice/cowork/context/{engagement_id}/prompts/{cadence}.md` via `Write`, then asserts byte count matches (non-zero and within 5% of source) via `wc -c`. Skips cadences that already have a customized prompt (byte count diverges from source) unless the user explicitly confirmed overwrite in Step 1.
- **Step 5 (Final summary):** emits a table of what was written, what was skipped, and what to expect on first fire.

## Lessons

1. **Cross-cycle test-assertion staleness.** HC-V0710-3b/3c (asserting old summary/warnings contract wording) and HC-V0710-4 (asserting the old `discriminator_tags` field name) and V068-ONBOARD-GUARD became stale because v0.74.0 contract changes superseded their literals. They were fixed post-preflight in follow-up `b69572f`. The v0.71.0 cycle hit the same pattern with `discriminator_tags` errata-3. **Lesson:** when changing a contract that prior cycles' tests assert against, audit ALL `HC-*` assertions for stale literals BEFORE preflight, not after. Candidate pre-stage-commit checklist item for `build-test-verify.md`.

2. **Plan-doc references to deprecated install commands.** The plan referred to `./install.sh` as the dogfood entrypoint. The workshop deprecated that since v0.36.0; the correct command is `sauce update`. The implementer correctly used `sauce update`, but the mismatch caused a plan-vs-reality friction point. **Lesson:** plan-doc boilerplate for the S10 dogfood step should reference the canonical `sauce update` command, not the legacy `./install.sh`. Consider an agent-guides note about the canonical dogfood command.

3. **Dogfood install touches more than just ranch state.** Plan's S10 step 10.6 listed only the 3 ranch/*.json files as the install commit scope. The actual `sauce update` also refreshed 28 consumer-mirror files (`.claude/skills/cowork/*`, `spice/cowork/context/engagement-templates/*`, `ranch/rules/cowork.json`). This required a follow-up commit `e796933`. **Lesson:** future S10 plans should anticipate the full mirror set — not just ranch state files but all files materialized into the self-subscription consumer path.

4. **`ranch/platform-subscription.json` top-level `workshop_version` field.** The v0.74.0 S9 plan called out bumping the `pinned` map entries but didn't mention the top-level `workshop_version` field that also lives in `platform-subscription.json`. Fixed in S9 follow-up `b60bbe7`. **Lesson:** the self-subscription invariant requires BOTH the cowork pin AND the top-level `workshop_version` field be bumped at S9. Worth documenting as an invariant note in `build-test-verify.md`.

5. **Stale plan-time pin assumptions (FA4/FA6 cowork pin step).** Plan step 8.8 named FA4 and FA6 as the harness locations needing cowork pin updates. The actual cowork validation lives in FA5's regex which already accepts 0.13.0. The step was effectively a no-op for FA4/FA6 and required only the `V071-VERSION` → `V074-VERSION` rename in run-cowork-smoke.js. **Lesson:** plan-time grep verification of which exact test pins reference the cowork version would catch stale assumptions before implementation begins.

6. **Engagement-template file count assertion margin.** The plan said 14 engagement-template prompt files (w2-fte without monthly); actual count is 15 (w2-fte/monthly-review.md exists as a placeholder). HC-V0740-14 used `trimmedFiles >= 13` to tolerate either count. **Lesson:** count assertions in harnesses should always carry a small safety margin for file-set drift rather than asserting exact equality.
