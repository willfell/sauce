# v0.94.0 — applyExternalPluginInstall design

Close the v0.93.3 existing-consumer install gap. Today `applyExternalPlugins` (platform/install.js:2695) is warning-only and `phaseFetchPlugins` (platform/bootstrap.js:120) installs but only during fresh-vault bootstrap. Existing consumers see a Notice + manual workflow when a mechanism declares a new external plugin. v0.94.0 introduces an install-time companion that auto-fetches missing plugin dirs during `sauce update`, mirroring bootstrap's behavior. The cycle also adds claudian (plugin id `realclaudian`, repo `YishenTu/claudian`) as a default external plugin under convenience.

## 1 — Architecture & seam

One new function lands inline in `platform/install.js`, alongside the existing `applyExternalPlugins` warning helper.

**Module imports** (within the helper, mirroring install.js's pattern of local require()s):

- `bootstrap-lib/fetch-plugin.js` → `fetchPlugin({ id, repo, vaultPath, force })`
- `bootstrap-lib/community-plugins-index.js` → `fetchIndex()` (resolves plugin id → repo URL via the obsidian-releases community-plugins index)
- `bootstrap-lib/community-plugins-merge.js` → `mergeCommunityPlugins({ vaultPath, addIds })` (atomically appends ids to `.obsidian/community-plugins.json`)

**Call site:** `platform/install.js:1071`. Currently that line is `await applyExternalPlugins(...)`. New ordering inside `installItem`:

```
1071  await applyExternalPluginInstall(tp, mech, vaultPath, history, git);  // NEW v0.94.0 — install missing
1072  await applyExternalPlugins(tp, mech, history, git);                    // EXISTING — warn loud on missing required:true
...
1080  await applyCommunityPluginData(tp, mech, variables, history, git);    // EXISTING — scaffolds data.json (now finds plugin dir present)
```

**Why this ordering:**

- Install must run before the warning helper so the warning only fires for plugins where the install attempt failed (or where the user disabled them post-install).
- Install must run before `applyCommunityPluginData` (line 1080), because data.json scaffolding requires `.obsidian/plugins/<id>/` to exist. v0.93.3's existing-consumer gap was exactly this: data.json was correctly skipped because the dir was absent; now the dir gets fetched first, so data.json scaffolding proceeds.

**Subscription gating:** Natural / free. `installItem` only runs for items in the consumer's subscription. The helper iterates the *current item's* `external_plugins[]` — plugins from unsubscribed mechanisms never get fetched. Mirrors `applyCommunityPluginData`'s posture.

**vaultPath threading:** `applyExternalPlugins` infers paths via `tp.app.vault.adapter`, but `fetchPlugin` takes a literal `vaultPath`. `installItem` already has the vault root in scope (line 1085's `applyVendoredThemes` is called with `target.path`); the new helper takes the same value via the same threading.

## 2 — The helper

```javascript
// applyExternalPluginInstall — v0.94.0. For each item that declares
// external_plugins[], fetch any plugin whose .obsidian/plugins/<id>/manifest.json
// is absent, then append id to community-plugins.json. Companion to the existing
// applyExternalPlugins warning helper (which still runs after to nag the user
// about required:true deps that remain disabled). Mirrors phaseFetchPlugins's
// posture: per-plugin failures are caught into a failed[] list; the wider
// install continues.
async function applyExternalPluginInstall(tp, manifest, vaultPath, history, git) {
  if (!manifest || !Array.isArray(manifest.external_plugins) || manifest.external_plugins.length === 0) return;

  const fetchPluginMod = require("./bootstrap-lib/fetch-plugin.js");
  const indexMod       = require("./bootstrap-lib/community-plugins-index.js");
  const mergeMod       = require("./bootstrap-lib/community-plugins-merge.js");

  let index;
  try {
    index = await indexMod.fetchIndex();
  } catch (e) {
    new Notice(`applyExternalPluginInstall: cannot fetch community-plugins index (${e.message}); skipping for ${manifest.name}`, 8000);
    if (history) history.push({
      event: "error", step: "external_plugin_install", name: manifest.name,
      message: `index fetch failed: ${e.message}`,
      git_commit: git.commit, git_tag: git.tag, git_dirty: git.dirty,
      attempted_at: new Date().toISOString(),
    });
    return;
  }

  const fetched = [], skipped = [], failed = [];

  for (const dep of manifest.external_plugins) {
    if (!dep || typeof dep.id !== "string") continue;
    const id = dep.id;
    const entry = index[id];
    if (!entry) {
      failed.push({ id, reason: `plugin id '${id}' not found in obsidian-releases index` });
      if (history) history.push({
        event: "error", step: "external_plugin_install", name: manifest.name,
        plugin_id: id, message: `not found in obsidian-releases index`,
        git_commit: git.commit, git_tag: git.tag, git_dirty: git.dirty,
        attempted_at: new Date().toISOString(),
      });
      continue;
    }
    try {
      const r = await fetchPluginMod.fetchPlugin({ id, repo: entry.repo, vaultPath });
      if (r.status === "skipped") {
        skipped.push({ id });
      } else if (r.status === "fetched") {
        fetched.push({ id });
        new Notice(`applyExternalPluginInstall: fetched ${id} from ${entry.repo}`, 6000);
        if (history) history.push({
          event: "fetched", step: "external_plugin_install", name: manifest.name,
          plugin_id: id, repo: entry.repo,
          git_commit: git.commit, git_tag: git.tag, git_dirty: git.dirty,
          attempted_at: new Date().toISOString(),
        });
      }
    } catch (e) {
      failed.push({ id, reason: e.message });
      new Notice(`applyExternalPluginInstall: failed to fetch ${id} (${e.message}); ${manifest.name} will still warn via applyExternalPlugins`, 10000);
      if (history) history.push({
        event: "error", step: "external_plugin_install", name: manifest.name,
        plugin_id: id, message: e.message,
        git_commit: git.commit, git_tag: git.tag, git_dirty: git.dirty,
        attempted_at: new Date().toISOString(),
      });
    }
  }

  // Mirror phaseFetchPlugins:161 — append id to community-plugins.json for
  // BOTH fetched AND skipped (skipped means dir already present; ensure the
  // id is enabled). Failed installs are NOT added — the warning helper still
  // surfaces them.
  const installedIds = [...fetched.map(x => x.id), ...skipped.map(x => x.id)];
  if (installedIds.length > 0) {
    await mergeMod.mergeCommunityPlugins({ vaultPath, addIds: installedIds });
  }
}
```

### Behavioral notes

- **Idempotence:** `fetchPlugin` already does skip-if-`manifest.json`-exists. No additional shape-check needed. Half-fetched/corrupt dirs (dir present but no manifest.json) trigger a fetch — which is the right recovery.
- **`required: true` is documentation-of-intent, not behavior:** the helper installs ALL declared `external_plugins[]`. `required:true` only affects what `applyExternalPlugins` warns loudly about afterward (unchanged from v0.93.3).
- **Notice text deliberately surfaces the repo** (`fetched realclaudian from YishenTu/claudian`) so an audit reader can verify the right source.
- **User-added plugins are additive-safe:** `mergeCommunityPlugins` never removes. If a consumer has manually installed `obsidian-git` (not declared by any sauce mechanism), the id stays in community-plugins.json untouched.

**Headspace-sauce post-v0.94.0 upgrade — first `sauce update --bump-pins`:**

     - `new-tab-default-page`: dir absent → **fetched** (`Notice: applyExternalPluginInstall: fetched new-tab-default-page from <repo>`); id appended to community-plugins.json
     - `realclaudian`: dir absent → **fetched** (`Notice: applyExternalPluginInstall: fetched realclaudian from YishenTu/claudian`); id appended to community-plugins.json
   - line 1072 `applyExternalPlugins` runs — no `required:true` entries in convenience; no warning Notices.
   - line 1080 `applyCommunityPluginData` runs — finds new-tab-default-page's dir present (just installed), prereq gate passes, writes data.json with the v0.93.3-baked settings (whatToOpen=daily-notes, mode=reading-mode, filePath="", compatibilityMode=false).
4. **smart-connections-bridge item** (subscribed):
   - line 1071 `applyExternalPluginInstall` iterates `[{id:"smart-connections", required:true}]`
     - `smart-connections`: dir already present (manually installed pre-v0.94.0 on headspace) → status `skipped`; id ensured in community-plugins.json (already there in this case; merge is no-op).
   - line 1072 `applyExternalPlugins` — id is in community-plugins.json; no warning.
5. Install completes. Notice log shows two `fetched` lines. install-history.json gains two `fetched` events + the standard pin-bump entries.
6. **Obsidian restart required** for the newly-installed plugins to load (Obsidian doesn't hot-load plugin dirs). User restarts → plugins active.

**Consequence for v0.93.3's manual-install documentation:** `Docs/install.md` § "Upgrading from v0.93.2 to v0.93.3" becomes a historical artifact. v0.94.0's `Docs/install.md` adds a new "Upgrading from v0.93.3 to v0.94.0" section noting "post-upgrade, run `sauce update --bump-pins`; the two v0.93.3 plugins auto-install on existing consumers + a new default plugin (realclaudian) joins. Restart Obsidian for the new plugins to load."

**User-added plugins:** A user-installed `obsidian-git` stays in community-plugins.json untouched. `mergeCommunityPlugins` is additive — appends sauce ids if missing, never removes anything. ✓

## 4 — Failure modes + landmine #17

### Per-plugin fetch failures (404, rate limit, network down)

- Caught into `failed[]`. Helper never throws.
- Notice: `applyExternalPluginInstall: failed to fetch X (reason); X will still warn via applyExternalPlugins`.
- history.json: `event: "error"` with `plugin_id` + `message`.
- id NOT appended to community-plugins.json. Downstream `applyExternalPlugins` retains its existing `required:true` warning teeth for these cases.
- Wider install continues — other plugins in the same external_plugins[] still get attempted; other subscribed mechanisms still install.

### Index fetch failure (obsidian-releases unreachable)

- Single Notice + history error event; helper returns early; warning helper still runs; install continues. The rare-but-real "GitHub.com down" case shouldn't brick the entire install pass.

### Plugin id not in obsidian-releases index (typo, deprecated)

- Logged to `failed[]` + history error event with reason "plugin id 'X' not found in obsidian-releases index". No Notice (avoid noise on a static manifest typo — surface via history audit). Downstream warning still fires for `required:true`.

### Plugin dir half-exists (interrupted prior fetch)

- `fetchPlugin`'s skip-if-`manifest.json`-exists check fails when manifest.json is absent → fetch proceeds → backup-on-edit overwrites any partial files. Self-healing.

### community-plugins.json malformed

- `mergeCommunityPlugins` (existing module) handles this via the same C4 hardening posture that `applyExternalPlugins` uses (preserve + report, never overwrite). No new code path needed.

### Landmine #17 amendment

Today's text: "Bootstrap is the only network gateway; fail-loud on plugin fetch errors."

v0.94.0 amendment:

> **Two network gateways, two postures.** `bootstrap.js:phaseFetchPlugins` is fail-loud (BS5 posture; per-plugin failures get caught into a failed[] but the bootstrap caller surfaces them). `install.js:applyExternalPluginInstall` (NEW v0.94.0) is warn-and-continue (per-plugin failures are caught + Noticed + history-logged; the install proceeds; downstream `applyExternalPlugins` retains `required:true` warning teeth for any failed install). Both share `bootstrap-lib/fetch-plugin.js`'s defense-in-depth: plugin-id allowlist regex, path-traversal guard, atomic writes with backup-on-edit, BS5 per-plugin failure handling, optional `process.env.GITHUB_TOKEN` honored.
