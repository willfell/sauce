## My recommended ordering (if you want a single recommendation)

A **two-bundle sprint** ordered by leverage:

**Bundle 1 — workshop tooling first (cuts every future session's cost).** Cycles #13 + #15 + #12 + #16 — `sauce status` CLI, cycle-status auto-update, scaffold script, dev-workflow doc. Net effect: next session opens with one command's worth of context instead of 5-10 tool calls + manual catch-up. Ships as v0.112.0 MINOR (tooling cycle).

**Bundle 2 — finance cohesion polish.** Cycles #1 (debt-payment exclusion semantics) + #3 (Band 3 click-through) + #5 (FinanceYearReview annual band). Net effect: closes the MonthlyOverview math correctness gap + unlocks annual-cohesion perspective. Ships as v0.112.1 → v0.113.0.

Alternative — if v0.111.3 has been in the field for a week and the user has signal that the math is double-counting OR that audit-trail is missing — flip the order. Bundle 2 first, then tooling.

## Anti-recommendations

- **Don't ship #11 (programmatic Obsidian launch)** until at least 3 cycles ship a real regression that field-level + cross-helper tests both missed. Heavy infra without proven need.
- **Don't ship #6 (paycheck source field)** without a use case the user actively wants. Schema migrations are expensive; speculative schema additions are anti-patterns.
- **Don't ship #8 (debt-attack suggestion)** until #1 (exclusion semantics) is done — they're coupled (suggestion math depends on accurate cashflow read).

End of brainstorm.
