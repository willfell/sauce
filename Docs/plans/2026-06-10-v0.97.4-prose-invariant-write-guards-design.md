# v0.97.4 prose-invariant write-guards — design

## TL;DR

The v0.97.3 cloud-sync-parity ship fixed the structural contract (path, frontmatter, sidecar). Today's accuris morning-briefing proved the structural side of the contract held — but THREE prose-level invariants still failed silently because the deterministic backstops can't see them:

1. Rating callout (`> [!todo]+ Was today useful?`) didn't fire even though the sidecar said `surfaced_kinds_for_rating.length=3` + `learning_enabled=true`. Rail L can't read prior_rating_state on the next fire — Rail L is dead for that engagement.
2. Anti-echo callout (`> [!question] Outside yesterday's frame`) didn't fire even though the sidecar said `render_aspects_applied: [anti_echo:include]`. Sidecar and body contradict each other.
3. Priority loop dispatched only 3 of 5 kinds. Sidecar `surfaced_kinds=[calendar,email,chat]` with `ado` + `github` silently dropped. GitHub deployment-approval notifications leaked into the Email callout because Github had no callout of its own.

Plus two high-severity gaps the chat + calendar microscopes mandated but the LLM under wrapper-load skipped:

4. Chat callout rendered as a flat reverse-chronological list instead of `Utilization snapshot` + urgency tiers (REPLY OWED - DIRECT / GROUP / TIME-SENSITIVE / FYI).
5. Calendar rendered as a bulleted list instead of a markdown table (Time / Event / Organizer / Status).

The architectural shift: prose-level invariants now have deterministic backstops. Where v0.97.3 made the SHAPE of the brief contractually correct, v0.97.4 makes the BEHAVIOR of the brief contractually correct.

## Architecture

### Five changes

1. **`write-atomic-note-helper.js` — three new write-guards.**
   - **Rating-callout sentinel.** Gate: `surfaced_kinds_for_rating.length > 0 && learning_enabled !== false`. Body MUST contain `<!-- cowork:rating-block schema=`. On miss, return `failed:contract-violation:missing-rating-callout`. No file written.
   - **Anti-echo callout.** Gate: `sidecar.render_aspects_applied.includes("anti_echo:include")`. Body MUST contain `Outside yesterday's frame`. On miss, return `failed:contract-violation:missing-anti-echo-callout`. No file written. Sidecar-driven gate — no new param needed.
   - **Coverage-gap injection + sidecar mirror.** Gate: `expected_kinds.length > surfaced_kinds.length`. Inject `> [!warning]+ Coverage gap` callout into body_md BEFORE the first per-kind block. Mirror `coverage_gap: { expected, surfaced, skipped }` into the sidecar. NON-failing — some kinds legitimately have no data — but the gap is now VISIBLE in the rendered brief AND machine-readable for `reconcile-cowork`'s cross-day monitoring.

2. **All 6 sidecar schemas grow an optional `coverage_gap` property.** `{ expected: string[], surfaced: string[], skipped: string[] }`. Required when present (full triple). The top-level `additionalProperties: false` no longer rejects the new field.

3. **`gather-from-served-by/SKILL.md` gains an inline microscope output-shape contract.**
   New section `## Microscope output-shape contract (INLINE — do not delegate to a separate read)` listing the FOUR mandatory structural elements verbatim:
     - Utilization snapshot lead-in (1-line situation summary, NOT a generic "Recent activity:" placeholder)
     - Urgency-tiered subsections with bold subheads (REPLY OWED - DIRECT / GROUP / TIME-SENSITIVE / FYI for chat; REPLY OWED / TIME-SENSITIVE / FYI for email; MINE - OPEN / BLOCKED / REVIEW REQUESTED / FYI for ado/github)
     - Inner-circle wikilink emission as `**[[Person Basename]]**`
     - Calendar: MARKDOWN TABLE (Time / Event / Organizer / Status), NOT bullets
   Plus a verbal-commitment line: BEFORE composing the per-kind callout, READ the microscope file in full AND echo back the section headers as a Notice. If file missing, emit Notice and apply structured fallback — `do NOT improvise a flat list`.
   Plus a pre-render self-check checklist enumerating four points the LLM mentally verifies before returning the callout.

4. **5 orchestrator-instructions cadence files update Step 8.5.**
   The existing Step 8.5 (sidecar schema validation backstop) gains a new paragraph documenting the three new `writeAtomicNote` params (`surfaced_kinds_for_rating`, `learning_enabled`, `expected_kinds`) and how each guard fires. This makes the new contract visible to both the cloud LLM (claude.ai Cowork UI) and the local CLI write path.

5. **plan-dispatch investigation: NO bug found.**
   HC-V0974-PD-1..5 prove the helper contract is already correct:
     - 5-priority engagements with all 5 connected → 5 dispatch_plan entries (PD-1)
     - `custom_kind: true` entries → NOT filtered (PD-2)
     - UUID-shaped `served_by` values → resolved against reachable_namespaces (PD-3)
     - Unreachable served_by → emits `warn` entry (NOT silent drop) (PD-4)
     - priorities[] declared order preserved (PD-5)
   The accuris morning fire's "only 3 of 5 priorities surfaced" was therefore an LLM-side priority-loop skip — the LLM saw 5 entries in `dispatch_plan` but iterated only 3 of them. The coverage-gap write-guard now makes that class of failure VISIBLE in the brief (and machine-readable in the sidecar for cross-day reconciler analysis).

### Guard ordering (deterministic)

`writeAtomicNote` now executes in this fixed order:

1. missing-input (existing)
2. missing-rating-callout (NEW — gate: surfaced_kinds_for_rating.length>0 AND learning_enabled !== false)
3. missing-anti-echo-callout (NEW — gate: sidecar.render_aspects_applied includes "anti_echo:include")
4. coverage-gap injection (NEW — gate: expected_kinds.length > surfaced_kinds.length; non-failing; mutates body_md + sidecar)
5. sidecar schema validation (existing) — runs against the POSSIBLY-mutated sidecar, so coverage_gap must validate
6. md write (existing)
7. sidecar write (existing)

Missing-input takes precedence over the new prose-invariant guards (HC-V0974-WG-8 pins this).

## Why this works

- **The LLM can no longer silently skip the rating + anti-echo callouts.** The write itself fails. The user / scheduled-job system sees a clear "contract-violation" status string and can re-fire.
- **The LLM can no longer silently drop priorities from the loop.** The coverage-gap write-guard reads `expected_kinds` (from `plan.dispatch_plan`) against `surfaced_kinds` (from the composed sidecar) and INJECTS a visible warning callout when they diverge. Gone are the days of "I noticed 5 priorities but only emitted 3 callouts and the user has no way to know."
- **The LLM can no longer ignore the microscope `## Output shape` directives.** The four mandatory structural elements are now INLINED into `gather-from-served-by/SKILL.md` itself — load-bearing prose that the wrapper composes into the LLM's context regardless of whether the microscope file is opened.

## Backward compatibility

All three new `writeAtomicNote` params are OPTIONAL. Existing callers (pre-v0.97.4 unit harnesses) continue to work — the helper degrades gracefully:
- No `surfaced_kinds_for_rating` → rating-callout guard skipped.
- No `render_aspects_applied` in sidecar → anti-echo guard's gate stays closed.
- No `expected_kinds` → coverage-gap injection skipped (no body mutation, no sidecar.coverage_gap).

The 6 sidecar schemas gain an OPTIONAL `coverage_gap` property — existing sidecars (without the field) still validate.
