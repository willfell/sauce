# v0.120.1 — note-picker fix PATCH — result

## Shipped

User reported on accuris 2026-06-16 20:09 UTC: the "Link a note" dropdown in the `+ New Task`
dialog "lists every note, and since there are so many notes, it only finds itself to the
letter D in notes, and then the dropdown items stop. So even when I search for notes that I
know exist, they aren't shown in the dropdown."

## Root cause

`ToDoCreateTask._loadNoteList()` returned `notes.slice(0, 200)` AFTER an alphabetical sort —
vaults with >200 markdown files lost every entry past `D`-ish in the alphabet. The
`repopulate(filter)` substring-filter ran over that already-truncated subset, so verbatim
matches past the cap returned nothing.

## Fix

`_loadNoteList()` now returns the FULL list as `{name, path, mtime}` (no cap; mtime carried
for recency-default sort). `repopulate(filter)` runs over the full list:
- **No filter**: defaults to top 50 most-recently-modified notes (recency-first — the most
  useful "show me what I might be linking to" default).
- **Filter**: substring-matches the entire list case-insensitively; sorts results by
  "starts-with priority + alpha" (so typing "GH" surfaces `Github Migrations` above
  `Big Github Issue`); caps rendered options at 50; if total matches exceed 50, surfaces
  `"… N more — refine the filter to narrow"` as a disabled hint option.
- **No matches**: surfaces `"(no matches)"` as a disabled hint option.

Filter placeholder now reads `"Filter N notes…"` showing the total vault count.

## Lessons

1. **The 200-cap was load-bearing latent.** Shipped in v0.4.0 (original dialog), sat invisible
   until the user accumulated >200 notes in any one vault. Hard caps on "list user content"
   surfaces should be applied AFTER filtering, not before — otherwise the user can't reach
   what's filtered out.

2. **Recency-first defaults beat alpha-first for picker affordances.** When the user opens
   the dropdown without typing, "what did I recently work on" is almost always more helpful
   than "what comes first alphabetically." Costs nothing (mtime already on file.stat).
