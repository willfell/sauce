## Architecture delta (one paragraph)

5 orchestrator SKILL.md bodies (morning-briefing / midday-tripwire / eod-review / weekly-review / monthly-review) carried byte-identical copies of the dispatch-plan pseudocode through v0.94.x (~100 lines per file). Same conceptual pre-flight step wore different sub-step labels across files (morning-briefing's `3a memory / 3b semantic-echoes / 3c read-prefs / 3d dispatch / 3e inner-circle` vs the other four's `3a memory / 3b read-prefs / 3c dispatch / 3d inner-circle`). Per-kind callout titles ("Today's calendar", "Email triage", "Chat") were inlined in each orchestrator's compose-body step. Connectivity signal authority (v0.91.3) + deferred MCP tool loading + Known-people-in-scope wikilink contract + PREFS UNAVAILABLE legacy-mode prose duplicated 5x. The `render_aspects` knob surface was a flat 6-key per-engagement-type map with no per-engagement override layer — to "reorder connectors per cadence per engagement," a user had to fork the engagement-type JSON. v0.95.0's `cowork:plan-dispatch` sub-skill is now the single structural owner: it reads `vault-config.md` + engagement-type bundle + (optional) `engagement.overrides` block, composes the layered preferences tree, reads per-kind microscopes + siblings + mcp-skill-map, invokes `planDispatch` + `composeVoiceContract`, resolves the inner-circle allowlist, loads `data/kind-titles.json`, and returns a 12-key contract that orchestrators consume as their single source of truth for Gather + Write. The 5 orchestrators each slim by collapsing pre-flight steps 3b/3c/3d (and 3e where present) into one `READ cowork:plan-dispatch` step.

## Lessons (for v0.95.0.x and beyond)

### Lesson 1 — Sub-skill contract evolves under refactor pressure
The original design specified a 10-key plan-dispatch contract. During S1.5 execution the contract grew to 11 keys (NEW `effective_hard_rules` — needed by gather-from-served-by independently of voice_contract) and then 12 keys (NEW `tripwire_aspects` — needed by midday-tripwire's per-aspect dispatch). Both were surface-area expansions that emerged organically as orchestrators consumed the result tree. **Carry-forward:** when designing a sub-skill contract, expect at least one extension during refactor. Reserve a slot or two in the contract for "I forgot one" expansions.

### Lesson 2 — Defense-in-depth surfaces resist slimming
The design's ~150-line target per orchestrator assumed the verify/write-guard/verbal-commitment prose could compress. In practice those surfaces are load-bearing (HC-V0911-WRITE-GUARD-* / HC-V0912-FM-* / HC-V0911-COMMIT-* / HC-V0912-COMMIT-*) and resisted further slim. The 1685 → 1098 (−587 line) outcome is a net win — the cohesion goal is achieved — but the absolute line targets in design docs should account for the defense-in-depth floor.

### Lesson 3 — Test-quality drift can mask cohesion regressions
The S1.5 cohesion sweep surfaced 41 pre-existing test failures in HC-V0891-ORCHESTRATOR / HC-V0900-IMPERATIVE/FALLBACK / HC-V0913-PREFS/TOOLS — each was asserting against load-bearing prose that the refactor LEGITIMATELY moved into the new sub-skill. The right fix was re-routing the assertions to read the orchestrator + plan-dispatch as a combined corpus, not preserving stale prose. **Carry-forward:** when refactoring shared prose into a new owner, audit prose-lint assertions in the same stage — not at preflight discovery time.

### Lesson 4 — Phantom plan steps signal stale assumptions
The plan's S1.4 Step 4 referenced `node Scripts/regenerate-claude-surface-registry.js` — that script does not exist. The registry is regenerated as a side effect of `platform/install.js` (Templater context). The plan author had assumed a standalone regenerator existed. **Carry-forward:** before authoring a plan step that runs a script, verify the script exists.

### Lesson 5 — Mid-execution scope expansion needs explicit surfacing
The 12th contract key (`tripwire_aspects`) was added during S1.5.2 — a scope adjustment from the design's "10-key" target. Surfaced explicitly in commit S1.5.2 + sub-skill SKILL.md narration. Per v0.93.3 lesson 5.6 (surface adaptations explicitly). **Carry-forward:** treat mid-execution contract additions as a design extension, not silent growth. Document the extension in the commit message + the sub-skill body.

### Lesson 6 — Workshop dogfood is a useful contract verifier
S2 dogfood install caught a manifest entry order issue (plan-dispatch claude_surface[] entry needed to sit after read-user-preferences for thematic coherence) and confirmed the data file materialized to the right path. The dogfood pass is short — 82 history entries, ~4 seconds — and worth running before every push, not just at the end.
