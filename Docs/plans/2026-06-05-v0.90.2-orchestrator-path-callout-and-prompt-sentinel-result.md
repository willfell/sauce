## Lessons

1. **Prose-only fixes have LLM-attention ceiling.** Even with a `[!warning]+ CRITICAL` callout block at the top of the SKILL.md, there's no guarantee the LLM reads it. FLN-v90-3 (write-guard in the sub-skill) is the deterministic fallback — it executes the path check at write-time regardless of LLM behavior. Queue it for v0.90.3 or v0.91.0.

2. **LLM-behavior variance is real and observable.** Today's evidence: identical accuris vault, identical orchestrator SKILL.md, identical v0.4.0 stub prompt body. Yesterday's LLM session produced a rich briefing; today's produced a stub. Variance is the input we have to design for, not the assumption we can rule out. Sentinel detection is fragile if the LLM doesn't reach Step 10; FLN-v90-3 hardening is essential.

3. **CLAUDE.md ambiguity propagates downstream.** The consumer vault's CLAUDE.md row `| Daily | spice/daily | /daily |` was structurally correct — it documents the daily-blueprint resolver. But the LLM applied it to a cowork atomic-note write, conflating two surfaces. The fix is in the orchestrator SKILL.md (callout at top), not in CLAUDE.md (which serves a legitimate function for daily-blueprint operations).

4. **Coordinated edits across 5 orchestrators is the new normal.** v0.89.1 wired 5 orchestrators for inner_circle_resolved threading. v0.90.0 added MANDATORY imperative-gather across 5. v0.90.2 adds CRITICAL output-path callouts across 5 AND sentinel detection across 5. Each cycle taught a new lesson about LLM behavior; each cycle added more imperative prose across the same 5 files. A meta-helper / template that generates the boilerplate across the 5 would reduce drift risk.
