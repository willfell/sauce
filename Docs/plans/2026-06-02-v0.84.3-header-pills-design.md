# v0.84.3 header-pills — design

Visual refinement of the three top-level daily-dashboard section headers (Tasks / Meetings / Activity). Pulls the inline `(N)` counts out of the title text into right-aligned pills that match the existing meeting-card pill type system. Tasks gets a dopamine treatment (orange "N Open" pill with a soft glow + optional green "N Done" pill). Meetings + Activity get a single subtle neutral count pill. Activity sub-groups stay as-is — out of scope this cycle.

No new mechanisms, no new blueprints. PATCH bump on workshop + daily blueprint only.

## §1 — Layout contract

All three section headers share the same DOM shape under the existing `.sauce-section-summary` flex row:

```
[.sauce-section-icon] [<title text>] [.sauce-section-counts] [.sauce-section-chevron]
```

The new `.sauce-section-counts` span carries `margin-left: auto`, pushing itself plus the chevron to the right edge. The counts span is itself a flex container with `gap: 6px` so multiple pills (Tasks: open + done) sit side-by-side with a small breath. Inside it goes zero, one, or two pill spans.

The title text drops the parenthetical count entirely:

| Section | v0.84.2 title | v0.84.3 title |
| --- | --- | --- |
| Tasks | `Tasks (3 open · 1 done)` | `Tasks` |
| Meetings | `Meetings (2)` | `Meetings` |
| Activity | `Activity (8)` | `Activity` |

Counts move to `.sauce-section-counts` as pills.

## §2 — Pill rendering rules

### §2.1 — Tasks

| State | `.sauce-section-counts` contents |
| --- | --- |
| `open === 0 && done === 0` | (section not rendered — `hasContent` gate) |
| `open > 0 && done === 0` | `[orange '<N> Open' pill]` |
| `open > 0 && done > 0` | `[orange '<N> Open' pill] [green '<K> Done' pill]` |
| `open === 0 && done > 0` | `[green '<K> Done' pill]` |

No celebration text variant. The empty Tasks list body already signals all-clear; the single green pill carries the dopamine.

### §2.2 — Meetings

Always renders a single `.sauce-section-count-pill` containing the meeting count when the section renders at all (i.e., when `meetings.length > 0`). The pill is the neutral subtle variant (transparent fill, modifier-border ring, muted text).

### §2.3 — Activity

Same as Meetings — one neutral count pill containing the total activity count when `activityCount > 0`.

### §2.4 — When the section doesn't render

The outer `if (hasContent)` gate at `space-daily-dashboard.js:202-207` is unchanged. Sections that don't render produce no DOM at all — no empty pill, no empty header.

## §4 — `_renderSection` opt: `rightHtml`

The helper at `space-daily-dashboard.js:899` already takes `{ accent, iconHtml, title, titleHtml, defaultOpen, stateKey, sectionState }` (the `titleHtml` opt landed in v0.84.1 carryforward). It grows one more option, `rightHtml`, with parallel semantics:

```javascript
_renderSection(container, { accent, iconHtml, title, titleHtml, rightHtml, defaultOpen, stateKey, sectionState }) {
  // ... existing detail / state-persistence logic unchanged ...

  const titleMarkup = (typeof titleHtml === "string" && titleHtml.length > 0)
    ? titleHtml
    : this._escapeHtml(title);
  const rightMarkup = (typeof rightHtml === "string" && rightHtml.length > 0)
    ? `<span class="sauce-section-counts">${rightHtml}</span>`
    : "";
  summary.innerHTML =
    `<span class="sauce-section-icon">${iconHtml}</span>` +
    `<span>${titleMarkup}</span>` +
    rightMarkup +
    `<span class="sauce-section-chevron">${this._CHEVRON_SVG}</span>`;
}
```

When a caller doesn't pass `rightHtml`, the counts span is omitted entirely — no empty markup, no layout shift. Callers that pass numeric-only interpolated content (the only callers planned this cycle) are safe from XSS. Same trust boundary as the v0.84.1 `titleHtml` opt.

## §5 — Call sites

### §5.1 — Tasks

Builds three forms of `rightHtml` based on open/done counts. Title becomes the bare string `"Tasks"`:

```javascript
let rightHtml;
if (openTasks.length > 0 && doneTasks.length > 0) {
  rightHtml = `<span class="sauce-section-open-pill">${openTasks.length} Open</span>` +
              `<span class="sauce-section-done-pill">${doneTasks.length} Done</span>`;
} else if (openTasks.length > 0) {
  rightHtml = `<span class="sauce-section-open-pill">${openTasks.length} Open</span>`;
} else {
  rightHtml = `<span class="sauce-section-done-pill">${doneTasks.length} Done</span>`;
}

const tasksBody = this._renderSection(container, {
  accent: "cyan",
  iconHtml: icons.checkSquare,
  title: "Tasks",
  rightHtml,
  defaultOpen: true,
  stateKey: "sauce-daily-dashboard:tasks",
  sectionState,
});
```

The v0.84.1 `tasksTitleHtml` variable is removed. The `_escapeHtml` ternary in `_renderSection` still handles the `title: "Tasks"` plain-text path.

### §5.2 — Meetings

Title becomes `"Meetings"`. The right-side is one neutral pill containing the count:

```javascript
const meetingsBody = this._renderSection(container, {
  accent: "blue",
  iconHtml: icons.calendar,
  title: "Meetings",
  rightHtml: `<span class="sauce-section-count-pill">${meetings.length}</span>`,
  defaultOpen: true,
  stateKey: "sauce-daily-dashboard:meetings",
  sectionState,
});
```

### §5.3 — Activity

Same pattern as Meetings:

```javascript
const activityBody = this._renderSection(container, {

  iconHtml: icons.activity,
  title: "Activity",
  rightHtml: `<span class="sauce-section-count-pill">${activityCount}</span>`,
```

## §8 — Risk register

| Risk | Mitigation |
| --- | --- |
| `color-mix()` lacks support in old browsers | Obsidian Electron uses a recent Chromium (≥111); `color-mix` is supported. Acceptable. |
| Orange glow looks too loud in dark mode | Orange is a Lucide / Obsidian theme variable that's already chosen for visibility. The 35% opacity glow at 8px is conservative. If actually loud in dogfood, reduce to 25% / 6px in a hotfix (one CSS edit). |
| `sauce-section-counts` flex with `margin-left: auto` clobbers section icon alignment | Existing summary is `display: flex; align-items: center; gap: 8px`. The new counts span is just another flex child. `margin-left: auto` is the standard right-align idiom and doesn't disturb sibling alignment. |
| Long meeting/activity counts (>= 100) overflow on mobile | Mobile pill padding tightens at ≤480px (§3.6). Count text uses `tabular-nums` for stable width. 100 → 3 chars; pill width grows but contains. |
| Persisted section-state stays bound to `sauce-daily-dashboard:tasks` etc. — unchanged | No state-key churn; existing collapsed/expanded states survive the cycle. |
| Some other caller of `_renderSection` accidentally relies on the absence of a `<span class="sauce-section-counts">` element | There are exactly 3 callers, all listed in §5; all explicitly opt into `rightHtml`. No third-party consumer. |
