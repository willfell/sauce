## What v0.82.0 changes for consumer vaults

**Pure-additive cowork cycle.** Two coherent UX-polish workstreams shipped together:

### WS-A — per-kind callout types now drive 5-6 distinct colors per atomic note

After `sauce update --bump-pins` runs on a consumer vault, each cowork orchestrator's gather loop will pass a per-kind callout type to `cowork:gather-from-served-by`, which now composes the callout as `> [!<callout_type>]+ <kind_title>` instead of the hard-coded `> [!example]+ <kind_title>`. The default mapping ships in `read-user-preferences-helper.js`:

| Kind | Default callout type | Rationale |
|---|---|---|
| `chat` | `info` | Blue — conversational signals |
| `finance` | `warning` | Amber — money matters |
| `calendar` | `tip` | Green — anchors / conflicts |
| `email` | `quote` | Gray — quiet / filtered |
| `ado` | `example` | Purple — board state |
| `github` | `note` | Sky blue — code state |

Users can override per kind by adding `callout_type: <type>` to `mcps.<kind>` in `spice/cowork/context/user-preferences.md`. Valid types: any of `info / note / tip / success / warning / caution / example / quote / danger`. Invalid or unknown values fall back to the default mapping; unknown kinds fall back to `example`.

### WS-B — gather-from-served-by/SKILL.md no longer prohibits tables

The "Bulleted lines preferred (no tables — cross-vendor portability)" line in Step 3's Output contract template is replaced with: "Render data in tables OR bullets, whichever gives the highest information density per vertical inch. Use tables for structured data with 3+ columns per item; use bullets for narrative or single-axis lists." Microscope `## Output shape` directives explicitly override.

Per the entering-v0.82.0 handoff's empirical evidence: this is contract-truthing — the 2026-06-01 second accuris morning brief already produced tables when the microscope said to. The "no tables" line wasn't blocking. v0.82.0 makes SKILL.md prose honest about what the agent already does.

### WS-C dropped (premise was wrong)

Originally designed to fix the accuris midday-tripwire silent no-op by editing workshop `engagement-types/w2-fte.json`. S0 investigation found: (a) w2-fte.json already has `midday` in `supported_cadences` + `tripwire_aspects: ["calendar_drift", "queue_growth"]` since v0.13.0; (b) the orchestrator's aspect-name convention is snake_case, not the plan's kebab-case; (c) engagement-type JSONs aren't in cowork's `files[]` so they never materialize to consumer vaults. The accuris silent no-op has a different root cause — see FLN-v82-1.

## Carry-forward queue (v0.83.0+ candidates)

### From v0.82.0 cycle execution

- **FLN-v82-1 (HIGH PRIORITY): engagement-type-accessibility fix.** Engagement-type JSON manifests aren't reachable from consumer vaults at runtime (not in cowork's `files[]`; `pantry/` may or may not exist depending on bootstrap path). Required for any engagement-type-driven orchestrator behavior (midday-tripwire, finance-snapshot future variants) to actually reach consumers. Three candidate designs:
  - (a) Add engagement-type JSONs to cowork's `files[]` so they materialize to `spice/cowork/context/engagement-types/*.json`; update midday-tripwire/SKILL.md to reference the materialized path.
  - (b) Embed `tripwire_aspects` (+ other manifest-derived runtime fields) per-engagement in vault-config.md; `cowork:bootstrap-vault` seeds defaults from manifest.
  - (c) Hardcode aspect mappings per engagement type into the orchestrator SKILL.md.
- **FLN-v82-2: ranch/rules/cowork.json dedup.** Install appends rather than dedupes rule_fragments; file has bloated to ~7900 lines with 13 duplicate copies of each path_glob. Pre-existing across cycles; not v0.82.0-introduced. Add unique-key dedup at install-time.
- **FLN-v82-3: parseYamlIsh hyphenated-key support.** Pre-existing flat-key regex `[a-z_]+` silently drops keys like `my-custom-kind` from `user-preferences.md`. Widen to `[a-z_][a-z0-9_-]*` to support hyphenated custom kinds (e.g., `lharries-whatsapp`).
