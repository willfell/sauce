# v0.88.0 — manual cleanup of pre-existing broken people notes

## Why this exists

v0.88.0 (people-cohesion-1) closes a bug where the `+ New Person` button in `spice/people/People.md` produced person notes with double frontmatter blocks, leftover `<% tp ... %>` literal text in the body, or templater-error toasts. Root cause: the people blueprint's `templater_folder_templates[]` binding double-fired Templater against files entity-create had already populated. Removed in v0.5.0 of the `people` blueprint.

**v0.88.0 does NOT auto-repair pre-existing broken notes.** The relaxed naming rule lets them pass audit by filename, but the body contents stay damaged. This is a one-time manual cleanup.

## How to identify a broken note

Open any file under `spice/people/`. Symptoms:
- More than one `---`-delimited frontmatter block.
- Literal `<% tp.file ... %>` or `<%* await ... %>` text visible in the body (not rendered).
- Templater error notice appearing when the file is opened.

## Per-file cleanup

For each broken note:

1. **Preserve frontmatter values.** Note down any non-empty values for: `company`, `location`, `title`, `email`, `website`, `aliases`, `phone`, `tags`. (`type: person` and `created_at` are auto-set on re-creation; safe to discard.)
2. **Delete the file.** From Obsidian: right-click → Delete. From shell: `rm "spice/people/<Name>.md"`.
3. **Re-create cleanly.** Open `spice/people/People.md` → click `+ New Person` → enter the same name. The file is created fresh with v0.5.0 contract (single frontmatter, intact body).
4. **Restore the preserved values.** Open the new file, paste each non-empty value from step 1 into the corresponding frontmatter field.
5. **Save.**

## Verifying after cleanup

Run the audit suite (this exercises the new naming pattern and frontmatter rules):

```
node platform/test/run-audit.js 2>&1 | grep -E "AU6|AU7|spice/people"
```

Expected: AU6/AU7 pass; no extra `spice/people/*` violations beyond what's listed in the existing audit-vault fixture set.

In the consumer vault, scan for files with two frontmatter blocks:

```
grep -lP "^---\n[\s\S]*?^---\n[\s\S]*?^---" spice/people/*.md
```

Expected: no output. Any file that surfaces here is still broken.

## Estimated scope

The blast radius is one user's worth of broken notes — likely small (<20). Plan a 15-minute block to handle them all.
